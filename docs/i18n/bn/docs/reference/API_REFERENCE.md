## চ্যাট কমপ্লিশন

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### কাস্টম হেডার

| হেডার                    | দিক        | বিবরণ                                                                                                                                                                                               |
| ------------------------ | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | রিকোয়েস্ট | ক্যাশ এড়িয়ে যেতে `true` হিসেবে সেট করুন                                                                                                                                                           |
| `x-omniroute-no-memory`  | রিকোয়েস্ট | এই রিকোয়েস্টের জন্য মেমরি + স্কিল ইনজেকশন বাদ দিতে `true` হিসেবে সেট করুন (নো-ক্যাশের অনুরূপ; প্রতিটি কলের টোকেন/খরচের অতিরিক্ত চাপ এড়ায়)                                                        |
| `X-OmniRoute-Progress`   | রিকোয়েস্ট | অগ্রগতি ইভেন্টের জন্য `true` হিসেবে সেট করুন                                                                                                                                                        |
| `X-Session-Id`           | রিকোয়েস্ট | বাহ্যিক সেশন অ্যাফিনিটির জন্য স্টিকি সেশন কী                                                                                                                                                        |
| `x_session_id`           | রিকোয়েস্ট | আন্ডারস্কোর ভ্যারিয়েন্টও গৃহীত হয় (সরাসরি HTTP)                                                                                                                                                   |
| `X-OmniRoute-Session-Id` | রিকোয়েস্ট | কলার-সরবরাহকৃত সেশন/কথোপকথন ট্যাগ (মেমরিতেও সরবরাহ করা হয়)। উপস্থিত থাকলে প্রতি-সেশন খরচ আরোপের জন্য `call_logs.session_tag`-এ হুবহু সংরক্ষিত হয় (#8249) — অনুপস্থিত থাকলে কখনোই সংশ্লেষিত হয় না |
| `Idempotency-Key`        | রিকোয়েস্ট | ডিডুপ কী (5s উইন্ডো)                                                                                                                                                                                |
| `X-Request-Id`           | রিকোয়েস্ট | বিকল্প ডিডুপ কী                                                                                                                                                                                     |
| `x-omniroute-connection` | রিকোয়েস্ট | একটি একক-মডেল রিকোয়েস্টকে তার id অনুযায়ী একটি প্রোভাইডার কানেকশনে (অ্যাকাউন্ট) পিন করুন — [প্রতি রিকোয়েস্টে অ্যাকাউন্ট পিনিং](#account-pinning-per-request) দেখুন                                |
| `X-OmniRoute-Cache`      | রেসপন্স    | `HIT` অথবা `MISS` (নন-স্ট্রিমিং)                                                                                                                                                                    |
| `X-OmniRoute-Idempotent` | রেসপন্স    | ডিডুপ্লিকেট করা হলে `true`                                                                                                                                                                          |
| `X-OmniRoute-Progress`   | রেসপন্স    | অগ্রগতি ট্র্যাকিং চালু থাকলে `enabled`                                                                                                                                                              |
| `X-OmniRoute-Session-Id` | রেসপন্স    | OmniRoute দ্বারা ব্যবহৃত কার্যকর সেশন ID                                                                                                                                                            |
| `X-OmniRoute-Request-Id` | রেসপন্স    | রিকোয়েস্ট কোরিলেশন id (জানা থাকলে)                                                                                                                                                                 |
| `X-OmniRoute-Version`    | রেসপন্স    | OmniRoute বিল্ড সংস্করণ (সর্বদা উপস্থিত)                                                                                                                                                            |
| `X-OmniRoute-Cost-Saved` | রেসপন্স    | একটি HIT-এর ক্ষেত্রে ক্যাশের কারণে সাশ্রয় হওয়া USD (শুধু ক্যাশ হিট)                                                                                                                               |
| `X-OmniRoute-Decision`   | রেসপন্স    | রাউটিং ট্রেস: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` হলো কম্বো কৌশল, অথবা নন-কম্বো রিকোয়েস্টের জন্য `single`) — সম্পন্ন হওয়ার রেসপন্সে সর্বদা উপস্থিত                      |

> Nginx নোট: আপনি যদি আন্ডারস্কোরযুক্ত হেডারের ওপর নির্ভর করেন (যেমন `x_session_id`), তবে `underscores_in_headers on;` সক্রিয় করুন।

#### প্রতিটি অনুরোধে অ্যাকাউন্ট পিন করা

কোনো প্রোভাইডারের একাধিক সংযোগ (অ্যাকাউন্ট বা কী) থাকলে, OmniRoute সাধারণত তার অ্যাকাউন্ট-নির্বাচন কৌশলের মাধ্যমে একটি বেছে নেয়। এর পরিবর্তে, কোনো অনুরোধে `x-omniroute-connection` হেডার ব্যবহার করে একটি নির্দিষ্ট সংযোগ পিন করা যায়:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **আইডি কোথায় পাবেন।** ড্যাশবোর্ডে প্রোভাইডার পৃষ্ঠাটি খুলুন
  (**ড্যাশবোর্ড → প্রোভাইডার → <provider>**) এবং কোনো সংযোগের সারিতে থাকা `xxxxxxxx…` আইডি চিপে ক্লিক করুন
  — এতে সম্পূর্ণ সংযোগ আইডিটি কপি হবে।
- **কোন অনুরোধগুলো এটি মানে।** `/v1/chat/completions`, `/v1/messages` এবং `/v1/responses`-এ
  একক-মডেল অনুরোধ (`provider/model`)। কম্বোগুলো হেডারটি উপেক্ষা করে: এর পরিবর্তে প্রতিটি কম্বো ধাপে
  সেই ধাপের নিজস্ব সংযোগের মাধ্যমে একটি অ্যাকাউন্ট পিন করুন।
- **পিনটি কঠোরভাবে প্রয়োগ করা হয়, এটি কেবল অগ্রাধিকার নয়।** একচেটিয়াভাবে পিন করা সংযোগটিই ব্যবহৃত হয়। কোনো
  অনুরোধের মধ্যে ব্যর্থতা ঘটলে অ্যাকাউন্টটির কুলডাউন রেকর্ড করা হয়, তবে একই প্রোভাইডারের
  অন্য কোনো সমপর্যায়ের অ্যাকাউন্টে **ঘোরানো হয় না**।
- **কুলডাউন ও কোটা পিনটি মুক্ত করে।** পিন করা সংযোগটি কুলডাউনে থাকা অবস্থায়,
  কোটা শেষ হয়ে গেলে বা কোনো কোটা নীতির কারণে ব্লক হলে, পরবর্তী অনুরোধগুলো প্রোভাইডারের
  অন্যান্য সংযোগে ফলব্যাক করে—ঠিক পিন না করা ট্রাফিকের মতো।
- **অজানা বা নিষ্ক্রিয় আইডির ক্ষেত্রে ব্যর্থতা ঘটে।** প্রোভাইডারের সক্রিয় পুলে নেই এমন কোনো আইডি (মুছে ফেলা,
  নিষ্ক্রিয় করা বা অন্য কোনো প্রোভাইডারের অন্তর্গত) ব্যবহারযোগ্য কোনো অ্যাকাউন্ট অবশিষ্ট রাখে না, তাই অন্য কোথাও
  নীরবে রাউট করার পরিবর্তে অনুরোধটি ব্যর্থ হয়।

Claude Code `ANTHROPIC_CUSTOM_HEADERS`-এর মাধ্যমে কাস্টম হেডার পাঠায়। এটি `~/.claude/settings.json`-এর
`env` ব্লকে রাখুন, অথবা প্রতিটি প্রকল্পের জন্য আলাদা অ্যাকাউন্ট পিন করতে প্রকল্প-স্তরের `.claude/settings.json`-এ রাখুন:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

উৎস: `src/sse/handlers/chat.ts` (হেডার পড়া), `src/sse/services/auth.ts` এবং
`src/sse/services/sessionAffinityPin.ts` (পিন মুক্ত করা এবং পুলে অনুপস্থিত থাকার পরীক্ষা)।

> **খরচের টেলিমেট্রি হেডার:** নন-স্ট্রিমিং সফল প্রতিক্রিয়াগুলোতে `X-OmniRoute-*` খরচ-টেলিমেট্রি সেটও থাকে—`X-OmniRoute-Response-Cost` (USD, দশমিকের পর নির্দিষ্ট ১০ ঘর; বিনামূল্যের/মূল্য নির্ধারিত নয় এমন কিছুর জন্য `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, এবং `X-OmniRoute-Fallback-Attempts` (শুধু > 0 হলে), সঙ্গে `X-OmniRoute-Request-Id` ও `X-OmniRoute-Version`। এগুলো চ্যাট কমপ্লিশন, `/v1/responses`, `/v1/messages`, **এবং মিডিয়া এন্ডপয়েন্টগুলোও** নির্গত করে—`/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, এবং `/v1/moderations` (খরচ সর্বদা `0`)। মূল্য পাওয়া গেলে প্রতিটি মোডালিটির ভিত্তিতে (প্রতি ছবি, প্রতি সেকেন্ড, প্রতি অক্ষর, প্রতি সার্চ-ইউনিট) মিডিয়ার খরচ গণনা করা হয়, অন্যথায় `0` (ফেইল-ওপেন)।

> **ক্যাশ-হিট খরচের অর্থ:** কোনো সেমান্টিক-ক্যাশ HIT-এ (`X-OmniRoute-Cache-Hit: true`) কোনো আপস্ট্রিম কল করা হয় না, তাই `X-OmniRoute-Response-Cost` হলো `0.0000000000` (হিটটি পরিবেশনের **ক্রমবর্ধমান** খরচ)। মূল/সম্ভাব্য খরচটি আলাদাভাবে `X-OmniRoute-Cost-Saved`-এ জানানো হয়। বিলিং ব্যবহারকারীদের `X-OmniRoute-Response-Cost`-এর যোগফল নেওয়া উচিত (হিটের কোনো খরচ নেই); ক্যাশ অ্যানালিটিক্সে `X-OmniRoute-Cost-Saved` সমষ্টিবদ্ধ করা যেতে পারে।

## এক্সক্লুসিভ ম্যানেজড সেশন লিজ

এক্সক্লুসিভ ম্যানেজড সেশন লিজিং হলো একটি অপ্ট-ইন, ক্লায়েন্ট-নিরপেক্ষ রাউটিং চুক্তি: একজন সক্রিয় মালিক
একটি উপযুক্ত OmniRoute সংযোগ ধারণ করে। এটি কোনো মডেল লিজ দেয় না, OAuth প্রয়োজন করে না, কোনো
নির্দিষ্ট ক্লায়েন্ট শনাক্ত করে না বা কোনো নির্দিষ্ট প্রদানকারী আবশ্যক করে না।

প্রমাণীকরণকারী API কীটির `lease:exclusive` স্কোপ এবং একটি সুস্পষ্ট, খালি নয় এমন
`allowedConnections` তালিকা থাকতে হবে। কী তৈরি এবং আংশিক আপডেটের সময় ডেটাবেস মিউটেশন সীমানা
দুটি ফিল্ডকেই একসঙ্গে প্রয়োগ করে।

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

সফল অধিগ্রহণ, নবায়ন এবং রিলিজ প্রতিক্রিয়াগুলো টাইমস্ট্যাম্প, `state` এবং সঠিক ধনাত্মক
`generation` প্রকাশ করে, তবে নির্বাচিত সংযোগ বা ক্রেডেনশিয়াল কখনোই প্রকাশ করে না। নবায়ন এবং রিলিজের ক্ষেত্রে
JSON বডিতে জেনারেশন সরবরাহ করা হয়:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

একজন সক্রিয় লিজ মালিক তার বর্তমান বাইন্ডিংয়ের জন্য সুস্পষ্টভাবে গোপনীয়তা-নিরাপদ প্রদর্শন মেটাডেটা অনুরোধ করতে পারেন:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

এই অপ্ট-ইন স্ট্যাটাস অ্যাকশনটি একটি ডেটাবেস ট্রানজ্যাকশনের মধ্যে অস্বচ্ছ মালিক, প্রমাণীকৃত ম্যানেজড API কী এবং সঠিক
সক্রিয় জেনারেশন দ্বারা সুরক্ষিত। `displayName` কেবল ট্রিম করা কনফিগারকৃত
সংযোগের নাম; কোনো নিরাপদ কনফিগারকৃত নাম না থাকলে এটি `null` হয়। OmniRoute কখনোই এর পরিবর্তে
কোনো ইমেইল বা জেনারেট করা অ্যাকাউন্ট পরিচয় ব্যবহার করে না। প্রদানকারীর মানটি একটি অ-সংবেদনশীল প্রদর্শন লেবেল এবং কখনোই
কোনো জেনারেট করা সামঞ্জস্যপূর্ণ-প্রদানকারী শনাক্তকারী নয়। ক্রেডেনশিয়াল, টোকেন, কুকি, কাঁচা সংযোগ বা API
কী আইডি, মালিকের হ্যাশ, ফেন্সিং সিক্রেট এবং অভ্যন্তরীণ রাউটিং ডেটা বাদ দেওয়া হয়।

ভুল কী, ভুল মালিক, পুরোনো জেনারেশন, অনুপস্থিত, মেয়াদোত্তীর্ণ, রিলিজ করা এবং অকার্যকর করা লুকআপ—সবগুলোই
সংযোগ মেটাডেটা ছাড়া একই `409 LEASE_FENCE_STALE` ত্রুটি ফেরত দেয়। ক্যাপাসিটি-অপেক্ষার প্রতিক্রিয়া পাওয়া কোনো ক্লায়েন্টের পরিদর্শন করার মতো সক্রিয় বাইন্ডিং থাকে না। রাউটিং যখন কোনো সক্রিয় লিজকে ট্রানজিশন করে,
তখন একই জেনারেশন বৈধ থাকে এবং স্ট্যাটাস অ্যাটমিকভাবে নতুন বাইন্ডিং ফেরত দেয়, পুরোনোটি কখনোই নয়।
বিদ্যমান ক্লায়েন্টগুলো অপরিবর্তিত থাকে, কারণ অধিগ্রহণ, নবায়ন, রিলিজ এবং অপেক্ষার প্রতিক্রিয়াগুলো তাদের
আগের কাঠামো বজায় রাখে।

এই সার্ভার চুক্তি স্টক OpenAI Codex `/status` পরিবর্তন করে না। স্টক Codex বর্তমানে তার
মডেল প্রদানকারী এবং বিল্ট-ইন প্রমাণীকরণ/অ্যাকাউন্টের অবস্থা রিপোর্ট করে, কিন্তু ইচ্ছামতো কাস্টম
প্রদানকারী অ্যাকাউন্ট মেটাডেটা রেন্ডার করে না; পরবর্তী কোনো ক্লায়েন্ট ইন্টিগ্রেশনকে এই অ্যাকশন কল করতে হবে এবং
`connection.displayName` কীভাবে প্রদর্শন করা হবে তা নির্ধারণ করতে হবে।

এরপর প্রতিটি ম্যানেজড ইনফারেন্স অনুরোধ উভয় কন্ট্রোল হেডার সরবরাহ করে:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

প্রতিটি সমর্থিত আপস্ট্রিম প্রচেষ্টার অব্যবহিত আগে সঠিক মালিক, জেনারেশন, সক্রিয় সংযোগ এবং প্রমাণীকৃত API কী
ফেন্স করা হয়। অন্য একটি কী দিয়ে মালিক ও জেনারেশন পুনরায় ব্যবহার করলে তা ব্যর্থ হয়, এমনকি
সেই কী একই সংযোগ অনুমোদন করলেও। কাঁচা মালিকের মান সংরক্ষণ করা, লগ করা, রিকোয়েস্ট স্ন্যাপশটে ধরে রাখা বা আপস্ট্রিমে ফরওয়ার্ড করা হয় না।

সাময়িক প্রতিদ্বন্দ্বিতার ক্ষেত্রে HTTP `429`, `Retry-After` এবং নিম্নলিখিতটি ফেরত দেওয়া হয়:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

এই প্রতিক্রিয়ার অর্থ শুধু এই যে সাধারণ উপযুক্ত সেটটি খালি ছিল না এবং প্রতিটি মুক্ত প্রার্থী
অন্য কোনো সক্রিয় লিজের দখলে ছিল। অসমর্থিত মডেল/প্রদানকারী, নীতির অমিল, কুলডাউন, কোটা,
স্বাস্থ্য এবং অন্যান্য সাধারণ উপযুক্ততা ব্যর্থতার ক্ষেত্রে তাদের বিদ্যমান OmniRoute প্রতিক্রিয়াই বহাল থাকে।

### `x-omniroute-compression`

প্রতি-অনুরোধে কম্প্রেশন পরিকল্পনা ওভাররাইড করে। সর্বোচ্চ অগ্রাধিকারপ্রাপ্ত—রাউটিং-কম্বো
ওভাররাইড, সক্রিয় প্রোফাইল, স্বয়ংক্রিয় ট্রিগার এবং প্যানেলের ডিফল্টকে অগ্রাহ্য করে। মানসমূহ:

| মান           | প্রভাব                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| `off`         | এই অনুরোধে কোনো কম্প্রেশন নয়।                                                                       |
| `default`     | প্যানেল থেকে নির্ধারিত ডিফল্ট প্রোফাইল (সক্রিয় প্রোফাইল উপেক্ষা করে)। লসি ইঞ্জিনগুলো বন্ধ রাখা হয়। |
| `safe`        | কেবল ডিডুপ এবং হোয়াইটস্পেস ফোল্ডিং।                                                                 |
| `allow-lossy` | সারাংশ এবং স্টাইল পুনর্লিখনসহ এই অনুরোধের জন্য অপারেটরের পরিকল্পনা বজায় রাখে।                       |
| `engine:<id>` | সক্রিয় থাকলে একটি একক ইঞ্জিন, যেমন `engine:rtk`। সেই ইঞ্জিনের জন্য প্রতি-অনুরোধে অপ্ট-ইন।           |
| `<combo>`     | একটি নামযুক্ত কম্বো, প্রথমে নামের ভিত্তিতে (কেস-ইনসেনসিটিভ), তারপর আইডির ভিত্তিতে মিলানো হয়।        |

নোট:

- অজানা মান উপেক্ষা করা হয় (অনুরোধটি কখনোই প্রত্যাখ্যাত হয় না); রেজোলিউশন স্বাভাবিক অপারেটর অগ্রাধিকার অনুযায়ী চলতে থাকে।
- একাধিক কম্বোর নাম একই হলে, নির্ধারিত মিলের জন্য কম্বোর **আইডি** দিন।
- যে কম্বোর নাম `off` বা `default`, সেটিকে নাম দিয়ে নির্বাচন করা যায় না (এই কীওয়ার্ডগুলো আগে ব্যাখ্যা করা হয়); এমন কম্বোকে তার আইডি দিয়ে রেফারেন্স করুন।
- প্রধান কম্প্রেশন সুইচটি একটি কঠোর গেট: কম্প্রেশন বিশ্বব্যাপী নিষ্ক্রিয় থাকলে, এই হেডার সেটি সক্রিয় করতে পারে না।

প্রয়োগ করা পরিকল্পনাটি প্রতিক্রিয়ার হেডারে প্রতিধ্বনিত হয়:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

যেখানে `<source>` হলো `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` অথবা `off`-এর একটি।

## এমবেডিং

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

উপলভ্য প্রোভাইডার: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI।

ক্যাটালগ আইডি হলো `provider/model` (উদাহরণ: `jina-ai/jina-embeddings-v5-omni-small`)। রেজিস্ট্রিতে থাকা প্রোভাইডারবিহীন Jina মডেল আইডিগুলোও (যেমন `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) সমাধান করা হয়। Jina embed/rerank/classify/segment প্রথমে ড্যাশবোর্ডের `jina-ai` ক্রেডেনশিয়াল ব্যবহার করে; ড্যাশবোর্ড কী না থাকলেই কেবল `JINA_AI_API_KEY` ফলব্যাক হিসেবে ব্যবহৃত হয়। `jina-reader` কার্ডটি কেবল Reader / `r.jina.ai`-এর জন্য (`POST /v1/web/fetch`) এবং কখনোই এমবেডিং বা রির্যাঙ্ক সরবরাহ করে না।

মাল্টিমোডাল সমর্থন ঘোষণা করা রেজিস্ট্রি মডেলগুলো সর্বোচ্চ ৩২টি প্রোভাইডার-নিরপেক্ষ স্ট্রাকচার্ড
আইটেমও গ্রহণ করে। মিডিয়া আইটেমের ধরন হলো `text`, `image`, `audio`, `video`, এবং `document`। এগুলোর মিডিয়া `source`
হয় `{"type":"url","url":"https://..."}`, অথবা
`{"type":"base64","data":"...","media_type":"..."}`।

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
এবং ফ্যামিলি অ্যালিয়াস `jina-ai/jina-embeddings-v5-omni` → omni-small) Jina-এর নেটিভ
EmbeddingsV5Request ডকুমেন্টও গ্রহণ করে এবং সেগুলো **অপরিবর্তিত অবস্থায় ফরওয়ার্ড করে** `https://api.jina.ai/v1/embeddings`-এ:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

নেটিভ `{ image | audio | video | pdf }` মান একটি পাবলিক HTTPS URL, একটি `data:` URI, অথবা কাঁচা
base64 হতে পারে। OmniRoute এসব অবজেক্টকে স্ট্রিংয়ে রূপান্তর করে না বা নেটিভ ইমেজ URL ফেচ করে না—Jina নিজেই
পাবলিক মিডিয়া সংগ্রহ করে। অতিরিক্ত Jina ফিল্ড (`task`, `normalized`, `truncate`, `embedding_type`)
ফরওয়ার্ড করা হয়। শুধু-টেক্সট Jina SKU এখনো নন-টেক্সট ডকুমেন্ট প্রত্যাখ্যান করে।

নিরাপত্তা ও ট্রান্সপোর্টের সীমা:

- রিমোট মিডিয়া URL অবশ্যই পাবলিক HTTPS হতে হবে। ক্যানোনিক্যাল `{type,source:url}` আইটেমগুলো
  সার্ভার-সাইডে ফেচ করা হয় (রিডাইরেক্ট পুনঃযাচাইকরণ, টাইমআউট, আকারের সীমা, পাবলিক DNS, কানেকশন পিনিং) এবং
  প্রোভাইডার কলের আগে ইনলাইন করা হয়। Jina-নেটিভ `{image:"https://..."}` আইটেমগুলো একই পাবলিক-HTTPS
  যাচাইয়ের পর অপরিবর্তিত অবস্থায় ফরওয়ার্ড করা হয়; Jina URL-টি ফেচ করে।
- ইনলাইন base64 মিডিয়া প্রতি আইটেমে ডিকোড করা অবস্থায় ৮ MiB এবং পুরো রিকোয়েস্টে ডিকোড করা অবস্থায় ১৬ MiB পর্যন্ত সীমাবদ্ধ।

প্রোভাইডার রূপান্তর (ক্যানোনিক্যাল আইটেম কখনোই অপরিবর্তিত অবস্থায় ফরওয়ার্ড করা হয় না):

- Jina মাল্টিমোডাল মডেল: প্রতিটি টপ-লেভেল আইটেম একটি মোডালিটি-কীযুক্ত অবজেক্টে পরিণত হয়
  (`text` / `image` / `audio` / `video` / `pdf`), যেখানে ইনলাইন মিডিয়ার জন্য data URI ব্যবহৃত হয়; প্রতি
  টপ-লেভেল আইটেমে একটি ভেক্টর।
- Gemini Embedding 2 ফ্যামিলি: একটি টপ-লেভেল অ্যারে একটি একক নেটিভ
  `models/{model}:embedContent` রিকোয়েস্টে পরিণত হয়, যেখানে `content.parts` (`text` অথবা `inline_data`) থাকে।
- llama.cpp (`llama-cpp/<model>`, লোকাল সার্ভারে লোড করা যেকোনো মডেল): ক্যানোনিক্যাল `text` আইটেম
  প্লেইন স্ট্রিংয়ে পরিণত হয়, এবং `image` / `audio` / `video`-এর প্রতিটি একটি
  `{"content": [part]}` অবজেক্টে পরিণত হয়; এতে ইনলাইন ডেটাসহ llama-server-এর চ্যাট কনটেন্ট পার্ট (`image_url`,
  `input_audio` যার ফরম্যাট `wav` / `mp3` / `flac`, `input_video`) ব্যবহৃত হয়; প্রতি টপ-লেভেল আইটেমে
  একটি ভেক্টর। সার্ভারটি অবশ্যই `--embedding --mmproj …` দিয়ে চালাতে হবে; প্রজেক্টর ছাড়া এটি নিজেই
  মিডিয়া প্রত্যাখ্যান করে। `document` সমর্থিত নয়।
- সুস্পষ্ট মোডালিটি মেটাডেটাবিহীন অজানা/ডায়নামিক মডেল HTTP 400 সহ স্ট্রাকচার্ড ইনপুট প্রত্যাখ্যান করে।

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

অসমর্থিত মডেল/মোডালিটি সমন্বয়ে আইটেমটিকে জোরপূর্বক রূপান্তর না করে HTTP 400 ফেরত দেওয়া হয়। লিগ্যাসি স্ট্রিং/টোকেন রিকোয়েস্টের
নন-ইনপুট এক্সটেনশন ফিল্ডগুলো আগের মতোই অপরিবর্তিত অবস্থায় পাস-থ্রু হয়।

```bash
# সব এমবেডিং মডেলের তালিকা দেখান
GET /v1/embeddings
```

## ছবি তৈরি

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

উপলভ্য প্রদানকারীদের মধ্যে রয়েছে OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (স্থানীয়), ComfyUI (স্থানীয়)।

`n`, `data[]`-এ `n`টি ছবি ফেরত দেয়। যেসব প্রদানকারীর আপস্ট্রিম API প্রতি কলে একটি ছবি ফেরত দেয়
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), তাদের জন্য সর্বাধিক ৪টি কল একসঙ্গে চলমান রেখে পৃথকভাবে `n`টি আপস্ট্রিম কল করা হয়। একটি
নির্দিষ্ট `seed` কলের সূচক অনুযায়ী অফসেট করা হয় (`seed`, `seed + 1`, …), ফলে ছবিগুলো আলাদা হলেও
পুনরুৎপাদনযোগ্য থাকে। `n`-এর সর্বোচ্চ সীমা ১০। কোনো একটি কল ব্যর্থ হলে পুরো অনুরোধটি
ব্যর্থ হয়। ফ্যান-আউট ফরম্যাটগুলোর তালিকা
`open-sse/handlers/imageGeneration/fanOut.ts`-এর `SINGLE_IMAGE_FANOUT_FORMATS`-এ রয়েছে।

ZenMux বিদ্যমান API-কী সংযোগ পুনরায় ব্যবহার করে এবং `zenmux/` বা `zm/` প্রিফিক্স গ্রহণ করে:

- `zenmux/openai/gpt-image-2`, ZenMux-এর OpenAI Images API ব্যবহার করে। বিকল্পগুলোর মধ্যে রয়েছে `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, এবং `response_format`।
- `zm/meta/muse-image-1.0`-এর মতো অন্যান্য প্রকাশক ZenMux-এর Vertex AI `:predict`
  এন্ডপয়েন্ট ব্যবহার করে। `n`, `sampleCount`-এ; `aspect_ratio`, `aspectRatio`-তে; এবং `image_size`
  (`1K`, `2K`, `4K`), `sampleImageSize`-এ ম্যাপ হয়। পিক্সেলভিত্তিক `size` শুধু একটি আকৃতির অনুপাত সরবরাহ করে,
  নিশ্চিত পিক্সেল মাত্রা নয়। সমর্থিত অনুপাত, রেজোলিউশন এবং সংখ্যা মডেলভেদে পরিবর্তিত হয়।
- `zm/inclusionai/ming-image-0.1-design` নিজস্ব মাত্রা নির্বাচন করে। `size`,
  `aspect_ratio`, এবং `image_size` বাদ দিন; স্পষ্ট মান দিলে HTTP 400 ফেরত আসে। `output_format` দিয়ে
  PNG, JPEG এবং WebP অনুরোধ করা যায়।

এই ইন্টিগ্রেশন টেক্সট-টু-ইমেজ তৈরি সমর্থন করে, রেফারেন্স-ইমেজ সম্পাদনা নয়। Vertex-এর
আউটপুট `data[].b64_json`-এ স্বাভাবিকীকরণ করা হয়; `response_format: "url"` একটি আপস্ট্রিম
HTTPS URL ফেরত দেয় অথবা শুধু ছবির বাইট উপলভ্য থাকলে একটি base64 data URL ফেরত দেয়। খালি/ফিল্টার করা আউটপুট
খালি সফল ফলাফলের পরিবর্তে একটি ত্রুটি ফেরত দেয়। মডেলে প্রবেশাধিকার ZenMux অ্যাকাউন্টের ওপর নির্ভর করে।
[ZenMux-এর Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) এবং
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image) দেখুন।

```bash
# সব ইমেজ মডেলের তালিকা দেখান
GET /v1/images/generations
```

## ডকুমেন্ট OCR

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model`, একটি `provider/model` প্রিফিক্সের মাধ্যমে OCR প্রদানকারী নির্বাচন করে; শুধু একটি মডেল id (যেমন
`mistral-ocr-latest`) দিলে সেটি তার নিবন্ধিত প্রদানকারীতে সমাধান হয়, আর `model` বাদ দিলে ডিফল্ট হিসেবে
Mistral (`mistral-ocr-latest`) ব্যবহৃত হয়। নিবন্ধিত প্রদানকারীরা (`open-sse/config/ocrRegistry.ts`):

| প্রদানকারী id                 | মডেল id              | `model`-এর মান                                                | নোট                                                                                                                     |
| ----------------------------- | -------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (অথবা শুধু `mistral-ocr-latest`) | সিঙ্ক্রোনাস — একক আপস্ট্রিম কল থেকে প্রতিক্রিয়া সরাসরি ফেরত দেওয়া হয়।                                                |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                   | অ্যাসিঙ্ক্রোনাস আপস্ট্রিম (`analyze` + পোল) — নিচে দেখুন।                                                               |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                       | সিঙ্ক্রোনাস, Vertex AI-এর `openapi/chat/completions` অংশীদার এন্ডপয়েন্টের মাধ্যমে — প্রমাণীকরণ/URL-এর জন্য নিচে দেখুন। |

তিনটি প্রদানকারীই একই Mistral-আকৃতির বডিতে প্রতিক্রিয়া দেয়:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence-এর পোল প্রবাহ

Azure Document Intelligence-এর `analyze` API অ্যাসিঙ্ক্রোনাস: প্রাথমিক অনুরোধটি বডির পরিবর্তে একটি
`Operation-Location` হেডার ফেরত দেয় এবং ফলাফলের জন্য পোল করতে হয়। হ্যান্ডলারটি
(`open-sse/handlers/ocr.ts`) সর্বোচ্চ ৩০টি প্রচেষ্টায় প্রতি সেকেন্ডে ওই URL পোল করে, কোনো non-`ok` পোল প্রতিক্রিয়া বা `"failed"` স্ট্যাটাস পেলে দ্রুত ব্যর্থ হয় (পোলিং
চালিয়ে যায় না), এবং নির্ধারিত প্রচেষ্টার সীমা শেষ হওয়ার পরও অপারেশন চলমান থাকলে `504` ফেরত দেয়।
চূড়ান্ত Azure প্রতিক্রিয়াটি কলারের কাছে ফেরত দেওয়ার আগে Mistral-এ ব্যবহৃত একই `pages`/`markdown` কাঠামোতে
স্বাভাবিকীকরণ করা হয়, তাই ক্লায়েন্ট কোডে প্রদানকারীভেদে বিশেষ ব্যবস্থা নেওয়ার প্রয়োজন হয় না।

### Vertex AI DeepSeek OCR-এর প্রমাণীকরণ ও এন্ডপয়েন্ট নির্ধারণ

`vertex-deepseek-ocr`, চ্যাট/ইমেজ ট্রাফিকের জন্য OmniRoute ইতিমধ্যেই সমর্থন করে এমন একই Vertex AI প্রমাণীকরণ
পুনরায় ব্যবহার করে (`open-sse/executors/vertex.ts`): সংযোগের API কী হয় একটি
Service Account JSON ক্রেডেনশিয়াল (JWT-bearer প্রবাহের মাধ্যমে স্বল্পমেয়াদি OAuth অ্যাক্সেস টোকেনে বিনিময় করা হয়),
অথবা আগে থেকেই তৈরি করা OAuth অ্যাক্সেস টোকেন, যা অপরিবর্তিতভাবে ব্যবহৃত হয়। আপস্ট্রিম এন্ডপয়েন্ট URL হলো Vertex-এর
সাধারণ `openapi/chat/completions` অংশীদার এন্ডপয়েন্ট, যা সংযোগের প্রজেক্ট ও
অঞ্চল থেকে তৈরি হয় — স্পষ্টভাবে দেওয়া `providerSpecificData.project`/`providerSpecificData.region` সর্বদা অগ্রাধিকার পায়;
অন্যথায় প্রজেক্টটি Service Account JSON-এর `project_id` থেকে নির্ণয় করা হয় এবং অঞ্চলের
ডিফল্ট মান হয় `us-central1`। উভয় নির্ধারণই `open-sse/handlers/ocr.ts`-এ
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) সম্পন্ন হয় এবং `handleOcr`-এ পাঠানোর আগে
`src/app/api/v1/ocr/route.ts` সেগুলো ব্যবহার করে।

## মডেলের তালিকা

```bash
GET /v1/models
Authorization: Bearer your-api-key

→ OpenAI ফরম্যাটে সব চ্যাট, এম্বেডিং এবং ইমেজ মডেল + কম্বো ফেরত দেয়
```

### মডেল id প্রিফিক্স (`?prefix=`)

বেশিরভাগ মডেল একটি **প্রোভাইডার প্রিফিক্সের** অধীনে প্রকাশিত হয়। আপনি কোন প্রিফিক্স পাবেন, তা
`MODELS_CATALOG_PREFIX_MODE` ফিচার ফ্ল্যাগ দ্বারা নিয়ন্ত্রিত হয় এবং একটি কোয়েরি প্যারামিটার দিয়ে
**প্রতি অনুরোধে** ওভাররাইড করা যায়—যে ক্লায়েন্ট অন্য সবার জন্য সার্ভারব্যাপী সেটিং পরিবর্তন না করে
একটি পরিচ্ছন্ন তালিকা চায়, তার জন্য এটি উপযোগী:

```bash
GET /v1/models?prefix=alias        # প্রতি মডেলে একটি id—সংক্ষিপ্ত alias প্রিফিক্স
GET /v1/models?prefix=dual         # উভয় রূপ (সার্ভারের ডিফল্ট)
GET /v1/models?prefix=canonical    # শুধু সম্পূর্ণ provider-id প্রিফিক্স
```

| মোড         | যা নির্গত করে                                             | নোট                                                                                                                                                                                            |
| ----------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **এবং** `claude/claude-sonnet-4-6` | **ডিফল্ট।** উভয় id একই মডেলে রাউট হয়; যেসব ক্লায়েন্ট কনফিগে যেকোনো একটি রূপ হার্ডকোড করা আছে, সেগুলো সচল রাখতে এটি বজায় রাখা হয়েছে। এটি ক্যাটালগের আকার প্রায় দ্বিগুণ করে।               |
| `alias`     | `cc/claude-sonnet-4-6`                                    | প্রতি মডেলে একটি এন্ট্রি। স্বতন্ত্র alias না থাকা প্রোভাইডারগুলোও তাদের এন্ট্রি নির্গত করে, ফলে কিছুই বাদ যায় না।                                                                             |
| `canonical` | `claude/claude-sonnet-4-6`                                | সম্পূর্ণ provider-id প্রিফিক্সের অধীনে প্রতি মডেলে একটি এন্ট্রি। স্বতন্ত্র alias না থাকা প্রোভাইডারগুলোও (যেমন `antigravity/…`, `agy/…`) এখানে তাদের একক id নির্গত করে, ফলে কিছুই বাদ যায় না। |

কোয়েরি প্যারামিটার ছাড়াও একটি `dual`-মোড মিরর শনাক্ত করা যায়: এতে প্রাথমিক id-কে নির্দেশকারী একটি `parent`
ফিল্ড থাকে।

যেসব ক্লায়েন্ট মডেল পিকার রেন্ডার করে, তাদের `?prefix=alias` অনুরোধ করা উচিত—এটিই
[OmniCopilot VS Code এক্সটেনশন](../guides/VSCODE-COPILOT.md) করে।

### ডিসকভারি ফিল্টার (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` ঐচ্ছিক ডিসকভারি ফিল্টার গ্রহণ করে। এগুলোর কোনোটি না থাকলে রেসপন্স
অপরিবর্তিত থাকে। এগুলো কলার ইতিমধ্যে যে ক্যাটালগ দেখতে পায় সেটিকেই সংকুচিত করে (API-key অনুমতি আগে প্রয়োগ হয়),
এবং OpenAI-ধাঁচের `limit` / `after` পেজিংয়ের আগে এগুলো কার্যকর হয়:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # তালিকাভুক্ত প্রতিটি capability অবশ্যই true হতে হবে
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # ক্যাটালগের `type`; এটি না থাকা সারিগুলো `chat`
GET /v1/models?q=sonnet&limit=10                           # id বা name-এর সঙ্গে case-insensitive মিল
```

| প্যারামিটার   | মান                                                                                                 |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | ঋণাত্মক নয় এমন পূর্ণসংখ্যা, যা `context_length`-এর সঙ্গে তুলনা করা হয়                             |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | ১–২০০টি অক্ষর                                                                                       |

অজানা কোনো মান অথবা ঋণাত্মক নয় এমন পূর্ণসংখ্যা নয় এমন `min_context` (উদাহরণস্বরূপ `1.5`)
HTTP `400` ফেরত দেয় এবং বার্তায় বৈধ মানগুলোর তালিকা থাকে। বাস্তবায়ন:
`src/app/api/v1/models/catalogFilters.ts`।

### মডেলের সংক্ষিপ্ত তালিকা (`POST /v1/models/query`)

`POST /v1/models/query` একই ক্যাটালগ থেকে একটি সংক্ষিপ্ত, নির্ধারিত তালিকা ফেরত দেয়, যেখানে
`GET /v1/models`-এর মতো একই প্রমাণীকরণ ও প্রতি-key দৃশ্যমানতা প্রযোজ্য:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

প্রতিটি ফিল্ড ঐচ্ছিক। `capabilities` এবং `exclude` একটি অ্যারে অথবা কমা দিয়ে পৃথক করা স্ট্রিং গ্রহণ করে;
`max_output`, `max_output_tokens`-এর সঙ্গে তুলনা করে। ফলাফল প্রথমে `owned_by`, তারপর `id` অনুযায়ী সাজানো হয়।
`limit`-এর ডিফল্ট মান `20` এবং `100`-এর বেশি মানকে `100`-এ সীমাবদ্ধ করা হয়। অবৈধ JSON, অজানা
ফিল্ড অথবা অবৈধ মান HTTP `400` ফেরত দেয়।

### পৃথকভাবে লুকানো চ্যাট মডেল

কোনো প্রোভাইডার পেজে **লুকানো** হিসেবে চিহ্নিত মডেলকে ক্যাটালগ থেকে বাদ দেওয়া হয় এবং স্পষ্টভাবে
অনুরোধ করা হলে HTTP `404` / `model_not_found` দিয়ে প্রত্যাখ্যান করা হয়। যাচাইটি সমাধানকৃত
প্রোভাইডার ও মডেল ব্যবহার করে, যার মধ্যে provider alias, compatible-provider node prefix এবং
connection default অন্তর্ভুক্ত। একটি কম্বো লুকানো টার্গেটগুলো এড়িয়ে যায় এবং দৃশ্যমান sibling ব্যবহার করতে পারে; যখন কোনো
কার্যকর টার্গেট অবশিষ্ট থাকে না, তখন এটি একই error code ফেরত দেয়। লুকানো অবস্থা সরানো হলে তা পরবর্তী
অনুরোধ থেকেই কার্যকর হয়। শুধু-ইমেজ দৃশ্যমানতার ওভাররাইড একই ID-র চ্যাট মডেলকে লুকায় না।

এই পৃথক মডেল সেটিংটি
[মডেল এক্সপোজার allow/deny তালিকা](../routing/MODEL_EXPOSURE_LIST.md) থেকে আলাদা, যা স্পষ্ট dispatch বজায় রেখে ক্যাটালগে
প্রকাশ এবং auto-routing candidate ফিল্টার করে। API-key মডেল অনুমতিগুলো স্বাধীনভাবে প্রযোজ্য থাকে।
ডিফল্ট ক্যাটালগ প্রিফিক্স মোড `dual`-ই থাকে।

### চিন্তন-বিহীন মডেল ভ্যারিয়েন্ট

চিন্তনে সক্ষম Claude মডেলগুলোর জন্য `/v1/models` একটি **চিন্তন-বিহীন** ভ্যারিয়েন্টও প্রকাশ করে, যার id-র শুরুতে `claude-3-omniroute-no-thinking/` থাকে:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

এই id নির্বাচন করলে (যেমন, এমন একটি Claude Code config-এ যা সর্বদা একটি `thinking` block সংযুক্ত করে) এটি reasoning নিষ্ক্রিয় রেখে প্রকৃত `<provider>/<model>`-এ পুনরায় resolve হয়—`/v1/messages` path-এ `thinking:{type:"disabled"}`, অথবা `/v1/chat/completions` path-এ `reasoning`/`reasoning_effort` field বাদ দেওয়া হয়। variant-টি কেবল সেই Claude-family model-গুলোর জন্য তালিকাভুক্ত করা হয়, যেগুলো thinking সমর্থন করে **এবং** `disabled` মেনে চলে (তাই, যেমন, যেসব adaptive-only model `disabled` প্রত্যাখ্যান করে সেগুলো বাদ দেওয়া হয়)। Operator-রা `ModelSpec.noThinkingAlias`-এর মাধ্যমে প্রতিটি model-এর জন্য variant-টি চালু বা বন্ধ করতে পারেন।

## ElevenLabs অডিও জেনারেশন

আপনার ElevenLabs API key দিয়ে OmniRoute-এ একটি `elevenlabs` প্রোভাইডার connection কনফিগার করুন।
ক্লায়েন্ট তাদের **OmniRoute** key (`Authorization: Bearer $OMNIROUTE_API_KEY`) দিয়ে authenticate করে;
gateway সংরক্ষিত প্রোভাইডার key-টি `xi-api-key` হিসেবে সরবরাহ করে। Gateway bearer token হিসেবে কখনোই ElevenLabs key পাঠাবেন না।

| মেথড | পাথ                         | রেসপন্স                                   | API key endpoint বিভাগ |
| ---- | --------------------------- | ----------------------------------------- | ---------------------- |
| POST | `/v1/sound-generation`      | নেটিভ অডিও bytes                          | `elevenlabs`           |
| POST | `/v1/music`                 | নেটিভ অডিও bytes                          | `music`                |
| POST | `/v1/music/stream`          | স্ট্রিমিং অডিও bytes                      | `music`                |
| POST | `/v1/music/detailed`        | নেটিভ multipart অডিও এবং composition plan | `music`                |
| POST | `/v1/music/detailed/stream` | নেটিভ SSE metadata এবং অডিও chunk         | `music`                |
| POST | `/v1/music/plan`            | JSON composition plan                     | `music`                |

এই endpoint-গুলো বিদ্যমান `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` এবং `/v1/speech-to-text` route-গুলোর পরিপূরক। `output_format` এবং `enable_logging`-এর মতো নেটিভ JSON field
ও query parameter অপরিবর্তিত থাকে।
`/v1/music/detailed` রেসপন্সে তাদের multipart boundary বজায় থাকে; এগুলোকে multipart হিসেবে parse করুন।
`/v1/music/detailed/stream` composition metadata এবং
SSE event-এ base64 অডিও chunk-সহ `text/event-stream` রিটার্ন করে। ছয়টি route-ই CORS preflight সমর্থন করে।

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# একটি সংক্ষিপ্ত sound effect। সময়কাল: 0.5 থেকে 30 সেকেন্ড।
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# সঙ্গীতের সময়কাল millisecond-এ প্রকাশ করা হয়: 3000 থেকে 600000।
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

ক্রমবর্ধমান অডিও সরবরাহের জন্য একই JSON body-সহ `/v1/music/stream` ব্যবহার করুন। Composition
ঠিক `prompt` অথবা `composition_plan`-এর যেকোনো একটি গ্রহণ করে; `/v1/music/plan`-এর জন্য `prompt` আবশ্যক
এবং ঐচ্ছিকভাবে `source_composition_plan` গ্রহণ করে। নেটিভ schema-গুলো অতিরিক্ত
প্রোভাইডার field বজায় রাখে, যাতে composition-plan version এবং fine-tuning option ElevenLabs পর্যন্ত পৌঁছায়।

সমন্বিত `/v1/music/generations` endpoint-টিও `elevenlabs/music_v1`,
`elevenlabs/music_v2` এবং `elevenlabs/music_v2_5` গ্রহণ করে। একটি সক্রিয় ElevenLabs connection থাকলে,
এই model-গুলো music catalog-এ প্রকাশিত হয়। এই endpoint
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}` রিটার্ন করে। এর `duration` field
সেকেন্ডে থাকে এবং `music_length_ms`-এ map হয়; সুস্পষ্টভাবে দেওয়া `music_length_ms` অগ্রাধিকার পায়।
`instrumental`, `force_instrumental`-এ map হয়, যেখানে নেটিভ field অগ্রাধিকার পায়।
স্ট্রিমিংয়ের জন্য নেটিভ streaming endpoint এবং শুধুমাত্র composition plan দ্বারা চালিত request-এর জন্য নেটিভ composition endpoint ব্যবহার করুন।

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Upstream call-এর আগে endpoint, model, budget এবং connection-সংক্রান্ত বিধিনিষেধ প্রযোজ্য হয়। নেটিভ
route-গুলো upstream status code এবং error body অপরিবর্তিতভাবে রিটার্ন করে, যার মধ্যে plan
বিধিনিষেধের জন্য `402` এবং quota limit-এর জন্য `429` অন্তর্ভুক্ত। উপস্থিত থাকলে `character-cost`, `song-id`, `request-id` এবং `retry-after`
header-গুলো বজায় রাখা হয়। বিনামূল্যের credit balance থাকলেই প্রতিটি
music model, output format বা API feature-এ access নিশ্চিত হয় না: প্রতিটি request-এর entitlement ElevenLabs নির্ধারণ করে।
সমন্বিত endpoint OmniRoute-এর normalized error envelope-এ error status code বজায় রাখে।

Upstream contract: [sound effect](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[music composition](https://elevenlabs.io/docs/api-reference/music/compose) এবং
[streaming music details](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream)।

> কোনো Docker/Compose সার্ভিসের নাম; এগুলোকে সরাসরি কল করা হয়, কখনোই `HTTP(S)_PROXY` বা কোনো
> সংযোগের পিন করা প্রক্সির মাধ্যমে নয়)। অন্য যেকোনো
> হোস্টে থাকা নোড—যেমন কোনো LAN বক্স বা Tailscale পিয়ার—শুধু তখনই ব্যবহারযোগ্য, যখন অপারেটর
> `RERANK_REMOTE_PROVIDER_NODES` ফিচার ফ্ল্যাগটি সক্রিয় করেন **এবং** নোডটির বেস URL প্রোভাইডারের
> আউটবাউন্ড URL নীতি (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`) পাস করে।
> মেমরি ইঞ্জিনের রির্যাঙ্ক ধাপটি লুপব্যাকের মাধ্যমে এই রুটকে
> কল করে, তাই Memory সেটিংসে `rerankProviderModel`-এর ক্ষেত্রেও একই নিয়ম প্রযোজ্য।
>
> **লোকাল সার্ভারের বিন্যাস:** নোডটিকে `<base>/v1/rerank`-এ কল করা হয় এবং 404 পাওয়া গেলে `<base>/rerank`-এ
> (Infinity, TEI) কল করা হয়। আপস্ট্রিম বডিতে Cohere/OpenAI নামকরণ (`documents`,
> `return_documents`) এবং TEI নামকরণ (`texts`, `return_text`) উভয়ই থাকে, আর আপস্ট্রিম প্রতিক্রিয়াটি
> Cohere এনভেলপে স্বাভাবিকীকরণ করা হয়: TEI-এর সরাসরি `[{index, score, text}]`, হালকা গেটওয়ে থেকে পাওয়া `{results: [{index, score}]}`
> এবং Voyage-ধাঁচের `{data: [...]}`—সবই ক্লায়েন্টের কাছে
> `{results: [{index, relevance_score, document?}]}` হিসেবে ফেরত আসে, স্কোর অনুযায়ী সাজানো এবং `top_n`-এ সীমাবদ্ধ অবস্থায়।

> **প্রোভাইডার-নোড আবিষ্কার:** OpenAI-সামঞ্জস্যপূর্ণ কোনো প্রোভাইডার নোডের মডেলগুলো নোড প্রিফিক্সের অধীনে `GET /v1/models`-এ
> দেখা যায়। যেসব সারিতে কোনো এন্ডপয়েন্ট মেটাডেটা নেই (লোকাল `/v1/models` তালিকায় যা সাধারণত দেখা যায়)
> সেগুলো নোডটির `apiType` উত্তরাধিকারসূত্রে পায়, ফলে কোনো `embeddings` নোডের মডেলগুলো চ্যাটে ডিফল্ট না হয়ে `type: "embedding"` হয় এবং কোনো
> `rerank` নোডের মডেলগুলো `type: "rerank"` হয়; তবে সিঙ্ক করা বা ম্যানুয়ালি যোগ করা কোনো সারিতে সুস্পষ্ট
> `supportedEndpoints` থাকলে সেটিই অগ্রাধিকার পায়।

### নিবেদিত প্রোভাইডার রুট

```bash
POST /v1/providers/{provider}/chat/completions
POST /v1/providers/{provider}/embeddings
POST /v1/providers/{provider}/images/generations
```

প্রোভাইডার প্রিফিক্স অনুপস্থিত থাকলে তা স্বয়ংক্রিয়ভাবে যোগ করা হয়। অমিল মডেলগুলো `400` ফেরত দেয়।

## Files API

ব্যাচ ইনপুট/আউটপুট এবং ফাইল-পারপাস আপলোডের জন্য OpenAI-সামঞ্জস্যপূর্ণ ফাইল এন্ডপয়েন্ট।

| মেথড   | পাথ                      | বিবরণ                                                                                                                      |
| ------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | একটি ফাইল আপলোড করে (মাল্টিপার্ট: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — সর্বোচ্চ 512 MiB |
| GET    | `/v1/files`              | প্রমাণীকৃত API কী-এর ফাইলগুলোর তালিকা দেখায়                                                                               |
| GET    | `/v1/files/[id]`         | একটি ফাইলের মেটাডেটা পুনরুদ্ধার করে                                                                                        |
| DELETE | `/v1/files/[id]`         | একটি ফাইল মুছে দেয়                                                                                                        |
| GET    | `/v1/files/[id]/content` | অপরিবর্তিত ফাইল বডি স্ট্রিম করে ফেরত দেয়                                                                                  |

**প্রমাণীকরণ:** Bearer API কী — `getApiKeyRequestScope`-এর মাধ্যমে ফাইলগুলো প্রতিটি API কী অনুযায়ী সীমাবদ্ধ। একটি কী
শুধু নিজের ফাইল দেখতে, ডাউনলোড করতে এবং মুছতে পারে; কী ছাড়া একটি ড্যাশবোর্ড সেশন সম্পূর্ণ
ইনস্ট্যান্স পড়তে পারে; মালিকবিহীন কোনো ফাইলে (বেনামী বা ড্যাশবোর্ড-সেশন আপলোড) প্রতিটি
নন-সেশন কলারের প্রবেশাধিকার প্রত্যাখ্যান করা হয়। `GET /v1/files` কোনো বেনামী কলারকে — এবং এমন কোনো প্রদত্ত কী-কে যা
সমাধান করা যায় না — `REQUIRE_API_KEY=false` হলেও, সব টেন্যান্টের
ফাইল তালিকাভুক্ত করার পরিবর্তে `401` দিয়ে প্রত্যাখ্যান করে (GHSA-m3hp-hq9g-fpmv, GHSA-2jm2-mpx8-6523)।

## Batches API

OpenAI-সামঞ্জস্যপূর্ণ ব্যাচ প্রক্রিয়াকরণ।

| মেথড   | পাথ                       | বিবরণ                                                                                                              |
| ------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| POST   | `/v1/batches`             | ব্যাচ তৈরি করে — বডি `v1BatchCreateSchema` দ্বারা যাচাই করা হয় (`input_file_id`, `endpoint`, `completion_window`) |
| GET    | `/v1/batches`             | ব্যাচগুলোর তালিকা দেখায়                                                                                           |
| GET    | `/v1/batches/[id]`        | ব্যাচের অবস্থা + `request_counts` পুনরুদ্ধার করে                                                                   |
| DELETE | `/v1/batches/[id]`        | একটি সমাপ্ত/ব্যর্থ ব্যাচ মুছে দেয়                                                                                 |
| POST   | `/v1/batches/[id]/cancel` | চলমান একটি ব্যাচ বাতিল করে                                                                                         |

**প্রমাণীকরণ:** Bearer API কী। ফাইলের মতো একই ত্রিমুখী নিয়মের অধীনে ব্যাচগুলো প্রতিটি API কী অনুযায়ী
সীমাবদ্ধ: শুধু নিজস্ব কী, ড্যাশবোর্ড সেশনে ইনস্ট্যান্সজুড়ে প্রবেশাধিকার, এবং মালিকবিহীন রেকর্ডে প্রতিটি
নন-সেশন কলারের প্রবেশাধিকার প্রত্যাখ্যান করা হয় (পুনরুদ্ধার, মোছা, বাতিল করা এবং তৈরির সময় `input_file_id` যাচাই)।
`GET /v1/batches` কোনো বেনামী কলারকে `REQUIRE_API_KEY=false` হলেও `401` দিয়ে প্রত্যাখ্যান করে।

## অনুসন্ধান API

ওয়েব/অনুসন্ধান প্রদানকারীর বিমূর্তকরণ (Tavily, Brave, Exa, Serper ইত্যাদি)।

| পদ্ধতি | পাথ                    | বিবরণ                                                                                               |
| ------ | ---------------------- | --------------------------------------------------------------------------------------------------- |
| GET    | `/v1/search`           | কনফিগার করা অনুসন্ধান প্রদানকারী ও সক্ষমতাগুলোর তালিকা প্রদর্শন                                     |
| POST   | `/v1/search`           | অনুসন্ধান কোয়েরি চালানো — বডি `v1SearchSchema` দ্বারা যাচাই করা হয়, ক্যাশিং/কোয়ালেসিং সমর্থন করে |
| GET    | `/v1/search/analytics` | প্রতি-প্রদানকারীর হিট/লেটেন্সি/ক্যাশ পরিসংখ্যান                                                     |

**প্রমাণীকরণ:** Bearer API কী (`extractApiKey` + `isValidApiKey`)। অনুসন্ধান নীতি `enforceApiKeyPolicy`-এর মাধ্যমে প্রয়োগ করা হয়।

### Exa এবং Tavily-এর `provider_options`

Exa এবং Tavily নেমস্পেসযুক্ত একটি ব্যাগ থেকে প্রদানকারী-নির্দিষ্ট ফিল্ড পড়ে:
`provider_options.exa` (অথবা `provider_options["exa-search"]`) এবং `provider_options.tavily`
(অথবা `provider_options["tavily-search"]`)। শুধু নিচের কীগুলোই ফরওয়ার্ড করা হয়। প্রতিটি কী
`open-sse/handlers/search/providerOptionsPassthrough.ts`-এ তার নিজস্ব Zod স্কিমার বিপরীতে
যাচাই করা হয় এবং ভুল টাইপের কী বাদ দেওয়া হয়। প্রমাণীকরণ, বেস URL,
`stream` এবং `outputSchema`-সহ অন্য যেকোনো কী উপেক্ষা করা হয়। অন্যান্য প্রদানকারীর ব্যবহৃত
ফ্ল্যাট কীগুলো (`cx`, `depth`, ...) আগের মতোই কাজ করে।

| প্রদানকারী | শীর্ষ-স্তরের ফিল্ড                                                                                                                                                                                                                                                                                                                                                        | নেস্টেড                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa        | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (ফ্ল্যাট প্রিমিটিভ), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                            | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` ডিফল্ট `{ text: true, highlights: true }`-এর ওপর মার্জ করা হয় |
| Tavily     | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                     |

জেনেরিক ফিল্ডগুলো সর্বদা অগ্রাধিকার পায়: `query`, `max_results`, `filters` (ডোমেইন), `country` এবং
`search_type` থেকে প্রাপ্ত টপিক। Exa-তে `search_type: "news"` ব্যবহার করলে `category: "news"` অপরিবর্তিত থাকে।
Tavily `search_type: "finance"`-ও গ্রহণ করে (`topic: "finance"`)।

জেনেরিক `time_range` এখন উভয় প্রদানকারীর কাছেই পৌঁছায়: Exa পায় `startPublishedDate` (ISO
টাইমস্ট্যাম্প) এবং Tavily পায় `start_date` (`YYYY-MM-DD`)। `provider_options`-এ একটি স্পষ্ট তারিখ
দেওয়া থাকলে সেটি ম্যাপ করা তারিখকে ওভাররাইড করে।

Exa-এর ফলাফলগুলো `provider_raw`-এ `id`, `highlight_scores`, `summary`, `subpages`, `entities` এবং `extras`
অপরিবর্তিত রাখে। Tavily-এর ফলাফলগুলো `images` এবং `favicon` অপরিবর্তিত রাখে।

খরচের হিসাব এখনো ফ্ল্যাট রেজিস্ট্রি `costPerQuery`। Tavily প্রতি কলে
`search_depth: "advanced"`-এর জন্য বেশি ক্রেডিট চার্জ করে, এবং সেই পার্থক্য
`usage.search_cost_usd`-এ প্রতিফলিত হয় না।

## Web Fetch API

কনফিগার করা web-fetch প্রদানকারীর (Firecrawl, Jina Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract) মাধ্যমে কোনো URL থেকে কনটেন্ট এক্সট্র্যাক্ট করুন।

Parallel Extract (`parallel-search`, Parallel Search-এর একই API key) শুধুমাত্র Markdown
ফেরত দেয় — অন্য যেকোনো `format`-এর ক্ষেত্রে `400` ফেরত আসে — এবং কনটেন্টের সীমা 100,000 অক্ষর। যখন
লক্ষ্য পেজটিই এক্সট্র্যাক্ট করা যায় না, তখন upstream একটি HTTP 200-এর মধ্যে সেটি রিপোর্ট করে;
OmniRoute সেটিকে একটি নির্দিষ্ট বার্তাসহ `422` হিসেবে প্রকাশ করে।

| মেথড | পাথ             | বিবরণ                                                                     |
| ---- | --------------- | ------------------------------------------------------------------------- |
| POST | `/v1/web/fetch` | একটি URL ফেচ/স্ক্র্যাপ করে — body `v1WebFetchSchema` দ্বারা যাচাই করা হয় |

**প্রমাণীকরণ:** Bearer API key (`extractApiKey` + `isValidApiKey`)। নীতি `enforceApiKeyPolicy`-এর মাধ্যমে প্রয়োগ করা হয়।

**কোটা-সচেতন fallback (#8297):** যখন সুস্পষ্ট কোনো `provider` দেওয়া হয় না, তখন pool-টি
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) নির্দিষ্ট
অগ্রাধিকারক্রমে (fill-first) অনুসরণ করা হয় — rate-limited কিন্তু কনফিগার করা কোনো প্রদানকারী অনুরোধটি
সঙ্গে সঙ্গে বন্ধ করার পরিবর্তে এড়িয়ে যাওয়া হয়, এবং retryable/quota-সংক্রান্ত upstream ব্যর্থতা
(HTTP 429 সর্বদা; Firecrawl/Tavily/TinyFish-এর quota-ধরনের free tier-এর ক্ষেত্রে 402/403 —
Jina Reader-এর ক্ষেত্রে নয়, এবং সাধারণ 400 bad request-এর ক্ষেত্রে কখনোই নয়) অনুরোধের সময়
পরবর্তী এখনো চেষ্টা না-করা credentialed প্রদানকারীর কাছে যায়। pool-এর প্রতিটি প্রদানকারী
নিঃশেষ হয়ে গেলে, endpoint আগের সাধারণ `400`-এর পরিবর্তে একটি মাত্র `429`
(`Retry-After` header-সহ) ফেরত দেয়। যখন কোনো সুস্পষ্ট `provider` অনুরোধ করা হয়,
তখন **কোনো** নীরব fallback হয় না — rate-limited বা ব্যর্থ সুস্পষ্ট প্রদানকারী
নিজস্ব error প্রকাশ করে (rate-limited হলে `429`, অন্যথায় upstream
status)।

## WebSocket স্ট্রিমিং

```bash
GET /v1/ws?handshake=1
```

একটি WebSocket upgrade handshake যাচাই করে এবং wire protocol-এর উদাহরণ বার্তাগুলো (`request`, `cancel`) ফেরত দেয়। প্রকৃত WS frame-গুলো Next.js route table-এর বাইরে থাকা bundled WS server দ্বারা পরিচালিত হয়।

**প্রমাণীকরণ:** handshake-এর সময় Bearer API key।

### WebSocket-এর মাধ্যমে Responses API (শুধুমাত্র codex)

```bash
# HTTP API-এর একই host:port (ডিফল্ট 20128); connection upgrade করুন:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (অথবা: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# প্রথম frame অবশ্যই response.create হতে হবে:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

একটি Responses-API-over-WebSocket proxy **একচেটিয়াভাবে `codex`-এর সঙ্গে** (ChatGPT
backend) সংযুক্ত। এটি API/dashboard-এর একই port-এ `/v1/responses`,
`/responses` এবং `/api/v1/responses` path-এ শোনে। প্রথম `response.create` frame-এ এটি
অভ্যন্তরীণ `codex-responses-ws` bridge-এর মাধ্যমে প্রমাণীকরণ ও প্রস্তুতি সম্পন্ন করে, একটি
codex OAuth connection নির্বাচন করে এবং `wreq-js` transport-এর মাধ্যমে
`wss://chatgpt.com/backend-api/codex/responses`-এ tunnel করে। **codex-বহির্ভূত model প্রত্যাখ্যাত হয়** (`codex_ws_provider_required`)।
quota-share routing-এর জন্য `model: "qtSd/<group>/codex/<model>"` ব্যবহার করুন। এটি
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`-এ বাস্তবায়িত।

**প্রমাণীকরণ:** handshake-এর সময় Bearer API key। bundled HTTP server (`server-ws.mjs`)
অবশ্যই সক্রিয় entrypoint হতে হবে (`app/server-ws.mjs` বিদ্যমান থাকলে ডিফল্টভাবেই এটি সক্রিয় থাকে)।

#### Model id: সরাসরি ChatGPT id ব্যবহার করুন (`codex/` prefix ছাড়া)

OpenAI **Codex CLI**, `supports_websockets = true` হলে client-side-এ model-এর নাম যাচাই করে
এবং `codex/gpt-5.5`-এর মতো **provider-prefixed id প্রত্যাখ্যান করে**
(`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`)। **সরাসরি** id পাঠান (যেমন `gpt-5.5`)। OmniRoute-এর bridge
শুধুমাত্র codex-এর জন্য, তাই upstream-এ tunnel করার আগে এটি একটি সরাসরি id-কে codex model হিসেবে
(`resolveCodexWsModelInfo`) পুনরায় resolve করে — যদিও সরাসরি
`gpt-5.5` অন্যথায় HTTP-এর মাধ্যমে অন্য প্রদানকারীর কাছে route হতো।

#### OpenAI Codex CLI কনফিগার করা

`~/.codex/config.toml`-এ WebSocket
support-সহ একটি custom provider যোগ করে Codex CLI-কে OmniRoute-এর দিকে নির্দেশ করুন (বিদ্যমান
config পরিবর্তন এড়াতে আলাদা `CODEX_HOME` ব্যবহার করুন):

```toml
model = "gpt-5.5"                 # সরাসরি id — "codex/gpt-5.5" নয়
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # শেষে slash নয়; WS URL derive করা হয় (production-এ https/wss ব্যবহার করুন)
wire_api = "responses"                    # Feb 2026 থেকে একমাত্র সমর্থিত value
supports_websockets = true                # Responses-over-WS transport সক্রিয় করে
env_key = "OMNIROUTE_API_KEY"             # OmniRoute API key ধারণ করে (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # একটি OmniRoute API key (REQUIRE_API_KEY=false হলে যেকোনো key)
codex exec "Responda apenas: PONG"
```

CLI, `base_url + /responses`-কে একটি WebSocket-এ upgrade করে এবং OmniRoute সেটিকে
নির্বাচিত codex OAuth connection-এ tunnel করে। স্থানীয়
server-এর বিপরীতে end-to-end যাচাই করা হয়েছে: ChatGPT `codex.rate_limits` + `response.created` ফেরত দেয় এবং
completion stream করে।

## স্ব-পরিষেবা ব্যবহার (`/api/usage/om-usage`)

যেকোনো API কী **নিজস্ব** ব্যবহার ও কোটা পড়তে পারে—কোনো ব্যবস্থাপনা প্রমাণীকরণ ছাড়াই। এটি সেই এন্ডপয়েন্ট, যা কোনো
ক্লায়েন্ট (CLI, OmniCopilot প্যানেল) একজন কী-ধারককে তাঁর ব্যয় দেখাতে ব্যবহার করে।

```bash
# টেক্সট ফর্ম (ঐতিহাসিক চুক্তি—টার্মিনালের জন্য প্লেইন টেক্সট)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# স্ট্রাকচার্ড ফর্ম—একটি UI যা ব্যবহার করে
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

কীটিতে অবশ্যই **`allowUsageCommand`** সক্রিয় থাকতে হবে (ডিফল্টভাবে বন্ধ—ড্যাশবোর্ডের API-কী
ম্যানেজার প্রতিটি কীর জন্য এটি টগল করে)। এটি ছাড়া এন্ডপয়েন্টটি `403` উত্তর দেয়।

`?format=json` একটি বৈষম্যসূচক কাঠামো ফেরত দেয়, যাতে কোনো কলার প্রত্যাখ্যানের ফলাফল থেকে কখনো ডেটা ফিল্ড না পড়ে।
সফল হলে:

```jsonc
{
  "allowed": true,
  // কেবল তখনই উপস্থিত থাকে, যখন কীটি প্রতি-কী ব্যবহারসীমা (দৈনিক/সাপ্তাহিক USD) বেছে নিয়েছে:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // নির্বাচিত প্রোভাইডারের কোটা স্ন্যাপশট, অথবা এখনো কিছু ক্যাশ না হলে null:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // প্রতিটি সংযোগের স্ন্যাপশট, যাতে একটি UI একাধিক প্রোভাইডার পাশাপাশি রেন্ডার করতে পারে:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

প্রত্যাখ্যাত হলে (`401` ভুল কী / `403` অনুমোদিত নয়), একই রুট
`{ "allowed": false, "error": { "message": "…" } }` ফেরত দেয়—উপস্থিত-কিন্তু-খালি `personal`/`provider`
(কী অনুমোদিত, তবে এখনো কিছু জানা যায়নি) প্রত্যাখ্যান থেকে ভিন্ন অবস্থা, এবং শুধু JSON ফর্মই
এগুলোর মধ্যে পার্থক্য করে।

**প্রমাণীকরণ:** কলারের নিজস্ব Bearer API কী, যা `isValidApiKey` দিয়ে যাচাই করা হয়—এটি ব্যবস্থাপনা
সারফেস (`/api/keys/…`) _নয়_, যা `requireManagementAuth`-এর আড়ালেই থাকে।

### অপরিশোধিত বনাম কাটঅফ-সমন্বিত কোটা শতাংশ

`/api/usage/om-usage` ব্যবহার করার সময়, কলারদের **প্লেইন-টেক্সট আউটপুট** এবং স্ট্রাকচার্ড
**JSON আউটপুটে** দেখানো শতাংশের মধ্যকার পার্থক্যটি লক্ষ্য করা উচিত:

| দিক                    | প্লেইন-টেক্সট ফরম্যাট (`/api/usage/om-usage` / `@@om-usage`)                                       | JSON ফরম্যাট (`?format=json`)                                           |
| :--------------------- | :------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------- |
| **আউটপুট ফিল্ড**       | `NN% left` (যেমন, `20% left`)                                                                      | `provider.quotas` / `providers[].quotas`                                |
| **পরিমাপ**             | **কাটঅফ-সমন্বিত ব্যবহারযোগ্য বরাদ্দ**: কাটঅফ থ্রেশহোল্ডের ওপরে অবশিষ্ট সক্ষমতা                     | **অপরিশোধিত আপস্ট্রিম কোটা**: প্রোভাইডারের অসমন্বিত পরিমাপ              |
| **কাটঅফ স্কেলিং**      | `effectiveRemainingPercent()` দিয়ে স্কেল করা হয়, যাতে সুরক্ষিত রিজার্ভকে `0% left` হিসেবে দেখায় | নেই (প্রোভাইডারের রিপোর্ট করা অপরিশোধিত স্ন্যাপশট মান)                  |
| **থ্রেশহোল্ড ডেটা**    | প্রদর্শিত শতাংশে অন্তর্ভুক্ত                                                                       | প্রতি সংযোগে `quotaWindowThresholds`-এ সংরক্ষিত (অথবা সার্ভারের ডিফল্ট) |
| **প্রধান ব্যবহারকারী** | ইন্টার্যাক্টিভ CLI, টার্মিনাল প্রম্পট, মানব অপারেটর                                                | প্রোগ্রাম্যাটিক ইন্টিগ্রেশন, ড্যাশবোর্ড, অ্যানালিটিক্স, বিলিং ট্র্যাকার |

#### কাটঅফ সমন্বয় সূত্র

OmniRoute আপস্ট্রিম নিঃশেষ হওয়া প্রতিরোধ করতে সক্রিয় কোটা কাটঅফ সমর্থন করে (সংযোগের
`quotaWindowThresholds`, প্রোভাইডারের ডিফল্ট অথবা গ্লোবাল রেজিলিয়েন্স সেটিংসের মাধ্যমে কনফিগার করা)। কোনো কোটা উইন্ডোতে
একটি কাটঅফ থ্রেশহোল্ড (যেমন, `cutoff = 25%`) সক্রিয় থাকলে, টেক্সট রেন্ডারার অবশিষ্ট বরাদ্দ এভাবে গণনা করে:

- যদি `remaining <= cutoff` হয়: `0%` ফেরত দেয়।
- যদি `remaining > cutoff` হয়: `((remaining - cutoff) / (100 - cutoff)) * 100` ফেরত দেয়।

ফরম্যাট করা টেক্সট আউটপুট এটিকে নিকটতম পূর্ণসংখ্যায় রাউন্ড করে (`Math.round(...)`)।

#### ব্যাখ্যামূলক উদাহরণ

**60% অপরিশোধিত ব্যবহার** (অতএব **40% অপরিশোধিত অবশিষ্ট কোটা**) এবং কনফিগার করা
**25% অবশিষ্ট-কোটা কাটঅফ** থ্রেশহোল্ডসহ একটি প্রোভাইডার উইন্ডো বিবেচনা করুন:

| উপস্থাপনা                           | গণনা                                               | অবশিষ্ট |          অন্তর্নিহিত ব্যবহার          |
| :---------------------------------- | :------------------------------------------------- | :-----: | :-----------------------------------: |
| **অপরিশোধিত JSON (`?format=json`)** | আপস্ট্রিম স্ন্যাপশট (`quotas[window]`)             | **40%** |                **60%**                |
| **টেক্সট ফরম্যাট (`NN% left`)**     | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (`100 - remaining` গণনা করলে) |

- **টেক্সটে কেন 20% অবশিষ্ট দেখায়:** অ্যাকাউন্টে অবশিষ্ট 40% প্রকৃত কোটার মধ্যে 25% কাটঅফ
  নীতির মাধ্যমে সংরক্ষিত। রাউটার এই সংযোগে রাউটিং বন্ধ করার আগে কলারের ব্যবহারযোগ্য 75% হেডরুমের
  মধ্যে মাত্র 15% অবশিষ্ট থাকে। স্কেলিং নিশ্চিত করে যে ঠিক যখন রাউটিং বন্ধ হবে, তখন সংযোগটি
  নিঃশেষিত হওয়ার সংকেত (`0% left`) দেয়।
- **JSON কেন অপরিশোধিত মান সংরক্ষণ করে:** JSON পেলোড সঠিক প্রোভাইডার স্ন্যাপশট (`UsageSnapshot`)
  ফেরত দেয়, যাতে বাহ্যিক টুলগুলো সার্ভার-সাইড ক্ষতিকর স্কেলিং ছাড়াই প্রকৃত আপস্ট্রিম ব্যবহার এবং সংযোগ-স্তরের
  `quotaWindowThresholds` অ্যাক্সেস করতে পারে।

#### ব্যবহারকারী মাইগ্রেশন নির্দেশিকা

যদি কোনো বাহ্যিক ইন্টিগ্রেশন (যেমন একটি এডিটর প্লাগইন বা এজেন্ট এক্সটেনশন) আগে টেক্সট
এন্ডপয়েন্ট (`NN% left`) স্ক্র্যাপ করে থাকে এবং ব্যবহৃত শতাংশ `100 - NN` হিসেবে গণনা করে থাকে, তাহলে `?format=json`-এ স্থানান্তরের অর্থ হলো:

- অপরিশোধিত JSON মান পড়লে **প্রকৃত আপস্ট্রিম ব্যবহার** প্রতিফলিত হবে (উপরের উদাহরণে 60% ব্যবহৃত)।
- যদি ইন্টিগ্রেশনটি টেক্সট এন্ডপয়েন্টের ব্যবহারযোগ্য-বরাদ্দের অর্থবিদ্যা বজায় রাখতে চায়, তাহলে এটি সংযোগ-স্তরের ওভাররাইডগুলোর জন্য `quotaWindowThresholds` ব্যবহার করে
  ক্লায়েন্টের দিকে কার্যকর অবশিষ্টের সূত্রটি মূল্যায়ন করতে পারে।

### ল্যাটেন্সির প্রভাব

একটি সেমান্টিক ক্যাশ HIT **আপস্ট্রিম কল ছাড়াই** ক্যাশ থেকে প্রতিক্রিয়া সরবরাহ করে, তাই রিপোর্ট করা `X-OmniRoute-Response-Latency` প্রায় শূন্য
(মূল আপস্ট্রিম ল্যাটেন্সি নির্বিশেষে)। ল্যাটেন্সি-সংবেদনশীল ক্লায়েন্টগুলোর
(বেঞ্চমার্কিং, p50/p99 পর্যবেক্ষণ) `X-OmniRoute-Cache-Latency` প্রতিক্রিয়া হেডার পরীক্ষা করা উচিত:

| মান           | অর্থ                                                                        |
| ------------- | --------------------------------------------------------------------------- |
| `synthetic`   | ক্যাশ থেকে প্রতিক্রিয়া দেওয়া হয়েছে; ল্যাটেন্সি প্রকৃত আপস্ট্রিম সময় নয় |
| _(অনুপস্থিত)_ | প্রকৃত আপস্ট্রিম কল থেকে পাওয়া প্রতিক্রিয়া                                |

### প্রতি-কী ক্যাশ বাইপাস

API কীগুলো `cacheDefaultMode`-এর মাধ্যমে সেমান্টিক ক্যাশ রিড থেকে অপ্ট আউট করতে পারে:

| মান      | আচরণ                                                            |
| -------- | --------------------------------------------------------------- |
| `legacy` | স্বাভাবিক ক্যাশ আচরণ (ডিফল্ট)                                   |
| `bypass` | ক্যাশ লুকআপ সম্পূর্ণভাবে এড়িয়ে যান; সর্বদা আপস্ট্রিমে কল করুন |

কী তৈরির সময় (`POST /api/keys`) সেট করুন অথবা (`PATCH /api/keys/[id]`) দিয়ে আপডেট করুন:

```json
{ "cacheDefaultMode": "bypass" }
```

### প্রতি-অনুরোধ বাইপাস

কী সেটিংস নির্বিশেষে যেকোনো অনুরোধ ক্যাশ বাইপাস করতে পারে:

```
X-OmniRoute-No-Cache: true
```

সিঙ্ক/আমদানি করা মডেলের জন্য, `PUT /api/provider-models` `provider`, `modelId`, এবং
`maxOutputTokenOverride` গ্রহণ করে: একটি ধনাত্মক পূর্ণসংখ্যা ম্যানুয়াল আউটপুট-টোকেন সীমা নির্ধারণ করে, এবং `null`
এটি মুছে দিয়ে ডিফল্ট পুনরুদ্ধার করে। `GET /api/provider-models?provider=<provider>` এসব
মান `modelOutputOverrides`-এ ফেরত দেয়, যার মধ্যে কাস্টম-মডেল সারি না থাকা মডেলও অন্তর্ভুক্ত। ওভাররাইডটি
রানটাইম `max_output_tokens` সক্ষমতা ব্যবহার করে এবং মডেল পুনরায় সিঙ্ক করার পরও বজায় থাকে। OpenAI-সামঞ্জস্যপূর্ণ
প্রদানকারী পেজে একই সম্পাদনা/মুছে ফেলার নিয়ন্ত্রণ রয়েছে এবং স্পষ্ট ভিশন সমর্থন থাকা মডেলগুলো চিহ্নিত করা হয়।

কাস্টম Chat Completions নোডগুলো স্পষ্ট রিজনিং অপ্ট-আউটকে আপস্ট্রিম ব্যাকএন্ডের উপযোগী করে। একটি
সফল সংযোগ পরীক্ষা প্রতিটি সঠিক মডেল ID-এর জন্য স্বয়ংক্রিয়ভাবে চ্যাট-টেমপ্লেট নিয়ন্ত্রণ নির্বাচন করে,
যার `/models` এন্ট্রি কোনো স্বীকৃত `owned_by` মান প্রমাণ করে: `vllm`, `sglang`, অথবা `llamacpp`।
স্বচ্ছ OpenAI-সামঞ্জস্যপূর্ণ র্যাপারগুলো একটি নেস্টেড `openai` অবজেক্টের মধ্যে মূল মডেল এন্ট্রি
সংরক্ষণ করতে পারে; শনাক্তকরণ এমন সর্বোচ্চ তিনটি আবরণ অনুসরণ করে। মালিকানা অনুপস্থিত, অজানা, অথবা
পরস্পরবিরোধী হলে মডেলগুলো সাধারণ OpenAI আচরণ বজায় রাখে। শনাক্তকরণ বিদ্যমান ক্যাটালগ অনুরোধ পুনরায় ব্যবহার করে,
কোনো কমপ্লিশন টোকেন তৈরি করে না, এবং সংযোগ এন্ডপয়েন্ট পরিবর্তিত হলে এটি অকার্যকর হয়ে যায়।

এই মেটাডেটা প্রকাশ করে না এমন কোনো ব্যাকএন্ডের জন্য আচরণটি নির্দিষ্ট করে দিতে, বিদ্যমান আংশিক
প্রদানকারী আপডেট API ব্যবহার করুন:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

ওই বডিটি `PUT /api/providers/<connection-id>`-এর সঙ্গে পাঠান। সেই সংযোগে, `none`-এর একটি স্পষ্ট
রিজনিং প্রচেষ্টা `chat_template_kwargs.thinking=false` এবং
`chat_template_kwargs.enable_thinking=false` হিসেবে পাঠানো হয়। কোনো সার্ভার-সাইড রিজনিং নিয়ম একটি প্রচেষ্টা
বলবৎ না করলে, স্পষ্ট নেটিভ টেমপ্লেট মানগুলোই কর্তৃত্বপূর্ণ থাকে। সেটিংটি কেবল তখনই প্রযোজ্য, যখন কোনো কাস্টম
OpenAI-সামঞ্জস্যপূর্ণ সংযোগ একটি Chat Completions বডি পাঠায়; Responses অনুরোধ এবং সাধারণ
প্রদানকারীরা তাদের নেটিভ অনুরোধ কাঠামো বজায় রাখে। সাধারণ OpenAI
`reasoning_effort` পাসথ্রু বলবৎ করতে `reasoningControl`-কে `openai` হিসেবে সেট করুন, অথবা স্বয়ংক্রিয় শনাক্তকরণ ব্যবহার করতে এটি বাদ দিন/`null` হিসেবে সেট করুন।

Claude Code অটো-মোড ক্লাসিফায়ার অনুরোধে কোনো স্পষ্ট রিজনিং নিয়ন্ত্রণ না থাকলে, সেগুলোর নেটিভ
থিংকিং ডিফল্টভাবে নিষ্ক্রিয় থাকে। শনাক্তকরণ মডেলের নাম বা কমপ্লিশন সীমা নয়, Claude-ফরম্যাটের
অনুরোধে ক্লাসিফায়ারের সিস্টেম মার্কার ব্যবহার করে। স্পষ্ট বডি নিয়ন্ত্রণ, সমর্থিত প্রচেষ্টা/থিংকিং
হেডার, রাউটিং নিয়ম এবং সমাধানকৃত মডেল প্রচেষ্টা তাদের বিদ্যমান অগ্রাধিকার বজায় রাখে। উভয় ক্লাসিফায়ার
ধাপই তাদের প্রম্পট, কমপ্লিশন সীমা, স্টপ সিকোয়েন্স এবং প্রকৃত আপস্ট্রিম অনুমতির সিদ্ধান্ত
বজায় রাখে; দ্বিতীয় ধাপটি এখনও সাধারণ টেক্সট হিসেবে তার অনুরোধকৃত দৃশ্যমান রিজনিং তৈরি করতে পারে।

`PATCH /api/keys/{id}` একটি বিদ্যমান কী-এর অনুমতি হালনাগাদ করে। প্রতিটি `/api/keys*` রুটের মতো, এটিরও ব্যবস্থাপনা অনুমোদন প্রয়োজন ([ব্যবস্থাপনা প্রমাণীকরণ](../guides/MANAGEMENT-AUTH.md) দেখুন), ইনফারেন্স কী নয়। আপনি যেসব ফিল্ড পরিবর্তন করতে চান, শুধু সেগুলোই পাঠান; এগুলোর কোনোটিই নেই এমন অনুরোধ `No valid fields to update` বার্তাসহ প্রত্যাখ্যাত হয়। গৃহীত ফিল্ডগুলো `src/shared/validation/schemas/keys.ts`-এর `updateKeyPermissionsSchema` দ্বারা সংজ্ঞায়িত।

দিয়ে পুনরুদ্ধার) এবং `POST /api/settings/import-json` সক্রিয় ডেটাবেস বা সেটিংস প্রতিস্থাপন করে, তাই কোনো মেশিন
ক্রেডেনশিয়ালও সেখানে `403` পায়; `omniroute sync import` লোকাল CLI ক্রেডেনশিয়াল পাঠায়। একই নিয়ম প্রযোজ্য

স্থায়ীভাবে সংরক্ষিত মানগুলো প্রতিটি ব্যাকআপের পর স্বয়ংক্রিয় ছাঁটাই নিয়ন্ত্রণ করে)। তালিকা দেখা (`GET`) এবং

### সংস্করণ এবং রিলিজ চ্যানেল

```bash
GET /api/system/version
```

শুধু লুপব্যাকের জন্য ম্যানেজমেন্ট রুট (অ্যাডমিন অথ)। এটি চলমান সংস্করণ, সর্বশেষ
প্রকাশিত সংস্করণ এবং স্বয়ংক্রিয় আপডেটের অবস্থা রিটার্ন করে। `releaseChannel` এবং `channels` হলো সংযোজিত
ফিল্ড (rail 3.8.54); `channel` তার অর্থ অপরিবর্তিত রাখে — ড্যাশবোর্ড আপডেটার যে ডিপ্লয়মেন্ট মোড
ব্যবহার করে (`npm`, `source` অথবা `docker-compose`)।

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — চলমান বিল্ডের npm চ্যানেল: `-nightly.*` সংস্করণের জন্য `nightly`,
  অন্যান্য প্রি-রিলিজের (`-rc.*`, `-beta.*`, `-alpha.*`) জন্য `next`, `channels.latest`-এর তুলনায়
  পুরোনো মেজরের কোনো স্থিতিশীল সংস্করণের জন্য `lts`, অন্যথায় `latest`। এটি
  `scripts/release/dist-tag.mjs`-এর একই নিয়ম অনুসরণ করে, যা প্রকাশের সময় npm dist-tag নির্বাচন করে।
- `channels` — `npm view omniroute dist-tags` থেকে প্রতিটি dist-tag-এর প্রকাশিত হেড (রেজিস্ট্রি
  HTTP ফলব্যাক), যা `latest`-এর মতো একই ১০-মিনিটের TTL দিয়ে ক্যাশ করা হয়। `latest` সর্বদা উপস্থিত থাকে
  (প্রথমে `latest` ফিল্ডে, তারপর `"unavailable"`-এ ফলব্যাক করে); `next`, `nightly` এবং `lts` শুধু
  সেই dist-tag বিদ্যমান থাকলেই প্রদর্শিত হয়। একটি `Cache-Control: no-cache` অনুরোধ উভয় লুকআপই রিফ্রেশ করে।

চ্যানেল মডেলটি (`latest` = 4.0 GA পর্যন্ত v3, `next` = rc, `nightly` = `develop` বিল্ড,
`lts` = 4.0 GA-এর পরের v3 প্যাচ) `docs/ops/RELEASE_STRATEGY.md`-এ বর্ণনা করা হয়েছে।

## অডিও ট্রান্সক্রিপশন

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

কনফিগার করা যেকোনো STT প্রদানকারী ব্যবহার করে অডিও ফাইল ট্রান্সক্রাইব করুন। প্রথম পাথ
সেগমেন্টটি নেটিভ প্রদানকারী নির্বাচন করে (`openai/…`, `deepgram/…`)। অন্য কোনো বিক্রেতার
মডেল পুনরায় রপ্তানি করে এমন গেটওয়েগুলো একটি যোগ্যতাসূচক id ব্যবহার করে
(`openrouter/deepgram/nova-3`)।

**অনুরোধ:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**প্রতিক্রিয়া:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**মডেল id-এর উদাহরণ:** `openai/whisper-1` (একটি OpenAI কী প্রয়োজন),
`openrouter/deepgram/nova-3` (একটি OpenRouter কী প্রয়োজন),
`deepgram/nova-3` (একটি নেটিভ Deepgram কী প্রয়োজন)। সরাসরি
`deepgram/nova-3` অনুরোধ OpenRouter ব্যবহার করে **না**।

**সমর্থিত ফরম্যাট:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`।

- টোকেনযুক্ত অ্যালিয়াসগুলো `/v1/*` এবং `/api/tags`-এর মতো একই হ্যান্ডলার পুনরায় ব্যবহার করে; প্রতিক্রিয়ার কাঠামো একই থাকে।

- URL-ভিত্তিক টোকেন OmniRoute-এর বাইরের রিভার্স-প্রক্সি লগ, ব্রাউজার ইতিহাস এবং টেলিমেট্রিতে দেখা যেতে পারে। এগুলোকে ডিফল্ট প্রমাণীকরণ পদ্ধতি হিসেবে নয়, বরং একটি সামঞ্জস্যতার বিকল্প হিসেবে বিবেচনা করুন।

# সব API কী-এর বাজেটের অবস্থা সংগ্রহ করুন

{

> **স্কিমা নোট** (`setBudgetSchema`): `apiKeyId` আবশ্যক; `dailyLimitUsd`, `weeklyLimitUsd`, অথবা `monthlyLimitUsd`-এর মধ্যে অন্তত একটির মান শূন্যের চেয়ে বেশি হতে হবে। ঐচ্ছিক ফিল্ড: `warningThreshold` (0–1), `resetInterval` (`daily` | `weekly` | `monthly`), `resetTime` (`HH:MM`)। পুরোনো `{keyId, limit, period}` কাঠামোটি `400 Bad Request` প্রদান করে।

## টোকেন সীমা

প্রতি-API-key **টোকেন** বাজেট (উপরের USD-ভিত্তিক বাজেট থেকে স্বতন্ত্র)। অনুরোধের পথে ইনলাইনে প্রয়োগ করা হয়: কোনো key-এর বর্তমান উইন্ডোর ব্যবহার তার সীমায় পৌঁছালে, অনুরোধগুলো `429 Too Many Requests` দিয়ে প্রত্যাখ্যান করা হয়। সীমাগুলো একটি নির্দিষ্ট `model`, একটি `provider`-এর জন্য নির্ধারণ করা যেতে পারে, অথবা key-টি জুড়ে `global`ভাবে প্রয়োগ করা যেতে পারে; যখন একাধিক সীমা কোনো অনুরোধের সঙ্গে মিলে যায়, তখন সবচেয়ে কঠোর সীমাটি কার্যকর হয়।

```bash
# একটি key-এর টোকেন সীমাগুলো তালিকাভুক্ত করুন (লাইভ উইন্ডো ব্যবহারসহ)
GET /api/usage/token-limits?apiKeyId=key-123

# একটি টোকেন সীমা তৈরি বা আপডেট করুন
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# id অনুযায়ী একটি টোকেন সীমা মুছুন
DELETE /api/usage/token-limits?id=tl-abc
```

> **স্কিমা নোট** (`setTokenLimitSchema`): `apiKeyId` এবং `scopeType` (`model` | `provider` | `global`) আবশ্যক। `scopeType` যদি `global` না হয়, তাহলে `scopeValue` আবশ্যক (যেমন `model` স্কোপের জন্য একটি model id, `provider` স্কোপের জন্য একটি provider id)। `tokenLimit` অবশ্যই একটি ধনাত্মক পূর্ণসংখ্যা হতে হবে (string থেকে রূপান্তরিত)। ঐচ্ছিক: `id` (তৈরি করতে বাদ দিন, আপডেট করতে প্রদান করুন), `resetInterval` (`daily` | `weekly` | `monthly`, ডিফল্ট `monthly`), `resetTime` (`HH:MM`), `enabled` (ডিফল্ট `true`)। `GET` প্রতিক্রিয়াগুলো প্রতিটি সীমার সঙ্গে `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, এবং `nextResetAt` যোগ করে সমৃদ্ধ করে। এটি একটি management-class endpoint (authz pipeline কেন্দ্রীয়ভাবে auth প্রয়োগ করে)।

## অনুরোধ প্রক্রিয়াকরণ

1. Client `/v1/*`-এ অনুরোধ পাঠায়
2. Route handler `handleChat`, `handleEmbedding`, `handleAudioTranscription`, অথবা `handleImageGeneration` কল করে
3. Model নির্ধারণ করা হয় (সরাসরি provider/model অথবা alias/combo)
4. Account availability filtering সহ স্থানীয় DB থেকে credentials নির্বাচন করা হয়
5. Chat-এর জন্য: `handleChatCore` semantic/signature cache পরীক্ষা করে এবং combo compression settings নির্ধারণ করে
6. সক্রিয় থাকলে provider translation-এর আগে proactive compression চালানো হয় (`lite`, Caveman, RTK, অথবা stacked)
7. Provider executor upstream অনুরোধ পাঠায়
8. প্রতিক্রিয়া আবার client format-এ অনুবাদ করা হয় (chat), অথবা অপরিবর্তিতভাবে ফেরত দেওয়া হয় (embeddings/images/audio)
9. Usage, compression analytics, এবং request logs রেকর্ড করা হয়
10. ত্রুটির ক্ষেত্রে combo rules অনুযায়ী fallback প্রয়োগ করা হয়

সম্পূর্ণ architecture reference: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Combo ব্যবস্থাপনা

উচ্চ-স্তরের routing combos (ইতিমধ্যে `/api/combos*`-এর অধীনে সংক্ষিপ্ত করা হয়েছে) একটি model id pattern থেকে 1:1 অনুপাতেও ম্যাপ করা যেতে পারে, যা একটি OpenAI-style model id-কে স্বচ্ছভাবে একটি combo-তে পুনর্নির্দেশ করতে দেয়।

| Method | Path                             | Description                                                                       |
| ------ | -------------------------------- | --------------------------------------------------------------------------------- |
| GET    | `/api/model-combo-mappings`      | সব model→combo mapping তালিকাভুক্ত করুন                                           |
| POST   | `/api/model-combo-mappings`      | Mapping তৈরি করুন — body: `{pattern, comboId, priority?, enabled?, description?}` |
| GET    | `/api/model-combo-mappings/[id]` | একটি একক mapping পুনরুদ্ধার করুন                                                  |
| PUT    | `/api/model-combo-mappings/[id]` | একটি বিদ্যমান mapping-এর field-গুলো আপডেট করুন                                    |
| DELETE | `/api/model-combo-mappings/[id]` | একটি mapping সরিয়ে ফেলুন                                                         |

**Auth:** management session/API key (`requireManagementAuth`)।

## ওয়েবহুকসমূহ

OmniRoute ইভেন্টগুলোর (অনুরোধ সম্পন্ন হওয়া, কোটা নিঃশেষ হওয়া, কী রোটেশন ইত্যাদি) জন্য আউটবাউন্ড ওয়েবহুক সাবস্ক্রিপশন।

| পদ্ধতি | পাথ                       | বিবরণ                                                                         |
| ------ | ------------------------- | ----------------------------------------------------------------------------- |
| GET    | `/api/webhooks`           | ওয়েবহুকগুলোর তালিকা দেখায় (সিক্রেটগুলো `<prefix>...` হিসেবে মাস্ক করা থাকে) |
| POST   | `/api/webhooks`           | ওয়েবহুক তৈরি করে — বডি: `{url, events?: ["*"], secret?, description?}`       |
| GET    | `/api/webhooks/[id]`      | একটি ওয়েবহুকের তথ্য উদ্ধার করে                                               |
| PUT    | `/api/webhooks/[id]`      | url/events/secret/description আপডেট করে                                       |
| DELETE | `/api/webhooks/[id]`      | একটি ওয়েবহুক সরিয়ে দেয়                                                     |
| POST   | `/api/webhooks/[id]/test` | ওয়েবহুক URL-এ একটি পরীক্ষামূলক পেলোড পাঠায় এবং ডেলিভারি স্ট্যাটাস ফেরত দেয় |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন/API কী (`requireManagementAuth`)।

## নিবন্ধিত কীসমূহ (স্বয়ংক্রিয় ব্যবস্থাপনা)

দৈনিক/প্রতি ঘণ্টার কোটা সহ কোনো ব্যাকিং প্রোভাইডার/অ্যাকাউন্টের বিপরীতে API কী ইস্যু ও রোটেট করতে স্বয়ংক্রিয় কী ব্যবস্থাপনা সাবসিস্টেম এটি ব্যবহার করে।

| পদ্ধতি | পাথ                                   | বিবরণ                                                                                                                                                                                                         |
| ------ | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/registered-keys`             | নিবন্ধিত কীসমূহের তালিকা দেখায় (শুধু মাস্ক করা প্রিফিক্স)                                                                                                                                                    |
| POST   | `/api/v1/registered-keys`             | একটি নতুন নিবন্ধিত কী ইস্যু করে — বডি: `{name, provider?, accountId?, idempotencyKey?, expiresAt?, dailyBudget?, hourlyBudget?}`। কাঁচা কীটি **শুধু একবার** ফেরত দেয়। কোটা প্রত্যাখ্যাত হলে `429` ফেরত দেয়। |
| GET    | `/api/v1/registered-keys/[id]`        | একটি নিবন্ধিত কী-এর মেটাডেটা উদ্ধার করে (কাঁচা উপাদান ছাড়া)                                                                                                                                                  |
| DELETE | `/api/v1/registered-keys/[id]`        | একটি নিবন্ধিত কী বাতিল করে                                                                                                                                                                                    |
| POST   | `/api/v1/registered-keys/[id]/revoke` | সুস্পষ্ট বাতিলকরণ এন্ডপয়েন্ট (DELETE-এর মতো একই প্রভাব)                                                                                                                                                      |

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন/API কী (`requireManagementAuth`) — `/api/keys`-এর মতো একই গার্ড: একটি ড্যাশবোর্ড সেশন, স্থানীয় CLI টোকেন, অথবা `manage`/`admin` স্কোপসহ একটি API কী; শুধু ইনফারেন্সের জন্য ব্যবহৃত API কীগুলো `403` পায়। `/v1/quotas/check` এবং `/v1/issues/report`-ও দেখুন।

## এজেন্ট প্রোটোকল

OmniRoute ব্যবহারকারীদের পক্ষ থেকে দূরবর্তীভাবে সম্পাদিত ক্লাউড এজেন্ট টাস্ক (Claude Code, Codex Cloud, OpenHands ইত্যাদি)।

| পদ্ধতি | পাথ                           | বিবরণ                                                                                                                                             |
| ------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/agents/tasks`        | টাস্কের তালিকা — ঐচ্ছিক `?provider=`, `?status=`, `?limit=` (1–500, ডিফল্ট 50)                                                                    |
| POST   | `/api/v1/agents/tasks`        | টাস্ক তৈরি — বডি `CreateCloudAgentTaskSchema` (`providerId`, `prompt`, `source`, `options?`) দ্বারা যাচাই করা হয়। টাস্ক এনভেলপসহ `201` ফেরত দেয় |
| DELETE | `/api/v1/agents/tasks?id=...` | একটি টাস্ক মুছে দেয়                                                                                                                              |
| GET    | `/api/v1/agents/tasks/[id]`   | টাস্ক পড়ে — `external_id` সেট করা থাকলে আপস্ট্রিম ক্লাউড এজেন্ট থেকে সমলয়ভাবে স্ট্যাটাস রিফ্রেশ করে                                             |
| POST   | `/api/v1/agents/tasks/[id]`   | পৃথকীকৃত অ্যাকশন: `{action: "approve"}`, `{action: "message", message}`, অথবা `{action: "cancel"}`                                                |
| DELETE | `/api/v1/agents/tasks/[id]`   | id অনুযায়ী একটি নির্দিষ্ট টাস্ক মুছে দেয়                                                                                                        |

> **প্রমাণীকরণ:** প্রতিটি মেথডে ম্যানেজমেন্ট প্রমাণীকরণ আবশ্যক (`requireCloudAgentManagementAuth`)। v3.8.0-এর আগে এগুলো প্রমাণীকরণবিহীন ছিল — ব্রেকিং পরিবর্তনের জন্য কমিট `588a0333` দেখুন।

```bash
# একটি Claude Code ক্লাউড টাস্ক তৈরি করুন
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Authorization: Bearer your-management-key" \
  -H "Content-Type: application/json" \
  -d '{"providerId":"claude-code-cloud","prompt":"Fix the failing test","source":{"repo":"...","branch":"..."}}'
```

## ম্যানেজমেন্ট প্রক্সি

আউটবাউন্ড HTTP(S)/SOCKS প্রক্সি, যেগুলো প্রোভাইডার, অ্যাকাউন্ট অথবা বিশ্বব্যাপী বরাদ্দ করা যায়।

| পদ্ধতি | পাথ                                          | বিবরণ                                                                                                                                                          |
| ------ | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/v1/management/proxies`                 | প্রক্সির তালিকা (`?id=` ব্যবহার করলে একটি ফেরত দেয়; `?id=&where_used=1` ব্যবহার করলে অ্যাসাইনমেন্ট গ্রাফ ফেরত দেয়)                                           |
| POST   | `/api/v1/management/proxies`                 | প্রক্সি তৈরি — বডি `createProxyRegistrySchema` দ্বারা যাচাই করা হয়                                                                                            |
| PATCH  | `/api/v1/management/proxies`                 | প্রক্সি আপডেট — বডি `updateProxyRegistrySchema` দ্বারা যাচাই করা হয় (`id` আবশ্যক)                                                                             |
| DELETE | `/api/v1/management/proxies?id=...&force=1`  | প্রক্সি মুছে দেয় (অ্যাসাইনমেন্ট বিচ্ছিন্ন করতে `force=1` ব্যবহার করুন)                                                                                        |
| GET    | `/api/v1/management/proxies/assignments`     | অ্যাসাইনমেন্টের তালিকা — `proxy_id`, `scope`, `scope_id` দ্বারা ফিল্টারযোগ্য; কোনো সংযোগের সক্রিয় প্রক্সি নির্ধারণ করতে `resolve_connection_id=<id>` পাস করুন |
| PUT    | `/api/v1/management/proxies/assignments`     | বরাদ্দ — বডি `proxyAssignmentSchema` (`{scope, scopeId?, proxyId?}`) দ্বারা যাচাই করা হয়। ডিসপ্যাচার ক্যাশ পরিষ্কার করে                                       |
| PUT    | `/api/v1/management/proxies/bulk-assign`     | একযোগে বরাদ্দ — বডি `bulkProxyAssignmentSchema` (`{scope, scopeIds[], proxyId?}`) দ্বারা যাচাই করা হয়                                                         |
| GET    | `/api/v1/management/proxies/health?hours=24` | একটি সময়সীমাজুড়ে প্রক্সির সামগ্রিক স্বাস্থ্য (সফলতা/ব্যর্থতার সংখ্যা, ল্যাটেন্সি)                                                                            |

**প্রমাণীকরণ:** প্রতিটি রুটে ম্যানেজমেন্ট সেশন/API কী আবশ্যক (`requireManagementAuth`)।

> টাস্কের বিবরণে থাকা `POST /api/v1/management/proxies/[id]/assignments` এবং `POST /api/v1/management/proxies/[id]/health` উপরে দেখানো সমতল `/assignments` এবং `/health` রুট দ্বারা পরিবেশিত হয় — কোডবেসে প্রতি-id-এর জন্য কোনো সাবরুট নেই।

## স্থিতিস্থাপকতা (বর্ধিত)

OmniRoute অস্থায়ী ব্যর্থতা মোকাবিলার জন্য তিনটি স্বতন্ত্র প্রক্রিয়া প্রদান করে; নিচের ব্যবস্থাপনা এন্ডপয়েন্টগুলো অপারেটরদের সেগুলোর অবস্থা পড়তে এবং ওভাররাইড করতে দেয়:

| পরিধি              | স্টেট সংরক্ষণ                        | পড়া                                      | রিসেট / পরিষ্কার                                                               |
| ------------------ | ------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------ |
| প্রোভাইডার ব্রেকার | `domain_circuit_breakers` + ইন-মেমরি | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                                   |
| সংযোগ কুলডাউন      | প্রোভাইডার সংযোগে `rateLimitedUntil` | `/api/rate-limits`, `/api/providers/[id]` | (প্রয়োজনের সময় পুনরায় সক্রিয় হয়; প্রোভাইডার PUT-এর মাধ্যমে পরিষ্কার করুন) |
| মডেল লকআউট         | ইন-মেমরি মডেল-উপলভ্যতা রেজিস্ট্রি    | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                       |

`PATCH /api/resilience` প্রোভাইডার ব্রেকার ওভাররাইডগুলো `providerBreaker.oauth` এবং `providerBreaker.apikey`-এর অধীনে গ্রহণ করে। প্রতিটি প্রোফাইল `degradationThreshold`, `failureThreshold`, এবং `resetTimeoutMs` সমর্থন করে; একই ফিল্ডগুলো Dashboard → Settings → Resilience-এও উপলভ্য।

```bash
# একটি নির্দিষ্ট মডেল লকআউট পরিষ্কার করুন
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# প্রতিটি লকআউট মুছে ফেলুন
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

সম্পূর্ণ ধারণাগত রেফারেন্স এবং ব্রেকারের ডিফল্ট মানের জন্য দেখুন: [`CLAUDE.md`](../../CLAUDE.md) → "রেজিলিয়েন্স রানটাইম স্টেট" এবং [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md)।

### রেট-লিমিট কিউ এবং স্বয়ংক্রিয়-সক্রিয়করণ সুরক্ষা ব্যবস্থা

- **সমর্থিত রাইট পাথ**: `POST /api/rate-limits`, যার বডি `{"connectionId": "<id>", "enabled": true|false}`, হলো কোনো সংযোগের রেট-লিমিট সুরক্ষা টগল করার জন্য সমর্থিত ব্যবস্থাপনা এন্ডপয়েন্ট। `PUT /api/providers/[id]` ইচ্ছাকৃতভাবে `rateLimitProtection` পরিবর্তন বা উল্টায় না (#11278)।
- **`enabled: false`-এর অর্থ**: `enabled: false` সেট করলে সংযোগটির সুস্পষ্ট সুরক্ষা অপসারিত হয়, কিন্তু এটি কোনো সক্রিয় API-কী সংযোগকে গ্লোবাল স্বয়ংক্রিয়-সক্রিয়করণ সুরক্ষা ব্যবস্থা (`autoEnableApiKeyProviders = true`) থেকে **বাদ দেয় না**। `reconcileEnabledConnections`-এ (`open-sse/services/rateLimitManager.ts`), `false` এবং `undefined` সমতুল্য; সুস্পষ্ট সুরক্ষাবিহীন সক্রিয় API-কী সংযোগগুলো স্বয়ংক্রিয়-সক্রিয়করণ সুরক্ষা ব্যবস্থার অধীনে সুরক্ষিত থাকে।
- **গ্লোবাল নিষ্ক্রিয়করণ**: রেট-লিমিট কিউ ছাড়াই API-কী সংযোগ চালাতে, `RATE_LIMIT_AUTO_ENABLE=false` (env) অথবা `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`)-এর মাধ্যমে সুরক্ষা ব্যবস্থাটি গ্লোবালভাবে নিষ্ক্রিয় করুন।

## MCP সার্ভার

OmniRoute-এর সঙ্গে 3টি ট্রান্সপোর্ট (stdio, SSE, streamable-http) এবং সীমাবদ্ধ-স্কোপের টুলসহ একটি এমবেডেড Model Context Protocol সার্ভার অন্তর্ভুক্ত থাকে। নিচের ড্যাশবোর্ড এন্ডপয়েন্টগুলো অবস্থা/অডিট ডেটা পড়ে এবং HTTP ট্রান্সপোর্টগুলোকে প্রক্সি করে।

| মেথড | পাথ | বিবরণ |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | হার্টবিট, ট্রান্সপোর্ট, অনলাইন অবস্থা, সর্বশেষ কল, শীর্ষ টুল, 24h সফলতার হার |
| GET | `/api/mcp/tools` | `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints`-সহ MCP টুলের তালিকা |
| GET | `/api/mcp/sse` | SSE ট্রান্সপোর্টের জন্য SSE স্ট্রিম খুলুন (MCP নিষ্ক্রিয় থাকলে বা ট্রান্সপোর্ট না মিললে `503` ফেরত দেয়) |
| POST | `/api/mcp/sse` | SSE ট্রান্সপোর্টে JSON-RPC ফ্রেম পাঠান |
| GET | `/api/mcp/stream` | Streamable HTTP ট্রান্সপোর্টের SSE দিকটি খুলুন (সার্ভার-সূচিত বার্তা) |
| POST | `/api/mcp/stream` | Streamable HTTP ট্রান্সপোর্টে JSON-RPC ফ্রেম পাঠান |
| DELETE | `/api/mcp/stream` | একটি Streamable HTTP session শেষ করুন |
| GET | `/api/mcp/audit` | অডিট লগ কোয়েরি করুন — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | সমষ্টিগত অডিট পরিসংখ্যান (মোট সংখ্যা, সফলতার হার, গড় সময়কাল, শীর্ষ টুল) |

**প্রমাণীকরণ:** `sse`/`stream` ট্রান্সপোর্টগুলো MCP-নির্দিষ্ট প্রমাণীকরণ ব্যবস্থা অনুসরণ করে (`mcp` স্কোপসহ Bearer API key); `status`/`tools`/`audit*` রুটগুলো ড্যাশবোর্ড থেকে পাঠযোগ্য (ড্যাশবোর্ড হোস্টে পৌঁছানোর বাইরে অতিরিক্ত প্রমাণীকরণের প্রয়োজন নেই)।

> উভয় HTTP ট্রান্সপোর্টই `settings.mcpEnabled` এবং `settings.mcpTransport` দ্বারা নিয়ন্ত্রিত — ট্রান্সপোর্ট না মিললে `400` এবং MCP নিষ্ক্রিয় থাকলে `503` ফেরত দেওয়া হয়।

## A2A সার্ভার

OmniRoute একটি A2A (Agent-to-Agent) JSON-RPC 2.0 এন্ডপয়েন্ট এবং পরিদর্শন/ড্যাশবোর্ডে ব্যবহারের জন্য একটি REST র্যাপার প্রদান করে।

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # ঐচ্ছিক, যদি না OMNIROUTE_API_KEY সেট করা থাকে
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

সমর্থিত মেথডসমূহ (সবগুলোই `settings.a2aEnabled` দ্বারা নিয়ন্ত্রিত):

| মেথড             | বিবরণ                                                                   |
| ---------------- | ----------------------------------------------------------------------- |
| `message/send`   | সিঙ্ক্রোনাস স্কিল এক্সিকিউশন; `{task, artifacts, metadata}` রিটার্ন করে |
| `message/stream` | একই স্কিল সেটের স্ট্রিমিং SSE এক্সিকিউশন                                |
| `tasks/get`      | `taskId` দিয়ে একটি টাস্ক ফেচ করে                                       |
| `tasks/cancel`   | `taskId` দিয়ে একটি টাস্ক বাতিল করে                                     |

বিল্ট-ইন স্কিলসমূহ: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`।

### এজেন্ট কার্ড

```bash
GET /.well-known/agent.json
```

পাবলিক A2A এজেন্ট কার্ড (নাম, বিবরণ, সক্ষমতা, স্কিল ক্যাটালগ, প্রমাণীকরণ স্কিম) রিটার্ন করে — সর্বজনীনভাবে 1 ঘণ্টার জন্য ক্যাশ করা হয়। কোনো প্রমাণীকরণের প্রয়োজন নেই।

### REST সহায়কসমূহ

| মেথড | পাথ                          | বিবরণ                                                                                                               |
| ---- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |

## ACP (Agent Client Protocol) ব্যবস্থাপনা

চাইল্ড প্রসেস হিসেবে। এই এন্ডপয়েন্টগুলো ACP এজেন্ট শনাক্তকরণ এবং কাস্টম এজেন্ট
নিবন্ধন পরিচালনা করে।

| মেথড   | পাথ               | বিবরণ                                                                                                                                                      |
| ------ | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/acp/agents` | ইনস্টলেশনের স্থিতি, ভার্সন ও বাইনারিসহ পরিচিত সব CLI এজেন্টের (বিল্ট-ইন + কাস্টম) তালিকা                                                                   |
| POST   | `/api/acp/agents` | একটি কাস্টম ACP এজেন্ট নিবন্ধন বা ক্যাশ রিফ্রেশ — বডি: `{id, name, binary, versionCommand, providerAlias, spawnArgs, protocol}` অথবা `{action: "refresh"}` |
| DELETE | `/api/acp/agents` | একটি কাস্টম ACP এজেন্ট অপসারণ — কোয়েরি প্যারামিটার: `?id=<agentId>`                                                                                       |

**রেসপন্সের উদাহরণ** (`GET /api/acp/agents`):

```json
{
  "agents": [
    {
      "id": "claude",
      "name": "Claude Code CLI",
      "binary": "claude",
      "version": "1.0.45",
      "installed": true,
      "protocol": "stdio",
      "providerAlias": "claude",
      "isCustom": false
    },
    {
      "id": "my-custom-cli",
      "name": "My Custom CLI",
      "installed": false,
      "protocol": "stdio",
      "providerAlias": "my-provider",
      "isCustom": true
    }
  ],
  "cacheTtlMs": 60000,
  "cacheAge": 1234
}
```

**প্রমাণীকরণ:** ম্যানেজমেন্ট সেশন (ড্যাশবোর্ডের `auth_token` কুকি) অথবা একটি
ম্যানেজমেন্ট-স্কোপড API কী প্রয়োজন।

সম্পূর্ণ বিবরণের জন্য [ACP ফ্রেমওয়ার্ক](../frameworks/ACP.md) দেখুন।

## প্রমাণীকরণ

চারটি ক্রেডেনশিয়াল পরিবার (ড্যাশবোর্ড সেশন, স্থানীয় CLI টোকেন, `oma_live_…` অ্যাক্সেস টোকেন, ম্যানেজমেন্ট-স্কোপড API কী) এবং ইনফারেন্স কী থেকে সেগুলোর পার্থক্য সম্পর্কে জানতে [ম্যানেজমেন্ট প্রমাণীকরণ](../guides/MANAGEMENT-AUTH.md) দেখুন।

- ড্যাশবোর্ড রুটগুলো (`/dashboard/*`) `auth_token` কুকি ব্যবহার করে
- লগইন সংরক্ষিত পাসওয়ার্ড হ্যাশ ব্যবহার করে; ফলব্যাক হিসেবে `INITIAL_PASSWORD` ব্যবহৃত হয়
- `/api/settings/require-login`-এর মাধ্যমে `requireLogin` টগল করা যায়
- `REQUIRE_API_KEY=true` হলে `/v1/*` রুটগুলোর জন্য ঐচ্ছিকভাবে Bearer API কী আবশ্যক হয়
- এই রেফারেন্সে "ম্যানেজমেন্ট টোকেন" / "ম্যানেজমেন্ট-স্কোপড API কী" বলতে ওই নির্দেশিকায় উল্লিখিত পরিবারগুলোর একটিকে বোঝায়—কোনো অসংজ্ঞায়িত অতিরিক্ত সিক্রেটের ধরনকে নয়

> **ব্রেকিং পরিবর্তন (v3.8.0)** — `/api/v1/agents/tasks/*` এবং কুলডাউন ম্যানেজমেন্ট এন্ডপয়েন্টগুলোর জন্য এখন **ম্যানেজমেন্ট প্রমাণীকরণ** (ড্যাশবোর্ড `auth_token` কুকি অথবা ম্যানেজমেন্ট-স্কোপড API কী) আবশ্যক। আগে যেসব ক্লায়েন্ট প্রমাণীকরণ ছাড়াই এই রুটগুলো কল করত, তারা এখন `401 Unauthorized` পাবে। commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`) দেখুন।
