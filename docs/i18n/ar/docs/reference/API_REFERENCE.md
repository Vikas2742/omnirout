## إكمالات الدردشة

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### الرؤوس المخصّصة

| الرأس                    | الاتجاه   | الوصف                                                                                                                                                                  |
| ------------------------ | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | الطلب     | اضبطه على `true` لتجاوز ذاكرة التخزين المؤقت                                                                                                                           |
| `x-omniroute-no-memory`  | الطلب     | اضبطه على `true` لتخطي إدراج الذاكرة والمهارات لهذا الطلب (يماثل عدم استخدام ذاكرة التخزين المؤقت؛ ويتجنب الحمل الإضافي للرموز المميزة/التكلفة لكل استدعاء)            |
| `X-OmniRoute-Progress`   | الطلب     | اضبطه على `true` لتلقي أحداث التقدم                                                                                                                                    |
| `X-Session-Id`           | الطلب     | مفتاح جلسة ثابت لارتباط الجلسة الخارجي                                                                                                                                 |
| `x_session_id`           | الطلب     | يُقبل أيضًا المتغير الذي يستخدم الشرطة السفلية (عبر HTTP المباشر)                                                                                                      |
| `X-OmniRoute-Session-Id` | الطلب     | وسم جلسة/محادثة يقدّمه المستدعي (ويغذي الذاكرة أيضًا). عند وجوده، يُحفظ حرفيًا في `call_logs.session_tag` لإسناد التكلفة لكل جلسة (#8249) — ولا يُنشأ مطلقًا عند غيابه |
| `Idempotency-Key`        | الطلب     | مفتاح إزالة التكرار (نافذة مدتها 5 ثوانٍ)                                                                                                                              |
| `X-Request-Id`           | الطلب     | مفتاح بديل لإزالة التكرار                                                                                                                                              |
| `x-omniroute-connection` | الطلب     | ثبّت طلب نموذج واحد على اتصال مزوّد واحد (حساب) باستخدام معرّفه — راجع [تثبيت الحساب لكل طلب](#account-pinning-per-request)                                            |
| `X-OmniRoute-Cache`      | الاستجابة | `HIT` أو `MISS` (دون بث)                                                                                                                                               |
| `X-OmniRoute-Idempotent` | الاستجابة | `true` إذا أُزيل التكرار                                                                                                                                               |
| `X-OmniRoute-Progress`   | الاستجابة | `enabled` إذا كان تتبع التقدم مفعّلًا                                                                                                                                  |
| `X-OmniRoute-Session-Id` | الاستجابة | معرّف الجلسة الفعلي الذي تستخدمه OmniRoute                                                                                                                             |
| `X-OmniRoute-Request-Id` | الاستجابة | معرّف ربط الطلب (عندما يكون معروفًا)                                                                                                                                   |
| `X-OmniRoute-Version`    | الاستجابة | إصدار بناء OmniRoute (موجود دائمًا)                                                                                                                                    |
| `X-OmniRoute-Cost-Saved` | الاستجابة | المبلغ بالدولار الأمريكي الذي وفّرته ذاكرة التخزين المؤقت عند `HIT` (إصابات ذاكرة التخزين المؤقت فقط)                                                                  |
| `X-OmniRoute-Decision`   | الاستجابة | تتبّع التوجيه: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` هي استراتيجية التركيب، أو `single` لطلب غير مركّب) — موجود دائمًا في استجابات الإكمال     |

> ملاحظة Nginx: إذا كنت تعتمد على ترويسات تحتوي على شرطات سفلية (مثل `x_session_id`)، ففعّل `underscores_in_headers on;`.

#### تثبيت الحساب لكل طلب

عندما يكون لدى موفّر عدة اتصالات (حسابات أو مفاتيح)، يختار OmniRoute عادةً أحدها
باستخدام استراتيجية اختيار الحساب. ويمكن بدلًا من ذلك تثبيت اتصال محدد لطلب ما
باستخدام الترويسة `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **مكان العثور على المعرّف.** افتح صفحة الموفّر في لوحة المعلومات
  (**لوحة المعلومات → الموفّرون → <provider>**) وانقر على شريحة المعرّف `xxxxxxxx…` في صف اتصال؛
  سيؤدي ذلك إلى نسخ معرّف الاتصال الكامل.
- **الطلبات التي تلتزم به.** طلبات النموذج الواحد (`provider/model`) على
  `/v1/chat/completions` و`/v1/messages` و`/v1/responses`. تتجاهل التركيبات هذه الترويسة: ثبّت
  حسابًا لكل خطوة في التركيبة عبر الاتصال الخاص بتلك الخطوة بدلًا من ذلك.
- **التثبيت صارم وليس تفضيلًا.** يُستخدم الاتصال المثبّت حصريًا. يؤدي حدوث
  فشل داخل الطلب إلى تسجيل فترة التهدئة للحساب، لكنه **لا** ينتقل إلى
  حساب آخر تابع للموفّر نفسه.
- **فترة التهدئة والحصة تلغيان التثبيت.** عندما يكون الاتصال المثبّت في فترة تهدئة،
  أو تكون حصته مستنفدة، أو يكون محظورًا بواسطة سياسة حصة، ترجع الطلبات اللاحقة إلى اتصالات
  الموفّر الأخرى، تمامًا مثل حركة البيانات غير المثبّتة.
- **تفشل المعرّفات المجهولة أو المعطّلة.** إذا لم يكن المعرّف موجودًا في مجموعة اتصالات الموفّر النشطة (بسبب حذفه،
  أو إلغاء تنشيطه، أو انتمائه إلى موفّر آخر)، فلن يتبقى حساب مؤهل، ولذلك يفشل الطلب
  بدلًا من توجيهه ضمنيًا إلى مكان آخر.

يرسل Claude Code الترويسات المخصصة عبر `ANTHROPIC_CUSTOM_HEADERS`. ضعه في كتلة `env`
داخل `~/.claude/settings.json`، أو في `.claude/settings.json` على مستوى المشروع لتثبيت حساب
مختلف لكل مشروع:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

المصدر: `src/sse/handlers/chat.ts` (قراءة الترويسة)، و`src/sse/services/auth.ts` و
`src/sse/services/sessionAffinityPin.ts` (إلغاء التثبيت والتحقق من عدم الوجود في المجموعة).

> **ترويسات قياس التكلفة:** تحمل استجابات النجاح غير المتدفقة أيضًا مجموعة قياس التكلفة `X-OmniRoute-*`، وهي `X-OmniRoute-Response-Cost` (بالدولار الأمريكي، بدقة ثابتة من 10 منازل عشرية؛ `0.0000000000` للخدمات المجانية أو التي لا تتوفر لها أسعار)، و`X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`، و`X-OmniRoute-Model`، و`X-OmniRoute-Provider`، و`X-OmniRoute-Latency-Ms`، و`X-OmniRoute-Cache-Hit`، و`X-OmniRoute-Fallback-Attempts` (فقط عندما تكون القيمة > 0)، بالإضافة إلى `X-OmniRoute-Request-Id` و`X-OmniRoute-Version`. تُصدر هذه الترويسات بواسطة إكمالات المحادثة، و`/v1/responses`، و`/v1/messages`، **وكذلك نقاط نهاية الوسائط** — `/v1/embeddings`، و`/v1/images/generations`، و`/v1/audio/speech`، و`/v1/audio/transcriptions`، و`/v1/rerank`، و`/v1/videos/generations`، و`/v1/music/generations`، و`/v1/moderations` (بتكلفة `0` دائمًا). تُحسب تكلفة الوسائط وفقًا لكل نمط (لكل صورة، أو ثانية، أو حرف، أو وحدة بحث) عند توفر الأسعار، وإلا فتكون `0` (السماح بالمتابعة عند الفشل).

> **دلالات التكلفة عند إصابة ذاكرة التخزين المؤقت:** عند حدوث إصابة في ذاكرة التخزين المؤقت الدلالية (`X-OmniRoute-Cache-Hit: true`)، لا يُجرى أي استدعاء إلى الخدمة المنبع، ولذلك تكون قيمة `X-OmniRoute-Response-Cost` هي `0.0000000000` (التكلفة **الإضافية** لخدمة الإصابة). وتُبلّغ التكلفة الأصلية أو التي كان من الممكن تكبدها بشكل منفصل في `X-OmniRoute-Cost-Saved`. ينبغي لمستهلكي بيانات الفوترة جمع قيم `X-OmniRoute-Response-Cost` (لا تترتب تكلفة على الإصابات)، بينما يمكن لتحليلات ذاكرة التخزين المؤقت تجميع قيم `X-OmniRoute-Cost-Saved`.

## عقود الإيجار الحصرية للجلسات المُدارة

يُعد تأجير الجلسات المُدارة حصريًا عقد توجيه اختياريًا ومحايدًا تجاه العميل: يحتفظ مالك نشط واحد
باتصال OmniRoute واحد مؤهل. لا يؤجّر هذا العقد نموذجًا، ولا يتطلب OAuth، ولا يحدد
عميلاً بعينه، ولا يتطلب مزودًا بعينه.

يجب أن يمتلك مفتاح API المستخدم للمصادقة النطاق `lease:exclusive` وقائمة صريحة غير فارغة
من `allowedConnections`. يفرض حدّ تعديل قاعدة البيانات وجود الحقلين معًا عند إنشاء المفتاح
وعند إجراء التحديثات الجزئية.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

تعرض استجابات الاستحواذ والتجديد والتحرير الناجحة الطوابع الزمنية و`state` والقيمة الموجبة الدقيقة
لـ`generation`، لكنها لا تعرض مطلقًا الاتصال المحدد أو بيانات الاعتماد. يوفّر التجديد والتحرير
قيمة الجيل في نص JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

يمكن لمالك عقد إيجار نشط أن يطلب صراحةً بيانات تعريف عرض آمنة من ناحية الخصوصية لارتباطه الحالي:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

يُحاط إجراء الحالة الاختياري هذا بسياج يعتمد على المالك المُبهم، ومفتاح API المُدار والمُصادق عليه، والجيل
النشط الدقيق ضمن معاملة واحدة في قاعدة البيانات. لا تكون `displayName` سوى اسم الاتصال المهيأ بعد
إزالة المسافات الزائدة؛ وتكون `null` عندما لا يتوفر اسم مهيأ آمن. لا يستبدل OmniRoute مطلقًا هذا الاسم
بعنوان بريد إلكتروني أو هوية حساب مُنشأة. قيمة المزود هي تسمية عرض غير حساسة، وليست مطلقًا
معرّفًا مُنشأً لمزود متوافق. تُستبعد بيانات الاعتماد والرموز المميزة وملفات تعريف الارتباط ومعرّفات الاتصال أو مفاتيح
API الأولية وتجزئات المالك وأسرار التسييج وبيانات التوجيه الداخلية.

تُرجع عمليات البحث ذات المفتاح الخاطئ أو المالك الخاطئ أو الجيل القديم، وكذلك عمليات البحث المفقودة أو المنتهية الصلاحية أو المحررة أو المُبطلة،
الخطأ نفسه `409 LEASE_FENCE_STALE` من دون بيانات تعريف الاتصال. لا يمتلك العميل الذي تلقّى استجابة انتظار السعة ارتباطًا نشطًا لفحصه. عندما ينقل التوجيه عقد إيجار نشطًا،
يظل الجيل نفسه صالحًا، وتُرجع الحالة الارتباط الجديد ذريًا، وليس القديم مطلقًا.
يظل العملاء الحاليون من دون تغيير لأن استجابات الاستحواذ والتجديد والتحرير والانتظار تحتفظ
ببُناها السابقة.

لا يغيّر عقد الخادم هذا `/status` القياسي الخاص بـOpenAI Codex. يُبلغ Codex القياسي حاليًا عن
مزود النموذج وحالة المصادقة/الحساب المدمجة، لكنه لا يعرض بيانات تعريف عشوائية لحسابات
المزودين المخصصين؛ ويجب على تكامل لاحق مع العميل استدعاء هذا الإجراء وتحديد كيفية
عرض `connection.displayName`.

بعد ذلك، يوفّر كل طلب استدلال مُدار ترويستي التحكم كلتيهما:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

يُسيَّج المالك الدقيق والجيل والاتصال النشط ومفتاح API المُصادق عليه مباشرةً
قبل كل محاولة مدعومة للاتصال بجهة المنبع. تفشل إعادة استخدام المالك والجيل مع مفتاح آخر حتى
عندما يسمح ذلك المفتاح بالاتصال نفسه. لا يُحتفظ بالمالكين بصيغتهم الأولية، ولا تُسجَّل بياناتهم، ولا تُحفظ في
لقطة الطلب، ولا تُمرر إلى جهة المنبع.

يُرجع التنازع المؤقت HTTP `429` مع `Retry-After` وما يلي:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

تعني هذه الاستجابة فقط أن مجموعة الاتصالات المؤهلة العادية لم تكن فارغة، وأن كل اتصال مرشح متاح
كان محتجزًا بموجب عقد إيجار نشط يملكه طرف آخر. تحتفظ النماذج/المزودون غير المدعومين، وعدم تطابق السياسة، وفترة التهدئة، والحصة،
والحالة الصحية، وغيرها من حالات فشل الأهلية العادية، باستجابات OmniRoute الحالية الخاصة بها.

### `x-omniroute-compression`

تجاوز خطة الضغط لكل طلب. له أعلى أولوية — إذ يتغلب على تجاوز تركيبة التوجيه
والملف الشخصي النشط والمُشغّل التلقائي والقيمة الافتراضية للوحة. القيم:

| القيمة        | التأثير                                                                                              |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| `off`         | لا يوجد ضغط لهذا الطلب.                                                                              |
| `default`     | ملف Default المستمد من اللوحة (يتجاهل الملف الشخصي النشط). تظل محركات الضغط مع فقدان البيانات معطلة. |
| `safe`        | إزالة التكرار وطيّ المسافات البيضاء فقط.                                                             |
| `allow-lossy` | الإبقاء على خطة المشغّل لهذا الطلب، بما يشمل الملخصات وإعادة صياغة الأسلوب.                          |
| `engine:<id>` | محرك واحد عند تمكينه، مثل `engine:rtk`. اشتراك اختياري خاص بكل طلب لهذا المحرك.                      |
| `<combo>`     | تركيبة مسماة، تُطابق بالاسم أولاً (من دون حساسية لحالة الأحرف)، ثم بالمعرّف.                         |

ملاحظات:

- تُتجاهل القيم غير المعروفة (لا يُرفض الطلب مطلقًا)؛ وتنتقل عملية الحل إلى ترتيب أسبقية المشغّل المعتاد.
- إذا كانت عدة تركيبات تحمل الاسم نفسه، فمرّر **المعرّف** الخاص بالتركيبة للحصول على تطابق حتمي.
- لا يمكن تحديد تركيبة اسمها `off` أو `default` بالاسم (تُفسَّر هاتان الكلمتان المفتاحيتان أولاً)؛ ارجع إلى مثل هذه التركيبة باستخدام معرّفها.
- مفتاح الضغط الرئيسي هو بوابة صارمة: عندما يكون الضغط معطلاً عموميًا، لا يمكن لهذه الترويسة تمكينه.

تُعاد الخطة المطبقة في ترويسة الاستجابة:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

حيث تكون `<source>` واحدة من `request-header` أو `routing-override` أو `active-profile` أو `auto-trigger` أو `default` أو `off`.

## التضمينات

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

المزوّدون المتاحون: Nebius، OpenAI، Mistral، Together AI، Fireworks، NVIDIA، **OpenRouter**، Jina AI.

معرّفات الكتالوج تكون بصيغة `provider/model` (مثال: `jina-ai/jina-embeddings-v5-omni-small`). كما يتم أيضًا التعرّف على معرّفات نماذج Jina المجرّدة التي تظهر في السجل (على سبيل المثال `jina-embeddings-v5-text-small` و`jina-reranker-v3.5`). تستخدم عمليات التضمين/إعادة الترتيب/التصنيف/التقسيم في Jina بيانات اعتماد `jina-ai` من لوحة المعلومات أولًا؛ ولا يُستخدم `JINA_AI_API_KEY` إلا كخيار احتياطي عند عدم وجود مفتاح في لوحة المعلومات. بطاقة `jina-reader` مخصّصة فقط لـ Reader / `r.jina.ai` ‏(`POST /v1/web/fetch`)، ولا توفّر أبدًا خدمات التضمين أو إعادة الترتيب.

تقبل نماذج السجل التي تعلن دعمًا متعدد الوسائط أيضًا ما يصل إلى 32 عنصرًا منظمًا ومحايدًا بالنسبة إلى المزوّد.
أنواع عناصر الوسائط هي `text` و`image` و`audio` و`video` و`document`. ويكون `source` الخاص بالوسائط
إما `{"type":"url","url":"https://..."}` أو
`{"type":"base64","data":"...","media_type":"..."}`.

يقبل Jina v5 Omni ‏(`jina-ai/jina-embeddings-v5-omni-small` و`jina-ai/jina-embeddings-v5-omni-nano`
والاسم المستعار للعائلة `jina-ai/jina-embeddings-v5-omni` → omni-small) أيضًا مستندات EmbeddingsV5Request الأصلية الخاصة بـ Jina،
ويقوم **بإعادة توجيهها دون تعديل** إلى `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

يمكن أن تكون قيم `{ image | audio | video | pdf }` الأصلية عنوان URL عامًا يستخدم HTTPS، أو معرّف URI من نوع `data:`، أو بيانات
base64 أولية. لا يحوّل OmniRoute هذه الكائنات إلى سلاسل نصية ولا يجلب عناوين URL الأصلية للصور — إذ تسترجع Jina
الوسائط العامة بنفسها. ويُعاد توجيه حقول Jina الإضافية (`task` و`normalized` و`truncate` و`embedding_type`).
أما وحدات SKU النصية فقط من Jina، فتستمر في رفض المستندات غير النصية.

حدود الأمان والنقل:

- يجب أن تكون عناوين URL للوسائط البعيدة عامة وتستخدم HTTPS. تُجلب عناصر `{type,source:url}` القياسية
  من جهة الخادم (مع إعادة التحقق من عمليات إعادة التوجيه، والمهلة الزمنية، وحدود الحجم، وDNS العام، وتثبيت الاتصال)، ثم
  تُضمَّن قبل استدعاء المزوّد. وتُعاد توجيه عناصر Jina الأصلية من نوع `{image:"https://..."}` كما هي
  بعد التحقق نفسه من أنها عامة وتستخدم HTTPS؛ وتتولى Jina جلب عنوان URL.
- تقتصر وسائط base64 المضمّنة على 8 MiB بعد فك الترميز لكل عنصر، وعلى 16 MiB بعد فك الترميز للطلب بأكمله.

التحويل حسب المزوّد (لا تُعاد توجيه العناصر القياسية دون تعديل مطلقًا):

- نماذج Jina متعددة الوسائط: يتحول كل عنصر من المستوى الأعلى إلى كائن واحد ذي مفتاح خاص بنوع الوسائط
  (`text` / `image` / `audio` / `video` / `pdf`) باستخدام معرّفات URI من نوع data للوسائط المضمّنة؛ متجه واحد لكل
  عنصر من المستوى الأعلى.
- عائلة Gemini Embedding 2: تتحول مصفوفة واحدة من المستوى الأعلى إلى طلب أصلي واحد
  من نوع `models/{model}:embedContent` مع `content.parts` ‏(`text` أو `inline_data`).
- ‏llama.cpp ‏(`llama-cpp/<model>`، أي نموذج حمّله الخادم المحلي): تتحول عناصر `text` القياسية
  إلى سلاسل نصية عادية، وتتحول عناصر `image` / `audio` / `video`، كل منها إلى كائن
  `{"content": [part]}` واحد، باستخدام أجزاء محتوى الدردشة الخاصة بـ llama-server ‏(`image_url`
  و`input_audio` بالتنسيق `wav` / `mp3` / `flac`، و`input_video`) مع بيانات مضمّنة؛ متجه واحد
  لكل عنصر من المستوى الأعلى. يجب تشغيل الخادم باستخدام `--embedding --mmproj …`؛ ومن دون جهاز إسقاط،
  يرفض الخادم الوسائط بنفسه. النوع `document` غير مدعوم.
- ترفض النماذج غير المعروفة/الديناميكية التي لا تحتوي على بيانات وصفية صريحة للوسائط الإدخال المنظم باستخدام HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

تُرجع مجموعات النموذج/نوع الوسائط غير المدعومة HTTP 400 بدلًا من تحويل العنصر قسرًا. وتستمر حقول
الامتداد غير المرتبطة بالإدخال في طلبات السلاسل النصية/الرموز القديمة بالمرور دون تعديل.

```bash
# سرد جميع نماذج التضمين
GET /v1/embeddings
```

## توليد الصور

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

يشمل موفرو الخدمة المتاحون OpenAI (GPT Image 2)، وxAI (Grok Image)، وTogether AI (FLUX)، وFireworks AI، وNebius (FLUX)، وHyperbolic، وNanoBanana، و**OpenRouter**، و**ZenMux**، وSD WebUI (محلي)، وComfyUI (محلي).

يعيد `n` عدد `n` من الصور في `data[]`. بالنسبة إلى موفري الخدمة الذين تعيد واجهة API المصدرية لديهم صورة واحدة لكل استدعاء
(Black Forest Labs، وStability AI، وLeonardo، وIdeogram، وHaiper، وHyperbolic، وMagnific/Freepik،
وNVIDIA NIM، وCloudflare Workers AI)، تُجرى `n` استدعاءات مصدرية منفصلة، بحد أقصى 4 استدعاءات متزامنة. تُزاح قيمة
`seed` الثابتة وفق فهرس الاستدعاء (`seed`، و`seed + 1`، …)، بحيث تختلف الصور مع بقائها
قابلة لإعادة الإنتاج. الحد الأقصى لقيمة `n` هو 10. يفشل الطلب بالكامل إذا فشل أي استدعاء. توجد قائمة
تنسيقات التوزيع في `SINGLE_IMAGE_FANOUT_FORMATS` ضمن
`open-sse/handlers/imageGeneration/fanOut.ts`.

يعيد ZenMux استخدام اتصال مفتاح API الحالي ويقبل البادئتين `zenmux/` أو `zm/`:

- يستخدم `zenmux/openai/gpt-image-2` واجهة OpenAI Images API الخاصة بـ ZenMux. تشمل الخيارات `size`،
  و`quality`، و`n`، و`output_format`، و`output_compression`، و`background`، و`response_format`.
- يستخدم ناشرون آخرون، مثل `zm/meta/muse-image-1.0`، نقطة النهاية `:predict`
  الخاصة بـ Vertex AI في ZenMux. تقابل `n` الحقل `sampleCount`، وتقابل `aspect_ratio` الحقل `aspectRatio`، وتقابل `image_size`
  (`1K`، و`2K`، و`4K`) الحقل `sampleImageSize`. لا توفر قيمة `size` بالبكسل سوى نسبة أبعاد،
  ولا تضمن أبعادًا محددة بالبكسل. تختلف النسب والدقات والأعداد المدعومة باختلاف النموذج.
- يختار `zm/inclusionai/ming-image-0.1-design` أبعاده بنفسه. احذف `size`،
  و`aspect_ratio`، و`image_size`؛ إذ تؤدي القيم الصريحة إلى إرجاع HTTP 400. يمكن طلب PNG وJPEG وWebP
  باستخدام `output_format`.

يدعم هذا التكامل توليد الصور من النص، وليس تحرير الصور المرجعية. تُوحَّد مخرجات Vertex
إلى `data[].b64_json`؛ ويعيد `response_format: "url"` عنوان URL من نوع HTTPS من المصدر،
أو عنوان URL لبيانات base64 عندما لا تتوفر سوى بايتات الصورة. تؤدي المخرجات الفارغة أو المُرشَّحة
إلى إرجاع خطأ بدلًا من نجاح فارغ. يعتمد الوصول إلى النموذج على حساب ZenMux.
راجع [واجهة Vertex API الخاصة بـ ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) و
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# سرد جميع نماذج الصور
GET /v1/images/generations
```

## التعرّف الضوئي على محارف المستندات

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

يحدد `model` موفر OCR عبر بادئة `provider/model`؛ ويُحل معرّف النموذج المجرد (مثل
`mistral-ocr-latest`) إلى موفره المسجّل، بينما تُستخدم Mistral افتراضيًا عند حذف `model`
(`mistral-ocr-latest`). موفرو الخدمة المسجّلون (`open-sse/config/ocrRegistry.ts`):

| معرّف موفر الخدمة             | معرّف النموذج        | قيمة `model`                                                  | ملاحظات                                                                                                 |
| ----------------------------- | -------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (أو `mistral-ocr-latest` مجردًا) | متزامن — تُعاد الاستجابة مباشرةً من الاستدعاء المصدري الوحيد.                                           |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                   | المصدر غير متزامن (`analyze` + الاستقصاء) — انظر أدناه.                                                 |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                       | متزامن، عبر نقطة نهاية الشريك `openapi/chat/completions` في Vertex AI — انظر أدناه للمصادقة وعنوان URL. |

يستجيب موفرو الخدمة الثلاثة بالبنية نفسها المشابهة لبنية Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### تدفق الاستقصاء في Azure Document Intelligence

واجهة `analyze` في Azure Document Intelligence غير متزامنة: يعيد الطلب الأولي ترويسة
`Operation-Location` بدلًا من جسم الاستجابة، ويجب استقصاء النتيجة. يقوم المعالج
(`open-sse/handlers/ocr.ts`) باستقصاء عنوان URL هذا كل ثانية لما يصل إلى 30 محاولة، ويفشل فورًا (من دون
مواصلة الاستقصاء) عند استجابة استقصاء ليست `ok` أو عند حالة `"failed"`، ويعيد `504` إذا كانت
العملية لا تزال قيد التشغيل بعد استنفاد عدد المحاولات. تُوحَّد استجابة Azure النهائية
إلى بنية `pages`/`markdown` نفسها التي تستخدمها Mistral قبل إعادتها إلى
المستدعي، لذلك لا تحتاج شيفرة العميل إلى معالجة موفر الخدمة كحالة خاصة.

### مصادقة Vertex AI DeepSeek OCR وتحديد نقطة النهاية

يعيد `vertex-deepseek-ocr` استخدام مصادقة Vertex AI نفسها التي يدعمها OmniRoute بالفعل
لحركة مرور المحادثات/الصور (`open-sse/executors/vertex.ts`): يكون مفتاح API الخاص بالاتصال إما
بيانات اعتماد JSON لحساب خدمة (تُستبدل برمز وصول OAuth قصير العمر عبر تدفق JWT-bearer)
أو رمز وصول OAuth مُصدَر مسبقًا يُستخدم كما هو. عنوان URL لنقطة النهاية المصدرية هو
نقطة نهاية الشريك العامة `openapi/chat/completions` في Vertex، ويُنشأ من مشروع الاتصال
ومنطقته — وتكون لقيمة `providerSpecificData.project`/`providerSpecificData.region` الصريحة الأولوية دائمًا؛
وإلا فيُستخرج المشروع من `project_id` في JSON الخاص بحساب الخدمة، وتكون المنطقة الافتراضية
`us-central1`. يحدث كلا التحديدين في `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`، و`resolveVertexOcrBaseUrl`)، وتستخدمهما
`src/app/api/v1/ocr/route.ts` قبل الإرسال إلى `handleOcr`.

### بادئات معرّفات النماذج (`?prefix=`)

تُعرَض معظم النماذج تحت **بادئة موفّر**. تتحكم علامة الميزة
`MODELS_CATALOG_PREFIX_MODE` في البادئة التي تحصل عليها، ويمكن تجاوزها **لكل طلب** باستخدام
معامل استعلام — وهذا مفيد لعميل يريد قائمة واضحة من دون تغيير الإعداد على مستوى الخادم
للجميع:

```bash
GET /v1/models?prefix=alias        # معرّف واحد لكل نموذج — بادئة الاسم المستعار القصيرة
GET /v1/models?prefix=dual         # كلا الشكلين (الإعداد الافتراضي للخادم)
GET /v1/models?prefix=canonical    # بادئة معرّف الموفّر الكاملة فقط
```

| الوضع       | ما يصدر                                                 | ملاحظات                                                                                                                                                                        |
| ----------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dual`      | `cc/claude-sonnet-4-6` **و** `claude/claude-sonnet-4-6` | **الافتراضي.** يُوجَّه كلا المعرّفين إلى النموذج نفسه؛ وقد أُبقيا لكي تظل إعدادات العملاء التي ثبّتت أيًا من الشكلين تعمل. يؤدي ذلك إلى مضاعفة حجم الكتالوج تقريبًا.           |
| `alias`     | `cc/claude-sonnet-4-6`                                  | إدخال واحد لكل نموذج. ما يزال الموفّرون الذين ليس لديهم اسم مستعار مميز يصدرون إدخالهم، لذلك لا يُفقد شيء.                                                                     |
| `canonical` | `claude/claude-sonnet-4-6`                              | إدخال واحد لكل نموذج تحت بادئة معرّف الموفّر الكاملة. كما يصدر الموفّرون الذين ليس لديهم اسم مستعار مميز (مثل `antigravity/…` و`agy/…`) معرّفهم الوحيد هنا، لذلك لا يُفقد شيء. |

يمكن أيضًا التعرّف على النسخة المطابقة في وضع `dual` من دون معامل الاستعلام: فهي تحمل حقل `parent`
يشير إلى المعرّف الأساسي.

ينبغي للعملاء الذين يعرضون منتقي نماذج طلب `?prefix=alias` — وهذا ما تفعله
[إضافة OmniCopilot لـ VS Code](../guides/VSCODE-COPILOT.md).

### مرشحات الاكتشاف (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

تقبل `GET /v1/models` مرشحات اكتشاف اختيارية. ومن دون أي منها، تظل الاستجابة
من دون تغيير. وهي تضيّق نطاق الكتالوج الذي يراه المستدعي بالفعل (تُطبّق أذونات مفتاح API أولًا)،
وتُشغّل قبل ترقيم الصفحات بأسلوب OpenAI عبر `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # يجب أن تكون كل إمكانية مدرجة صحيحة
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # قيمة `type` في الكتالوج؛ الصفوف التي لا تحتوي عليها تكون `chat`
GET /v1/models?q=sonnet&limit=10                           # مطابقة غير حساسة لحالة الأحرف على المعرّف أو الاسم
```

| المعامل       | القيم                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | عدد صحيح غير سالب، يُقارن مع `context_length`                                                       |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | من 1 إلى 200 حرف                                                                                    |

تؤدي القيمة غير المعروفة، أو قيمة `min_context` التي ليست عددًا صحيحًا غير سالب (مثل `1.5`)،
إلى إرجاع HTTP `400`، وتسرد الرسالة القيم الصالحة. التنفيذ:
`src/app/api/v1/models/catalogFilters.ts`.

### القائمة المختصرة للنماذج (`POST /v1/models/query`)

تعيد `POST /v1/models/query` قائمة قصيرة وحتمية من الكتالوج نفسه، مع المصادقة نفسها
وإمكانية الرؤية الخاصة بكل مفتاح كما في `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

كل حقل اختياري. يقبل كل من `capabilities` و`exclude` مصفوفة أو سلسلة مفصولة بفواصل؛
وتُقارن `max_output` مع `max_output_tokens`. تُرتّب النتائج حسب `owned_by`، ثم `id`.
القيمة الافتراضية لـ`limit` هي `20`، وتُقيّد القيم التي تتجاوز `100` عند `100`. يؤدي JSON غير الصالح، أو الحقل غير المعروف،
أو القيمة غير الصالحة إلى إرجاع HTTP `400`.

### نماذج المحادثة المخفية فرديًا

يُستبعد النموذج المعلَّم بأنه **مخفي** في صفحة موفّره من الكتالوج، ويُرفض
باستخدام HTTP `404` / `model_not_found` عند طلبه صراحةً. يستخدم الفحص الموفّر
والنموذج بعد حلّهما، بما في ذلك الأسماء المستعارة للموفّرين، وبادئات عُقد الموفّرين المتوافقين،
والإعدادات الافتراضية للاتصال. تتخطى التركيبة الأهداف المخفية ويمكنها استخدام هدف شقيق ظاهر؛ وعندما لا
يتبقى أي هدف قابل للتنفيذ، فإنها تعيد رمز الخطأ نفسه. يسري إلغاء الإخفاء في الطلب التالي.
لا تؤدي تجاوزات إمكانية الرؤية الخاصة بالصور فقط إلى إخفاء نموذج المحادثة الذي يحمل المعرّف نفسه.

إعداد النموذج الفردي هذا منفصل عن
[قوائم السماح/الرفض لإظهار النماذج](../routing/MODEL_EXPOSURE_LIST.md)، التي ترشّح عرض الكتالوج
والنماذج المرشحة للتوجيه التلقائي مع الاحتفاظ بالإرسال الصريح. تستمر أذونات النماذج الخاصة بمفتاح API
في التطبيق بصورة مستقلة. يظل وضع بادئة الكتالوج الافتراضي `dual`.

### متغيرات النماذج من دون تفكير

بالنسبة إلى نماذج Claude القادرة على التفكير، تعلن `/v1/models` أيضًا عن متغير **من دون تفكير** يبدأ معرّفه بالبادئة `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

يؤدي تحديد هذا المعرّف (على سبيل المثال، في إعداد Claude Code يُرفق دائمًا كتلة `thinking`) إلى إعادة التحويل إلى `<provider>/<model>` الفعلي مع تعطيل الاستدلال — باستخدام `thinking:{type:"disabled"}` في مسار `/v1/messages`، أو بإزالة حقلي `reasoning`/`reasoning_effort` في مسار `/v1/chat/completions`. لا يُدرج هذا المتغير إلا لنماذج عائلة Claude التي تدعم التفكير **وتلتزم** بالقيمة `disabled` (لذلك، على سبيل المثال، تُستبعد النماذج ذات الوضع التكيفي فقط التي ترفض `disabled`). يمكن للمشغّلين فرض تفعيل هذا المتغير أو تعطيله لكل نموذج عبر `ModelSpec.noThinkingAlias`.

## إنشاء الصوت باستخدام ElevenLabs

هيّئ اتصال مزوّد `elevenlabs` في OmniRoute باستخدام مفتاح ElevenLabs API الخاص بك.
تُصادق التطبيقات العميلة باستخدام مفتاح **OmniRoute** الخاص بها (`Authorization: Bearer $OMNIROUTE_API_KEY`)؛
وتوفّر البوابة مفتاح المزوّد المخزّن على هيئة `xi-api-key`. لا ترسل أبدًا مفتاح ElevenLabs
بصفته رمز حامل البوابة.

| الطريقة | المسار                      | الاستجابة                               | فئة نقطة نهاية مفتاح API |
| ------- | --------------------------- | --------------------------------------- | ------------------------ |
| POST    | `/v1/sound-generation`      | بايتات صوت أصلية                        | `elevenlabs`             |
| POST    | `/v1/music`                 | بايتات صوت أصلية                        | `music`                  |
| POST    | `/v1/music/stream`          | بايتات صوت متدفقة                       | `music`                  |
| POST    | `/v1/music/detailed`        | صوت أصلي متعدد الأجزاء وخطة تأليف       | `music`                  |
| POST    | `/v1/music/detailed/stream` | بيانات وصفية أصلية عبر SSE ومقاطع صوتية | `music`                  |
| POST    | `/v1/music/plan`            | خطة تأليف بصيغة JSON                    | `music`                  |

تُكمل نقاط النهاية هذه المسارات الحالية `/v1/audio/speech` و`/v1/audio/transcriptions`
و`/v1/voices` و`/v1/text-to-speech/{voiceId}` و`/v1/speech-to-text`. تُحفظ حقول JSON الأصلية
ومعلمات الاستعلام مثل `output_format` و`enable_logging`.
تحتفظ استجابات `/v1/music/detailed` بحدود الأجزاء المتعددة الخاصة بها؛ لذا حلّلها على أنها متعددة الأجزاء.
تُرجع `/v1/music/detailed/stream` النوع `text/event-stream` مع بيانات التأليف الوصفية
ومقاطع صوتية بترميز base64 ضمن أحداث SSE. تدعم المسارات الستة جميعها طلبات CORS التمهيدية.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# مؤثر صوتي قصير. المدة: من 0.5 إلى 30 ثانية.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# تُعبّر مدة الموسيقى بالمللي ثانية: من 3000 إلى 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

استخدم `/v1/music/stream` مع نص JSON نفسه لتسليم الصوت تدريجيًا. يقبل التأليف
واحدًا فقط من `prompt` أو `composition_plan`؛ وتتطلب `/v1/music/plan` الحقل `prompt`
وتقبل اختياريًا `source_composition_plan`. تحتفظ المخططات الأصلية بحقول المزوّد الإضافية
كي تصل إصدارات خطط التأليف وخيارات الضبط الدقيق إلى ElevenLabs.

تقبل نقطة النهاية الموحّدة `/v1/music/generations` أيضًا `elevenlabs/music_v1`
و`elevenlabs/music_v2` و`elevenlabs/music_v2_5`. عند وجود اتصال ElevenLabs نشط،
تُعرض هذه النماذج في كتالوج الموسيقى. تُرجع نقطة النهاية هذه
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. يُقاس حقل `duration` فيها
بالثواني ويُطابق `music_length_ms`؛ وتكون الأولوية لقيمة `music_length_ms` الصريحة.
يُطابق `instrumental` الحقل `force_instrumental`، مع إعطاء الأولوية للحقل الأصلي.
استخدم نقاط النهاية الأصلية للبث، ونقطة نهاية التأليف الأصلية
للطلبات المعتمدة فقط على خطة تأليف.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

تُطبّق قيود نقطة النهاية والنموذج والميزانية والاتصال قبل إجراء استدعاء إلى الخدمة العليا. تُرجع
المسارات الأصلية رموز حالة الخدمة العليا ونصوص الأخطاء دون تغيير، بما في ذلك `402` عند وجود قيد
في الخطة و`429` عند بلوغ حد الحصة. تُحفظ الترويسات `character-cost` و`song-id` و`request-id` و`retry-after`
عند وجودها. لا يضمن رصيد ائتماني مجاني إمكانية الوصول إلى كل نموذج موسيقي
أو تنسيق إخراج أو ميزة API؛ إذ تحدد ElevenLabs الأهلية لكل طلب.
تحافظ نقطة النهاية الموحّدة على رموز حالة الأخطاء ضمن غلاف الأخطاء الموحّد الخاص بـ OmniRoute.

عقود الخدمة العليا: [المؤثرات الصوتية](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert)،
[تأليف الموسيقى](https://elevenlabs.io/docs/api-reference/music/compose)، و
[تفاصيل بث الموسيقى](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **عُقد موفّر إعادة الترتيب:** يوجّه `POST /v1/rerank` أيضًا الطلبات إلى عُقد موفّرين متوافقة مع OpenAI
> ‏(oMLX وvLLM وInfinity وTEI خلف بوابة، …) يُشار إليها بالصيغة `<node-prefix>/<model>`. تكون عُقد الاسترجاع
> الحلقي (`localhost` و`127.0.0.1` و`172.16.0.0/12`) مؤهلة دائمًا، وكذلك أسماء المضيفين التي
> يدرجها المشغّل في `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (مثل اسم خدمة Docker/Compose
> كـ `http://reranker:8080/v1`؛ إذ تُستدعى هذه العُقد مباشرةً، ولا تمر أبدًا عبر `HTTP(S)_PROXY` أو
> الوكيل المثبّت لاتصال ما). لا تكون العُقد الموجودة على أي مضيف آخر
> — سواء كان جهازًا على الشبكة المحلية أو نظيرًا عبر Tailscale — مؤهلة إلا عندما يفعّل المشغّل
> علامة الميزة `RERANK_REMOTE_PROVIDER_NODES` **و** يجتاز عنوان URL الأساسي للعقدة سياسة عناوين URL
> الصادرة للموفّر (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> تستدعي خطوة إعادة الترتيب في محرك الذاكرة هذا المسار عبر
> الاسترجاع الحلقي، ولذلك تنطبق القاعدة نفسها على `rerankProviderModel` في إعدادات الذاكرة.
>
> **أشكال الخوادم المحلية:** تُستدعى العقدة عند `<base>/v1/rerank`، وعند تلقي 404، عند `<base>/rerank`
> ‏(Infinity وTEI). يتضمن نص الطلب المرسل إلى الخادم المصدر كلاً من صياغة Cohere/OpenAI (`documents`
> و`return_documents`) وصياغة TEI (`texts` و`return_text`)، وتُطبَّع استجابة الخادم المصدر
> إلى غلاف Cohere: إذ تُعاد مصفوفة TEI المجرّدة `[{index, score, text}]`، والبنية `{results: [{index, score}]}`
> من البوابات الخفيفة، والبنية بأسلوب Voyage‏ `{data: [...]}` جميعها إلى العميل بالصيغة
> `{results: [{index, relevance_score, document?}]}`، مرتبةً حسب الدرجة ومحدودةً بالقيمة `top_n`.

> **اكتشاف عُقد الموفّرين:** تظهر النماذج الموجودة على عقدة موفّر متوافقة مع OpenAI ضمن `GET /v1/models`
> تحت بادئة العقدة. ترث الصفوف التي لا تحمل بيانات وصفية لنقطة النهاية (وهو أمر شائع في قوائم `/v1/models` المحلية)
> قيمة `apiType` الخاصة بالعقدة، ولذلك تكون نماذج عقدة `embeddings` من النوع `type: "embedding"` وتكون
> نماذج عقدة `rerank` من النوع `type: "rerank"` بدلًا من تعيينها افتراضيًا إلى المحادثة؛ ومع ذلك تظل قيمة
> `supportedEndpoints` الصريحة في صف متزامن أو مضاف يدويًا ذات أولوية.

### ‏`provider_options` في Exa وTavily

يقرأ Exa وTavily الحقول الخاصة بالموفّر من حاوية ذات نطاق اسمي:
`provider_options.exa` (أو `provider_options["exa-search"]`) و`provider_options.tavily`
(أو `provider_options["tavily-search"]`). لا تُمرَّر سوى المفاتيح أدناه. يُفحَص كل واحد منها
مقابل مخطط Zod الخاص به في `open-sse/handlers/search/providerOptionsPassthrough.ts`،
ويُستبعد أي مفتاح من النوع غير الصحيح. ويُتجاهل أي مفتاح آخر، بما في ذلك المصادقة وعنوان URL الأساسي
و`stream` و`outputSchema`. تستمر المفاتيح المسطّحة التي تستخدمها الجهات الموفّرة الأخرى (`cx` و`depth` و...) في العمل
كما كانت من قبل.

| الموفّر | حقول المستوى الأعلى                                                                                                                                                                                                                                                                                                                                                       | المتداخلة                                                                                                                                                             |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa     | `type`، `category`، `userLocation`، `moderation`، `additionalQueries`، `objective`، `systemPrompt`، `compliance` (قيم أولية مسطّحة)، `startPublishedDate`، `endPublishedDate`                                                                                                                                                                                             | تُدمج `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` فوق القيمة الافتراضية `{ text: true, highlights: true }` |
| Tavily  | `search_depth`، `chunks_per_source`، `time_range`، `start_date`، `end_date`، `include_published_date`، `filter_by_published_date`، `include_answer`، `include_raw_content`، `include_images`، `include_image_descriptions`، `include_favicon`، `include_domains_mode`، `language`، `filter_by_language`، `auto_parameters`، `exact_match`، `include_usage`، `safe_search` | —                                                                                                                                                                     |

تكون الأولوية دائمًا للحقول العامة: `query` و`max_results` و`filters` (النطاقات) و`country`، وكذلك
الموضوع المشتق من `search_type`. في Exa، تُبقي `search_type: "news"` على `category: "news"`.
يقبل Tavily أيضًا `search_type: "finance"` ‏(`topic: "finance"`).

ويتلقى Tavily ‏`start_date` ‏(`YYYY-MM-DD`). ويتجاوز التاريخ المحدد صراحةً في `provider_options`
التاريخ المعيّن تلقائيًا.

تحتفظ نتائج Exa بالحقول `id` و`highlight_scores` و`summary` و`subpages` و`entities` و`extras` داخل
`provider_raw`. وتحتفظ نتائج Tavily بالحقول `images` و`favicon`.

لا تزال محاسبة التكلفة تستخدم السجل المسطّح `costPerQuery`. يحتسب Tavily
تكلفة `search_depth: "advanced"` بعدد أكبر من الأرصدة لكل استدعاء، ولا يظهر هذا الفرق في
`usage.search_cost_usd`.

## واجهة Web Fetch API

استخرج المحتوى من عنوان URL عبر موفّر web-fetch مُهيّأ (Firecrawl، أو Jina
Reader، أو Tavily Extract، أو TinyFish Fetch، أو Nimble Extract، أو Parallel Extract).

يُرجع Parallel Extract (`parallel-search`، باستخدام مفتاح API نفسه الخاص بـ Parallel Search) تنسيق Markdown
فقط — وأي `format` آخر يؤدي إلى `400` — ويحدّ المحتوى بـ 100,000 حرف. عندما
يتعذّر استخراج الصفحة المستهدفة نفسها، تُبلغ الخدمة المصدرية عن ذلك ضمن استجابة HTTP 200؛
ويعرض OmniRoute ذلك على هيئة `422` مع رسالة ثابتة.

| الطريقة | المسار          | الوصف                                                                        |
| ------- | --------------- | ---------------------------------------------------------------------------- |
| POST    | `/v1/web/fetch` | جلب/استخلاص عنوان URL — يتم التحقق من النص الأساسي بواسطة `v1WebFetchSchema` |

**المصادقة:** مفتاح API من نوع Bearer (`extractApiKey` + `isValidApiKey`). تُطبَّق السياسة عبر `enforceApiKeyPolicy`.

**الرجوع الاحتياطي المراعي للحصة (#8297):** عند عدم تحديد `provider` صراحةً، يتم
اجتياز المجموعة
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`)
وفق ترتيب أولوية ثابت (الملء أولًا) — حيث يتم تخطي الموفّر المُهيّأ الذي يخضع لتحديد المعدّل
بدلًا من إنهاء الطلب مبكرًا، كما يؤدي فشل قابل لإعادة المحاولة/مرتبط بالحصة من الخدمة المصدرية
(HTTP 429 دائمًا؛ و402/403 لخطط المستويات المجانية المرتبطة بالحصة لدى Firecrawl/Tavily/TinyFish —
وليس لدى Jina Reader، وليس أبدًا عند وجود طلب 400 غير صالح عادي) إلى الانتقال إلى
الموفّر التالي غير المجرّب الذي تتوفر له بيانات اعتماد أثناء تنفيذ الطلب. عند استنفاد جميع الموفّرين في
المجموعة، تُرجع نقطة النهاية استجابة `429` واحدة (مع ترويسة `Retry-After`)
بدلًا من استجابة `400` العامة السابقة. عند طلب `provider` صراحةً،
لا يوجد **أي** رجوع احتياطي صامت — إذ يعرض الموفّر الصريح الذي يخضع لتحديد المعدّل أو يفشل
خطأه الخاص (`429` إذا كان خاضعًا لتحديد المعدّل، وإلا فتُعرض حالة
الخدمة المصدرية).

## البث عبر WebSocket

```bash
GET /v1/ws?handshake=1
```

يتحقق من مصافحة ترقية WebSocket ويُرجع رسائل أمثلة بروتوكول النقل (`request`، و`cancel`). تتم معالجة إطارات WS الفعلية بواسطة خادم WS المضمّن خارج جدول مسارات Next.js.

**المصادقة:** مفتاح API من نوع Bearer أثناء المصافحة.

### Responses API عبر WebSocket (لـ codex فقط)

```bash
# المضيف والمنفذ نفسيهما لواجهة HTTP API (الافتراضي 20128)؛ قم بترقية الاتصال:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (أو: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# يجب أن يكون الإطار الأول response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

وكيل Responses-API-over-WebSocket موصول **حصريًا بـ `codex`** (الواجهة الخلفية لـ ChatGPT).
ويستمع على المنفذ نفسه المستخدم لواجهة API/لوحة المعلومات ضمن المسارات `/v1/responses`،
و`/responses`، و`/api/v1/responses`. عند أول إطار `response.create`، يُجري
المصادقة والتحضير عبر جسر `codex-responses-ws` الداخلي، ويختار اتصال
OAuth خاصًا بـ codex، وينشئ نفقًا إلى `wss://chatgpt.com/backend-api/codex/responses`
عبر وسيلة النقل `wreq-js`. **تُرفض النماذج غير التابعة لـ codex** (`codex_ws_provider_required`).
لاستخدام التوجيه عبر مشاركة الحصة، استخدم `model: "qtSd/<group>/codex/<model>"`. تم التنفيذ في
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**المصادقة:** مفتاح API من نوع Bearer أثناء المصافحة. يجب أن يكون خادم HTTP المضمّن (`server-ws.mjs`)
هو نقطة الدخول النشطة (وهو كذلك افتراضيًا عند وجود `app/server-ws.mjs`).

#### معرّف النموذج: استخدم معرّف ChatGPT المجرّد (من دون بادئة `codex/`)

تتحقق واجهة سطر أوامر OpenAI **Codex CLI** من اسم النموذج من جانب العميل عندما تكون
`supports_websockets = true`، كما **ترفض المعرّفات المسبوقة باسم الموفّر** مثل
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). أرسل المعرّف **المجرّد** (مثل `gpt-5.5`). جسر OmniRoute
مخصص لـ codex فقط، ولذلك يعيد مطابقة المعرّف المجرّد كنموذج codex
(`resolveCodexWsModelInfo`) قبل إنشاء النفق إلى الخدمة المصدرية — رغم أن المعرّف المجرّد
`gpt-5.5` كان سيوجَّه بخلاف ذلك إلى موفّر آخر عبر HTTP.

#### تهيئة OpenAI Codex CLI

وجّه Codex CLI إلى OmniRoute عن طريق إضافة موفّر مخصص يدعم WebSocket
إلى `~/.codex/config.toml` (استخدم `CODEX_HOME` منفصلًا لتجنب تعديل
تهيئة موجودة):

```toml
model = "gpt-5.5"                 # معرّف مجرّد — وليس "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # من دون شرطة مائلة لاحقة؛ يُشتق عنوان URL الخاص بـ WS (استخدم https/wss في بيئة الإنتاج)
wire_api = "responses"                    # القيمة الوحيدة المدعومة منذ فبراير 2026
supports_websockets = true                # يفعّل وسيلة النقل Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # يحتوي على مفتاح OmniRoute API ‏(Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # مفتاح OmniRoute API (أي مفتاح إذا كانت REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

تُرقّي واجهة CLI المسار `base_url + /responses` إلى WebSocket، وينشئ OmniRoute نفقًا له
إلى اتصال OAuth المحدد الخاص بـ codex. تم التحقق منه من طرف إلى طرف مقابل الخادم
المحلي: يُرجع ChatGPT ‏`codex.rate_limits` + `response.created` ويبث
الإكمال.

## الاستخدام بالخدمة الذاتية (`/api/usage/om-usage`)

يمكن لأي مفتاح API قراءة استخدامه وحصصه **الخاصة به** — من دون مصادقة إدارية. هذه هي نقطة النهاية التي
يستخدمها العميل (CLI، أو لوحة OmniCopilot) لعرض إنفاق حامل المفتاح.

```bash
# الصيغة النصية (العقد التاريخي — نص عادي للطرفية)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# الصيغة المنظّمة — وهي ما تستهلكه واجهة المستخدم
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

يجب أن يكون الخيار **`allowUsageCommand`** مفعّلًا للمفتاح (وهو معطّل افتراضيًا — يبدّله مدير مفاتيح API
في لوحة المعلومات لكل مفتاح على حدة). من دونه، تستجيب نقطة النهاية بالحالة `403`.

يعيد `?format=json` بنية مميّزة بحيث لا يقرأ المستدعي أبدًا حقل بيانات من استجابة
رفض. عند النجاح:

```jsonc
{
  "allowed": true,
  // لا يظهر إلا عندما يختار المفتاح حدود استخدام خاصة بكل مفتاح (يومية/أسبوعية بالدولار الأمريكي):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // لقطة حصة المزوّد المحدد، أو null عندما لا يكون أي شيء مخزّنًا مؤقتًا بعد:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // لقطة كل اتصال، لكي تتمكن واجهة المستخدم من عرض عدة مزوّدين جنبًا إلى جنب:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

عند الرفض (`401` لمفتاح غير صالح / `403` لعدم السماح)، يعيد المسار نفسه
`{ "allowed": false, "error": { "message": "…" } }` — وتختلف حالة وجود `personal`/`provider` فارغ
(المفتاح مسموح به، لكن لم تُجمع أي معلومات بعد) عن حالة الرفض، ولا تميّز بينهما إلا صيغة JSON.

**المصادقة:** مفتاح API من نوع Bearer الخاص بالمستدعي، ويُتحقق منه باستخدام `isValidApiKey` — وهذه _ليست_
واجهة الإدارة (`/api/keys/…`)، التي تظل محمية بواسطة `requireManagementAuth`.

### النسب المئوية الخام للحصص مقابل النسب المعدّلة وفق حد القطع

عند استهلاك `/api/usage/om-usage`، ينبغي للمستدعين ملاحظة الفرق بين النسب المئوية المعروضة في
**المخرجات النصية العادية** وتلك الواردة في **مخرجات JSON** المنظّمة:

| الجانب               | تنسيق النص العادي (`/api/usage/om-usage` / `@@om-usage`)                              | تنسيق JSON ‏(`?format=json`)                                                       |
| :------------------- | :------------------------------------------------------------------------------------ | :--------------------------------------------------------------------------------- |
| **حقل المخرجات**     | `NN% left` (مثل `20% left`)                                                           | `provider.quotas` / `providers[].quotas`                                           |
| **القياس**           | **السعة القابلة للاستخدام المعدّلة وفق حد القطع**: السعة المتبقية فوق عتبة القطع      | **حصة المصدر الخام**: قياس المزوّد غير المعدّل                                     |
| **تحجيم حد القطع**   | يُحجّم عبر `effectiveRemainingPercent()` بحيث يظهر الاحتياطي المحمي على أنه `0% left` | لا يوجد (قيم اللقطة الخام كما أبلغ عنها المزوّد)                                   |
| **بيانات العتبة**    | مضمّنة في النسبة المئوية المعروضة                                                     | مخزّنة في `quotaWindowThresholds` لكل اتصال (أو تُستخدم إعدادات الخادم الافتراضية) |
| **المستهلك الأساسي** | واجهات CLI التفاعلية، ومطالبات الطرفية، والمشغّلون البشريون                           | عمليات التكامل البرمجية، ولوحات المعلومات، والتحليلات، ومتتبعات الفوترة            |

#### معادلة تعديل حد القطع

يدعم OmniRoute حدود قطع استباقية للحصص لمنع استنفاد موارد المصدر (تُهيّأ عبر
`quotaWindowThresholds` الخاصة بالاتصال، أو إعدادات المزوّد الافتراضية، أو إعدادات المرونة العامة). عندما تكون عتبة قطع
(مثل `cutoff = 25%`) نشطة ضمن نافذة حصة، يحسب عارض النص السعة المتبقية كما يلي:

- إذا كان `remaining <= cutoff`: يُرجع `0%`.
- إذا كان `remaining > cutoff`: يُرجع `((remaining - cutoff) / (100 - cutoff)) * 100`.

تقرّب المخرجات النصية المنسّقة هذه القيمة إلى أقرب عدد صحيح (`Math.round(...)`).

#### مثال توضيحي

لنفترض وجود نافذة لمزوّد تبلغ فيها **نسبة الاستخدام الخام 60%** (وبالتالي **حصة خام متبقية قدرها 40%**) مع
تهيئة عتبة **قطع عند 25% من الحصة المتبقية**:

| التمثيل                         | العملية الحسابية                                   | المتبقي |           الاستخدام الضمني           |
| :------------------------------ | :------------------------------------------------- | :-----: | :----------------------------------: |
| **JSON الخام (`?format=json`)** | لقطة المصدر (`quotas[window]`)                     | **40%** |               **60%**                |
| **التنسيق النصي (`NN% left`)**  | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (عند حساب `100 - remaining`) |

- **لماذا يعرض النص بقاء 20%:** من أصل 40% من الحصة الفعلية المتبقية في الحساب، تحجز
  سياسة القطع 25%. لا يتبقى للمستدعي سوى 15% من أصل هامش قابل للاستخدام قدره 75% قبل أن يتوقف الموجّه
  عن توجيه الطلبات إلى هذا الاتصال. يضمن التحجيم أن يشير الاتصال إلى الاستنفاد (`0% left`) بالضبط عندما
  يتوقف التوجيه.
- **لماذا يحتفظ JSON بالقيم الخام:** تعيد حمولة JSON لقطة المزوّد الدقيقة (`UsageSnapshot`)
  لكي تتمكن الأدوات الخارجية من الوصول إلى استخدام المصدر الفعلي الموثوق و
  `quotaWindowThresholds` على مستوى الاتصال، من دون تحجيم فاقد للمعلومات من جانب الخادم.

#### إرشادات ترحيل المستهلكين

إذا كان تكامل خارجي (مثل مكوّن إضافي للمحرر أو امتداد للوكيل) قد استخرج سابقًا النص آليًا من
نقطة النهاية النصية (`NN% left`) وحسب النسبة المئوية المستخدمة على أنها `100 - NN`، فإن الانتقال إلى `?format=json` يعني:

- ستعكس قراءة قيم JSON الأولية **الاستهلاك الفعلي في المصدر الرئيسي** (استخدام 60% في المثال أعلاه).
- إذا أراد التكامل الحفاظ على دلالات المقدار المتاح للاستخدام في نقطة النهاية النصية، فيمكنه تقييم
  صيغة المتبقي الفعلي من جانب العميل باستخدام `quotaWindowThresholds` لعمليات التجاوز على مستوى الاتصال.

  },
  "idempotency": {

### التأثير في زمن الاستجابة

عند حدوث إصابة في ذاكرة التخزين المؤقت الدلالية، تُقدَّم الاستجابة من ذاكرة التخزين المؤقت **من دون إجراء استدعاء
للخدمة الأصلية**، ولذلك تكون قيمة `X-OmniRoute-Response-Latency` المُبلّغ عنها قريبة من الصفر
(بغض النظر عن زمن استجابة الخدمة الأصلية). ينبغي للعملاء الحساسين لزمن الاستجابة
(الذين يجرون اختبارات الأداء أو يراقبون p50/p99) التحقق من ترويسة الاستجابة
`X-OmniRoute-Cache-Latency`:

| القيمة      | المعنى                                                                                  |
| ----------- | --------------------------------------------------------------------------------------- |
| `synthetic` | قُدِّمت الاستجابة من ذاكرة التخزين المؤقت؛ وزمن الاستجابة ليس زمن الخدمة الأصلية الفعلي |
| _(غائبة)_   | الاستجابة ناتجة عن استدعاء فعلي للخدمة الأصلية                                          |

### تجاوز ذاكرة التخزين المؤقت لكل مفتاح

يمكن لمفاتيح API إلغاء الاشتراك في عمليات القراءة من ذاكرة التخزين المؤقت الدلالية عبر `cacheDefaultMode`:

| القيمة   | السلوك                                                                     |
| -------- | -------------------------------------------------------------------------- |
| `legacy` | السلوك الطبيعي لذاكرة التخزين المؤقت (الافتراضي)                           |
| `bypass` | تخطّي البحث في ذاكرة التخزين المؤقت تمامًا؛ واستدعاء الخدمة الأصلية دائمًا |

يمكن تعيينه عند إنشاء المفتاح (`POST /api/keys`) أو تحديثه (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### التجاوز لكل طلب

يمكن لأي طلب تجاوز ذاكرة التخزين المؤقت بغض النظر عن إعدادات المفتاح:

```
X-OmniRoute-No-Cache: true
```

[مصادقة الإدارة](../guides/MANAGEMENT-AUTH.md).

### المصادقة

| نقطة النهاية                  | الطريقة  | الوصف                                                                                                                                                                                                                                                                                                 |
| ----------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/auth/login`             | POST     | تسجيل الدخول                                                                                                                                                                                                                                                                                          |
| `/api/auth/logout`            | POST     | تسجيل الخروج                                                                                                                                                                                                                                                                                          |
| `/api/settings/require-login` | GET/POST | حالة تسجيل الدخول (GET، عامة). يعيّن POST كلمة المرور أو يبدّل حالة تسجيل الدخول: يقتصر على المشغّل بمجرد وجود كلمة مرور (جلسة لوحة المعلومات أو CLI محلي أو عند تعطيل تسجيل الدخول — تتلقى مفاتيح API ورموز `oma_` الاستجابة `403`)؛ ترسل جلسة لوحة المعلومات `currentPassword` لاستبدال كلمة المرور |

| نقطة النهاية                            | الطريقة                   | الوصف                                                                                                                                             |

| `/api/providers/bulk`                   | POST                      | إضافة مفاتيح API دفعةً واحدة لموفّر واحد                                                                                                          |
| `/api/providers/import`                 | POST                      | استيراد قائمة غير متجانسة من الموفّرين من ملف CSV/JSON جرى تحليله (#6836)؛ مع نتائج فشل جزئي لكل صف                                               |

| `/api/provider-models`                  | GET/POST/PUT/PATCH/DELETE | النماذج المخصصة وعمليات التجاوز لكل نموذج (الإضافة، والتحديث، والإخفاء/الإظهار، والحذف)                                                           |

بالنسبة إلى النماذج المتزامنة/المستوردة، تقبل `PUT /api/provider-models` القيم `provider` و`modelId` و
`maxOutputTokenOverride`: يعيّن العدد الصحيح الموجب حدًا أقصى يدويًا لرموز المخرجات، بينما تؤدي `null`
إلى مسحه لاستعادة القيمة الافتراضية. يعيد `GET /api/provider-models?provider=<provider>` هذه
القيم ضمن `modelOutputOverrides`، بما في ذلك النماذج التي لا تحتوي على صف نموذج مخصص. يستخدم التجاوز
إمكانية وقت التشغيل `max_output_tokens` ويظل قائمًا بعد إعادة مزامنة النموذج. توفر صفحة الموفّر المتوافق
مع OpenAI عناصر التحكم نفسها للتحرير/المسح، وتضع علامة على النماذج التي تدعم الرؤية بشكل صريح.

تكيّف عُقد Chat Completions المخصصة عمليات إلغاء الاشتراك الصريحة في الاستدلال مع الواجهة الخلفية المنبع. يؤدي
اختبار الاتصال الناجح تلقائيًا إلى تحديد عناصر التحكم في قالب المحادثة لكل معرّف نموذج مطابق تمامًا
يثبت إدخاله في `/models` قيمة `owned_by` معروفة: `vllm` أو `sglang` أو `llamacpp`.
قد تحتفظ الأغلفة الشفافة المتوافقة مع OpenAI بإدخال النموذج الأصلي داخل كائن
`openai` متداخل؛ ويتتبع الاكتشاف ما يصل إلى ثلاثة أغلفة من هذا النوع. تحتفظ النماذج ذات الملكية المفقودة أو المجهولة أو
المتعارضة بسلوك OpenAI المعتاد. يعيد الاكتشاف استخدام طلب الكتالوج الحالي،
ولا ينشئ أي رموز إكمال، ويُبطَل عند تغيير نقطة نهاية الاتصال.

لتثبيت هذا السلوك لواجهة خلفية لا تعرض تلك البيانات الوصفية، استخدم واجهة API الحالية
للتحديث الجزئي للموفّر:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

أرسل ذلك النص مع `PUT /api/providers/<connection-id>`. في ذلك الاتصال، يُرسل
جهد الاستدلال الصريح بالقيمة `none` على هيئة `chat_template_kwargs.thinking=false` و
`chat_template_kwargs.enable_thinking=false`. تظل قيم القالب الأصلية الصريحة هي المرجع المعتمد
ما لم تفرض قاعدة استدلال من جانب الخادم مستوى جهد. لا ينطبق الإعداد إلا عندما يرسل اتصال
مخصص متوافق مع OpenAI نص طلب Chat Completions؛ وتحتفظ طلبات Responses والموفّرون العاديون
ببنية طلباتهم الأصلية. اضبط `reasoningControl` على `openai` لفرض تمرير
`reasoning_effort` المعتاد في OpenAI، أو احذفه/اضبطه على `null` لاستخدام الاكتشاف التلقائي.

تُعطّل طلبات مصنّف الوضع التلقائي في Claude Code التفكير الأصلي افتراضيًا عندما لا تحتوي
على عناصر تحكم صريحة في الاستدلال. يستخدم الاكتشاف علامة النظام الخاصة بالمصنّف في الطلبات بتنسيق Claude،
وليس أسماء النماذج أو حدود الإكمال. تظل الأولوية الحالية لعناصر التحكم الصريحة في النص،
ورؤوس الجهد/التفكير المدعومة، وقواعد التوجيه، وجهد النموذج الذي جرى حله. تحتفظ مرحلتا المصنّف
كلتاهما بالمطالبات وحدود الإكمال وتسلسلات الإيقاف وأحكام الأذونات الفعلية من المنبع؛
ولا يزال بإمكان المرحلة الثانية إنتاج الاستدلال المرئي المطلوب كنص عادي.

### الإصدار وقناة الإصدار

```bash
GET /api/system/version
```

مسار إدارة متاح للمضيف المحلي فقط (يتطلب مصادقة المسؤول). يُرجع الإصدار قيد التشغيل وأحدث
إصدار منشور وحالة التحديث التلقائي. الحقلان `releaseChannel` و`channels` هما حقلا إضافة
(المسار 3.8.54)؛ ويحتفظ `channel` بمعناه — أي وضع النشر الذي يستخدمه محدّث لوحة المعلومات
(`npm` أو `source` أو `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — قناة npm للبنية قيد التشغيل: `nightly` للإصدارات التي تتضمن `-nightly.*`،
  و`next` للإصدارات التجريبية الأخرى (`-rc.*` و`-beta.*` و`-alpha.*`)، و`lts` لإصدار مستقر من
  إصدار رئيسي أقدم من `channels.latest`، وإلا فتكون `latest`. وهي القواعد نفسها المستخدمة في
  `scripts/release/dist-tag.mjs`، الذي يختار وسم توزيع npm وقت النشر.
- `channels` — أحدث إصدار منشور لكل وسم توزيع، من `npm view omniroute dist-tags` (مع الرجوع
  الاحتياطي إلى HTTP الخاص بالسجل)، ويُخزّن مؤقتًا باستخدام مدة الصلاحية نفسها البالغة 10 دقائق مثل `latest`. يكون `latest` موجودًا دائمًا
  (ويرجع احتياطيًا إلى الحقل `latest`، ثم `"unavailable"`)، بينما لا تظهر `next` و`nightly` و`lts`
  إلا عند وجود وسم التوزيع المقابل. يؤدي طلب `Cache-Control: no-cache` إلى تحديث عمليتي البحث كلتيهما.

يوضَّح نموذج القنوات (`latest` = v3 حتى الإصدار العام 4.0، و`next` = rc، و`nightly` = بُنى `develop`،
و`lts` = تصحيحات v3 بعد الإصدار العام 4.0) في `docs/ops/RELEASE_STRATEGY.md`.

```bash
# اسم مستعار للكتالوج بنمط OpenAI
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# أسماء مستعارة للمحادثة بنمط OpenAI

# أسماء مستعارة بنمط Ollama
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

مثال:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

ملاحظات:

- تعيد الأسماء المستعارة ذات الرموز المضمّنة استخدام المعالجات نفسها المستخدمة مع `/v1/*` و`/api/tags`؛ وتظل بُنى الاستجابات متطابقة.
- استخدم `Authorization: Bearer ...` بشكل مفضّل متى كان العميل يدعم الترويسات المخصصة.
- قد تظهر الرموز المضمّنة في عناوين URL ضمن سجلات الوكيل العكسي وسجل المتصفح وبيانات القياس عن بُعد خارج OmniRoute. تعامل معها كخيار للتوافق، وليس كأسلوب المصادقة الافتراضي.

## حدود الرموز

ميزانيات **الرموز** لكل مفتاح API (وهي منفصلة عن الميزانية المستندة إلى USD أعلاه). تُفرض مباشرةً ضمن مسار الطلب: عندما يصل استخدام المفتاح في النافذة الحالية إلى الحد المسموح به، تُرفض الطلبات بالاستجابة `429 Too Many Requests`. يمكن تحديد نطاق الحدود لنموذج `model` معين، أو مزوّد `provider`، أو تطبيقها `global` على المفتاح بأكمله؛ وعندما تتطابق عدة حدود مع طلب ما، يُطبّق الحد الأكثر تقييدًا.

```bash
# سرد حدود الرموز الخاصة بمفتاح (يتضمن الاستخدام المباشر للنافذة)
GET /api/usage/token-limits?apiKeyId=key-123

# إنشاء حد للرموز أو تحديثه
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# حذف حد للرموز حسب المعرّف
DELETE /api/usage/token-limits?id=tl-abc
```

> **ملاحظات المخطط** (`setTokenLimitSchema`): الحقلان `apiKeyId` و`scopeType` (`model` | `provider` | `global`) مطلوبان. يكون `scopeValue` مطلوبًا ما لم يكن `scopeType` هو `global` (مثل معرّف نموذج لنطاق `model`، أو معرّف مزوّد لنطاق `provider`). يجب أن يكون `tokenLimit` عددًا صحيحًا موجبًا (ويُحوَّل من سلسلة نصية). الحقول الاختيارية: `id` (احذفه للإنشاء، وقدّمه للتحديث)، و`resetInterval` (`daily` | `weekly` | `monthly`، والقيمة الافتراضية `monthly`)، و`resetTime` (`HH:MM`)، و`enabled` (القيمة الافتراضية `true`). تُثري استجابات `GET` كل حد بالحقول `tokensUsed` و`remaining` و`windowStart` و`periodStartAt` و`nextResetAt`. هذه نقطة نهاية من فئة الإدارة (تُفرض المصادقة مركزيًا بواسطة مسار التفويض).

## معالجة الطلبات

1. يرسل العميل طلبًا إلى `/v1/*`
2. يستدعي معالج المسار `handleChat` أو `handleEmbedding` أو `handleAudioTranscription` أو `handleImageGeneration`
3. يُحدَّد النموذج (مزوّد/نموذج مباشر أو اسم مستعار/تركيبة)
4. تُحدَّد بيانات الاعتماد من قاعدة البيانات المحلية مع تصفية الحسابات حسب التوفر
5. بالنسبة إلى المحادثة: يتحقق `handleChatCore` من ذاكرة التخزين المؤقت الدلالية/الخاصة بالتوقيع ويحدّد إعدادات ضغط التركيبة
6. يُنفَّذ الضغط الاستباقي قبل الترجمة الخاصة بالمزوّد عند تمكينه (`lite` أو Caveman أو RTK أو المكدّس)
7. يرسل منفّذ المزوّد الطلب إلى الخدمة العليا
8. تُترجم الاستجابة مجددًا إلى تنسيق العميل (للمحادثة) أو تُعاد كما هي (للتضمينات/الصور/الصوت)
9. يُسجَّل الاستخدام وتحليلات الضغط وسجلات الطلبات
10. يُطبَّق البديل الاحتياطي عند حدوث أخطاء وفقًا لقواعد التركيبة

| PATCH   | `/api/v1/management/proxies`                 | تحديث وكيل — يُتحقق من صحة النص الأساسي بواسطة `updateProxyRegistrySchema` (يتطلب `id`)                                              |
| DELETE  | `/api/v1/management/proxies?id=...&force=1`  | حذف وكيل (استخدم `force=1` لفصل الإسنادات)                                                                                           |
| GET     | `/api/v1/management/proxies/assignments`     | سرد الإسنادات — يمكن تصفيتها حسب `proxy_id` و`scope` و`scope_id`؛ مرّر `resolve_connection_id=<id>` لتحديد الوكيل النشط لاتصال       |
| PUT     | `/api/v1/management/proxies/assignments`     | إسناد — يُتحقق من صحة النص الأساسي بواسطة `proxyAssignmentSchema` (`{scope, scopeId?, proxyId?}`). يمسح ذاكرة التخزين المؤقت للمرسِل |
| PUT     | `/api/v1/management/proxies/bulk-assign`     | إسناد جماعي — يُتحقق من صحة النص الأساسي بواسطة `bulkProxyAssignmentSchema` (`{scope, scopeIds[], proxyId?}`)                        |
| GET     | `/api/v1/management/proxies/health?hours=24` | تجميع حالة الوكلاء (أعداد حالات النجاح/الفشل وزمن الاستجابة) خلال نافذة زمنية                                                        |

**المصادقة:** جلسة إدارة/مفتاح API مطلوب لكل مسار (`requireManagementAuth`).

> إن المسارين `POST /api/v1/management/proxies/[id]/assignments` و`POST /api/v1/management/proxies/[id]/health` المذكورين في وصف المهمة توفرهما مسارات `/assignments` و`/health` المباشرة الموضحة أعلاه — ولا توجد مسارات فرعية خاصة بكل معرّف في قاعدة الشفرة.

## المرونة (موسّع)

يوفّر OmniRoute ثلاث آليات مستقلة للتعامل مع حالات الفشل المؤقت؛ وتتيح نقاط النهاية الإدارية أدناه للمشغّلين قراءة حالاتها وتجاوزها:

| النطاق             | تخزين الحالة                           | القراءة                                   | إعادة الضبط / المسح                            |
| ------------------ | -------------------------------------- | ----------------------------------------- | ---------------------------------------------- |
| قاطع دائرة المزوّد | `domain_circuit_breakers` + في الذاكرة | `/api/monitoring/health`                  | `POST /api/resilience/reset`                   |
| فترة تهدئة الاتصال | `rateLimitedUntil` في اتصالات المزوّد  | `/api/rate-limits`, `/api/providers/[id]` | (تُعاد إتاحته تدريجيًا؛ يُمسح عبر PUT للمزوّد) |
| حظر النموذج        | سجل إتاحة النماذج في الذاكرة           | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`       |

تقبل `PATCH /api/resilience` تجاوزات قاطع دائرة المزوّد ضمن `providerBreaker.oauth` و`providerBreaker.apikey`. يدعم كل ملف تعريف `degradationThreshold` و`failureThreshold` و`resetTimeoutMs`؛ كما تتوفر الحقول نفسها في لوحة المعلومات ← الإعدادات ← المرونة.

```bash
# مسح حظر نموذج واحد
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# مسح جميع حالات الحظر
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

للاطلاع على المرجع المفاهيمي الكامل والقيم الافتراضية لقاطع الدائرة: راجع [`CLAUDE.md`](../../CLAUDE.md) ← "حالة وقت تشغيل المرونة" و[`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### قائمة انتظار حدود المعدّل وشبكة أمان التمكين التلقائي

- **مسار الكتابة المدعوم**: تُعدّ `POST /api/rate-limits` مع المحتوى `{"connectionId": "<id>", "enabled": true|false}` نقطة النهاية الإدارية المدعومة لتبديل حماية حدود المعدّل لاتصال. لا تعدّل `PUT /api/providers/[id]` القيمة `rateLimitProtection` ولا تبدّلها عمدًا (#11278).
- **دلالات `enabled: false`**: يؤدي تعيين `enabled: false` إلى إزالة الحماية الصريحة للاتصال، لكنه **لا** يستثني اتصالًا نشطًا يستخدم مفتاح API من شبكة أمان التمكين التلقائي العامة (`autoEnableApiKeyProviders = true`). في `reconcileEnabledConnections` ‏(`open-sse/services/rateLimitManager.ts`)، تكون `false` و`undefined` متكافئتين؛ وتظل اتصالات مفاتيح API النشطة التي لا تتمتع بحماية صريحة محميةً بموجب شبكة أمان التمكين التلقائي.
- **التعطيل العام**: لتشغيل اتصالات مفاتيح API دون قوائم انتظار حدود المعدّل، عطّل شبكة الأمان عموميًا عبر `RATE_LIMIT_AUTO_ENABLE=false` (متغير بيئة) أو `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (الإعدادات ← المرونة / `PATCH /api/resilience`).

## خادم MCP

يتضمن OmniRoute خادم Model Context Protocol مضمّنًا مع 3 وسائل نقل (stdio وSSE وstreamable-http) وأدوات محددة النطاق. تقرأ نقاط نهاية لوحة المعلومات أدناه بيانات الحالة/التدقيق وتعمل كوسيط لوسائل نقل HTTP.

| الطريقة | المسار | الوصف |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | نبضات الاتصال، ووسيلة النقل، وحالة الاتصال، وآخر استدعاء، وأبرز الأدوات، ومعدل النجاح خلال 24 ساعة |
| GET | `/api/mcp/tools` | قائمة أدوات MCP مع `name`، و`description`، و`scopes`، و`phase`، و`auditLevel`، و`sourceEndpoints` |
| GET | `/api/mcp/sse` | فتح تدفق SSE لوسيلة نقل SSE (يعيد `503` إذا كان MCP معطّلًا أو كانت وسيلة النقل غير متطابقة) |
| POST | `/api/mcp/sse` | إرسال إطار JSON-RPC عبر وسيلة نقل SSE |
| GET | `/api/mcp/stream` | فتح جانب SSE من وسيلة نقل HTTP القابلة للبث (الرسائل التي يبدأها الخادم) |
| POST | `/api/mcp/stream` | إرسال إطار JSON-RPC عبر وسيلة نقل HTTP القابلة للبث |
| DELETE | `/api/mcp/stream` | إنهاء جلسة HTTP قابلة للبث |
| GET | `/api/mcp/audit` | الاستعلام عن سجل التدقيق — `?limit=`، `?offset=`، `?tool=`، `?success=true                                | false`، `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | إحصاءات تدقيق مجمّعة (الإجماليات، ومعدل النجاح، ومتوسط المدة، وأبرز الأدوات) |

**المصادقة:** تراعي وسيلتا النقل `sse`/`stream` واجهة المصادقة الخاصة بـMCP (مفتاح API من نوع Bearer بنطاق `mcp`)؛ ويمكن قراءة مسارات `status`/`tools`/`audit*` من لوحة المعلومات (لا توجد مصادقة إضافية مطلوبة بخلاف إمكانية الوصول إلى مضيف لوحة المعلومات).

> تخضع كلتا وسيلتي نقل HTTP لـ`settings.mcpEnabled` و`settings.mcpTransport` — يؤدي عدم تطابق وسيلة النقل إلى إرجاع `400`، بينما تؤدي حالة تعطيل MCP إلى إرجاع `503`.

## خادم A2A

يوفّر OmniRoute نقطة نهاية A2A (من وكيل إلى وكيل) تستخدم JSON-RPC 2.0، بالإضافة إلى واجهة REST مخصّصة للفحص والاستخدام في لوحة المعلومات.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # اختياري ما لم يتم تعيين OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

الأساليب المدعومة (كلها مشروطة بتفعيل `settings.a2aEnabled`):

| الأسلوب          | الوصف                                                     |
| ---------------- | --------------------------------------------------------- |
| `message/send`   | تنفيذ متزامن للمهارة؛ يُرجع `{task, artifacts, metadata}` |
| `message/stream` | تنفيذ متدفق عبر SSE لمجموعة المهارات نفسها                |
| `tasks/get`      | جلب مهمة حسب `taskId`                                     |
| `tasks/cancel`   | إلغاء مهمة حسب `taskId`                                   |

المهارات المضمّنة: `smart-routing`، و`quota-management`، و`provider-discovery`، و`cost-analysis`، و`health-report`.

### بطاقة الوكيل

```bash
GET /.well-known/agent.json
```

يُرجع بطاقة وكيل A2A العامة (الاسم والوصف والإمكانات وكتالوج المهارات ونظام المصادقة) — مخزّنة مؤقتًا بشكل عام لمدة ساعة واحدة. لا تتطلب مصادقة.

### أدوات REST المساعدة

| الأسلوب | المسار                       | الوصف                                                                                                              |
| ------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| GET     | `/api/a2a/status`            | حالة تفعيل A2A + إحصاءات المهام + ملخص بطاقة الوكيل المخزّنة مؤقتًا                                                |
| GET     | `/api/a2a/tasks`             | سرد المهام — `?state=submitted\|working\|completed\|failed\|cancelled`، و`?skill=`، و`?limit=` (≤200)، و`?offset=` |
| POST    | `/api/a2a/tasks`             | (غير منفّذ كأداة REST مساعدة — أنشئ المهمة عبر JSON-RPC باستخدام `message/send`)                                   |
| GET     | `/api/a2a/tasks/[id]`        | استرداد مهمة واحدة                                                                                                 |
| POST    | `/api/a2a/tasks/[id]/cancel` | إلغاء مهمة                                                                                                         |

**المصادقة:** تعمل أدوات REST المساعدة دون مصادقة إدارية (ويمكن قراءتها من لوحة المعلومات)؛ ويستخدم مسار JSON-RPC `/a2a` الرمز المميز Bearer المحدد في `OMNIROUTE_API_KEY` إذا كان مهيّأً.

## المصادقة

راجع [مصادقة الإدارة](../guides/MANAGEMENT-AUTH.md) للتعرّف على عائلات بيانات الاعتماد الأربع
(جلسة لوحة المعلومات، ورمز CLI المحلي، ورمز الوصول `oma_live_…`،
ومفتاح API ذي نطاق الإدارة) وكيف تختلف عن مفاتيح الاستدلال.

- تستخدم مسارات لوحة المعلومات (`/dashboard/*`) ملف تعريف الارتباط `auth_token`
- يستخدم تسجيل الدخول تجزئة كلمة المرور المحفوظة؛ مع الرجوع إلى `INITIAL_PASSWORD` عند تعذّر ذلك
- يمكن تبديل `requireLogin` عبر `/api/settings/require-login`
- يمكن أن تتطلب مسارات `/v1/*` مفتاح API من نوع Bearer عند ضبط `REQUIRE_API_KEY=true`
- يُقصد بعبارة «رمز الإدارة» / «مفتاح API ذي نطاق الإدارة» في هذا المرجع إحدى العائلات الواردة في ذلك الدليل — وليس نوعًا إضافيًا غير معرّف من الأسرار

> **تغيير غير متوافق (v3.8.0)** — تتطلب الآن `/api/v1/agents/tasks/*` ونقاط نهاية إدارة فترة التهدئة **مصادقة الإدارة** (ملف تعريف الارتباط `auth_token` الخاص بلوحة المعلومات أو مفتاح API ذي نطاق الإدارة). ستتلقى التطبيقات العميلة التي كانت تستدعي هذه المسارات سابقًا دون مصادقة الاستجابة `401 Unauthorized`. راجع الالتزام `588a0333` ‏(`fix(auth): require management auth for agent and cooldown APIs`).
