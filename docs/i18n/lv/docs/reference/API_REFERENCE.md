## Tērzēšanas pabeigšanas

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

#### Konta piesaiste katram pieprasījumam

Ja pakalpojumu sniedzējam ir vairāki savienojumi (konti vai atslēgas), OmniRoute parasti izvēlas vienu
no tiem, izmantojot savu kontu atlases stratēģiju. Tā vietā pieprasījumu var piesaistīt konkrētam savienojumam,
izmantojot galveni `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kur atrast identifikatoru.** Informācijas panelī atveriet pakalpojumu sniedzēja lapu
  (**Informācijas panelis → Pakalpojumu sniedzēji → <pakalpojumu sniedzējs>**) un savienojuma rindā noklikšķiniet uz `xxxxxxxx…` identifikatora elementa —
  tādējādi tiek nokopēts pilnais savienojuma identifikators.
- **Kuri pieprasījumi to ņem vērā.** Viena modeļa pieprasījumi (`provider/model`) galapunktos
  `/v1/chat/completions`, `/v1/messages` un `/v1/responses`. Kombinācijas ignorē šo galveni: tā vietā
  piesaistiet kontu katram kombinācijas solim, izmantojot attiecīgā soļa savienojumu.
- **Piesaiste ir stingra, nevis tikai priekšroka.** Tiek izmantots tikai piesaistītais savienojums.
  Kļūme pieprasījuma izpildes laikā aktivizē konta nogaidīšanas periodu, taču **neizraisa** pārslēgšanos uz
  citu tā paša pakalpojumu sniedzēja kontu.
- **Nogaidīšanas periods un kvota atceļ piesaisti.** Kamēr piesaistītajam savienojumam ir spēkā nogaidīšanas periods,
  ir izsmelta kvota vai tas ir bloķēts kvotu politikas dēļ, turpmākie pieprasījumi izmanto citus pakalpojumu sniedzēja
  savienojumus tieši tāpat kā nepiesaistīta datplūsma.
- **Nezināmi vai atspējoti identifikatori izraisa kļūmi.** Ja identifikators nav pakalpojumu sniedzēja aktīvajā kopā (tas ir izdzēsts,
  deaktivizēts vai pieder citam pakalpojumu sniedzējam), nav neviena piemērota konta, tādēļ pieprasījums
  beidzas ar kļūmi, nevis tiek nemanāmi maršrutēts citur.

Claude Code nosūta pielāgotas galvenes, izmantojot `ANTHROPIC_CUSTOM_HEADERS`. Ievietojiet to `env` blokā
failā `~/.claude/settings.json` vai projekta līmeņa failā `.claude/settings.json`, lai katram projektam piesaistītu citu
kontu:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Avots: `src/sse/handlers/chat.ts` (galvenes nolasīšana), `src/sse/services/auth.ts` un
`src/sse/services/sessionAffinityPin.ts` (piesaistes atcelšana un pārbaude, vai savienojuma nav aktīvajā kopā).

> **Izmaksu telemetrijas galvenes:** arī veiksmīgas atbildes bez straumēšanas ietver `X-OmniRoute-*` izmaksu telemetrijas kopu — `X-OmniRoute-Response-Cost` (USD, fiksētas 10 zīmes aiz komata; `0.0000000000` bezmaksas gadījumā vai ja cena nav norādīta), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` un `X-OmniRoute-Fallback-Attempts` (tikai tad, ja > 0), kā arī `X-OmniRoute-Request-Id` un `X-OmniRoute-Version`. Tās tiek pievienotas tērzēšanas pabeigšanas atbildēm, `/v1/responses`, `/v1/messages`, **kā arī multivides galapunktu atbildēm** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` un `/v1/moderations` (izmaksas vienmēr ir `0`). Multivides izmaksas tiek aprēķinātas katrai modalitātei atsevišķi (par attēlu, sekundi, rakstzīmi vai meklēšanas vienību), ja ir pieejama cenu informācija; pretējā gadījumā tās ir `0` (kļūmes gadījumā apstrāde tiek turpināta).

> **Kešatmiņas trāpījuma izmaksu semantika:** semantiskās kešatmiņas TRĀPĪJUMA (`X-OmniRoute-Cache-Hit: true`) gadījumā netiek veikts izsaukums augšupējam pakalpojumam, tādēļ `X-OmniRoute-Response-Cost` vērtība ir `0.0000000000` (trāpījuma apkalpošanas **papildu** izmaksas). Sākotnējās jeb iespējamās izmaksas tiek norādītas atsevišķi galvenē `X-OmniRoute-Cost-Saved`. Norēķinu sistēmām jāsumē `X-OmniRoute-Response-Cost` (trāpījumi neko nemaksā); kešatmiņas analītikā var apkopot `X-OmniRoute-Cost-Saved`.

## Ekskluzīvas pārvaldīto sesiju nomas

Ekskluzīva pārvaldīto sesiju noma ir pēc izvēles aktivizējams, no klienta neatkarīgs maršrutēšanas līgums: viens aktīvais īpašnieks
tur vienu prasībām atbilstošu OmniRoute savienojumu. Tas nenomā modeli, nepieprasa OAuth, neidentificē
konkrētu klientu un nepieprasa konkrētu pakalpojumu sniedzēju.

Autentificējošajai API atslēgai ir jābūt tvērumam `lease:exclusive` un skaidri norādītam netukšam
`allowedConnections` sarakstam. Datubāzes mutācijas robeža atslēgas
izveides un daļējas atjaunināšanas laikā nodrošina abu lauku vienlaicīgu izpildi.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Veiksmīgas iegūšanas, atjaunošanas un atbrīvošanas atbildes ietver laikspiedolus, `state` un precīzu pozitīvu
`generation`, taču nekad neatklāj atlasīto savienojumu vai akreditācijas datus. Atjaunošanas un atbrīvošanas pieprasījumos
paaudze tiek norādīta JSON pamattekstā:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Aktīvas nomas īpašnieks var tieši pieprasīt privātumu saglabājošus attēlošanas metadatus par savu pašreizējo piesaisti:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Šī pēc izvēles aktivizējamā statusa darbība vienā datubāzes transakcijā ir norobežota ar necaurredzamo īpašnieka identifikatoru, autentificēto pārvaldīto API atslēgu un precīzu
aktīvo paaudzi. `displayName` ir tikai apgrieztais konfigurētā
savienojuma nosaukums; ja nav droša konfigurētā nosaukuma, tā vērtība ir `null`. OmniRoute nekad neaizstāj to ar
e-pasta adresi vai ģenerētu konta identitāti. Pakalpojumu sniedzēja vērtība ir nesensitīva attēlošanas etiķete, nevis
ģenerēts saderīga pakalpojumu sniedzēja identifikators. Akreditācijas dati, pilnvaras, sīkfaili, neapstrādāti savienojumu vai API
atslēgu ID, īpašnieku jaucējvērtības, norobežošanas noslēpumi un iekšējie maršrutēšanas dati netiek iekļauti.

Meklējumi ar nepareizu atslēgu, nepareizu īpašnieku, novecojušu paaudzi, kā arī trūkstoši, beigušies, atbrīvoti un nederīgi nomas ieraksti
atgriež vienu un to pašu `409 LEASE_FENCE_STALE` kļūdu bez savienojuma metadatiem. Klientam, kas saņēmis atbildi par jaudas gaidīšanu, nav aktīvas piesaistes, ko pārbaudīt. Kad maršrutēšana pārslēdz aktīvu nomu,
tā pati paaudze paliek derīga, un statusa darbība atomāri atgriež jauno piesaisti, nekad neatgriežot veco.
Esošie klienti paliek nemainīti, jo iegūšanas, atjaunošanas, atbrīvošanas un gaidīšanas atbildes saglabā
iepriekšējo struktūru.

Šis servera līgums nemaina standarta OpenAI Codex `/status`. Standarta Codex pašlaik ziņo par savu
modeļa pakalpojumu sniedzēju un iebūvēto autentifikācijas/konta stāvokli, taču neatveido patvaļīgus pielāgota
pakalpojumu sniedzēja konta metadatus; turpmākai klienta integrācijai ir jāizsauc šī darbība un jāizlemj, kā
attēlot `connection.displayName`.

Pēc tam katrs pārvaldītais inferenču pieprasījums norāda abas vadības galvenes:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Precīzais īpašnieks, paaudze, aktīvais savienojums un autentificētā API atslēga tiek norobežoti tieši
pirms katra atbalstītā augšupstraumes mēģinājuma. Īpašnieka un paaudzes atkārtota izmantošana ar citu atslēgu neizdodas pat
tad, ja šī atslēga atļauj to pašu savienojumu. Neapstrādāti īpašnieku identifikatori netiek pastāvīgi glabāti, reģistrēti žurnālos, saglabāti
pieprasījuma momentuzņēmumā vai pārsūtīti augšupstraumei.

Īslaicīgas konkurences gadījumā tiek atgriezts HTTP `429` ar `Retry-After` un:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Šī atbilde nozīmē tikai to, ka parastā prasībām atbilstošā kopa nebija tukša un katru brīvo kandidātu
turēja cita aktīva noma. Neatbalstīti modeļi/pakalpojumu sniedzēji, politikas neatbilstība, atdzišanas periods, kvota,
veselības stāvoklis un citas parastas atbilstības kļūmes saglabā esošās OmniRoute atbildes.

### `x-omniroute-compression`

Katra pieprasījuma saspiešanas plāna pārrakstīšana. Augstākā prioritāte — tā pārspēj maršrutēšanas kombinācijas
pārrakstīšanu, aktīvo profilu, automātisko aktivizēšanu un paneļa noklusējuma iestatījumu. Vērtības:

| Vērtība       | Ietekme                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| `off`         | Šim pieprasījumam saspiešana netiek veikta.                                                                        |
| `default`     | No paneļa atvasinātais noklusējuma profils (aktīvais profils tiek ignorēts). Zudumradošie dzinēji paliek izslēgti. |
| `safe`        | Tikai dublikātu noņemšana un atstarpju sakļaušana.                                                                 |
| `allow-lossy` | Šim pieprasījumam tiek saglabāts operatora plāns, tostarp kopsavilkumi un stila pārrakstīšana.                     |
| `engine:<id>` | Viens dzinējs, ja tas ir iespējots, piemēram, `engine:rtk`. Šī dzinēja aktivizēšana konkrētajam pieprasījumam.     |
| `<combo>`     | Nosaukta kombinācija, kas vispirms tiek meklēta pēc nosaukuma (nereģistrjutīgi) un pēc tam pēc ID.                 |

Piezīmes:

- Nezināmas vērtības tiek ignorētas (pieprasījums nekad netiek noraidīts); noteikšana turpinās atbilstoši parastajai operatoru prioritātei.
- Ja vairākām kombinācijām ir vienāds nosaukums, determinētai atbilstībai norādiet kombinācijas **ID**.
- Kombināciju, kuras nosaukums ir `off` vai `default`, nevar atlasīt pēc nosaukuma (šie atslēgvārdi tiek interpretēti vispirms); norādiet šādu kombināciju pēc tās ID.
- Galvenais saspiešanas slēdzis ir stingrs ierobežojums: ja saspiešana ir globāli atspējota, šī galvene to nevar iespējot.

Piemērotais plāns tiek atgriezts atbildes galvenē:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

kur `<source>` ir viena no vērtībām `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` vai `off`.

## Iegulumi

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Pieejamie nodrošinātāji: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Kataloga identifikatori ir `provider/model` (piemērs: `jina-ai/jina-embeddings-v5-omni-small`). Tiek atpazīti arī reģistrā esošie Jina modeļu identifikatori bez prefiksa (piemēram, `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`). Jina iegulšanas/pārkārtošanas/klasificēšanas/segmentēšanas darbības vispirms izmanto informācijas paneļa `jina-ai` akreditācijas datus; `JINA_AI_API_KEY` tiek izmantota kā rezerves iespēja tikai tad, ja informācijas panelī nav atslēgas. `jina-reader` kartīte ir paredzēta tikai Reader / `r.jina.ai` (`POST /v1/web/fetch`) un nekad nenodrošina iegulšanu vai pārkārtošanu.

Reģistra modeļi, kuri norāda multimodālu atbalstu, pieņem arī līdz 32 no nodrošinātāja neatkarīgiem strukturētiem
vienumiem. Multivides vienumu tipi ir `text`, `image`, `audio`, `video` un `document`. To multivides `source`
ir vai nu `{"type":"url","url":"https://..."}`, vai
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
un saimes aizstājvārds `jina-ai/jina-embeddings-v5-omni` → omni-small) pieņem arī Jina vietējos
EmbeddingsV5Request dokumentus un **pārsūta tos nemainītus** uz `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Vietējās `{ image | audio | video | pdf }` vērtības var būt publisks HTTPS URL, `data:` URI vai neapstrādāti
base64 dati. OmniRoute nepārvērš šos objektus virknēs un neielādē vietējos attēlu URL — Jina pati izgūst
publisko multividi. Papildu Jina lauki (`task`, `normalized`, `truncate`, `embedding_type`) tiek
pārsūtīti. Tikai tekstam paredzētie Jina SKU joprojām noraida dokumentus, kas nav teksts.

Drošības un transporta ierobežojumi:

- Attālās multivides URL jābūt publiski pieejamiem, izmantojot HTTPS. Kanoniskie `{type,source:url}` vienumi tiek izgūti
  servera pusē (atkārtota novirzīšanas validācija, taimauts, izmēra ierobežojumi, publisks DNS, savienojuma piesaiste) un
  iegulti pirms nodrošinātāja izsaukuma. Jina vietējie `{image:"https://..."}` vienumi pēc tās pašas publiskā HTTPS pārbaudes
  tiek pārsūtīti nemainītā veidā; Jina izgūst URL.
- Iekļautās base64 multivides apjoms ir ierobežots līdz 8 MiB dekodētu datu katram vienumam un 16 MiB dekodētu datu visam pieprasījumam.

Pārveidošana nodrošinātājam (kanoniskie vienumi nekad netiek pārsūtīti nemainīti):

- Jina multimodālie modeļi: katrs augstākā līmeņa vienums kļūst par vienu objektu ar modalitātes atslēgu
  (`text` / `image` / `audio` / `video` / `pdf`), iekļautajai multividei izmantojot datu URI; viens vektors katram
  augstākā līmeņa vienumam.
- Gemini Embedding 2 saime: viens augstākā līmeņa masīvs kļūst par vienu vietējo
  `models/{model}:embedContent` pieprasījumu ar `content.parts` (`text` vai `inline_data`).
- llama.cpp (`llama-cpp/<model>`, jebkurš vietējā servera ielādētais modelis): kanoniskie `text` vienumi
  kļūst par vienkāršām virknēm, bet `image` / `audio` / `video` kļūst par vienu
  `{"content": [part]}` objektu katrs, izmantojot llama-server tērzēšanas satura daļas (`image_url`,
  `input_audio` ar formātu `wav` / `mp3` / `flac`, `input_video`) un iekļautus datus; viens vektors
  katram augstākā līmeņa vienumam. Serveris jāpalaiž ar `--embedding --mmproj …`; bez projektora tas
  pats noraida multividi. `document` netiek atbalstīts.
- Nezināmi/dinamiski modeļi bez skaidriem modalitāšu metadatiem noraida strukturētu ievadi ar HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Neatbalstītas modeļa/modalitātes kombinācijas atgriež HTTP 400, nevis pārveido vienumu. Ar ievadi nesaistītie
paplašinājuma lauki mantotajos virkņu/marķieru pieprasījumos joprojām tiek pārsūtīti nemainīti.

```bash
# Uzskaitīt visus iegulumu modeļus
GET /v1/embeddings
```

## Attēlu ģenerēšana

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Pieejamie nodrošinātāji ietver OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokāli), ComfyUI (lokāli).

`n` atgriež `n` attēlus masīvā `data[]`. Nodrošinātājiem, kuru augšupstraumes API vienā izsaukumā atgriež vienu attēlu
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), tiek veikti `n` atsevišķi augšupstraumes izsaukumi, vienlaikus izpildot ne vairāk kā 4. Fiksētai
`seed` vērtībai tiek pieskaitīts izsaukuma indekss (`seed`, `seed + 1`, …), tāpēc attēli atšķiras, bet ir
reproducējami. `n` maksimālā vērtība ir 10. Ja kāds izsaukums neizdodas, viss pieprasījums tiek uzskatīts par neveiksmīgu. Izvēršanas
formātu saraksts ir `SINGLE_IMAGE_FANOUT_FORMATS` failā
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux atkārtoti izmanto esošo API atslēgas savienojumu un pieņem prefiksus `zenmux/` vai `zm/`:

- `zenmux/openai/gpt-image-2` izmanto ZenMux OpenAI Images API. Opcijas ietver `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` un `response_format`.
- Citi izdevēji, piemēram, `zm/meta/muse-image-1.0`, izmanto ZenMux Vertex AI `:predict`
  galapunktu. `n` tiek kartēts uz `sampleCount`, `aspect_ratio` — uz `aspectRatio`, bet `image_size`
  (`1K`, `2K`, `4K`) — uz `sampleImageSize`. Pikseļos norādīts `size` nosaka tikai malu attiecību,
  nevis garantētus pikseļu izmērus. Atbalstītās malu attiecības, izšķirtspējas un skaits atšķiras atkarībā no modeļa.
- `zm/inclusionai/ming-image-0.1-design` pats izvēlas izmērus. Izlaidiet `size`,
  `aspect_ratio` un `image_size`; skaidri norādītas vērtības atgriež HTTP 400. PNG, JPEG un WebP
  var pieprasīt, izmantojot `output_format`.

Šī integrācija atbalsta attēlu ģenerēšanu no teksta, nevis atsauces attēlu rediģēšanu. Vertex
izvade tiek normalizēta uz `data[].b64_json`; `response_format: "url"` atgriež augšupstraumes
HTTPS URL vai base64 datu URL, ja ir pieejami tikai attēla baiti. Tukša vai filtrēta izvade
atgriež kļūdu, nevis tukšu veiksmīgu rezultātu. Piekļuve modeļiem ir atkarīga no ZenMux konta.
Skatiet [ZenMux Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) un
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Uzskaitīt visus attēlu modeļus
GET /v1/images/generations
```

## Dokumentu OCR

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` atlasa OCR nodrošinātāju, izmantojot prefiksu `provider/model`; modeļa ID bez prefiksa (piemēram,
`mistral-ocr-latest`) tiek piesaistīts tā reģistrētajam nodrošinātājam, bet, ja `model` nav norādīts, pēc noklusējuma tiek izmantots
Mistral (`mistral-ocr-latest`). Reģistrētie nodrošinātāji (`open-sse/config/ocrRegistry.ts`):

| Nodrošinātāja ID              | Modeļa ID            | `model` vērtība                                               | Piezīmes                                                                                                           |
| ----------------------------- | -------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (vai tikai `mistral-ocr-latest`) | Sinhrons — atbilde tiek atgriezta tieši no vienīgā augšupstraumes izsaukuma.                                       |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                   | Asinhrona augšupstraume (`analyze` + aptauja) — skatiet tālāk.                                                     |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                       | Sinhrons, izmantojot Vertex AI `openapi/chat/completions` partnera galapunktu — autentifikāciju/URL skatiet tālāk. |

Visi trīs nodrošinātāji atbild ar vienādas Mistral formas pamattekstu:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligence aptaujas plūsma

Azure Document Intelligence `analyze` API ir asinhrona: sākotnējais pieprasījums pamatteksta vietā atgriež
`Operation-Location` galveni, un rezultāts ir jāiegūst ar periodisku aptauju. Apstrādātājs
(`open-sse/handlers/ocr.ts`) aptaujā šo URL reizi sekundē līdz 30 mēģinājumiem, nekavējoties pārtraucot izpildi (neturpinot
aptauju), ja aptaujas atbilde nav `ok` vai statuss ir `"failed"`, un atgriež `504`, ja
darbība joprojām turpinās pēc mēģinājumu limita izsmelšanas. Galīgā Azure atbilde pirms atgriešanas
izsaucējam tiek normalizēta tajā pašā `pages`/`markdown` formā, ko izmanto Mistral,
tāpēc klienta kodam nav nepieciešams īpaši apstrādāt katru nodrošinātāju.

### Vertex AI DeepSeek OCR autentifikācija un galapunkta noteikšana

`vertex-deepseek-ocr` atkārtoti izmanto to pašu Vertex AI autentifikāciju, ko OmniRoute jau atbalsta
tērzēšanas/attēlu datplūsmai (`open-sse/executors/vertex.ts`): savienojuma API atslēga ir vai nu
Service Account JSON akreditācijas dati (kas, izmantojot JWT nesēja
plūsmu, tiek apmainīti pret īslaicīgu OAuth piekļuves pilnvaru), vai jau izsniegta OAuth piekļuves pilnvara, kas tiek izmantota bez izmaiņām. Augšupstraumes galapunkta URL ir Vertex
vispārīgais `openapi/chat/completions` partnera galapunkts, kas izveidots no savienojuma projekta un
reģiona — skaidri norādīts `providerSpecificData.project`/`providerSpecificData.region` vienmēr ir prioritārs;
pretējā gadījumā projekts tiek iegūts no Service Account JSON lauka `project_id`, bet reģiona
noklusējuma vērtība ir `us-central1`. Abas vērtības tiek noteiktas failā `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) un izmantotas failā
`src/app/api/v1/ocr/route.ts` pirms pārsūtīšanas uz `handleOcr`.

### Modeļu ID prefiksi (`?prefix=`)

Lielākā daļa modeļu tiek publicēti ar **nodrošinātāja prefiksu**. Izmantoto prefiksu nosaka
`MODELS_CATALOG_PREFIX_MODE` funkcijas karodziņš, un to var pārrakstīt **katram pieprasījumam atsevišķi** ar
vaicājuma parametru — tas ir noderīgi klientam, kas vēlas pārskatāmu sarakstu, nemainot servera mēroga
iestatījumu visiem pārējiem:

```bash
GET /v1/models?prefix=alias        # viens ID katram modelim — īsais aizstājvārda prefikss
GET /v1/models?prefix=dual         # abas formas (servera noklusējums)
GET /v1/models?prefix=canonical    # tikai pilnais nodrošinātāja ID prefikss
```

| Režīms      | Izvada                                                   | Piezīmes                                                                                                                                                                                                  |
| ----------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **un** `claude/claude-sonnet-4-6` | **Noklusējums.** Abi ID tiek maršrutēti uz vienu un to pašu modeli; tas saglabāts, lai klientu konfigurācijas, kurās ir stingri norādīta kāda no formām, turpinātu darboties. Aptuveni divkāršo katalogu. |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Viens ieraksts katram modelim. Nodrošinātāji bez atsevišķa aizstājvārda joprojām izvada savu ierakstu, tāpēc nekas netiek zaudēts.                                                                        |
| `canonical` | `claude/claude-sonnet-4-6`                               | Viens ieraksts katram modelim ar pilno nodrošinātāja ID prefiksu. Nodrošinātāji bez atsevišķa aizstājvārda (piem., `antigravity/…`, `agy/…`) arī šeit izvada savu vienīgo ID, tāpēc nekas netiek zaudēts. |

`dual` režīma spoguļierakstu var atpazīt arī bez vaicājuma parametra: tam ir `parent`
lauks, kas norāda uz primāro ID.

Klientiem, kas attēlo modeļa izvēlni, jāpieprasa `?prefix=alias` — tā dara
[OmniCopilot VS Code paplašinājums](../guides/VSCODE-COPILOT.md).

### Atklāšanas filtri (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` pieņem neobligātus atklāšanas filtrus. Ja neviens no tiem nav norādīts, atbilde
nemainās. Tie sašaurina katalogu, ko izsaucējs jau var redzēt (vispirms tiek piemērotas API atslēgas atļaujas),
un tie tiek izpildīti pirms OpenAI stila `limit` / `after` lapošanas:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # katrai norādītajai iespējai jābūt patiesai
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # kataloga `type`; rindas bez tā ir `chat`
GET /v1/models?q=sonnet&limit=10                           # reģistrnejutīga atbilstība pēc ID vai nosaukuma
```

| Parametrs     | Vērtības                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nenegatīvs vesels skaitlis, kas tiek salīdzināts ar `context_length`                                |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 rakstzīmes                                                                                    |

Nezināma vērtība vai `min_context`, kas nav nenegatīvs vesels skaitlis (piemēram, `1.5`),
atgriež HTTP `400`, un ziņojumā ir uzskaitītas derīgās vērtības. Implementācija:
`src/app/api/v1/models/catalogFilters.ts`.

### Modeļu atlases saraksts (`POST /v1/models/query`)

`POST /v1/models/query` atgriež īsu, deterministisku sarakstu no tā paša kataloga ar tādu pašu
autentifikāciju un katrai atslēgai noteikto redzamību kā `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Katrs lauks ir neobligāts. `capabilities` un `exclude` pieņem masīvu vai ar komatiem atdalītu virkni;
`max_output` tiek salīdzināts ar `max_output_tokens`. Rezultāti tiek kārtoti vispirms pēc `owned_by`, pēc tam pēc `id`.
`limit` noklusējuma vērtība ir `20`, un vērtības virs `100` tiek ierobežotas līdz `100`. Nederīgs JSON, nezināms
lauks vai nederīga vērtība atgriež HTTP `400`.

### Atsevišķi paslēpti tērzēšanas modeļi

Modelis, kas tā nodrošinātāja lapā atzīmēts kā **Paslēpts**, tiek izslēgts no kataloga, un tā tieša
pieprasīšana tiek noraidīta ar HTTP `404` / `model_not_found`. Pārbaudē tiek izmantots atrisinātais
nodrošinātājs un modelis, tostarp nodrošinātāju aizstājvārdi, saderīgo nodrošinātāju mezglu prefiksi un
savienojuma noklusējuma vērtības. Kombinācija izlaiž paslēptos mērķus un var izmantot redzamu alternatīvu; ja
nepaliek neviens izpildāms mērķis, tā atgriež to pašu kļūdas kodu. Paslēpšanas atcelšana stājas spēkā nākamajā
pieprasījumā. Tikai attēliem paredzēti redzamības pārrakstījumi nepaslēpj tērzēšanas modeli ar to pašu ID.

Šis individuālais modeļa iestatījums ir atsevišķs no
[modeļu pieejamības atļaušanas/aizliegšanas sarakstiem](../routing/MODEL_EXPOSURE_LIST.md), kas filtrē kataloga
publicētos ierakstus un automātiskās maršrutēšanas kandidātus, vienlaikus saglabājot tiešo nosūtīšanu. API atslēgu modeļu
atļaujas joprojām tiek piemērotas neatkarīgi. Noklusējuma kataloga prefiksu režīms joprojām ir `dual`.

### Modeļu varianti bez domāšanas

Claude modeļiem, kas atbalsta domāšanu, `/v1/models` publicē arī **bezdomāšanas** variantu, kura ID sākas ar `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Atlasot šo ID (piem., Claude Code konfigurācijā, kas vienmēr pievieno `thinking` bloku), tas tiek atgriezts uz īsto `<provider>/<model>` ar nomāktu spriešanu — `thinking:{type:"disabled"}` ceļā `/v1/messages` vai ar noņemtiem laukiem `reasoning`/`reasoning_effort` ceļā `/v1/chat/completions`. Variants tiek uzskaitīts tikai Claude saimes modeļiem, kas atbalsta domāšanu **un** ievēro `disabled` (tādēļ, piem., tiek izslēgti tikai adaptīvo režīmu atbalstoši modeļi, kas noraida `disabled`). Operatori var piespiedu kārtā iespējot vai atspējot šo variantu katram modelim atsevišķi, izmantojot `ModelSpec.noThinkingAlias`.

## ElevenLabs audio ģenerēšana

Konfigurējiet `elevenlabs` pakalpojumu sniedzēja savienojumu OmniRoute, izmantojot savu ElevenLabs API atslēgu.
Klienti autentificējas ar savu **OmniRoute** atslēgu (`Authorization: Bearer $OMNIROUTE_API_KEY`);
vārteja nodrošina saglabāto pakalpojumu sniedzēja atslēgu kā `xi-api-key`. Nekad nesūtiet ElevenLabs atslēgu
kā vārtejas nesēja pilnvarojuma marķieri.

| Metode | Ceļš                        | Atbilde                                                  | API atslēgas galapunkta kategorija |
| ------ | --------------------------- | -------------------------------------------------------- | ---------------------------------- |
| POST   | `/v1/sound-generation`      | Sākotnējā formāta audio baiti                            | `elevenlabs`                       |
| POST   | `/v1/music`                 | Sākotnējā formāta audio baiti                            | `music`                            |
| POST   | `/v1/music/stream`          | Straumēti audio baiti                                    | `music`                            |
| POST   | `/v1/music/detailed`        | Sākotnējā formāta vairākdaļu audio un kompozīcijas plāns | `music`                            |
| POST   | `/v1/music/detailed/stream` | Sākotnējā formāta SSE metadati un audio fragmenti        | `music`                            |
| POST   | `/v1/music/plan`            | JSON kompozīcijas plāns                                  | `music`                            |

Šie galapunkti papildina esošos `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` un `/v1/speech-to-text` maršrutus. Sākotnējā formāta JSON lauki
un vaicājuma parametri, piemēram, `output_format` un `enable_logging`, tiek saglabāti.
`/v1/music/detailed` atbildēs tiek saglabātas to vairākdaļu robežas; apstrādājiet tās kā vairākdaļu datus.
`/v1/music/detailed/stream` atgriež `text/event-stream` ar kompozīcijas metadatiem un
base64 audio fragmentiem SSE notikumos. Visi seši maršruti atbalsta CORS priekšpieprasījumus.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Īss skaņas efekts. Ilgums: no 0,5 līdz 30 sekundēm.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Mūzikas ilgums tiek norādīts milisekundēs: no 3000 līdz 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Izmantojiet `/v1/music/stream` ar to pašu JSON pamatdaļu pakāpeniskai audio piegādei. Kompozīcijas
pieprasījums pieņem tieši vienu no `prompt` vai `composition_plan`; `/v1/music/plan` pieprasa `prompt`
un pēc izvēles pieņem `source_composition_plan`. Sākotnējās shēmas saglabā papildu
pakalpojumu sniedzēja laukus, lai kompozīcijas plāna versijas un precīzās pielāgošanas opcijas sasniegtu ElevenLabs.

Vienotais `/v1/music/generations` galapunkts pieņem arī `elevenlabs/music_v1`,
`elevenlabs/music_v2` un `elevenlabs/music_v2_5`. Ja ir aktīvs ElevenLabs savienojums,
šie modeļi ir pieejami mūzikas katalogā. Šis galapunkts atgriež
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Tā `duration` lauks tiek norādīts
sekundēs un tiek kartēts uz `music_length_ms`; skaidri norādītam `music_length_ms` ir prioritāte.
`instrumental` tiek kartēts uz `force_instrumental`, un sākotnējam laukam ir prioritāte.
Straumēšanai izmantojiet sākotnējā formāta straumēšanas galapunktus, bet pieprasījumiem, kuru pamatā ir tikai kompozīcijas plāns,
izmantojiet sākotnējā formāta kompozīcijas galapunktu.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Galapunkta, modeļa, budžeta un savienojuma ierobežojumi tiek piemēroti pirms augšupstraumes izsaukuma. Sākotnējā formāta
maršruti atgriež augšupstraumes statusa kodus un kļūdu pamatdaļas bez izmaiņām, tostarp `402` plāna
ierobežojuma gadījumā un `429` kvotas ierobežojuma gadījumā. Galvenes `character-cost`, `song-id`, `request-id` un `retry-after`
tiek saglabātas, ja tās ir pieejamas. Bezmaksas kredītu atlikums negarantē piekļuvi visiem
mūzikas modeļiem, izvades formātiem vai API funkcijām: ElevenLabs nosaka piekļuves tiesības katram pieprasījumam.
Vienotais galapunkts saglabā kļūdu statusa kodus OmniRoute normalizētajā kļūdu aploksnē.

Augšupstraumes līgumi: [skaņas efekti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[mūzikas kompozīcija](https://elevenlabs.io/docs/api-reference/music/compose) un
[straumētas mūzikas detalizētā informācija](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

```bash
# Pārkārtošana (mākoņa reģistra nodrošinātājs vai ar OpenAI saderīgs nodrošinātāja mezgls formātā "<prefix>/<model>")

```

> **Pārrindošanas nodrošinātāja mezgli:** `POST /v1/rerank` maršrutē pieprasījumus arī uz ar OpenAI saderīgiem nodrošinātāja mezgliem
> (oMLX, vLLM, Infinity, TEI aiz vārtejas, …), kas adresēti kā `<node-prefix>/<model>`. Atgriezeniskās cilpas
> mezgli (`localhost`, `127.0.0.1`, `172.16.0.0/12`) vienmēr ir atļauti, tāpat kā resursdatoru nosaukumi, kurus
> operators norāda mainīgajā `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (piemēram, Docker/Compose pakalpojuma nosaukums,
> tāds kā `http://reranker:8080/v1`; tie tiek izsaukti tieši, nekad neizmantojot `HTTP(S)_PROXY` vai
> savienojumam piesaistīto starpniekserveri). Mezglus jebkurā citā
> resursdatorā — lokālā tīkla ierīcē vai Tailscale vienādranga mezglā — drīkst izmantot tikai tad, ja operators iespējo
> funkcijas karogu `RERANK_REMOTE_PROVIDER_NODES` **un** mezgla bāzes URL atbilst nodrošinātāja
> izejošo URL politikai (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Atmiņas dziņa pārrindošanas darbība izsauc šo maršrutu,
> izmantojot atgriezenisko cilpu, tādēļ tas pats noteikums regulē `rerankProviderModel` atmiņas iestatījumos.
>
> **Lokālā servera formāti:** mezgls tiek izsaukts adresē `<base>/v1/rerank` un 404 atbildes gadījumā — adresē `<base>/rerank`
> (Infinity, TEI). Augšupstraumes ķermenī ir gan Cohere/OpenAI rakstība (`documents`,
> `return_documents`), gan TEI rakstība (`texts`, `return_text`), un augšupstraumes atbilde tiek
> normalizēta Cohere aploksnē: TEI vienkāršais `[{index, score, text}]`, plāno vārteju
> `{results: [{index, score}]}` un Voyage stila `{data: [...]}` tiek atgriezti klientam kā
> `{results: [{index, relevance_score, document?}]}`, sakārtoti pēc vērtējuma un ierobežoti līdz `top_n`.

> **Nodrošinātāja mezglu atklāšana:** ar OpenAI saderīgā nodrošinātāja mezgla modeļi tiek parādīti `GET /v1/models`
> zem mezgla prefiksa. Rindas bez galapunktu metadatiem (tipiski lokāliem `/v1/models` sarakstiem)
> manto mezgla `apiType`, tādēļ `embeddings` mezgla modeļiem tiek norādīts `type: "embedding"`, bet
> `rerank` mezgla modeļiem — `type: "rerank"`, nevis pēc noklusējuma tērzēšanas tips; sinhronizētā vai manuāli pievienotā rindā skaidri norādītam
> `supportedEndpoints` joprojām ir prioritāte.

## Failu API

Ar OpenAI saderīgs failu galapunkts pakešievadei/izvadei un failu augšupielādei ar norādītu nolūku.

| Metode | Ceļš                     | Apraksts                                                                                                              |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| POST   | `/v1/files`              | Augšupielādēt failu (multipart: `file`, `purpose`, `expires_after[anchor]`, `expires_after[seconds]`) — maks. 512 MiB |
| GET    | `/v1/files`              | Uzskaitīt autentificētās API atslēgas failus                                                                          |
| GET    | `/v1/files/[id]`         | Iegūt faila metadatus                                                                                                 |
| DELETE | `/v1/files/[id]`         | Dzēst failu                                                                                                           |
| GET    | `/v1/files/[id]/content` | Straumēt atpakaļ neapstrādāto faila saturu                                                                            |

**Autentifikācija:** API nesēja atslēga — failu tvērums katrai API atslēgai tiek noteikts, izmantojot `getApiKeyRequestScope`. Atslēga
var skatīt, lejupielādēt un dzēst tikai savus failus; informācijas paneļa sesija bez atslēgas var lasīt
visas instances failus; fails bez īpašnieka (anonīma vai informācijas paneļa sesijas augšupielāde) nav pieejams nevienam

### Exa un Tavily `provider_options`

Exa un Tavily nolasa nodrošinātājam specifiskus laukus no nosaukumvietas objekta:
`provider_options.exa` (vai `provider_options["exa-search"]`) un `provider_options.tavily`
(vai `provider_options["tavily-search"]`). Tālāk tiek nodotas tikai tālāk norādītās atslēgas. Katra no tām tiek
pārbaudīta pret savu Zod shēmu failā `open-sse/handlers/search/providerOptionsPassthrough.ts`,
un atslēga ar nepareizu tipu tiek atmesta. Visas pārējās atslēgas tiek ignorētas, tostarp autentifikācijas dati, bāzes URL,
`stream` un `outputSchema`. Plakanās atslēgas, ko izmanto citi nodrošinātāji (`cx`, `depth`, ...), darbojas
tāpat kā iepriekš.

| Nodrošinātājs | Augšējā līmeņa lauki                                                                                                                                                                                                                                                                                                                                                      | Ligzdotie lauki                                                                                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa           | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (plakanas primitīvās vērtības), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                 | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` tiek sapludināts ar noklusējuma vērtību `{ text: true, highlights: true }` |
| Tavily        | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                                 |

Vispārīgajiem laukiem vienmēr ir prioritāte: `query`, `max_results`, `filters` (domēni), `country` un no
`search_type` atvasinātais topic. Exa gadījumā `search_type: "news"` saglabā `category: "news"`.
Tavily pieņem arī `search_type: "finance"` (`topic: "finance"`).

Vispārīgais `time_range` tagad sasniedz abus nodrošinātājus: Exa saņem `startPublishedDate` (ISO
laikspiedolu), bet Tavily saņem `start_date` (`YYYY-MM-DD`). Laukā `provider_options`
skaidri norādītam datumam ir prioritāte pār kartēto datumu.

Exa rezultāti saglabā `id`, `highlight_scores`, `summary`, `subpages`, `entities` un `extras` laukā
`provider_raw`. Tavily rezultāti saglabā `images` un `favicon`.

Izmaksu uzskaitei joprojām tiek izmantots plakanais reģistrs `costPerQuery`. Tavily par
`search_depth: "advanced"` iekasē vairāk kredītu par izsaukumu, un šī atšķirība nav atspoguļota
`usage.search_cost_usd`.

## Tīmekļa ielādes API

Izgūst saturu no URL, izmantojot konfigurētu tīmekļa ielādes nodrošinātāju (Firecrawl, Jina

Parallel Extract (`parallel-search`, tā pati API atslēga, kas tiek izmantota Parallel Search) atgriež tikai Markdown
— jebkurš cits `format` izraisa `400` — un ierobežo saturu līdz 100 000 rakstzīmēm. Ja
pašu mērķa lapu nevar izgūt, augšupējais pakalpojums par to ziņo HTTP 200 atbildē;
OmniRoute to atgriež kā `422` ar fiksētu ziņojumu.

| Metode | Ceļš            | Apraksts                                                                |
| ------ | --------------- | ----------------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Ielādē/iegūst URL saturu — ķermenis tiek validēts ar `v1WebFetchSchema` |

**Kvotu ievērojoša atkāpšanās (#8297):** ja nav norādīts konkrēts `provider`, kopa
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) tiek
izstaigāta fiksētā
prioritāšu secībā (vispirms aizpildot pirmo) — ātruma ierobežojumu sasniedzis, bet konfigurēts nodrošinātājs tiek izlaists,
nevis pieprasījums tiek nekavējoties pārtraukts, un atkārtojama/kvotas izraisīta augšupējā pakalpojuma kļūme
(HTTP 429 vienmēr; 402/403 Firecrawl/Tavily/TinyFish kvotu tipa bezmaksas līmeņiem —
ne Jina Reader gadījumā un nekad vienkāršam 400 kļūdainam pieprasījumam) pieprasījuma izpildes laikā pāriet pie
nākamā vēl neizmēģinātā nodrošinātāja, kuram ir akreditācijas dati. Kad visi kopas nodrošinātāji ir
izsmelti, galapunkts iepriekšējā vispārīgā `400` vietā atgriež vienu `429` (ar `Retry-After`
galveni). Ja tiek pieprasīts konkrēts `provider`, **netiek** veikta nemanāma atkāpšanās — ātruma ierobežojumu sasniedzis vai kļūmi izraisījis konkrētais
nodrošinātājs atgriež savu kļūdu (`429`, ja sasniegts ātruma ierobežojums, citādi augšupējā pakalpojuma
statusu).

### Responses API, izmantojot WebSocket (tikai codex)


aizmugursistēmai). Tas klausās tajā pašā portā, kurā darbojas API/informācijas panelis, izmantojot ceļus `/v1/responses`,

Kvotas koplietošanas maršrutēšanai izmantojiet `model: "qtSd/<group>/codex/<model>"`. Realizēts
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentifikācija:** Bearer API atslēga rokasspiediena laikā. Komplektā iekļautajam HTTP serverim (`server-ws.mjs`)

#### Modeļa ID: izmantojiet tikai ChatGPT ID (bez `codex/` prefiksa)

## Pašapkalpošanās lietojuma dati (`/api/usage/om-usage`)

Jebkura API atslēga var nolasīt **savu** lietojumu un kvotas — pārvaldības autentifikācija nav nepieciešama. Šo galapunktu
klients (CLI, OmniCopilot panelis) izmanto, lai parādītu atslēgas turētājam tā tēriņus.

```bash
# Teksta formāts (vēsturiskais līgums — vienkāršs teksts terminālim)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Strukturētais formāts — tas, ko izmanto lietotāja saskarne
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Atslēgai jābūt iespējotam iestatījumam **`allowUsageCommand`** (pēc noklusējuma tas ir izslēgts — informācijas paneļa API atslēgu
pārvaldnieks to pārslēdz katrai atslēgai atsevišķi). Bez tā galapunkts atbild ar `403`.

`?format=json` atgriež atšķiramu struktūru, lai izsaucējs nekad nemēģinātu nolasīt datu lauku no
atteikuma. Veiksmīgas atbildes gadījumā:

```jsonc
{
  "allowed": true,
  // pieejams tikai tad, ja atslēgai ir iespējoti atsevišķās atslēgas lietojuma ierobežojumi (dienas/nedēļas USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // atlasītā pakalpojumu sniedzēja kvotas momentuzņēmums vai null, ja vēl nekas nav saglabāts kešatmiņā:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // katra savienojuma momentuzņēmums, lai lietotāja saskarnē varētu blakus attēlot vairākus pakalpojumu sniedzējus:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Atteikuma gadījumā (`401` nederīga atslēga / `403` nav atļauts) tas pats maršruts atgriež
`{ "allowed": false, "error": { "message": "…" } }` — esošs, bet tukšs `personal`/`provider`
(atslēga ir atļauta, taču vēl nekas nav noskaidrots) ir atšķirīgs stāvoklis no atteikuma, un tos atšķir tikai JSON
formāts.

**Autentifikācija:** izsaucēja paša Bearer API atslēga, kas pārbaudīta ar `isValidApiKey` — šī _nav_
pārvaldības saskarne (`/api/keys/…`), kuru joprojām aizsargā `requireManagementAuth`.

### Neapstrādātie un atslēgšanas sliekšņa koriģētie kvotu procenti

Izmantojot `/api/usage/om-usage`, izsaucējiem jāņem vērā atšķirība starp procentiem, kas tiek parādīti
**vienkārša teksta izvadē**, un strukturēto **JSON izvadi**:

| Aspekts                  | Vienkārša teksta formāts (`/api/usage/om-usage` / `@@om-usage`)                                         | JSON formāts (`?format=json`)                                                              |
| :----------------------- | :------------------------------------------------------------------------------------------------------ | :----------------------------------------------------------------------------------------- |
| **Izvades lauks**        | `NN% left` (piemēram, `20% left`)                                                                       | `provider.quotas` / `providers[].quotas`                                                   |
| **Mērījums**             | **Atslēgšanas sliekšņa koriģētais izmantojamais apjoms**: atlikusī kapacitāte virs atslēgšanas sliekšņa | **Neapstrādāta augšupējā kvota**: nekoriģēts pakalpojumu sniedzēja mērījums                |
| **Sliekšņa mērogošana**  | Mērogots, izmantojot `effectiveRemainingPercent()`, lai aizsargātā rezerve tiktu attēlota kā `0% left`  | Nav (neapstrādātas momentuzņēmuma vērtības, kā tās ziņojis pakalpojumu sniedzējs)          |
| **Sliekšņa dati**        | Iekļauti attēlotajā procentuālajā vērtībā                                                               | Saglabāti katra savienojuma `quotaWindowThresholds` (vai servera noklusējuma iestatījumos) |
| **Galvenais patērētājs** | Interaktīvi CLI, termināļa uzvednes, operatori                                                          | Programmiskas integrācijas, informācijas paneļi, analītika, norēķinu uzskaites rīki        |

#### Atslēgšanas sliekšņa korekcijas formula

OmniRoute atbalsta proaktīvus kvotu atslēgšanas sliekšņus, lai novērstu augšupējo resursu izsmelšanu (konfigurēti, izmantojot savienojuma
`quotaWindowThresholds`, pakalpojumu sniedzēja noklusējuma iestatījumus vai globālos noturības iestatījumus). Ja kvotas logam ir aktīvs atslēgšanas slieksnis
(piemēram, `cutoff = 25%`), teksta atveidotājs aprēķina atlikušo apjomu šādi:

- Ja `remaining <= cutoff`: atgriež `0%`.
- Ja `remaining > cutoff`: atgriež `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formatētajā teksta izvadē šī vērtība tiek noapaļota līdz tuvākajam veselajam skaitlim (`Math.round(...)`).

#### Ilustratīvs piemērs

Apskatīsim pakalpojumu sniedzēja logu ar **60% neapstrādātu lietojumu** (tātad **40% neapstrādātas atlikušās kvotas**) un konfigurētu
**25% atlikušās kvotas atslēgšanas slieksni**:

| Attēlojums                             | Aprēķins                                           | Atlikums |           Netieši izmantots           |
| :------------------------------------- | :------------------------------------------------- | :------: | :-----------------------------------: |
| **Neapstrādāts JSON (`?format=json`)** | Augšupējais momentuzņēmums (`quotas[window]`)      | **40%**  |                **60%**                |
| **Teksta formāts (`NN% left`)**        | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%**  | **80%** (aprēķinot `100 - remaining`) |

- **Kāpēc tekstā tiek rādīts 20% atlikums:** No kontā fiziski atlikušajiem 40% kvotas 25% rezervē
  atslēgšanas politika. Izsaucējam ir atlikuši tikai 15% no 75% izmantojamās rezerves, pirms maršrutētājs pārtrauc
  maršrutēšanu uz šo savienojumu. Mērogošana nodrošina, ka savienojums signalizē par resursu izsmelšanu (`0% left`) tieši tad, kad
  maršrutēšana tiks pārtraukta.
- **Kāpēc JSON saglabā neapstrādātās vērtības:** JSON lietderīgā slodze atgriež precīzu pakalpojumu sniedzēja momentuzņēmumu (`UsageSnapshot`),
  lai ārējiem rīkiem būtu piekļuve faktiskajam augšupējo resursu lietojumam un savienojuma līmeņa
  `quotaWindowThresholds` bez zudumus izraisošas servera puses mērogošanas.

#### Norādījumi patērētāju migrācijai

Ja ārējā integrācija (piemēram, redaktora spraudnis vai aģenta paplašinājums) iepriekš ieguva datus no teksta
galapunkta (`NN% left`) un aprēķināja izmantoto procentuālo daļu kā `100 - NN`, pāreja uz `?format=json` nozīmē:

- Neapstrādātu JSON vērtību nolasīšana atspoguļos **faktisko augšupstraumes patēriņu** (iepriekš minētajā piemērā izmantoti 60%).
- Ja integrācija vēlas saglabāt teksta galapunkta izmantojamā atlikuma semantiku, tā var klienta pusē aprēķināt
  faktisko atlikumu, izmantojot `quotaWindowThresholds` savienojuma līmeņa pārrakstīšanai.

Sinhronizētiem/importētiem modeļiem `PUT /api/provider-models` pieņem `provider`, `modelId` un
`maxOutputTokenOverride`: pozitīvs vesels skaitlis iestata manuālu izvades tokenu ierobežojumu, bet `null`
to notīra, lai atjaunotu noklusējuma vērtību. `GET /api/provider-models?provider=<provider>` atgriež šīs
vērtības laukā `modelOutputOverrides`, tostarp modeļiem bez pielāgotā modeļa rindas. Pārrakstītā vērtība
izmanto izpildlaika `max_output_tokens` iespēju un saglabājas pēc modeļa atkārtotas sinhronizācijas. Ar OpenAI saderīgā
nodrošinātāja lapa piedāvā tādas pašas rediģēšanas/notīrīšanas vadīklas un atzīmē modeļus ar tieši norādītu redzes atbalstu.

Pielāgotie Chat Completions mezgli pielāgo tiešas spriešanas atteikšanās norādes augšupstraumes aizmugursistēmai. Veiksmīgs
savienojuma tests automātiski atlasa tērzēšanas veidņu vadīklas katram precīzajam modeļa ID,
kura `/models` ieraksts apliecina atpazītu `owned_by` vērtību: `vllm`, `sglang` vai `llamacpp`.
Caurspīdīgi ar OpenAI saderīgi ietvari var saglabāt sākotnējo modeļa ierakstu ligzdotā
`openai` objektā; noteikšana izseko ne vairāk kā trim šādiem apvalkiem. Modeļi ar trūkstošu, nezināmu vai
pretrunīgu īpašnieka informāciju saglabā parasto OpenAI darbību. Noteikšana atkārtoti izmanto esošo kataloga pieprasījumu,
neģenerē pabeigšanas tokenus un tiek anulēta, kad mainās savienojuma galapunkts.

Lai fiksētu darbību aizmugursistēmai, kas neatklāj šos metadatus, izmantojiet esošo daļējas
nodrošinātāja atjaunināšanas API:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Nosūtiet šo ķermeni ar `PUT /api/providers/<connection-id>`. Šajā savienojumā tieši norādīta
spriešanas intensitāte `none` tiek nosūtīta kā `chat_template_kwargs.thinking=false` un
`chat_template_kwargs.enable_thinking=false`. Tieši norādītās vietējās veidnes vērtības saglabā prioritāti,
ja vien servera puses spriešanas kārtula neuzspiež noteiktu intensitāti. Iestatījums ir spēkā tikai tad, kad pielāgots
ar OpenAI saderīgs savienojums nosūta Chat Completions ķermeni; Responses pieprasījumi un parastie
nodrošinātāji saglabā savu vietējo pieprasījuma struktūru. Iestatiet `reasoningControl` uz `openai`, lai piespiestu parasto OpenAI
`reasoning_effort` pārsūtīšanu, vai izlaidiet to/iestatiet uz `null`, lai izmantotu automātisko noteikšanu.

Claude Code automātiskā režīma klasifikatora pieprasījumiem vietējā domāšana pēc noklusējuma ir atspējota, ja tie nesatur
tiešas spriešanas vadīklas. Noteikšana izmanto klasifikatora sistēmas marķieri Claude formāta
pieprasījumos, nevis modeļu nosaukumus vai pabeigšanas ierobežojumus. Tiešas ķermeņa vadīklas, atbalstītās intensitātes/domāšanas
galvenes, maršrutēšanas kārtulas un atrisinātā modeļa intensitāte saglabā savu pašreizējo prioritāti. Abi klasifikatora
posmi saglabā savas uzvednes, pabeigšanas ierobežojumus, apturēšanas secības un reālos augšupstraumes atļauju
spriedumus; otrais posms joprojām var ģenerēt pieprasīto redzamo spriešanu kā parastu tekstu.

### Versija un laidiena kanāls

```bash
GET /api/system/version
```

Tikai atgriezeniskās cilpas saskarnē pieejams pārvaldības maršruts (administratora autentifikācija). Atgriež darbojošos versiju, jaunāko
publicēto versiju un automātiskās atjaunināšanas statusu. `releaseChannel` un `channels` ir papildinoši
lauki (3.8.54 laidiena virkne); `channel` saglabā savu nozīmi — izvietošanas režīms, ko izmanto vadības paneļa atjauninātājs
(`npm`, `source` vai `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — darbojošā būvējuma npm kanāls: `nightly` versijām ar `-nightly.*`,
  `next` citām pirmsizlaides versijām (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` stabilai versijai ar
  vecāku galveno versijas numuru nekā `channels.latest`, citādi `latest`. Tie paši noteikumi, kas izmantoti
  `scripts/release/dist-tag.mjs`, kurš publicēšanas laikā izvēlas npm dist-tag.
- `channels` — katra dist-tag jaunākā publicētā versija no `npm view omniroute dist-tags` (ar reģistra
  HTTP rezerves variantu), kas kešota ar tādu pašu 10 minūšu TTL kā `latest`. `latest` vienmēr ir pieejams
  (rezerves variantā izmanto lauku `latest`, pēc tam `"unavailable"`); `next`, `nightly` un `lts` parādās
  tikai tad, ja attiecīgais dist-tag pastāv. Pieprasījums ar `Cache-Control: no-cache` atsvaidzina abus vaicājumus.

Kanālu modelis (`latest` = v3 līdz 4.0 vispārējai pieejamībai, `next` = rc, `nightly` = `develop` būvējumi,
`lts` = v3 labojumversijas pēc 4.0 vispārējās pieejamības) ir aprakstīts `docs/ops/RELEASE_STRATEGY.md`.

## Tokenizēti VS Code aizstājvārdi bez galvenēm

Izmantojiet šos aizstājvārdus, ja integrācija nevar ievietot `Authorization` galveni un API atslēga ir jāiekļauj bāzes URL.

```bash
# OpenAI stila kataloga aizstājvārds
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# OpenAI stila tērzēšanas aizstājvārdi
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Ollama stila aizstājvārdi
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

Piemērs:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

Piezīmes:

- Tokenizētie aizstājvārdi atkārtoti izmanto tos pašus apstrādātājus, ko `/v1/*` un `/api/tags`; atbilžu struktūras paliek identiskas.
- Dodiet priekšroku `Authorization: Bearer ...`, ja klients atbalsta pielāgotas galvenes.
- URL iekļautie tokeni var parādīties reversā starpniekservera žurnālos, pārlūkprogrammas vēsturē un telemetrijā ārpus OmniRoute. Uzskatiet tos par saderības iespēju, nevis noklusējuma autentifikācijas režīmu.

## Tokenu ierobežojumi

Katras API atslēgas **tokenu** budžeti (atšķirīgi no iepriekš minētā uz USD balstītā budžeta). Tie tiek piemēroti tieši pieprasījuma apstrādes ceļā: kad atslēgas lietojums pašreizējā periodā sasniedz ierobežojumu, pieprasījumi tiek noraidīti ar `429 Too Many Requests`. Ierobežojumus var attiecināt uz konkrētu `model`, `provider` vai piemērot `global` visai atslēgai; ja pieprasījumam atbilst vairāki ierobežojumi, tiek izmantots visstingrākais.

```bash
# Uzskaitīt atslēgas tokenu ierobežojumus (ietver pašreizējā perioda lietojumu)
GET /api/usage/token-limits?apiKeyId=key-123

# Izveidot vai atjaunināt tokenu ierobežojumu
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Dzēst tokenu ierobežojumu pēc identifikatora
DELETE /api/usage/token-limits?id=tl-abc
```

> **Shēmas piezīmes** (`setTokenLimitSchema`): `apiKeyId` un `scopeType` (`model` | `provider` | `global`) ir obligāti. `scopeValue` ir obligāts, izņemot gadījumus, kad `scopeType` ir `global` (piemēram, modeļa identifikators tvērumam `model` vai nodrošinātāja identifikators tvērumam `provider`). `tokenLimit` jābūt pozitīvam veselam skaitlim (virkne tiek pārveidota). Neobligāti: `id` (izlaidiet, lai izveidotu; norādiet, lai atjauninātu), `resetInterval` (`daily` | `weekly` | `monthly`, noklusējums ir `monthly`), `resetTime` (`HH:MM`), `enabled` (noklusējums ir `true`). `GET` atbildēs katrs ierobežojums tiek papildināts ar `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` un `nextResetAt`. Šis ir pārvaldības klases galapunkts (autentifikācija tiek centralizēti piemērota autorizācijas konveijerā).

## Pieprasījumu apstrāde

1. Klients nosūta pieprasījumu uz `/v1/*`
2. Maršruta apstrādātājs izsauc `handleChat`, `handleEmbedding`, `handleAudioTranscription` vai `handleImageGeneration`
3. Tiek noteikts modelis (tiešs nodrošinātājs/modelis vai aizstājvārds/kombinācija)
4. Akreditācijas dati tiek atlasīti no lokālās datubāzes, filtrējot pēc konta pieejamības
5. Tērzēšanai: `handleChatCore` pārbauda semantisko/paraksta kešatmiņu un nosaka kombinācijas saspiešanas iestatījumus
6. Ja iespējota proaktīvā saspiešana, tā tiek veikta pirms pārveidošanas nodrošinātāja formātā (`lite`, Caveman, RTK vai to kombinācija)
7. Nodrošinātāja izpildītājs nosūta pieprasījumu augšupējam pakalpojumam
8. Atbilde tiek pārveidota atpakaļ klienta formātā (tērzēšanai) vai atgriezta nemainīta (iegultnēm/attēliem/audio)
9. Tiek reģistrēts lietojums, saspiešanas analītika un pieprasījumu žurnāli
10. Kļūdu gadījumā saskaņā ar kombinācijas noteikumiem tiek izmantots rezerves variants

Pilna arhitektūras atsauce: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Noturība (paplašināti)

OmniRoute nodrošina trīs neatkarīgus pagaidu kļūmju apstrādes mehānismus; tālāk norādītie pārvaldības galapunkti ļauj operatoriem nolasīt un mainīt to iestatījumus:

| Tvērums                                 | Stāvokļa glabāšana                                    | Nolasīšana                                | Atiestatīšana / notīrīšana                                                  |
| --------------------------------------- | ----------------------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------- |
| Pakalpojumu sniedzēja ķēdes pārtraucējs | `domain_circuit_breakers` + atmiņā                    | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                                |
| Savienojuma nogaidīšanas periods        | `rateLimitedUntil` pakalpojumu sniedzēju savienojumos | `/api/rate-limits`, `/api/providers/[id]` | (atkārtoti iespējo atlikti; notīriet, izmantojot pakalpojumu sniedzēja PUT) |
| Modeļa bloķējums                        | Atmiņā esošs modeļu pieejamības reģistrs              | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                    |

`PATCH /api/resilience` pieņem pakalpojumu sniedzēja ķēdes pārtraucēja pārrakstīšanas iestatījumus laukos `providerBreaker.oauth` un `providerBreaker.apikey`. Katrs profils atbalsta `degradationThreshold`, `failureThreshold` un `resetTimeoutMs`; tie paši lauki ir pieejami sadaļā Informācijas panelis → Iestatījumi → Noturība.

```bash
# Notīrīt viena modeļa bloķējumu
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Notīrīt visus bloķējumus
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Pilnu konceptuālo aprakstu un ķēdes pārtraucēja noklusējuma iestatījumus skatiet [`CLAUDE.md`](../../CLAUDE.md) → "Noturības izpildlaika stāvoklis" un [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Ātruma ierobežojumu rinda un automātiskās iespējošanas drošības mehānisms

- **Atbalstītais rakstīšanas ceļš**: `POST /api/rate-limits` ar pamattekstu `{"connectionId": "<id>", "enabled": true|false}` ir atbalstītais pārvaldības galapunkts, ar kuru savienojumam ieslēgt vai izslēgt ātruma ierobežojumu aizsardzību. `PUT /api/providers/[id]` apzināti nemaina un nepārslēdz `rateLimitProtection` (#11278).
- **`enabled: false` semantika**: iestatot `enabled: false`, savienojumam tiek noņemta tieši norādītā aizsardzība, taču aktīvs API atslēgas savienojums **netiek** izslēgts no globālā automātiskās iespējošanas drošības mehānisma (`autoEnableApiKeyProviders = true`). Funkcijā `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) vērtības `false` un `undefined` ir līdzvērtīgas; aktīvie API atslēgu savienojumi bez tieši norādītas aizsardzības joprojām tiek aizsargāti ar automātiskās iespējošanas drošības mehānismu.
- **Globāla atspējošana**: lai izmantotu API atslēgu savienojumus bez ātruma ierobežojumu rindām, globāli atspējojiet drošības mehānismu, izmantojot `RATE_LIMIT_AUTO_ENABLE=false` (vides mainīgais) vai `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Iestatījumi → Noturība / `PATCH /api/resilience`).

## A2A serveris

OmniRoute nodrošina A2A (aģents–aģents) JSON-RPC 2.0 galapunktu, kā arī REST apvalku pārbaudei un informācijas paneļa lietošanai.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # neobligāts, ja vien nav iestatīts OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Atbalstītās metodes (visas ir atkarīgas no `settings.a2aEnabled`):

| Metode           | Apraksts                                                        |
| ---------------- | --------------------------------------------------------------- |
| `message/send`   | Sinhrona prasmes izpilde; atgriež `{task, artifacts, metadata}` |
| `message/stream` | Tās pašas prasmju kopas straumēta SSE izpilde                   |
| `tasks/get`      | Iegūst uzdevumu pēc `taskId`                                    |
| `tasks/cancel`   | Atceļ uzdevumu pēc `taskId`                                     |

Iebūvētās prasmes: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Aģenta karte

```bash
GET /.well-known/agent.json
```

Atgriež publisko A2A aģenta karti (nosaukumu, aprakstu, iespējas, prasmju katalogu, autentifikācijas shēmu) — publiski kešotu 1 stundu. Autentifikācija nav nepieciešama.

### REST palīgmetodes

| Metode | Ceļš                         | Apraksts                                                                                                               |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | A2A iespējošanas statuss, uzdevumu statistika un kešotās aģenta kartes kopsavilkums                                    |
| GET    | `/api/a2a/tasks`             | Uzdevumu saraksts — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nav ieviesta kā REST palīgmetode — izveidojiet, izmantojot JSON-RPC `message/send`)                                   |
| GET    | `/api/a2a/tasks/[id]`        | Iegūst vienu uzdevumu                                                                                                  |
| POST   | `/api/a2a/tasks/[id]/cancel` | Atceļ uzdevumu                                                                                                         |

**Autentifikācija:** REST palīgmetodes darbojas bez pārvaldības autentifikācijas (lasāmas informācijas panelī); JSON-RPC maršruts `/a2a` izmanto Bearer `OMNIROUTE_API_KEY`, ja tas ir konfigurēts.

devin-cli u.c.). Pilnu sarakstu skatiet [nodrošinātāju atsaucē](./PROVIDER_REFERENCE.md).

| Metode | Ceļš                                    | Apraksts                                                                                                                                                                         |
| ------ | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/cli-tools/all-statuses`           | Visu CLI rīku statuss (instalēts, versija, pēdējoreiz konstatēts)                                                                                                                |
| GET    | `/api/cli-tools/status`                 | Detalizēts viena CLI rīka statuss (`?tool=` vaicājums)                                                                                                                           |
| POST   | `/api/cli-tools/apply`                  | Ierakstīt rīka ģenerēto konfigurāciju (`dryRun` nodrošina priekšskatījumu; `422` + `containerEphemeralTarget`, ja darbojas konteinerā; `migration` norāda uz mantotu Codex YAML) |
| GET    | `/api/cli-tools/backups`                | Uzskaitīt CLI rīku konfigurāciju dublējumkopijas                                                                                                                                 |
| POST   | `/api/cli-tools/backups`                | Izveidot visu CLI rīku konfigurāciju dublējumkopiju                                                                                                                              |
| POST   | `/api/cli-tools/backups`                | Atjaunot: tas pats galapunkts ar `{tool, backupId}` pamattekstā atjauno attiecīgo dublējumkopiju                                                                                 |
| GET    | `/api/cli-tools/antigravity-mitm`       | Antigravity MITM starpniekservera statuss (`antigravity-mitm` CLI rīks)                                                                                                          |
| POST   | `/api/cli-tools/antigravity-mitm/alias` | Konfigurēt antigravity-mitm aizstājvārdus                                                                                                                                        |

**Autentifikācija:** Nepieciešama pārvaldības sesija.

## Aizsargmehānismi

## Autentifikācija

Informāciju par četrām akreditācijas datu grupām (informācijas paneļa sesija, lokālais CLI marķieris, `oma_live_…` piekļuves marķieris un pārvaldības tvēruma API atslēga) un to atšķirībām no inferenču atslēgām skatiet sadaļā [Pārvaldības autentifikācija](../guides/MANAGEMENT-AUTH.md).

- Informācijas paneļa maršruti (`/dashboard/*`) izmanto `auth_token` sīkfailu
- Pieteikšanās izmanto saglabāto paroles jaucējvērtību; ja tā nav pieejama, tiek izmantots `INITIAL_PASSWORD`
- `requireLogin` var ieslēgt vai izslēgt, izmantojot `/api/settings/require-login`
- Maršrutiem `/v1/*` pēc izvēles var būt nepieciešama Bearer API atslēga, ja `REQUIRE_API_KEY=true`
- Šajā atsauces materiālā “pārvaldības marķieris” / “pārvaldības tvēruma API atslēga” nozīmē kādu no šajā ceļvedī aprakstītajām grupām, nevis kādu nedefinētu papildu slepenās informācijas veidu

> **Nesaderīgas izmaiņas (v3.8.0)** — `/api/v1/agents/tasks/*` un pārtraukuma perioda pārvaldības galapunktiem tagad ir nepieciešama **pārvaldības autentifikācija** (informācijas paneļa `auth_token` sīkfails vai pārvaldības tvēruma API atslēga). Klienti, kas iepriekš izsauca šos maršrutus bez autentifikācijas, saņems `401 Unauthorized`. Skatiet izmaiņu kopu `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
