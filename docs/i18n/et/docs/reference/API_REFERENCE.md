## Vestluse lõpetamised

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Kohandatud päised

| Päis                     | Suund  | Kirjeldus                                                                                                                                                                                                                |
| ------------------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `X-OmniRoute-No-Cache`   | Päring | Vahemälu eiramiseks määrake väärtuseks `true`                                                                                                                                                                            |
| `x-omniroute-no-memory`  | Päring | Selle päringu puhul mälu ja oskuste lisamise vahelejätmiseks määrake väärtuseks `true` (toimib nagu vahemälu eiramine ning väldib iga API-kõne tokeni- ja kulukulu)                                                      |
| `X-OmniRoute-Progress`   | Päring | Edenemissündmuste saamiseks määrake väärtuseks `true`                                                                                                                                                                    |
| `X-Session-Id`           | Päring | Püsiv seansivõti välise seansikuuluvuse jaoks                                                                                                                                                                            |
| `x_session_id`           | Päring | Aktsepteeritakse ka alakriipsuga varianti (otsene HTTP)                                                                                                                                                                  |
| `X-OmniRoute-Session-Id` | Päring | Kutsuja määratud seansi-/vestlussilt (edastatakse ka mällu). Kui see on olemas, talletatakse see muutmata kujul väljal `call_logs.session_tag`, et omistada kulud seansipõhiselt (#8249) — puudumisel seda ei sünteesita |
| `Idempotency-Key`        | Päring | Duplikaatide eemaldamise võti (5 s aken)                                                                                                                                                                                 |
| `X-Request-Id`           | Päring | Alternatiivne duplikaatide eemaldamise võti                                                                                                                                                                              |
| `x-omniroute-connection` | Päring | Kinnitage ühe mudeli päring ID alusel ühe pakkuja ühenduse (konto) külge — vt [Konto kinnitamine päringupõhiselt](#account-pinning-per-request)                                                                          |
| `X-OmniRoute-Cache`      | Vastus | `HIT` või `MISS` (voogedastuseta)                                                                                                                                                                                        |
| `X-OmniRoute-Idempotent` | Vastus | `true`, kui duplikaat eemaldati                                                                                                                                                                                          |
| `X-OmniRoute-Progress`   | Vastus | `enabled`, kui edenemise jälgimine on sisse lülitatud                                                                                                                                                                    |
| `X-OmniRoute-Session-Id` | Vastus | OmniRoute'i kasutatud tegelik seansi ID                                                                                                                                                                                  |
| `X-OmniRoute-Request-Id` | Vastus | Päringu korrelatsiooni-ID (kui teada)                                                                                                                                                                                    |
| `X-OmniRoute-Version`    | Vastus | OmniRoute'i järguversioon (alati olemas)                                                                                                                                                                                 |
| `X-OmniRoute-Cost-Saved` | Vastus | USD-des summa, mis jäi vahemälu `HIT` tõttu kulutamata (ainult vahemälutabamuste korral)                                                                                                                                 |
| `X-OmniRoute-Decision`   | Vastus | Marsruutimise jälg: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` on kombinatsioonistrateegia või `single` mittekombineeritud päringu puhul) — lõpetamisvastustes alati olemas                           |

> Nginxi märkus: kui kasutate allkriipsudega päiseid (näiteks `x_session_id`), lubage `underscores_in_headers on;`.

#### Konto fikseerimine päringu kohta

Kui teenusepakkujal on mitu ühendust (kontot või võtit), valib OmniRoute tavaliselt ühe
oma kontovaliku strateegia alusel. Selle asemel saab päringu fikseerida ühele kindlale ühendusele
päise `x-omniroute-connection` abil:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kust id leida.** Avage juhtpaneelil teenusepakkuja leht
  (**Juhtpaneel → Teenusepakkujad → <provider>**) ja klõpsake ühenduse real `xxxxxxxx…` id-sildil
  — see kopeerib täieliku ühenduse id.
- **Millised päringud seda arvestavad.** Ühe mudeliga päringud (`provider/model`) lõpp-punktides
  `/v1/chat/completions`, `/v1/messages` ja `/v1/responses`. Kombinatsioonid eiravad päist: fikseerige
  konto kombinatsiooni iga sammu jaoks selle sammu enda ühenduse kaudu.
- **Fikseerimine on range, mitte eelistus.** Kasutatakse ainult fikseeritud ühendust. Päringu
  käigus ilmnev tõrge salvestab konto ooteaja, kuid **ei** lülitu sama teenusepakkuja
  teisele kontole.
- **Ooteaeg ja kvoot vabastavad fikseeringu.** Kui fikseeritud ühendus on ooteajal,
  selle kvoot on ammendunud või kvoodireegel on selle blokeerinud, kasutavad hilisemad päringud
  teenusepakkuja teisi ühendusi täpselt nagu fikseerimata liiklus.
- **Tundmatud või keelatud id-d põhjustavad tõrke.** Id, mis ei kuulu teenusepakkuja aktiivsesse kogumisse (on kustutatud,
  inaktiveeritud või kuulub teisele teenusepakkujale), ei jäta ühtegi sobivat kontot, mistõttu päring
  nurjub, selle asemel et märkamatult mujale suunataks.

Claude Code saadab kohandatud päiseid muutuja `ANTHROPIC_CUSTOM_HEADERS` kaudu. Lisage see faili
`~/.claude/settings.json` plokki `env` või projektitaseme faili `.claude/settings.json`, et fikseerida
iga projekti jaoks erinev konto:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Allikas: `src/sse/handlers/chat.ts` (päise lugemine), `src/sse/services/auth.ts` ja
`src/sse/services/sessionAffinityPin.ts` (fikseeringu vabastamine ja kogumist puudumise kontroll).

> **Kulutelemeetria päised:** edukad voogedastuseta vastused sisaldavad ka `X-OmniRoute-*` kulutelemeetria komplekti — `X-OmniRoute-Response-Cost` (USD, fikseeritud 10 kümnendkohta; tasuta/hinnastamata päringute korral `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` ja `X-OmniRoute-Fallback-Attempts` (ainult siis, kui > 0), lisaks `X-OmniRoute-Request-Id` ja `X-OmniRoute-Version`. Neid väljastavad vestluslõpetused, `/v1/responses`, `/v1/messages` **ja meedia lõpp-punktid** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` ja `/v1/moderations` (kulu on alati `0`). Kui hinnateave on saadaval, arvutatakse meediakulu modaalsuse järgi (pildi, sekundi, tähemärgi või otsinguühiku kohta); vastasel juhul on see `0` (tõrke korral lubav).

> **Vahemälutabamuse kulusemantika:** semantilise vahemälu TABAMUSE korral (`X-OmniRoute-Cache-Hit: true`) ülesvoolupäringut ei tehta, seega on `X-OmniRoute-Response-Cost` väärtus `0.0000000000` (tabamuse teenindamise **lisanduv** kulu). Algne/eeldatav kulu esitatakse eraldi päises `X-OmniRoute-Cost-Saved`. Arvelduse tarbijad peaksid summeerima `X-OmniRoute-Response-Cost` väärtused (tabamused ei maksa midagi); vahemäluanalüütikas saab koondada `X-OmniRoute-Cost-Saved` väärtused.

## Eksklusiivsed hallatud seansirendid

Eksklusiivne hallatud seansirent on valikuline ja kliendist sõltumatu marsruutimisleping: üks aktiivne omanik
hoiab enda valduses üht sobivat OmniRoute’i ühendust. See ei rendi mudelit, ei nõua OAuthi, ei tuvasta
konkreetset klienti ega nõua kindlat teenusepakkujat.

Autentimiseks kasutataval API-võtmel peab olema ulatus `lease:exclusive` ja sõnaselgelt määratud mittetühi
`allowedConnections` loend. Andmebaasi muutmispiir jõustab võtme loomisel ja osalistel uuendustel mõlemad
väljad koos.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Edukad hõivamis-, pikendamis- ja vabastamisvastused avaldavad ajatemplid, `state` väärtuse ning täpse positiivse
`generation` väärtuse, kuid mitte kunagi valitud ühendust ega pääsuandmeid. Pikendamisel ja vabastamisel esitatakse
põlvkond JSON-kehas:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Aktiivse rendi omanik saab sõnaselgelt taotleda oma praeguse seose kohta privaatsust säilitavaid kuvamismetaandmeid:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Seda valikulist olekutoimingut piiravad ühe andmebaasitehingu sees läbipaistmatu omanik, autenditud hallatud API-võti ja täpne
aktiivne põlvkond. `displayName` on ainult kärbitud seadistatud
ühenduse nimi; kui turvalist seadistatud nime pole, on selle väärtus `null`. OmniRoute ei asenda seda kunagi
e-posti aadressi ega genereeritud kontoidentiteediga. Teenusepakkuja väärtus on mittetundlik kuvasilt ega ole kunagi
genereeritud ühilduva teenusepakkuja identifikaator. Pääsuandmed, pääsmikud, küpsised, töötlemata ühenduse või API-võtme
ID-d, omaniku räsid, piiramissaladused ja sisemised marsruutimisandmed jäetakse välja.

Vale võtme, vale omaniku, aegunud põlvkonna, puuduva, aegunud, vabastatud ja kehtetuks tunnistatud rendi otsingud
tagastavad kõik sama `409 LEASE_FENCE_STALE` vea ilma ühenduse metaandmeteta. Kliendil, kes sai läbilaskevõime ootamise vastuse, ei ole aktiivset seost, mida kontrollida. Kui marsruutimine viib aktiivse rendi
teisele ühendusele, jääb sama põlvkond kehtima ja olek tagastab atomaarselt uue seose, mitte kunagi vana.
Olemasolevad kliendid ei muutu, sest hõivamis-, pikendamis-, vabastamis- ja ootamisvastuste
senine kuju säilib.

See serverileping ei muuda standardset OpenAI Codexi `/status` väljundit. Standardne Codex esitab praegu oma
mudeli teenusepakkuja ning sisseehitatud autentimis- ja kontooleku, kuid ei kuva suvalisi kohandatud
teenusepakkuja konto metaandmeid; hilisem kliendiintegratsioon peab selle toimingu välja kutsuma ja otsustama, kuidas
kuvada `connection.displayName`.

Seejärel esitab iga hallatud järelduspäring mõlemad juhtpäised:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Täpset omanikku, põlvkonda, aktiivset ühendust ja autenditud API-võtit kontrollitakse vahetult
enne iga toetatud ülesvoolupäringu katset. Omaniku ja põlvkonna taasesitamine teise võtmega ebaõnnestub isegi
siis, kui see võti lubab sama ühendust. Töötlemata omanikke ei talletata, logita, säilitata
päringu hetktõmmises ega edastata ülesvoolu.

Ajutine konkurents tagastab HTTP `429` koos päisega `Retry-After` ja järgmise sisuga:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

See vastus tähendab ainult seda, et tavaline sobiv komplekt ei olnud tühi ja iga vaba kandidaat oli
mõne teise aktiivse rendi valduses. Toetamata mudelid/teenusepakkujad, reeglite mittevastavus, ooteaeg, kvoot,
seisund ja muud tavalised sobivustõrked säilitavad olemasolevad OmniRoute’i vastused.

### `x-omniroute-compression`

Tihendusplaani päringupõhine alistus. Kõrgeim prioriteet — alistab marsruutimiskombinatsiooni
alistuse, aktiivse profiili, automaatse käivituse ja paneeli vaikevaliku. Väärtused:

| Väärtus       | Mõju                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------- |
| `off`         | Selle päringu puhul tihendamist ei kasutata.                                                      |
| `default`     | Paneelist tuletatud vaikeprofiil (eirab aktiivset profiili). Kadudega mootorid jäävad välja.      |
| `safe`        | Ainult duplikaatide eemaldamine ja tühimärkide koondamine.                                        |
| `allow-lossy` | Säilitab selle päringu jaoks operaatori plaani, sealhulgas kokkuvõtted ja stiili ümberkirjutused. |
| `engine:<id>` | Üks mootor, kui see on lubatud, nt `engine:rtk`. Selle mootori päringupõhine lubamine.            |
| `<combo>`     | Nimega kombinatsioon, mida sobitatakse esmalt nime (tõstutundetult) ja seejärel ID järgi.         |

Märkused:

- Tundmatuid väärtusi eiratakse (päringut ei lükata kunagi tagasi); lahendamine jätkub operaatori tavapärase prioriteedijärjestuse alusel.
- Kui mitmel kombinatsioonil on sama nimi, edastage deterministliku vaste saamiseks kombinatsiooni **ID**.
- Kombinatsiooni, mille nimi on `off` või `default`, ei saa nime järgi valida (neid võtmesõnu tõlgendatakse esmajärjekorras); viidake sellisele kombinatsioonile selle ID abil.
- Tihendamise pealüliti on absoluutne piirang: kui tihendamine on globaalselt keelatud, ei saa see päis seda lubada.

Rakendatud plaan tagastatakse vastusepäises:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

kus `<source>` on üks järgmistest: `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` või `off`.

## Vektoriesitused

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Saadaolevad pakkujad: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Kataloogi ID-d on kujul `provider/model` (näide: `jina-ai/jina-embeddings-v5-omni-small`). Registris olevad Jina mudeli-ID-d ilma pakkuja nimeta (näiteks `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) lahendatakse samuti. Jina manustamis-, ümberjärjestamis-, klassifitseerimis- ja segmenteerimisfunktsioonid kasutavad esmalt juhtpaneeli `jina-ai` identimisteavet; `JINA_AI_API_KEY` on varuvariant ainult siis, kui juhtpaneeli võtit pole. Kaart `jina-reader` on mõeldud ainult Readeri / `r.jina.ai` jaoks (`POST /v1/web/fetch`) ega paku kunagi vektoriesitusi ega ümberjärjestamist.

Registrimudelid, mis deklareerivad multimodaalset tuge, aktsepteerivad ka kuni 32 pakkujast sõltumatut struktureeritud
elementi. Meediaelementide tüübid on `text`, `image`, `audio`, `video` ja `document`. Nende meedia `source`
on kas `{"type":"url","url":"https://..."}` või
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
ja perekonna alias `jina-ai/jina-embeddings-v5-omni` → omni-small) aktsepteerib ka Jina omavormingus
EmbeddingsV5Requesti dokumente ning **edastab need muutmata kujul** aadressile `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Omavormingus `{ image | audio | video | pdf }` väärtused võivad olla avalik HTTPS-i URL, `data:` URI või töötlemata
base64. OmniRoute ei teisenda neid objekte stringideks ega hangi omavormingus piltide URL-e — Jina hangib
avaliku meedia ise. Jina lisaväljad (`task`, `normalized`, `truncate`, `embedding_type`) edastatakse.
Ainult teksti toetavad Jina SKU-d lükkavad mittetekstilised dokumendid endiselt tagasi.

Turbe- ja transpordipiirangud:

- Kaugmeedia URL-id peavad olema avalikud HTTPS-i aadressid. Kanoonilised `{type,source:url}` elemendid hangitakse
  serveri poolel (ümbersuunamiste uuesti valideerimine, ajalõpp, suurusepiirangud, avalik DNS, ühenduse sidumine) ning
  lisatakse enne pakkuja poole pöördumist päringusse. Jina omavormingus `{image:"https://..."}` elemendid edastatakse muutmata kujul
  pärast sama avaliku HTTPS-i kontrolli; URL-i hangib Jina.
- Reasisese base64-meedia piirang on 8 MiB dekodeeritud andmeid elemendi kohta ja 16 MiB dekodeeritud andmeid kogu päringu kohta.

Pakkujapõhine teisendus (kanoonilisi elemente ei edastata kunagi muutmata kujul):

- Jina multimodaalsed mudelid: iga tipptaseme element muutub üheks modaalsusvõtmega objektiks
  (`text` / `image` / `audio` / `video` / `pdf`), mis kasutab reasisese meedia jaoks andme-URI-sid; üks vektor iga
  tipptaseme elemendi kohta.
- Gemini Embedding 2 perekond: ühest tipptaseme massiivist saab üks omavormingus
  `models/{model}:embedContent` päring väljaga `content.parts` (`text` või `inline_data`).
- llama.cpp (`llama-cpp/<model>`, mis tahes kohaliku serveri laaditud mudel): kanoonilistest `text` elementidest
  saavad lihtstringid ning `image` / `audio` / `video` elementidest igaühest üks
  `{"content": [part]}` objekt, mis kasutab llama-serveri vestlussisu osi (`image_url`,
  `input_audio` vorminguga `wav` / `mp3` / `flac`, `input_video`) koos reasiseselt lisatud andmetega; üks vektor
  iga tipptaseme elemendi kohta. Server peab töötama võtmetega `--embedding --mmproj …`; ilma projektorita
  lükkab see meedia ise tagasi. Tüüp `document` ei ole toetatud.
- Tundmatud/dünaamilised mudelid, millel puuduvad selgesõnalised modaalsuse metaandmed, lükkavad struktureeritud sisendi tagasi HTTP 400 vastusega.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Mittetoetatud mudeli ja modaalsuse kombinatsioonid tagastavad elemendi sundteisendamise asemel HTTP 400 vastuse. Sisendiga mitteseotud
laiendusväljad edastatakse pärandvormingus stringi-/sõneüksusepäringutes endiselt muutmata kujul.

```bash
# Loetle kõik vektoriesituse mudelid
GET /v1/embeddings
```

See integratsioon toetab tekstist pildi genereerimist, mitte viitepildi redigeerimist. Vertexi
väljund normaliseeritakse kujule `data[].b64_json`; `response_format: "url"` tagastab ülesvoolu

### Azure Document Intelligence'i päringutega kontrollimise voog

Azure Document Intelligence'i `analyze` API on asünkroonne: algne päring tagastab keha asemel
`Operation-Location` päise ning tulemust tuleb päringutega kontrollida. Töötleja
(`open-sse/handlers/ocr.ts`) kontrollib seda URL-i iga sekundi järel kuni 30 korda, nurjub kohe (ei
jätka kontrollimist), kui kontrollpäringu vastus pole `ok` või olek on `"failed"`, ning tagastab `504`, kui
toiming on pärast katsete limiidi ammendumist endiselt pooleli. Azure'i lõplik vastus
normaliseeritakse enne kutsujale tagastamist samale `pages`/`markdown` kujule, mida kasutab Mistral,
nii et kliendikood ei pea pakkujat eraldi käsitlema.

### Vertex AI DeepSeek OCR-i autentimine ja lõpp-punkti lahendamine

`vertex-deepseek-ocr` kasutab sama Vertex AI autentimist, mida OmniRoute juba toetab
vestlus- ja pildiliikluse jaoks (`open-sse/executors/vertex.ts`): ühenduse API-võti on kas
Service Account JSON-i mandaat (mis vahetatakse JWT-kandja voo kaudu lühiajalise OAuthi juurdepääsutõendi
vastu) või juba väljastatud OAuthi juurdepääsutõend, mida kasutatakse sellisena. Ülesvoolu lõpp-punkti URL on Vertexi
üldine `openapi/chat/completions` partneri lõpp-punkt, mis koostatakse ühenduse projektist ja
regioonist — selgesõnaline `providerSpecificData.project`/`providerSpecificData.region` on alati ülimuslik;
vastasel juhul tuletatakse projekt Service Account JSON-i väljast `project_id` ja regiooni
vaikeväärtus on `us-central1`. Mõlemad väärtused lahendatakse failis `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) ning neid kasutab
`src/app/api/v1/ocr/route.ts` enne kutse edastamist funktsioonile `handleOcr`.

### Mudeli-ID prefiksid (`?prefix=`)

Enamik mudeleid avaldatakse **teenusepakkuja prefiksiga**. Kasutatavat prefiksit juhib
funktsioonilipp `MODELS_CATALOG_PREFIX_MODE` ning seda saab **iga päringu jaoks eraldi** alistada
päringuparameetriga — see on kasulik kliendile, kes soovib puhast loendit, muutmata kogu serveri
seadistust kõigi teiste jaoks:

```bash
GET /v1/models?prefix=alias        # üks ID mudeli kohta — lühike aliasprefiks
GET /v1/models?prefix=dual         # mõlemad vormid (serveri vaikeväärtus)
GET /v1/models?prefix=canonical    # ainult täielik teenusepakkuja ID prefiks
```

| Režiim      | Väljastab                                                | Märkused                                                                                                                                                                                          |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **ja** `claude/claude-sonnet-4-6` | **Vaikeväärtus.** Mõlemad ID-d suunatakse samale mudelile; see säilitatakse, et kummagi vormi püsivalt määranud kliendikonfiguratsioonid töötaksid edasi. Kataloogi maht ligikaudu kahekordistub. |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Üks kirje mudeli kohta. Eraldi aliaseta teenusepakkujad väljastavad endiselt oma kirje, seega midagi ei lähe kaduma.                                                                              |
| `canonical` | `claude/claude-sonnet-4-6`                               | Üks kirje mudeli kohta täieliku teenusepakkuja ID prefiksiga. Eraldi aliaseta teenusepakkujad (nt `antigravity/…`, `agy/…`) väljastavad ka siin oma ainsa ID, seega midagi ei lähe kaduma.        |

Režiimi `dual` peegelkirje saab ära tunda ka ilma päringuparameetrita: sellel on esmasele ID-le
osutav väli `parent`.

Mudeli valijat kuvavad kliendid peaksid pärima `?prefix=alias` — seda teeb ka
[OmniCopiloti VS Code'i laiendus](../guides/VSCODE-COPILOT.md).

### Otsingufiltrid (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` aktsepteerib valikulisi otsingufiltreid. Ilma nendeta jääb vastus
muutumatuks. Need kitsendavad kataloogi, mida päringu tegija juba näeb (esmalt rakendatakse
API-võtme õigusi), ning neid rakendatakse enne OpenAI-laadset `limit` / `after` lehekülgjaotust:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # iga loetletud võimekus peab olema tõene
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # kataloogi `type`; ilma selleta read on `chat`
GET /v1/models?q=sonnet&limit=10                           # tõstutundetu vaste ID või nime alusel
```

| Parameeter    | Väärtused                                                                                           |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | mittenegatiivne täisarv, mida võrreldakse väärtusega `context_length`                               |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 märki                                                                                         |

Tundmatu väärtus või `min_context`, mis ei ole mittenegatiivne täisarv (näiteks `1.5`),
tagastab HTTP `400` ning teates loetletakse kehtivad väärtused. Teostus:
`src/app/api/v1/models/catalogFilters.ts`.

### Mudelite lühiloend (`POST /v1/models/query`)

`POST /v1/models/query` tagastab samast kataloogist lühikese deterministliku loendi, kasutades
sama autentimist ja võtmepõhist nähtavust nagu `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Kõik väljad on valikulised. `capabilities` ja `exclude` aktsepteerivad massiivi või komadega eraldatud stringi;
`max_output` võrreldakse väärtusega `max_output_tokens`. Tulemused sorditakse esmalt välja `owned_by`, seejärel `id` järgi.
Parameetri `limit` vaikeväärtus on `20` ning väärtused üle `100` piiratakse väärtusele `100`. Vigane JSON, tundmatu
väli või vigane väärtus tagastab HTTP `400`.

### Eraldi peidetud vestlusmudelid

Teenusepakkuja lehel märkega **Peidetud** mudel jäetakse kataloogist välja ning selle otsesel
pärimisel tagastatakse HTTP `404` / `model_not_found`. Kontroll kasutab lahendatud
teenusepakkujat ja mudelit, sealhulgas teenusepakkuja aliaseid, ühilduva teenusepakkuja sõlmeprefikseid ning
ühenduse vaikeväärtusi. Kombinatsioon jätab peidetud sihtmärgid vahele ja võib kasutada nähtavat sõsarmudelit; kui
ühtegi käivitatavat sihtmärki ei jää, tagastatakse sama veakood. Peitmise tühistamine jõustub järgmise
päringu ajal. Ainult piltidele kehtivad nähtavuse alistused ei peida sama ID-ga vestlusmudelit.

See eraldi mudeli seadistus ei sõltu
[mudelite avaldamise lubamis- ja keelamisloenditest](../routing/MODEL_EXPOSURE_LIST.md), mis filtreerivad kataloogis
avaldatavaid mudeleid ja automaatse suunamise kandidaate, säilitades samal ajal otsese suunamise. API-võtme mudeliõigusi
rakendatakse jätkuvalt eraldi. Kataloogi prefiksirežiimi vaikeväärtus on endiselt `dual`.

### Ilma mõtlemiseta mudelivariandid

Mõtlemisvõimeliste Claude'i mudelite puhul avaldab `/v1/models` ka **ilma mõtlemiseta** variandi, mille ID prefiks on `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Selle id valimine (nt Claude Code'i konfiguratsioonis, mis lisab alati `thinking`-ploki) lahendatakse tagasi tegelikuks `<provider>/<model>`-iks, kus arutluskäik on välja lülitatud — `/v1/messages`-teel kasutatakse `thinking:{type:"disabled"}`, `/v1/chat/completions`-teel aga jäetakse väljad `reasoning`/`reasoning_effort` välja. Variant kuvatakse ainult Claude'i perekonna mudelite puhul, mis toetavad mõtlemist **ja** arvestavad väärtust `disabled` (seega jäetakse välja näiteks ainult adaptiivset režiimi toetavad mudelid, mis lükkavad väärtuse `disabled` tagasi). Operaatorid saavad variandi iga mudeli puhul sundkorras sisse või välja lülitada atribuudi `ModelSpec.noThinkingAlias` kaudu.

## ElevenLabsi heli genereerimine

Konfigureerige OmniRoute'is pakkuja `elevenlabs` ühendus oma ElevenLabsi API-võtmega.
Kliendid autendivad oma **OmniRoute'i** võtmega (`Authorization: Bearer $OMNIROUTE_API_KEY`);
lüüs edastab salvestatud pakkuja võtme päisena `xi-api-key`. Ärge kunagi saatke ElevenLabsi võtit
lüüsi kandjaautentimise loana.

| Meetod | Tee                         | Vastus                                              | API-võtme lõpp-punkti kategooria |
| ------ | --------------------------- | --------------------------------------------------- | -------------------------------- |
| POST   | `/v1/sound-generation`      | Algupärased heli baidid                             | `elevenlabs`                     |
| POST   | `/v1/music`                 | Algupärased heli baidid                             | `music`                          |
| POST   | `/v1/music/stream`          | Voogedastatavad heli baidid                         | `music`                          |
| POST   | `/v1/music/detailed`        | Algupärane mitmeosaline heli ja kompositsiooniplaan | `music`                          |
| POST   | `/v1/music/detailed/stream` | Algupärased SSE metaandmed ja heliosad              | `music`                          |
| POST   | `/v1/music/plan`            | JSON-kompositsiooniplaan                            | `music`                          |

Need lõpp-punktid täiendavad olemasolevaid marsruute `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` ja `/v1/speech-to-text`. Algupärased JSON-väljad
ja päringuparameetrid, nagu `output_format` ja `enable_logging`, säilitatakse.
`/v1/music/detailed` vastustes säilivad nende mitmeosalise sisu eraldajad; sõeluge neid mitmeosalise sisuna.
`/v1/music/detailed/stream` tagastab `text/event-stream` sisu kompositsiooni metaandmete ja
base64-vormingus heliosadega SSE-sündmustes. Kõik kuus marsruuti toetavad CORS-i eelpäringuid.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Lühike heliefekt. Kestus: 0,5 kuni 30 sekundit.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Muusika kestust väljendatakse millisekundites: 3000 kuni 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Kasutage astmeliseks heli edastamiseks lõpp-punkti `/v1/music/stream` koos sama JSON-kehaga. Kompositsioon
aktsepteerib täpselt üht väljadest `prompt` või `composition_plan`; `/v1/music/plan` nõuab välja `prompt`
ja aktsepteerib valikuliselt välja `source_composition_plan`. Algupärased skeemid säilitavad pakkuja
lisaväljad, et kompositsiooniplaani versioonid ja peenhäälestuse suvandid jõuaksid ElevenLabsi.

Ühtne lõpp-punkt `/v1/music/generations` aktsepteerib ka mudeleid `elevenlabs/music_v1`,
`elevenlabs/music_v2` ja `elevenlabs/music_v2_5`. Aktiivse ElevenLabsi ühenduse korral
kuvatakse need mudelid muusikakataloogis. See lõpp-punkt tagastab
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Selle väli `duration` on esitatud
sekundites ja vastendatakse väljale `music_length_ms`; sõnaselgelt määratud `music_length_ms` on ülimuslik.
`instrumental` vastendatakse väljale `force_instrumental`, kusjuures algupärane väli on ülimuslik.
Kasutage voogedastuseks algupäraseid voogedastuse lõpp-punkte ja ainult kompositsiooniplaanil
põhinevate päringute jaoks algupärast kompositsiooni lõpp-punkti.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Lõpp-punkti, mudeli, eelarve ja ühenduse piirangud rakenduvad enne ülesvoolu päringu tegemist. Algupärased
marsruudid tagastavad ülesvoolu olekukoodid ja veakehad muutmata kujul, sealhulgas `402` paketi
piirangu ning `429` kvoodipiirangu korral. Päised `character-cost`, `song-id`, `request-id` ja `retry-after`
säilitatakse, kui need on olemas. Tasuta krediidijääk ei taga juurdepääsu igale
muusikamudelile, väljundvormingule ega API-funktsioonile: ElevenLabs otsustab iga päringu õiguste üle.
Ühtne lõpp-punkt säilitab vea olekukoodid OmniRoute'i normaliseeritud veaümbrises.

Ülesvoolu lepingud: [heliefektid](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[muusika komponeerimine](https://elevenlabs.io/docs/api-reference/music/compose) ja
[muusika üksikasjade voogedastus](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> (oMLX, vLLM, Infinity, lüüsi taga olev TEI, …), mille aadress on kujul `<node-prefix>/<model>`. Tagasisideahela

> operaator loetleb muutujas `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (nt Dockeri/Compose’i teenuse nimi,
> nagu `http://reranker:8080/v1`; neid kutsutakse otse, mitte kunagi `HTTP(S)_PROXY` ega
> ühendusele kinnistatud puhverserveri kaudu). Mis tahes muus
> hostis asuvad sõlmed — kohtvõrgu masin või Tailscale’i partner — on lubatud ainult siis, kui operaator lubab
> funktsioonilipu `RERANK_REMOTE_PROVIDER_NODES` **ja** sõlme baas-URL vastab pakkuja
> väljaminevate URL-ide poliitikale (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Mälu mootori ümberjärjestamise etapp kutsub seda marsruuti
> tagasisideahela kaudu, seega kehtib sama reegel mälu seadistuses olevale väärtusele `rerankProviderModel`.
>
> **Kohalike serverite kujud:** sõlme kutsutakse aadressil `<base>/v1/rerank` ja vastuse 404 korral aadressil `<base>/rerank`
> (Infinity, TEI). Ülesvoolu päringu keha sisaldab nii Cohere’i/OpenAI kirjapilti (`documents`,
> `return_documents`) kui ka TEI kirjapilti (`texts`, `return_text`) ning ülesvoolu vastus
> normaliseeritakse Cohere’i ümbrikusse: TEI paljas `[{index, score, text}]`, õhukestest lüüsidest pärinev `{results: [{index, score}]}`
> ja Voyage’i laadis `{data: [...]}` tagastatakse kõik kliendile kujul
> `{results: [{index, relevance_score, document?}]}`, skoori järgi sordituna ja väärtusega `top_n` piiratud.
>
> **Pakkujasõlmede tuvastamine:** OpenAI-ga ühilduva pakkujasõlme mudelid kuvatakse päringus `GET /v1/models`
> sõlme prefiksi all. Read, mis ei sisalda lõpp-punktide metaandmeid (tavaline kohalike `/v1/models` loendite puhul),
> pärivad sõlme atribuudi `apiType`, nii et `embeddings`-sõlme mudelite tüüp on `type: "embedding"` ja
> `rerank`-sõlme mudelite tüüp on `type: "rerank"`, selle asemel et vaikimisi kasutada vestlust; sünkroonitud või käsitsi lisatud real
> sõnaselgelt määratud `supportedEndpoints` jääb endiselt prioriteetseks.

### Exa ja Tavily `provider_options`

Exa ja Tavily loevad pakkujapõhiseid välju nimeruumiga kogumist:
`provider_options.exa` (või `provider_options["exa-search"]`) ja `provider_options.tavily`
(või `provider_options["tavily-search"]`). Edastatakse ainult allpool loetletud võtmed. Igaüht
kontrollitakse selle enda Zodi skeemi järgi failis `open-sse/handlers/search/providerOptionsPassthrough.ts`
ning vale tüübiga võti jäetakse välja. Kõiki teisi võtmeid eiratakse, sealhulgas autentimist, baas-URL-i,
`stream` ja `outputSchema`. Teiste pakkujate kasutatavad lamedad võtmed (`cx`, `depth`, ...) töötavad
nagu varem.

| Pakkuja | Tipptaseme väljad                                                                                                                                                                                                                                                                                                                                                         | Pesastatud                                                                                                                                                               |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Exa     | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (lamedad primitiivid), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                          | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` liidetakse vaikeväärtuse `{ text: true, highlights: true }` peale |
| Tavily  | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                        |

Üldised väljad on alati ülimuslikud: `query`, `max_results`, `filters` (domeenid), `country` ja väljast
`search_type` tuletatud teema. Exa puhul säilitab `search_type: "news"` väärtuse `category: "news"`.
Tavily aktsepteerib ka väärtust `search_type: "finance"` (`topic: "finance"`).

Üldine `time_range` jõuab nüüd mõlema pakkujani: Exa saab `startPublishedDate` (ISO
ajatempel) ja Tavily saab `start_date` (`YYYY-MM-DD`). Selgesõnaliselt määratud kuupäev väljal `provider_options`
kirjutab vastendatud väärtuse üle.

Exa tulemused säilitavad väljad `id`, `highlight_scores`, `summary`, `subpages`, `entities` ja `extras`
väljal `provider_raw`. Tavily tulemused säilitavad väljad `images` ja `favicon`.

Kulude arvestuseks kasutatakse endiselt lamedat registrit `costPerQuery`. Tavily arveldab
`search_depth: "advanced"` korral päringu kohta rohkem krediite ning see erinevus ei kajastu väljal
`usage.search_cost_usd`.

| Meetod | Tee             | Kirjeldus                                                       |
| ------ | --------------- | --------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | URL-i hankimine/kraapimine — keha valideerib `v1WebFetchSchema` |

**Autentimine:** Bearer API-võti (`extractApiKey` + `isValidApiKey`). Reeglistik jõustatakse `enforceApiKeyPolicy` kaudu.

**Kvooditeadlik varumehhanism (#8297):** kui selgesõnalist `provider` väärtust pole antud, läbitakse kogum
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`)
fikseeritud prioriteetsuse järjekorras (esmalt täitmine) — päringusagedusega piiratud, kuid konfigureeritud pakkuja jäetakse
päringu katkestamise asemel vahele ning korduskatset lubavast või kvoodiga seotud ülesvoolutõrkest
(HTTP 429 alati; 402/403 Firecrawli/Tavily/TinyFishi kvoodilaadsete tasuta tasemete korral —
mitte Jina Readeri puhul ja mitte kunagi tavalise vigase päringu 400 korral) liigutakse päringu ajal
järgmise veel proovimata ning kasutusandmetega pakkuja juurde. Kui kõik kogumi pakkujad on
ammendatud, tagastab lõpp-punkt varasema üldise `400` asemel ühe vastuse `429` (koos
päisega `Retry-After`). Kui taotletakse selgesõnalist `provider` väärtust, **ei** kasutata
vaikimisi varumehhanismi — päringusagedusega piiratud või tõrkuv selgesõnaline
pakkuja edastab oma vea (`429`, kui rakendub päringusageduse piirang, muul juhul ülesvooluteenuse
olekukood).

## Iseteeninduslik kasutus (`/api/usage/om-usage`)

Iga API-võti saab lugeda **enda** kasutust ja kvoote — halduse autentimist pole vaja. Seda otspunkti
kasutab klient (CLI, OmniCopiloti paneel), et näidata võtme omanikule tema kulutusi.

```bash
# Tekstivorm (ajalooline leping — lihttekst terminali jaoks)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Struktureeritud vorm — seda kasutab kasutajaliides
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Võtmel peab olema **`allowUsageCommand`** lubatud (vaikimisi välja lülitatud — töölaua API-võtmete
haldur lülitab selle sisse iga võtme kohta eraldi). Ilma selleta vastab otspunkt koodiga `403`.

`?format=json` tagastab eristatava struktuuri, et kutsuja ei loeks kunagi andmevälja keeldumisvastusest.
Edu korral:

```jsonc
{
  "allowed": true,
  // esineb ainult siis, kui võtmele on lubatud võtmepõhised kasutuspiirangud (päevane/nädalane USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // valitud teenusepakkuja kvoodi hetktõmmis või null, kui midagi pole veel vahemällu salvestatud:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // iga ühenduse hetktõmmis, et kasutajaliides saaks kuvada mitu teenusepakkujat kõrvuti:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Keeldumise korral (`401` vigane võti / `403` pole lubatud) tagastab sama marsruut
`{ "allowed": false, "error": { "message": "…" } }` — olemasolev, kuid tühi `personal`/`provider`
(võti on lubatud, kuid midagi pole veel tuvastatud) on keeldumisest erinev olek ning ainult JSON-vorm
eristab neid.

**Autentimine:** kutsuja enda Bearer API-võti, mis valideeritakse funktsiooniga `isValidApiKey` — see _ei ole_
haldusliides (`/api/keys/…`), mis jääb funktsiooni `requireManagementAuth` kaitse alla.

### Töötlemata ja katkestuslävega kohandatud kvoodiprotsendid

Otspunkti `/api/usage/om-usage` kasutades peaksid kutsujad arvestama **lihttekstiväljundis** ja
struktureeritud **JSON-väljundis** esitatud protsentide erinevusega:

| Aspekt                   | Lihttekstivorming (`/api/usage/om-usage` / `@@om-usage`)                                              | JSON-vorming (`?format=json`)                                                           |
| :----------------------- | :---------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------- |
| **Väljundväli**          | `NN% left` (nt `20% left`)                                                                            | `provider.quotas` / `providers[].quotas`                                                |
| **Mõõtmine**             | **Katkestuslävega kohandatud kasutatav maht**: üle katkestusläve olev jääkmaht                        | **Töötlemata ülesvoolukvoot**: teenusepakkuja kohandamata mõõtmistulemus                |
| **Katkestusläve skaala** | Skaleeritakse funktsiooniga `effectiveRemainingPercent()`, et kaitstud reservi kuvataks kui `0% left` | Puudub (töötlemata hetktõmmise väärtused teenusepakkuja esitatud kujul)                 |
| **Läveandmed**           | Sisalduvad kuvatavas protsendis                                                                       | Salvestatakse iga ühenduse väljal `quotaWindowThresholds` (või serveri vaikeväärtustes) |
| **Peamine tarbija**      | Interaktiivsed CLI-d, terminaliviibad, inimoperaatorid                                                | Programmilised integratsioonid, töölauad, analüütika, arveldusjälgijad                  |

#### Katkestuslävega kohandamise valem

OmniRoute toetab ennetavaid kvoodi katkestuslävesid, et vältida ülesvooluressursi ammendumist (seadistatakse
ühenduse väljal `quotaWindowThresholds`, teenusepakkuja vaikeväärtustes või üldistes töökindluse seadetes).
Kui kvoodiaknas on aktiivne katkestuslävi (nt `cutoff = 25%`), arvutab tekstirenderdaja allesjäänud mahu järgmiselt:

- Kui `remaining <= cutoff`: tagastab `0%`.
- Kui `remaining > cutoff`: tagastab `((remaining - cutoff) / (100 - cutoff)) * 100`.

Vormindatud tekstiväljund ümardab selle lähima täisarvuni (`Math.round(...)`).

#### Illustreeriv näide

Vaatleme teenusepakkuja akent, mille **töötlemata kasutus on 60%** (seega **töötlemata allesjäänud kvoot on 40%**)
ja millele on seadistatud **allesjäänud kvoodi 25% katkestuslävi**:

| Esitus                               | Arvutus                                            |  Alles  |            Tuletatud kasutus             |
| :----------------------------------- | :------------------------------------------------- | :-----: | :--------------------------------------: |
| **Töötlemata JSON (`?format=json`)** | Ülesvoolu hetktõmmis (`quotas[window]`)            | **40%** |                 **60%**                  |
| **Tekstivorming (`NN% left`)**       | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (kui arvutada `100 - remaining`) |

- **Miks tekst näitab, et alles on 20%:** Konto füüsilisest 40% allesjäänud kvoodist on 25% reserveeritud
  katkestusläve reegliga. Kutsujal on 75% kasutatavast puhvrist alles ainult 15%, enne kui marsruuter lõpetab
  päringute suunamise sellele ühendusele. Skaleerimine tagab, et ühendus annab ammendumisest märku (`0% left`)
  täpselt siis, kui marsruutimine lõpetatakse.
- **Miks JSON säilitab töötlemata väärtused:** JSON-andmestik tagastab teenusepakkuja täpse hetktõmmise (`UsageSnapshot`),
  et välistel tööriistadel oleks juurdepääs tegelikule ülesvooluressursi kasutusele ja ühenduse taseme
  väljale `quotaWindowThresholds` ilma serveripoolse kadudega skaleerimiseta.

#### Juhised tarbijate migreerimiseks

Kui väline integratsioon (näiteks redaktori pistikprogramm või agendilaiendus) kraapis varem teksti
lõpp-punkti (`NN% left`) ja arvutas kasutatud protsendi valemiga `100 - NN`, tähendab üleminek vormingule `?format=json` järgmist:

- JSON-i toorväärtuste lugemine kajastab **tegelikku ülesvoolu tarbimist** (ülaltoodud näites on kasutatud 60%).
- Kui integratsioon soovib säilitada teksti lõpp-punkti kasutatava jäägi semantika, saab see hinnata
  efektiivse jäägi valemit kliendi poolel, kasutades ühenduse taseme alistusteks välja `quotaWindowThresholds`.

Kohandatud Chat Completionsi sõlmed kohandavad selgesõnalised arutlusest loobumised ülesvoolu taustsüsteemile. Edukas
ühendustest valib automaatselt vestlusmalli juhtelemendid iga täpse mudeli ID jaoks,
mille `/models` kirje tõendab tunnustatud `owned_by` väärtust: `vllm`, `sglang` või `llamacpp`.
Läbipaistvad OpenAI-ga ühilduvad ümbrised võivad säilitada algse mudelikirje pesastatud
`openai` objektis; tuvastamine järgib kuni kolme sellist ümbrist. Puuduva, tundmatu või
vastuolulise omanikuteabega mudelid säilitavad tavapärase OpenAI käitumise. Tuvastamine kasutab uuesti olemasolevat kataloogipäringut,
ei genereeri lõpetamistokeneid ning muutub ühenduse lõpp-punkti muutmisel kehtetuks.

Sellise taustsüsteemi käitumise kindlaksmääramiseks, mis neid metaandmeid ei avalda, kasutage olemasolevat osalise
teenusepakkuja uuendamise API-t:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Saatke see keha päringuga `PUT /api/providers/<connection-id>`. Selle ühenduse puhul saadetakse selgesõnaline
arutluse intensiivsus `none` väärtustena `chat_template_kwargs.thinking=false` ja
`chat_template_kwargs.enable_thinking=false`. Selgesõnaliselt määratud mallipõhised väärtused jäävad määravaks,
välja arvatud juhul, kui serveripoolne arutlusreegel jõustab intensiivsuse. Säte rakendub ainult siis, kui kohandatud
OpenAI-ga ühilduv ühendus edastab Chat Completionsi keha; Responsesi päringud ja tavapärased
teenusepakkujad säilitavad oma loomuliku päringuvormingu. Tavapärase OpenAI
`reasoning_effort` muutmata edastamise jõustamiseks määrake `reasoningControl` väärtuseks `openai`;
automaatse tuvastamise kasutamiseks jätke see välja või määrake väärtuseks `null`.

Claude Code'i automaatrežiimi klassifikaatori päringud seavad loomuliku mõtlemise vaikimisi keelatuks, kui need
ei sisalda selgesõnalisi arutluse juhtelemente. Tuvastamine kasutab Claude'i vormingus
päringutes klassifikaatori süsteemimarkerit, mitte mudelinimesid ega lõpetamispiiranguid. Selgesõnalised keha juhtelemendid, toetatud arutluse/mõtlemise
päised, marsruutimisreeglid ja lahendatud mudeli arutluse intensiivsus säilitavad oma senise prioriteedi. Mõlemad klassifikaatori
etapid säilitavad oma viibad, lõpetamispiirangud, peatamisjadad ja tegelikud ülesvoolu loaotsused;
teine etapp võib soovitud nähtava arutluse endiselt tavatekstina väljastada.

### Versioon ja väljalaskekanal

```bash
GET /api/system/version
```

Ainult loopback-liidese kaudu kasutatav haldusmarsruut (administraatori autentimine). Tagastab töötava versiooni, uusima
avaldatud versiooni ja automaatse värskendamise oleku. `releaseChannel` ja `channels` on lisatud
väljad (haru 3.8.54); `channel` säilitab oma tähenduse — juurutusrežiim, mida juhtpaneeli värskendaja
kasutab (`npm`, `source` või `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — töötava järgu npm-kanal: `nightly` versioonide puhul, mis sisaldavad `-nightly.*`,
  `next` muude eelväljalasete puhul (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` stabiilse versiooni puhul,
  mille põhiversioon on vanem kui `channels.latest`, muul juhul `latest`. Samad reeglid mis failis
  `scripts/release/dist-tag.mjs`, mis valib avaldamise ajal npm-i dist-tag'i.
- `channels` — iga dist-tag'i uusim avaldatud versioon käsust `npm view omniroute dist-tags` (registri
  HTTP-varuvariant), mis on vahemällu salvestatud sama 10-minutilise TTL-iga nagu `latest`. `latest` on alati olemas
  (varuvariandina kasutatakse välja `latest`, seejärel `"unavailable"`); `next`, `nightly` ja `lts` kuvatakse
  ainult siis, kui vastav dist-tag on olemas. Päring `Cache-Control: no-cache` värskendab mõlemat päringut.

Kanalimudelit (`latest` = v3 kuni 4.0 GA-ni, `next` = rc, `nightly` = `develop`-järgud,
`lts` = v3 paigad pärast 4.0 GA-d) kirjeldatakse failis `docs/ops/RELEASE_STRATEGY.md`.

## Heli transkribeerimine

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

Transkribeerige helifaile mis tahes konfigureeritud STT-pakkuja abil. Esimene tee
segment valib otsepakkuja (`openai/…`, `deepgram/…`). Lüüsid, mis
ekspordivad edasi teise teenusepakkuja mudelit, kasutavad kvalifitseeritud ID-d
(`openrouter/deepgram/nova-3`).

**Päring:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Vastus:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

**Mudeli-ID-de näited:** `openai/whisper-1` (nõuab OpenAI võtit),
`openrouter/deepgram/nova-3` (nõuab OpenRouteri võtit),
`deepgram/nova-3` (nõuab Deepgrami otsevõtit). Lihtne
`deepgram/nova-3` päring **ei** kasuta OpenRouterit.

**Toetatud vormingud:** `mp3`, `wav`, `m4a`, `flac`, `ogg`, `webm`.

## Tokeniseeritud VS Code'i / päiseta pseudonüümid

```bash
GET /api/v1/vscode/{token}/models

# OpenAI-laadse vestluse pseudonüümid

# Ollama-laadsed pseudonüümid
```

Näide:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
```

- Tokeniseeritud pseudonüümid kasutavad samu töötlejaid nagu `/v1/*` ja `/api/tags`; vastuste struktuur jääb samaks.

- URL-il põhinevad tokenid võivad ilmuda pöördpuhverserveri logides, brauseri ajaloos ja OmniRoute'ist väljapoole jäävas telemeetrias. Käsitlege neid ühilduvusvalikuna, mitte vaikimisi autentimisrežiimina.

## Tokenipiirangud

API-võtme põhised **tokenite** eelarved (erinevad ülaltoodud USD-põhisest eelarvest). Neid jõustatakse päringu töötlemise käigus: kui võtme praeguse perioodi kasutus jõuab piiranguni, lükatakse päringud tagasi vastusega `429 Too Many Requests`. Piirangu ulatuseks võib olla konkreetne `model`, `provider` või kogu võtmele rakenduv `global`; kui päringule vastab mitu piirangut, rakendatakse neist kõige rangemat.

```bash
# Võtme tokenipiirangute loetelu (sisaldab praeguse perioodi reaalajas kasutust)
GET /api/usage/token-limits?apiKeyId=key-123

# Tokenipiirangu loomine või värskendamine
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Tokenipiirangu kustutamine ID järgi
DELETE /api/usage/token-limits?id=tl-abc
```

> **Skeemi märkused** (`setTokenLimitSchema`): `apiKeyId` ja `scopeType` (`model` | `provider` | `global`) on kohustuslikud. `scopeValue` on kohustuslik, välja arvatud juhul, kui `scopeType` on `global` (nt mudeli ID ulatuse `model` puhul või teenusepakkuja ID ulatuse `provider` puhul). `tokenLimit` peab olema positiivne täisarv (string teisendatakse automaatselt). Valikulised: `id` (loomiseks jätke välja, värskendamiseks lisage), `resetInterval` (`daily` | `weekly` | `monthly`, vaikimisi `monthly`), `resetTime` (`HH:MM`), `enabled` (vaikimisi `true`). `GET`-vastustes täiendatakse iga piirangut väljadega `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` ja `nextResetAt`. See on haldusklassi lõpp-punkt (autentimist jõustab tsentraalselt autoriseerimiskonveier).

## Päringu töötlemine

1. Klient saadab päringu aadressile `/v1/*`
2. Marsruudikäitleja kutsub välja `handleChat`, `handleEmbedding`, `handleAudioTranscription` või `handleImageGeneration`
3. Mudel lahendatakse (otse teenusepakkuja/mudel või alias/kombinatsioon)
4. Mandaadid valitakse kohalikust andmebaasist, filtreerides kontode saadavuse alusel
5. Vestluse puhul kontrollib `handleChatCore` semantilist/signatuuri vahemälu ja lahendab kombinatsiooni tihendussätted
6. Kui ennetav tihendamine on lubatud, käivitatakse see enne teenusepakkuja vormingusse teisendamist (`lite`, Caveman, RTK või kombineeritud)
7. Teenusepakkuja täitur saadab päringu ülesvoolu
8. Vastus teisendatakse tagasi kliendi vormingusse (vestlus) või tagastatakse muutmata kujul (vektorisitus/pildid/heli)
9. Kasutus, tihendusanalüütika ja päringulogid salvestatakse
10. Vigade korral rakendatakse kombinatsiooni reeglite kohast varuvarianti

Täielik arhitektuuri kirjeldus: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Töökindlus (laiendatud)

OmniRoute pakub kolme sõltumatut ajutiste tõrgete mehhanismi; alltoodud halduslõpp-punktid võimaldavad operaatoritel nende olekut vaadata ja alistada:

| Ulatus                      | Oleku salvestuskoht                          | Vaatamine                                 | Lähtestamine / tühjendamine                                             |
| --------------------------- | -------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------- |
| Teenusepakkuja kaitselüliti | `domain_circuit_breakers` + mälusisene       | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                            |
| Ühenduse ooteaeg            | `rateLimitedUntil` teenusepakkuja ühendustel | `/api/rate-limits`, `/api/providers/[id]` | (lubatakse viivitusega uuesti; tühjendage teenusepakkuja PUT-päringuga) |
| Mudeli lukustus             | Mälusisene mudelite saadavuse register       | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                |

`PATCH /api/resilience` aktsepteerib teenusepakkuja kaitselüliti alistusi väljade `providerBreaker.oauth` ja `providerBreaker.apikey` all. Iga profiil toetab välju `degradationThreshold`, `failureThreshold` ja `resetTimeoutMs`; samad väljad on saadaval ka jaotises Dashboard → Settings → Resilience.

```bash
# Ühe mudeli lukustuse tühjendamine
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Kõigi lukustuste kustutamine
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Täieliku kontseptuaalse kirjelduse ja kaitselüliti vaikeväärtuste kohta vaadake [`CLAUDE.md`](../../CLAUDE.md) → „Töökindluse käitusaegne olek” ning [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Päringulimiidi järjekord ja automaatse lubamise turvavõrk

- **Toetatud kirjutamistee**: `POST /api/rate-limits` kehaga `{"connectionId": "<id>", "enabled": true|false}` on toetatud halduslõpp-punkt ühenduse päringulimiidi kaitse sisse- või väljalülitamiseks. `PUT /api/providers/[id]` ei muuda ega lülita tahtlikult välja `rateLimitProtection` väärtust (#11278).
- **Väärtuse `enabled: false` semantika**: Väärtuse `enabled: false` määramine eemaldab ühenduse selgesõnalise kaitse, kuid **ei** eemalda aktiivset API-võtmega ühendust globaalsest automaatse lubamise turvavõrgust (`autoEnableApiKeyProviders = true`). Funktsioonis `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) on `false` ja `undefined` samaväärsed; aktiivsed API-võtmega ühendused, millel puudub selgesõnaline kaitse, jäävad automaatse lubamise turvavõrgu kaudu kaitstuks.
- **Globaalne keelamine**: API-võtmega ühenduste käitamiseks ilma päringulimiidi järjekordadeta keelake turvavõrk globaalselt keskkonnamuutuja `RATE_LIMIT_AUTO_ENABLE=false` kaudu või määrake `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`).


Toetatud meetodid (kõik sõltuvad sättest `settings.a2aEnabled`):

| Meetod           | Kirjeldus                                                             |
| ---------------- | --------------------------------------------------------------------- |
| `message/send`   | Oskuse sünkroonne käivitamine; tagastab `{task, artifacts, metadata}` |
| `message/stream` | Sama oskustekomplekti voogedastus SSE kaudu                           |
| `tasks/get`      | Ülesande hankimine `taskId` järgi                                     |
| `tasks/cancel`   | Ülesande tühistamine `taskId` järgi                                   |

Sisseehitatud oskused: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Agendikaart

```bash
GET /.well-known/agent.json
```

## Autentimine

Nelja identimisteabe perekonna (töölaua seanss, kohalik CLI-luba, `oma_live_…` juurdepääsutõend, halduse ulatusega API-võti) ja nende erinevuste kohta inferentsivõtmetest vaadake jaotist [Halduse autentimine](../guides/MANAGEMENT-AUTH.md).

- Töölaua marsruudid (`/dashboard/*`) kasutavad küpsist `auth_token`
- Sisselogimisel kasutatakse salvestatud parooliräsi; varuvariandina kasutatakse väärtust `INITIAL_PASSWORD`
- Suvandit `requireLogin` saab lülitada marsruudi `/api/settings/require-login` kaudu
- Marsruudid `/v1/*` võivad nõuda Beareri API-võtit, kui `REQUIRE_API_KEY=true`
- „Haldusluba” / „halduse ulatusega API-võti” tähendab selles teatmikus ühte vastavas juhendis kirjeldatud perekondadest, mitte määratlemata täiendavat saladuse tüüpi

> **Ühilduvust katkestav muudatus (v3.8.0)** — `/api/v1/agents/tasks/*` ja jahutusperioodi haldamise lõpp-punktid nõuavad nüüd **halduse autentimist** (töölaua küpsis `auth_token` või halduse ulatusega API-võti). Kliendid, mis varem kutsusid neid marsruute autentimata, saavad vastuseks `401 Unauthorized`. Vaadake muudatust `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
