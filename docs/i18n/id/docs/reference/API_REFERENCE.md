## Penyelesaian Chat

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Header Khusus

| Header                   | Arah       | Deskripsi                                                                                                                                                                                                                      |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `X-OmniRoute-No-Cache`   | Permintaan | Atur ke `true` untuk melewati cache                                                                                                                                                                                            |
| `x-omniroute-no-memory`  | Permintaan | Atur ke `true` untuk melewati injeksi memori + keterampilan bagi permintaan ini (mencerminkan no-cache; menghindari overhead token/biaya per panggilan)                                                                        |
| `X-OmniRoute-Progress`   | Permintaan | Atur ke `true` untuk peristiwa progres                                                                                                                                                                                         |
| `X-Session-Id`           | Permintaan | Kunci sesi persisten untuk afinitas sesi eksternal                                                                                                                                                                             |
| `x_session_id`           | Permintaan | Varian dengan garis bawah juga diterima (HTTP langsung)                                                                                                                                                                        |
| `X-OmniRoute-Session-Id` | Permintaan | Tag sesi/percakapan yang diberikan pemanggil (juga digunakan oleh memori). Jika ada, disimpan apa adanya ke `call_logs.session_tag` untuk atribusi biaya per sesi (#8249) — tidak pernah dibuat secara sintetis jika tidak ada |
| `Idempotency-Key`        | Permintaan | Kunci deduplikasi (jendela 5 detik)                                                                                                                                                                                            |
| `X-Request-Id`           | Permintaan | Kunci deduplikasi alternatif                                                                                                                                                                                                   |
| `x-omniroute-connection` | Permintaan | Sematkan permintaan model tunggal ke satu koneksi penyedia (akun) berdasarkan ID-nya — lihat [Penyematan akun per permintaan](#account-pinning-per-request)                                                                    |
| `X-OmniRoute-Cache`      | Respons    | `HIT` atau `MISS` (non-streaming)                                                                                                                                                                                              |
| `X-OmniRoute-Idempotent` | Respons    | `true` jika dideduplikasi                                                                                                                                                                                                      |
| `X-OmniRoute-Progress`   | Respons    | `enabled` jika pelacakan progres aktif                                                                                                                                                                                         |
| `X-OmniRoute-Session-Id` | Respons    | ID sesi efektif yang digunakan oleh OmniRoute                                                                                                                                                                                  |
| `X-OmniRoute-Request-Id` | Respons    | ID korelasi permintaan (jika diketahui)                                                                                                                                                                                        |
| `X-OmniRoute-Version`    | Respons    | Versi build OmniRoute (selalu ada)                                                                                                                                                                                             |
| `X-OmniRoute-Cost-Saved` | Respons    | Nilai dalam USD yang dihemat oleh cache saat terjadi HIT (hanya cache hit)                                                                                                                                                     |
| `X-OmniRoute-Decision`   | Respons    | Jejak perutean: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` adalah strategi kombo, atau `single` untuk permintaan nonkombo) — selalu ada pada respons penyelesaian                                           |

> Catatan Nginx: jika Anda mengandalkan header dengan garis bawah (misalnya `x_session_id`), aktifkan `underscores_in_headers on;`.

#### Penyematan akun per permintaan

Ketika suatu penyedia memiliki beberapa koneksi (akun atau kunci), OmniRoute biasanya memilih salah satunya
melalui strategi pemilihan akunnya. Sebagai alternatif, suatu permintaan dapat menyematkan satu koneksi tertentu
dengan header `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Tempat menemukan id.** Buka halaman penyedia di dasbor
  (**Dasbor → Penyedia → <penyedia>**) dan klik chip id `xxxxxxxx…` pada baris koneksi
  — tindakan ini menyalin id koneksi lengkap.
- **Permintaan yang mematuhinya.** Permintaan model tunggal (`provider/model`) pada
  `/v1/chat/completions`, `/v1/messages`, dan `/v1/responses`. Kombinasi mengabaikan header tersebut: sematkan
  akun untuk setiap langkah kombinasi melalui koneksi milik langkah itu sendiri.
- **Penyematan bersifat ketat, bukan preferensi.** Koneksi yang disematkan digunakan secara eksklusif. Suatu
  kegagalan di dalam permintaan akan mencatat masa jeda akun, tetapi **tidak** beralih ke
  akun lain dari penyedia yang sama.
- **Masa jeda dan kuota melepaskan penyematan.** Saat koneksi yang disematkan sedang dalam masa jeda,
  kehabisan kuota, atau diblokir oleh kebijakan kuota, permintaan berikutnya beralih ke koneksi lain milik penyedia,
  persis seperti lalu lintas yang tidak disematkan.
- **Id yang tidak dikenal atau dinonaktifkan akan gagal.** Id yang tidak berada dalam kumpulan aktif penyedia (dihapus,
  dinonaktifkan, atau milik penyedia lain) menyebabkan tidak adanya akun yang memenuhi syarat, sehingga permintaan
  gagal alih-alih dialihkan secara diam-diam ke tempat lain.

Claude Code mengirim header khusus melalui `ANTHROPIC_CUSTOM_HEADERS`. Letakkan variabel tersebut di blok `env`
pada `~/.claude/settings.json`, atau di `.claude/settings.json` tingkat proyek untuk menyematkan akun yang berbeda
bagi setiap proyek:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Sumber: `src/sse/handlers/chat.ts` (pembacaan header), `src/sse/services/auth.ts`, dan
`src/sse/services/sessionAffinityPin.ts` (pelepasan penyematan dan pemeriksaan ketidakberadaan dalam kumpulan).

> **Header telemetri biaya:** respons berhasil non-streaming juga menyertakan kumpulan telemetri biaya `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, tetap 10 angka desimal; `0.0000000000` untuk yang gratis/tanpa harga), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, dan `X-OmniRoute-Fallback-Attempts` (hanya ketika > 0), ditambah `X-OmniRoute-Request-Id` dan `X-OmniRoute-Version`. Header-header ini dihasilkan oleh penyelesaian percakapan, `/v1/responses`, `/v1/messages`, **dan endpoint media** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, dan `/v1/moderations` (biaya selalu `0`). Biaya media dihitung berdasarkan setiap modalitas (per gambar, per detik, per karakter, per unit pencarian) ketika informasi harga tersedia, atau `0` jika tidak tersedia (fail-open).

> **Semantik biaya cache-hit:** pada HIT cache semantik (`X-OmniRoute-Cache-Hit: true`), tidak ada panggilan upstream yang dilakukan, sehingga `X-OmniRoute-Response-Cost` adalah `0.0000000000` (biaya **inkremental** untuk menyajikan hit tersebut). Biaya awal/biaya yang seharusnya timbul dilaporkan secara terpisah dalam `X-OmniRoute-Cost-Saved`. Konsumen penagihan harus menjumlahkan `X-OmniRoute-Response-Cost` (hit tidak memerlukan biaya); analitik cache dapat mengagregasikan `X-OmniRoute-Cost-Saved`.

## Lease Sesi Terkelola Eksklusif

Penyewaan sesi terkelola eksklusif merupakan kontrak perutean yang bersifat opsional dan netral terhadap klien: satu pemilik aktif
memegang satu koneksi OmniRoute yang memenuhi syarat. Kontrak ini tidak menyewakan model, mewajibkan OAuth, mengidentifikasi
klien tertentu, atau mewajibkan penyedia tertentu.

Kunci API yang digunakan untuk autentikasi harus memiliki cakupan `lease:exclusive` dan daftar
`allowedConnections` eksplisit yang tidak kosong. Batas mutasi database memberlakukan kedua bidang tersebut secara bersamaan saat
pembuatan kunci dan pembaruan parsial.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Respons keberhasilan untuk perolehan, perpanjangan, dan pelepasan menampilkan stempel waktu, `state`, serta
`generation` positif yang tepat, tetapi tidak pernah menampilkan koneksi atau kredensial yang dipilih. Perpanjangan dan pelepasan menyertakan
generasi dalam isi JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Pemilik lease aktif dapat secara eksplisit meminta metadata tampilan yang aman bagi privasi untuk pengikatannya saat ini:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Tindakan status opsional ini dibatasi oleh pemilik buram, kunci API terkelola yang diautentikasi, dan
generasi aktif yang tepat dalam satu transaksi database. `displayName` hanya berisi nama koneksi terkonfigurasi
yang telah dipangkas; nilainya adalah `null` jika tidak ada nama terkonfigurasi yang aman. OmniRoute tidak pernah menggantinya dengan
email atau identitas akun yang dihasilkan. Nilai penyedia merupakan label tampilan yang tidak sensitif dan tidak pernah
berupa pengidentifikasi penyedia kompatibel yang dihasilkan. Kredensial, token, cookie, ID mentah koneksi atau kunci
API, hash pemilik, rahasia pembatasan, dan data perutean internal tidak disertakan.

Pencarian dengan kunci yang salah, pemilik yang salah, generasi usang, data yang tidak ada, kedaluwarsa, telah dilepas, atau telah diinvalidation semuanya
mengembalikan kesalahan `409 LEASE_FENCE_STALE` yang sama tanpa metadata koneksi. Klien yang menerima respons menunggu kapasitas tidak memiliki pengikatan aktif untuk diperiksa. Ketika perutean mengalihkan lease aktif,
generasi yang sama tetap valid dan status secara atomik mengembalikan pengikatan baru, bukan pengikatan lama.
Klien yang sudah ada tetap tidak berubah karena respons perolehan, perpanjangan, pelepasan, dan penantian mempertahankan
struktur sebelumnya.

Kontrak server ini tidak mengubah `/status` OpenAI Codex standar. Saat ini, Codex standar melaporkan
penyedia model dan status autentikasi/akun bawaannya, tetapi tidak merender metadata akun penyedia khusus
yang arbitrer; integrasi klien mendatang harus memanggil tindakan ini dan menentukan cara
menampilkan `connection.displayName`.

Setiap permintaan inferensi terkelola kemudian menyertakan kedua header kontrol:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Pemilik yang tepat, generasi, koneksi aktif, dan kunci API yang diautentikasi dibatasi tepat
sebelum setiap percobaan upstream yang didukung. Memutar ulang pemilik dan generasi dengan kunci lain akan gagal meskipun
kunci tersebut mengizinkan koneksi yang sama. Pemilik mentah tidak disimpan secara persisten, dicatat dalam log, dipertahankan dalam
snapshot permintaan, atau diteruskan ke upstream.

Persaingan sementara mengembalikan HTTP `429` dengan `Retry-After` dan:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Respons ini hanya berarti bahwa kumpulan biasa yang memenuhi syarat tidak kosong dan setiap kandidat bebas sedang
dipegang oleh lease aktif milik pihak lain. Model/penyedia yang tidak didukung, ketidakcocokan kebijakan, periode tunggu, kuota,
kesehatan, dan kegagalan kelayakan biasa lainnya tetap menggunakan respons OmniRoute yang sudah ada.

### `x-omniroute-compression`

Penggantian paket kompresi per permintaan. Prioritas tertinggi — mengungguli penggantian kombinasi perutean,
profil aktif, pemicu otomatis, dan Default panel. Nilai:

| Nilai         | Efek                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| `off`         | Tidak ada kompresi untuk permintaan ini.                                                                            |
| `default`     | Profil Default yang berasal dari panel (mengabaikan profil aktif). Mesin lossy tetap dinonaktifkan.                 |
| `safe`        | Hanya deduplikasi dan pelipatan spasi kosong.                                                                       |
| `allow-lossy` | Pertahankan paket operator untuk permintaan ini, termasuk ringkasan dan penulisan ulang gaya.                       |
| `engine:<id>` | Satu mesin saat diaktifkan, misalnya `engine:rtk`. Keikutsertaan per permintaan untuk mesin tersebut.               |
| `<combo>`     | Kombinasi bernama, dicocokkan berdasarkan nama terlebih dahulu (tidak peka huruf besar-kecil), lalu berdasarkan ID. |

Catatan:

- Nilai yang tidak dikenal akan diabaikan (permintaan tidak pernah ditolak); resolusi akan beralih ke urutan prioritas operator normal.
- Jika beberapa kombinasi memiliki nama yang sama, teruskan **id** kombinasi tersebut untuk pencocokan deterministik.
- Kombinasi dengan nama `off` atau `default` tidak dapat dipilih berdasarkan nama (kata kunci tersebut ditafsirkan terlebih dahulu); rujuk kombinasi tersebut berdasarkan ID-nya.
- Sakelar kompresi utama merupakan gerbang mutlak: ketika kompresi dinonaktifkan secara global, header ini tidak dapat mengaktifkannya.

Paket yang diterapkan dikembalikan dalam header respons:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

dengan `<source>` merupakan salah satu dari `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, atau `off`.

## Embedding

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Penyedia yang tersedia: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID katalog menggunakan format `provider/model` (contoh: `jina-ai/jina-embeddings-v5-omni-small`). ID model Jina tanpa nama penyedia yang muncul dalam registri (misalnya `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) juga dapat di-resolve. Operasi embed/rerank/classify/segment Jina terlebih dahulu menggunakan kredensial dasbor `jina-ai`; `JINA_AI_API_KEY` hanya digunakan sebagai fallback jika tidak ada kunci dasbor. Kartu `jina-reader` hanya untuk Reader / `r.jina.ai` (`POST /v1/web/fetch`) dan tidak pernah menyediakan embedding atau rerank.

Model registri yang menyatakan dukungan multimodal juga menerima hingga 32 item terstruktur yang netral terhadap penyedia. Jenis item media adalah `text`, `image`, `audio`, `video`, dan `document`. `source` medianya berupa `{"type":"url","url":"https://..."}` atau `{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`, dan alias keluarga `jina-ai/jina-embeddings-v5-omni` → omni-small) juga menerima dokumen EmbeddingsV5Request native Jina dan **meneruskannya secara utuh** ke `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Nilai native `{ image | audio | video | pdf }` dapat berupa URL HTTPS publik, URI `data:`, atau base64 mentah. OmniRoute tidak mengubah objek tersebut menjadi string atau mengambil URL gambar native — Jina mengambil sendiri media publik tersebut. Kolom Jina tambahan (`task`, `normalized`, `truncate`, `embedding_type`) diteruskan. SKU Jina khusus teks tetap menolak dokumen nonteks.

Batasan keamanan dan transportasi:

- URL media jarak jauh harus menggunakan HTTPS publik. Item kanonis `{type,source:url}` diambil di sisi server (validasi ulang pengalihan, batas waktu, batas ukuran, DNS publik, dan penguncian koneksi), lalu disisipkan sebelum pemanggilan penyedia. Item native Jina `{image:"https://..."}` diteruskan apa adanya setelah pemeriksaan HTTPS publik yang sama; Jina mengambil URL tersebut.
- Media base64 inline dibatasi hingga 8 MiB hasil dekode per item dan 16 MiB hasil dekode untuk keseluruhan permintaan.

Penerjemahan penyedia (item kanonis tidak pernah diteruskan tanpa perubahan):

- Model multimodal Jina: setiap item tingkat teratas menjadi satu objek dengan kunci modalitas (`text` / `image` / `audio` / `video` / `pdf`) yang menggunakan URI data untuk media inline; satu vektor per item tingkat teratas.
- Keluarga Gemini Embedding 2: satu array tingkat teratas menjadi satu permintaan native `models/{model}:embedContent` dengan `content.parts` (`text` atau `inline_data`).
- llama.cpp (`llama-cpp/<model>`, model apa pun yang dimuat oleh server lokal): item `text` kanonis menjadi string biasa, sedangkan `image` / `audio` / `video` masing-masing menjadi satu objek `{"content": [part]}`, menggunakan bagian konten percakapan llama-server (`image_url`, `input_audio` dengan format `wav` / `mp3` / `flac`, `input_video`) dengan data inline; satu vektor per item tingkat teratas. Server harus dijalankan dengan `--embedding --mmproj …`; tanpa proyektor, server akan menolak sendiri media tersebut. `document` tidak didukung.
- Model yang tidak dikenal/dinamis tanpa metadata modalitas eksplisit menolak input terstruktur dengan HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Kombinasi model/modalitas yang tidak didukung mengembalikan HTTP 400 alih-alih memaksakan konversi item. Kolom ekstensi non-input pada permintaan string/token lama tetap diteruskan tanpa perubahan.

```bash
# Cantumkan semua model embedding
GET /v1/embeddings
```

## Pembuatan Gambar

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Penyedia yang tersedia mencakup OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokal), ComfyUI (lokal).

`n` mengembalikan `n` gambar dalam `data[]`. Penyedia yang API upstream-nya mengembalikan satu gambar per panggilan
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) akan menerima `n` panggilan upstream terpisah, dengan maksimal 4 panggilan berjalan bersamaan. Nilai
`seed` tetap akan digeser berdasarkan indeks panggilan (`seed`, `seed + 1`, …), sehingga gambar yang dihasilkan berbeda tetapi tetap
dapat direproduksi. `n` dibatasi hingga 10. Permintaan secara keseluruhan akan gagal jika salah satu panggilan gagal. Daftar
format fan-out adalah `SINGLE_IMAGE_FANOUT_FORMATS` dalam
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux menggunakan kembali koneksi kunci API yang sudah ada dan menerima awalan `zenmux/` atau `zm/`:

- `zenmux/openai/gpt-image-2` menggunakan OpenAI Images API milik ZenMux. Opsi yang tersedia mencakup `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, dan `response_format`.
- Penerbit lain, seperti `zm/meta/muse-image-1.0`, menggunakan endpoint `:predict`
  Vertex AI milik ZenMux. `n` dipetakan ke `sampleCount`, `aspect_ratio` ke `aspectRatio`, dan `image_size`
  (`1K`, `2K`, `4K`) ke `sampleImageSize`. Nilai `size` dalam piksel hanya menentukan rasio aspek,
  bukan dimensi piksel yang dijamin. Rasio, resolusi, dan jumlah yang didukung berbeda-beda menurut model.
- `zm/inclusionai/ming-image-0.1-design` memilih dimensinya sendiri. Jangan sertakan `size`,
  `aspect_ratio`, dan `image_size`; nilai eksplisit akan menghasilkan HTTP 400. PNG, JPEG, dan WebP
  dapat diminta menggunakan `output_format`.

Integrasi ini mendukung pembuatan gambar dari teks, bukan pengeditan gambar referensi. Output Vertex
dinormalisasi menjadi `data[].b64_json`; `response_format: "url"` mengembalikan URL HTTPS upstream
atau URL data base64 ketika hanya byte gambar yang tersedia. Output kosong/terfilter
akan menghasilkan galat, bukan respons sukses kosong. Akses model bergantung pada akun ZenMux.
Lihat [API Vertex ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) dan
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Cantumkan semua model gambar
GET /v1/images/generations
```

## OCR Dokumen

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` memilih penyedia OCR melalui awalan `provider/model`; ID model tanpa awalan (misalnya
`mistral-ocr-latest`) akan diarahkan ke penyedia terdaftarnya, dan jika `model` tidak disertakan,
nilai default-nya adalah Mistral (`mistral-ocr-latest`). Penyedia terdaftar (`open-sse/config/ocrRegistry.ts`):

| ID penyedia                   | ID model             | Nilai `model`                                                         | Catatan                                                                                                      |
| ----------------------------- | -------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (atau `mistral-ocr-latest` tanpa awalan) | Sinkron — respons dikembalikan langsung dari satu panggilan upstream.                                        |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                           | Upstream asinkron (`analyze` + polling) — lihat di bawah.                                                    |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                               | Sinkron, melalui endpoint mitra `openapi/chat/completions` milik Vertex AI — lihat autentikasi/URL di bawah. |

Ketiga penyedia memberikan respons dalam format isi yang sama seperti Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Alur polling Azure Document Intelligence

API `analyze` Azure Document Intelligence bersifat asinkron: permintaan awal mengembalikan
header `Operation-Location`, bukan isi respons, dan hasilnya harus diperiksa melalui polling. Handler
(`open-sse/handlers/ocr.ts`) melakukan polling URL tersebut setiap detik hingga maksimal 30 percobaan, langsung gagal (tidak
melanjutkan polling) jika respons polling bukan `ok` atau statusnya `"failed"`, dan mengembalikan `504` jika
operasi masih berjalan setelah jatah percobaan habis. Respons akhir Azure
dinormalisasi ke dalam format `pages`/`markdown` yang sama dengan yang digunakan oleh Mistral sebelum dikembalikan kepada
pemanggil, sehingga kode klien tidak perlu menangani penyedia tersebut secara khusus.

### Autentikasi dan resolusi endpoint OCR DeepSeek Vertex AI

`vertex-deepseek-ocr` menggunakan kembali autentikasi Vertex AI yang sama dengan yang telah didukung OmniRoute untuk
lalu lintas percakapan/gambar (`open-sse/executors/vertex.ts`): kunci API koneksi dapat berupa
kredensial JSON Service Account (yang ditukarkan dengan token akses OAuth berumur pendek melalui alur JWT-bearer)
atau token akses OAuth yang sudah dibuat dan digunakan apa adanya. URL endpoint upstream adalah endpoint mitra
generik `openapi/chat/completions` milik Vertex, yang dibuat berdasarkan proyek dan
wilayah koneksi — `providerSpecificData.project`/`providerSpecificData.region` yang eksplisit selalu diprioritaskan;
jika tidak, proyek diperoleh dari `project_id` dalam JSON Service Account dan wilayah
secara default adalah `us-central1`. Kedua resolusi dilakukan dalam `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), lalu digunakan oleh
`src/app/api/v1/ocr/route.ts` sebelum diteruskan ke `handleOcr`.

## Daftar Model

```bash
GET /v1/models
Authorization: Bearer your-api-key

→ Mengembalikan semua model chat, embedding, dan gambar + combo dalam format OpenAI
```

### Prefiks id model (`?prefix=`)

Sebagian besar model ditampilkan menggunakan **prefiks penyedia**. Prefiks yang Anda dapatkan dikontrol oleh
flag fitur `MODELS_CATALOG_PREFIX_MODE`, dan dapat ditimpa **per permintaan** dengan
parameter kueri — berguna bagi klien yang menginginkan daftar bersih tanpa mengubah pengaturan
seluruh server untuk pengguna lain:

```bash
GET /v1/models?prefix=alias        # satu id per model — prefiks alias pendek
GET /v1/models?prefix=dual         # kedua bentuk (default server)
GET /v1/models?prefix=canonical    # hanya prefiks id penyedia lengkap
```

| Mode        | Menghasilkan                                              | Catatan                                                                                                                                                                                                        |
| ----------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **dan** `claude/claude-sonnet-4-6` | **Default.** Kedua id dirutekan ke model yang sama; dipertahankan agar konfigurasi klien yang menetapkan salah satu bentuk secara langsung tetap berfungsi. Kira-kira menggandakan ukuran katalog.             |
| `alias`     | `cc/claude-sonnet-4-6`                                    | Satu entri per model. Penyedia tanpa alias terpisah tetap menghasilkan entrinya, sehingga tidak ada yang hilang.                                                                                               |
| `canonical` | `claude/claude-sonnet-4-6`                                | Satu entri per model di bawah prefiks id penyedia lengkap. Penyedia tanpa alias terpisah (misalnya `antigravity/…`, `agy/…`) juga menghasilkan satu-satunya id mereka di sini, sehingga tidak ada yang hilang. |

Mirror mode `dual` juga dapat dikenali tanpa parameter kueri: mirror tersebut memiliki field `parent`
yang menunjuk ke id utama.

Klien yang merender pemilih model sebaiknya meminta `?prefix=alias` — inilah yang dilakukan oleh
[ekstensi OmniCopilot untuk VS Code](../guides/VSCODE-COPILOT.md).

### Filter penemuan (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` menerima filter penemuan opsional. Tanpa filter tersebut, respons
tidak berubah. Filter mempersempit katalog yang sudah dapat dilihat pemanggil (izin kunci API diterapkan terlebih dahulu),
dan dijalankan sebelum paginasi bergaya OpenAI `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # setiap kapabilitas yang dicantumkan harus bernilai benar
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` katalog; baris tanpa nilai tersebut dianggap `chat`
GET /v1/models?q=sonnet&limit=10                           # pencocokan tanpa membedakan huruf besar-kecil pada id atau nama
```

| Param         | Nilai                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | bilangan bulat nonnegatif, dibandingkan dengan `context_length`                                     |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 karakter                                                                                      |

Nilai yang tidak dikenal, atau `min_context` yang bukan bilangan bulat nonnegatif (misalnya `1.5`),
mengembalikan HTTP `400`, dan pesannya mencantumkan nilai yang valid. Implementasi:
`src/app/api/v1/models/catalogFilters.ts`.

### Daftar pendek model (`POST /v1/models/query`)

`POST /v1/models/query` mengembalikan daftar pendek deterministik dari katalog yang sama, dengan autentikasi
dan visibilitas per kunci yang sama seperti `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Setiap field bersifat opsional. `capabilities` dan `exclude` menerima array atau string yang dipisahkan koma;
`max_output` dibandingkan dengan `max_output_tokens`. Hasil diurutkan berdasarkan `owned_by`, lalu `id`.
Nilai default `limit` adalah `20`, dan nilai di atas `100` dibatasi menjadi `100`. JSON yang tidak valid, field yang tidak dikenal,
atau nilai yang tidak valid akan mengembalikan HTTP `400`.

### Model chat yang disembunyikan secara individual

Model yang ditandai **Tersembunyi** pada halaman penyedianya dikecualikan dari katalog dan ditolak
dengan HTTP `404` / `model_not_found` ketika diminta secara eksplisit. Pemeriksaan menggunakan
penyedia dan model yang telah diresolusikan, termasuk alias penyedia, prefiks node penyedia yang kompatibel, dan
default koneksi. Combo melewati target tersembunyi dan dapat menggunakan model lain yang terlihat; ketika tidak ada
target yang dapat dieksekusi, combo mengembalikan kode kesalahan yang sama. Menampilkan kembali model mulai berlaku pada
permintaan berikutnya. Penimpaan visibilitas khusus gambar tidak menyembunyikan model chat dengan ID yang sama.

Pengaturan model individual ini terpisah dari
[daftar izinkan/tolak eksposur model](../routing/MODEL_EXPOSURE_LIST.md), yang memfilter penayangan katalog
dan kandidat perutean otomatis sambil tetap mempertahankan pengiriman eksplisit. Izin model kunci API
tetap berlaku secara independen. Mode prefiks katalog default tetap `dual`.

### Varian model tanpa pemikiran

Untuk model Claude yang mendukung pemikiran, `/v1/models` juga menampilkan varian **tanpa pemikiran** yang id-nya diawali dengan `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Memilih id ini (misalnya dalam konfigurasi Claude Code yang selalu menyertakan blok `thinking`) akan di-resolve kembali ke `<provider>/<model>` yang sebenarnya dengan penalaran dinonaktifkan — `thinking:{type:"disabled"}` pada jalur `/v1/messages`, atau kolom `reasoning`/`reasoning_effort` dihapus pada jalur `/v1/chat/completions`. Varian ini hanya dicantumkan untuk model keluarga Claude yang mendukung thinking **dan** mematuhi `disabled` (sehingga, misalnya, model adaptive-only yang menolak `disabled` tidak disertakan). Operator dapat mengaktifkan atau menonaktifkan varian secara paksa untuk setiap model melalui `ModelSpec.noThinkingAlias`.

| ------ | --------------------------- | -------------------------------------------- | --------------------------- |
| POST   | `/v1/sound-generation`      | Byte audio native                            | `elevenlabs`                |
| POST   | `/v1/music`                 | Byte audio native                            | `music`                     |
| POST   | `/v1/music/stream`          | Byte audio streaming                         | `music`                     |
| POST   | `/v1/music/detailed`        | Audio multipart native dan rencana komposisi | `music`                     |
| POST   | `/v1/music/detailed/stream` | Metadata SSE native dan potongan audio       | `music`                     |
| POST   | `/v1/music/plan`            | Rencana komposisi JSON                       | `music`                     |

Endpoint ini melengkapi rute `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}`, dan `/v1/speech-to-text` yang sudah ada. Kolom JSON native
dan parameter kueri seperti `output_format` dan `enable_logging` dipertahankan.
Respons `/v1/music/detailed` mempertahankan batas multipart-nya; uraikan sebagai multipart.
`/v1/music/detailed/stream` mengembalikan `text/event-stream` dengan metadata komposisi dan
potongan audio base64 dalam peristiwa SSE. Keenam rute mendukung preflight CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Efek suara singkat. Durasi: 0,5 hingga 30 detik.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Durasi musik dinyatakan dalam milidetik: 3000 hingga 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Gunakan `/v1/music/stream` dengan isi JSON yang sama untuk pengiriman audio secara bertahap. Komposisi
menerima tepat salah satu dari `prompt` atau `composition_plan`; `/v1/music/plan` memerlukan `prompt`
dan secara opsional menerima `source_composition_plan`. Skema native mempertahankan kolom penyedia
tambahan agar versi rencana komposisi dan opsi penyempurnaan dapat diteruskan ke ElevenLabs.

Endpoint terpadu `/v1/music/generations` juga menerima `elevenlabs/music_v1`,
`elevenlabs/music_v2`, dan `elevenlabs/music_v2_5`. Dengan koneksi ElevenLabs yang aktif,
model-model ini ditampilkan dalam katalog musik. Endpoint ini mengembalikan
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Kolom `duration` dinyatakan dalam
detik dan dipetakan ke `music_length_ms`; nilai `music_length_ms` yang diberikan secara eksplisit diprioritaskan.
`instrumental` dipetakan ke `force_instrumental`, dengan kolom native diprioritaskan.
Gunakan endpoint streaming native untuk streaming dan endpoint komposisi native
untuk permintaan yang hanya didasarkan pada rencana komposisi.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Pembatasan endpoint, model, anggaran, dan koneksi diterapkan sebelum panggilan upstream. Rute native
mengembalikan kode status dan isi kesalahan upstream tanpa perubahan, termasuk `402` untuk pembatasan
paket dan `429` untuk batas kuota. Header `character-cost`, `song-id`, `request-id`, dan `retry-after`
dipertahankan jika tersedia. Saldo kredit gratis tidak menjamin akses ke setiap
model musik, format output, atau fitur API: ElevenLabs menentukan hak akses untuk setiap permintaan.
Endpoint terpadu mempertahankan kode status kesalahan dalam amplop kesalahan OmniRoute yang dinormalisasi.

Kontrak upstream: [efek suara](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[komposisi musik](https://elevenlabs.io/docs/api-reference/music/compose), dan
[detail musik streaming](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **Node penyedia rerank:** `POST /v1/rerank` juga merutekan ke node penyedia yang kompatibel dengan OpenAI
> (oMLX, vLLM, Infinity, TEI di belakang gateway, …) yang dialamatkan sebagai `<node-prefix>/<model>`. Node
> loopback (`localhost`, `127.0.0.1`, `172.16.0.0/12`) selalu memenuhi syarat, begitu pula nama host yang
> dicantumkan operator dalam `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (misalnya nama layanan Docker/Compose
> seperti `http://reranker:8080/v1`; node ini dipanggil secara langsung, tidak pernah melalui `HTTP(S)_PROXY`
> atau proksi yang disematkan pada koneksi). Node pada host lain mana pun
> — perangkat LAN atau peer Tailscale — hanya memenuhi syarat jika operator mengaktifkan flag fitur
> `RERANK_REMOTE_PROVIDER_NODES` **dan** URL dasar node tersebut lolos kebijakan URL keluar penyedia
> (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Langkah rerank mesin memori memanggil rute ini melalui
> loopback, sehingga aturan yang sama berlaku untuk `rerankProviderModel` dalam pengaturan Memori.
>
> **Bentuk server lokal:** node dipanggil di `<base>/v1/rerank` dan, jika menerima 404, di `<base>/rerank`
> (Infinity, TEI). Isi permintaan upstream memuat ejaan Cohere/OpenAI (`documents`,
> `return_documents`) dan ejaan TEI (`texts`, `return_text`), sedangkan respons upstream
> dinormalisasi ke dalam amplop Cohere: array mentah TEI `[{index, score, text}]`, `{results: [{index, score}]}`
> dari gateway sederhana, dan `{data: [...]}` bergaya Voyage semuanya dikembalikan kepada klien sebagai
> `{results: [{index, relevance_score, document?}]}`, diurutkan berdasarkan skor dan dibatasi hingga `top_n`.

> **Penemuan node penyedia:** model pada node penyedia yang kompatibel dengan OpenAI muncul di `GET /v1/models`
> di bawah prefiks node. Baris yang tidak memiliki metadata endpoint (umumnya pada daftar `/v1/models` lokal)
> mewarisi `apiType` milik node, sehingga model milik node `embeddings` memiliki `type: "embedding"` dan model
> milik node `rerank` memiliki `type: "rerank"`, alih-alih menggunakan chat sebagai nilai default; nilai
> `supportedEndpoints` eksplisit pada baris yang disinkronkan atau ditambahkan secara manual tetap diprioritaskan.

### `provider_options` Exa dan Tavily

Exa dan Tavily membaca kolom khusus penyedia dari wadah dengan namespace:
`provider_options.exa` (atau `provider_options["exa-search"]`) dan `provider_options.tavily`
(atau `provider_options["tavily-search"]`). Hanya kunci di bawah ini yang diteruskan. Masing-masing
diperiksa terhadap skema Zod-nya sendiri di `open-sse/handlers/search/providerOptionsPassthrough.ts`,
dan kunci dengan tipe yang salah akan dihapus. Kunci lainnya diabaikan, termasuk autentikasi, URL dasar,
`stream`, dan `outputSchema`. Kunci datar yang digunakan oleh penyedia lain (`cx`, `depth`, ...) tetap berfungsi
seperti sebelumnya.

| Penyedia | Kolom tingkat atas                                                                                                                                                                                                                                                                                                                                                        | Bersarang                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa      | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (primitif datar), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                               | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` digabungkan di atas nilai default `{ text: true, highlights: true }` |
| Tavily   | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                           |

Kolom generik selalu diprioritaskan: `query`, `max_results`, `filters` (domain), `country`, dan
topik yang diturunkan dari `search_type`. Pada Exa, `search_type: "news"` mempertahankan `category: "news"`.
Tavily juga menerima `search_type: "finance"` (`topic: "finance"`).

`time_range` generik kini diteruskan ke kedua penyedia: Exa menerima `startPublishedDate` (stempel waktu
ISO) dan Tavily menerima `start_date` (`YYYY-MM-DD`). Tanggal eksplisit dalam `provider_options`
menggantikan tanggal hasil pemetaan.

Hasil Exa mempertahankan `id`, `highlight_scores`, `summary`, `subpages`, `entities`, dan `extras` dalam
`provider_raw`. Hasil Tavily mempertahankan `images` dan `favicon`.

Penghitungan biaya tetap menggunakan registri datar `costPerQuery`. Tavily mengenakan
lebih banyak kredit per panggilan untuk `search_depth: "advanced"`, dan perbedaan tersebut tidak tercermin dalam
`usage.search_cost_usd`.

## Web Fetch API

Ekstrak konten dari URL melalui penyedia web-fetch yang telah dikonfigurasi (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, menggunakan API key yang sama dengan Parallel Search) hanya
mengembalikan Markdown — `format` lainnya akan menghasilkan `400` — dan membatasi konten hingga 100.000 karakter. Jika
halaman target itu sendiri tidak dapat diekstrak, upstream melaporkannya di dalam HTTP 200;
OmniRoute menampilkannya sebagai `422` dengan pesan tetap.

| Metode | Jalur           | Deskripsi                                                      |
| ------ | --------------- | -------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Mengambil/scrape URL — body divalidasi oleh `v1WebFetchSchema` |

**Autentikasi:** Bearer API key (`extractApiKey` + `isValidApiKey`). Kebijakan diberlakukan melalui `enforceApiKeyPolicy`.

**Fallback yang mempertimbangkan kuota (#8297):** jika `provider` tidak diberikan secara eksplisit, pool
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) akan
ditelusuri dalam urutan
prioritas tetap (fill-first) — penyedia yang dikonfigurasi tetapi terkena pembatasan laju akan dilewati
alih-alih langsung menghentikan permintaan, dan kegagalan upstream yang dapat dicoba ulang/terkait kuota
(HTTP 429 selalu; 402/403 untuk paket gratis bergaya kuota Firecrawl/Tavily/TinyFish —
tidak untuk Jina Reader, dan tidak pernah untuk permintaan buruk 400 biasa) akan beralih ke
penyedia berikutnya yang belum dicoba dan memiliki kredensial pada saat permintaan berlangsung. Ketika setiap penyedia dalam
pool telah habis, endpoint mengembalikan satu `429` (dengan header `Retry-After`)
alih-alih `400` generik sebelumnya. Ketika `provider` eksplisit
diminta, **tidak ada** fallback diam-diam — penyedia eksplisit yang terkena pembatasan laju atau gagal
akan menampilkan error-nya sendiri (`429` jika terkena pembatasan laju, jika tidak maka status
upstream).

## Streaming WebSocket

```bash
GET /v1/ws?handshake=1
```

Memvalidasi handshake upgrade WebSocket dan mengembalikan pesan contoh protokol wire (`request`, `cancel`). Frame WS aktual ditangani oleh server WS bawaan di luar tabel rute Next.js.

**Autentikasi:** Bearer API key selama handshake.

### Responses API melalui WebSocket (khusus codex)

```bash
# Host:port yang sama dengan API HTTP (default 20128); upgrade koneksi:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (atau: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Frame pertama HARUS berupa response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy Responses-API-over-WebSocket terhubung **secara eksklusif ke `codex`** (backend ChatGPT).
Proxy ini mendengarkan pada port yang sama dengan API/dashboard di jalur `/v1/responses`,
`/responses`, dan `/api/v1/responses`. Pada frame `response.create` pertama, proxy ini
melakukan autentikasi + persiapan melalui bridge internal `codex-responses-ws`, memilih
koneksi OAuth codex, dan membuat tunnel ke `wss://chatgpt.com/backend-api/codex/responses`
melalui transport `wreq-js`. **Model non-codex ditolak** (`codex_ws_provider_required`).
Untuk perutean berbagi kuota, gunakan `model: "qtSd/<group>/codex/<model>"`. Diimplementasikan dalam
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentikasi:** Bearer API key selama handshake. Server HTTP bawaan (`server-ws.mjs`)
harus menjadi entrypoint aktif (dan memang demikian secara default ketika `app/server-ws.mjs` tersedia).

#### ID model: gunakan ID ChatGPT polos (tanpa prefiks `codex/`)

**Codex CLI** OpenAI memvalidasi nama model di sisi klien ketika
`supports_websockets = true` dan **menolak ID berprefiks penyedia** seperti
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Kirim ID **polos** (misalnya `gpt-5.5`). Bridge OmniRoute
khusus codex, sehingga bridge tersebut me-resolve ulang ID polos sebagai model codex
(`resolveCodexWsModelInfo`) sebelum membuat tunnel ke upstream — meskipun
`gpt-5.5` polos seharusnya dirutekan ke penyedia lain melalui HTTP.

#### Mengonfigurasi OpenAI Codex CLI

Arahkan Codex CLI ke OmniRoute dengan menambahkan penyedia kustom yang mendukung WebSocket
ke `~/.codex/config.toml` (gunakan `CODEX_HOME` terpisah agar tidak mengubah
konfigurasi yang sudah ada):

```toml
model = "gpt-5.5"                 # bare id — NOT "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # no trailing slash; the WS URL is derived (use https/wss in production)
wire_api = "responses"                    # only supported value since Feb 2026
supports_websockets = true                # enables the Responses-over-WS transport
env_key = "OMNIROUTE_API_KEY"             # holds the OmniRoute API key (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # API key OmniRoute (key apa pun jika REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI meng-upgrade `base_url + /responses` menjadi WebSocket dan OmniRoute membuat tunnel
ke koneksi OAuth codex yang dipilih. Telah divalidasi secara end-to-end terhadap server
lokal: ChatGPT mengembalikan `codex.rate_limits` + `response.created` dan melakukan streaming
penyelesaian.

## Penggunaan layanan mandiri (`/api/usage/om-usage`)

Setiap kunci API dapat membaca penggunaan dan kuotanya **sendiri** — tanpa autentikasi manajemen. Ini adalah endpoint yang
digunakan klien (CLI, panel OmniCopilot) untuk menampilkan pengeluaran pemegang kunci.

```bash
# Bentuk teks (kontrak historis — teks biasa untuk terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Bentuk terstruktur — yang digunakan oleh UI
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kunci tersebut harus mengaktifkan **`allowUsageCommand`** (dinonaktifkan secara default — pengelola kunci API di dasbor
mengaktifkan atau menonaktifkannya untuk setiap kunci). Tanpanya, endpoint merespons dengan `403`.

`?format=json` mengembalikan bentuk terdiskriminasi sehingga pemanggil tidak pernah membaca bidang data dari sebuah
penolakan. Saat berhasil:

```jsonc
{
  "allowed": true,
  // hanya ada ketika kunci memilih untuk menggunakan batas penggunaan per kunci (USD harian/mingguan):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // snapshot kuota penyedia yang dipilih, atau null ketika belum ada yang di-cache:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // snapshot setiap koneksi, sehingga UI dapat merender beberapa penyedia secara berdampingan:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Saat ditolak (`401` kunci salah / `403` tidak diizinkan), rute yang sama mengembalikan
`{ "allowed": false, "error": { "message": "…" } }` — `personal`/`provider` yang ada tetapi kosong
(kunci diizinkan, tetapi belum ada informasi yang diperoleh) merupakan status yang berbeda dari penolakan, dan hanya bentuk JSON
yang dapat membedakannya.

**Autentikasi:** kunci API Bearer milik pemanggil sendiri, divalidasi dengan `isValidApiKey` — ini _bukan_
antarmuka manajemen (`/api/keys/…`), yang tetap dilindungi oleh `requireManagementAuth`.

### Persentase Kuota Mentah vs. yang Disesuaikan dengan Batas Penghentian

Saat menggunakan `/api/usage/om-usage`, pemanggil perlu memperhatikan perbedaan antara
persentase yang ditampilkan oleh **output teks biasa** dan **output JSON** terstruktur:

| Aspek                            | Format teks biasa (`/api/usage/om-usage` / `@@om-usage`)                                                                 | Format JSON (`?format=json`)                                             |
| :------------------------------- | :----------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------- |
| **Bidang output**                | `NN% left` (misalnya, `20% left`)                                                                                        | `provider.quotas` / `providers[].quotas`                                 |
| **Pengukuran**                   | **Jatah yang dapat digunakan setelah penyesuaian batas penghentian**: kapasitas tersisa di atas ambang batas penghentian | **Kuota upstream mentah**: pengukuran penyedia yang tidak disesuaikan    |
| **Penskalaan batas penghentian** | Diskalakan melalui `effectiveRemainingPercent()` sehingga cadangan yang dilindungi terbaca sebagai `0% left`             | Tidak ada (nilai snapshot mentah seperti yang dilaporkan oleh penyedia)  |
| **Data ambang batas**            | Diperhitungkan dalam persentase yang ditampilkan                                                                         | Disimpan dalam `quotaWindowThresholds` per koneksi (atau default server) |
| **Pengguna utama**               | CLI interaktif, prompt terminal, operator manusia                                                                        | Integrasi terprogram, dasbor, analitik, pelacak penagihan                |

#### Rumus Penyesuaian Batas Penghentian

OmniRoute mendukung batas penghentian kuota proaktif untuk mencegah kehabisan kuota upstream (dikonfigurasi melalui
`quotaWindowThresholds` koneksi, default penyedia, atau pengaturan ketahanan global). Ketika ambang batas penghentian
(misalnya, `cutoff = 25%`) aktif pada jendela kuota, perender teks menghitung jatah tersisa sebagai berikut:

- Jika `remaining <= cutoff`: mengembalikan `0%`.
- Jika `remaining > cutoff`: mengembalikan `((remaining - cutoff) / (100 - cutoff)) * 100`.

Output teks yang diformat membulatkannya ke bilangan bulat terdekat (`Math.round(...)`).

#### Contoh Ilustratif

Pertimbangkan jendela penyedia dengan **penggunaan mentah 60%** (sehingga **kuota mentah tersisa 40%**) dan ambang batas
**penghentian pada 25% kuota tersisa** yang dikonfigurasi:

| Representasi                     | Perhitungan                                        | Tersisa |             Penggunaan Tersirat             |
| :------------------------------- | :------------------------------------------------- | :-----: | :-----------------------------------------: |
| **JSON mentah (`?format=json`)** | Snapshot upstream (`quotas[window]`)               | **40%** |                   **60%**                   |
| **Format teks (`NN% left`)**     | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (jika menghitung `100 - remaining`) |

- **Mengapa teks menampilkan 20% tersisa:** Dari 40% kuota fisik yang tersisa pada akun, 25% dicadangkan oleh
  kebijakan batas penghentian. Pemanggil hanya memiliki 15% dari 75% ruang kapasitas yang dapat digunakan sebelum router berhenti
  merutekan ke koneksi ini. Penskalaan memastikan koneksi menandakan kehabisan (`0% left`) tepat ketika
  perutean dihentikan.
- **Mengapa JSON mempertahankan nilai mentah:** Payload JSON mengembalikan snapshot penyedia yang tepat (`UsageSnapshot`)
  sehingga alat eksternal memiliki akses ke pemanfaatan upstream yang sebenarnya dan
  `quotaWindowThresholds` tingkat koneksi tanpa penskalaan lossy di sisi server.

#### Panduan Migrasi Pengguna

Jika integrasi eksternal (seperti plugin editor atau ekstensi agen) sebelumnya mengambil teks dari
endpoint (`NN% left`) dan menghitung persentase penggunaan sebagai `100 - NN`, migrasi ke `?format=json` berarti:

- Membaca nilai JSON mentah akan mencerminkan **konsumsi upstream yang sebenarnya** (60% digunakan dalam contoh di atas).
- Jika integrasi ingin mempertahankan semantik jatah yang dapat digunakan dari endpoint teks, integrasi tersebut dapat mengevaluasi
  rumus sisa efektif di sisi klien menggunakan `quotaWindowThresholds` untuk penggantian pada tingkat koneksi.

## Cache Semantik

```bash
# Dapatkan statistik cache
GET /api/cache/stats

# Hapus semua cache
DELETE /api/cache/stats
```

Contoh respons:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Dampak latensi

HIT pada cache semantik menyajikan respons dari cache **tanpa panggilan ke
upstream**, sehingga `X-OmniRoute-Response-Latency` yang dilaporkan mendekati nol
(terlepas dari latensi upstream asli). Klien yang sensitif terhadap latensi
(benchmarking, pemantauan p50/p99) harus memeriksa header respons
`X-OmniRoute-Cache-Latency`:

| Nilai         | Arti                                                             |
| ------------- | ---------------------------------------------------------------- |
| `synthetic`   | Respons disajikan dari cache; latensi bukan waktu upstream nyata |
| _(tidak ada)_ | Respons dari panggilan upstream nyata                            |

### Melewati cache per kunci

Kunci API dapat memilih untuk tidak melakukan pembacaan cache semantik melalui `cacheDefaultMode`:

| Nilai    | Perilaku                                                 |
| -------- | -------------------------------------------------------- |
| `legacy` | Perilaku cache normal (default)                          |
| `bypass` | Lewati pencarian cache sepenuhnya; selalu akses upstream |

Atur saat membuat kunci (`POST /api/keys`) atau memperbaruinya (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Melewati cache per permintaan

Permintaan apa pun dapat melewati cache terlepas dari pengaturan kunci:

```
X-OmniRoute-No-Cache: true
```

Untuk model yang disinkronkan/diimpor, `PUT /api/provider-models` menerima `provider`, `modelId`, dan
`maxOutputTokenOverride`: bilangan bulat positif menetapkan batas token keluaran manual, sedangkan `null`

nilai-nilai ini dalam `modelOutputOverrides`, termasuk model tanpa baris model khusus. Penggantian tersebut
menggunakan kapabilitas runtime `max_output_tokens` dan tetap berlaku setelah sinkronisasi ulang model. Halaman
penyedia yang kompatibel dengan OpenAI menawarkan kontrol edit/hapus yang sama dan menandai model dengan dukungan visi eksplisit.

Node Chat Completions khusus menyesuaikan penolakan eksplisit atas penalaran untuk backend upstream. Pengujian
koneksi yang berhasil secara otomatis memilih kontrol templat chat untuk setiap ID model yang sama persis
dan entri `/models`-nya membuktikan nilai `owned_by` yang dikenali: `vllm`, `sglang`, atau `llamacpp`.
Wrapper transparan yang kompatibel dengan OpenAI dapat mempertahankan entri model asli di dalam objek
`openai` bertingkat; deteksi mengikuti hingga tiga lapisan pembungkus tersebut. Model dengan kepemilikan yang
tidak ada, tidak dikenal, atau bertentangan akan tetap menggunakan perilaku OpenAI biasa. Deteksi menggunakan
kembali permintaan katalog yang sudah ada, tidak menghasilkan token penyelesaian, dan dibatalkan ketika endpoint koneksi berubah.

Untuk menetapkan perilaku tersebut bagi backend yang tidak mengekspos metadata itu, gunakan API pembaruan
parsial penyedia yang sudah ada:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Kirim isi tersebut dengan `PUT /api/providers/<connection-id>`. Pada koneksi itu, upaya
penalaran eksplisit sebesar `none` dikirim sebagai `chat_template_kwargs.thinking=false` dan
`chat_template_kwargs.enable_thinking=false`. Nilai templat native yang eksplisit tetap menjadi acuan utama,
kecuali aturan penalaran sisi server memaksakan suatu tingkat upaya. Pengaturan ini hanya berlaku ketika koneksi
khusus yang kompatibel dengan OpenAI mengirimkan isi Chat Completions; permintaan Responses dan penyedia biasa
tetap mempertahankan bentuk permintaan native masing-masing. Atur `reasoningControl` ke `openai` untuk memaksakan
penerusan `reasoning_effort` OpenAI biasa, atau hilangkan/atur ke `null` untuk menggunakan deteksi otomatis.

Permintaan pengklasifikasi mode otomatis Claude Code secara bawaan menonaktifkan pemikiran native ketika
tidak berisi kontrol penalaran eksplisit. Deteksi menggunakan penanda sistem pengklasifikasi dalam permintaan
berformat Claude, bukan nama model atau batas penyelesaian. Kontrol isi eksplisit, header upaya/pemikiran yang
didukung, aturan perutean, dan upaya model yang telah ditentukan tetap mempertahankan prioritas yang ada.
Kedua tahap pengklasifikasi mempertahankan prompt, batas penyelesaian, urutan penghentian, dan keputusan izin
upstream yang sebenarnya; tahap kedua tetap dapat menghasilkan penalaran terlihat yang diminta sebagai teks biasa.

### Versi dan Kanal Rilis

```bash
GET /api/system/version
```

Rute manajemen khusus loopback (autentikasi admin). Mengembalikan versi yang sedang berjalan, versi terbaru yang dipublikasikan, dan status pembaruan otomatis. `releaseChannel` dan `channels` adalah bidang tambahan (rail 3.8.54); `channel` tetap memiliki arti yang sama — mode deployment yang digunakan pembaru dasbor (`npm`, `source`, atau `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — kanal npm dari build yang sedang berjalan: `nightly` untuk versi `-nightly.*`,
  `next` untuk pra-rilis lainnya (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` untuk versi stabil dari
  versi mayor yang lebih lama daripada `channels.latest`, dan `latest` untuk kondisi lainnya. Aturannya sama dengan
  `scripts/release/dist-tag.mjs`, yang memilih dist-tag npm saat publikasi.
- `channels` — versi terdepan yang dipublikasikan dari setiap dist-tag, dari `npm view omniroute dist-tags` (dengan fallback
  HTTP registry), di-cache dengan TTL 10 menit yang sama seperti `latest`. `latest` selalu tersedia
  (melakukan fallback ke bidang `latest`, lalu `"unavailable"`); `next`, `nightly`, dan `lts` muncul
  hanya jika dist-tag tersebut tersedia. Permintaan `Cache-Control: no-cache` menyegarkan kedua pencarian.

Model kanal (`latest` = v3 hingga GA 4.0, `next` = rc, `nightly` = build `develop`,
`lts` = patch v3 setelah GA 4.0) dijelaskan dalam `docs/ops/RELEASE_STRATEGY.md`.

## Alias VS Code Bertoken / Tanpa Header

Gunakan alias ini ketika integrasi tidak dapat menyisipkan header `Authorization` dan memerlukan kunci API yang disematkan dalam URL dasar.

```bash
# Alias katalog bergaya OpenAI
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# Alias chat bergaya OpenAI
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Alias bergaya Ollama
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

Contoh:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models

  -H "Content-Type: application/json" \
```

Catatan:

- Alias bertoken menggunakan kembali handler yang sama seperti `/v1/*` dan `/api/tags`; bentuk respons tetap identik.
- Utamakan `Authorization: Bearer ...` apabila klien mendukung header khusus.
- Token berbasis URL dapat muncul dalam log reverse proxy, riwayat browser, dan telemetri di luar OmniRoute. Perlakukan token tersebut sebagai opsi kompatibilitas, bukan mode autentikasi default.

## Batas Token

Anggaran **token** per kunci API (berbeda dari Anggaran berbasis USD di atas). Diberlakukan langsung pada jalur permintaan: ketika penggunaan dalam jendela saat ini untuk suatu kunci mencapai batasnya, permintaan akan ditolak dengan `429 Too Many Requests`. Batas dapat dicakupkan ke `model` tertentu, `provider`, atau diterapkan secara `global` di seluruh kunci; ketika beberapa batas cocok dengan suatu permintaan, batas yang paling ketat akan berlaku.

```bash
# Cantumkan batas token suatu kunci (termasuk penggunaan jendela secara langsung)
GET /api/usage/token-limits?apiKeyId=key-123

# Buat atau perbarui batas token
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Hapus batas token berdasarkan id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Catatan skema** (`setTokenLimitSchema`): `apiKeyId` dan `scopeType` (`model` | `provider` | `global`) wajib diisi. `scopeValue` wajib diisi kecuali jika `scopeType` adalah `global` (misalnya id model untuk cakupan `model`, atau id penyedia untuk cakupan `provider`). `tokenLimit` harus berupa bilangan bulat positif (dikonversi dari string). Opsional: `id` (hilangkan untuk membuat, sertakan untuk memperbarui), `resetInterval` (`daily` | `weekly` | `monthly`, nilai default `monthly`), `resetTime` (`HH:MM`), `enabled` (nilai default `true`). Respons `GET` melengkapi setiap batas dengan `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, dan `nextResetAt`. Ini adalah endpoint kelas manajemen (autentikasi diberlakukan secara terpusat oleh pipeline otorisasi).

## Pemrosesan Permintaan

1. Klien mengirim permintaan ke `/v1/*`
2. Penangan rute memanggil `handleChat`, `handleEmbedding`, `handleAudioTranscription`, atau `handleImageGeneration`
3. Model di-resolve (penyedia/model langsung atau alias/kombo)
4. Kredensial dipilih dari DB lokal dengan pemfilteran ketersediaan akun
5. Untuk chat: `handleChatCore` memeriksa cache semantik/tanda tangan dan me-resolve pengaturan kompresi kombo
6. Kompresi proaktif dijalankan sebelum penerjemahan penyedia ketika diaktifkan (`lite`, Caveman, RTK, atau bertumpuk)
7. Eksekutor penyedia mengirim permintaan upstream
8. Respons diterjemahkan kembali ke format klien (chat) atau dikembalikan apa adanya (embedding/gambar/audio)
9. Penggunaan, analitik kompresi, dan log permintaan dicatat
10. Fallback diterapkan saat terjadi kesalahan sesuai dengan aturan kombo

Referensi arsitektur lengkap: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Ketahanan (lanjutan)

OmniRoute menyediakan tiga mekanisme kegagalan sementara yang independen; endpoint pengelolaan di bawah ini memungkinkan operator membaca dan menimpanya:

| Cakupan             | Penyimpanan status                       | Baca                                      | Atur ulang / hapus                                           |
| ------------------- | ---------------------------------------- | ----------------------------------------- | ------------------------------------------------------------ |
| Pemutus provider    | `domain_circuit_breakers` + dalam memori | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                 |
| Masa tunggu koneksi | `rateLimitedUntil` pada koneksi provider | `/api/rate-limits`, `/api/providers/[id]` | (diaktifkan kembali secara lazy; hapus melalui PUT provider) |
| Penguncian model    | Registri ketersediaan model dalam memori | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                     |

`PATCH /api/resilience` menerima penimpaan pemutus provider di bawah `providerBreaker.oauth` dan `providerBreaker.apikey`. Setiap profil mendukung `degradationThreshold`, `failureThreshold`, dan `resetTimeoutMs`; bidang yang sama tersedia di Dasbor → Pengaturan → Ketahanan.

```bash
# Hapus satu penguncian model
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Hapus semua penguncian
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Referensi konseptual lengkap dan nilai default pemutus: lihat [`CLAUDE.md`](../../CLAUDE.md) → "Status Runtime Ketahanan" dan [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Antrean Batas Laju & Jaring Pengaman Pengaktifan Otomatis

- **Jalur tulis yang didukung**: `POST /api/rate-limits` dengan body `{"connectionId": "<id>", "enabled": true|false}` adalah endpoint pengelolaan yang didukung untuk mengaktifkan atau menonaktifkan perlindungan batas laju bagi sebuah koneksi. `PUT /api/providers/[id]` sengaja tidak mengubah atau membalikkan `rateLimitProtection` (#11278).
- **Semantik `enabled: false`**: Menetapkan `enabled: false` akan menghapus perlindungan eksplisit untuk koneksi tersebut, tetapi **tidak** mengecualikan koneksi API-key aktif dari jaring pengaman pengaktifan otomatis global (`autoEnableApiKeyProviders = true`). Dalam `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` dan `undefined` setara; koneksi API-key aktif tanpa perlindungan eksplisit tetap terlindungi oleh jaring pengaman pengaktifan otomatis.
- **Penonaktifan global**: Untuk menjalankan koneksi API-key tanpa antrean batas laju, nonaktifkan jaring pengaman secara global melalui `RATE_LIMIT_AUTO_ENABLE=false` (env) atau `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Pengaturan → Ketahanan / `PATCH /api/resilience`).

## Server MCP

OmniRoute dilengkapi dengan server Model Context Protocol tertanam yang memiliki 3 transport (stdio, SSE, streamable-http) dan alat dengan cakupan tertentu. Endpoint dasbor di bawah membaca data status/audit dan bertindak sebagai proksi untuk transport HTTP.

| Metode | Jalur | Deskripsi |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Heartbeat, transport, status online, panggilan terakhir, alat teratas, tingkat keberhasilan 24 jam |
| GET | `/api/mcp/tools` | Daftar alat MCP dengan `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Membuka stream SSE untuk transport SSE (mengembalikan `503` jika MCP dinonaktifkan atau transport tidak cocok) |
| POST | `/api/mcp/sse` | Mengirim frame JSON-RPC melalui transport SSE |
| GET | `/api/mcp/stream` | Membuka sisi SSE dari transport Streamable HTTP (pesan yang dimulai oleh server) |
| POST | `/api/mcp/stream` | Mengirim frame JSON-RPC melalui transport Streamable HTTP |
| DELETE | `/api/mcp/stream` | Mengakhiri sesi Streamable HTTP |
| GET | `/api/mcp/audit` | Mengkueri log audit — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Statistik audit agregat (total, tingkat keberhasilan, durasi rata-rata, alat teratas) |

**Autentikasi:** transport `sse`/`stream` menggunakan mekanisme autentikasi khusus MCP (kunci API Bearer dengan cakupan `mcp`); rute `status`/`tools`/`audit*` dapat dibaca dari dasbor (tidak memerlukan autentikasi tambahan selain akses ke host dasbor).

> Kedua transport HTTP dikendalikan oleh `settings.mcpEnabled` dan `settings.mcpTransport` — ketidakcocokan transport mengembalikan `400`, sedangkan status MCP yang dinonaktifkan mengembalikan `503`.

## Server A2A

OmniRoute menyediakan endpoint JSON-RPC 2.0 A2A (Agent-to-Agent) serta pembungkus REST untuk keperluan inspeksi/dasbor.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # opsional kecuali OMNIROUTE_API_KEY ditetapkan
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Metode yang didukung (semuanya bergantung pada `settings.a2aEnabled`):

| Metode           | Deskripsi                                                                  |
| ---------------- | -------------------------------------------------------------------------- |
| `message/send`   | Eksekusi keterampilan sinkron; mengembalikan `{task, artifacts, metadata}` |
| `message/stream` | Eksekusi SSE streaming untuk kumpulan keterampilan yang sama               |
| `tasks/get`      | Mengambil tugas berdasarkan `taskId`                                       |
| `tasks/cancel`   | Membatalkan tugas berdasarkan `taskId`                                     |

Keterampilan bawaan: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kartu Agen

```bash
GET /.well-known/agent.json
```

Mengembalikan kartu agen A2A publik (nama, deskripsi, kapabilitas, katalog keterampilan, skema autentikasi) — disimpan dalam cache publik selama 1 jam. Tidak memerlukan autentikasi.

### Pembantu REST

| Metode | Jalur                        | Deskripsi                                                                                                               |
| ------ | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Status aktif A2A + statistik tugas + ringkasan kartu agen yang disimpan dalam cache                                     |
| GET    | `/api/a2a/tasks`             | Mencantumkan tugas — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Tidak diimplementasikan sebagai pembantu REST — buat melalui JSON-RPC `message/send`)                                  |
| GET    | `/api/a2a/tasks/[id]`        | Mengambil satu tugas                                                                                                    |
| POST   | `/api/a2a/tasks/[id]/cancel` | Membatalkan tugas                                                                                                       |

**Autentikasi:** pembantu REST berjalan tanpa autentikasi manajemen (dapat dibaca oleh dasbor); rute JSON-RPC `/a2a` menggunakan Bearer `OMNIROUTE_API_KEY` jika dikonfigurasi.

## Autentikasi

Lihat [Autentikasi Manajemen](../guides/MANAGEMENT-AUTH.md) untuk empat
keluarga kredensial (sesi dasbor, token CLI lokal, Token Akses `oma_live_…`,
kunci API dengan cakupan manajemen) dan perbedaannya dari kunci inferensi.

- Rute dasbor (`/dashboard/*`) menggunakan cookie `auth_token`
- Login menggunakan hash kata sandi tersimpan; sebagai fallback, gunakan `INITIAL_PASSWORD`
- `requireLogin` dapat diaktifkan atau dinonaktifkan melalui `/api/settings/require-login`
- Rute `/v1/*` secara opsional memerlukan kunci API Bearer ketika `REQUIRE_API_KEY=true`
- "token manajemen" / "kunci API dengan cakupan manajemen" dalam referensi ini berarti salah satu keluarga dalam panduan tersebut — bukan jenis rahasia tambahan yang tidak didefinisikan

> **Perubahan yang merusak kompatibilitas (v3.8.0)** — `/api/v1/agents/tasks/*` dan endpoint manajemen cooldown kini memerlukan **autentikasi manajemen** (cookie `auth_token` dasbor atau kunci API dengan cakupan manajemen). Klien yang sebelumnya memanggil rute-rute ini tanpa autentikasi akan menerima `401 Unauthorized`. Lihat commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
