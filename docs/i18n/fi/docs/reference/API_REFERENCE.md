## Keskustelutäydennykset

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

| `x-omniroute-connection` | Pyyntö  | Kiinnitä yhden mallin pyyntö yhteen palveluntarjoajayhteyteen (tiliin) sen tunnuksen perusteella — katso [Tilikohtainen kiinnitys pyyntöä kohden](#account-pinning-per-request)                                                                                 |

#### Tilin kiinnittäminen pyyntökohtaisesti

Kun palveluntarjoajalla on useita yhteyksiä (tilejä tai avaimia), OmniRoute valitsee tavallisesti yhden
tilinvalintastrategiansa avulla. Pyynnön voi sen sijaan kiinnittää tiettyyn yhteyteen
`x-omniroute-connection`-otsakkeella:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Mistä tunnus löytyy.** Avaa palveluntarjoajan sivu hallintapaneelissa
  (**Hallintapaneeli → Palveluntarjoajat → <provider>**) ja napsauta yhteysrivillä olevaa `xxxxxxxx…`-tunnistekenttää
  — tällöin koko yhteystunnus kopioidaan.
- **Mitkä pyynnöt huomioivat sen.** Yhden mallin pyynnöt (`provider/model`) päätepisteissä
  `/v1/chat/completions`, `/v1/messages` ja `/v1/responses`. Yhdistelmät ohittavat otsakkeen: kiinnitä
  tili yhdistelmän kullekin vaiheelle vaiheen oman yhteyden kautta.
- **Kiinnitys on ehdoton, ei pelkkä suositus.** Vain kiinnitettyä yhteyttä käytetään. Pyynnön
  aikana tapahtuva virhe kirjaa tilille jäähdytysajan, mutta **ei** vaihda saman palveluntarjoajan
  rinnakkaiseen tiliin.
- **Jäähdytys ja kiintiö vapauttavat kiinnityksen.** Kun kiinnitetty yhteys on jäähdytystilassa,
  sen kiintiö on käytetty loppuun tai kiintiökäytäntö estää sen käytön, myöhemmät pyynnöt käyttävät varalla palveluntarjoajan
  muita yhteyksiä aivan kuten kiinnittämätön liikenne.
- **Tuntemattomat tai käytöstä poistetut tunnukset aiheuttavat virheen.** Tunnus, joka ei kuulu palveluntarjoajan aktiiviseen joukkoon (poistettu,
  deaktivoitu tai toiselle palveluntarjoajalle kuuluva), ei jätä yhtään kelvollista tiliä, joten pyyntö
  epäonnistuu sen sijaan, että se reititettäisiin huomaamatta muualle.

Claude Code lähettää mukautetut otsakkeet `ANTHROPIC_CUSTOM_HEADERS`-muuttujan kautta. Lisää se tiedoston `~/.claude/settings.json`
`env`-lohkoon tai projektitason `.claude/settings.json`-tiedostoon, jos haluat kiinnittää eri
tilin kullekin projektille:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Lähde: `src/sse/handlers/chat.ts` (otsakkeen lukeminen), `src/sse/services/auth.ts` ja
`src/sse/services/sessionAffinityPin.ts` (kiinnityksen vapauttaminen ja joukosta puuttumisen tarkistus).

> **Kustannustelemetrian otsakkeet:** suoratoistamattomat onnistuneet vastaukset sisältävät myös `X-OmniRoute-*`-kustannustelemetriajoukon — `X-OmniRoute-Response-Cost` (USD, kiinteästi 10 desimaalia; `0.0000000000` ilmaisille tai hinnoittelemattomille), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` ja `X-OmniRoute-Fallback-Attempts` (vain kun > 0) sekä `X-OmniRoute-Request-Id` ja `X-OmniRoute-Version`. Niitä tuottavat keskustelutäydennykset, `/v1/responses`, `/v1/messages` **sekä mediapäätepisteet** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` ja `/v1/moderations` (kustannus aina `0`). Median kustannus lasketaan modaliteettikohtaisesti (kuvaa, sekuntia, merkkiä tai hakuyksikköä kohden), kun hinnoittelu on saatavilla; muussa tapauksessa se on `0` (virhetilanteessa salliva).

> **Välimuistiosuman kustannussemantiikka:** semanttisen välimuistin OSUMAN (`X-OmniRoute-Cache-Hit: true`) yhteydessä ylävirran kutsua ei tehdä, joten `X-OmniRoute-Response-Cost` on `0.0000000000` (osuman palvelemisen **lisäkustannus**). Alkuperäinen tai ilman välimuistia syntynyt kustannus ilmoitetaan erikseen otsakkeessa `X-OmniRoute-Cost-Saved`. Laskutusta käsittelevien järjestelmien tulee laskea yhteen `X-OmniRoute-Response-Cost`-arvot (osumat eivät maksa mitään); välimuistianalytiikka voi koostaa `X-OmniRoute-Cost-Saved`-arvot.

## Yksinomaiset hallitut istuntovuokrat

Yksinomainen hallittu istuntovuokraus on valinnainen ja asiakasohjelmasta riippumaton reitityssopimus: yhdellä aktiivisella omistajalla on hallussaan yksi kelvollinen OmniRoute-yhteys. Se ei vuokraa mallia, edellytä OAuth-todennusta, yksilöi tiettyä asiakasohjelmaa eikä edellytä tiettyä palveluntarjoajaa.

Todennukseen käytettävällä API-avaimella on oltava oikeusalue `lease:exclusive` ja nimenomainen, ei-tyhjä `allowedConnections`-luettelo. Tietokannan mutaatioraja pakottaa molemmat kentät käyttöön yhdessä avainta luotaessa ja osittaisissa päivityksissä.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Onnistuneet hankinta-, uusinta- ja vapautusvastaukset tuovat näkyviin aikaleimat, `state`-arvon ja täsmällisen positiivisen `generation`-arvon, mutta eivät koskaan valittua yhteyttä tai tunnistetietoja. Uusinnassa ja vapautuksessa sukupolvi annetaan JSON-rungossa:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Aktiivisen vuokran omistaja voi erikseen pyytää yksityisyyden suojaavia näyttömetatietoja nykyisestä sidoksestaan:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Tämä valinnainen tilatoiminto eristetään yhdessä tietokantatransaktiossa läpinäkymättömällä omistajatunnisteella, todennetulla hallitulla API-avaimella ja täsmällisellä aktiivisella sukupolvella. `displayName` on ainoastaan määritetyn yhteysnimen ympäröivistä välilyönneistä siistitty versio; sen arvo on `null`, jos turvallista määritettyä nimeä ei ole. OmniRoute ei koskaan käytä sen sijaan sähköpostiosoitetta tai luotua tilin tunnistetta. Palveluntarjoajan arvo on ei-arkaluonteinen näyttönimi eikä koskaan luotu yhteensopivan palveluntarjoajan tunniste. Tunnistetiedot, tunnukset, evästeet, käsittelemättömät yhteys- tai API-avaintunnisteet, omistajatiivisteet, eristyssalaisuudet ja sisäiset reititystiedot jätetään pois.

Väärällä avaimella tai omistajalla tehdyt, vanhentuneen sukupolven sisältävät sekä puuttuvaan, vanhentuneeseen, vapautettuun tai mitätöityyn vuokraan kohdistuvat haut palauttavat kaikki saman `409 LEASE_FENCE_STALE`-virheen ilman yhteysmetatietoja. Kapasiteetin odotusvastauksen saaneella asiakasohjelmalla ei ole tarkasteltavaa aktiivista sidosta. Kun reititys siirtää aktiivisen vuokran, sama sukupolvi säilyy voimassa ja tila palauttaa atomisesti uuden sidoksen, ei koskaan vanhaa. Nykyiset asiakasohjelmat säilyvät muuttumattomina, koska hankinta-, uusinta-, vapautus- ja odotusvastausten aiemmat rakenteet säilyvät.

Tämä palvelinsopimus ei muuta OpenAI Codexin vakiomuotoista `/status`-toimintoa. Vakio-Codex ilmoittaa tällä hetkellä mallinsa palveluntarjoajan ja sisäänrakennetun todennus- ja tilitilan, mutta ei näytä mielivaltaisia mukautetun palveluntarjoajatilin metatietoja. Myöhemmän asiakasintegraation on kutsuttava tätä toimintoa ja päätettävä, miten `connection.displayName` näytetään.

Jokainen hallittu päättelypyyntö antaa tämän jälkeen molemmat ohjausotsakkeet:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Täsmällinen omistaja, sukupolvi, aktiivinen yhteys ja todennettu API-avain eristetään välittömästi ennen jokaista tuettua ylävirran yritystä. Omistajan ja sukupolven uudelleentoisto toisella avaimella epäonnistuu, vaikka kyseinen avain sallisi saman yhteyden. Käsittelemättömiä omistajatunnisteita ei tallenneta pysyvästi, kirjata lokiin, säilytetä pyynnön tilannevedoksessa eikä välitetä ylävirtaan.

Tilapäinen kilpailutilanne palauttaa HTTP-tilan `429`, `Retry-After`-otsakkeen ja seuraavan vastauksen:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Tämä vastaus tarkoittaa ainoastaan, että tavallinen kelvollisten yhteyksien joukko ei ollut tyhjä ja jokainen vapaa ehdokas oli vieraan aktiivisen vuokran hallussa. Ei-tuetut mallit tai palveluntarjoajat, käytäntöristiriidat, jäähdytysajat, kiintiöt, kuntotila ja muut tavalliset kelpoisuusvirheet säilyttävät nykyiset OmniRoute-vastauksensa.

### `x-omniroute-compression`

Pyyntökohtainen pakkaussuunnitelman ohitus. Korkein prioriteetti — ohittaa reititysyhdistelmän ohituksen, aktiivisen profiilin, automaattisen laukaisun ja paneelin oletusasetuksen. Arvot:

| Arvo          | Vaikutus                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `off`         | Tätä pyyntöä ei pakata.                                                                                                |
| `default`     | Paneelista johdettu oletusprofiili (aktiivinen profiili ohitetaan). Häviölliset moottorit eivät ole käytössä.          |
| `safe`        | Vain kaksoiskappaleiden poisto ja tyhjämerkkien yhdistäminen.                                                          |
| `allow-lossy` | Säilyttää operaattorin suunnitelman tässä pyynnössä, mukaan lukien yhteenvedot ja tyylin uudelleenkirjoitukset.        |
| `engine:<id>` | Yksittäinen moottori, kun se on käytössä, esimerkiksi `engine:rtk`. Kyseisen moottorin pyyntökohtainen käyttöönotto.   |
| `<combo>`     | Nimetty yhdistelmä, joka täsmätään ensin nimen perusteella kirjainkoosta riippumatta ja sitten tunnisteen perusteella. |

Huomautukset:

- Tuntemattomat arvot ohitetaan (pyyntöä ei koskaan hylätä); ratkaisu etenee normaaliin operaattorin prioriteettijärjestykseen.
- Jos useilla yhdistelmillä on sama nimi, anna yhdistelmän **tunniste** determinististä täsmäystä varten.
- Yhdistelmää, jonka nimi on `off` tai `default`, ei voi valita nimen perusteella (nämä avainsanat tulkitaan ensin); viittaa tällaiseen yhdistelmään sen tunnisteella.
- Pakkauksen pääkytkin on ehdoton portti: kun pakkaus on poistettu käytöstä yleisesti, tämä otsake ei voi ottaa sitä käyttöön.

Käytetty suunnitelma palautetaan vastausotsakkeessa:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

jossa `<source>` on jokin arvoista `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` tai `off`.

## Upotukset

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Saatavilla olevat palveluntarjoajat: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Luettelotunnukset ovat muotoa `provider/model` (esimerkki: `jina-ai/jina-embeddings-v5-omni-small`). Myös rekisterissä olevat Jina-mallien pelkät tunnukset (esimerkiksi `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) tunnistetaan. Jinan upotus-, uudelleenjärjestely-, luokittelu- ja segmentointitoiminnot käyttävät ensisijaisesti hallintapaneelin `jina-ai`-tunnistetietoja; `JINA_AI_API_KEY` toimii varavaihtoehtona vain, jos hallintapaneelin avainta ei ole. `jina-reader`-kortti on tarkoitettu vain Readerille / `r.jina.ai`-palvelulle (`POST /v1/web/fetch`), eikä se koskaan tarjoa upotuksia tai uudelleenjärjestelyä.

Rekisterimallit, jotka ilmoittavat tukevansa multimodaalisuutta, hyväksyvät myös enintään 32 palveluntarjoajasta riippumatonta rakenteista kohdetta. Mediakohteiden tyypit ovat `text`, `image`, `audio`, `video` ja `document`. Niiden media-arvo `source` on joko `{"type":"url","url":"https://..."}` tai `{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano` ja perhealias `jina-ai/jina-embeddings-v5-omni` → omni-small) hyväksyy myös Jinan natiivit EmbeddingsV5Request-dokumentit ja **välittää ne muuttamattomina** osoitteeseen `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Natiivien `{ image | audio | video | pdf }`-arvojen muoto voi olla julkinen HTTPS-URL, `data:`-URI tai käsittelemätön base64. OmniRoute ei muunna näitä objekteja merkkijonoiksi eikä nouda natiivien kuvien URL-osoitteita — Jina noutaa julkisen median itse. Jinan lisäkentät (`task`, `normalized`, `truncate`, `embedding_type`) välitetään eteenpäin. Vain tekstiä tukevat Jina-SKU:t hylkäävät edelleen muut kuin tekstidokumentit.

Tietoturva- ja siirtorajoitukset:

- Etämedian URL-osoitteiden on oltava julkisia HTTPS-osoitteita. Kanoniset `{type,source:url}`-kohteet noudetaan palvelinpuolella (uudelleenohjausten uudelleenvalidointi, aikakatkaisu, kokorajoitukset, julkinen DNS ja yhteyden kiinnitys) ja sisällytetään ennen palveluntarjoajakutsua. Jina-natiivit `{image:"https://..."}`-kohteet välitetään sellaisinaan saman julkisen HTTPS-tarkistuksen jälkeen; Jina noutaa URL-osoitteen.
- Sisäisen base64-median purettu koko on rajoitettu 8 MiB:iin kohdetta kohti ja 16 MiB:iin koko pyynnössä.

Palveluntarjoajakohtainen muunnos (kanonisia kohteita ei koskaan välitetä muuttamattomina):

- Jinan multimodaaliset mallit: jokaisesta ylimmän tason kohteesta tulee yksi modaliteettiavaimella varustettu objekti (`text` / `image` / `audio` / `video` / `pdf`), jossa sisäinen media esitetään data-URI:na; yksi vektori kutakin ylimmän tason kohdetta kohti.
- Gemini Embedding 2 -perhe: yhdestä ylimmän tason taulukosta muodostetaan yksi natiivi `models/{model}:embedContent`-pyyntö, jossa on `content.parts` (`text` tai `inline_data`).
- llama.cpp (`llama-cpp/<model>`, mikä tahansa paikallisen palvelimen lataama malli): kanoniset `text`-kohteet muunnetaan tavallisiksi merkkijonoiksi, ja kukin `image`- / `audio`- / `video`-kohde muunnetaan yhdeksi `{"content": [part]}`-objektiksi käyttämällä llama-serverin chat-sisältöosia (`image_url`, `input_audio` muodossa `wav` / `mp3` / `flac`, `input_video`) ja sisäistä dataa; yksi vektori kutakin ylimmän tason kohdetta kohti. Palvelin on käynnistettävä valinnoilla `--embedding --mmproj …`; ilman projektoria se hylkää median itse. `document`-tyyppiä ei tueta.
- Tuntemattomat tai dynaamiset mallit, joilla ei ole eksplisiittisiä modaliteettien metatietoja, hylkäävät rakenteisen syötteen HTTP 400 -vastauksella.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Mallin ja modaliteetin yhdistelmät, joita ei tueta, palauttavat HTTP 400 -vastauksen sen sijaan, että kohde muunnettaisiin väkisin. Vanhojen merkkijono- tai tunnistepyyntöjen syötteeseen kuulumattomat laajennuskentät välitetään edelleen muuttamattomina.

```bash
# Luettele kaikki upotusmallit
GET /v1/embeddings
```

Saatavilla oleviin palveluntarjoajiin kuuluvat OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (paikallinen) ja ComfyUI (paikallinen).

- Muut julkaisijat, kuten `zm/meta/muse-image-1.0`, käyttävät ZenMuxin Vertex AI `:predict`

- `zm/inclusionai/ming-image-0.1-design` valitsee omat mittansa. Jätä pois `size`,

tuloste normalisoidaan muotoon `data[].b64_json`; `response_format: "url"` palauttaa ylävirran

palauttavat virheen tyhjän onnistumisvastauksen sijaan. Mallien käyttöoikeudet riippuvat ZenMux-tilistä.

{

`model` valitsee OCR-palveluntarjoajan etuliitteen `provider/model` avulla; pelkkä mallitunnus (esim.

Mistralia (`mistral-ocr-latest`). Rekisteröidyt palveluntarjoajat (`open-sse/config/ocrRegistry.ts`):

| Palveluntarjoajan tunnus      | Mallin tunnus        | `model`-arvo                                                   | Huomautukset                                                                                                         |
| ----------------------------- | -------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (tai pelkkä `mistral-ocr-latest`) | Synkroninen — vastaus palautetaan suoraan yhdestä ylävirran kutsusta.                                                |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                    | Asynkroninen ylävirta (`analyze` + kysely) — katso alta.                                                             |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                        | Synkroninen, Vertex AI:n `openapi/chat/completions`-kumppanipäätepisteen kautta — katso alta todennus ja URL-osoite. |

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Azure Document Intelligencen kyselykulku

Azure Document Intelligencen `analyze`-API on asynkroninen: alkuperäinen pyyntö palauttaa rungon sijasta
`Operation-Location`-otsakkeen, ja tulosta on kyseltävä toistuvasti. Käsittelijä
(`open-sse/handlers/ocr.ts`) kyselee kyseistä URL-osoitetta sekunnin välein enintään 30 kertaa, epäonnistuu heti (eikä
jatka kyselyä), jos kyselyvastaus ei ole `ok` tai tila on `"failed"`, ja palauttaa arvon `504`, jos
toiminto on edelleen käynnissä yritysbudjetin täytyttyä. Lopullinen Azure-vastaus
normalisoidaan samaan Mistralin käyttämään `pages`/`markdown`-muotoon ennen sen palauttamista
kutsujalle, joten asiakaskoodin ei tarvitse käsitellä palveluntarjoajaa erikoistapauksena.

### Vertex AI DeepSeek OCR:n todennus ja päätepisteen ratkaisu

`vertex-deepseek-ocr` käyttää uudelleen samaa Vertex AI -todennusta, jota OmniRoute jo tukee
keskustelu- ja kuvaliikenteessä (`open-sse/executors/vertex.ts`): yhteyden API-avain on joko
Service Account JSON -tunnistetieto (joka vaihdetaan lyhytikäiseen OAuth-käyttöoikeustunnukseen JWT bearer
-kulun avulla) tai valmiiksi luotu OAuth-käyttöoikeustunnus, jota käytetään sellaisenaan. Ylävirran päätepisteen URL-osoite on Vertexin
yleinen `openapi/chat/completions`-kumppanipäätepiste, joka muodostetaan yhteyden projektista ja
alueesta — eksplisiittinen `providerSpecificData.project`/`providerSpecificData.region` on aina ensisijainen;
muussa tapauksessa projekti johdetaan Service Account JSONin `project_id`-arvosta ja alueen
oletusarvona on `us-central1`. Molemmat ratkaisut tehdään tiedostossa `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), ja
`src/app/api/v1/ocr/route.ts` käyttää niitä ennen pyynnön välittämistä funktiolle `handleOcr`.

### Mallitunnusten etuliitteet (`?prefix=`)

Useimmat mallit julkaistaan **palveluntarjoajan etuliitteellä**. Käytettävää etuliitettä ohjaa
`MODELS_CATALOG_PREFIX_MODE`-ominaisuuslippu, ja sen voi ohittaa **pyyntökohtaisesti**
kyselyparametrilla — tästä on hyötyä asiakkaalle, joka haluaa selkeän luettelon muuttamatta
palvelimen yleistä asetusta kaikille muille:

```bash
GET /v1/models?prefix=alias        # yksi tunnus mallia kohden — lyhyt alias-etuliite
GET /v1/models?prefix=dual         # molemmat muodot (palvelimen oletus)
GET /v1/models?prefix=canonical    # vain täydellinen palveluntarjoajatunnuksen etuliite
```

| Tila        | Tuottaa                                                  | Huomautukset                                                                                                                                                                                                                                  |
| ----------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **ja** `claude/claude-sonnet-4-6` | **Oletus.** Molemmat tunnukset reititetään samaan malliin. Näin jommankumman muodon kovakoodanneet asiakasmääritykset toimivat edelleen. Luettelon koko suunnilleen kaksinkertaistuu.                                                         |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Yksi merkintä mallia kohden. Palveluntarjoajat, joilla ei ole erillistä aliasta, tuottavat silti oman merkintänsä, joten mitään ei menetetä.                                                                                                  |
| `canonical` | `claude/claude-sonnet-4-6`                               | Yksi merkintä mallia kohden täydellisellä palveluntarjoajatunnuksen etuliitteellä. Palveluntarjoajat, joilla ei ole erillistä aliasta (esim. `antigravity/…`, `agy/…`), tuottavat tässäkin yksittäisen tunnuksensa, joten mitään ei menetetä. |

`dual`-tilan peilitunnisteen voi tunnistaa myös ilman kyselyparametria: siinä on ensisijaiseen
tunnukseen osoittava `parent`-kenttä.

Mallivalitsimen näyttävien asiakkaiden tulisi pyytää `?prefix=alias` — näin toimii
[OmniCopilotin VS Code -laajennus](../guides/VSCODE-COPILOT.md).

### Hakusuodattimet (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` hyväksyy valinnaisia hakusuodattimia. Ilman niitä vastaus ei muutu.
Ne rajaavat luetteloa, jonka kutsuja jo näkee (API-avaimen käyttöoikeudet käsitellään ensin),
ja ne suoritetaan ennen OpenAI-tyylisiä `limit`- ja `after`-sivutusparametreja:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # jokaisen luetellun ominaisuuden on oltava tosi
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # luettelon `type`; rivit, joilta se puuttuu, ovat tyyppiä `chat`
GET /v1/models?q=sonnet&limit=10                           # kirjainkoosta riippumaton osuma tunnukseen tai nimeen
```

| Parametri     | Arvot                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | ei-negatiivinen kokonaisluku, jota verrataan arvoon `context_length`                                |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 merkkiä                                                                                       |

Tuntematon arvo tai `min_context`, joka ei ole ei-negatiivinen kokonaisluku (esimerkiksi `1.5`),
palauttaa HTTP `400` -vastauksen, jonka viestissä luetellaan kelvolliset arvot. Toteutus:
`src/app/api/v1/models/catalogFilters.ts`.

### Mallien esivalinta (`POST /v1/models/query`)

`POST /v1/models/query` palauttaa samasta luettelosta lyhyen, deterministisen listan käyttäen samoja
todennus- ja avainkohtaisia näkyvyyssääntöjä kuin `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Jokainen kenttä on valinnainen. `capabilities` ja `exclude` hyväksyvät taulukon tai pilkuilla erotellun merkkijonon;
`max_output`-arvoa verrataan `max_output_tokens`-arvoon. Tulokset lajitellaan ensin `owned_by`-kentän ja sitten `id`-kentän mukaan.
`limit`-arvon oletus on `20`, ja arvoa `100` suuremmat arvot rajataan arvoon `100`. Virheellinen JSON, tuntematon
kenttä tai virheellinen arvo palauttaa HTTP `400` -vastauksen.

### Yksittäin piilotetut keskustelumallit

Palveluntarjoajan sivulla **piilotetuksi** merkitty malli jätetään pois luettelosta ja hylätään
HTTP `404`- / `model_not_found`-vastauksella, kun sitä pyydetään nimenomaisesti. Tarkistus käyttää ratkaistua
palveluntarjoajaa ja mallia, mukaan lukien palveluntarjoajien aliakset, yhteensopivien palveluntarjoajien solmujen etuliitteet ja
yhteyksien oletukset. Yhdistelmä ohittaa piilotetut kohteet ja voi käyttää näkyvää rinnakkaiskohdetta. Jos
suoritettavaa kohdetta ei jää jäljelle, se palauttaa saman virhekoodin. Piilotuksen poistaminen tulee voimaan seuraavassa
pyynnössä. Vain kuvia koskevat näkyvyyden ohitukset eivät piilota samalla tunnuksella olevaa keskustelumallia.

Tämä yksittäisen mallin asetus on erillinen
[mallien näkyvyyden sallittujen ja estettyjen luetteloista](../routing/MODEL_EXPOSURE_LIST.md), jotka suodattavat luettelossa
julkaistavia malleja ja automaattisen reitityksen ehdokkaita säilyttäen samalla nimenomaisen reitityksen. API-avaimen
mallikohtaisia käyttöoikeuksia sovelletaan edelleen itsenäisesti. Luettelon etuliitetilan oletuksena säilyy `dual`.

### Mallivariantit ilman ajattelua

Ajattelua tukeville Claude-malleille `/v1/models` julkaisee myös **ilman ajattelua** toimivan variantin, jonka tunnuksen etuliite on `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Tämän tunnisteen valitseminen (esim. Claude Code -määrityksessä, joka liittää aina `thinking`-lohkon) palautuu todelliseen `<provider>/<model>`-malliin päättely poistettuna käytöstä — `/v1/messages`-polussa käytetään asetusta `thinking:{type:"disabled"}`, kun taas `/v1/chat/completions`-polussa `reasoning`- ja `reasoning_effort`-kentät jätetään pois. Variantti näytetään vain Claude-malliperheen malleille, jotka tukevat ajattelua **ja** hyväksyvät `disabled`-arvon (joten esimerkiksi vain mukautuvaa ajattelua tukevat mallit, jotka hylkäävät `disabled`-arvon, jätetään pois). Ylläpitäjät voivat pakottaa variantin käyttöön tai pois käytöstä mallikohtaisesti `ModelSpec.noThinkingAlias`-asetuksella.

## ElevenLabs-äänen generointi

Määritä OmniRouteen `elevenlabs`-palveluntarjoajayhteys ElevenLabs-API-avaimellasi.
Asiakkaat tunnistautuvat **OmniRoute**-avaimellaan (`Authorization: Bearer $OMNIROUTE_API_KEY`);
yhdyskäytävä toimittaa tallennetun palveluntarjoaja-avaimen `xi-api-key`-otsakkeessa. Älä koskaan lähetä ElevenLabs-avainta
yhdyskäytävän bearer-tunnuksena.

| Menetelmä | Polku                       | Vastaus                                       | API-avaimen päätepisteluokka |
| --------- | --------------------------- | --------------------------------------------- | ---------------------------- |
| POST      | `/v1/sound-generation`      | Natiivit äänitavut                            | `elevenlabs`                 |
| POST      | `/v1/music`                 | Natiivit äänitavut                            | `music`                      |
| POST      | `/v1/music/stream`          | Suoratoistettavat äänitavut                   | `music`                      |
| POST      | `/v1/music/detailed`        | Natiivi multipart-ääni ja sävellyssuunnitelma | `music`                      |
| POST      | `/v1/music/detailed/stream` | Natiivit SSE-metatiedot ja äänipalat          | `music`                      |
| POST      | `/v1/music/plan`            | JSON-sävellyssuunnitelma                      | `music`                      |

Nämä päätepisteet täydentävät nykyisiä `/v1/audio/speech`-, `/v1/audio/transcriptions`-,
`/v1/voices`-, `/v1/text-to-speech/{voiceId}`- ja `/v1/speech-to-text`-reittejä. Natiivit JSON-kentät
ja kyselyparametrit, kuten `output_format` ja `enable_logging`, säilytetään.
`/v1/music/detailed`-vastaukset säilyttävät multipart-erottimensa; jäsennä ne multipart-muodossa.
`/v1/music/detailed/stream` palauttaa `text/event-stream`-sisältöä, joka sisältää sävellyksen metatiedot ja
base64-koodatut äänipalat SSE-tapahtumissa. Kaikki kuusi reittiä tukevat CORS-esitarkistuspyyntöjä.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Lyhyt äänitehoste. Kesto: 0,5–30 sekuntia.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Musiikin kesto ilmaistaan millisekunteina: 3000–600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Käytä `/v1/music/stream`-päätepistettä samalla JSON-rungolla äänen vaiheittaiseen toimittamiseen. Sävellys
hyväksyy täsmälleen toisen kentistä `prompt` tai `composition_plan`; `/v1/music/plan` edellyttää `prompt`-kenttää
ja hyväksyy valinnaisesti `source_composition_plan`-kentän. Natiivit skeemat säilyttävät palveluntarjoajan
lisäkentät, jotta sävellyssuunnitelmien versiot ja hienosäätöasetukset välittyvät ElevenLabsille.

Yhtenäinen `/v1/music/generations`-päätepiste hyväksyy myös mallit `elevenlabs/music_v1`,
`elevenlabs/music_v2` ja `elevenlabs/music_v2_5`. Kun ElevenLabs-yhteys on aktiivinen,
nämä mallit näkyvät musiikkiluettelossa. Tämä päätepiste palauttaa arvon
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Sen `duration`-kentän yksikkö on
sekunti, ja se muunnetaan `music_length_ms`-kentäksi; eksplisiittinen `music_length_ms` on ensisijainen.
`instrumental` muunnetaan `force_instrumental`-kentäksi, ja natiivi kenttä on ensisijainen.
Käytä suoratoistoon natiiveja suoratoistopäätepisteitä ja pelkästään sävellyssuunnitelmaan
perustuviin pyyntöihin natiivia sävellyspäätepistettä.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Päätepiste-, malli-, budjetti- ja yhteysrajoitukset tarkistetaan ennen kutsua ylävirran palveluun. Natiivit
reitit palauttavat ylävirran tilakoodit ja virherungot muuttamattomina, mukaan lukien `402` palvelupaketin
rajoituksesta ja `429` kiintiörajoituksesta. Otsakkeet `character-cost`, `song-id`, `request-id` ja `retry-after`
säilytetään, kun ne ovat mukana. Ilmainen krediittisaldo ei takaa pääsyä kaikkiin
musiikkimalleihin, tulostusmuotoihin tai API-ominaisuuksiin: ElevenLabs ratkaisee käyttöoikeuden jokaiselle pyynnölle.
Yhtenäinen päätepiste säilyttää virheiden tilakoodit OmniRouten normalisoidussa virhekuoressa.

Ylävirran sopimukset: [äänitehosteet](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[musiikin säveltäminen](https://elevenlabs.io/docs/api-reference/music/compose) ja
[suoratoistettavan musiikin tiedot](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> **Uudelleenjärjestelypalveluntarjoajan solmut:** `POST /v1/rerank` reitittää pyynnöt myös OpenAI-yhteensopiviin palveluntarjoajasolmuihin
> (oMLX, vLLM, Infinity, yhdyskäytävän takana oleva TEI, …), joihin viitataan muodossa `<node-prefix>/<model>`. Takaisinkytkentäsolmut
> (`localhost`, `127.0.0.1`, `172.16.0.0/12`) hyväksytään aina, samoin isäntänimet, jotka
> operaattori luettelee muuttujassa `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (esimerkiksi Docker/Compose-palvelun nimi,
> kuten `http://reranker:8080/v1`; näihin muodostetaan yhteys suoraan, ei koskaan `HTTP(S)_PROXY`-välityspalvelimen tai
> yhteydelle kiinnitetyn välityspalvelimen kautta). Millä tahansa muulla
> isännällä sijaitsevat solmut — lähiverkon kone tai Tailscale-vertaislaite — hyväksytään vain, kun operaattori ottaa käyttöön
> `RERANK_REMOTE_PROVIDER_NODES`-ominaisuuslipun **ja** solmun perus-URL läpäisee palveluntarjoajan
> lähtevien URL-osoitteiden käytännön (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Muistimoottorin uudelleenjärjestelyvaihe kutsuu tätä reittiä
> takaisinkytkennän kautta, joten sama sääntö koskee Muisti-asetusten `rerankProviderModel`-määritystä.
>
> **Paikallisten palvelimien muodot:** solmua kutsutaan ensin osoitteessa `<base>/v1/rerank` ja 404-vastauksen jälkeen osoitteessa `<base>/rerank`
> (Infinity, TEI). Ylävirtaan lähetettävä runko sisältää sekä Cohere/OpenAI-kirjoitusasun (`documents`,
> `return_documents`) että TEI-kirjoitusasun (`texts`, `return_text`), ja ylävirran vastaus
> normalisoidaan Cohere-kääreeseen: TEI:n paljas `[{index, score, text}]`, kevyiden yhdyskäytävien
> `{results: [{index, score}]}` ja Voyage-tyylinen `{data: [...]}` palautetaan kaikki asiakkaalle muodossa
> `{results: [{index, relevance_score, document?}]}`, pisteiden mukaan lajiteltuina ja enintään `top_n`-määrään rajattuina.

> **Palveluntarjoajasolmujen haku:** OpenAI-yhteensopivan palveluntarjoajasolmun mallit näkyvät kohdassa `GET /v1/models`
> solmun etuliitteen alla. Rivit, joissa ei ole päätepisteiden metatietoja (tyypillistä paikallisille `/v1/models`-luetteloille),
> perivät solmun `apiType`-arvon, joten `embeddings`-solmun mallien tyyppi on `type: "embedding"` ja
> `rerank`-solmun mallien tyyppi on `type: "rerank"` sen sijaan, että oletuksena käytettäisiin keskustelua; synkronoidulla tai manuaalisesti lisätyllä rivillä
> eksplisiittisesti määritetty `supportedEndpoints` on edelleen etusijalla.

| Exa              | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (yksinkertaiset ylätason arvot), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` yhdistettynä oletusarvon `{ text: true, highlights: true }` päälle |

Yleiset kentät ovat aina etusijalla: `query`, `max_results`, `filters` (verkkotunnukset), `country` sekä
kentästä `search_type` johdettu aihe. Exassa `search_type: "news"` säilyttää arvon `category: "news"`.
Tavily hyväksyy myös arvon `search_type: "finance"` (`topic: "finance"`).

Yleinen `time_range` välitetään nyt molemmille palveluntarjoajille: Exa saa kentän `startPublishedDate` (ISO-
aikaleima) ja Tavily kentän `start_date` (`YYYY-MM-DD`). Kentässä `provider_options`
nimenomaisesti määritetty päivämäärä ohittaa muunnetun arvon.

Exan tulokset säilyttävät kentät `id`, `highlight_scores`, `summary`, `subpages`, `entities` ja `extras`
kentässä `provider_raw`. Tavily-tulokset säilyttävät kentät `images` ja `favicon`.

Kustannuslaskenta käyttää edelleen yksinkertaista `costPerQuery`-rekisteriä. Tavily veloittaa
arvolla `search_depth: "advanced"` enemmän krediittejä kutsua kohden, eikä tämä ero näy
kentässä `usage.search_cost_usd`.

## Web Fetch API

Poimi sisältö URL-osoitteesta määritetyn verkkonoudon palveluntarjoajan avulla (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, sama API-avain kuin Parallel Searchissa) palauttaa vain
Markdownia — mikä tahansa muu `format` johtaa `400`-vastaukseen — ja rajoittaa sisällön 100 000 merkkiin. Kun
kohdesivua ei voida poimia, ylävirran palvelu ilmoittaa siitä HTTP 200 -vastauksen sisällä;
OmniRoute välittää tämän `422`-vastauksena, jossa on kiinteä viesti.

| Metodi | Polku           | Kuvaus                                                                    |
| ------ | --------------- | ------------------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Nouda/haravoi URL-osoite — runko validoidaan `v1WebFetchSchema`-skeemalla |

**Todennus:** Bearer-API-avain (`extractApiKey` + `isValidApiKey`). Käytäntö pakotetaan `enforceApiKeyPolicy`-toiminnolla.

**Kiintiöt huomioiva varapalvelu (#8297):** kun eksplisiittistä `provider`-arvoa ei anneta, joukko
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) käydään
läpi kiinteässä
prioriteettijärjestyksessä (täyttö ensin) — nopeusrajoitettu mutta määritetty palveluntarjoaja ohitetaan
sen sijaan, että pyyntö keskeytettäisiin, ja uudelleen yritettävästä tai kiintiöön liittyvästä ylävirran virheestä
(HTTP 429 aina; 402/403 Firecrawl-, Tavily- ja TinyFish-palveluiden kiintiötyylisillä ilmaisversioilla —
ei Jina Readerilla eikä koskaan tavallisella virheellisen pyynnön 400-vastauksella) siirrytään pyynnön aikana
seuraavaan vielä kokeilemattomaan palveluntarjoajaan, jolla on tunnistetiedot. Kun kaikki joukon palveluntarjoajat
on käytetty loppuun, päätepiste palauttaa yhden `429`-vastauksen (jossa on `Retry-After`-otsake)
aiemman yleisen `400`-vastauksen sijaan. Kun eksplisiittinen `provider` pyydetään,
**hiljaista varapalveluun siirtymistä ei tehdä** — nopeusrajoitettu tai epäonnistuva eksplisiittinen
palveluntarjoaja välittää oman virheensä (`429`, jos sitä on nopeusrajoitettu, muussa tapauksessa ylävirran
tilakoodin).

## WebSocket-suoratoisto

```bash
GET /v1/ws?handshake=1
```

Validoi WebSocket-päivityksen kättelyn ja palauttaa siirtoprotokollan esimerkkiviestit (`request`, `cancel`). Varsinaiset WS-kehykset käsittelee mukana toimitettu WS-palvelin Next.js-reititystaulukon ulkopuolella.

**Todennus:** Bearer-API-avain kättelyn aikana.

### Responses API WebSocketin kautta (vain codex)

```bash
# Sama isäntä ja portti kuin HTTP API:lla (oletusarvoisesti 20128); päivitä yhteys:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (tai: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Ensimmäisen kehyksen ON OLTAVA response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Responses API:n WebSocket-välityspalvelin on yhdistetty **ainoastaan `codex`-palveluun** (ChatGPT-
taustajärjestelmä). Se kuuntelee samassa portissa kuin API/hallintapaneeli poluissa `/v1/responses`,
`/responses` ja `/api/v1/responses`. Ensimmäisen `response.create`-kehyksen yhteydessä se
todentaa ja valmistelee pyynnön sisäisen `codex-responses-ws`-sillan kautta, valitsee
codex OAuth -yhteyden ja tunneloi osoitteeseen `wss://chatgpt.com/backend-api/codex/responses`
`wreq-js`-siirtokerroksen kautta. **Muut kuin codex-mallit hylätään** (`codex_ws_provider_required`).
Käytä kiintiöosuuteen perustuvassa reitityksessä arvoa `model: "qtSd/<group>/codex/<model>"`. Toteutus sijaitsee
tiedostoissa `app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Todennus:** Bearer-API-avain kättelyn aikana. Mukana toimitetun HTTP-palvelimen (`server-ws.mjs`)
on oltava aktiivinen käynnistyspiste (ja se on oletusarvoisesti, kun `app/server-ws.mjs` on olemassa).

#### Mallin tunniste: käytä paljasta ChatGPT-tunnistetta (ei `codex/`-etuliitettä)

OpenAI **Codex CLI** validoi mallin nimen asiakaspuolella, kun
`supports_websockets = true`, ja **hylkää palveluntarjoajan etuliitteellä varustetut tunnisteet**, kuten
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Lähetä **paljas** tunniste (esim. `gpt-5.5`). OmniRouten silta on
vain codexille, joten se selvittää paljaan tunnisteen uudelleen codex-malliksi
(`resolveCodexWsModelInfo`) ennen tunnelointia ylävirtaan — vaikka paljas
`gpt-5.5` reititettäisiin muutoin HTTP:n kautta toiselle palveluntarjoajalle.

#### OpenAI Codex CLI:n määrittäminen

Ohjaa Codex CLI OmniRouteen lisäämällä WebSocket-
tuella varustettu mukautettu palveluntarjoaja tiedostoon `~/.codex/config.toml` (käytä erillistä `CODEX_HOME`-hakemistoa, jotta
olemassa olevaan määritykseen ei kosketa):

```toml
model = "gpt-5.5"                 # paljas tunniste — EI "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # ei loppukauttaviivaa; WS-URL johdetaan tästä (käytä tuotannossa https/wss)
wire_api = "responses"                    # ainoa tuettu arvo helmikuusta 2026 lähtien
supports_websockets = true                # ottaa Responses-over-WS-siirtotavan käyttöön
env_key = "OMNIROUTE_API_KEY"             # sisältää OmniRouten API-avaimen (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRouten API-avain (mikä tahansa avain, jos REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI päivittää osoitteen `base_url + /responses` WebSocket-yhteydeksi, ja OmniRoute tunneloi sen
valittuun codex OAuth -yhteyteen. Toiminta on validoitu päästä päähän paikallista
palvelinta vasten: ChatGPT palauttaa `codex.rate_limits` + `response.created` ja suoratoistaa
vastauksen.

## Itsepalvelukäyttö (`/api/usage/om-usage`)

Mikä tahansa API-avain voi lukea **oman** käyttönsä ja kiintiönsä ilman hallintatodennusta. Asiakas
(CLI tai OmniCopilot-paneeli) näyttää tämän päätepisteen avulla avaimen haltijalle tämän kulutuksen.

```bash
# Tekstimuoto (historiallinen sopimus — pelkkä teksti päätettä varten)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Rakenteinen muoto — käyttöliittymän käyttämä muoto
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Avaimella on oltava **`allowUsageCommand`** käytössä (oletusarvoisesti poissa käytöstä — hallintapaneelin
API-avainten hallinta ottaa sen käyttöön tai poistaa sen käytöstä avainkohtaisesti). Ilman sitä päätepiste vastaa tilakoodilla `403`.

`?format=json` palauttaa erotellun rakenteen, jotta kutsuja ei koskaan lue tietokenttää
hylkäysvastauksesta. Onnistuneessa vastauksessa:

```jsonc
{
  "allowed": true,
  // mukana vain, kun avaimelle on otettu käyttöön avainkohtaiset käyttörajat (päivittäinen/viikoittainen USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // valitun palveluntarjoajan kiintiön tilannevedos tai null, jos mitään ei ole vielä välimuistissa:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // kaikkien yhteyksien tilannevedokset, jotta käyttöliittymä voi näyttää useita palveluntarjoajia rinnakkain:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Hylkäyksen yhteydessä (`401` virheellinen avain / `403` ei sallittu) sama reitti palauttaa
`{ "allowed": false, "error": { "message": "…" } }` — olemassa oleva mutta tyhjä `personal`/`provider`
(avain on sallittu, mutta tietoja ei ole vielä saatu) on eri tila kuin hylkäys, ja vain JSON-muoto
erottaa ne toisistaan.

**Todennus:** kutsujan oma Bearer-API-avain, joka validoidaan `isValidApiKey`-toiminnolla — tämä _ei_ ole
hallintarajapinta (`/api/keys/…`), joka pysyy `requireManagementAuth`-suojauksen takana.

### Raakamuotoiset ja katkaisurajaan suhteutetut kiintiöprosentit

Päätepistettä `/api/usage/om-usage` käyttävien kutsujien tulee huomioida **pelkkänä tekstinä annettavan tulosteen**
ja rakenteisen **JSON-tulosteen** prosenttien välinen ero:

| Ominaisuus                 | Pelkkä tekstimuoto (`/api/usage/om-usage` / `@@om-usage`)                                                       | JSON-muoto (`?format=json`)                                                                            |
| :------------------------- | :-------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| **Tulostekenttä**          | `NN% left` (esim. `20% left`)                                                                                   | `provider.quotas` / `providers[].quotas`                                                               |
| **Mittaustapa**            | **Katkaisurajaan suhteutettu käytettävissä oleva määrä**: jäljellä oleva kapasiteetti katkaisurajan yläpuolella | **Raaka ylävirran kiintiö**: palveluntarjoajan suhteuttamaton mittaus                                  |
| **Katkaisurajan skaalaus** | Skaalataan `effectiveRemainingPercent()`-toiminnolla, jotta suojattu varaus näkyy arvona `0% left`              | Ei käytössä (palveluntarjoajan ilmoittamat tilannevedoksen raaka-arvot)                                |
| **Raja-arvotiedot**        | Sisällytetään näytettävään prosenttiin                                                                          | Tallennetaan yhteyskohtaisesti kohtaan `quotaWindowThresholds` (tai käytetään palvelimen oletusarvoja) |
| **Ensisijainen käyttäjä**  | Interaktiiviset CLI:t, päätekehotteet ja ihmisoperaattorit                                                      | Ohjelmalliset integraatiot, hallintapaneelit, analytiikka ja laskutusseurannat                         |

#### Katkaisurajaan suhteuttamisen kaava

OmniRoute tukee ennakoivia kiintiön katkaisurajoja ylävirran kiintiön ehtymisen estämiseksi (määritetään yhteyden
`quotaWindowThresholds`-asetuksilla, palveluntarjoajan oletusarvoilla tai yleisillä häiriönsietoasetuksilla). Kun kiintiöikkunassa
on käytössä katkaisuraja (esim. `cutoff = 25%`), tekstin hahmontaja laskee jäljellä olevan määrän seuraavasti:

- Jos `remaining <= cutoff`: palauttaa `0%`.
- Jos `remaining > cutoff`: palauttaa `((remaining - cutoff) / (100 - cutoff)) * 100`.

Muotoiltu tekstituloste pyöristää tämän lähimpään kokonaislukuun (`Math.round(...)`).

#### Havainnollistava esimerkki

Tarkastellaan palveluntarjoajan ikkunaa, jonka **raaka käyttöaste on 60 %** (jolloin **raakakiintiöstä on jäljellä 40 %**) ja jolle on määritetty
**25 %:n katkaisuraja jäljellä olevalle kiintiölle**:

| Esitysmuoto                     | Laskenta                                           | Jäljellä |            Johdettu käyttöaste             |
| :------------------------------ | :------------------------------------------------- | :------: | :----------------------------------------: |
| **Raaka JSON (`?format=json`)** | Ylävirran tilannevedos (`quotas[window]`)          | **40 %** |                  **60 %**                  |
| **Tekstimuoto (`NN% left`)**    | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20 %** | **80 %** (jos lasketaan `100 - remaining`) |

- **Miksi teksti näyttää, että jäljellä on 20 %:** Tilillä fyysisesti jäljellä olevasta 40 %:n kiintiöstä 25 % on varattu
  katkaisukäytännöllä. Kutsujalla on vain 15 % jäljellä 75 %:n käytettävissä olevasta liikkumavarasta ennen kuin reititin lopettaa
  pyyntöjen reitittämisen tähän yhteyteen. Skaalaus varmistaa, että yhteys ilmoittaa kiintiön ehtyneen (`0% left`) täsmälleen silloin, kun
  reititys lakkaa.
- **Miksi JSON säilyttää raaka-arvot:** JSON-tietosisältö palauttaa palveluntarjoajan tarkan tilannevedoksen (`UsageSnapshot`),
  jotta ulkoiset työkalut voivat käyttää todellisia ylävirran käyttöastetietoja ja yhteystason
  `quotaWindowThresholds`-arvoja ilman palvelinpuolen häviöllistä skaalausta.

#### Ohjeita käyttäjien siirtymiseen

Jos ulkoinen integraatio (kuten editoriliitännäinen tai agenttilaajennus) on aiemmin jäsentänyt tekstimuotoista
päätepistettä (`NN% left`) ja laskenut käytetyn prosenttiosuuden kaavalla `100 - NN`, siirtyminen muotoon `?format=json` tarkoittaa seuraavaa:

- Raakojen JSON-arvojen lukeminen kuvastaa **todellista ylävirran kulutusta** (yllä olevassa esimerkissä käytetty 60 %).
- Jos integraatio haluaa säilyttää tekstimuotoisen päätepisteen käytettävissä olevan kiintiön semantiikan, se voi laskea
  jäljellä olevan määrän efektiivisen kaavan asiakaspuolella käyttäen `quotaWindowThresholds`-arvoja yhteystason ohituksiin.

Synkronoitujen/tuotujen mallien tapauksessa `PUT /api/provider-models` hyväksyy kentät `provider`, `modelId` ja

palveluntarjoajan sivu tarjoaa samat muokkaus- ja tyhjennysohjaimet sekä merkitsee mallit, joilla on nimenomainen kuvasyötteiden tuki.

Mukautetut Chat Completions -solmut sovittavat päättelyn nimenomaisen käytöstäpoiston ylävirran taustajärjestelmään. Onnistunut
yhteystesti valitsee automaattisesti chat-mallin ohjaimet jokaiselle täsmälliselle mallitunnukselle,
jonka `/models`-merkintä osoittaa tunnetun `owned_by`-arvon: `vllm`, `sglang` tai `llamacpp`.
Läpinäkyvät OpenAI-yhteensopivat kääreet voivat säilyttää alkuperäisen mallimerkinnän sisäkkäisessä
`openai`-objektissa; tunnistus seuraa enintään kolmea tällaista käärettä. Mallit, joiden omistajuus puuttuu,
on tuntematon tai ristiriitainen, säilyttävät tavallisen OpenAI-toiminnan. Tunnistus käyttää uudelleen olemassa olevaa
luettelopyyntöä, ei generoi täydennysmerkkejä ja mitätöityy, kun yhteyden päätepiste muuttuu.

Jos taustajärjestelmä ei paljasta näitä metatietoja, voit kiinnittää toimintatavan käyttämällä olemassa olevaa osittaista
palveluntarjoajan päivitysrajapintaa:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Lähetä tämä runko komennolla `PUT /api/providers/<connection-id>`. Kyseisessä yhteydessä nimenomainen
päättelyponnistus `none` lähetetään arvoina `chat_template_kwargs.thinking=false` ja
`chat_template_kwargs.enable_thinking=false`. Nimenomaiset natiivit malliarvot pysyvät määräävinä,
ellei palvelinpuolen päättelysääntö pakota tiettyä ponnistusta. Asetus on voimassa vain, kun mukautettu
OpenAI-yhteensopiva yhteys lähettää Chat Completions -rungon; Responses-pyynnöt ja tavalliset
palveluntarjoajat säilyttävät natiivin pyyntörakenteensa. Aseta `reasoningControl` arvoon `openai`, jos haluat pakottaa tavallisen OpenAI
`reasoning_effort`-arvon välityksen, tai jätä se pois / aseta arvoksi `null`, jos haluat käyttää automaattista tunnistusta.

Claude Coden automaattisen tilan luokittelupyynnöissä natiivi päättely on oletusarvoisesti poistettu käytöstä, jos pyynnöt eivät sisällä
nimenomaisia päättelyohjaimia. Tunnistus käyttää luokittelijan järjestelmämerkintää Claude-muotoisissa
pyynnöissä, ei mallien nimiä tai täydennysrajoja. Rungon nimenomaiset ohjaimet, tuetut ponnistus-/päättelyotsakkeet,
reitityssäännöt ja ratkaistu mallin ponnistus säilyttävät nykyisen prioriteettinsa. Molemmat luokitteluvaiheet
säilyttävät kehotteensa, täydennysrajansa, pysäytyssekvenssinsä ja todelliset ylävirran käyttöoikeuspäätökset;
toinen vaihe voi edelleen tuottaa pyydetyn näkyvän päättelyn tavallisena tekstinä.

Vain loopback-yhteyksille tarkoitettu hallintareitti (järjestelmänvalvojan todennus). Palauttaa käytössä olevan version, uusimman
julkaistun version ja automaattisen päivityksen tilan. `releaseChannel` ja `channels` ovat lisättyjä
kenttiä (julkaisulinja 3.8.54); `channel` säilyttää merkityksensä — käyttöönottotapa, jota hallintapaneelin päivitystoiminto
käyttää (`npm`, `source` tai `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — käytössä olevan koontiversion npm-kanava: `nightly` versioille, joiden tunniste on `-nightly.*`,
  `next` muille esijulkaisuille (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` sellaiselle vakaalle versiolle, jonka
  pääversio on vanhempi kuin `channels.latest`, muussa tapauksessa `latest`. Samat säännöt kuin tiedostossa
  `scripts/release/dist-tag.mjs`, joka valitsee npm-jakelutunnisteen julkaisuhetkellä.
- `channels` — kunkin jakelutunnisteen viimeisin julkaistu versio komennosta `npm view omniroute dist-tags` (varalla
  rekisterin HTTP-rajapinta); välimuistissa samalla 10 minuutin TTL-ajalla kuin `latest`. `latest` on aina mukana
  (varalla käytetään `latest`-kenttää ja sen jälkeen arvoa `"unavailable"`); `next`, `nightly` ja `lts` näkyvät
  vain, kun kyseinen jakelutunniste on olemassa. `Cache-Control: no-cache` -pyyntö päivittää molemmat haut.

Kanavamalli (`latest` = v3 version 4.0 GA-julkaisuun asti, `next` = rc, `nightly` = `develop`-koonnit,
`lts` = v3-korjausversiot version 4.0 GA-julkaisun jälkeen) kuvataan tiedostossa `docs/ops/RELEASE_STRATEGY.md`.

## Tokenirajat

API-avainkohtaiset **token**-budjetit (erillään edellä kuvatusta USD-pohjaisesta budjetista). Ne valvotaan suoraan pyynnön käsittelypolulla: kun avaimen nykyisen aikaikkunan käyttö saavuttaa rajan, pyynnöt hylätään virheellä `429 Too Many Requests`. Rajat voidaan kohdistaa tiettyyn `model`-malliin tai `provider`-palveluntarjoajaan tai niitä voidaan soveltaa `global`-laajuisesti koko avaimeen. Kun pyyntöön täsmää useita rajoja, tiukin niistä on voimassa.

```bash
# Luettele avaimen tokenrajat (sisältää aikaikkunan ajantasaiset käyttötiedot)
GET /api/usage/token-limits?apiKeyId=key-123

# Luo tai päivitä tokenraja
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Poista tokenraja tunnuksen perusteella
DELETE /api/usage/token-limits?id=tl-abc
```

> **Skeemaa koskevat huomautukset** (`setTokenLimitSchema`): `apiKeyId` ja `scopeType` (`model` | `provider` | `global`) ovat pakollisia. `scopeValue` on pakollinen, ellei `scopeType` ole `global` (esimerkiksi mallin tunnus `model`-kohdistukselle tai palveluntarjoajan tunnus `provider`-kohdistukselle). `tokenLimit`-arvon on oltava positiivinen kokonaisluku (merkkijono muunnetaan automaattisesti). Valinnaiset kentät: `id` (jätä pois luotaessa, anna päivitettäessä), `resetInterval` (`daily` | `weekly` | `monthly`, oletusarvo `monthly`), `resetTime` (`HH:MM`) ja `enabled` (oletusarvo `true`). `GET`-vastauksissa kuhunkin rajaan lisätään kentät `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` ja `nextResetAt`. Tämä on hallintaluokan päätepiste (todennus valvotaan keskitetysti käyttöoikeusputkessa).

## Pyyntöjen käsittely

1. Asiakas lähettää pyynnön osoitteeseen `/v1/*`
2. Reitinkäsittelijä kutsuu toimintoa `handleChat`, `handleEmbedding`, `handleAudioTranscription` tai `handleImageGeneration`
3. Malli ratkaistaan (suora palveluntarjoaja/malli tai alias/yhdistelmä)
4. Tunnistetiedot valitaan paikallisesta tietokannasta tilin saatavuuden suodatuksen perusteella
5. Keskustelupyynnöissä `handleChatCore` tarkistaa semanttisen/allekirjoitusvälimuistin ja ratkaisee yhdistelmän pakkausasetukset
6. Ennakoiva pakkaus suoritetaan ennen palveluntarjoajamuunnosta, kun se on käytössä (`lite`, Caveman, RTK tai pinottu)
7. Palveluntarjoajan suorittaja lähettää pyynnön ylävirtaan
8. Vastaus muunnetaan takaisin asiakasmuotoon (keskustelu) tai palautetaan sellaisenaan (upotukset/kuvat/ääni)
9. Käyttö, pakkausanalytiikka ja pyyntölokit tallennetaan
10. Virhetilanteissa käytetään varavaihtoehtoa yhdistelmän sääntöjen mukaisesti

Täydellinen arkkitehtuurikuvaus: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Vikasietoisuus (laajennettu)

OmniRoute tarjoaa kolme toisistaan riippumatonta tilapäisten virheiden käsittelymekanismia. Alla olevien hallintapäätepisteiden avulla ylläpitäjät voivat lukea niiden tilan ja ohittaa sen:

| Kohde                        | Tilan tallennus                                  | Lukeminen                                 | Nollaus / tyhjennys                                                                  |
| ---------------------------- | ------------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------ |
| Palveluntarjoajan katkaisija | `domain_circuit_breakers` + muistissa            | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                                         |
| Yhteyden jäähdytys           | `rateLimitedUntil` palveluntarjoajan yhteyksissä | `/api/rate-limits`, `/api/providers/[id]` | (otetaan uudelleen käyttöön viivästetysti; tyhjennä palveluntarjoajan PUT-pyynnöllä) |
| Mallin lukitus               | Muistissa oleva mallien saatavuusrekisteri       | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                             |

`PATCH /api/resilience` hyväksyy palveluntarjoajan katkaisijan ohitukset kohdissa `providerBreaker.oauth` ja `providerBreaker.apikey`. Kukin profiili tukee kenttiä `degradationThreshold`, `failureThreshold` ja `resetTimeoutMs`; samat kentät ovat käytettävissä kohdassa Dashboard → Settings → Resilience.

```bash
# Tyhjennä yksittäisen mallin lukitus
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Poista kaikki lukitukset
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Kattava käsitteellinen viite ja katkaisijoiden oletusarvot: katso [`CLAUDE.md`](../../CLAUDE.md) → "Vikasietoisuuden suorituksenaikainen tila" ja [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Nopeusrajoitusjono ja automaattisen käyttöönoton turvaverkko

- **Tuettu kirjoituspolku**: `POST /api/rate-limits`, jonka runko on `{"connectionId": "<id>", "enabled": true|false}`, on tuettu hallintapäätepiste yhteyden nopeusrajoitussuojauksen käyttöön ottamiseen tai käytöstä poistamiseen. `PUT /api/providers/[id]` ei tarkoituksellisesti muuta eikä vaihda `rateLimitProtection`-asetusta (#11278).
- **Asetuksen `enabled: false` merkitys**: Asetus `enabled: false` poistaa yhteyden nimenomaisen suojauksen, mutta **ei** jätä aktiivista API-avainyhteyttä yleisen automaattisen käyttöönoton turvaverkon (`autoEnableApiKeyProviders = true`) ulkopuolelle. Kohteessa `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) arvot `false` ja `undefined` vastaavat toisiaan; aktiiviset API-avainyhteydet, joilla ei ole nimenomaista suojausta, pysyvät suojattuina automaattisen käyttöönoton turvaverkon kautta.
- **Yleinen käytöstäpoisto**: Jos API-avainyhteyksiä halutaan käyttää ilman nopeusrajoitusjonoja, poista turvaverkko yleisesti käytöstä ympäristömuuttujalla `RATE_LIMIT_AUTO_ENABLE=false` tai asetuksella `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`).

## MCP-palvelin

OmniRoute sisältää integroidun Model Context Protocol -palvelimen, jossa on kolme siirtotapaa (stdio, SSE, streamable-http) ja käyttöalueittain rajatut työkalut. Alla olevat hallintapaneelin päätepisteet lukevat tila- ja auditointitietoja sekä välittävät HTTP-siirtotapojen liikenteen.

| Menetelmä | Polku | Kuvaus |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Syke, siirtotapa, verkkotila, viimeisin kutsu, suosituimmat työkalut, onnistumisaste viimeisen 24 tunnin ajalta |
| GET | `/api/mcp/tools` | Luettelo MCP-työkaluista sekä niiden `name`, `description`, `scopes`, `phase`, `auditLevel` ja `sourceEndpoints` |
| GET | `/api/mcp/sse` | Avaa SSE-virta SSE-siirtotapaa varten (palauttaa `503`, jos MCP on poistettu käytöstä tai siirtotapa ei täsmää) |
| POST | `/api/mcp/sse` | Lähetä JSON-RPC-kehys SSE-siirtotavalla |
| GET | `/api/mcp/stream` | Avaa Streamable HTTP -siirtotavan SSE-puoli (palvelimen käynnistämät viestit) |
| POST | `/api/mcp/stream` | Lähetä JSON-RPC-kehys Streamable HTTP -siirtotavalla |
| DELETE | `/api/mcp/stream` | Päätä Streamable HTTP -istunto |
| GET | `/api/mcp/audit` | Tee haku auditointilokista — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Koostetut auditointitilastot (kokonaismäärät, onnistumisaste, keskimääräinen kesto, suosituimmat työkalut) |

**Todennus:** `sse`/`stream`-siirtotavat käyttävät MCP-kohtaista todennuspintaa (Bearer-API-avain, jolla on `mcp`-käyttöalue); `status`/`tools`/`audit*`-reitit ovat luettavissa hallintapaneelista (hallintapaneelin isäntäkoneen saavuttamisen lisäksi ei tarvita erillistä todennusta).

> Molempia HTTP-siirtotapoja ohjaavat `settings.mcpEnabled` ja `settings.mcpTransport` — siirtotavan yhteensopimattomuus palauttaa `400`-vastauksen ja MCP:n poistaminen käytöstä palauttaa `503`-vastauksen.

## A2A-palvelin

OmniRoute tarjoaa A2A (Agent-to-Agent) JSON-RPC 2.0 -päätepisteen sekä REST-kääreen tarkastelua ja hallintapaneelikäyttöä varten.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # valinnainen, ellei OMNIROUTE_API_KEY ole asetettu
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Tuetut metodit (kaikki edellyttävät, että `settings.a2aEnabled` on käytössä):

| Metodi           | Kuvaus                                                               |
| ---------------- | -------------------------------------------------------------------- |
| `message/send`   | Synkroninen taidon suoritus; palauttaa `{task, artifacts, metadata}` |
| `message/stream` | Saman taitojoukon suoratoistettava SSE-suoritus                      |
| `tasks/get`      | Hakee tehtävän `taskId`-tunnuksen perusteella                        |
| `tasks/cancel`   | Peruuttaa tehtävän `taskId`-tunnuksen perusteella                    |

Sisäänrakennetut taidot: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Agenttikortti

```bash
GET /.well-known/agent.json
```

Palauttaa julkisen A2A-agenttikortin (nimi, kuvaus, ominaisuudet, taitoluettelo, todennusmalli) — tallennetaan julkisesti välimuistiin 1 tunniksi. Todennusta ei vaadita.

### REST-aputoiminnot

| Metodi | Polku                        | Kuvaus                                                                                                                  |
| ------ | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | A2A:n käyttötila + tehtävätilastot + välimuistiin tallennetun agenttikortin yhteenveto                                  |
| GET    | `/api/a2a/tasks`             | Luettelee tehtävät — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Ei toteutettu REST-aputoimintona — luo JSON-RPC-metodilla `message/send`)                                              |
| GET    | `/api/a2a/tasks/[id]`        | Hakee yhden tehtävän                                                                                                    |
| POST   | `/api/a2a/tasks/[id]/cancel` | Peruuttaa tehtävän                                                                                                      |

**Todennus:** REST-aputoiminnot toimivat ilman hallintatodennusta (hallintapaneeli voi lukea niitä); JSON-RPC-reitti `/a2a` käyttää Bearer `OMNIROUTE_API_KEY` -avainta, jos se on määritetty.

## Todennus

Katso kohdasta [Hallinnan todennus](../guides/MANAGEMENT-AUTH.md) neljä
tunnistetietoperhettä (hallintapaneelin istunto, paikallinen CLI-tunnus, `oma_live_…`-käyttöoikeustunnus,
hallintaoikeuksilla rajattu API-avain) ja niiden erot päättelyavaimiin nähden.

- Hallintapaneelin reitit (`/dashboard/*`) käyttävät `auth_token`-evästettä
- Kirjautuminen käyttää tallennettua salasanatiivistettä; varavaihtoehtona on `INITIAL_PASSWORD`
- `requireLogin` voidaan ottaa käyttöön tai poistaa käytöstä reitin `/api/settings/require-login` kautta
- `/v1/*`-reitit voivat valinnaisesti edellyttää Bearer-API-avainta, kun `REQUIRE_API_KEY=true`
- Tässä viitteessä ”hallintatunnus” / ”hallintaoikeuksilla rajattu API-avain” tarkoittaa yhtä kyseisessä oppaassa kuvatuista tunnistetietoperheistä — ei määrittelemätöntä ylimääräistä salaisuustyyppiä

> **Rikkova muutos (v3.8.0)** — `/api/v1/agents/tasks/*` ja jäähdytysajan hallinnan päätepisteet edellyttävät nyt **hallinnan todennusta** (hallintapaneelin `auth_token`-evästettä tai hallintaoikeuksilla rajattua API-avainta). Asiakkaat, jotka aiemmin kutsuivat näitä reittejä ilman todennusta, saavat vastauksen `401 Unauthorized`. Katso commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
