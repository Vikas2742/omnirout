> ഹുക്കുകൾ ഏതെല്ലാം റൂട്ടുകളിലും പ്രതികരണ പാതകളിലും എത്തുന്നു, ലയിപ്പിച്ച പ്രവർത്തനരഹിതമാക്കൽ ഹെഡറുകൾ (#16412), നിർബന്ധിത അതിർത്തിയായുള്ള ഇൻജക്ഷൻ
> ബ്ലോക്ക് മോഡ് (#16413), പോസ്റ്റ്-കോളിന് മുമ്പ് പ്രതികരണം കാണുന്നവ എന്നിവ)

OmniRoute-നും അപ്സ്ട്രീം ദാതാക്കൾക്കും ഇടയിലുള്ള അതിർത്തിയിൽ ഗാർഡ്റെയിലുകൾ സുരക്ഷ, നയം,
ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ നടപ്പാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും അഭ്യർത്ഥന പേലോഡുകൾ
(`preCall`), അപ്സ്ട്രീം പ്രതികരണങ്ങൾ (`postCall`) എന്നിവ പരിശോധിക്കാനും (ആവശ്യമെങ്കിൽ
നിരസിക്കാനും, പരിവർത്തനം ചെയ്യാനും, വ്യാഖ്യാനം ചേർക്കാനും) കഴിയും.

സിസ്റ്റം **fail-open** രീതിയിലാണ് പ്രവർത്തിക്കുന്നത്: ഒരു ഗാർഡ്റെയിൽ പ്രവർത്തനത്തിനിടെ എറർ എറിഞ്ഞാൽ,
അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിനുപകരം രജിസ്ട്രി ആ എറർ രേഖപ്പെടുത്തി അടുത്ത ഗാർഡ്റെയിലുമായി
തുടരുന്നു. ബ്ലോക്ക് ചെയ്യുന്നത് വ്യക്തമായ ഒരു തീരുമാനമാണ് (`block: true`), ഒരിക്കലും അബദ്ധത്തിൽ
സംഭവിക്കുന്നതല്ല. അബോർട്ട് ചെയ്ത അഭ്യർത്ഥനയാണ് ഏക അപവാദം: കോൾ ചെയ്യുന്നയാളുടെ `signal`
അബോർട്ട് ചെയ്യപ്പെട്ടാൽ, എറർ എറിയുന്ന ഗാർഡ്റെയിൽ ഒഴിവാക്കപ്പെടുന്നതിനുപകരം ഹുക്ക് റൺ
നിരസിക്കപ്പെടുന്നു.

എല്ലാ റൂട്ടുകളിലും എല്ലാ പ്രതികരണങ്ങളിലും ഹുക്കുകൾ പ്രവർത്തിക്കില്ല. ഒരു ഗാർഡ്റെയിലിനെ സുരക്ഷാ
നിയന്ത്രണമായി ആശ്രയിക്കുന്നതിന് മുമ്പ് [പരിരക്ഷാ വ്യാപ്തിയും പരിമിതികളും](#coverage-and-limits)
വായിക്കുക.

## ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ

ഇംപോർട്ട് ചെയ്യുമ്പോൾ രജിസ്ട്രി മുൻഗണനാ ക്രമത്തിൽ ആറ് ഗാർഡ്റെയിലുകൾ സ്വയമേവ ലോഡ് ചെയ്യുന്നു
(`registry.ts` → `registerDefaultGuardrails()` കാണുക):

| മുൻഗണന | പേര്                | ഘട്ടം(ങ്ങൾ)    | ഫയൽ                   |
| ------ | ------------------- | -------------- | --------------------- |
| `5`    | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`    | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`    | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`   | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`   | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`   | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

കുറഞ്ഞ മുൻഗണനാ നമ്പറുകളുള്ളവ **ആദ്യം** പ്രവർത്തിക്കും.

### വിഷൻ ബ്രിഡ്ജ് (`visionBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-1

GLM 5.3 അടിസ്ഥാന മോഡലിനും `glm-5.3-{low,high,max}`-നും വ്യക്തമായ
`supportsVision:false` രജിസ്ട്രി/സ്പെക് മെറ്റാഡാറ്റയുണ്ട്. GLM 5.3 Flash വകഭേദങ്ങൾ
നേറ്റീവ്-വിഷൻ മോഡലുകളായി തുടരുന്നു. Claude Code-ന്റെ `/v1/messages` റൂട്ട്,
Claude-ൽ നിന്ന് OpenAI-ലേക്കുള്ള പരിവർത്തനത്തിന് **മുമ്പ്**, പങ്കിട്ട `handleChat`
പ്രീ-കോൾ ഗാർഡ്റെയിൽ ശൃംഖലയിൽ പ്രവേശിക്കുന്നു; ആ പരിവർത്തനം നെസ്റ്റഡ് `Read`
ടൂൾ-ഫല ചിത്രങ്ങളെ OpenAI `image_url` ഉള്ളടക്കത്തിലേക്ക് ഉയർത്തുന്നതിന് മുമ്പ്,
അവ വിവരിക്കുകയോ കൈകാര്യം ചെയ്യുകയോ വേണം (#17069).

**വിഷൻ പിന്തുണയില്ലാത്ത മോഡലുകളെ** ലക്ഷ്യമിടുന്ന, ചിത്രങ്ങൾ ഉൾക്കൊള്ളുന്ന അഭ്യർത്ഥനകളെ
തടഞ്ഞ്, മുഴുവൻ അഭ്യർത്ഥനയും വിഷൻ ശേഷിയുള്ള മോഡലിലേക്ക് റീറൂട്ട് ചെയ്യുകയോ അപ്സ്ട്രീം
കോളിന് മുമ്പ് കോൺഫിഗർ ചെയ്യാവുന്ന വിഷൻ മോഡൽ സൃഷ്ടിച്ച ടെക്സ്റ്റ് വിവരണങ്ങൾ കൊണ്ട് ചിത്ര
ഭാഗങ്ങൾ മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നു. ഇതിലൂടെ ടെക്സ്റ്റ്-മാത്രം ദാതാക്കൾക്ക് മൾട്ടിമോഡൽ
പേലോഡുകൾ സുതാര്യമായി കൈകാര്യം ചെയ്യാനാകും.

പ്രവാഹം:

1. ലക്ഷ്യ മോഡൽ ഇതിനകം വിഷനെ പിന്തുണയ്ക്കുന്നുവെങ്കിൽ ഒഴിവാക്കുക (അത് നിർബന്ധിത-ബ്രിഡ്ജ്
   പട്ടികയായ `isVisionBridgeForcedModel`-ൽ ഉണ്ടെങ്കിൽ ഒഴികെ).
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) വഴി ചിത്ര ഭാഗങ്ങൾ
   എക്സ്ട്രാക്റ്റ് ചെയ്യുക; ഇത് `open-sse/utils/mediaParts.ts`-ലെ **ഏകീകൃത മീഡിയ
   ഡിറ്റക്ടറായ** `detectMediaParts()`-ലേക്ക് ചുമതല കൈമാറുന്നു — കോംബോ അനുയോജ്യതാ
   ഫിൽട്ടറുമായും പങ്കിടുന്ന ഏക ആധികാരിക ഉറവിടം.
   `replaceImageParts`-ന് തിരികെ ചേർക്കാൻ കഴിയുന്ന രൂപങ്ങളിലേക്ക് മാത്രമാണ്
   എക്സ്ട്രാക്ഷൻ അനുവദിച്ചിരിക്കുന്നത് (extract↔replace കരാർ): OpenAI `image_url`,
   Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`,
   Responses API `input_image`. Claude Code `tool_result.content`-ലും Responses
   ടൂൾ ഔട്ട്പുട്ടുകളിലും നെസ്റ്റ് ചെയ്ത പൊരുത്തപ്പെടുന്ന ചിത്രങ്ങളും എക്സ്ട്രാക്റ്റ് ചെയ്ത്
   അവയുടെ യഥാർത്ഥ പാതകളിൽ മാറ്റിസ്ഥാപിക്കുന്നു; സൂചകം മാത്രമുള്ള രൂപങ്ങൾ കോംബോ-ഫിൽട്ടർ
   മെറ്റീരിയലാണ്, അവ എക്സ്ട്രാക്റ്റ് ചെയ്യില്ല.
   ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. `resolveVisionBridgeRuntimeSettings()` വഴി റൺടൈം കോൺഫിഗ് നിർണ്ണയിക്കുക
   (`src/shared/constants/modalityBridgeDefaults.ts`): പുതിയ `modalityBridge*`
   ക്രമീകരണ കീകൾക്കാണ് മുൻഗണന; പഴയ `visionBridge*` കീകൾ **ഒരു സൈക്കിൾ
   ഫാൾബാക്കായി** (റോൾബാക്ക് വിൻഡോ) തുടരും. ബ്രിഡ്ജ് പ്രവർത്തനരഹിതമാണെങ്കിൽ ഏതെങ്കിലും
   മീഡിയ ട്രാവേഴ്സലിന് മുമ്പ് ഒഴിവാക്കുക.
4. മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`, താഴെയുള്ള പട്ടിക കാണുക) റീറൂട്ട് ചെയ്യണോ
   വിവരിക്കണോ എന്ന് തീരുമാനിക്കുന്നു. റീറൂട്ട് `model` മാത്രം മാറ്റിയ `modifiedPayload`-ഉം,
   `{ rerouted, fromModel, toModel, imagesKept }` മെറ്റായും തിരികെ നൽകുന്നു.
5. വിവരണ പാത: ചിത്രങ്ങളുടെ എണ്ണം `maxImages` ആയി പരിമിതപ്പെടുത്തുക, ടാസ്ക്-അവബോധമുള്ള
   പ്രോംപ്റ്റ് സംയോജിപ്പിക്കുക, വിവരണ കാഷ് പരിശോധിക്കുക, വിഷൻ മോഡലിനെ **സമാന്തരമായി**
   (`Promise.allSettled`) വിളിക്കുക, തുടർന്ന് അവയുടെ സ്ഥാനത്ത് `[Image N]: <description>`
   ടെക്സ്റ്റ് ഭാഗങ്ങൾ ഇൻജക്റ്റ് ചെയ്യുക. പരാജയപ്പെട്ട വിവരണത്തിന് `null` ലഭിക്കും:
   അജ്ഞാതമായ/വിഷൻ ശേഷിയുള്ള ലക്ഷ്യങ്ങൾക്കായി അസംസ്കൃത ചിത്രം നിലനിർത്തും (#4012);
   എന്നാൽ **സ്ഥിരീകരിച്ച ടെക്സ്റ്റ്-മാത്രം നേരിട്ടുള്ള ലക്ഷ്യത്തിനോ** സീറോ-വിഷൻ കോംബോയ്ക്കോ,
   ഭാഗിക പരാജയങ്ങളും വിവരണ-കോൾ പരിധിക്കപ്പുറമുള്ള ചിത്രങ്ങളും ഉൾപ്പെടെ, വിവരണം ലഭിക്കാത്ത
   ഓരോ ചിത്രത്തിനും വ്യക്തമായ `(unavailable — no vision-capable provider connected)`
   ടെക്സ്റ്റ് സ്റ്റബ് ലഭിക്കും (#17069). നിലവിലുള്ള, എല്ലാ വിവരണങ്ങളും പരാജയപ്പെട്ട കോംബോ
   ഫാൾബാക്ക് അതേപടി തുടരും (#8430).
6. `modifiedPayload` + മെറ്റാ (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) തിരികെ നൽകുക.

#### മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`)

| മോഡ്       | സ്വതവേ | പെരുമാറ്റം                                                                                                                                                                                                                                                                                                                           |
| ---------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `auto`     | ✔      | പാരമ്പര്യ ഹ്യൂറിസ്റ്റിക്, മാറ്റമില്ലാതെ (#6640/#7204): നോൺ-കോംബോ/`auto/` മോഡലുകൾ ഏറ്റവും മികച്ച വിഷൻ മോഡലിലേക്ക് റീറൂട്ട് ചെയ്യുന്നു, ഒറിജിനൽ മോഡലിന് ഇതിനകം ഉപയോഗയോഗ്യമായ ക്രെഡൻഷ്യലുകൾ ഉണ്ടെങ്കിൽ ഒഴികെ (അപ്പോൾ വിവരണം നൽകുന്നു); കോംബോ ലക്ഷ്യങ്ങൾ എപ്പോഴും വിവരണം നൽകുന്നു.                                                       |
| `describe` |        | എപ്പോഴും വിവരണം നൽകുന്നു — റീറൂട്ട് ബ്ലോക്ക് പൂർണ്ണമായും ഒഴിവാക്കപ്പെടുന്നു; ഉപയോക്താവ് തിരഞ്ഞെടുത്ത മോഡൽ എപ്പോഴും ഉത്തരം നൽകുന്നു.                                                                                                                                                                                                  |
| `reroute`  |        | റീറൂട്ട് നിർബന്ധമാക്കുക: keep-credentialed-model ഗാർഡ് ഒഴിവാക്കപ്പെടുന്നു. റീറൂട്ട്-**ടാർഗെറ്റ്** ക്രെഡൻഷ്യൽ ഗാർഡ് ഇപ്പോഴും ബാധകമാണ് — ഉപയോഗയോഗ്യമായ വിഷൻ ടാർഗെറ്റ് ഇല്ലാത്തപ്പോൾ, ബ്രിഡ്ജ് വിവരണം നൽകുകയോ അസംസ്കൃത ഇമേജുകൾ ടെക്സ്റ്റ്-ഒൺലി ടാർഗെറ്റിലേക്ക് അയയ്ക്കുകയോ ചെയ്യുന്നതിനുപകരം വ്യക്തമായ ഒരു പിശകോടെ ബ്ലോക്ക് ചെയ്യുന്നു. |

നിർബന്ധിത മോഡുകൾ auto ഹ്യൂറിസ്റ്റിക് പ്രവർത്തിക്കുന്നതിന് **മുമ്പ്** ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു; `auto` പെരുമാറ്റം pre-PR-1 ഗാർഡ്റെയിലിന് ബൈറ്റ്-ഐഡന്റിക്കൽ ആണ്.

#### API-കീ പരിധി (`visionBridgeKeyScope.ts`)

വിളിക്കുന്നയാളുടെ API കീ `allowedConnections`, ക്വോട്ട പൂളുകൾ (`allowedQuotas`) അല്ലെങ്കിൽ മോഡലുകൾ (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) എന്നിവ നിയന്ത്രിക്കുമ്പോൾ, കീ ഉപയോഗിക്കാൻ അനുവദിക്കുന്ന കണക്ഷനുകളിൽ, കീ ഉപയോഗിക്കാവുന്ന റീറൂട്ട്, വിവരണ മോഡലുകൾ മാത്രമേ ബ്രിഡ്ജ് തിരഞ്ഞെടുക്കൂ. അപ്പോൾ വിവരണ കോൾ എപ്പോഴും `x-omniroute-self-loop-key-id` ഹെഡറോടുകൂടി OmniRoute self-loop വഴി പോകുന്നു; അതിനാൽ സ്വീകരിക്കുന്ന ചാറ്റ് അഭ്യർത്ഥന ആ കീയുടെ കണക്ഷൻ, മോഡൽ നയം വീണ്ടും നടപ്പിലാക്കുന്നു. `enforceApiKeyPolicy()` ആ ഹെഡറിനെ self-loop bearer-നോടൊപ്പം മാത്രമേ പരിഗണിക്കൂ; അതിനാൽ അത് ആക്സസ് ഇടുക്കാൻ മാത്രമേ കഴിയൂ, റിസോൾവ് ചെയ്യാത്ത ഒരു id നിരസിക്കപ്പെടുന്നു.

കീയ്ക്ക് വിഷൻ മോഡൽ അനുവദനീയമല്ലെങ്കിൽ, **സ്ഥിരീകരിച്ച ടെക്സ്റ്റ്-ഒൺലി ടാർഗെറ്റ്** ഇമേജ് ബൈറ്റുകൾ കഴിവില്ലാത്ത അപ്സ്ട്രീമിലേക്ക് കൈമാറുന്നതിനുപകരം വ്യക്തമായ HTTP 400-നൊപ്പം ഇമേജ് അഭ്യർത്ഥന ലോക്കലായി നിരസിക്കുന്നു (#17069). അജ്ഞാതമോ നേറ്റീവ് വിഷൻ കഴിവോ ഉള്ള ടാർഗെറ്റുകൾക്ക്, വിവരണ പാത അതിന്റെ മുൻ fail-open പെരുമാറ്റം നിലനിർത്തുന്നു (meta `{ skipped: true, reason: "no_permitted_vision_model" }`). കീ ഇല്ലാത്ത അഭ്യർത്ഥനകളും ഈ നിയന്ത്രണങ്ങളില്ലാത്ത കീകളും മുമ്പത്തെപ്പോലെത്തന്നെ പ്രവർത്തിക്കുന്നു.

#### ടാസ്ക്-അവേയർ വിവരണ പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

സ്വതവേ **true**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) അടിസ്ഥാന വിവരണ പ്രോംപ്റ്റിലേക്ക് **അവസാന ഉപയോക്തൃ സന്ദേശത്തിന്റെ** വാചകം (500 പ്രതീകങ്ങളായി ചുരുക്കി) ചേർക്കുന്നു, ഉപയോക്താവ് യഥാർത്ഥത്തിൽ ചോദിച്ചതിലേക്ക് വിവരണത്തെ നയിക്കുകയും (codex-vision-proxy പാറ്റേൺ) കാണുന്ന വാചകം ട്രാൻസ്ക്രൈബ് ചെയ്യാൻ വിഷൻ മോഡലിനോട് ആവശ്യപ്പെടുകയും ചെയ്യുന്നു. ഫ്ലാഗ് ഓഫ് ആണെങ്കിൽ — അല്ലെങ്കിൽ ഉപയോക്തൃ വാചകം ഇല്ലെങ്കിൽ — അടിസ്ഥാന പ്രോംപ്റ്റ് മാറ്റമില്ലാതെ ഉപയോഗിക്കുന്നു.

വിവരണ self-loop-ന്റെ സ്വന്തം OpenAI-അനുയോജ്യമായ അഭ്യർത്ഥന (`callVisionModelSingle()` in `visionBridgeHelpers.ts`) എപ്പോഴും `image_url.detail: "high"` അഭ്യർത്ഥിക്കുന്നു — നിരുപാധികം, എല്ലാ വിളിക്കുന്നയാൾക്കും/പ്രൊവൈഡർക്കും, ഏതെങ്കിലും ക്ലയന്റ് സിഗ്നലിനെ ആശ്രയിച്ചല്ല. ഈ പ്രോംപ്റ്റ് ആവശ്യപ്പെടുന്ന കൃത്യമായ ടെക്സ്റ്റ്-ട്രാൻസ്ക്രിപ്ഷൻ ടാസ്കിന് low-detail സാമ്പ്ലിംഗ് OCR കൃത്യത കുറയ്ക്കുന്നു, അതിനാൽ വിവരണ കോൾ തന്നെ ഒറിജിനൽ inbound അഭ്യർത്ഥന ഉപയോഗിച്ച detail ലെവൽ എന്തായിരുന്നാലും എപ്പോഴും high detail ആവശ്യപ്പെടുന്നു. ഇത് ആന്തരിക വിവരണ അഭ്യർത്ഥന ബോഡിയെ മാത്രം ബാധിക്കുന്നു; പ്രൈമറി അഭ്യർത്ഥനയിൽ OmniRoute വിളിക്കുന്നയാളുടെ സ്വന്തം `image_url.detail` എങ്ങനെ കൈമാറുന്നു എന്നത് ഇത് മാറ്റുന്നില്ല — ആ ഡിഫോൾട്ട് വെവ്വേറെയാണ് പ്രയോഗിക്കുന്നത്, കണ്ടെത്തിയ OpenCode ക്ലയന്റുകൾക്ക് മാത്രം, `defaultImageDetail()`-ൽ (`open-sse/handlers/chatCore/upstreamBody.ts`). വിവരണ self-loop-ന്റെ Anthropic wire-format ബ്രാഞ്ചിന് `detail` ഫീൽഡ് ഇല്ല, രണ്ട് ഡിഫോൾട്ടുകളിൽ ഏതിനാലും ബാധിക്കപ്പെടുന്നില്ല.

#### വിവരണ ഔട്ട്പുട്ട് പരിധി (`modalityBridgeVisionMaxChars`)

| കീ                             | സ്വതവേ | പരിധി                    |
| ------------------------------ | ------ | ------------------------ |
| `modalityBridgeVisionMaxChars` | `0`    | `0` അല്ലെങ്കിൽ 100–50000 |

`0` (സ്വതവേ) **പരിധിയില്ല** എന്നാണ് അർത്ഥമാക്കുന്നത് — `callVisionModel()` തിരികെ നൽകുന്ന വിവരണം മാറ്റമില്ലാതെ കൈമാറുന്നു, നിലവിലുള്ള പെരുമാറ്റം നിലനിർത്തുന്നു. 100–50000 പരിധിയിലുള്ള ഏത് മൂല്യവും വിവരണം `…` സഫിക്സോടെ ചുരുക്കുന്നു, അതിനുശേഷം അത് `[Image N]: <description>` ആയി തിരികെ ചേർക്കുന്നു (`VisionBridgeGuardrail.preCall()` എന്നത് `src/lib/guardrails/visionBridge.ts`-ൽ). downstream മോഡലിന് പൂർണ്ണ ട്രാൻസ്ക്രിപ്ഷൻ ആവശ്യമുള്ള detail-heavy OCR ടാസ്കുകൾക്ക് ഇത് വർദ്ധിപ്പിക്കുക; ചാറ്റി വിഷൻ മോഡലുകളിൽ ടോക്കൺ ഉപയോഗം പരിമിതപ്പെടുത്താൻ ഇത് കുറയ്ക്കുക. ഡാഷ്ബോർഡ് ഫീൽഡ് Vision ടാബിന്റെ Advanced പാനലിലാണ് (`modality-bridge-max-chars` എന്നത് `ModalityBridgeVisionTab.tsx`-ൽ), കൂടാതെ 1-നും 99-നും ഇടയിലുള്ള ഏത് മൂല്യവും 100 ഫ്ലോർ വരെ ക്ലാമ്പ് ചെയ്യുന്നു, അതേസമയം വ്യക്തമായ `0` മാറ്റമില്ലാതെ വിടുന്നു — `0` അതിന്റെതന്നെ അർത്ഥത്തിൽ സാധുവായ ഒരു Zod മൂല്യമാണ് (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), "unset" ഡിഫോൾട്ട് മാത്രമല്ല.

#### വിവരണ കാഷെ (`modalityBridge/bridgeCache.ts`)

വിവരണ ഔട്ട്പുട്ടുകൾക്കായുള്ള ഇൻ-മെമ്മറി LRU + TTL കാഷെ, പ്രോസസ്സ് മുഴുവൻ പങ്കിടുന്നു. കീ = `sha256(imageRef + composedPrompt + configuredBridgeModel)`, length-prefix ഫ്രെയിമിംഗോടുകൂടി (ഫീൽഡ്-ബൗണ്ടറി കൂട്ടിയിടികൾ ഇല്ല). മോഡൽ ഘടകം **കോൺഫിഗർ ചെയ്ത** ബ്രിഡ്ജ് മോഡലാണ്, യഥാർത്ഥത്തിൽ ഉത്തരം നൽകിയ മോഡലല്ല — `callVisionModel` ആന്തരികമായി ഫാൾബാക്ക് ചെയ്തേക്കാം, ഓരോ ശ്രമത്തിനും കീ നൽകുന്നത് കാഷെ ശകലീകരിക്കും. പരാജയപ്പെട്ട വിവരണങ്ങൾ ഒരിക്കലും കാഷെ ചെയ്യപ്പെടുന്നില്ല. ക്രമീകരണങ്ങൾ:

| കീ                              | സ്വതവേ | പരിധി   |
| ------------------------------- | ------ | ------- |
| `modalityBridgeCacheEnabled`    | `true` | —       |
| `modalityBridgeCacheTtlMinutes` | `60`   | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`  | 10–5000 |

(`ensureBase64ImagesForClaudeWire`) എന്നിവയിൽ, രണ്ടിലും
`visionBridgeHelpers.ts`-ലെ `fetchRemoteImageAsDataUri()` വഴി — ലഭിക്കുന്ന data
URI, vision-model അഭ്യർത്ഥനയിൽ ഉൾച്ചേർക്കുന്നതിന് മുമ്പ് `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) വഴി കടത്തിവിടുന്നു. അമിത വലുപ്പമുള്ള
ഇമേജുകൾ **2048px നീളമുള്ള അരികിലേക്ക്** ഡൗൺസ്കെയിൽ ചെയ്യുന്നു (OpenAI/Anthropic
ഇതിനകം server-side-ൽ പ്രയോഗിക്കുന്ന resize പരിധിയുമായി പൊരുത്തപ്പെടുന്നു);
ഇത് vision മോഡൽ കാണുന്നതിൽ മാറ്റം വരുത്താതെ upload bytes/latency കുറയ്ക്കുന്നു.
റീസൈസിംഗിന് dynamic import വഴി ലോഡ് ചെയ്യുന്ന `sharp` ഉപയോഗിക്കുന്നു: അതിന്റെ
native binary ലോഡ് ചെയ്യുന്നതിൽ പരാജയപ്പെടുന്ന ഒരു പ്ലാറ്റ്ഫോമിൽ,
`normalizeDataUri()` **ഒരിക്കലും exception എറിയില്ല** — അത് യഥാർത്ഥ bytes
മാറ്റമില്ലാതെ കടത്തിവിടുന്നതിലേക്ക് fallback ചെയ്യുന്നു; അതിനാൽ
describe/base64-conversion പാത എപ്പോഴും പ്രവർത്തിച്ചുകൊണ്ടിരിക്കും. ഇമേജ്
അല്ലാത്ത bytes-ഉം (ഡീകോഡ് ചെയ്യാവുന്ന ഒരു ഇമേജ് തിരികെ നൽകാത്ത fetch) മാറ്റമില്ലാതെ
കടത്തിവിടുന്നു. ബ്രിഡ്ജ് സ്വന്തം self-call-നായി ഫെച്ച് ചെയ്യുന്ന ഇമേജുകൾക്ക്
മാത്രമാണ് ഈ normalization ബാധകമാകുന്നത് — caller-ന്റെ raw passthrough
payload-ന് ഇത് ഒരിക്കലും പ്രയോഗിക്കില്ല; ഇത് opt-in-only mutation തത്ത്വവുമായി
(Hard Rule #20) പൊരുത്തപ്പെടുന്നു.

#### ഡാഷ്ബോർഡ് കോൺഫിഗറേഷൻ

പ്രത്യേക dashboard പേജ്
`/dashboard/settings/modality-bridge` ആണ്. URL വഴി നേരിട്ട് അഭിസംബോധന
ചെയ്യാവുന്ന അതിലെ `Vision`, `Audio`, `Video` ടാബുകൾ `tab` മൂല്യം മാറ്റുമ്പോൾ
query parameters നിലനിർത്തുന്നു. Vision ടാബിൽ enablement, mode, model
selection (automatic default ഉൾപ്പെടെ), task-aware prompting, advanced
timeout/image/description-length/cache പരിധികൾ, runtime counters, കൂടാതെ
സംരക്ഷിതമായ ഒരു sample request എന്നിവ ലഭ്യമാണ്. Audio ടാബും പ്രവർത്തനസജ്ജമാണ്:
അതിൽ enablement, Auto ഉൾപ്പെടെയുള്ള STT-only model picker,
timeout/max-clip പരിധികൾ, audio counters, കൂടാതെ ഒരു `input_audio` sample test
എന്നിവ ലഭ്യമാണ്. Video ടാബ് പൂർണ്ണമായി പ്രവർത്തിക്കുന്നു: അത് FFmpeg/ffprobe
runtime നില റിപ്പോർട്ട് ചെയ്യുന്നു — നാല് വ്യക്തമായ UI നിലകളിൽ ഒന്ന്
(`unknown`, probe പുരോഗമിക്കുമ്പോഴോ പൂർത്തിയാക്കാൻ കഴിയാതിരിക്കുമ്പോഴോ;
`restricted`, client-side-ൽ probe ഒഴിവാക്കുന്ന non-loopback dashboard
host-ൽ; `unavailable`, probe ചെയ്ത ശേഷം ലഭ്യമല്ലെന്ന് സ്ഥിരീകരിക്കുമ്പോൾ;
അല്ലെങ്കിൽ FFmpeg/ffprobe version-ുകളോടെ `available`) — enable/model/frame/video/timeout
പരിധികൾ persist ചെയ്യുന്നു, model picker-നെ vision-capable മോഡലുകളിലേക്ക്
filter ചെയ്യുന്നു, കൂടാതെ video counters ലഭ്യമാക്കുന്നു.

AI settings-ന് കീഴിലുണ്ടായിരുന്ന പഴയ Vision Bridge card ഇപ്പോൾ പുതിയ
പേജിലേക്കുള്ള compatibility link ആണ്; form-ന്റെ രണ്ടാമത്തെ പകർപ്പ് ഇനി അതിൽ
ഇല്ല. നിലവിലുള്ള Speech-to-Text playground നീക്കം ചെയ്യാതെ, Media Providers
എന്നത് Image-to-Text, Speech-to-Text workflows എന്നിവയെ ബന്ധപ്പെട്ട Modality
Bridge ടാബുകളിലേക്ക് link ചെയ്യുകയും ചെയ്യുന്നു.

**Self-loop admission bypass:** describe call OmniRoute-ന്റെ സ്വന്തം `/v1`
self-loop വഴി route ചെയ്യുമ്പോൾ (non-standard provider model), sub-request
`x-omniroute-admission-bypass: internal` അയയ്ക്കുകയും resolve ചെയ്ത self-loop
credential ഉപയോഗിച്ച് authenticate ചെയ്യുകയും ചെയ്യുന്നു — local mode-ൽ
local `sk_omniroute` sentinel, അല്ലെങ്കിൽ operator configure ചെയ്ത
`OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env key (#1350); അതിനാൽ
`REQUIRE_API_KEY=true` deployments-നും describe call പ്രവർത്തിപ്പിക്കാൻ കഴിയും.
കൃത്യമായി ആ credentials-ന് മാത്രമാണ് bypass അനുവദിക്കുന്നത്; അതിനാൽ external
clients-ന് admission ഒഴിവാക്കാൻ ഈ header ഉപയോഗിക്കാനാവില്ല.

പഴയ defaults `src/shared/constants/visionBridgeDefaults.ts`-ൽ നിലനിൽക്കുന്നു;
പുതിയ mode/task-aware/cache defaults-ഉം settings resolver-ഉം
`src/shared/constants/modalityBridgeDefaults.ts`-ൽ നിലനിൽക്കുന്നു. Tests-ന്
വ്യാജ `getSettings`, `callVisionModel` implementations inject ചെയ്യാൻ
കഴിയുന്നവിധം guardrail ഒരു `deps` constructor option ലഭ്യമാക്കുന്നു.

### Audio Bridge (`audioBridge.ts`) — Modality Bridge PR-3

Audio input സ്വീകരിക്കുമെന്ന് അറിയപ്പെടാത്ത ഒരു target-ൽ എത്തുന്നതിന് മുമ്പ്,
audio ഉൾപ്പെട്ട chat requests intercept ചെയ്യുന്നു. ഇത് chat request ഒരിക്കലും
reroute ചെയ്യുന്നില്ല: നിലവിലുള്ള OpenAI-compatible multipart endpoint വഴി
audio parts transcribe ചെയ്യപ്പെടുന്നു, തുടർന്ന് തിരഞ്ഞെടുത്ത chat model text
transcripts ഉപയോഗിച്ച് തുടരുന്നു.

ഒഴുക്ക്:

1. `getResolvedModelCapabilities()` വഴി `supportsAudio` പരിഹരിക്കുക. വ്യക്തമായി നൽകിയ
   provider-registry മെറ്റാഡാറ്റയ്ക്കാണ് മുൻഗണന; തുടർന്ന് സ്റ്റാറ്റിക് മോഡൽ മെറ്റാഡാറ്റയ്ക്കും, അതിനുശേഷം സമന്വയിപ്പിച്ച
   `modalities_input`-നും. `audio` ഇല്ലാത്ത പ്രഖ്യാപിത ഇൻപുട്ട് ലിസ്റ്റ് `false` ആണ്; ശേഷി സംബന്ധിച്ച
   തെളിവുകളൊന്നുമില്ലെങ്കിൽ `null` ആണ്. `false`, `null` എന്നിവ രണ്ടും
   യാഥാസ്ഥിതിക ബ്രിഡ്ജ് സജീവമാക്കുന്നു; `true` അതിനെ മറികടക്കുന്നു.
2. `modalityBridgeAudio*` ക്രമീകരണങ്ങൾ പരിഹരിച്ച്, പങ്കിട്ട `detectMediaParts()`
   ഡിറ്റക്ടർ വഴി എല്ലാ സന്ദേശങ്ങളിൽനിന്നും സ്പ്ലൈസ് ചെയ്യാവുന്ന ടോപ്പ്-ലെവൽ ഓഡിയോ ഭാഗങ്ങൾ വേർതിരിച്ചെടുക്കുക.
   പിന്തുണയ്ക്കുന്ന വയർ രൂപങ്ങൾ OpenAI `input_audio`, `audio_url`, കൂടാതെ
   `source.media_type: "audio/*"` എന്നിവയാണ്. നെസ്റ്റഡ് ഓഡിയോ റൂട്ടിംഗിനായി കണ്ടെത്തുമെങ്കിലും
   സ്പ്ലൈസ് പാത അത് നീക്കം ചെയ്യില്ല. പ്രവർത്തനം `modalityBridgeAudioMaxClips` ഉപയോഗിച്ച്
   പരിമിതപ്പെടുത്തുന്നു; പിന്നീടുള്ള ഭാഗങ്ങൾ മാറ്റമില്ലാതെ തുടരും.
3. കോൺഫിഗർ ചെയ്ത `provider/model` മാനിക്കുക; അല്ലെങ്കിൽ `selectAudioBridgeModel()`-നെ
   സ്ഥിരതയുള്ള കാറ്റലോഗ് ക്രമത്തിൽ `AUDIO_TRANSCRIPTION_PROVIDERS` പരിശോധിച്ച് ഉപയോഗയോഗ്യമായ
   സജീവ പ്രൊവൈഡർ ക്രെഡൻഷ്യൽ ഉള്ള ആദ്യ മോഡൽ തിരഞ്ഞെടുക്കാൻ അനുവദിക്കുക.
4. `callAudioTranscription()` base64/data-URI ഓഡിയോയെ മൾട്ടിപാർട്ട്
   `file` ആക്കി മാറ്റുന്നു; അല്ലെങ്കിൽ DNS പിന്നിംഗും 25 MB പരിധിയുമുള്ള, പൊതു ലക്ഷ്യങ്ങൾ മാത്രം
   അനുവദിക്കുന്ന ഔട്ട്ബൗണ്ട് ഗാർഡ് വഴി റിമോട്ട് `audio_url` ഡൗൺലോഡ് ചെയ്യുന്നു. തുടർന്ന് അത് ഫയലും
   തിരഞ്ഞെടുത്ത മോഡലും പ്രാദേശിക `/v1/audio/transcriptions` സെൽഫ്-ലൂപ്പിലേക്ക് POST ചെയ്യുന്നു;
   `resolveSelfLoopBearer()` ഉപയോഗിച്ചാണ് പ്രാമാണീകരണം. നിലവിലുള്ള ട്രാൻസ്ക്രിപ്ഷൻ റൂട്ട് സാധാരണ
   ക്രെഡൻഷ്യൽ ലുക്കപ്പ്, കൂൾഡൗൺ/നിരക്ക്-പരിധി കൈകാര്യം ചെയ്യൽ, പ്രൊവൈഡർ ഡിസ്പാച്ച് എന്നിവ നിർവഹിക്കുന്നു.
5. വിജയകരമായ കോളുകൾ അവയുടെ ഭാഗങ്ങളെ `[Audio N]: <transcript>` ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു.
   കോളുകൾ `Promise.allSettled` ഉപയോഗിച്ച് പ്രവർത്തിക്കുന്നു: ഒറ്റപ്പെട്ട ഒരു പരാജയം ആ യഥാർത്ഥ
   ഓഡിയോ ഭാഗം നിലനിർത്തുന്നു (#4012 കരാർ). എല്ലാ കോളുകളും പരാജയപ്പെടുകയും ലക്ഷ്യം
   `supportsAudio === false` ആണെന്ന് തെളിയിക്കപ്പെടുകയും ചെയ്താൽ, ഭാഗങ്ങൾ
   `[Audio N]: (unavailable — no STT provider connected)` ആയി മാറുന്നു (#8430 കരാർ).
   അജ്ഞാത ലക്ഷ്യത്തിന് (`null`), എല്ലാം പരാജയപ്പെടുന്ന ഫലം മാറ്റമില്ലാതെ തുടരും. ഉപയോഗയോഗ്യമായ
   STT ക്രെഡൻഷ്യൽ ഇല്ലാത്ത, ടെക്സ്റ്റ് മാത്രം പിന്തുണയ്ക്കുന്നുവെന്ന് തെളിയിക്കപ്പെട്ട ലക്ഷ്യത്തിന്,
   നെറ്റ്വർക്ക് കോൾ നടത്താതെ അതേ വ്യക്തമായ സ്റ്റബ് ലഭിക്കുന്നു.

വിജയകരമായ ട്രാൻസ്ക്രിപ്റ്റുകൾ പ്രോസസ്-വ്യാപകമായ Modality Bridge LRU/TTL കാഷ് ഉപയോഗിക്കുന്നു.
കീയിൽ ഓഡിയോ റഫറൻസ്, സ്ഥിരതയുള്ള `audio-transcription` ഓപ്പറേഷൻ ലേബൽ,
തിരഞ്ഞെടുത്ത STT മോഡൽ എന്നിവ സംയോജിപ്പിക്കുന്നു; പരാജയങ്ങൾ ഒരിക്കലും കാഷ് ചെയ്യില്ല. ഓഡിയോ ശ്രമങ്ങൾ
പങ്കിട്ട `bridged`, `cacheHits`, `failures`, `lastUsedAt` കൗണ്ടറുകൾ അപ്ഡേറ്റ് ചെയ്യുന്നു.
പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങളിൽ
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ഉൾപ്പെടുന്നു; മാറ്റമില്ലാത്ത
അഭ്യർത്ഥനകൾക്ക് Audio Bridge സെഗ്മെന്റ് ലഭിക്കില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB പിന്തുണയുള്ളതും Zod ഉപയോഗിച്ച് സാധൂകരിക്കുന്നതുമാണ്:

| കീ                            | ഡിഫോൾട്ട് | പരിധി                   |
| ----------------------------- | --------- | ----------------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —                       |
| `modalityBridgeAudioModel`    | `""`      | ഓട്ടോ അല്ലെങ്കിൽ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000             |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10                    |

പങ്കിട്ട കാഷ് ഇപ്പോഴും `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാൽ നിയന്ത്രിക്കപ്പെടുന്നു.

### വീഡിയോ ബ്രിഡ്ജ് (`videoBridge.ts`, `videoBridgePipeline.ts`)

നേറ്റീവ് വീഡിയോ പിന്തുണയുണ്ടെന്ന് അറിയാത്ത ഒരു ലക്ഷ്യം വിളിക്കുന്നതിന് മുമ്പ്, Chat Completions
`messages`-ലെയും Responses API `input`-ലെയും ടോപ്പ്-ലെവൽ വീഡിയോ ഭാഗങ്ങളെ തടഞ്ഞ് കൈകാര്യം ചെയ്യുന്നു.
പിന്തുണയ്ക്കുന്ന രൂപങ്ങൾ `input_video`, `video_url`, `video_source`, HTTPS URL-കൾ,
കൂടാതെ `data:video/*;base64,...` data URI-കൾ എന്നിവയാണ്. ടെക്സ്റ്റിലുള്ള സാധാരണ ഫയൽനാമങ്ങൾ
വീഡിയോയായി പരിഗണിക്കില്ല.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) അഭ്യർത്ഥന ട്രാവേഴ്സൽ,
ശേഷി/നയ പരിശോധന, ഓരോ അഭ്യർത്ഥനയുടെയും അഗ്രിഗേഷൻ, പ്രതികരണ പേലോഡ് എന്നിവയുടെ ചുമതല വഹിക്കുന്നു.
ഓരോ വീഡിയോയ്ക്കുമുള്ള പ്രവർത്തനം — സമാഹരണം, പൂർണ്ണ-ഫല കാഷ്, ഫ്രെയിം ശ്രേണി വിവരിക്കൽ
(കോളർ പ്രഖ്യാപിച്ച ഏതെങ്കിലും ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റ് ഇതിൽ സംയോജിപ്പിക്കുന്നു), ഓരോ ശ്രമത്തിന്റെയും
മെട്രിക്സ്/അബോർട്ട്/ക്ലീനപ്പ് — `videoBridgePipeline.ts`-ലെ `processVideoPart`-ന് പിന്നിൽ
മറച്ചിരിക്കുന്നു; `preCall`-ന്റെ ലൂപ്പിനുള്ളിൽ ഓരോ വീഡിയോ ഭാഗത്തിനും ഒരിക്കൽ വീതം ഇത് വിളിക്കുന്നു.
ആ മൊഡ്യൂൾ വ്യക്തമായ പോർട്ട് അതിരുകളായ `VideoMediaBrokerPort`
(ബൈറ്റുകൾ സമാഹരിക്കുകയും സാമ്പിൾ ചെയ്ത ഫ്രെയിമുകൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുകയും ചെയ്യുന്നു),
`VideoAudioTranscriptionPort` (കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റിനെ സാമ്പിൾ ചെയ്ത
ക്യാപ്ഷനുകളുമായി സംയോജിപ്പിക്കുന്നു), `VideoDrilldownPort` (ഫ്രെയിം ഡ്രിൽ-ഡൗൺ പെർസിസ്റ്റൻസ് അതിർത്തി;
ഇത് ഇതുവരെ `processVideoPart`-ലേക്ക് വയർ ചെയ്തിട്ടില്ല — നിലവിൽ വേറിട്ട
`/api/modality-bridge/video/drilldown` റൂട്ട് മാത്രമാണ് ഡ്രിൽ-ഡൗൺ എൻട്രികൾ എഴുതുന്നത്) എന്നിവയും നിർവചിക്കുന്നു.

പൊതുവായ `/v1` അഭ്യർത്ഥന പാത ഒരിക്കലും ഒരു സബ്പ്രോസസ് ഇമ്പോർട്ട് ചെയ്യുകയോ ഇൻവോക്ക് ചെയ്യുകയോ ഇല്ല.
റിമോട്ട് വീഡിയോകൾ 50 MiB പരിധിയിൽ ഡൗൺലോഡ് ചെയ്യുന്നു; ഇൻലൈൻ base64 വീഡിയോകൾക്ക്, ഓരോ വീഡിയോയ്ക്കും
യാഥാസ്ഥിതികമായ 36 MiB ഡീകോഡ് ചെയ്ത പരിധിയുണ്ട്, അതിനാൽ മോഡൽ/സന്ദേശങ്ങൾ/ഫ്രെയ്മിംഗ് എൻവലപ്പ്
50 MiB എന്ന പൊതു JSON അഭ്യർത്ഥന അഡ്മിഷൻ പരിധിക്കുള്ളിൽ നിലനിർത്താനാകും. അലോക്കേഷനു മുമ്പ്
ഇൻലൈൻ നീളവും ഡീകോഡ് ചെയ്ത വലുപ്പത്തിന്റെ എസ്റ്റിമേറ്റുകളും പരിശോധിക്കുന്നു. പ്രാരംഭ റിമോട്ട് URL-ലും
എല്ലാ റീഡയറക്ടുകളിലും HTTPS നിർബന്ധമാണ്; ഇതിനായി DNS പിന്നിംഗുള്ള, നിലവിലുള്ള പൊതു ലക്ഷ്യങ്ങൾ മാത്രം
അനുവദിക്കുന്ന ഔട്ട്ബൗണ്ട് ഗാർഡ് ഉപയോഗിക്കുന്നു. തുടർന്ന് ബൈറ്റുകൾ കൃത്യമായ ആന്തരിക
`POST /api/modality-bridge/video/extract` ബ്രോക്കർ അതിർത്തി കടക്കുന്നു. ആ റൂട്ട്
`LOCAL_ONLY`-യും `SPAWN_CAPABLE`-യും ആണ്; ഓരോ പ്രോസസിനും പ്രത്യേകം പ്രാമാണീകരിച്ച,
വിശ്വസനീയമായ ലൂപ്പ്ബാക്ക് അഭ്യർത്ഥനകൾ മാത്രം അത് സ്വീകരിക്കുന്നു, കൂടാതെ URL, ഫയൽസിസ്റ്റം പാത,
എക്സിക്യൂട്ടബിൾ, അല്ലെങ്കിൽ ആർഗ്യുമെന്റ് ലിസ്റ്റ് എന്നിവ ഒരിക്കലും സ്വീകരിക്കില്ല. API ബോഡി-വലുപ്പ
പൈപ്പ്ലൈനും ഹാൻഡ്ലറിന്റെ ഇൻക്രിമെന്റൽ ബോഡി റീഡറും സ്വതന്ത്രമായി 50 MiB ബ്രോക്കർ ഇൻപുട്ട് പരിധി
നടപ്പാക്കുന്നു. അതിന്റെ പരിധിയുള്ള ക്യൂ ഒരേസമയം ഒരു എക്സ്ട്രാക്ഷൻ പ്രവർത്തിപ്പിക്കുന്നു, ശേഷിക്കുന്ന
നാല് ജോലികൾ അനുവദിക്കുന്നു, ശേഷിക്കുന്ന ഇൻപുട്ട് 100 MiB ആയി പരിമിതപ്പെടുത്തുന്നു.

ബ്രോക്കറിനുള്ളിൽ, `ffprobe` ഒരു സ്വകാര്യ ലോക്കൽ ഫയൽ വായിക്കുന്നു; നിശ്ചിത ഫോർമാറ്റ് അനുവദനീയപ്പട്ടിക പ്ലേലിസ്റ്റ്, മാനിഫെസ്റ്റ് ഫോർമാറ്റുകൾ ഒഴിവാക്കുന്നു. അനുവദിച്ച MOV-കുടുംബ കണ്ടെയ്നറുകൾക്ക്, ബാഹ്യ MOV ഡാറ്റാ റഫറൻസുകൾ സ്വതവേ പ്രവർത്തനരഹിതമായി തുടരുന്നു, നിശ്ചിത കമാൻഡ് അവയ്ക്ക് ഒപ്റ്റ്-ഇൻ ചെയ്യുന്നുമില്ല. `ffprobe`-ഉം `ffmpeg`-ഉം `file`-മാത്രം പ്രോട്ടോക്കോൾ വൈറ്റ്ലിസ്റ്റ്, ഒരു ത്രെഡ്, നിശ്ചിത ആർഗ്യുമെന്റ് അറേകൾ, ഷെൽ ഇല്ല, കൂടാതെ `PATH`-ൽ നിന്ന് റിസോൾവ് ചെയ്യുന്ന എക്സിക്യൂട്ടബിളുകൾ എന്നിവ ഉപയോഗിക്കുന്നു. അറ്റാച്ച്ഡ്-പിക്ചർ കവർ സ്ട്രീമുകൾ പ്ലേ ചെയ്യാവുന്ന സ്ഥാനാർത്ഥികളല്ല. എല്ലാ പ്ലേ ചെയ്യാവുന്ന സ്ട്രീമുകളും പരിധികൾ പാലിക്കണം, കൂടാതെ നിർണ്ണയാത്മകമായ ഏറ്റവും കുറഞ്ഞ-ഇൻഡക്സ് ഫാൾബാക്കിന് മുമ്പ് വ്യക്തമായ ഡീഫോൾട്ട് സ്ട്രീമിന് മുൻഗണന നൽകുന്നു. വീഡിയോകൾ 600 സെക്കൻഡ്, ഓരോ വിമാനത്തിലും 8,192 പിക്സൽ, 33,554,432 സ്രോതസ്സ് പിക്സൽ എന്നിവയിൽ പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. FFmpeg 1–16 മിഡ്പോയിന്റ് JPEG ഫ്രെയിമുകൾ സാമ്പിൾ ചെയ്യുന്നു, ചെറിയ ഇൻപുട്ടുകൾ അപ്സ്കെയിൽ ചെയ്യാതെ നീളമുള്ള അറ്റം പരമാവധി 1,024 പിക്സലിലേക്ക് ചുരുക്കുന്നു, ഒരിക്കലും URL സ്വീകരിക്കുന്നില്ല. സാമ്പ്ലിംഗ് സ്വതവേ `uniform` ആണ്. ഓപ്ഷണൽ `scene_aware`, പരീക്ഷണാത്മക `segment_aware` പോളിസികൾ ഇതിനകം സാധുവാക്കിയ ലോക്കൽ സ്ട്രീമിന് മേൽ ഒരു അധിക നിശ്ചിത FFmpeg പാസ് നടത്തുന്നു, പരിമിതപ്പെടുത്തിയ `showinfo` രംഗ ടൈംസ്റ്റാമ്പുകൾ തിരഞ്ഞെടുക്കുന്നു, ഡിറ്റക്ടർ പരാജയം, ടൈംഔട്ട്, വികലമായ ഔട്ട്പുട്ട്, അല്ലെങ്കിൽ ശൂന്യമായ സ്ഥാനാർത്ഥി സെറ്റ് എന്നിവയിൽ അതേ യൂണിഫോം മിഡ്പോയിന്റുകളിലേക്ക് നിർണ്ണയാത്മകമായി ഫാൾബാക്ക് ചെയ്യുന്നു. സെഗ്മെന്റ്-അവെയർ മോഡ് മിഡ്പോയിന്റ് സാമ്പിളുകൾ സാധുവാക്കിയ രംഗ ഇടവേളകൾക്ക് ആനുപാതികമായി അനുവദിക്കുന്നു; സെഗ്മെന്റ്-അവെയർ തെളിവും ഫാൾബാക്ക് സ്വഭാവവും താഴെ വിശദീകരിക്കുന്നു. കഠിനമായ 16-ഫ്രെയിം പരിധി ഓരോ പോളിസിയിലും തിരഞ്ഞെടുപ്പിന് ശേഷം പ്രയോഗിക്കുന്നു. ഒരു സീൻ-അവെയർ അഭ്യർത്ഥനയ്ക്ക് ഒരു ഫ്രെയിം ബജറ്റ് മാത്രമുള്ളപ്പോൾ, സജീവമായ പൂർണ്ണ-വീഡിയോ അല്ലെങ്കിൽ ഫോക്കസ് വിൻഡോയുടെ യൂണിഫോം മിഡ്പോയിന്റ് ഉപയോഗിക്കുകയും `policyEffective: uniform` റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യുന്നു: തിരഞ്ഞെടുത്ത ഒരു സീൻ ഫ്രെയിമിന് സമയപരിധിയിലെ രണ്ട് അറ്റങ്ങളും നിലനിർത്താൻ കഴിയില്ല. ഒരു കോളർ ഓപ്ഷണലായി ഒരു പരിമിത ഫോക്കസ് വിൻഡോ (`start`/`end` സെക്കൻഡുകൾ) നൽകാം; പരിധികൾ മീഡിയ ദൈർഘ്യത്തിലേക്ക് ക്ലാമ്പ് ചെയ്യുന്നു, തലതിരിഞ്ഞതോ പരിമിതമല്ലാത്തതോ ആയ വിൻഡോകൾ നിരസിക്കുന്നു, എല്ലാ സാമ്പ്ലിംഗ് പോളിസികളും സാധാരണീകരിച്ച ഇടവേളയ്ക്കുള്ളിൽ മാത്രം നടത്തുന്നു. ഫലമായുണ്ടാകുന്ന വിൻഡോ സാമ്പ്ലിംഗ് മെറ്റാഡാറ്റയിലും വിശ്വസനീയമല്ലാത്ത വിവരണ പ്രിഫിക്സിലും ഉൾപ്പെടുത്തുന്നു, അതിനാൽ ഡൗൺസ്ട്രീം മോഡലുകൾക്ക് ഫോക്കസ് ചെയ്ത ഒരു ഉദ്ധരണിയെ പൂർണ്ണ ടൈംലൈനിൽ നിന്ന് വേർതിരിച്ചറിയാൻ കഴിയും.

സെമാന്റിക് ക്യാപ്ഷൻ ഫോക്കസ് ഒരു വേറിട്ട, വ്യക്തമായ ക്രമീകരണമാണ്. സ്വതവേയുള്ള `full` വിശകലന മോഡ് നിലവിലുള്ള ഫ്രെയിം പ്രോംപ്റ്റ് നിലനിർത്തുന്നു, അഭ്യർത്ഥനാ ടെക്സ്റ്റ് ഒരിക്കലും ക്യാപ്ഷൻ മോഡലിലേക്ക് കൈമാറുന്നില്ല. `focused` മോഡിൽ, ബ്രിഡ്ജ് ഒരേ Chat അല്ലെങ്കിൽ Responses കണ്ടെയ്നറിൽ നിന്ന് ഏറ്റവും പുതിയ ശൂന്യമല്ലാത്ത, ഉപയോക്താവ് രചിച്ച `text`/`input_text` മാത്രം വായിക്കുന്നു, അതിനെ NFC-യിലേക്ക് സാധാരണീകരിക്കുന്നു, നിയന്ത്രണ പ്രതീകങ്ങളും വൈറ്റ്സ്പേസും ചുരുക്കുന്നു, 500 യൂണികോഡ് കോഡ് പോയിന്റുകളിൽ പരിമിതപ്പെടുത്തുന്നു. ഫലം ശൂന്യമാണെങ്കിൽ കൃത്യമായ `full` പ്രോംപ്റ്റിലേക്ക് ഫാൾബാക്ക് ചെയ്യുന്നു. ഉപയോഗയോഗ്യമായ ഒരു സൂചന ഒരു സമർപ്പിത വിശ്വസനീയമല്ലാത്ത-ഉപയോക്തൃ-സന്ദർഭ ബ്ലോക്കിൽ JSON ആയി സീരിയലൈസ് ചെയ്യുന്നു, കൂടാതെ നിരീക്ഷിക്കാവുന്ന വിശദാംശങ്ങൾക്ക് മാത്രം മുൻഗണന നൽകാം; മീഡിയയിൽ കാണാവുന്നതോ കേൾക്കാവുന്നതോ ആയ നിർദ്ദേശങ്ങൾ പിന്തുടരുന്നതിനെതിരായ വേറിട്ട മുന്നറിയിപ്പിനെ അത് അസാധുവാക്കാൻ കഴിയില്ല. ടെക്സ്ച്വൽ ഫോക്കസ് ഒരിക്കലും `start`/`end` അനുമാനിക്കുന്നില്ല, അല്ലെങ്കിൽ ടെമ്പറൽ സാമ്പ്ലറിനെ മാറ്റുന്നില്ല.

#### FU-07 ഘടനാപരമായ സെഗ്മെന്റ് തെളിവ്

`segment_aware` ഇതിനകം സാധുവാക്കിയ ലോക്കൽ വീഡിയോ സ്ട്രീമിന് മേൽ ഒരു പരിമിത മുൻകൂർ വിശകലന പാസ് ഉപയോഗിക്കുന്നു. നിശ്ചിത ഫിൽട്ടർ ചെയിൻ ആദ്യം പരമാവധി 320 പിക്സൽ വീതിയിലേക്ക് സ്കെയിൽ ചെയ്യുന്നു, സീൻ മാറ്റങ്ങളും ഫ്രീസ് ചെയ്ത ഇടവേളകളും കണ്ടെത്തുന്നു, തുടർന്ന് ബ്ലർ, ശരാശരി ലൂമ, സ്പേഷ്യൽ/ടെമ്പറൽ വിവരങ്ങൾക്കായി സെക്കൻഡിൽ 1 ഫ്രെയിം എന്ന നിരക്കിൽ സാമ്പിൾ ചെയ്യുന്നു. ഈ പാസ് 600 ഘടനാപരമായ സാമ്പിളുകൾ, ഒരു FFmpeg/ഫിൽട്ടർ ത്രെഡ്, അതേ `file`-മാത്രം പ്രോട്ടോക്കോളും കണ്ടെയ്നർ അനുവദനീയപ്പട്ടികകളും, 1 MiB പ്രോസസ്-ഔട്ട്പുട്ട് പരിധി, ബ്രോക്കറിന്റെ പങ്കിട്ട അബോർട്ട്/ഡെഡ്ലൈനിനുള്ളിൽ പരമാവധി 30 സെക്കൻഡ് എന്നിവയിൽ പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. അഭ്യർത്ഥനയിൽ നിന്ന് ഒരു കമാൻഡ്, ഫിൽട്ടർ, പാത്ത്, അല്ലെങ്കിൽ URL ഒരിക്കലും സ്വീകരിക്കുന്നില്ല.

ഘടനാപരമായ മൂല്യങ്ങൾ നിർണ്ണയാത്മക സാമ്പ്ലിംഗ് തെളിവാണ്, സെമാന്റിക് വീഡിയോ ധാരണയല്ല. അവ വിഷയങ്ങൾ, പ്രവർത്തനങ്ങൾ, ക്യാപ്ഷനുകൾ, സംഭാഷണം, അല്ലെങ്കിൽ ഉപയോക്തൃ ഉദ്ദേശം എന്നിവ അനുമാനിക്കുന്നില്ല. രംഗ-, ഫ്രീസ് അതിരുകൾ സെഗ്മെന്റുകൾ രൂപപ്പെടുത്തുന്നു; ഫ്രീസ് കവറേജ്, ബ്ലർ, എക്സ്പോഷർ, സ്പേഷ്യൽ വിശദാംശം, ടെമ്പറൽ മാറ്റം എന്നിവ നിലവിലുള്ള 1–16 ഫ്രെയിം ബജറ്റ് എങ്ങനെ അനുവദിക്കപ്പെടുന്നു എന്നതിനെ മാത്രം സ്വാധീനിക്കുന്നു. പൂർണ്ണമായി ഫ്രീസ് ചെയ്ത ഒരു സെഗ്മെന്റ് ഒരു ഫ്രെയിമിൽ പരിമിതപ്പെടുത്തുന്നു, ഫ്രീസ് ചെയ്യാത്ത സെഗ്മെന്റുകൾ ബാക്കിയുള്ള ബജറ്റിനായി മത്സരിക്കുന്നു. അതിരുകൾ ഫ്രെയിമുകളേക്കാൾ കൂടുതലാകുമ്പോൾ, യൂണിഫോം ടൈംലൈൻ കവറേജ് നിലനിർത്തുന്നു, അതിനാൽ വേഗത്തിലുള്ള തുടക്ക കട്ടുകൾക്ക് നീണ്ട ഒരു ട്രെയിലിംഗ് സെഗ്മെന്റ് മറയ്ക്കാൻ കഴിയില്ല. ഒരു ഫ്രീസ് അതിരിന്റെ 1-സെക്കൻഡ് വിശകലന റെസല്യൂഷനുള്ളിലെ രംഗ അതിരുകൾ സംയോജിപ്പിക്കുന്നു.

ഫിൽട്ടറുകൾ ഇല്ലാത്തത്, വികലമായ/ശൂന്യമായ തെളിവ്, ഡിറ്റക്ടർ പിശക്, അല്ലെങ്കിൽ പരിമിത മുൻകൂർ വിശകലന ടൈംഔട്ട് എന്നിവ കൃത്യമായ യൂണിഫോം മിഡ്പോയിന്റ് പോളിസിയിലേക്ക് ഫെയിൽ ഓപ്പൺ ചെയ്യുന്നു. കോളർ അബോർട്ട് അല്ലെങ്കിൽ ബ്രോക്കർ ഡെഡ്ലൈൻ ഫെയിൽ ഓപ്പൺ ചെയ്യുന്നില്ല: അത് നടന്നുകൊണ്ടിരിക്കുന്ന സബ്പ്രോസസിനെ അവസാനിപ്പിക്കുന്നു, പിന്നീടുള്ള ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുന്നു, സ്വകാര്യ താൽക്കാലിക ട്രീ `finally`-ൽ നീക്കം ചെയ്യുന്നു.

`scripts/perf/video-bridge-fu07-eval.ts` ഡീഡപ്പിന് ശേഷമുള്ള ക്യാപ്ഷൻ-കോൾ ലാഭം, ഡെൻസ്-മോഷൻ ബജറ്റ് അനുവദനം, ബ്ലർ/എക്സ്പോഷർ/SI-TI തെളിവ്, നീണ്ട ടെയിലുള്ള വേഗത്തിലുള്ള കട്ടുകൾ, ഗ്രാജ്വൽ-ഫേഡ് തെറ്റായ പോസിറ്റീവുകൾ എന്നിവയ്ക്കായി നിർണ്ണയാത്മകമായ യഥാർത്ഥ FFmpeg ഫിക്സ്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് മുൻകൂർ വിശകലന വാൾ ടൈം രേഖപ്പെടുത്തുന്നു, കൂടാതെ `/usr/bin/time` ലഭ്യമായിടത്ത് ചൈൽഡ് CPU-യും പീക്ക് RSS-ഉം രേഖപ്പെടുത്തുന്നു. അതിന്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഒറാക്കിളുകൾ മാത്രമാണ്. യഥാർത്ഥ ക്യാപ്ഷൻ-മോഡൽ ഗുണനിലവാരം `HOLD` ആയി തുടരുന്നു, കാരണം ഈ ഹാർനെസിന് അംഗീകൃത എൻഡ്പോയിന്റോ ഫ്രോസൺ ജഡ്ജോ ഇല്ല. പണ ലാഭവും `HOLD` ആയി തുടരുന്നു, `--caption-cost-per-call-usd` വ്യക്തമായ ഒരു പോസിറ്റീവ് പ്രതി-കോൾ എസ്റ്റിമേറ്റ് നൽകുന്നില്ലെങ്കിൽ; സ്ക്രിപ്റ്റ് ഇരു ഫലങ്ങളും ഒരിക്കലും കെട്ടിച്ചമയ്ക്കുന്നില്ല.

ഓരോ ഫ്രെയിമും 4 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു, എല്ലാ റോ ഫ്രെയിമുകളും ഒരുമിച്ച് 23 MiB, സീരിയലൈസ് ചെയ്ത ബ്രോക്കർ പ്രതികരണം 32 MiB. ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി `finally`-ൽ നീക്കം ചെയ്യുന്നു. OmniRoute FFmpeg ബണ്ടിൽ ചെയ്യുന്നില്ല, ഇഷ്ടാനുസൃത എക്സിക്യൂട്ടബിൾ പാത സ്വീകരിക്കുന്നുമില്ല. ക്യാപ്ഷനിംഗിന് മുമ്പ്, ബ്രിഡ്ജ് ഒരു യഥാസ്ഥിതിക ദൃശ്യ ഡീഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG-ഉം 16×16 ഗ്രേസ്കെയിൽ ബഫറായി ചുരുക്കി, നിലനിർത്തിയ അവസാന ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുന്നു. ഒരു ഫ്രെയിമിന് മുകളിലുള്ള ക്യാപ്ഷൻ ബജറ്റ് അഭ്യർത്ഥിക്കുമ്പോൾ, എക്സ്ട്രാക്ഷൻ ആ ബജറ്റിന്റെ ഇരട്ടിവരെയും ഒരിക്കലും 16 ഫ്രെയിമുകളിൽ കൂടാതെയും ഒരു പരിമിത കാൻഡിഡേറ്റ് പൂൾ നൽകുന്നു. അഭ്യർത്ഥിച്ച പരിധി ഡീഡ്യൂപ്ലിക്കേഷനു ശേഷം മാത്രം പ്രയോഗിക്കുന്നു; ബജറ്റ് കുറഞ്ഞത് രണ്ടെങ്കിൽ അന്തിമ ഫ്രെയിം കുറയ്ക്കൽ ഘട്ടത്തിൽ ആദ്യത്തേതും അവസാനത്തേതുമായ തിരഞ്ഞെടുത്ത കാൻഡിഡേറ്റുകൾ നിലനിർത്തുന്നു. പതിപ്പിച്ച `grayscale-16x16-mean-cells-v2` നയം ശരാശരി luma ഡെൽറ്റയിലും, സാധാരണവൽക്കരിച്ച ഡെൽറ്റ കുറഞ്ഞത് 0.05 ആയ തംബ്നെയിൽ സെല്ലുകളുടെ അനുപാതത്തിലും വലുതായത് ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് സ്ഥിരാങ്കമായ 0.04 ആണ്; പ്രവചനക്ഷമതയ്ക്കായി തിരഞ്ഞെടുത്തത്, റൺടൈം ക്രമീകരണമായി വെളിപ്പെടുത്തിയിട്ടില്ല. ഈ ദ്വിതീയ ഉയർന്ന കോൺട്രാസ്റ്റ് സിഗ്നൽ ചെറിയ ചലനവും ദൃശ്യ ടെക്സ്റ്റ് മാറ്റങ്ങളും സംരക്ഷിക്കുന്നു; ശരാശരി-മാത്രം താരതമ്യത്തിന് അവ മറയ്ക്കാം. കമ്പാരേറ്റർ അല്ലെങ്കിൽ ഡീകോഡർ പിശകുകൾ fail open ആകുകയും കവറേജ് നിലനിർത്തുകയും ചെയ്യുന്നു. ഔട്ട്പുട്ട് മെറ്റാഡാറ്റ എക്സ്ട്രാക്ട് ചെയ്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, ഉപേക്ഷിച്ച ദൃശ്യ ഡ്യൂപ്ലിക്കേറ്റുകൾ എന്നിവ വേർതിരിക്കുന്നു.

വ്യക്തമായി അടയാളപ്പെടുത്തിയ ഒരു വീഡിയോ ഭാഗം ടൈംസ്റ്റാമ്പ് ചെയ്ത കോൺടാക്റ്റ് ഷീറ്റ് അഭ്യർത്ഥിക്കാം. ബ്രിഡ്ജ് പരമാവധി 4-നിര, 16-ഫ്രെയിം JPEG ഗ്രിഡ് നിർമ്മിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിന്റെ സ്രോതസ്സ് ടൈംസ്റ്റാമ്പ് ഉയർന്ന കോൺട്രാസ്റ്റുള്ള അടിഭാഗ ബാൻഡിൽ ബേൺ ചെയ്യുന്നു; അതേ ടൈംസ്റ്റാമ്പുകൾ ഡൗൺസ്ട്രീം അസോസിയേഷനും ഓഡിറ്റിനും വേണ്ടി ടെക്സ്റ്റ് മെറ്റാഡാറ്റയിൽ തുടരുന്നു. മുഴുവൻ JPEG-ഉം 32 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. `sharp`-ന് ഗ്രിഡ് ഡീകോഡ് ചെയ്യാനോ രചിക്കാനോ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് വ്യക്തിഗത JPEG ഫ്രെയിമുകളിലേക്ക് പിൻവാങ്ങുന്നു; ക്ലയന്റ് നിർത്തലാക്കൽ ഇപ്പോഴും ഷീറ്റ് പ്രവർത്തനത്തിലൂടെ കടന്നുപോകുന്നു.

പ്രൊമോഷൻ തെളിവ് സിന്തറ്റിക് കോമ്പോസിഷൻ മൈക്രോബെഞ്ച്മാർക്കിൽ നിന്ന് ബോധപൂർവം വേർതിരിച്ചിരിക്കുന്നു. `scripts/perf/video-bridge-contact-sheet-eval.ts` യഥാർത്ഥ OpenAI-കോംപാറ്റിബിൾ വിഷൻ മോഡലുകൾക്കായി സ്കീമ-പതിപ്പിച്ച A/B ഹാർനെസ് നിർവചിക്കുന്നു. ഇത് ദാതാവ് റിപ്പോർട്ട് ചെയ്ത ടോക്കണുകൾ, എൻഡ്-ടു-എൻഡ് വാൾ ലേറ്റൻസി (ഷീറ്റ് കോമ്പോസിഷൻ ഉൾപ്പെടെ), മോഡൽ-കോൾ എണ്ണം, മാനിഫെസ്റ്റ് നിർവചിച്ച വസ്തുത നിലനിർത്തൽ എന്നിവ അളക്കുന്നു. അസംസ്കൃത മോഡൽ പ്രതികരണങ്ങൾ റിപ്പോർട്ടിൽ എഴുതുന്നില്ല; SHA-256 ഡൈജസ്റ്റുകളും പൊരുത്തപ്പെട്ട വസ്തുത ID-കളും മാത്രം നിലനിർത്തുന്നു. `--execute-real` നൽകുകയും `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ കോൺഫിഗർ ചെയ്യുകയും ചെയ്താൽ മാത്രമേ ഹാർനെസ് നെറ്റ്വർക്ക് അല്ലെങ്കിൽ പണം നൽകേണ്ട മോഡൽ കോൾ നടത്തുകയുള്ളൂ. ആ വ്യക്തമായ യഥാർത്ഥ റണ്ണില്ലാതെ, അതിന്റെ മെഷീൻ-വായനാക്ഷമമായ വിധി `HOLD` ആയി തുടരുന്നു; സിന്തറ്റിക് പേലോഡ്/കോൾ-എണ്ണം അളവുകൾ മാത്രം പ്രൊമോഷൻ തെളിവല്ല.

ക്ലയന്റുകൾക്ക് ഇതിനകം അലൈൻ ചെയ്ത ടെക്സ്റ്റ് ഉണ്ടെങ്കിൽ, പിന്തുണയുള്ള ഒരു വീഡിയോ ഭാഗത്തേക്ക് ഓപ്ഷണൽ `transcript.cues` അറേ ചേർക്കാം. ഓരോ ക്യൂവും `text`, പരിശോധിച്ച ദൈർഘ്യത്തിനുള്ളിൽ പരിമിതമായ `start`/`end` ഇടവേള, വൈറ്റ്ലിസ്റ്റ് ചെയ്ത `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ വഹിക്കണം; `confidence` സ്വതവേ `1` ആണ്, കൂടാതെ `0`-നും `1`-നും ഇടയിൽ തുടരണം. കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റ് ക്യൂകൾ ഒന്നാക്കി ചുരുക്കുന്നു. OmniRoute ഈ മെറ്റാഡാറ്റയിൽ നിന്ന് ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കുന്നില്ല: സാധുതയുള്ള ക്യൂകൾ സ്രോതസ്സ്, കോൺഫിഡൻസ്, ഇടവേള എന്നിവയോടെ വിവരിച്ച ഫലത്തിലേക്ക് പകർത്തുകയും ഫ്രെയിം ക്യാപ്ഷനുകൾക്കൊപ്പം അവിശ്വസനീയ നിരീക്ഷണങ്ങളായി റെൻഡർ ചെയ്യുകയും ചെയ്യുന്നു. അസാധുവായ, പരിധിക്ക് പുറത്തുള്ള, അല്ലെങ്കിൽ ഉത്ഭവ-രഹിത ടെക്സ്റ്റ് ക്യാപ്ഷൻ സ്ട്രീമിലേക്ക് കലർത്തുന്നതിന് പകരം നിരസിക്കുന്നു. രണ്ട് റിക്വസ്റ്റ്-ബോഡി ട്രാൻസ്ക്രിപ്റ്റ് ചാനലുകളും നൽകിയ ഉത്ഭവം `client` ആയി സാധാരണവൽക്കരിക്കുന്നു; സ്വയം പ്രഖ്യാപിച്ച `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബലുകളും ഇതിൽ ഉൾപ്പെടുന്നു. സർവർ-ഉടമസ്ഥതയിലുള്ള ഒരു അഡാപ്റ്ററിന് മാത്രമേ കോഡ്-മാത്രം `trustedSource` ആർഗ്യുമെന്റിലൂടെ ആ വിശ്വസ്ത ലേബലുകൾ നൽകാൻ കഴിയൂ; ഒരു റിക്വസ്റ്റ് JSON ഫീൽഡിന് ആ ആർഗ്യുമെന്റിൽ എത്താൻ കഴിയില്ല. ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് അതിന്റെ ഉത്ഭവം എന്തായാലും അവിശ്വസനീയ മീഡിയ-ഉത്പന്ന ഉള്ളടക്കമായി തുടരുന്നു, കൂടാതെ ഒരിക്കലും ഓതറൈസേഷൻ നിർണ്ണയിക്കരുത്.

ഒരു വിപുലമായ കോളർ അതേ വീഡിയോയ്ക്ക് ഓപ്ഷണൽ `audioTranscript` ട്രാക്ക് നൽകാം; ഇത് ക്ലയന്റ്-നൽകിയ ടെക്സ്റ്റായി പരിഗണിക്കുന്നു, സർവർ ട്രാൻസ്ക്രിപ്ഷന്റെ തെളിവായി അല്ല. ഫ്യൂഷൻ സീം ദൃശ്യ, ഓഡിയോ നിരീക്ഷണങ്ങൾ ഒരു ഡെഡ്ലൈനിനും അബോർട്ട് സിഗ്നലിനും കീഴിൽ പ്രവർത്തിപ്പിക്കുന്നു, അവയെ ഒരു പൊതു ടൈംലൈനിൽ ക്രമീകരിക്കുന്നു, കൃത്യമായ ഡ്യൂപ്ലിക്കേറ്റുകൾ ഒന്നാക്കി ചുരുക്കുന്നു, ഒരു വശം മാത്രം വിജയിക്കുമ്പോൾ ഭാഗിക ഫലം റിപ്പോർട്ട് ചെയ്യുന്നു. അസാധുവായ `audioTranscript` ആ ഭാഗിക ഫലത്തിലേക്ക് ക്ഷയിക്കുന്നു — ദൃശ്യ വിവരണം നിലനിർത്തുകയും ഓഡിയോ ശാഖ ഒരു സാനിറ്റൈസ് ചെയ്ത പരാജയ കോഡ് രേഖപ്പെടുത്തുകയും ചെയ്യുന്നു — മുഴുവൻ വീഡിയോയും പരാജയപ്പെടുത്തുന്നതിന് പകരം. ഓരോ ശാഖയുടെയും ലഭ്യത, ഭാഗിക ഫ്ലാഗ്, സാനിറ്റൈസ് ചെയ്ത പരാജയ കോഡുകൾ എന്നിവ വിവരിച്ച ഫലത്തിൽ, ഗാർഡ്റെയിൽ മെറ്റാഡാറ്റയിൽ (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), ഫല-കാഷെ മെറ്റാഡാറ്റയിൽ, ബ്രിഡ്ജ് ഫ്യൂഷൻ കൗണ്ടറുകളിൽ എന്നിവയിൽ സംരക്ഷിക്കുന്നു. സ്വതവേയുള്ള Video Bridge പാത സ്പീച്ച്-ടു-ടെക്സ്റ്റ് വിളിക്കുന്നില്ല, രണ്ടാമത്തെ മീഡിയ പകർപ്പ് ഡൗൺലോഡ് ചെയ്യുന്നുമില്ല; ആ വ്യക്തമായ ട്രാക്ക് ഇല്ലാതെ, അത് വീഡിയോ-മാത്രമായി തുടരുന്നു.

**ട്രാൻസ്ക്രിപ്റ്റ് നിലനിർത്തൽ (#12150 P1).** വീഡിയോ ബ്രിഡ്ജ് (അതുതന്നെ ഓപ്റ്റ്-ഇൻ) ഒരു ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ റെൻഡർ ചെയ്യുമ്പോഴെല്ലാം ഇത് സ്വയമേവ ബാധകമാകുന്നു — പ്രത്യേക നിലനിർത്തൽ ഫ്ലാഗ് ഇല്ല. ഒരു അഭ്യർത്ഥന ഏതെങ്കിലും ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ (കോളർ പ്രഖ്യാപിച്ച `transcript` അല്ലെങ്കിൽ സംയോജിപ്പിച്ച `audioTranscript`) റെൻഡർ ചെയ്യുമ്പോൾ, ഗാർഡ്റെയിൽ അതിനെ `videoBridgeObserved` എന്ന് അടയാളപ്പെടുത്തുകയും വീഡിയോ വിവരണത്തിന്റെ റീഡാക്റ്റ് ചെയ്ത ഷാഡോ നിർമ്മിക്കുകയും ചെയ്യുന്നു — ഓരോ ക്യൂവിന്റെയും ഫ്രീ-ടെക്സ്റ്റ് ബോഡി `[redacted-video-transcript]` എന്നതിനാൽ മാറ്റിസ്ഥാപിച്ച ഒരേപോലെയുള്ള റെൻഡറിംഗ്; സ്ട്രിംഗ് കൂട്ടിച്ചേർക്കുന്നതിന് മുമ്പ് ഘടനാപരമായ ക്യൂ ഫീൽഡ് മാറ്റിസ്ഥാപിച്ചാണ് ഇത് നിർമ്മിക്കുന്നത് (പരന്ന ടെക്സ്റ്റ് പാഴ്സ് ചെയ്തല്ല ഒരിക്കലും; അതിനാൽ `]` അടങ്ങിയ `[inaudible]`/`[music]` പോലുള്ള ബോഡികൾ ഉൾപ്പെടെ ഏതെങ്കിലും ക്യൂ ഉള്ളടക്കം — ആക്രമണാത്മകമോ സാധാരണമോ ആയത് — അതിജീവിക്കാൻ കഴിയില്ല). നിലനിർത്തിയ കോൾ-ലോഗ് അഭ്യർത്ഥനാ ബോഡി ഓരോ വീഡിയോയിൽ നിന്ന് ഉരുത്തിരിഞ്ഞ ടെക്സ്റ്റ് ഭാഗവും ആ റീഡാക്റ്റ് ചെയ്ത ഷാഡോ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു; ഉള്ളടക്ക സമത്വം വച്ചാണ് പൊരുത്തപ്പെടുത്തുന്നത്. `fullText` ആങ്കർ പൂർത്തിയായ പ്രീ-കോൾ ഗാർഡ്റെയിൽ പേലോഡിൽ നിന്ന് വീണ്ടും വായിക്കുന്നു; അതിനാൽ പിന്നീടുള്ള ചെയിൻ ഗാർഡ്റെയിലുകൾ (PII, ക്രെഡൻഷ്യൽ മാസ്കറുകൾ, മുൻഗണനകൾ 10/95) വിവരണ ടെക്സ്റ്റ് അതേ സ്ഥലത്ത് തന്നെ മാറ്റിയെഴുതിയതിന് ശേഷവും സിസ്റ്റം-പ്രോംപ്റ്റ്/ഹാൻഡ്ഓഫ്/മെമ്മറി ഇൻജെക്ഷൻ സന്ദേശ നിരയെ പുനഃരൂപപ്പെടുത്തിയതിന് ശേഷവും പൊരുത്തം വിജയിക്കുന്നു. മോഡലിലേക്ക് അപ്സ്ട്രീം അയയ്ക്കുന്ന ബോഡി മാറ്റമില്ലാതെ തുടരുന്നു. നിരീക്ഷിച്ച അഭ്യർത്ഥന സ്ഥിരമായ മെമ്മറിയിൽ ഒന്നും നിറയ്ക്കുന്നില്ല (അഭ്യർത്ഥനയിൽ നിന്നും പ്രതികരണത്തിൽ നിന്നും ഉള്ള എക്സ്ട്രാക്ഷൻ രണ്ടും ഒഴിവാക്കുന്നു); അതിനാൽ മോഡലിന്റെ സ്വന്തം മറുപടിക്ക് ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് മെമ്മറിയിലേക്ക് പ്രതിധ്വനിപ്പിക്കാൻ കഴിയില്ല.

**അസംസ്കൃത വീഡിയോ ഫീൽഡുകൾ (#12430).** ബ്രിഡ്ജ് പ്രവർത്തനക്ഷമമായിരിക്കുകയും നേറ്റീവ് വീഡിയോ പിന്തുണ അജ്ഞാതമോ അഭാവമോ ആയിരിക്കുകയും ചെയ്യുമ്പോൾ, നിർവചിച്ച `transcript`/`audioTranscript` ഫീൽഡുകളും `videoBridgeObserved` സജീവമാക്കുന്നു; വിവരണ പരാജയത്തിന് ശേഷമോ `maxVideos` പരിധിക്ക് ശേഷമോ പോലും. `null` ഉം ശൂന്യമായ സ്ട്രിംഗുകളും കണക്കിലെടുക്കുന്നു; അഭാവത്തിലുള്ള ഫീൽഡുകളും വീഡിയോ-ഇതര മെറ്റാഡാറ്റയും കണക്കിലെടുക്കുന്നില്ല. നിലനിർത്തിയ പകർപ്പുകൾ ഈ ഫീൽഡുകൾ റീഡാക്റ്റ് ചെയ്യുന്നു അല്ലെങ്കിൽ അഭ്യർത്ഥന ഒഴിവാക്കുന്നു; കാഷുകളും മെമ്മറിയും ഒഴിവാക്കപ്പെടുന്നു.

ആ ഫോൾബാക്ക് പാതകളിൽ, സാധുവായ കോളർ ക്യൂകൾ നോൺസ്റ്റാൻഡേർഡ് പ്രൊവൈഡർ ഫീൽഡുകൾക്കുപകരം പിന്തുണയുള്ള `text`/`input_text` ഭാഗങ്ങളാകുന്നു. അഭ്യർത്ഥന നൽകിയ രണ്ട് ട്രാക്കുകളും വിശ്വസിക്കാനാവാത്ത `client` നിരീക്ഷണങ്ങളായി തുടരുന്നു; വീഡിയോ വിവരിച്ചിട്ടില്ലെന്നും ടൈംസ്റ്റാമ്പുകൾ മീഡിയയുമായി പരിശോധിച്ചിട്ടില്ലെന്നും വ്യക്തമായ മുന്നറിയിപ്പോടെ. നിലവിലുള്ള 256-ക്യൂ/64-KiB മൊത്തവും ഓരോ ക്യൂവിനുമുള്ള ബജറ്റുകളും രണ്ട് ട്രാക്കുകളിലുമായി ഒരുമിച്ച് ബാധകമാണ്; ടൈംസ്റ്റാമ്പുകൾ ബ്രോക്കറുടെ 600-സെക്കൻഡ് പരിധിയിലും നൽകിയിട്ടുള്ള ഏതെങ്കിലും ഫോക്കസ് വിൻഡോയിലും ഉൾപ്പെടണം. അസാധുവായ ട്രാക്കുകൾ ഒഴിവാക്കുന്നു; അവയെ അനിയന്ത്രിത ടെക്സ്റ്റായി കൈമാറുന്നില്ല; അവയുടെ സംയുക്ത ബജറ്റ് കവിയാത്ത പക്ഷം സാധുവായ സഹോദര ട്രാക്ക് ഇപ്പോഴും ഉപയോഗിക്കാം. നൾ/ശൂന്യ ഫീൽഡുകൾ ടെക്സ്റ്റ് ചേർക്കുന്നില്ല. ഈ ഫോൾബാക്ക് മീഡിയ ഫെച്ചോ ട്രാൻസ്ക്രിപ്ഷനോ ചേർക്കുന്നില്ല. ട്രാൻസ്ക്രിപ്റ്റ് എക്സ്റ്റൻഷൻ ഫീൽഡുകൾ ഫോൾബാക്ക് വീഡിയോ കാരിയറിൽ നിന്നും അതിന്റെ `video_url`/`source` ഒബ്ജക്റ്റുകളിൽ നിന്നും നീക്കം ചെയ്യുന്നു. OpenAI വയർ അലവ്ലിസ്റ്റ് കർശനമായി തുടരുന്നു; അജ്ഞാത-നേറ്റീവ് വീഡിയോ കാരിയറുകൾ ലഭ്യമായി തുടരുന്നു; അറിയപ്പെടുന്ന ടെക്സ്റ്റ്-മാത്ര ലക്ഷ്യങ്ങൾ സുരക്ഷിത മാർക്കറുകൾ നിലനിർത്തുന്നു. ഘടനാപരമായ റീഡാക്ഷൻ ഷാഡോകൾ ചേർത്ത ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റിനെ സംരക്ഷിക്കുന്നു; യഥാർത്ഥ കോളർ-ഉടമസ്ഥതയിലുള്ള അഭ്യർത്ഥന മാറ്റമില്ലാതെ തുടരുന്നു. നേറ്റീവ് പിന്തുണയുള്ള ലക്ഷ്യങ്ങളും ഡിസേബിൾ ചെയ്ത ബ്രിഡ്ജുകളും അവയുടെ നിലവിലുള്ള ബൈപ്പാസ് സ്വഭാവം നിലനിർത്തുന്നു.

അധിക നിലനിർത്തിയ പകർപ്പുകൾ അതേ നിരീക്ഷിച്ച-അഭ്യർത്ഥന സിഗ്നൽ ഉപയോഗിക്കുന്നു. അസംസ്കൃത പ്രീ-ഗാർഡ്റെയിൽ ക്ലയന്റ്-അഭ്യർത്ഥന സ്നാപ്ഷോട്ട്, മെമ്മറിയിലുള്ള പെൻഡിംഗ് അഭ്യർത്ഥന, നേരത്തേയുള്ള നിരസിച്ച-അഭ്യർത്ഥന ലോഗ് എന്നിവ വീഡിയോ ഭാഗങ്ങളിലെ ട്രാൻസ്ക്രിപ്റ്റ് ഫീൽഡുകൾ ഘടനാപരമായി മാറ്റിസ്ഥാപിക്കുന്നു; പൈപ്പ്ലൈൻ ഘട്ടങ്ങളും കോൺടെക്സ്റ്റ് ഹാൻഡ്ഓഫും സംശ്ലേഷിപ്പിച്ച സ്ട്രിംഗ് പ്രോംപ്റ്റുകൾ നിലനിർത്തിയ അഭ്യർത്ഥനാ-ബോഡി സിങ്കിൽ റീഡാക്റ്റ് ചെയ്യുന്നു. നിലനിർത്തിയ `video_content_removed` മാർക്കർ, ബോധപൂർവം ഒഴിവാക്കിയ ടെക്സ്റ്റ് പുനർനിർമ്മിക്കുന്നതിനുപകരം `previous_response_id` തുടർച്ച ഫെയിൽ ക്ലോസ്ഡ് ആക്കുന്നു. ഒരു നിരീക്ഷിച്ച അഭ്യർത്ഥന ലോഗിംഗിന് മുമ്പ് അതിന്റെ ഓരോ ഭാഗത്തിനുമുള്ള റീഡാക്ഷൻ ഷാഡോ നഷ്ടപ്പെടുകയാണെങ്കിൽ, അല്ലെങ്കിൽ പിന്നീടുള്ള അഭ്യർത്ഥന മ്യൂട്ടേഷനുകൾക്ക് ശേഷം നിരവധി വീഡിയോ ഷാഡോകളിൽ ഒന്നെങ്കിലും പൊരുത്തപ്പെടാൻ പരാജയപ്പെടുകയാണെങ്കിൽ, ഭാഗികമായി റീഡാക്റ്റ് ചെയ്ത ട്രാൻസ്ക്രിപ്റ്റ് നിലനിർത്തുന്നതിനുപകരം നിലനിർത്തിയ അഭ്യർത്ഥനാ ബോഡി പൂർണ്ണമായും ഒഴിവാക്കുന്നു.

ഒരു നിരീക്ഷിച്ച അഭ്യർത്ഥനയ്ക്ക്, മോഡൽ പ്രതികരണം ഘടനാപരമായ ക്യൂ അതിർത്തിയില്ലാതെ ട്രാൻസ്ക്രിപ്റ്റിന്റെ ഏതെങ്കിലും ഭാഗം ഉദ്ധരിച്ചേക്കാം. അതിനാൽ അതിന്റെ നിലനിർത്തിയ കോൾ-ലോഗ് `responseBody` ഒഴിവാക്കൽ മാർക്കർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു; വിശദമായ പൈപ്പ്ലൈൻ ആർട്ടിഫാക്റ്റ് (അപ്സ്ട്രീം/ക്ലയന്റ് ബോഡികളും സ്ട്രീം ചങ്കുകളും ഉൾപ്പെടാം) നിലനിർത്തുന്നില്ല. സെമാന്റിക്, ഐഡംപൊട്ടൻസി, റീസണിംഗ്-റീപ്ലേ കാഷുകൾ ആ അഭ്യർത്ഥനയ്ക്കുള്ള വായനകളും എഴുത്തുകളും ഒഴിവാക്കുന്നു. പ്രൊവൈഡർ അഭ്യർത്ഥനയും ക്ലയന്റിന് ദൃശ്യമായ പ്രതികരണവും മാറ്റമില്ലാതെ തുടരുന്നു. വിശദമായ ആർട്ടിഫാക്റ്റ് ഒഴിവാക്കുമ്പോൾ നേരത്തേയുള്ള കീപ്പലൈവ് ബൈറ്റുകൾ താൽക്കാലിക ബഫറിൽ നിന്ന് ഡ്രെയിൻ ചെയ്യുന്നു. Kiro-യുടെ വികലമായ EventStream മുന്നറിയിപ്പ് പേലോഡ് ബൈറ്റ് എണ്ണം മാത്രം റിപ്പോർട്ട് ചെയ്യുന്നു; അതിന്റെ ഉള്ളടക്കമോ JSON പാഴ്സറിന്റെ അസംസ്കൃത പിശകോ ഒരിക്കലും റിപ്പോർട്ട് ചെയ്യുന്നില്ല. ബന്ധമില്ലാത്ത എല്ലാ പ്രൊവൈഡർ/പ്ലഗിൻ ഡയഗ്നോസ്റ്റിക്സും ഓഡിറ്റ് ചെയ്തിട്ടുണ്ടെന്ന് ഇത് അവകാശപ്പെടുന്നില്ല; വിശാലമായ നിലനിർത്തിയ-സിങ്ക് സ്വീപ്പ് #11658-ൽ ട്രാക്ക് ചെയ്യുന്നു.

ആന്തരിക `/api/modality-bridge/video/drilldown` ജീവിതചക്രം വേറിട്ട ലൂപ്പ്ബാക്ക്/ടോക്കൺ-ഓതന്റിക്കേറ്റഡ് കാഷ് സബ്സ്ട്രേറ്റ് ആണ്. ഓരോ പ്രവർത്തനത്തിനും ഒരു കാനോനിക്കൽ ഒപാക് പ്രിൻസിപ്പൽ ID ആവശ്യമാണ്. ഒരു പ്രൊഡക്ഷൻ കോളർ പ്രവർത്തനക്ഷമമാക്കുന്നതിന് മുമ്പ്, അത് ആ ID ഓതന്റിക്കേറ്റ് ചെയ്ത ടെനന്റിൽ നിന്ന് ഡെറൈവ് ചെയ്യണം; ക്ലയന്റ് തിരഞ്ഞെടുത്ത മൂല്യം ഒരിക്കലും കൈമാറരുത്. കാഷ് കീകൾ ആ പ്രിൻസിപ്പലിനെ കാനോനിക്കൽ സെഷൻ, വീഡിയോ-റഫറൻസ് ID-കളുമായി ബന്ധിപ്പിക്കുന്നു; അവയുടെ SHA-256-ൽ നിന്ന് ഉരുത്തിരിഞ്ഞ കീകൾ മാത്രം സൂക്ഷിക്കുന്നു; വായനകളും ഡിലീഷനും ഒരേ പ്രിൻസിപ്പലിലേക്ക് പരിമിതപ്പെടുത്തുന്നു. കാഷ് ഓരോ എൻട്രിക്കും പരമാവധി 16 ഡെറൈവ്ഡ് JPEG ഫ്രെയിമുകൾ സൂക്ഷിക്കുന്നു, പത്ത് മിനിറ്റിന് ശേഷം അവ കാലഹരണപ്പെടുത്തുന്നു, പരിമിതമായ `start`/`end` വായനകളെയോ വ്യക്തമായ സെഷൻ ഡിലീഷനെയോ പിന്തുണയ്ക്കുന്നു.

ഓരോ പ്രിൻസിപ്പലും 16 എൻട്രികളിലും 64 MiB കാനോനിക്കൽ JPEG ഡാറ്റയിലും പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. ആ പരിധികൾ ആഗോള 64-എൻട്രി/256 MiB പരിധിയിൽ നിന്ന് സ്വതന്ത്രമാണ്: പ്രിൻസിപ്പൽ ക്വോട്ടാ സമ്മർദ്ദം ആഗോള LRU എവിക്ഷൻ പരിഗണിക്കുന്നതിന് മുമ്പ് ആ പ്രിൻസിപ്പലിന്റെ ഏറ്റവും കുറച്ച് സമീപകാലത്ത് ഉപയോഗിച്ച എൻട്രികൾ മാത്രം എവിക്ട് ചെയ്യുന്നു. കാഷ് പ്രവർത്തനത്തിൽ കാലഹരണപ്പെട്ട എൻട്രികൾ പ്രിൻസിപ്പൽ, ആഗോള അക്കൗണ്ടിംഗ് എന്നിവയിൽ നിന്ന് സ്വീപ്പ് ചെയ്യുന്നു; റദ്ദാക്കലും വാലിഡേഷൻ പരാജയവും ഭാഗിക മാറ്റിസ്ഥാപനം കമ്മിറ്റ് ചെയ്യുന്നില്ല.

### PII Masker (`piiMasker.ts`)

**രണ്ട്** stages-ലും പ്രവർത്തിക്കുന്നു.

- **`preCall`** പേലോഡ് ക്ലോൺ ചെയ്യുന്നു, `system`, `messages`, `input`, `prompt` (പ്ലെയിൻ സ്ട്രിങ് ഇനങ്ങൾ ഉൾപ്പെടെ) എന്നിവയിലൂടെ നടന്ന്, സ്ട്രിങ് `content`/`text` ഫീൽഡുകളിൽ `processPII()` (`@/shared/utils/inputSanitizer`-ൽ നിന്ന്) പ്രയോഗിക്കുന്നു. `PII_REDACTION_ENABLED=true` ആകുമ്പോൾ, കണ്ടെത്തിയ PII ഔട്ട്ബൗണ്ട് പേലോഡിൽ റിഡാക്ട് ചെയ്യും. ഇത് `INPUT_SANITIZER_MODE`-ൽ നിന്ന് സ്വതന്ത്രമാണ് (അത് പ്രോംപ്റ്റ്-ഇൻജെക്ഷൻ നയം മാത്രമാണ് നിയന്ത്രിക്കുന്നത്). റിഡാക്ഷൻ ഓഫ് ആയിരിക്കുമ്പോൾ, ഉള്ളടക്കം പുനരെഴുതാതെ കോൾ കണ്ടെത്തൽ എണ്ണങ്ങൾ രേഖപ്പെടുത്തുന്നു.
- **`postCall`** റെസ്പോൺസ് ഡീപ്-ക്ലോൺ ചെയ്യുന്നു, `sanitizePIIResponse()`-നൊപ്പം Responses-API-ആകൃതിയിലുള്ള മാസ്കർ (`maskResponsesOutput` — `output_text`-ഉം `output[].content[].text`-ഉം ഉൾക്കൊള്ളുന്നു) പ്രവർത്തിപ്പിക്കുന്നു. ഏതെങ്കിലും റിഡാക്ഷൻ സംഭവിക്കുകയാണെങ്കിൽ, പരിഷ്കരിച്ച റെസ്പോൺസ് യഥാർത്ഥത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.

ഗാർഡ്റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുന്നില്ല; അത് അനോട്ടേറ്റ് ചെയ്യുകയോ (`meta.detections`, `meta.redacted`) അല്ലെങ്കിൽ പുനരെഴുതുകയോ മാത്രം ചെയ്യുന്നു.

#### തരം അനുസരിച്ചുള്ള തിരഞ്ഞെടുപ്പ്, കസ്റ്റം പാറ്റേണുകൾ, കണ്ടെത്തൽ കൗണ്ടറുകൾ

**Dashboard → Settings → Security → PII masking** ഏതാണ് മാസ്ക് ചെയ്യേണ്ടത് എന്ന് തിരഞ്ഞെടുക്കുന്നു. ഇത് മാസ്കിംഗ് ഓണാക്കുന്നില്ല: അത് ഇപ്പോഴും `PII_REDACTION_ENABLED` (റിക്വസ്റ്റ്), `PII_RESPONSE_SANITIZATION` (റെസ്പോൺസ് + SSE) എന്നിവയാണ്, രണ്ടും സ്ഥിരസ്ഥിതിയിൽ ഓഫാണ്.

- **തരം അനുസരിച്ചുള്ള തിരഞ്ഞെടുപ്പ്** — ബിൽറ്റ്-ഇൻ ഐഡികൾ `src/shared/constants/piiTypes.ts`-ൽ (`PII_BUILTIN_TYPES`) ലിസ്റ്റ് ചെയ്തിരിക്കുന്നു. സെറ്റ് ചെയ്യാത്തത് എന്നാൽ എല്ലാ തരങ്ങളും (ഈ ക്രമീകരണം നിലവിൽ വരുന്നതിന് മുമ്പുള്ള പെരുമാറ്റം). റിക്വസ്റ്റ് എൻജിന്റെ `ssn_us` പാറ്റേൺ `ssn`-ലേക്ക് മാപ്പ് ചെയ്യുന്നു. ടെംപ്ലേറ്റുകൾ (Minimal, Standard, Financial, Brazilian, USA, Full) UI-യിലെ ചെക്ക്ബോക്സുകൾ മാത്രം പൂരിപ്പിക്കുന്നു.
- **കസ്റ്റം പാറ്റേണുകൾ** — പരമാവധി 20 regex അല്ലെങ്കിൽ വൈൽഡ്കാർഡ് പാറ്റേണുകൾ (`*` = പരമാവധി 64 വൈറ്റ്സ്പേസ്-അല്ലാത്ത പ്രതീകങ്ങൾ, `?` = ഒന്ന്). പൊരുത്തങ്ങൾ `[CUSTOM_REDACTED]` ആയി മാറുന്നു. ഓരോ പാറ്റേണും `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`) വഴി കടന്നുപോകുന്നു: പരമാവധി 500 പ്രതീകങ്ങൾ, ഫ്ലാഗുകൾ `g i m s u` എന്നിവയിൽ പരിമിതപ്പെടുത്തണം, കംപൈൽ ചെയ്യണം, `safe-regex` പാസ് ചെയ്യണം (വിനാശകരമായ ബാക്ക്ട്രാക്കിംഗ്), ശൂന്യമായ സ്ട്രിങുമായോ റിഡാക്ഷൻ പ്ലേസ്ഹോൾഡറുമായോ പൊരുത്തപ്പെടരുത്. പരാജയപ്പെടുന്ന പാറ്റേൺ സേവ് ചെയ്യുമ്പോഴും ടെസ്റ്റ് ചെയ്യുമ്പോഴും നിരസിക്കും, പരാജയപ്പെടുന്ന സംഭരിച്ച വരി കംപൈൽ ചെയ്യുന്നതിനുപകരം റൺടൈമിൽ ഒഴിവാക്കും. മാസ്കിംഗ് ഓണായിരിക്കുമ്പോൾ മാത്രമേ കസ്റ്റം പാറ്റേണുകൾ പ്രവർത്തിക്കൂ.
- **കണ്ടെത്തൽ കൗണ്ടറുകൾ** — തരം അനുസരിച്ചുള്ള എണ്ണങ്ങൾ (പൊരുത്തപ്പെട്ട മൂല്യങ്ങൾ ഒരിക്കലുമല്ല), മെമ്മറിയിൽ സൂക്ഷിക്കുന്നു, റീസ്റ്റാർട്ടിൽ പുനഃസജ്ജീകരിക്കുന്നു (`src/lib/pii/piiDetectionStats.ts`). മാസ്കിംഗ് ഓണായിരിക്കുമ്പോൾ മാത്രം അവ വർദ്ധിക്കുന്നു.

ക്രമീകരണങ്ങൾ `key_value` ടേബിളിൽ (നെയിംസ്പേസ് `pii_settings`, `src/lib/db/piiSettings.ts`) സ്ഥിതി ചെയ്യുന്നു, 1 സെക്കൻഡ് കാഷെ വഴി വായിക്കുന്നു. API:

| രീതി   | പാത                      | ഉദ്ദേശ്യം                                                                             |
| ------ | ------------------------ | ------------------------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | ഫ്ലാഗ് അവസ്ഥ, `enabledTypes`, `customPatterns`, കണ്ടെത്തൽ കൗണ്ടറുകൾ                   |
| `PUT`  | `/api/settings/pii`      | `enabledTypes` (`null` = എല്ലാം) കൂടാതെ/അല്ലെങ്കിൽ `customPatterns` മാറ്റിസ്ഥാപിക്കുക |
| `POST` | `/api/settings/pii/test` | പരമാവധി 8 KB സാമ്പിളിനെതിരെ ഒരു പാറ്റേൺ ഡ്രൈ-റൺ ചെയ്യുക; ഒന്നും സംഭരിക്കില്ല          |

മൂന്നും മാനേജ്മെന്റ് ഓത്ത് ആവശ്യപ്പെടുന്നു, ബോഡി Zod ഉപയോഗിച്ച് വാലിഡേറ്റ് ചെയ്യുന്നു (`src/shared/validation/schemas/piiSettings.ts`).

### പ്രോംപ്റ്റ് ഇൻജെക്ഷൻ (`promptInjection.ts`)

ഉപയോക്താവ് നൽകുന്ന ഉള്ളടക്കത്തിലെ എതിരാളി ഘടനകൾ കണ്ടെത്തി കോൺഫിഗർ ചെയ്ത നയം നടപ്പാക്കുന്നു. പെരുമാറ്റം എൻവയോൺമെന്റ് വേരിയബിളുകളും കൺസ്ട്രക്ടർ ഓപ്ഷനുകളും നയിക്കുന്നു:

| ക്രമീകരണം          | Env വേരിയബിൾ                                                                                           | സ്ഥിരസ്ഥിതി | ഫലം                                                                                                                                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------ | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| പ്രവർത്തനക്ഷമം     | `INPUT_SANITIZER_ENABLED`                                                                              | `true`      | `false` ആകുമ്പോൾ, ഗാർഡ്റെയിൽ ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു.                                                                                                                                                                  |
| മോഡ്               | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                        | `warn`      | ഇൻജെക്ഷൻ നയം: `block`, `warn`, അല്ലെങ്കിൽ `log`. (ബാക്ക്-കോംപാറ്റിനായി `redact` സ്വീകരിക്കുന്നു, പക്ഷേ ഇൻജെക്ഷൻ ടെക്സ്റ്റ് **നീക്കം ചെയ്യുന്നില്ല**; റിക്വസ്റ്റ് PII പുനരെഴുത്ത് `PII_REDACTION_ENABLED` നിയന്ത്രിക്കുന്നു.) |
| ബ്ലോക്ക് ത്രെഷോൾഡ് | `blockThreshold` ഓപ്ഷൻ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (അലിയാസ് `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`      | ബ്ലോക്ക് ചെയ്യാൻ ആവശ്യമായ കുറഞ്ഞ തീവ്രത. സ്ഥിരസ്ഥിതിയിൽ Medium നിരീക്ഷണം മാത്രമാണ്.                                                                                                                                          |

**മോഡ് മുൻഗണന** (`getMode`): വിളിക്കുന്നയാളുടെ `options.mode` → `INJECTION_GUARD_MODE` **DB ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (Dashboard → Settings → Feature Flags) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. അതിനാൽ ഡാഷ്ബോർഡ് ഓവർറൈഡ് env വേരിയബിളുകളേക്കാൾ മുൻതൂക്കം നേടുന്നു, അതുകൊണ്ട് Feature Flags UI പ്രവർത്തിക്കുന്ന ഗാർഡിനെ തത്സമയം നിയന്ത്രിക്കുന്നു (റീസ്റ്റാർട്ട് വേണ്ട). DB വായന fail-safe ആണ്: പിശകുണ്ടായാൽ, ഗാർഡ് env അടിസ്ഥാനമാക്കിയുള്ള പെരുമാറ്റത്തിലേക്ക് തിരിച്ചുപോകുന്നു, ഓവർറൈഡ് സെറ്റ് ചെയ്തിട്ടില്ലെങ്കിൽ പെരുമാറ്റം env-മാത്രം റെസല്യൂഷന് തുല്യമാണ്.

കണ്ടെത്തൽ സ്രോതസ്സുകൾ:

1. `@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള `sanitizeRequest()` (പൈപ്പ്ലൈനിൽ മറ്റിടങ്ങളിൽ ഉപയോഗിക്കുന്ന പങ്കിട്ട ഡിറ്റക്ടർ സെറ്റ്).
2. ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (നിലവിൽ `system_override_inline`-ഉം `markdown_system_block`-ഉം, രണ്ടും `high` തീവ്രത).
3. കൺസ്ട്രക്ടർ ഓപ്ഷനുകൾ വഴി നൽകുന്ന ഓപ്ഷണൽ `customPatterns` (സ്ട്രിങുകൾ, regex, അല്ലെങ്കിൽ `{ name, pattern, severity }` റെക്കോർഡുകൾ).

`mode === "block"` **ഒപ്പം** കുറഞ്ഞത് ഒരു കണ്ടെത്തലെങ്കിലും തീവ്രത പരിധി കണ്ടുമുട്ടുമ്പോൾ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` തിരികെ നൽകുന്നു. `warn`/`log` മോഡുകളിൽ ഗാർഡ്റെയിൽ ലോഗ് ചെയ്യുന്നു, പക്ഷേ കോൾ അനുവദിക്കുന്നു. രജിസ്ട്രിയിലൂടെ പോകാതെ പ്രോംപ്റ്റുകൾ വിലയിരുത്തേണ്ട കോളർമാർക്കും പങ്കിട്ട ഹെൽപ്പർ `evaluatePromptInjection()` എക്സ്പോർട്ട് ചെയ്തിരിക്കുന്നു.

**സ്കാൻ പരിധി (v3.8.20):** ഡിറ്റക്ടർ കൂട്ടിച്ചേർത്ത പ്രോംപ്റ്റ് ടെക്സ്റ്റിന്റെ **ആദ്യ 16 KB** മാത്രം പരിശോധിക്കുന്നു — `src/shared/utils/inputSanitizer.ts`-ലെ `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ). `detectInjection()` ഉം `evaluatePromptInjection()` ഉം പാറ്റേൺ ലൂപ്പ് പ്രവർത്തിപ്പിക്കുന്നതിന് മുമ്പ് `slice(0, MAX_INJECTION_SCAN_BYTES)` ചെയ്യുന്നു. ഇൻജെക്ഷൻ നിർദ്ദേശങ്ങൾ ഇൻപുട്ടിന്റെ മുകളിലായി സ്ഥിതി ചെയ്യുന്നു, അതിനാൽ ഇത് കണ്ടെത്തൽ ദുർബലമാക്കാതെ നൂറുകണക്കിന് KB വലുപ്പമുള്ള പേലോഡുകളിൽ regex CPU/GC പരിമിതപ്പെടുത്തുന്നു (കാണുക #3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്കർ (`credentialMasker.ts`)

**രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു, സ്വതവേയുള്ള ചെയിനിൽ അവസാനത്തേത് (മുൻഗണന `95`). പുറത്തേക്കുള്ള പേലോഡിൽ നിന്നും (സന്ദേശ ഉള്ളടക്കം, ടൂൾ-കോൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ ഫലങ്ങൾ) **കൂടാതെ** പ്രൊവൈഡർ പ്രതികരണത്തിൽ നിന്നും അറിയപ്പെടുന്ന API-കീ / സീക്രട്ട്-ടോക്കൺ പാറ്റേണുകൾ റിഡാക്ട് ചെയ്യുന്നു, അതിനാൽ ഒരു പ്രോംപ്റ്റിലേക്ക് പേസ്റ്റ് ചെയ്ത (അല്ലെങ്കിൽ ഒരു ടൂൾ ഫലം വഴി തിരികെ പ്രതിധ്വനിപ്പിച്ച) ക്രെഡൻഷ്യൽ അപ്സ്ട്രീം പ്രൊവൈഡറിലേക്കോ തിരികെ ക്ലയന്റിലേക്കോ ചോർന്നുപോകുന്നില്ല.

- **ഓപ്റ്റ്-ഇൻ മാത്രം**, PII റിഡാക്ഷനുമായി (Hard Rule #20-നോട് അനുബന്ധം) സമാനമായ സമ്പ്രദായം:
  `settings.credentialRedactionEnabled === true` **അല്ലെങ്കിൽ**
  `CREDENTIAL_REDACTION_ENABLED=true` ആയാൽ മാത്രം പ്രവർത്തനക്ഷമം; അല്ലാത്തപക്ഷം പ്രവർത്തനരഹിതം. ഇത് ഓഫ് ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ ഒരു നോ-ഓപ്പ് ആണ് —
  അത് ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുന്നില്ല, ഒരിക്കലും വീണ്ടും എഴുതുന്നില്ല.
- `redactCredentials()` മുഴുവൻ പേലോഡ്/പ്രതികരണ ട്രീയിലൂടെ സഞ്ചരിക്കുന്നു (`walkValue()`, പ്രോട്ടോടൈപ്പ്-പൊല്യൂഷൻ-സുരക്ഷിതം, `WeakSet` വഴി സൈക്കിൾ-സുരക്ഷിതം), കൂടാതെ പൊരുത്തങ്ങൾ `[REDACTED:<type>]` പ്ലേസ്ഹോൾഡർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു, യഥാർത്ഥത്തിൽ മാറിയ ശാഖകൾ മാത്രം ക്ലോൺ ചെയ്യുന്നു.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ടോക്കണുകൾ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square), ക്ലൗഡ്
  കീകൾ (AWS ആക്സസ് കീ, Twilio, SendGrid, Mailgun), പ്രൈവറ്റ് കീകൾ / JWT-കൾ,
  ക്രെഡൻഷ്യൽ അടങ്ങിയ കണക്ഷൻ സ്ട്രിംഗുകൾ (`mongodb://user:pass@...`, മുതലായവ), കൂടാതെ
  ഒരു സാമാന്യ `Authorization`/`x-api-key`/`api-key`/`apikey` ഹെഡർ-മൂല്യ
  പാറ്റേൺ എന്നിവ ഉൾക്കൊള്ളുന്നു. ഹെഡർ രൂപത്തിലുള്ള കീകൾ (`authorization`, `x-api-key`, `api-key`,
  `apikey`) ഘടനാപരമായി റിഡാക്ട് ചെയ്യുന്നു (മൂല്യം മാത്രം, `Bearer `/`Basic ` പോലുള്ള
  സ്കീം പ്രിഫിക്സ് സംരക്ഷിക്കപ്പെടുന്നു), സാമാന്യ ടെക്സ്റ്റ് regex വഴിയല്ല.
- ഗാർഡ്റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുന്നില്ല; അത് `modifiedPayload` /
  `modifiedResponse` മാത്രം വീണ്ടും എഴുതുന്നു, കൂടാതെ `meta.credentialsRedacted`, `meta.count` അനോട്ടേറ്റ് ചെയ്യുന്നു.

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ചെയിനിനെ ഉടൻ അവസാനിപ്പിക്കുന്നു
  message?: string; // ബ്ലോക്ക് ചെയ്യുമ്പോൾ പ്രദർശിപ്പിക്കുന്നു
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന മാറ്റിയെഴുതുന്നതിനായി preCall മടക്കിനൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം മാറ്റിയെഴുതുന്നതിനായി postCall മടക്കിനൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

`void`, `{}`, അല്ലെങ്കിൽ `{ block: false }` എന്നിവയിൽ ഏതെങ്കിലും മടക്കിനൽകിക്കൊണ്ട് ഒരു ഗാർഡ്റെയിൽ "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നു. `modifiedPayload`/`modifiedResponse` മടക്കിനൽകുന്നത്, തുടർന്നുള്ള ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.
`signal?: AbortSignal` കോളറിന്റെ ലൈഫ്സൈക്കിൾ ഗാർഡ്റെയിലുകളിലേക്ക് എത്തിക്കുന്നു. അഭ്യർത്ഥന അബോർട്ട് ചെയ്യുന്നത് മനഃപൂർവമുള്ള fail-open ഒഴിവാക്കലാണ്: റോ മീഡിയയെ പിന്തുണയ്ക്കില്ലെന്ന് അറിയാവുന്ന ടാർഗറ്റിലേക്ക് അത് പുനഃസ്ഥാപിക്കാതെ മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തനം നിർത്തുകയും ക്ലീനപ്പ് നടത്തുകയും ചെയ്യുന്നു.

## രജിസ്ട്രി (`registry.ts`)

സിംഗിൾടൺ `guardrailRegistry` താഴെപ്പറയുന്നവ ലഭ്യമാക്കുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ നോർമലൈസ് ചെയ്ത പേരനുസരിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു), തുടർന്ന് ആരോഹണ `priority` ക്രമത്തിൽ വീണ്ടും സോർട്ട് ചെയ്യുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് ഹെൽപ്പറുകൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, `modifiedPayload` വഴി പേലോഡ് കൈമാറുന്നു, ആദ്യത്തെ `block: true` ലഭിക്കുമ്പോൾ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ ഭാഗത്തും ഇതേ ഫ്ലോ പിന്തുടരുന്നു.
- `resetGuardrailsForTests({ registerDefaults })` — ശുദ്ധമായ ടെസ്റ്റ് ഐസൊലേഷനായി സ്റ്റേറ്റ് മായ്ക്കുകയും, ആവശ്യമെങ്കിൽ ഡിഫോൾട്ടുകൾ വീണ്ടും രജിസ്റ്റർ ചെയ്യുകയും ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` മടക്കിനൽകുന്നു. ഇവിടെ `results` എന്നത് ഓരോ ഗാർഡ്റെയിലിന്റെയും `blocked`, `skipped`, `modified`, `error`, `meta` ഫീൽഡുകൾ ഉൾക്കൊള്ളുന്ന `GuardrailExecutionResult` റെക്കോർഡുകളുടെ ഒരു അറേയാണ്; ട്രേസിംഗിന് ഇത് ഉപകാരപ്രദമാണ്.

### ഓരോ അഭ്യർത്ഥനയ്ക്കുമായി ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കൽ

നിലവിലെ അഭ്യർത്ഥനയ്ക്കായി ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ ഡ്യൂപ്ലിക്കേറ്റുകളില്ലാത്ത ഒരു ലിസ്റ്റ് `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` സമാഹരിക്കുന്നു. അഞ്ച് ചാനലുകളുണ്ട്; അവ ഈ ക്രമത്തിൽ വായിക്കുകയും ഒരൊറ്റ ലിസ്റ്റിലേക്ക് ലയിപ്പിക്കുകയും ചെയ്യുന്നു (ഡ്യൂപ്ലിക്കേറ്റുകൾ നീക്കുമ്പോൾ ആദ്യം വന്നത് നിലനിർത്തുന്നു):

1. `apiKeyInfo.disabledGuardrails`
2. അഭ്യർത്ഥന ബോഡിയിലെ `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
3. അഭ്യർത്ഥന ബോഡിയിലെ `metadata.disabledGuardrails` (`metadata` ഒരു ഒബ്ജക്റ്റായിരിക്കുമ്പോൾ മാത്രം)
4. ഹെഡർ `x-omniroute-disabled-guardrails`
5. ലെഗസി ഹെഡർ `x-disabled-guardrails`

രണ്ട് ഹെഡറുകളും ഉൾപ്പെടെ അഞ്ച് ചാനലുകളും ലയിപ്പിക്കുന്നു: `x-omniroute-disabled-guardrails`, `x-disabled-guardrails` എന്നിവ രണ്ടും അയയ്ക്കുന്നത് അവയുടെ ലിസ്റ്റുകളുടെ യൂണിയൻ ഒഴിവാക്കുന്നു; കൂടാതെ, ശൂന്യമായ ഒരു മോഡേൺ ഹെഡർ ഇനി ലെഗസി ഹെഡറിനെ മറയ്ക്കില്ല
([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412), [#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805)-ൽ പരിഹരിച്ചു).

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ അറേകളോ കോമ ഉപയോഗിച്ച് വേർതിരിച്ച സ്ട്രിംഗോ ആകാം; പേരുകളിലെ അധിക സ്പേസുകൾ നീക്കി അവയെ lowercase kebab-case-ലേക്ക് നോർമലൈസ് ചെയ്യുന്നു (`pii_masker` → `pii-masker`), കൂടാതെ ശൂന്യമായ എൻട്രികൾ ഒഴിവാക്കുന്നു. ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു; പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകൾ രജിസ്ട്രി ഒഴിവാക്കുന്നു (`results`-ൽ `skipped: true`).

പ്രവർത്തനരഹിതമാക്കൽ ലിസ്റ്റ് **രജിസ്ട്രിയെ** മാത്രമാണ് ബാധിക്കുന്നത്. Prompt-injection `block` മോഡ് നിർബന്ധിതമായ ഒരു അതിർത്തിയാണ്: injection-guard മിഡിൽവെയർ
(`src/middleware/promptInjectionGuard.ts`) കോളർ നിയന്ത്രിക്കുന്ന ഒരു disable ലിസ്റ്റും കൂടാതെ `evaluatePromptInjection()` വിളിക്കുന്നു (മുമ്പ് അത് നടത്തിയിരുന്ന, പ്രവർത്തനരഹിതമായ
`resolveDisabledGuardrails({ body })` കോൾ
[#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934)-ൽ നീക്കം ചെയ്തു), അതിനാൽ `prompt-injection` പ്രവർത്തനരഹിതമാക്കുന്ന ഒരു അഭ്യർത്ഥന പോലും `block` മോഡിൽ നിരസിക്കപ്പെടും. ഇത് ഉദ്ദേശിച്ചുള്ള രൂപകൽപ്പനയാണ്. പ്രവർത്തനരഹിതമാക്കൽ ചാനലുകൾ കോളർ നിയന്ത്രിക്കുന്നവയാണ് (അഭ്യർത്ഥന ബോഡി,
മെറ്റാഡാറ്റ, ഹെഡറുകൾ), കൂടാതെ ഓപ്പറേറ്റർ സജ്ജമാക്കിയ ഒരു സുരക്ഷാ നിയന്ത്രണം ഓഫ് ചെയ്യാൻ കോളർക്ക് കഴിയരുത്
([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). [#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412)-ലെ ഹെഡർ യൂണിയൻ ഏതൊക്കെ രജിസ്ട്രി ഗാർഡ്റെയിലുകളാണ് ഒഴിവാക്കപ്പെടുന്നത് എന്നത് മാത്രമാണ് മാറ്റുന്നത്; മിഡിൽവെയർ മറികടക്കാൻ അത് ഒരു ക്ലയന്റിനെ അനുവദിക്കുന്നില്ല. നിർബന്ധിതമായ ഓരോ കീയ്ക്കും ഓരോ ഗ്രൂപ്പിനുമുള്ള ഗാർഡ്റെയിൽ നയങ്ങൾ v4 RFC [#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417)-ൽ ട്രാക്ക് ചെയ്യുന്നു.
[കവറേജും പരിമിതികളും](#coverage-and-limits) കാണുക.

## എക്സിക്യൂഷൻ ക്രമം

`src/sse/handlers/chat.ts`-ലൂടെയും `open-sse/handlers/chatCore.ts`-ലൂടെയും (ചാറ്റ്-ഫാമിലി റൂട്ടുകൾ [കവറേജും പരിധികളും](#coverage-and-limits)-ന് കീഴിൽ ലിസ്റ്റ് ചെയ്തിരിക്കുന്നു) കടന്നുപോകുന്ന ഓരോ അഭ്യർത്ഥനയ്ക്കും:

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽനിന്ന് സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ഗാർഡ്റെയിലുകൾ ആരോഹണ മുൻഗണനാ ക്രമത്തിൽ പ്രവർത്തിപ്പിക്കുന്നു:
   - ഡിസേബിൾ ചെയ്ത ഗാർഡ്റെയിലുകൾ `skipped` എന്ന് രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall` `modifiedPayload` വഴി പേലോഡ് മാറ്റിയെഴുതാം.
   - ആദ്യത്തെ `block: true` ചെയിൻ ഷോർട്ട്-സർക്യൂട്ട് ചെയ്യുന്നു, ഹാൻഡ്ലർ ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം നൽകുന്നു.
3. (സാധ്യമായി മാറ്റിയെഴുതിയ) പേലോഡ് കോംബോ റൗട്ടിംഗിലേക്കും അപ്സ്ട്രീം ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. **നോൺ-സ്ട്രീമിംഗ് മാത്രം:** പ്രതികരണം അസംബിൾ ചെയ്ത ശേഷം, `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിൽ അതേ ചെയിൻ പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` അപ്സ്ട്രീം പ്രതികരണം ഉപേക്ഷിച്ച് HTTP 400 നൽകുന്നു. സ്ട്രീം ചെയ്ത പ്രതികരണങ്ങൾ ഈ ഘട്ടം പൂർണ്ണമായും ഒഴിവാക്കുന്നു.

എറർ ത്രോ ചെയ്യുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും `logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു, പക്ഷേ ചെയിൻ തുടരുന്നു — രൂപകൽപ്പനയിൽത്തന്നെ ഫെയിൽ-ഓപ്പൺ.

## കവറേജും പരിധികളും

ഗാർഡ്റെയിൽ രജിസ്ട്രി ചാറ്റ് പൈപ്പ്ലൈനിൽ മാത്രമാണ് വയർ ചെയ്തിരിക്കുന്നത്. ഈ പരിധികൾ `tests/unit/guardrail-pipeline-wiring-characterization.test.ts`-ഉം `tests/unit/guardrail-pipeline-characterization.test.ts`-ഉം പിൻ ചെയ്യുന്നു; പെരുമാറ്റം മാറുമ്പോൾ ആ ടെസ്റ്റുകൾ ബോധപൂർവ്വം അപ്ഡേറ്റ് ചെയ്യുക.

### ഹൂക്കുകൾ പ്രവർത്തിക്കുന്ന സ്ഥലങ്ങൾ

| ഹൂക്ക് / നിയന്ത്രണം              | പ്രവർത്തിക്കുന്നത്                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runPreCallHooks`                | `handleChat` (`src/sse/handlers/chat.ts`) കൈകാര്യം ചെയ്യുന്ന അഭ്യർത്ഥനകൾ: `/v1/chat/completions`, `/v1/completions`, `/v1/messages`, `/v1/responses` (ഒപ്പം `/v1/responses/*`), `/v1/relay/chat/completions`, `/v1/providers/{provider}/chat/completions`, `/v1/api/chat`, `/v1/antigravity`, `/v1beta/models/*`, കൂടാതെ ടെലിഗ്രാം ചാറ്റ് പ്രോക്സിയും. ഡാഷ്ബോർഡ് ടെസ്റ്റ് എൻഡ്പോയിന്റ് `/api/guardrails/test`-ഉം ഇതിൽ ഉൾപ്പെടുന്നു. ഒരു പ്രീ-കോൾ ബ്ലോക്ക് HTTP 400 നൽകുന്നു. |

### ഉൾപ്പെടുത്താത്തവ

- **മീഡിയ, എംബെഡ്ഡിംഗ്സ്, ഡാറ്റ റൂട്ടുകൾ** (`/v1/images/*`, `/v1/embeddings`,
  `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`,
  `/v1/rerank`, `/v1/search`, `/v1/moderations`) രജിസ്ട്രിയിൽ എത്തുന്നില്ല. അവിടെ
  PII മാസ്കിംഗോ ക്രെഡൻഷ്യൽ മാസ്കിംഗോ മോഡാലിറ്റി ബ്രിഡ്ജോ പ്രവർത്തിക്കുന്നില്ല. അവയുടെ
  ഏക പരിശോധന ലെഗസി ഇഞ്ചക്ഷൻ-ഗാർഡ് മിഡിൽവെയർ മാത്രമാണ്.
- **സ്ട്രീം ചെയ്ത പ്രതികരണങ്ങൾക്ക്** പോസ്റ്റ്-കോൾ ഗാർഡ്റെയിലുകൾ ലഭിക്കുന്നില്ല: `pii-masker`-ഓ
  `credential-masker`-ഓ പോസ്റ്റ്-കോൾ ഇല്ല, പോസ്റ്റ്-കോൾ ബ്ലോക്കുമില്ല. സ്ട്രീമിംഗ് PII
  ട്രാൻസ്ഫോം മാത്രം ബാധകമാണ് (`PII_RESPONSE_SANITIZATION` ഓണായിരിക്കുമ്പോൾ). സ്ട്രീം ചെയ്ത
  പ്രതികരണത്തിൽ തിരികെ വരുന്ന ക്രെഡൻഷ്യൽ റിഡാക്ട് ചെയ്യപ്പെടുന്നില്ല.
- **ഡിസേബിൾ ചാനലുകളും മിഡിൽവെയറും (രൂപകൽപ്പനപ്രകാരം):** മിഡിൽവെയർ പ്രോംപ്റ്റ് ഇഞ്ചക്ഷൻ
  വിലയിരുത്തുന്നത് സ്വന്തം `evaluatePromptInjection()` കോളിലൂടെയാണ്, കോളർ നിയന്ത്രിക്കുന്ന
  ഡിസേബിൾ ലിസ്റ്റ് ഒന്നും കൈമാറാതെ. `block` മോഡ് നിർബന്ധിത അതിർത്തിയാണ്; കോളർ
  നിയന്ത്രിക്കുന്ന ഡിസേബിളുകൾക്ക് ഇത് മറികടക്കാനാവില്ല, ചാറ്റ്-ഫാമിലി റൂട്ടുകളിലും
  ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). `prompt-injection`
  ഡിസേബിൾ ചെയ്യുമ്പോൾ രജിസ്ട്രി ഗാർഡ്റെയിൽ മാത്രം ഒഴിവാക്കപ്പെടുന്നു.

### പോസ്റ്റ്-കോളിന് മുമ്പ് പ്രതികരണം കാണുന്നത് എന്ത്

നോൺ-സ്ട്രീമിംഗ് പാതയിൽ ക്രമം ഇതാണ്: മെമ്മറി എക്സ്ട്രാക്ഷൻ → ബിൽറ്റ്-ഇൻ ടൂൾ
എക്സിക്യൂഷൻ → പോസ്റ്റ്-കോൾ ഗാർഡ്റെയിലുകൾ → പോസ്റ്റ്-കോൾ ബ്ലോക്ക് എക്സിറ്റ് → സെമാന്റിക്-കാഷെ സ്റ്റോർ.

- **മെമ്മറി എക്സ്ട്രാക്ഷനും** **ടൂൾ എക്സിക്യൂഷനും** പോസ്റ്റ്-കോൾ ഗാർഡ്റെയിലുകൾക്ക് അത് തിരുത്താനോ തടയാനോ കഴിയുന്നതിന് മുമ്പ് തന്നെ പ്രതികരണം കാണുന്നു. [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) മുതൽ,
  `PII_RESPONSE_SANITIZATION` ഓണായിരിക്കുമ്പോൾ (സ്ട്രീമിംഗിലും നോൺ-സ്ട്രീമിംഗിലും) മെമ്മറി
  എക്സ്ട്രാക്ഷൻ എക്സ്ട്രാക്റ്റ് ചെയ്ത ടെക്സ്റ്റ് `sanitizePII` വഴി കടത്തിവിടുന്നു, എന്നാൽ പോസ്റ്റ്-കോൾ
  പിന്നീട് തടയുന്ന ഒരു പ്രതികരണം ഇപ്പോഴും മെമ്മറിക്കും ടൂളുകൾക്കും നൽകപ്പെട്ടിട്ടുണ്ട്.
- **സെമാന്റിക് കാഷെ** പോസ്റ്റ്-കോളിന് ശേഷമാണ് പ്രതികരണം സംഭരിക്കുന്നത്, അതിനാൽ അത്
  തിരുത്തിയ പ്രതികരണമാണ് സംഭരിക്കുന്നത്, തടയപ്പെട്ട പ്രതികരണം ഒരിക്കലും കാഷെ ചെയ്യപ്പെടുന്നില്ല. കാഷെ എൻട്രികൾ
  ഓരോ API കീയുടെ അടിസ്ഥാനത്തിൽ കീ ചെയ്യുന്നു.

## കോൺഫിഗറേഷൻ

ബിൽട്ട്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | ഫലം                                                                                                                |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | കണ്ടെത്തൽ പൂർണ്ണമായും നിർജ്ജീവമാക്കാൻ `false` സെറ്റ് ചെയ്യുക.                                                      |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജെക്ഷൻ പോളിസി: `warn`, `block`, അല്ലെങ്കിൽ `log`. പഴയ മൂല്യമായ `redact` ഇൻജെക്ഷൻ ടെക്സ്റ്റ് മാറ്റിയെഴുതുന്നില്ല. |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജെക്ഷൻ ഗാർഡിന്റെ മോഡ്; എൻവയോൺമെന്റ് വേരിയബിളുകളെ **ഓവർറൈഡ്** ചെയ്യുന്ന DB ഫീച്ചർ ഫ്ലാഗും ഇതാണ് (DB > ENV).       |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (ഡിഫോൾട്ട്), `medium`, അല്ലെങ്കിൽ `low`.                   |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` എന്നതിന്റെ പഴയ അലിയാസ്.                                                          |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആയാൽ, അഭ്യർത്ഥനയിലെ PII റിഡാക്ട് ചെയ്യപ്പെടുന്നു (ഇൻജെക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രം).                        |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (downstream) | പ്രതികരണ വശത്തെ മാസ്കർ സ്വഭാവം നിയന്ത്രിക്കുന്നു.                                                                  |

Modality Bridge ഗാർഡ്റെയിലുകൾ എൻവയോൺമെന്റ് വേരിയബിളുകളിൽ നിന്നല്ല, DB-ബാക്ക്ഡ് സെറ്റിംഗ്സ്
സ്റ്റോറിൽ (`getSettings()`) നിന്നാണ് റൺടൈം കോൺഫിഗ് വായിക്കുന്നത്. Vision-ന്റെ പ്രൈമറി കീകൾ
`modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`,
`modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`,
`modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`,
`modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`,
`modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, കൂടാതെ
`modalityBridgeCacheMaxEntries` എന്നിവയാണ്. പഴയ
`visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്ത ഒരു-സൈക്കിൾ റീഡ്
ഫാൾബാക്ക് ആയി മാത്രമാണ് സ്വീകരിക്കുന്നത്; ഡാഷ്ബോർഡ് എഴുത്തുകൾ പ്രൈമറി കീകൾ ഉപയോഗിക്കുന്നു. ഡിഫോൾട്ടുകളും ഫാൾബാക്ക്
റിസോൾവറും `src/shared/constants/modalityBridgeDefaults.ts` ൽ ആണ്, പഴയ
കോൺസ്റ്റന്റുകൾ `src/shared/constants/visionBridgeDefaults.ts` ൽ നിലനിർത്തിയിരിക്കുന്നു.

Audio `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`,
`modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവയും, പങ്കിട്ട
`modalityBridgeCache*` സെറ്റിംഗുകളും ഉപയോഗിക്കുന്നു. ഈ കീകൾ Modality Bridge
സ്കീമയോടൊപ്പമാണ് അവതരിപ്പിച്ചത് എന്നതിനാൽ Audio-യ്ക്ക് പഴയ-കീ ഫാൾബാക്ക് ഇല്ല.

Video `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`,
`modalityBridgeVideoModel`,
`modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`,
`modalityBridgeVideoMaxVideos`, `modalityBridgeVideoTimeout` എന്നിവയും, പങ്കിട്ട
`modalityBridgeCache*` സെറ്റിംഗുകളും ഉപയോഗിക്കുന്നു. FFmpeg/ffprobe ഓപ്ഷണൽ
ഓപ്പറേഷണൽ ഡിപ്പൻഡൻസികൾ ആയതിനാലും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും
മോഡൽ ചെലവും കൂട്ടുന്നതിനാലും ഇത് സ്വതവേ നിർജ്ജീവമാണ്.

## ഇഷ്ടാനുസൃത ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1. `BaseGuardrail` വിപുലീകരിച്ച് `src/lib/guardrails/myGuardrail.ts` സൃഷ്ടിക്കുക.
2. `preCall` കൂടാതെ/അല്ലെങ്കിൽ `postCall` നടപ്പിലാക്കുക.
3. ഒന്നുകിൽ ഇംപോർട്ട് സമയത്ത് രജിസ്റ്റർ ചെയ്യുക (`registerDefaultGuardrails`-ൽ നിന്ന് പുഷ് ചെയ്യുക) അല്ലെങ്കിൽ
   റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — രജിസ്ട്രി ഒരേ നോർമലൈസ് ചെയ്ത പേരുള്ള ഏതൊരു മുൻ ഗാർഡ്റെയിലിനെയും മാറ്റിസ്ഥാപിക്കുന്നു.
4. `tests/unit/`-ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## ടെസ്റ്റിംഗ്

അറിയപ്പെടുന്ന അവസ്ഥയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക.
ശൂന്യമായ ഒരു രജിസ്ട്രിയിൽ നിന്ന് ആരംഭിച്ച് പരിശോധിക്കുന്ന ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ ചെയ്യാൻ `{ registerDefaults: false }` നൽകുക. വിഷൻ ബ്രിഡ്ജ് ഡിപ്പൻഡൻസി ഇൻജക്ഷൻ സ്വീകരിക്കുന്നു (`deps.getSettings`, `deps.callVisionModel`); ഓഡിയോ ബ്രിഡ്ജ് ക്രമീകരണങ്ങൾ, കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുപ്പ്, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കുള്ള തത്തുല്യമായ സീമുകൾ വെളിപ്പെടുത്തുന്നു. അതിനാൽ ടെസ്റ്റുകൾക്ക് DB അല്ലെങ്കിൽ നെറ്റ്വർക്ക് ആക്സസ് ഇല്ലാതെ രണ്ട് പ്രവാഹങ്ങളും പ്രവർത്തിപ്പിക്കാം.

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജും റെഡ്-ടീമും (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഇൻജക്ഷൻ-ഗാർഡ് (`createInjectionGuard` / `withInjectionGuard`) ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളും ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE` നെ മാനിക്കുന്നു (സ്ഥിരസ്ഥിതി `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` നൽകുന്നു).

| തരം                       | റൂട്ടുകൾ                                                                                                                                             | സ്ഥിരസ്ഥിതി മോഡ് |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| ടെക്സ്റ്റ് (നിലവിലുള്ളത്) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn             |
| ജനറേറ്റീവ്                | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn             |
| ഡാറ്റ                     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn             |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (നൈറ്റ്ലി, `nightly-llm-security.yml`):** promptfoo, `INJECTION_GUARD_MODE=block`-ൽ ഓരോ റൂട്ടും OWASP-LLM കോർപ്പസ് തടയുന്നുവെന്ന് സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ പ്രവർത്തിപ്പിക്കുന്നു (രഹസ്യമില്ലാതെ ഒഴിവാക്കുന്നു).
`moderations` സ്ഥിരതയ്ക്കായി ഉൾപ്പെടുത്തിയിരിക്കുന്നു. ബ്ലോക്ക് മോഡ് നിർബന്ധിത അതിർത്തിയാണ്: `evaluatePromptInjection()`
മിഡിൽവെയർ അതിന് നൽകുന്ന പെർ-റിക്വസ്റ്റ് ഡിസേബിൾ ലിസ്റ്റ് അവഗണിക്കുന്നു, അതിനാൽ `disabledGuardrails` ഒരു റൂട്ടിനെയും അതിൽ നിന്ന് **ഒഴിവാക്കുന്നില്ല** ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).

നൈറ്റ്ലി വർക്ക്ഫ്ലോയിൽ (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ
ഡിസ്പാച്ച്) രണ്ട് ജോബുകളുണ്ട്:

- **`promptfoo-guard` (ബ്ലോക്കിംഗ്)** — `INJECTION_GUARD_MODE=block`-നൊപ്പം `promptfoo eval -c promptfooconfig.yaml`
  പ്രവർത്തിപ്പിക്കുന്നു. ഓരോ എതിരാളി കേസും (ഉദാ. "എല്ലാ മുൻ നിർദ്ദേശങ്ങളും അവഗണിക്കുക…", DAN-ശൈലിയിലുള്ള ജയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ
  `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശകം)** — പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay`
  പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പ്രൊവൈഡർ രഹസ്യത്തിൽ (`PROMPTFOO_PROVIDER_KEY`) ഗേറ്റ് ചെയ്തിരിക്കുന്നു; സൗമ്യമായി ഒഴിവാക്കുകയും
  `|| true` സഫിക്സ് ചേർക്കുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടുത്താതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`)
കവറേജ് പ്രോംപ്റ്റ് ഉള്ള എല്ലാ `/v1` റൂട്ടുകളിലും വ്യാപിക്കുന്നു; പ്രോംപ്റ്റ് ടെക്സ്റ്റ്
`src/shared/utils/inputSanitizer.ts`-ലെ `extractMessageContents()` വഴി
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`-ൽ നിന്ന് എടുക്കുന്നു.
