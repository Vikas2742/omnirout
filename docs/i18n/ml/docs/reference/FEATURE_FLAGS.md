> OmniRoute-ൻ്റെ സ്വഭാവം **പുനർവിന്യാസം കൂടാതെ** മാറ്റുന്ന റൺടൈം ടോഗിളുകൾ.
> ഇവിടെ ലിസ്റ്റ് ചെയ്തിട്ടുള്ള എല്ലാ ഫ്ലാഗുകളും
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> എന്ന ഫയലിൽ നിർവചിച്ചിരിക്കുന്നു — ഇത് വിവരങ്ങളുടെ ഏക ഉറവിടമാണ്. ഡാഷ്ബോർഡും REST API-യും ഈ ഫയലിൽ നിന്നാണ് വായിക്കുന്നത്, അതിനാൽ താഴെയുള്ള പട്ടിക 1:1 എന്ന രീതിയിൽ അതിനോട് യോജിപ്പിച്ച് ജനറേറ്റ് ചെയ്തിരിക്കുന്നു.

## ഫീച്ചർ ഫ്ലാഗുകൾ എന്തൊക്കെയാണ്

ഒരു ഫീച്ചർ ഫ്ലാഗ് എന്നത് പേരുള്ള ഒരു ടോഗിൾ (ബൂളിയൻ അല്ലെങ്കിൽ എനം) ആണ്, അതിൻ്റെ മൂല്യം റൺടൈമിൽ മാറ്റാനും ഡാറ്റാബേസിൽ നിലനിർത്താനും കഴിയും, ഇതിന് പ്രോസസ്സ് പുനർവിന്യാസം ആവശ്യമില്ല. ഓരോ ഫ്ലാഗും ഒരു `FeatureFlagDefinition` ഉപയോഗിച്ച് വിവരിക്കുന്നു, അതിന് ഒരു `key`, `label`, `description`, `category`, `defaultValue`, `type`, കൂടാതെ ഒരു `requiresRestart` സൂചനയും ഉണ്ട്.

### റെസല്യൂഷൻ ഓർഡർ

ഒരു ഫ്ലാഗിൻ്റെ **ഫലപ്രദമായ മൂല്യം** [`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) ഉപയോഗിച്ച് ഈ മുൻഗണനയോടെ (ഏറ്റവും ഉയർന്നത് വിജയിക്കുന്നു) പരിഹരിക്കുന്നു:

1. **DB ഓവർറൈഡ്** — `key_value` പട്ടികയിൽ `feature_flags` നെയിംസ്പേസിന് കീഴിൽ സംഭരിച്ചിരിക്കുന്ന ഒരു മൂല്യം (ഡാഷ്ബോർഡ് വഴിയോ REST API വഴിയോ സജ്ജീകരിച്ചിരിക്കുന്നു).
2. **പരിസ്ഥിതി വേരിയബിൾ** — `process.env[<KEY>]`, സജ്ജീകരിച്ചിട്ടുണ്ടെങ്കിൽ, ശൂന്യമല്ലെങ്കിൽ.
3. **നിർവചന ഡിഫോൾട്ട്** — `featureFlagDefinitions.ts`-ൽ നിന്നുള്ള `defaultValue`.

ഒരു ബൂളിയൻ ഫ്ലാഗ് **പ്രവർത്തനക്ഷമമാക്കിയിരിക്കുന്നു** എന്ന് കണക്കാക്കുന്നത് അതിൻ്റെ ഫലപ്രദമായ മൂല്യം `"true"`, `"1"`, അല്ലെങ്കിൽ `"yes"` ( `isFeatureFlagEnabled()` കാണുക) ആയിരിക്കുമ്പോഴാണ്.

> [!NOTE]
> മിക്ക ഫ്ലാഗുകൾക്കും [`ENVIRONMENT.md`](./ENVIRONMENT.md) എന്നതിൽ രേഖപ്പെടുത്തിയിട്ടുള്ള **അതേ പേരിൽ** ഒരു അനുയോജ്യമായ പരിസ്ഥിതി വേരിയബിളും ഉണ്ട്. ഫ്ലാഗിൻ്റെ DB ഓവർറൈഡ് ആ പരിസ്ഥിതി വേരിയബിളിന് മുൻഗണന നൽകുന്നു. `requiresRestart: true` ഉള്ള ഒരു ഫ്ലാഗ് ഉടനടി നിലനിർത്തുന്നു, പക്ഷേ പ്രോസസ്സ് ആരംഭിക്കുമ്പോൾ മാത്രമേ വീണ്ടും വായിക്കുകയുള്ളൂ — ഇത് ടോഗിൾ ചെയ്യുന്നത് ഡാഷ്ബോർഡിൽ ഒരു **"സെർവർ പുനരാരംഭിക്കുക"** ബാനർ കാണിക്കുന്നു.

## ഫ്ലാഗ് പട്ടിക

6 വിഭാഗങ്ങളിലായി 86 ഫ്ലാഗുകൾ. **സ്ഥിരസ്ഥിതി** എന്നത് നിർവചനത്തിലെ സ്ഥിരസ്ഥിതി മൂല്യമാണ് — DB ഓവർറൈഡോ എൻവയോൺമെന്റ് വേരിയബിളോ ഇല്ലാത്തപ്പോൾ

## ഫ്ലാഗുകൾ ടോഗിൾ ചെയ്യുന്നു

### ഡാഷ്ബോർഡ്

**ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ → ഫീച്ചർ ഫ്ലാഗുകൾ**
(`/dashboard/settings/feature-flags`) എന്നതിലേക്ക് പോകുക. ഗ്രിഡ്
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
പിന്തുണയ്ക്കുന്നു:

- കീ അല്ലെങ്കിൽ വിവരണം ഉപയോഗിച്ച് **തിരയുക**, വിഭാഗം അനുസരിച്ച് **ഫിൽട്ടർ ചെയ്യുക** (കൂടാതെ ഒരു സിന്തറ്റിക്
  **റീസ്റ്റാർട്ട് ആവശ്യമാണ്** എന്ന കാഴ്ചയും).
- ബൂളിയൻ ഫ്ലാഗുകൾക്കായി ഒരു **ടോഗിൾ**, എനം ഫ്ലാഗുകൾക്കായി ഒരു **ഡ്രോപ്പ്ഡൗൺ**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- ഓരോ ഫ്ലാഗിനും ഒരു **സോഴ്സ് ബാഡ്ജ്** — `DB`, `ENV`, അല്ലെങ്കിൽ `DEF` — ഫലപ്രദമായ മൂല്യം എവിടെ നിന്ന് വന്നുവെന്ന് കാണിക്കുന്നു.
- ഓവർറൈഡ് ഒഴിവാക്കാൻ ഒരു **റീസെറ്റ്** ബട്ടൺ (`DB`-യിൽ നിന്ന് ലഭിച്ച ഫ്ലാഗുകൾക്ക് മാത്രം കാണിക്കുന്നു), താഴെയായി ഒരു **എല്ലാ ഓവർറൈഡുകളും റീസെറ്റ് ചെയ്യുക** ബട്ടൺ.
- ഒരു `requiresRestart` ഫ്ലാഗ് മാറ്റുമ്പോൾ ഒരു **സെർവർ റീസ്റ്റാർട്ട് ചെയ്യുക** ബാനർ.

### REST API

എല്ലാ പ്രവർത്തനങ്ങളും ഒരു റൂട്ടിലൂടെയാണ് നടക്കുന്നത്:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
ഓരോ രീതിക്കും ഒരു പ്രാമാണീകരിച്ച ഡാഷ്ബോർഡ് സെഷൻ ആവശ്യമാണ് (`401` അല്ലെങ്കിൽ).

#### `GET /api/settings/feature-flags`

ഓരോ ഫ്ലാഗിനെയും അതിന്റെ ഫലപ്രദമായ മൂല്യം, ഉറവിടം, ഒരു സംഗ്രഹം എന്നിവ സഹിതം തിരികെ നൽകുന്നു.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

ഒരു ഓവർറൈഡ് സജ്ജീകരിക്കുക അല്ലെങ്കിൽ നീക്കം ചെയ്യുക. ബോഡി: `{ key: string; value?: string }`.
`value` ഒഴിവാക്കുന്നത് ഓവർറൈഡ് നീക്കംചെയ്യുന്നു (env / default പുനഃസ്ഥാപിക്കുന്നു).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

പ്രതികരണം പുതിയ `effectiveValue`/`source`, `previousValue`/
`previousSource`, കൂടാതെ `requiresRestart` എന്നിവയെ പ്രതിഫലിപ്പിക്കുന്നു. അറിയാത്ത കീകൾ, പരിധിക്ക് പുറത്തുള്ള എനം
മൂല്യങ്ങൾ എന്നിവ `400` ഉപയോഗിച്ച് നിരസിക്കപ്പെടും.

#### `DELETE /api/settings/feature-flags`

**എല്ലാ** DB ഓവർറൈഡുകളും ഒരേസമയം മായ്ക്കുന്നു, ഓരോ ഫ്ലാഗിനെയും അതിന്റെ env / default
മൂല്യത്തിലേക്ക് പുനഃസ്ഥാപിക്കുന്നു. `{ cleared: <count>, message: "..." }` എന്ന് തിരികെ നൽകുന്നു.

> [!NOTE]
> `requiresRestart: true` ഉള്ള ഫ്ലാഗുകൾ ഒരു പ്രോസസ്സ് റീലോഡിന് ശേഷം മാത്രമേ പ്രാബല്യത്തിൽ വരൂ.
> ഡാഷ്ബോർഡിന്റെ റീസ്റ്റാർട്ട് ഫ്ലോ `POST /api/restart` എന്ന് വിളിക്കുകയും തുടർന്ന് സെർവർ വീണ്ടും പ്രവർത്തിക്കുന്നത് വരെ `GET /api/health/ping` എന്ന് പോൾ ചെയ്യുകയും ചെയ്യുന്നു.

## അടിയന്തര ബജറ്റ് ഫാൾബാക്ക്

`OMNIROUTE_EMERGENCY_FALLBACK` (`runtime` വിഭാഗം, ഡിഫോൾട്ട് `true`)
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts)-ലെ
അടിയന്തര സൗജന്യ ഫാൾബാക്ക് പാതയെ നിയന്ത്രിക്കുന്നു. ഇത് പ്രവർത്തനക്ഷമമാക്കിയിരിക്കുമ്പോൾ, ബജറ്റ്
തീർന്ന അഭ്യർത്ഥനകൾ പൂർണ്ണമായും പരാജയപ്പെടുന്നതിനു പകരം ഒരു സൗജന്യ ഫാൾബാക്ക്
പ്രൊവൈഡർ/മോഡലിലേക്ക് റൂട്ട് ചെയ്യപ്പെടും. ഈ പ്രവർത്തനം പ്രവർത്തനരഹിതമാക്കാനും ബജറ്റ് തീർന്ന
അഭ്യർത്ഥനകൾ പരാജയപ്പെടാൻ അനുവദിക്കാനും ഡാഷ്ബോർഡ് ടോഗിൾ, ഒരു DB ഓവർറൈഡ്, അല്ലെങ്കിൽ
`OMNIROUTE_EMERGENCY_FALLBACK` എൻവയോൺമെന്റ് വേരിയബിൾ എന്നിവ വഴി ഇത് `false`
(അല്ലെങ്കിൽ `0`) ആയി സജ്ജീകരിക്കുക. (PR-കൾ #3741 / #3752-ൽ ഡാഷ്ബോർഡ് ടോഗിളായി
ലഭ്യമാക്കിയിരിക്കുന്നു.)

ഈ ഫാൾബാക്ക് നൽകുന്ന ഒരു പ്രതികരണത്തിൽ
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>` ഉണ്ടായിരിക്കും,
അതിനാൽ ഒരു ക്ലയന്റിന് അതിന്റെ അഭ്യർത്ഥനയുമായി `X-OmniRoute-Provider` താരതമ്യം ചെയ്യാതെതന്നെ
അത് വീണ്ടും റൂട്ട് ചെയ്യപ്പെട്ടതായി തിരിച്ചറിയാനാകും. മറ്റെല്ലാ പ്രതികരണങ്ങളിലും ഈ ഹെഡർ
ഉണ്ടായിരിക്കില്ല.
