## Dokončenia chatu

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

#### Pripnutie účtu pre jednotlivé požiadavky

Keď má poskytovateľ viacero pripojení (účtov alebo kľúčov), OmniRoute zvyčajne vyberie jedno
pomocou svojej stratégie výberu účtu. Požiadavka však môže pripnúť konkrétne pripojenie
pomocou hlavičky `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Kde nájsť ID.** Otvorte stránku poskytovateľa na ovládacom paneli
  (**Ovládací panel → Poskytovatelia → <provider>**) a kliknite na čip ID `xxxxxxxx…` v riadku
  pripojenia — tým sa skopíruje úplné ID pripojenia.
- **Ktoré požiadavky ho rešpektujú.** Požiadavky s jedným modelom (`provider/model`) na
  `/v1/chat/completions`, `/v1/messages` a `/v1/responses`. Kombinácie túto hlavičku ignorujú:
  namiesto toho pripnite účet pre každý krok kombinácie prostredníctvom vlastného pripojenia daného kroku.
- **Pripnutie je striktné, nejde iba o preferenciu.** Použije sa výhradne pripnuté pripojenie.
  Zlyhanie počas požiadavky zaznamená dobu čakania účtu, ale **neprepne** na iný účet
  toho istého poskytovateľa.
- **Doba čakania a kvóta pripnutie uvoľnia.** Kým je pripnuté pripojenie v režime čakania,
  má vyčerpanú kvótu alebo je zablokované zásadou kvót, ďalšie požiadavky sa presmerujú na
  ostatné pripojenia poskytovateľa, presne ako nepripnutá prevádzka.
- **Neznáme alebo deaktivované ID spôsobia zlyhanie.** ID, ktoré sa nenachádza v aktívnej
  množine poskytovateľa (bolo odstránené, deaktivované alebo patrí inému poskytovateľovi),
  nezanechá žiadny oprávnený účet, takže požiadavka zlyhá namiesto toho, aby bola bez upozornenia
  smerovaná inam.

Claude Code odosiela vlastné hlavičky prostredníctvom `ANTHROPIC_CUSTOM_HEADERS`. Umiestnite ho do bloku `env`
v súbore `~/.claude/settings.json` alebo do projektového súboru `.claude/settings.json`, ak chcete pre každý
projekt pripnúť iný účet:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Zdroj: `src/sse/handlers/chat.ts` (čítanie hlavičky), `src/sse/services/auth.ts` a
`src/sse/services/sessionAffinityPin.ts` (uvoľnenie pripnutia a kontrola neprítomnosti v množine).

> **Hlavičky telemetrie nákladov:** úspešné odpovede bez streamovania obsahujú aj sadu telemetrie nákladov `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, s pevnými 10 desatinnými miestami; `0.0000000000` pre bezplatné položky alebo položky bez stanovenej ceny), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` a `X-OmniRoute-Fallback-Attempts` (iba keď > 0), spolu s `X-OmniRoute-Request-Id` a `X-OmniRoute-Version`. Tieto hlavičky poskytujú dokončenia chatu, `/v1/responses`, `/v1/messages` **aj koncové body médií** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` a `/v1/moderations` (náklady sú vždy `0`). Náklady na médiá sa vypočítavajú podľa modality (za obrázok, za sekundu, za znak, za jednotku vyhľadávania), keď sú k dispozícii cenové údaje; inak sú `0` (pri zlyhaní sa pokračuje).

> **Sémantika nákladov pri zásahu do vyrovnávacej pamäte:** pri ZÁSAHU do sémantickej vyrovnávacej pamäte (`X-OmniRoute-Cache-Hit: true`) sa nevykoná žiadne volanie nadradenej služby, takže hodnota `X-OmniRoute-Response-Cost` je `0.0000000000` (**prírastkové** náklady na poskytnutie výsledku z vyrovnávacej pamäte). Pôvodné/predpokladané náklady sa uvádzajú samostatne v `X-OmniRoute-Cost-Saved`. Systémy spracúvajúce fakturáciu by mali sčítavať hodnoty `X-OmniRoute-Response-Cost` (zásahy do vyrovnávacej pamäte nič nestoja); analytické systémy vyrovnávacej pamäte môžu agregovať hodnoty `X-OmniRoute-Cost-Saved`.

## Exkluzívne prenájmy spravovaných relácií

Exkluzívny prenájom spravovaných relácií je voliteľná zmluva smerovania nezávislá od klienta: jeden aktívny vlastník
drží jedno vyhovujúce pripojenie OmniRoute. Neprenajíma model, nevyžaduje OAuth, neidentifikuje
konkrétneho klienta ani nevyžaduje konkrétneho poskytovateľa.

Overovaný kľúč API musí mať rozsah `lease:exclusive` a explicitný neprázdny
zoznam `allowedConnections`. Hranica databázovej mutácie vynucuje obe polia spoločne pri vytváraní
kľúča aj pri čiastočných aktualizáciách.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Úspešné odpovede na získanie, obnovenie a uvoľnenie sprístupňujú časové pečiatky, `state` a presnú kladnú
hodnotu `generation`, nikdy však vybrané pripojenie ani prihlasovacie údaje. Pri obnovení a uvoľnení sa
generácia uvádza v tele JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Vlastník aktívneho prenájmu môže explicitne požiadať o metadáta aktuálnej väzby, ktoré možno bezpečne zobraziť bez narušenia súkromia:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Táto voliteľná akcia na zistenie stavu je v rámci jednej databázovej transakcie zabezpečená nepriehľadným identifikátorom vlastníka, overeným spravovaným kľúčom API a presnou
aktívnou generáciou. `displayName` je iba skrátený nakonfigurovaný
názov pripojenia; ak neexistuje bezpečný nakonfigurovaný názov, jeho hodnota je `null`. OmniRoute nikdy nenahrádza názov
e-mailovou adresou ani vygenerovanou identitou účtu. Hodnota poskytovateľa je necitlivé zobrazované označenie a nikdy
nejde o vygenerovaný identifikátor kompatibilného poskytovateľa. Prihlasovacie údaje, tokeny, súbory cookie, nespracované identifikátory pripojení alebo kľúčov
API, haše vlastníkov, tajné údaje ohraničenia a interné údaje smerovania sú vylúčené.

Vyhľadania s nesprávnym kľúčom, nesprávnym vlastníkom, zastaranou generáciou, chýbajúcim, exspirovaným, uvoľneným alebo zneplatneným prenájmom
vracajú rovnakú chybu `409 LEASE_FENCE_STALE` bez metadát pripojenia. Klient, ktorý dostal odpoveď o čakaní na kapacitu, nemá žiadnu aktívnu väzbu, ktorú by mohol skontrolovať. Keď smerovanie prepne aktívny prenájom,
rovnaká generácia zostáva platná a stav atomicky vráti novú väzbu, nikdy nie starú.
Existujúci klienti zostávajú nezmenení, pretože odpovede na získanie, obnovenie, uvoľnenie a čakanie si zachovávajú
svoje predchádzajúce štruktúry.

Táto serverová zmluva nemení štandardný príkaz OpenAI Codex `/status`. Štandardný Codex v súčasnosti hlási svojho
poskytovateľa modelu a vstavaný stav overenia/účtu, ale nezobrazuje ľubovoľné vlastné
metadáta účtu poskytovateľa; budúca integrácia klienta musí zavolať túto akciu a rozhodnúť, ako
zobraziť `connection.displayName`.

Každá požiadavka na spravovanú inferenciu potom poskytne obe riadiace hlavičky:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Presný vlastník, generácia, aktívne pripojenie a overený kľúč API sa kontrolujú bezprostredne
pred každým podporovaným pokusom o prístup k nadradenej službe. Opätovné použitie vlastníka a generácie s iným kľúčom zlyhá aj vtedy,
keď tento kľúč povoľuje rovnaké pripojenie. Nespracované identifikátory vlastníkov sa neukladajú, nezaznamenávajú do protokolov, neuchovávajú v
snímke požiadavky ani nepreposielajú nadradenej službe.

Dočasný konflikt vracia HTTP `429` s hlavičkou `Retry-After` a:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Táto odpoveď znamená iba to, že bežná množina vyhovujúcich pripojení nebola prázdna a každý voľný kandidát bol
držaný cudzím aktívnym prenájmom. Nepodporované modely/poskytovatelia, nesúlad so zásadami, doba čakania,
kvóta, stav a ďalšie bežné zlyhania spôsobilosti si zachovávajú svoje existujúce odpovede OmniRoute.

### `x-omniroute-compression`

Nahradenie kompresného plánu pre jednotlivú požiadavku. Má najvyššiu prioritu — prevažuje nad nahradením kombinácie smerovania,
aktívnym profilom, automatickým spustením aj predvoleným nastavením panela. Hodnoty:

| Hodnota       | Účinok                                                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `off`         | Pre túto požiadavku sa nepoužije kompresia.                                                                                 |
| `default`     | Predvolený profil odvodený z panela (ignoruje aktívny profil). Stratové mechanizmy zostanú vypnuté.                         |
| `safe`        | Iba deduplikácia a zlučovanie bielych znakov.                                                                               |
| `allow-lossy` | Zachová plán operátora pre túto požiadavku vrátane súhrnov a štylistických úprav.                                           |
| `engine:<id>` | Jeden mechanizmus, ak je povolený, napr. `engine:rtk`. Explicitná aktivácia daného mechanizmu pre jednotlivú požiadavku.    |
| `<combo>`     | Pomenovaná kombinácia, ktorá sa najprv porovná podľa názvu (bez rozlišovania veľkosti písmen) a potom podľa identifikátora. |

Poznámky:

- Neznáme hodnoty sa ignorujú (požiadavka sa nikdy neodmietne); vyhodnocovanie pokračuje podľa bežného poradia priorít operátora.
- Ak má viacero kombinácií rovnaký názov, na deterministické priradenie odovzdajte **id** kombinácie.
- Kombináciu s názvom `off` alebo `default` nemožno vybrať podľa názvu (tieto kľúčové slová sa interpretujú ako prvé); na takúto kombináciu odkazujte pomocou jej identifikátora.
- Hlavný prepínač kompresie je neprekročiteľné obmedzenie: keď je kompresia globálne zakázaná, táto hlavička ju nemôže povoliť.

Použitý plán sa zopakuje v hlavičke odpovede:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

kde `<source>` je jedna z hodnôt `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` alebo `off`.

## Embeddingy

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Dostupní poskytovatelia: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID v katalógu majú formát `provider/model` (príklad: `jina-ai/jina-embeddings-v5-omni-small`). Samostatné ID modelov Jina, ktoré sa nachádzajú v registri (napríklad `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`), sa tiež rozpoznajú. Operácie embed/rerank/classify/segment služby Jina používajú najprv prihlasovacie údaje `jina-ai` z ovládacieho panela; `JINA_AI_API_KEY` sa použije ako záložná možnosť iba vtedy, keď v ovládacom paneli neexistuje žiadny kľúč. Karta `jina-reader` slúži iba pre Reader / `r.jina.ai` (`POST /v1/web/fetch`) a nikdy neposkytuje embeddingy ani reranking.

Modely v registri, ktoré deklarujú podporu multimodality, prijímajú aj najviac 32 štruktúrovaných
položiek nezávislých od poskytovateľa. Typy mediálnych položiek sú `text`, `image`, `audio`, `video` a `document`. Ich mediálny `source`
je buď `{"type":"url","url":"https://..."}`, alebo
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
a alias rodiny `jina-ai/jina-embeddings-v5-omni` → omni-small) prijíma aj natívne dokumenty
EmbeddingsV5Request služby Jina a **preposiela ich bezo zmeny** na `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Natívne hodnoty `{ image | audio | video | pdf }` môžu byť verejnou adresou URL HTTPS, identifikátorom URI `data:` alebo nespracovanými
dátami base64. OmniRoute neprevádza tieto objekty na reťazce ani nenačítava natívne adresy URL obrázkov — verejné
médiá načítava samotná služba Jina. Dodatočné polia Jina (`task`, `normalized`, `truncate`, `embedding_type`) sa
preposielajú. SKU Jina určené iba pre text naďalej odmietajú netextové dokumenty.

Bezpečnostné a prenosové obmedzenia:

- Adresy URL vzdialených médií musia byť verejné adresy HTTPS. Kanonické položky `{type,source:url}` sa načítavajú
  na strane servera (opätovné overenie presmerovaní, časový limit, obmedzenia veľkosti, verejný DNS, pripnutie spojenia) a
  pred volaním poskytovateľa sa vložia priamo do požiadavky. Natívne položky Jina `{image:"https://..."}` sa preposielajú bez zmeny
  po rovnakej kontrole verejnej adresy HTTPS; adresu URL načíta služba Jina.
- Vložené médiá base64 sú obmedzené na 8 MiB dekódovaných dát na položku a 16 MiB dekódovaných dát v rámci celej požiadavky.

Transformácia pre poskytovateľov (kanonické položky sa nikdy nepreposielajú bez zmeny):

- Multimodálne modely Jina: každá položka najvyššej úrovne sa zmení na jeden objekt s kľúčom modality
  (`text` / `image` / `audio` / `video` / `pdf`), pričom pre vložené médiá sa použijú identifikátory URI typu data; jeden vektor na
  položku najvyššej úrovne.
- Rodina Gemini Embedding 2: jedno pole najvyššej úrovne sa zmení na jednu natívnu
  požiadavku `models/{model}:embedContent` s `content.parts` (`text` alebo `inline_data`).
- llama.cpp (`llama-cpp/<model>`, ľubovoľný model načítaný lokálnym serverom): kanonické položky `text`
  sa zmenia na obyčajné reťazce a položky `image` / `audio` / `video` sa zmenia každá na jeden
  objekt `{"content": [part]}` s použitím častí obsahu chatu servera llama-server (`image_url`,
  `input_audio` s formátom `wav` / `mp3` / `flac`, `input_video`) a vloženými dátami; jeden vektor
  na položku najvyššej úrovne. Server musí byť spustený s `--embedding --mmproj …`; bez projektora
  odmietne médiá samotný server. Typ `document` nie je podporovaný.
- Neznáme/dynamické modely bez explicitných metadát modality odmietnu štruktúrovaný vstup s odpoveďou HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Nepodporované kombinácie modelu a modality vrátia odpoveď HTTP 400 namiesto konverzie položky. Rozširujúce polia
mimo vstupu v starších požiadavkách s reťazcami/tokenmi sa naďalej preposielajú bez zmeny.

```bash
# Zobraziť všetky modely embeddingov
GET /v1/embeddings
```

## Generovanie obrázkov

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Medzi dostupných poskytovateľov patria OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokálne), ComfyUI (lokálne).

Parameter `n` vráti `n` obrázkov v poli `data[]`. Pri poskytovateľoch, ktorých nadradené API vracia jeden obrázok na volanie
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI), sa vykoná `n` samostatných volaní nadradeného API, pričom súbežne môžu prebiehať najviac 4. Pevná
hodnota `seed` sa posúva podľa indexu volania (`seed`, `seed + 1`, …), takže obrázky sú odlišné, ale zostávajú
reprodukovateľné. Hodnota `n` je obmedzená na 10. Ak zlyhá ktorékoľvek volanie, zlyhá celá požiadavka. Zoznam
formátov s rozvetvením sa nachádza v `SINGLE_IMAGE_FANOUT_FORMATS` v súbore
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux opätovne používa existujúce pripojenie s kľúčom API a akceptuje predpony `zenmux/` alebo `zm/`:

- `zenmux/openai/gpt-image-2` používa API OpenAI Images služby ZenMux. Medzi možnosti patria `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` a `response_format`.
- Ostatní vydavatelia, napríklad `zm/meta/muse-image-1.0`, používajú koncový bod `:predict`
  služby Vertex AI v ZenMux. Parameter `n` sa mapuje na `sampleCount`, `aspect_ratio` na `aspectRatio` a `image_size`
  (`1K`, `2K`, `4K`) na `sampleImageSize`. Parameter `size` v pixeloch určuje iba pomer strán,
  nie zaručené rozmery v pixeloch. Podporované pomery strán, rozlíšenia a počty sa líšia podľa modelu.
- `zm/inclusionai/ming-image-0.1-design` si volí vlastné rozmery. Vynechajte `size`,
  `aspect_ratio` a `image_size`; explicitné hodnoty vrátia HTTP 400. Pomocou `output_format`
  možno požadovať PNG, JPEG a WebP.

Táto integrácia podporuje generovanie obrázkov z textu, nie úpravu referenčných obrázkov. Výstup služby Vertex
sa normalizuje do `data[].b64_json`; `response_format: "url"` vráti nadradenú
HTTPS URL alebo dátovú URL vo formáte base64, ak sú k dispozícii iba bajty obrázka. Prázdne/filtrované výstupy
vrátia chybu namiesto prázdnej úspešnej odpovede. Prístup k modelom závisí od účtu ZenMux.
Pozrite si [API Vertex služby ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) a
[API OpenAI Images](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Zoznam všetkých modelov obrázkov
GET /v1/images/generations
```

## OCR dokumentov

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

Parameter `model` vyberá poskytovateľa OCR pomocou predpony `provider/model`; samotný identifikátor modelu (napr.
`mistral-ocr-latest`) sa priradí k jeho zaregistrovanému poskytovateľovi a pri vynechaní `model` sa predvolene použije
Mistral (`mistral-ocr-latest`). Zaregistrovaní poskytovatelia (`open-sse/config/ocrRegistry.ts`):

| ID poskytovateľa              | ID modelu            | Hodnota `model`                                                   | Poznámky                                                                                                                                              |
| ----------------------------- | -------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (alebo samotné `mistral-ocr-latest`) | Synchrónne — odpoveď sa vráti priamo z jediného nadradeného volania.                                                                                  |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                       | Asynchrónne nadradené API (`analyze` + dopytovanie) — pozrite nižšie.                                                                                 |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                           | Synchrónne, prostredníctvom partnerského koncového bodu `openapi/chat/completions` služby Vertex AI — informácie o autentifikácii/URL nájdete nižšie. |

Všetci traja poskytovatelia odpovedajú v rovnakom tele v tvare používanom službou Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Priebeh dopytovania služby Azure Document Intelligence

API `analyze` služby Azure Document Intelligence je asynchrónne: počiatočná požiadavka vráti namiesto tela
hlavičku `Operation-Location` a výsledok je potrebné získavať opakovaným dopytovaním. Obslužná rutina
(`open-sse/handlers/ocr.ts`) sa na túto URL dopytuje každú sekundu, najviac však 30-krát. Pri odpovedi na dopytovanie, ktorá nemá stav `ok`, alebo pri stave `"failed"` zlyhá okamžite (v dopytovaní
nepokračuje) a vráti `504`, ak operácia stále prebieha po vyčerpaní povoleného počtu pokusov. Konečná odpoveď služby Azure sa
pred vrátením volajúcemu normalizuje do rovnakého tvaru `pages`/`markdown`, aký používa Mistral,
takže klientsky kód nemusí poskytovateľa spracovávať osobitne.

### Autentifikácia a určovanie koncového bodu Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` opätovne používa rovnakú autentifikáciu Vertex AI, ktorú OmniRoute už podporuje pre
prenosy chatu/obrázkov (`open-sse/executors/vertex.ts`): kľúč API pripojenia je buď
poverenie Service Account vo formáte JSON (vymenené za krátkodobý prístupový token OAuth prostredníctvom postupu JWT bearer),
alebo už vydaný prístupový token OAuth použitý bez zmeny. Nadradená URL koncového bodu je všeobecný
partnerský koncový bod `openapi/chat/completions` služby Vertex, zostavený z projektu a
regiónu pripojenia — explicitné hodnoty `providerSpecificData.project`/`providerSpecificData.region` majú vždy prednosť;
inak sa projekt odvodí z `project_id` v JSON Service Account a predvoleným regiónom je
`us-central1`. Obe hodnoty sa určujú v `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`) a používa ich
`src/app/api/v1/ocr/route.ts` pred odovzdaním do `handleOcr`.

## Zoznam modelov

```bash
GET /v1/models
Authorization: Bearer your-api-key

→ Vráti všetky modely pre čet, vkladanie a obrázky + kombinácie vo formáte OpenAI
```

### Prefixy ID modelov (`?prefix=`)

Väčšina modelov sa zverejňuje pod **prefixom poskytovateľa**. To, ktorý prefix získate, riadi
príznak funkcie `MODELS_CATALOG_PREFIX_MODE` a možno ho prepísať **pre každú požiadavku** pomocou
parametra dopytu — čo je užitočné pre klienta, ktorý chce čistý zoznam bez zmeny nastavenia
platného pre celý server a všetkých ostatných:

```bash
GET /v1/models?prefix=alias        # jedno ID na model — krátky aliasový prefix
GET /v1/models?prefix=dual         # obe formy (predvolené nastavenie servera)
GET /v1/models?prefix=canonical    # iba úplný prefix ID poskytovateľa
```

| Režim       | Vracia                                                  | Poznámky                                                                                                                                                                                     |
| ----------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **a** `claude/claude-sonnet-4-6` | **Predvolené.** Obe ID smerujú na rovnaký model; zachované, aby naďalej fungovali konfigurácie klientov, ktoré majú napevno nastavenú ktorúkoľvek formu. Katalóg je približne dvojnásobný.   |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Jedna položka na model. Poskytovatelia bez samostatného aliasu svoju položku stále vracajú, takže sa nič nestratí.                                                                           |
| `canonical` | `claude/claude-sonnet-4-6`                              | Jedna položka na model pod úplným prefixom ID poskytovateľa. Poskytovatelia bez samostatného aliasu (napr. `antigravity/…`, `agy/…`) tu tiež vracajú svoje jediné ID, takže sa nič nestratí. |

Zrkadlovú položku režimu `dual` možno rozpoznať aj bez parametra dopytu: obsahuje pole `parent`,
ktoré odkazuje na primárne ID.

Klienti, ktorí zobrazujú výber modelu, by mali požadovať `?prefix=alias` — takto to robí
[rozšírenie OmniCopilot pre VS Code](../guides/VSCODE-COPILOT.md).

### Filtre vyhľadávania (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` podporuje voliteľné filtre vyhľadávania. Bez nich zostáva odpoveď
nezmenená. Zužujú katalóg, ktorý už volajúci vidí (najprv sa uplatnia oprávnenia API kľúča),
a použijú sa pred stránkovaním v štýle OpenAI pomocou `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # každá uvedená schopnosť musí byť aktívna
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # katalógový `type`; riadky bez neho sú `chat`
GET /v1/models?q=sonnet&limit=10                           # zhoda ID alebo názvu bez rozlišovania veľkosti písmen
```

| Parameter     | Hodnoty                                                                                             |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nezáporné celé číslo porovnávané s `context_length`                                                 |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 znakov                                                                                        |

Neznáma hodnota alebo `min_context`, ktorý nie je nezáporným celým číslom (napríklad `1.5`),
vráti HTTP `400` a správa uvedie platné hodnoty. Implementácia:
`src/app/api/v1/models/catalogFilters.ts`.

### Užší výber modelov (`POST /v1/models/query`)

`POST /v1/models/query` vráti krátky, deterministický zoznam z rovnakého katalógu s rovnakým
overovaním a viditeľnosťou podľa jednotlivých kľúčov ako `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Každé pole je voliteľné. `capabilities` a `exclude` prijímajú pole alebo reťazec oddelený čiarkami;
`max_output` sa porovnáva s `max_output_tokens`. Výsledky sú zoradené podľa `owned_by` a potom podľa `id`.
Predvolená hodnota `limit` je `20` a hodnoty vyššie ako `100` sú obmedzené na `100`. Neplatný JSON, neznáme
pole alebo neplatná hodnota vrátia HTTP `400`.

### Individuálne skryté četové modely

Model označený na stránke svojho poskytovateľa ako **Skrytý** je vylúčený z katalógu a pri
explicitnom vyžiadaní odmietnutý s HTTP `404` / `model_not_found`. Kontrola používa vyriešeného
poskytovateľa a model vrátane aliasov poskytovateľov, prefixov uzlov kompatibilných poskytovateľov
a predvolených nastavení pripojenia. Kombinácia preskočí skryté ciele a môže použiť viditeľný
súvisiaci model; ak nezostane žiadny spustiteľný cieľ, vráti rovnaký kód chyby. Zrušenie skrytia
sa prejaví pri nasledujúcej požiadavke. Prepísania viditeľnosti iba pre obrázky neskryjú četový
model s rovnakým ID.

Toto individuálne nastavenie modelu je oddelené od
[zoznamov povolenia/odmietnutia sprístupnenia modelov](../routing/MODEL_EXPOSURE_LIST.md), ktoré filtrujú
zverejnenie v katalógu a kandidátov automatického smerovania, pričom zachovávajú explicitné odoslanie.
Oprávnenia modelov pre API kľúče sa naďalej uplatňujú nezávisle. Predvoleným režimom prefixu katalógu
zostáva `dual`.

### Varianty modelov bez uvažovania

Pre modely Claude podporujúce uvažovanie zverejňuje `/v1/models` aj variant **bez uvažovania**, ktorého ID má prefix `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Výber tohto ID (napr. v konfigurácii Claude Code, ktorá vždy pripája blok `thinking`) sa spätne preloží na skutočný `<provider>/<model>` s potlačeným uvažovaním — `thinking:{type:"disabled"}` na ceste `/v1/messages` alebo s vynechanými poľami `reasoning`/`reasoning_effort` na ceste `/v1/chat/completions`. Variant sa uvádza iba pre modely z rodiny Claude, ktoré podporujú uvažovanie **a zároveň** rešpektujú hodnotu `disabled` (takže napr. modely výhradne s adaptívnym režimom, ktoré odmietajú hodnotu `disabled`, sú vylúčené). Operátori môžu variant pre jednotlivé modely vynútene zapnúť alebo vypnúť prostredníctvom `ModelSpec.noThinkingAlias`.

## Generovanie zvuku pomocou ElevenLabs

V OmniRoute nakonfigurujte pripojenie poskytovateľa `elevenlabs` pomocou svojho API kľúča ElevenLabs.
Klienti sa overujú svojím kľúčom **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`);
brána poskytne uložený kľúč poskytovateľa ako `xi-api-key`. Nikdy neposielajte kľúč ElevenLabs
ako nosný token brány.

| Metóda | Cesta                       | Odpoveď                                   | Kategória koncového bodu API kľúča |
| ------ | --------------------------- | ----------------------------------------- | ---------------------------------- |
| POST   | `/v1/sound-generation`      | Natívne zvukové bajty                     | `elevenlabs`                       |
| POST   | `/v1/music`                 | Natívne zvukové bajty                     | `music`                            |
| POST   | `/v1/music/stream`          | Streamované zvukové bajty                 | `music`                            |
| POST   | `/v1/music/detailed`        | Natívny viacdielny zvuk a plán kompozície | `music`                            |
| POST   | `/v1/music/detailed/stream` | Natívne metadáta SSE a zvukové bloky      | `music`                            |
| POST   | `/v1/music/plan`            | Plán kompozície vo formáte JSON           | `music`                            |

Tieto koncové body dopĺňajú existujúce trasy `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` a `/v1/speech-to-text`. Natívne polia JSON
a parametre dopytu, ako napríklad `output_format` a `enable_logging`, zostávajú zachované.
Odpovede `/v1/music/detailed` si zachovávajú svoje viacdielne hranice; spracujte ich ako viacdielne.
`/v1/music/detailed/stream` vracia `text/event-stream` s metadátami kompozície a
zvukovými blokmi vo formáte base64 v udalostiach SSE. Všetkých šesť trás podporuje predbežné požiadavky CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Krátky zvukový efekt. Trvanie: 0,5 až 30 sekúnd.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Trvanie hudby sa vyjadruje v milisekundách: 3000 až 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Na priebežné doručovanie zvuku použite `/v1/music/stream` s rovnakým telom JSON. Kompozícia
prijíma presne jednu z možností `prompt` alebo `composition_plan`; `/v1/music/plan` vyžaduje `prompt`
a voliteľne prijíma `source_composition_plan`. Natívne schémy zachovávajú dodatočné
polia poskytovateľa, takže verzie plánov kompozície a možnosti jemného dolaďovania sa prenesú do ElevenLabs.

Zjednotený koncový bod `/v1/music/generations` prijíma aj `elevenlabs/music_v1`,
`elevenlabs/music_v2` a `elevenlabs/music_v2_5`. Pri aktívnom pripojení ElevenLabs
sú tieto modely dostupné v katalógu hudby. Tento koncový bod vracia
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Jeho pole `duration` je uvedené v
sekundách a mapuje sa na `music_length_ms`; explicitná hodnota `music_length_ms` má prednosť.
`instrumental` sa mapuje na `force_instrumental`, pričom natívne pole má prednosť.
Na streamovanie používajte natívne streamovacie koncové body a na požiadavky riadené
výlučne plánom kompozície použite natívny koncový bod kompozície.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Pred volaním nadradenej služby sa uplatňujú obmedzenia koncového bodu, modelu, rozpočtu a pripojenia. Natívne
trasy vracajú stavové kódy a telá chýb nadradenej služby bez zmien vrátane `402` pri obmedzení
plánu a `429` pri prekročení kvóty. Hlavičky `character-cost`, `song-id`, `request-id` a `retry-after`
zostávajú zachované, ak sú prítomné. Zostatok bezplatného kreditu nezaručuje prístup ku každému
hudobnému modelu, výstupnému formátu ani funkcii API: o oprávnení pre každú požiadavku rozhoduje ElevenLabs.
Zjednotený koncový bod zachováva stavové kódy chýb v normalizovanom chybovom obale OmniRoute.

Zmluvy nadradenej služby: [zvukové efekty](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[kompozícia hudby](https://elevenlabs.io/docs/api-reference/music/compose) a
[podrobnosti streamovania hudby](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Pre klientov, ktorí nemôžu pripojiť `Authorization: Bearer ...`, OmniRoute prijíma kľúče API aj v adrese URL, a to buď prostredníctvom kompatibilných parametrov reťazca dopytu (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`), alebo prostredníctvom vyhradených koncových bodov `/api/v1/vscode/{token}/...` zdokumentovaných nižšie.

```bash
# Preusporiadanie (poskytovateľ cloudového registra alebo uzol poskytovateľa kompatibilného s OpenAI vo formáte "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Klasifikácia Jina (prihlasovacie údaje Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Segmentátor Jina
POST /v1/segment     { "content": "...", "return_chunks": true }

# Vyhľadávanie Jina (s.jina.ai; aliasy poskytovateľa: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Moderovanie
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — vracia telo audio/mpeg (alebo telo v požadovanom formáte)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS vyžaduje jazyk a hlas: predvolená hodnota `language` je "en"; chýbajúci
# hlas alebo názov štandardného hlasu OpenAI (alloy, nova, …) sa zmení na "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Úprava obrázka (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Generovanie videa/hudby (ID modelu s predponou poskytovateľa)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Uzly poskytovateľa pre rerankovanie:** `POST /v1/rerank` smeruje požiadavky aj do uzlov poskytovateľov kompatibilných s OpenAI
> (oMLX, vLLM, Infinity, TEI za bránou, …), ktoré sú adresované ako `<node-prefix>/<model>`. Uzly spätnej slučky
> (`localhost`, `127.0.0.1`, `172.16.0.0/12`) sú vždy oprávnené, rovnako ako názvy hostiteľov, ktoré
> prevádzkovateľ uvedie v `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (napr. názov služby Docker/Compose,
> ako je `http://reranker:8080/v1`; tieto uzly sa volajú priamo, nikdy nie prostredníctvom `HTTP(S)_PROXY` ani
> proxy pripnutej ku konkrétnemu pripojeniu). Uzly na akomkoľvek inom
> hostiteľovi — zariadenie v sieti LAN alebo partner Tailscale — sú oprávnené iba vtedy, keď prevádzkovateľ povolí
> príznak funkcie `RERANK_REMOTE_PROVIDER_NODES` **a zároveň** základná URL adresa uzla vyhovuje pravidlám
> pre odchádzajúce URL adresy poskytovateľa (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Krok rerankovania pamäťového mechanizmu volá túto trasu prostredníctvom
> spätnej slučky, takže rovnaké pravidlo určuje aj správanie `rerankProviderModel` v nastaveniach pamäte.
>
> **Formáty lokálnych serverov:** uzol sa volá na adrese `<base>/v1/rerank` a pri odpovedi 404 na adrese `<base>/rerank`
> (Infinity, TEI). Telo odoslané upstreamu obsahuje názvy používané rozhraniami Cohere/OpenAI (`documents`,
> `return_documents`) aj názvy používané rozhraním TEI (`texts`, `return_text`) a odpoveď upstreamu sa
> normalizuje do obálky Cohere: holé pole TEI `[{index, score, text}]`, objekt `{results: [{index, score}]}`
> z jednoduchých brán a formát Voyage `{data: [...]}` sa klientovi vrátia ako
> `{results: [{index, relevance_score, document?}]}`, zoradené podľa skóre a obmedzené hodnotou `top_n`.
>
> **Vyhľadávanie uzlov poskytovateľov:** modely v uzle poskytovateľa kompatibilnom s OpenAI sa zobrazia v `GET /v1/models`
> pod prefixom uzla. Riadky bez metadát koncového bodu (typické pre lokálne výpisy `/v1/models`)
> dedia hodnotu `apiType` uzla, takže modely uzla `embeddings` majú `type: "embedding"` a modely uzla
> `rerank` majú `type: "rerank"` namiesto predvoleného typu chatu; explicitná hodnota
> `supportedEndpoints` v synchronizovanom alebo manuálne pridanom riadku má aj naďalej prednosť.

### `provider_options` pre Exa a Tavily

Exa a Tavily čítajú polia špecifické pre poskytovateľa z menného priestoru:
`provider_options.exa` (alebo `provider_options["exa-search"]`) a `provider_options.tavily`
(alebo `provider_options["tavily-search"]`). Preposielajú sa iba kľúče uvedené nižšie. Každý z nich sa
kontroluje podľa vlastnej schémy Zod v `open-sse/handlers/search/providerOptionsPassthrough.ts`
a kľúč s nesprávnym typom sa zahodí. Všetky ostatné kľúče sa ignorujú vrátane autentifikácie, základnej URL adresy,
`stream` a `outputSchema`. Ploché kľúče používané ostatnými poskytovateľmi (`cx`, `depth`, ...) fungujú
rovnako ako predtým.

| Poskytovateľ | Polia najvyššej úrovne                                                                                                                                                                                                                                                                                                                                                    | Vnorené                                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Exa          | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (ploché primitívne hodnoty), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                    | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` zlúčené s predvolenou hodnotou `{ text: true, highlights: true }` |
| Tavily       | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                        |

Všeobecné polia majú vždy prednosť: `query`, `max_results`, `filters` (domény), `country` a
téma odvodená z `search_type`. V prípade Exa hodnota `search_type: "news"` zachová `category: "news"`.
Tavily prijíma aj `search_type: "finance"` (`topic: "finance"`).

Všeobecné pole `time_range` sa teraz prenáša k obom poskytovateľom: Exa dostane `startPublishedDate` (časovú
pečiatku ISO) a Tavily dostane `start_date` (`YYYY-MM-DD`). Explicitný dátum v `provider_options`
má prednosť pred namapovanou hodnotou.

Výsledky Exa zachovávajú `id`, `highlight_scores`, `summary`, `subpages`, `entities` a `extras` v
`provider_raw`. Výsledky Tavily zachovávajú `images` a `favicon`.

Účtovanie nákladov naďalej používa plochý register `costPerQuery`. Tavily účtuje
za `search_depth: "advanced"` viac kreditov na jedno volanie a tento rozdiel sa neodráža v
`usage.search_cost_usd`.

## API Web Fetch

Extrahuje obsah z adresy URL prostredníctvom nakonfigurovaného poskytovateľa webového načítania (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, rovnaký kľúč API ako Parallel Search) vracia iba Markdown
— akýkoľvek iný `format` spôsobí odpoveď `400` — a obmedzuje obsah na 100 000 znakov. Keď
samotnú cieľovú stránku nemožno extrahovať, nadradená služba to oznámi v odpovedi HTTP 200;
OmniRoute to sprístupní ako `422` s pevne stanovenou správou.

| Metóda | Cesta           | Opis                                                           |
| ------ | --------------- | -------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Načíta/extrahuje URL — telo overené schémou `v1WebFetchSchema` |

**Autentifikácia:** Kľúč API typu Bearer (`extractApiKey` + `isValidApiKey`). Zásady sa vynucujú prostredníctvom `enforceApiKeyPolicy`.

**Záložné smerovanie zohľadňujúce kvóty (#8297):** keď nie je zadaný explicitný `provider`, fond
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) sa
prechádza v pevnom
poradí priorít (najprv sa naplní prvý) — poskytovateľ s obmedzenou frekvenciou požiadaviek, ktorý je však nakonfigurovaný, sa preskočí
namiesto okamžitého ukončenia požiadavky a opakovateľné zlyhanie nadradenej služby alebo zlyhanie kvóty
(HTTP 429 vždy; 402/403 pre bezplatné úrovne Firecrawl/Tavily/TinyFish so štýlom kvót —
nie pre Jina Reader a nikdy nie pre obyčajnú chybnú požiadavku 400) spôsobí pri spracovaní požiadavky prechod
na ďalšieho zatiaľ nevyskúšaného poskytovateľa s prihlasovacími údajmi. Keď sú vyčerpaní všetci poskytovatelia vo
fonde, koncový bod vráti jednu odpoveď `429` (s hlavičkou `Retry-After`)
namiesto predchádzajúcej všeobecnej odpovede `400`. Keď sa požaduje explicitný `provider`,
**nedochádza** k tichému záložnému smerovaniu — explicitný poskytovateľ s obmedzenou frekvenciou alebo zlyhaním
vráti svoju vlastnú chybu (`429`, ak má obmedzenú frekvenciu, inak stav
nadradenej služby).

## Streamovanie cez WebSocket

```bash
GET /v1/ws?handshake=1
```

Overí nadviazanie spojenia s prechodom na WebSocket a vráti vzorové správy drôtového protokolu (`request`, `cancel`). Samotné rámce WS spracúva pribalený server WS mimo tabuľky trás Next.js.

**Autentifikácia:** Kľúč API typu Bearer počas nadväzovania spojenia.

### Responses API cez WebSocket (iba codex)

```bash
# Rovnaký hostiteľ:port ako HTTP API (predvolene 20128); prepnite spojenie:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (alebo: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Prvý rámec MUSÍ byť response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy Responses API cez WebSocket je pripojené **výhradne ku `codex`** (backend ChatGPT).
Počúva na rovnakom porte ako API/ovládací panel na cestách `/v1/responses`,
`/responses` a `/api/v1/responses`. Pri prvom rámci `response.create`
vykoná autentifikáciu a prípravu prostredníctvom interného mosta `codex-responses-ws`, vyberie
pripojenie codex OAuth a vytvorí tunel k `wss://chatgpt.com/backend-api/codex/responses`
prostredníctvom transportu `wreq-js`. **Modely, ktoré nie sú codex, sú odmietnuté** (`codex_ws_provider_required`).
Na smerovanie podľa zdieľanej kvóty použite `model: "qtSd/<group>/codex/<model>"`. Implementované v
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentifikácia:** Kľúč API typu Bearer počas nadväzovania spojenia. Pribalený server HTTP (`server-ws.mjs`)
musí byť aktívnym vstupným bodom (predvolene ním je, keď existuje `app/server-ws.mjs`).

#### ID modelu: použite holé ID ChatGPT (bez predpony `codex/`)

OpenAI **Codex CLI** overuje názov modelu na strane klienta, keď je
`supports_websockets = true`, a **odmieta ID s predponou poskytovateľa**, ako napríklad
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Odošlite **holé** ID (napr. `gpt-5.5`). Most OmniRoute je
určený iba pre codex, preto holé ID pred vytvorením tunela k nadradenej službe
znova rozpozná ako model codex (`resolveCodexWsModelInfo`) — aj keď by sa holé
`gpt-5.5` inak cez HTTP smerovalo k inému poskytovateľovi.

#### Konfigurácia OpenAI Codex CLI

Nasmerujte Codex CLI na OmniRoute pridaním vlastného poskytovateľa s podporou
WebSocket do `~/.codex/config.toml` (použite samostatný `CODEX_HOME`, aby ste
neupravili existujúcu konfiguráciu):

```toml
model = "gpt-5.5"                 # holé ID — NIE „codex/gpt-5.5“
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bez koncovej lomky; URL WS sa odvodí (v produkcii použite https/wss)
wire_api = "responses"                    # jediná podporovaná hodnota od februára 2026
supports_websockets = true                # povoľuje transport Responses cez WS
env_key = "OMNIROUTE_API_KEY"             # obsahuje kľúč API OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # kľúč API OmniRoute (ľubovoľný kľúč, ak REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI prepne `base_url + /responses` na WebSocket a OmniRoute ho tuneluje
k vybranému pripojeniu codex OAuth. Overené komplexne voči lokálnemu
serveru: ChatGPT vráti `codex.rate_limits` + `response.created` a streamuje
dokončenie.

## Samoobslužné používanie (`/api/usage/om-usage`)

Každý API kľúč môže čítať údaje o **svojom vlastnom** používaní a kvótach — bez autentifikácie na správu. Toto je koncový bod, ktorý
klient (CLI, panel OmniCopilot) používa na zobrazenie výdavkov držiteľa kľúča.

```bash
# Textová forma (historický kontrakt — obyčajný text pre terminál)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Štruktúrovaná forma — používaná používateľským rozhraním
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kľúč musí mať povolenú možnosť **`allowUsageCommand`** (predvolene je vypnutá — správca API kľúčov na ovládacom paneli
ju prepína pre jednotlivé kľúče). Bez nej koncový bod odpovie stavom `403`.

`?format=json` vracia diskriminovanú štruktúru, takže volajúci nikdy nečíta dátové pole z
odmietnutej odpovede. Pri úspechu:

```jsonc
{
  "allowed": true,
  // uvedené iba vtedy, keď má kľúč aktivované limity používania pre daný kľúč (denné/týždenné v USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // snímka kvóty vybraného poskytovateľa alebo null, ak zatiaľ nič nie je uložené vo vyrovnávacej pamäti:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // snímka každého pripojenia, aby používateľské rozhranie mohlo vykresliť viacero poskytovateľov vedľa seba:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Pri odmietnutí (`401` neplatný kľúč / `403` nepovolený prístup) tá istá trasa vráti
`{ "allowed": false, "error": { "message": "…" } }` — prítomné, ale prázdne pole `personal`/`provider`
(kľúč je povolený, ale zatiaľ neboli získané žiadne údaje) predstavuje iný stav než odmietnutie a rozlišuje ich iba forma JSON.

**Autentifikácia:** vlastný API kľúč volajúceho typu Bearer, overený pomocou `isValidApiKey` — toto _nie je_
rozhranie na správu (`/api/keys/…`), ktoré naďalej chráni `requireManagementAuth`.

### Nespracované percentá kvót a percentá upravené podľa hraničnej hodnoty

Pri používaní `/api/usage/om-usage` by volajúci mali brať do úvahy rozdiel medzi
percentami uvádzanými vo **výstupe vo formáte obyčajného textu** a v štruktúrovanom **výstupe JSON**:

| Aspekt                 | Formát obyčajného textu (`/api/usage/om-usage` / `@@om-usage`)                                   | Formát JSON (`?format=json`)                                                              |
| :--------------------- | :----------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------- |
| **Výstupné pole**      | `NN% left` (napr. `20% left`)                                                                    | `provider.quotas` / `providers[].quotas`                                                  |
| **Meranie**            | **Použiteľný limit upravený podľa hranice**: zostávajúca kapacita nad hraničnou hodnotou         | **Nespracovaná kvóta upstreamu**: neupravená hodnota nameraná poskytovateľom              |
| **Škálovanie hranice** | Škálované pomocou `effectiveRemainingPercent()`, aby sa chránená rezerva zobrazila ako `0% left` | Žiadne (nespracované hodnoty snímky podľa hlásenia poskytovateľa)                         |
| **Údaje o prahoch**    | Zahrnuté do zobrazeného percenta                                                                 | Uložené v `quotaWindowThresholds` pre každé pripojenie (alebo predvolené hodnoty servera) |
| **Hlavný používateľ**  | Interaktívne CLI, terminálové výzvy, ľudskí operátori                                            | Programové integrácie, ovládacie panely, analytika, nástroje na sledovanie fakturácie     |

#### Vzorec úpravy podľa hraničnej hodnoty

OmniRoute podporuje proaktívne hraničné hodnoty kvót, aby zabránil vyčerpaniu upstreamu (nakonfigurované prostredníctvom
`quotaWindowThresholds` pripojenia, predvolených hodnôt poskytovateľa alebo globálnych nastavení odolnosti). Keď je v okne kvóty aktívna hraničná hodnota
(napr. `cutoff = 25%`), vykresľovanie textu vypočíta zostávajúci limit takto:

- Ak `remaining <= cutoff`: vráti `0%`.
- Ak `remaining > cutoff`: vráti `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formátovaný textový výstup túto hodnotu zaokrúhli na najbližšie celé číslo (`Math.round(...)`).

#### Ilustračný príklad

Predstavme si okno poskytovateľa so **60 % nespracovaného využitia** (teda **40 % nespracovanej zostávajúcej kvóty**) a nakonfigurovanou
**25 % hraničnou hodnotou zostávajúcej kvóty**:

| Reprezentácia                          | Výpočet                                            | Zostáva  |            Odvodené využitie             |
| :------------------------------------- | :------------------------------------------------- | :------: | :--------------------------------------: |
| **Nespracovaný JSON (`?format=json`)** | Snímka upstreamu (`quotas[window]`)                | **40 %** |                 **60 %**                 |
| **Textový formát (`NN% left`)**        | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20 %** | **80 %** (pri výpočte `100 - remaining`) |

- **Prečo text zobrazuje 20 % zostávajúcej kvóty:** Z 40 % fyzickej kvóty zostávajúcej na účte je 25 % rezervovaných
  politikou hraničnej hodnoty. Volajúcemu zostáva iba 15 % zo 75 % použiteľnej rezervy, kým smerovač prestane
  smerovať na toto pripojenie. Škálovanie zaisťuje, že pripojenie signalizuje vyčerpanie (`0% left`) presne vtedy,
  keď sa smerovanie ukončí.
- **Prečo JSON zachováva nespracované hodnoty:** Obsah JSON vracia presnú snímku poskytovateľa (`UsageSnapshot`),
  takže externé nástroje majú prístup k skutočnému využitiu upstreamu a k
  `quotaWindowThresholds` na úrovni pripojenia bez stratového škálovania na strane servera.

#### Pokyny na migráciu pre používateľov

Ak externá integrácia (napríklad doplnok editora alebo rozšírenie agenta) predtým získavala údaje z textového
koncového bodu (`NN% left`) a vypočítavala percento využitia ako `100 - NN`, prechod na `?format=json` znamená:

- Čítanie nespracovaných hodnôt JSON bude odrážať **skutočnú spotrebu upstreamu** (v príklade vyššie je využitých 60 %).
- Ak chce integrácia zachovať sémantiku dostupnej kvóty textového koncového bodu, môže
  vzorec efektívneho zostávajúceho množstva vyhodnotiť na strane klienta pomocou `quotaWindowThresholds` pre prepísania na úrovni pripojenia.

### Vplyv na latenciu

Pri ZÁSAHU do sémantickej vyrovnávacej pamäte sa odpoveď poskytne z vyrovnávacej pamäte **bez volania nadradenej
služby**, takže uvádzaná hodnota `X-OmniRoute-Response-Latency` je takmer nulová
(bez ohľadu na pôvodnú latenciu nadradenej služby). Klienti citliví na latenciu
(benchmarking, monitorovanie p50/p99) by mali skontrolovať hlavičku odpovede
`X-OmniRoute-Cache-Latency`:

| Hodnota     | Význam                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------- |
| `synthetic` | Odpoveď poskytnutá z vyrovnávacej pamäte; latencia nie je skutočným časom nadradenej služby |
| _(chýba)_   | Odpoveď zo skutočného volania nadradenej služby                                             |

### Obídenie vyrovnávacej pamäte pre jednotlivé kľúče

| `legacy` | Bežné správanie vyrovnávacej pamäte (predvolené)                                  |
| `bypass` | Úplne preskočí vyhľadávanie vo vyrovnávacej pamäti; vždy použije nadradenú službu |

Nastavte pri vytváraní kľúča (`POST /api/keys`) alebo aktualizácii (`PATCH /api/keys/[id]`):

```json

```


používa schopnosť `max_output_tokens` za behu a zachová sa aj po opätovnej synchronizácii modelu. Stránka
poskytovateľa kompatibilného s OpenAI ponúka rovnaké ovládacie prvky na úpravu/zrušenie a označuje modely s explicitnou podporou videnia.

Vlastné uzly Chat Completions prispôsobujú explicitné vypnutie uvažovania nadradenému backendu. Úspešný
test pripojenia automaticky vyberie ovládacie prvky šablóny chatu pre každé presné ID modelu,
pri ktorom položka `/models` preukazuje rozpoznanú hodnotu `owned_by`: `vllm`, `sglang` alebo `llamacpp`.
Transparentné obálky kompatibilné s OpenAI môžu zachovať pôvodnú položku modelu vo vnorenom
objekte `openai`; detekcia prechádza najviac tromi takýmito obálkami. Modely s chýbajúcim, neznámym alebo
konfliktným vlastníctvom si zachovajú bežné správanie OpenAI. Detekcia opätovne používa existujúcu požiadavku na katalóg,
negeneruje žiadne tokeny dokončenia a pri zmene koncového bodu pripojenia sa zneplatní.

Ak chcete toto správanie pevne nastaviť pre backend, ktorý tieto metadáta neposkytuje, použite existujúce rozhranie API
na čiastočnú aktualizáciu poskytovateľa:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Toto telo odošlite pomocou `PUT /api/providers/<connection-id>`. Pri danom pripojení sa explicitná
úroveň úsilia uvažovania `none` odošle ako `chat_template_kwargs.thinking=false` a
`chat_template_kwargs.enable_thinking=false`. Explicitné natívne hodnoty šablóny zostávajú smerodajné,
pokiaľ pravidlo uvažovania na strane servera nevynúti konkrétnu úroveň úsilia. Nastavenie sa uplatní iba vtedy, keď vlastné
pripojenie kompatibilné s OpenAI odošle telo Chat Completions; požiadavky Responses a bežní
poskytovatelia si zachovajú svoj natívny tvar požiadavky. Nastavte `reasoningControl` na `openai`, ak chcete vynútiť bežné
priame odovzdanie OpenAI `reasoning_effort`, alebo ho vynechajte/nastavte na `null`, ak chcete použiť automatickú detekciu.

Požiadavky klasifikátora automatického režimu Claude Code predvolene nastavujú natívne uvažovanie ako vypnuté, ak
neobsahujú žiadne explicitné ovládacie prvky uvažovania. Detekcia používa systémovú značku klasifikátora v požiadavkách
vo formáte Claude, nie názvy modelov ani limity dokončenia. Explicitné ovládacie prvky tela, podporované hlavičky úsilia/uvažovania,
pravidlá smerovania a určená úroveň úsilia modelu si zachovávajú svoju existujúcu prioritu. Obe fázy klasifikátora
si zachovávajú svoje prompty, limity dokončenia, ukončovacie sekvencie a skutočné výsledky overenia oprávnení
nadradenou službou; druhá fáza môže naďalej vytvárať požadované viditeľné uvažovanie ako bežný text.

### Verzia a kanál vydania

```bash
GET /api/system/version
```

Trasa správy dostupná iba cez loopback rozhranie (vyžaduje overenie správcu). Vráti spustenú verziu, najnovšiu
publikovanú verziu a stav automatických aktualizácií. `releaseChannel` a `channels` sú doplnkové
polia (vetva 3.8.54); `channel` si zachováva svoj význam — režim nasadenia, ktorý používa aktualizačný nástroj
ovládacieho panela (`npm`, `source` alebo `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm kanál spustenej zostavy: `nightly` pre verzie `-nightly.*`,
  `next` pre ostatné predbežné vydania (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` pre stabilnú verziu
  staršej hlavnej verzie, než je `channels.latest`, inak `latest`. Platia rovnaké pravidlá ako v
  `scripts/release/dist-tag.mjs`, ktorý pri publikovaní vyberá npm dist-tag.
- `channels` — najnovšia publikovaná verzia každého dist-tagu získaná z `npm view omniroute dist-tags` (s náhradným
  použitím HTTP registra), uložená vo vyrovnávacej pamäti s rovnakou 10-minútovou dobou platnosti ako `latest`. `latest` je vždy prítomný
  (pri nedostupnosti sa použije pole `latest` a následne `"unavailable"`); `next`, `nightly` a `lts` sa zobrazia
  iba vtedy, keď daný dist-tag existuje. Požiadavka s `Cache-Control: no-cache` obnoví obe vyhľadávania.

Model kanálov (`latest` = v3 až do všeobecnej dostupnosti verzie 4.0, `next` = rc, `nightly` = zostavy z vetvy `develop`,
`lts` = opravy v3 po všeobecnej dostupnosti verzie 4.0) je opísaný v `docs/ops/RELEASE_STRATEGY.md`.

## Limity tokenov

Rozpočty **tokenov** pre jednotlivé kľúče API (odlišné od vyššie uvedeného rozpočtu v USD). Vynucujú sa priamo počas spracovania požiadavky: keď využitie kľúča v aktuálnom časovom okne dosiahne svoj limit, požiadavky sa odmietnu s chybou `429 Too Many Requests`. Limity možno obmedziť na konkrétny `model`, `provider` alebo ich uplatniť `global` na celý kľúč. Ak požiadavke zodpovedá viacero limitov, použije sa najprísnejší z nich.

```bash
# Zobrazenie limitov tokenov kľúča (vrátane aktuálneho využitia časového okna)
GET /api/usage/token-limits?apiKeyId=key-123

# Vytvorenie alebo aktualizácia limitu tokenov
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Odstránenie limitu tokenov podľa identifikátora
DELETE /api/usage/token-limits?id=tl-abc
```

> **Poznámky k schéme** (`setTokenLimitSchema`): `apiKeyId` a `scopeType` (`model` | `provider` | `global`) sú povinné. `scopeValue` je povinné, pokiaľ `scopeType` nie je `global` (napr. identifikátor modelu pre rozsah `model` alebo identifikátor poskytovateľa pre rozsah `provider`). `tokenLimit` musí byť kladné celé číslo (konvertované z reťazca). Voliteľné: `id` (vynechajte pri vytváraní, zadajte pri aktualizácii), `resetInterval` (`daily` | `weekly` | `monthly`, predvolená hodnota `monthly`), `resetTime` (`HH:MM`), `enabled` (predvolená hodnota `true`). Odpovede `GET` dopĺňajú každý limit o `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` a `nextResetAt`. Ide o koncový bod triedy správy (overovanie oprávnenia centrálne vynucuje autorizačný kanál).

## Spracovanie požiadaviek

1. Klient odošle požiadavku na `/v1/*`
2. Obslužná rutina trasy zavolá `handleChat`, `handleEmbedding`, `handleAudioTranscription` alebo `handleImageGeneration`
3. Určí sa model (priamy poskytovateľ/model alebo alias/kombinácia)
4. Z lokálnej databázy sa vyberú prihlasovacie údaje s filtrovaním podľa dostupnosti účtu
5. Pre čet: `handleChatCore` skontroluje sémantickú/signatúrnu vyrovnávaciu pamäť a určí nastavenia kompresie kombinácie
6. Ak je povolená proaktívna kompresia, spustí sa pred transformáciou pre poskytovateľa (`lite`, Caveman, RTK alebo vrstvená)
7. Vykonávací modul poskytovateľa odošle požiadavku nadradenej službe
8. Odpoveď sa transformuje späť do formátu klienta (čet) alebo sa vráti bez zmien (vektorové reprezentácie/obrázky/zvuk)
9. Zaznamenajú sa údaje o využití, analytika kompresie a protokoly požiadaviek
10. Pri chybách sa podľa pravidiel kombinácie použije záložná možnosť

Úplný popis architektúry: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Odolnosť (rozšírené)

OmniRoute poskytuje tri nezávislé mechanizmy na riešenie dočasných zlyhaní; nižšie uvedené koncové body na správu umožňujú operátorom čítať a prepisovať ich stav:

| Rozsah                   | Úložisko stavu                                 | Čítanie                                   | Resetovanie / vymazanie                                    |
| ------------------------ | ---------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------- |
| Istič poskytovateľa      | `domain_circuit_breakers` + pamäť              | `/api/monitoring/health`                  | `POST /api/resilience/reset`                               |
| Ochranná lehota spojenia | `rateLimitedUntil` v spojeniach poskytovateľov | `/api/rate-limits`, `/api/providers/[id]` | (opätovne sa povolí lenivo; vymažte cez PUT poskytovateľa) |
| Blokovanie modelu        | Register dostupnosti modelov v pamäti          | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                   |

`PATCH /api/resilience` prijíma prepísania ističa poskytovateľa v `providerBreaker.oauth` a `providerBreaker.apikey`. Každý profil podporuje `degradationThreshold`, `failureThreshold` a `resetTimeoutMs`; rovnaké polia sú dostupné v Ovládací panel → Nastavenia → Odolnosť.

```bash
# Vymazanie blokovania jedného modelu
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Vymazanie všetkých blokovaní
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Úplný koncepčný prehľad a predvolené nastavenia ističov: pozrite si [`CLAUDE.md`](../../CLAUDE.md) → „Stav behu odolnosti“ a [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Front obmedzenia rýchlosti a poistka automatického zapnutia

- **Podporovaný spôsob zápisu**: `POST /api/rate-limits` s telom `{"connectionId": "<id>", "enabled": true|false}` je podporovaný koncový bod na správu zapínania a vypínania ochrany spojenia pred obmedzením rýchlosti. `PUT /api/providers/[id]` zámerne neupravuje ani neprepína `rateLimitProtection` (#11278).
- **Sémantika `enabled: false`**: Nastavenie `enabled: false` odstráni explicitnú ochranu spojenia, ale **nevyradí** aktívne spojenie s API kľúčom z globálnej poistky automatického zapnutia (`autoEnableApiKeyProviders = true`). Vo funkcii `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) sú hodnoty `false` a `undefined` ekvivalentné; aktívne spojenia s API kľúčom bez explicitnej ochrany zostávajú chránené poistkou automatického zapnutia.
- **Globálne vypnutie**: Ak chcete používať spojenia s API kľúčom bez frontov obmedzenia rýchlosti, vypnite poistku globálne prostredníctvom `RATE_LIMIT_AUTO_ENABLE=false` (premenná prostredia) alebo `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Nastavenia → Odolnosť / `PATCH /api/resilience`).

## Server MCP

OmniRoute obsahuje vstavaný server Model Context Protocol s 3 transportmi (stdio, SSE, streamable-http) a nástrojmi s obmedzeným rozsahom. Nižšie uvedené koncové body ovládacieho panela čítajú údaje o stave/audite a sprostredkúvajú HTTP transporty.

| Metóda | Cesta | Popis |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Signál aktivity, transport, stav online, posledné volanie, najpoužívanejšie nástroje, úspešnosť za 24 hodín |
| GET | `/api/mcp/tools` | Zoznam nástrojov MCP s `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Otvorenie prúdu SSE pre transport SSE (vráti `503`, ak je MCP zakázané alebo sa transport nezhoduje) |
| POST | `/api/mcp/sse` | Odoslanie rámca JSON-RPC cez transport SSE |
| GET | `/api/mcp/stream` | Otvorenie strany SSE transportu Streamable HTTP (správy iniciované serverom) |
| POST | `/api/mcp/stream` | Odoslanie rámca JSON-RPC cez transport Streamable HTTP |
| DELETE | `/api/mcp/stream` | Ukončenie relácie Streamable HTTP |
| GET | `/api/mcp/audit` | Dotazovanie denníka auditu — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Súhrnné štatistiky auditu (celkové počty, úspešnosť, priemerné trvanie, najpoužívanejšie nástroje) |

**Autentifikácia:** transporty `sse`/`stream` rešpektujú autentifikačné rozhranie špecifické pre MCP (kľúč API typu Bearer s rozsahom `mcp`); trasy `status`/`tools`/`audit*` sú čitateľné z ovládacieho panela (okrem prístupu k hostiteľovi ovládacieho panela sa nevyžaduje žiadna ďalšia autentifikácia).

> Oba HTTP transporty sú riadené nastaveniami `settings.mcpEnabled` a `settings.mcpTransport` — nezhoda transportu vráti `400`, zakázaný stav MCP vráti `503`.

## Server A2A

OmniRoute sprístupňuje koncový bod A2A (Agent-to-Agent) JSON-RPC 2.0 a tiež REST obal na účely kontroly a použitia v ovládacom paneli.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # voliteľné, ak nie je nastavená premenná OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Podporované metódy (všetky podmienené nastavením `settings.a2aEnabled`):

| Metóda           | Popis                                                                |
| ---------------- | -------------------------------------------------------------------- |
| `message/send`   | Synchrónne vykonanie zručnosti; vracia `{task, artifacts, metadata}` |
| `message/stream` | Streamované vykonanie rovnakej množiny zručností cez SSE             |
| `tasks/get`      | Načíta úlohu podľa `taskId`                                          |
| `tasks/cancel`   | Zruší úlohu podľa `taskId`                                           |

Vstavané zručnosti: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Karta agenta

```bash
GET /.well-known/agent.json
```

Vracia verejnú kartu agenta A2A (názov, popis, schopnosti, katalóg zručností, schéma autentifikácie) — verejne uloženú vo vyrovnávacej pamäti na 1 hodinu. Autentifikácia sa nevyžaduje.

### Pomocné rozhrania REST

| Metóda | Cesta                        | Popis                                                                                                            |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Stav povolenia A2A + štatistiky úloh + súhrn karty agenta z vyrovnávacej pamäte                                  |
| GET    | `/api/a2a/tasks`             | Zoznam úloh — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nie je implementované ako pomocné rozhranie REST — vytvárajte prostredníctvom JSON-RPC `message/send`)          |
| GET    | `/api/a2a/tasks/[id]`        | Načíta jednu úlohu                                                                                               |
| POST   | `/api/a2a/tasks/[id]/cancel` | Zruší úlohu                                                                                                      |

**Autentifikácia:** pomocné rozhrania REST fungujú bez autentifikácie na správu (sú čitateľné ovládacím panelom); trasa JSON-RPC `/a2a` používa Bearer `OMNIROUTE_API_KEY`, ak je nakonfigurovaný.

## Tieňové smerovanie

Tieňové porovnávanie poskytovateľov / porovnávanie poskytovateľov metódou A/B **nie je samostatným rozhraním REST** — konfiguruje sa prostredníctvom kombinovaného smerovania (pozrite si dokument [Automatická kombinácia](../routing/AUTO-COMBO.md)). Metriky porovnania pre jednotlivé kombinácie poskytuje `GET /api/combos/metrics`.

## Ochranné mechanizmy

Skontrolujte ochranné mechanizmy behového prostredia (detekciu osobných identifikačných údajov, detekciu vloženia škodlivých inštrukcií do promptu a premostenie spracovania obrazu). Ochranné mechanizmy sa spúšťajú pri každej požiadavke; ich vypnutie pre konkrétne volanie sa vykonáva prostredníctvom hlavičky požiadavky `x-omniroute-disabled-guardrails` — neexistuje žiadne trvalé rozhranie na ich povolenie alebo zakázanie.

| Metóda | Cesta                  | Popis                                                                                               |
| ------ | ---------------------- | --------------------------------------------------------------------------------------------------- |
| GET    | `/api/guardrails`      | Zoznam zaregistrovaných ochranných mechanizmov a ich stavov (názov / povolené / priorita)           |
| POST   | `/api/guardrails/test` | Skúšobné spustenie reťazca pred volaním nad vzorovým vstupom — telo: `{input, disabledGuardrails?}` |

## Autentifikácia

Informácie o štyroch skupinách prihlasovacích údajov (relácia ovládacieho panela, lokálny token CLI, prístupový token `oma_live_…`, API kľúč s rozsahom správy) a o tom, ako sa líšia od kľúčov na inferenciu, nájdete v časti [Autentifikácia správy](../guides/MANAGEMENT-AUTH.md).

- Trasy ovládacieho panela (`/dashboard/*`) používajú súbor cookie `auth_token`
- Prihlásenie používa uložený hash hesla; ako záložná možnosť sa používa `INITIAL_PASSWORD`
- Nastavenie `requireLogin` možno prepínať prostredníctvom `/api/settings/require-login`
- Trasy `/v1/*` môžu voliteľne vyžadovať API kľúč Bearer, keď je `REQUIRE_API_KEY=true`
- Výrazy „token správy“ / „API kľúč s rozsahom správy“ v tejto referenčnej dokumentácii označujú jednu zo skupín uvedených v danej príručke — nie nedefinovaný dodatočný typ tajného údaja

> **Nekompatibilná zmena (v3.8.0)** — `/api/v1/agents/tasks/*` a koncové body na správu čakacej lehoty teraz vyžadujú **autentifikáciu správy** (súbor cookie `auth_token` ovládacieho panela alebo API kľúč s rozsahom správy). Klienti, ktorí predtým volali tieto trasy bez autentifikácie, dostanú odpoveď `401 Unauthorized`. Pozrite si commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
