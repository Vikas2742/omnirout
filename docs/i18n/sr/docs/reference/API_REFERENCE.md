## Довршавања ћаскања

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Прилагођена заглавља

| Заглавље                 | Смер    | Опис                                                                                                                                                                                                                          |
| ------------------------ | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Захтев  | Поставите на `true` да бисте заобишли кеш                                                                                                                                                                                     |
| `x-omniroute-no-memory`  | Захтев  | Поставите на `true` да бисте за овај захтев прескочили уметање меморије и вештина (одговара понашању без кеша; избегава додатну потрошњу токена/трошак по позиву)                                                             |
| `X-OmniRoute-Progress`   | Захтев  | Поставите на `true` за догађаје напретка                                                                                                                                                                                      |
| `X-Session-Id`           | Захтев  | Кључ лепљиве сесије за спољни афинитет сесије                                                                                                                                                                                 |
| `x_session_id`           | Захтев  | Прихвата се и варијанта са доњом цртом (директни HTTP)                                                                                                                                                                        |
| `X-OmniRoute-Session-Id` | Захтев  | Ознака сесије/разговора коју задаје позивалац (користи се и за меморију). Када је присутна, дословно се чува у `call_logs.session_tag` ради приписивања трошкова по сесији (#8249) — никада се не генерише када није присутна |
| `Idempotency-Key`        | Захтев  | Кључ за уклањање дупликата (прозор од 5 s)                                                                                                                                                                                    |
| `X-Request-Id`           | Захтев  | Алтернативни кључ за уклањање дупликата                                                                                                                                                                                       |
| `x-omniroute-connection` | Захтев  | Везује захтев за један модел за једну везу добављача (налог) према њеном ID-у — погледајте [Везивање налога по захтеву](#account-pinning-per-request)                                                                         |
| `X-OmniRoute-Cache`      | Одговор | `HIT` или `MISS` (без стримовања)                                                                                                                                                                                             |
| `X-OmniRoute-Idempotent` | Одговор | `true` ако су дупликати уклоњени                                                                                                                                                                                              |
| `X-OmniRoute-Progress`   | Одговор | `enabled` ако је праћење напретка укључено                                                                                                                                                                                    |
| `X-OmniRoute-Session-Id` | Одговор | Ефективни ID сесије који користи OmniRoute                                                                                                                                                                                    |
| `X-OmniRoute-Request-Id` | Одговор | ID за корелацију захтева (када је познат)                                                                                                                                                                                     |
| `X-OmniRoute-Version`    | Одговор | Верзија издања OmniRoute-а (увек присутна)                                                                                                                                                                                    |
| `X-OmniRoute-Cost-Saved` | Одговор | Износ у USD који је кеш уштедео при `HIT` (само за поготке кеша)                                                                                                                                                              |
| `X-OmniRoute-Decision`   | Одговор | Траг усмеравања: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` је стратегија комбинације или `single` за захтев који није комбинација) — увек је присутан у одговорима по завршетку                           |

> Напомена за Nginx: ако се ослањате на заглавља са доњим цртама (на пример `x_session_id`), омогућите `underscores_in_headers on;`.

#### Везивање налога по захтеву

Када добављач има више веза (налога или кључева), OmniRoute обично бира једну
помоћу своје стратегије избора налога. Уместо тога, захтев може да се веже за одређену везу
помоћу заглавља `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Где пронаћи идентификатор.** Отворите страницу добављача на контролној табли
  (**Контролна табла → Добављачи → <provider>**) и кликните на ознаку идентификатора `xxxxxxxx…` у реду
  везе — тиме се копира цео идентификатор везе.
- **Који захтеви га поштују.** Захтеви за један модел (`provider/model`) на
  `/v1/chat/completions`, `/v1/messages` и `/v1/responses`. Комбинације игноришу заглавље: вежите
  налог за сваки корак комбинације преко сопствене везе тог корака.
- **Везивање је строго, а не само приоритет.** Везана веза се користи искључиво. Неуспех
  унутар захтева бележи период хлађења налога, али се **не** пребацује на
  други налог истог добављача.
- **Период хлађења и квота ослобађају везу.** Док је везана веза у периоду хлађења,
  док јој је квота исцрпљена или је блокирана политиком квота, наредни захтеви прелазе на друге
  везе добављача, потпуно исто као саобраћај без везивања.
- **Непознати или онемогућени идентификатори доводе до неуспеха.** Идентификатор који није у активном скупу добављача (избрисан,
  деактивиран или припада другом добављачу) не оставља ниједан одговарајући налог, па захтев
  не успева уместо да буде неприметно усмерен на друго место.

Claude Code шаље прилагођена заглавља преко `ANTHROPIC_CUSTOM_HEADERS`. Поставите га у блок `env`
датотеке `~/.claude/settings.json` или у `.claude/settings.json` на нивоу пројекта да бисте везали други
налог за сваки пројекат:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Извор: `src/sse/handlers/chat.ts` (читање заглавља), `src/sse/services/auth.ts` и
`src/sse/services/sessionAffinityPin.ts` (ослобађање везе и провера одсуства из скупа).

> **Заглавља телеметрије трошкова:** успешни одговори без стримовања такође садрже скуп телеметрије трошкова `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, фиксних 10 децималних места; `0.0000000000` за бесплатне услуге или услуге без дефинисане цене), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` и `X-OmniRoute-Fallback-Attempts` (само када је > 0), као и `X-OmniRoute-Request-Id` и `X-OmniRoute-Version`. Њих емитују довршавања ћаскања, `/v1/responses`, `/v1/messages`, **као и крајње тачке за медије** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` и `/v1/moderations` (трошак је увек `0`). Трошак медија израчунава се по модалитету (по слици, по секунди, по знаку, по јединици претраге) када су цене доступне, а у супротном је `0` (наставак рада у случају грешке).

> **Семантика трошкова при поготку кеша:** при ПОГОТКУ семантичког кеша (`X-OmniRoute-Cache-Hit: true`) не упућује се позив узводном сервису, па је `X-OmniRoute-Response-Cost` једнак `0.0000000000` (**инкрементални** трошак опслуживања поготка). Првобитни трошак, односно трошак који би иначе настао, пријављује се засебно у `X-OmniRoute-Cost-Saved`. Системи за обрачун треба да сабирају `X-OmniRoute-Response-Cost` (погоци не коштају ништа); аналитика кеша може да агрегира `X-OmniRoute-Cost-Saved`.

## Ексклузивни закупи управљаних сесија

Ексклузивни закуп управљаних сесија је опциони уговор о рутирању, независан од клијента: један активни власник
држи једну одговарајућу OmniRoute везу. Он не закупљује модел, не захтева OAuth, не идентификује
одређеног клијента нити захтева одређеног добављача.

API кључ који се користи за аутентификацију мора имати опсег `lease:exclusive` и изричито наведену непразну
листу `allowedConnections`. Граница мутације базе података намеће оба поља заједно приликом креирања кључа
и делимичних ажурирања.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Успешни одговори на стицање, обнављање и ослобађање излажу временске ознаке, `state` и тачну позитивну
вредност `generation`, али никада изабрану везу или акредитиве. Обнављање и ослобађање наводе
генерацију у JSON телу:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Власник активног закупа може изричито да затражи метаподатке за приказ који не угрожавају приватност за своје тренутно повезивање:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Ова опиона радња за добијање статуса заштићена је непрозирним идентификатором власника, аутентификованим управљаним API кључем и тачном
активном генерацијом у оквиру једне трансакције базе података. `displayName` је само скраћени конфигурисани
назив везе; има вредност `null` када не постоји безбедан конфигурисани назив. OmniRoute никада не користи
адресу е-поште или генерисани идентитет налога као замену. Вредност добављача је неосетљива ознака за приказ и никада
није генерисани идентификатор компатибилног добављача. Акредитиви, токени, колачићи, необрађени идентификатори везе или API
кључа, хешеви власника, тајне за ограђивање и интерни подаци о рутирању су изузети.

Претраге са погрешним кључем, погрешним власником, застарелом генерацијом, као и претраге недостајућих, истеклих, ослобођених и поништених закупа,
увек враћају исту грешку `409 LEASE_FENCE_STALE` без метаподатака о вези. Клијент који је примио одговор о чекању капацитета нема активно повезивање које може да провери. Када рутирање пребаци активни закуп,
иста генерација остаје важећа, а статус атомарно враћа ново повезивање, никада старо.
Постојећи клијенти остају непромењени јер одговори на стицање, обнављање, ослобађање и чекање задржавају
своје претходне облике.

Овај серверски уговор не мења стандардни OpenAI Codex `/status`. Стандардни Codex тренутно пријављује свог
добављача модела и уграђено стање аутентификације/налога, али не приказује произвољне прилагођене
метаподатке налога добављача; будућа интеграција клијента мора позвати ову радњу и одлучити како ће
приказати `connection.displayName`.

Сваки управљани захтев за извођење инференције затим наводи оба контролна заглавља:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Тачан власник, генерација, активна веза и аутентификовани API кључ проверавају се непосредно
пре сваког подржаног покушаја према надређеном сервису. Поновна употреба власника и генерације са другим кључем не успева чак
и када тај кључ дозвољава исту везу. Необрађени идентификатори власника се не чувају трајно, не евидентирају се, не задржавају у
снимку захтева нити се прослеђују надређеном сервису.

Привремено надметање за ресурсе враћа HTTP `429` са `Retry-After` и:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Овај одговор само значи да уобичајени скуп одговарајућих веза није био празан и да је сваки слободан кандидат
био заузет туђим активним закупом. Неподржани модели/добављачи, неусклађеност са смерницама, период чекања, квота,
здравствено стање и други уобичајени разлози неподобности задржавају своје постојеће OmniRoute одговоре.

### `x-omniroute-compression`

Замена плана компресије за појединачни захтев. Има највиши приоритет — надјачава замену комбинације
рутирања, активни профил, аутоматски окидач и подразумевано подешавање панела. Вредности:

| Вредност      | Дејство                                                                                                           |
| ------------- | ----------------------------------------------------------------------------------------------------------------- |
| `off`         | Без компресије за овај захтев.                                                                                    |
| `default`     | Подразумевани профил изведен из панела (занемарује активни профил). Механизми са губицима остају искључени.       |
| `safe`        | Само дедупликација и сажимање размака.                                                                            |
| `allow-lossy` | Задржава план оператера за овај захтев, укључујући сажетке и преписивање стила.                                   |
| `engine:<id>` | Један механизам када је омогућен, нпр. `engine:rtk`. Опционо укључивање тог механизма за појединачни захтев.      |
| `<combo>`     | Именована комбинација, прво упарена по називу (без разликовања великих и малих слова), а затим по идентификатору. |

Напомене:

- Непознате вредности се занемарују (захтев се никада не одбија); разрешавање се наставља према уобичајеном приоритету оператера.
- Ако више комбинација има исти назив, проследите **id** комбинације ради детерминистичког подударања.
- Комбинација чији је назив `off` или `default` не може се изабрати по називу (те кључне речи се прве тумаче); такву комбинацију наведите помоћу њеног идентификатора.
- Главни прекидач компресије представља строгу контролу: када је компресија глобално онемогућена, ово заглавље не може да је омогући.

Примењени план се враћа у заглављу одговора:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

где је `<source>` једно од `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` или `off`.

## Уграђивања

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Доступни добављачи: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Идентификатори каталога имају облик `provider/model` (пример: `jina-ai/jina-embeddings-v5-omni-small`). Непрефиксовани идентификатори Jina модела који се појављују у регистру (на пример `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) такође се разрешавају. Jina операције уграђивања/поновног рангирања/класификације/сегментације најпре користе `jina-ai` акредитиве са контролне табле; `JINA_AI_API_KEY` служи као резервна опција само када кључ са контролне табле не постоји. Картица `jina-reader` служи само за Reader / `r.jina.ai` (`POST /v1/web/fetch`) и никада не пружа уграђивања нити поновно рангирање.

Модели у регистру који наводе мултимодалну подршку прихватају и до 32 структуриране
ставке независне од добављача. Типови медијских ставки су `text`, `image`, `audio`, `video` и `document`. Њихов медијски `source`
је или `{"type":"url","url":"https://..."}` или
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
као и псеудоним породице `jina-ai/jina-embeddings-v5-omni` → omni-small) такође прихвата Jina изворне
EmbeddingsV5Request документе и **прослеђује их непромењене** на `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Изворне вредности `{ image | audio | video | pdf }` могу бити јавни HTTPS URL, `data:` URI или сирови
base64. OmniRoute не претвара те објекте у ниске нити преузима изворне URL-ове слика — Jina сама преузима
јавне медије. Додатна Jina поља (`task`, `normalized`, `truncate`, `embedding_type`) се
прослеђују. Jina SKU-ови намењени искључиво тексту и даље одбацују нетекстуалне документе.

Безбедносна и транспортна ограничења:

- URL-ови удаљених медија морају бити јавни HTTPS URL-ови. Канонске ставке `{type,source:url}` преузимају се
  на серверској страни (поновна валидација преусмеравања, временско ограничење, ограничења величине, јавни DNS, фиксирање везе) и
  умећу се пре позива добављача. Jina изворне ставке `{image:"https://..."}` прослеђују се непромењене
  након исте провере јавног HTTPS-а; Jina преузима URL.
- Уметнути base64 медији ограничени су на 8 MiB декодираних података по ставци и 16 MiB декодираних података у целом захтеву.

Превођење за добављаче (канонске ставке се никада не прослеђују непромењене):

- Jina мултимодални модели: свака ставка највишег нивоа постаје један објекат са кључем модалитета
  (`text` / `image` / `audio` / `video` / `pdf`), уз коришћење URI-ја података за уметнуте медије; један вектор по
  ставци највишег нивоа.
- Породица Gemini Embedding 2: један низ највишег нивоа постаје један изворни
  `models/{model}:embedContent` захтев са `content.parts` (`text` или `inline_data`).
- llama.cpp (`llama-cpp/<model>`, било који модел који је локални сервер учитао): канонске `text` ставке
  постају обичне ниске, док `image` / `audio` / `video` постају по један
  `{"content": [part]}` објекат, користећи делове садржаја за ћаскање llama-server-а (`image_url`,
  `input_audio` са форматом `wav` / `mp3` / `flac`, `input_video`) са уметнутим подацима; један вектор
  по ставци највишег нивоа. Сервер мора бити покренут са `--embedding --mmproj …`; без пројектора
  сам одбацује медије. `document` није подржан.
- Непознати/динамички модели без експлицитних метаподатака о модалитету одбацују структурирани улаз са HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Неподржане комбинације модела и модалитета враћају HTTP 400 уместо принудног претварања ставке. Проширена
поља која нису улазна на застарелим захтевима са нискама/токенима и даље се прослеђују непромењена.

```bash
# Прикажи све моделе за уграђивање
GET /v1/embeddings
```

## Генерисање слика

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Доступни добављачи обухватају OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (локално), ComfyUI (локално).

`n` враћа `n` слика у `data[]`. За добављаче чији узводни API враћа једну слику по позиву
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) извршава се `n` засебних узводних позива, од којих су највише 4 истовремено активна. Фиксна
вредност `seed` увећава се за индекс позива (`seed`, `seed + 1`, …), тако да се слике разликују, али остају
поновљиве. `n` је ограничен на 10. Цео захтев не успева ако било који позив не успе. Листа
формата са вишеструким позивима налази се у `SINGLE_IMAGE_FANOUT_FORMATS` у
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux поново користи постојећу везу са API кључем и прихвата префиксе `zenmux/` или `zm/`:

- `zenmux/openai/gpt-image-2` користи OpenAI Images API сервиса ZenMux. Опције обухватају `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` и `response_format`.
- Други издавачи, као што је `zm/meta/muse-image-1.0`, користе Vertex AI крајњу тачку `:predict`
  сервиса ZenMux. `n` се мапира на `sampleCount`, `aspect_ratio` на `aspectRatio`, а `image_size`
  (`1K`, `2K`, `4K`) на `sampleImageSize`. Вредност `size` у пикселима задаје само однос ширине и висине,
  а не и гарантоване димензије у пикселима. Подржани односи, резолуције и бројеви слика разликују се у зависности од модела.
- `zm/inclusionai/ming-image-0.1-design` сам бира своје димензије. Изоставите `size`,
  `aspect_ratio` и `image_size`; експлицитне вредности враћају HTTP 400. PNG, JPEG и WebP
  могу се затражити помоћу `output_format`.

Ова интеграција подржава генерисање слика из текста, али не и уређивање референтних слика. Vertex
излаз се нормализује у `data[].b64_json`; `response_format: "url"` враћа узводни
HTTPS URL или base64 URL података када су доступни само бајтови слике. Празни/филтрирани излази
враћају грешку уместо празног успешног одговора. Приступ моделима зависи од ZenMux налога.
Погледајте [Vertex API сервиса ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) и
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

```bash
# Прикажи све моделе за слике
GET /v1/images/generations
```

## OCR докумената

```bash
POST /v1/ocr
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "mistral/mistral-ocr-latest",
  "document": {
    "type": "document_url",
    "document_url": "https://example.com/invoice.pdf"
  }
}
```

`model` бира OCR добављача помоћу префикса `provider/model`; самостални ID модела (нпр.
`mistral-ocr-latest`) разрешава се на регистрованог добављача, а ако је `model` изостављен, подразумевана вредност је
Mistral (`mistral-ocr-latest`). Регистровани добављачи (`open-sse/config/ocrRegistry.ts`):

| ID добављача                  | ID модела            | Вредност `model`                                             | Напомене                                                                                                                     |
| ----------------------------- | -------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (или само `mistral-ocr-latest`) | Синхроно — одговор се враћа директно из једног узводног позива.                                                              |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                  | Асинхрони узводни ток (`analyze` + проверавање) — погледајте испод.                                                          |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                      | Синхроно, преко партнерске крајње тачке `openapi/chat/completions` сервиса Vertex AI — погледајте испод за ауторизацију/URL. |

Сва три добављача одговарају телом истог облика као Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Ток проверавања у Azure Document Intelligence

API `analyze` сервиса Azure Document Intelligence је асинхрон: почетни захтев враћа
заглавље `Operation-Location` уместо тела, а затим се резултат мора периодично проверавати. Обрађивач
(`open-sse/handlers/ocr.ts`) проверава тај URL сваке секунде, највише 30 пута, и одмах прекида са грешком (не
наставља са проверавањем) ако одговор провере није `ok` или ако је статус `"failed"`, а враћа `504` ако је
операција и даље у току након што се исцрпи дозвољени број покушаја. Коначни Azure одговор се
нормализује у исти облик `pages`/`markdown` који користи Mistral пре него што се врати
позиваоцу, тако да клијентски кôд не мора посебно да обрађује сваког добављача.

### Ауторизација и разрешавање крајње тачке за Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` поново користи исту Vertex AI аутентификацију коју OmniRoute већ подржава за
саобраћај ћаскања/слика (`open-sse/executors/vertex.ts`): API кључ везе је или
JSON акредитив сервисног налога (који се размењује за краткотрајни OAuth приступни токен путем JWT-bearer
тока) или већ издати OAuth приступни токен који се користи без измена. URL узводне крајње тачке је Vertex
генеричка партнерска крајња тачка `openapi/chat/completions`, формирана на основу пројекта и
региона везе — експлицитни `providerSpecificData.project`/`providerSpecificData.region` увек имају предност;
у супротном, пројекат се изводи из `project_id` у JSON-у сервисног налога, а подразумевани регион је
`us-central1`. Оба разрешавања се обављају у `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), а користи их
`src/app/api/v1/ocr/route.ts` пре прослеђивања у `handleOcr`.

GET /v1/models
Authorization: Bearer your-api-key

→ Враћа све моделе за ћаскање, уграђивање и слике + комбинације у OpenAI формату

### Префикси идентификатора модела (`?prefix=`)

Већина модела се оглашава под **префиксом добављача**. Префикс који добијате контролише
ознака функције `MODELS_CATALOG_PREFIX_MODE`, а може се заменити **за сваки захтев појединачно** помоћу
параметра упита — што је корисно за клијента који жели чисту листу без мењања подешавања
на нивоу целог сервера за све остале:

```bash
GET /v1/models?prefix=alias        # један идентификатор по моделу — кратки префикс псеудонима
GET /v1/models?prefix=dual         # оба облика (подразумевана вредност сервера)
GET /v1/models?prefix=canonical    # само пуни префикс идентификатора добављача
```

| Режим       | Емитује                                                 | Напомене                                                                                                                                                                                                 |
| ----------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **и** `claude/claude-sonnet-4-6` | **Подразумевано.** Оба идентификатора усмеравају ка истом моделу; задржани су како би конфигурације клијената у којима је било који облик уграђен наставиле да раде. Приближно удвостручује каталог.     |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Један унос по моделу. Добављачи без посебног псеудонима и даље емитују свој унос, тако да се ништа не губи.                                                                                              |
| `canonical` | `claude/claude-sonnet-4-6`                              | Један унос по моделу под пуним префиксом идентификатора добављача. Добављачи без посебног псеудонима (нпр. `antigravity/…`, `agy/…`) и овде емитују свој једини идентификатор, тако да се ништа не губи. |

Одраз у режиму `dual` може се препознати и без параметра упита: садржи поље `parent`
које указује на примарни идентификатор.

Клијенти који приказују бирач модела треба да захтевају `?prefix=alias` — то ради и
[OmniCopilot проширење за VS Code](../guides/VSCODE-COPILOT.md).

### Филтери за откривање (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` прихвата опционе филтере за откривање. Без њих одговор остаје
непромењен. Они сужавају каталог који позивалац већ види (дозволе API кључа примењују се прве)
и извршавају се пре страничења у OpenAI стилу помоћу `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # свака наведена могућност мора бити омогућена
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # каталошки `type`; редови без њега су `chat`
GET /v1/models?q=sonnet&limit=10                           # подударање идентификатора или назива без обзира на величину слова
```

| Параметар     | Вредности                                                                                           |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | ненегативан цео број, пореди се са `context_length`                                                 |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 знакова                                                                                       |

Непозната вредност или `min_context` који није ненегативан цео број (на пример `1.5`)
враћа HTTP `400`, а порука наводи важеће вредности. Имплементација:
`src/app/api/v1/models/catalogFilters.ts`.

### Ужи избор модела (`POST /v1/models/query`)

`POST /v1/models/query` враћа кратку, детерминистичку листу из истог каталога, са истом
аутентификацијом и видљивошћу по кључу као `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Свако поље је опционo. `capabilities` и `exclude` прихватају низ или ниску раздвојену зарезима;
`max_output` се пореди са `max_output_tokens`. Резултати се сортирају прво по `owned_by`, а затим по `id`.
Подразумевана вредност за `limit` је `20`, а вредности веће од `100` ограничавају се на `100`. Неважећи JSON, непознато
поље или неважећа вредност враћају HTTP `400`.

### Појединачно скривени модели за ћаскање

Модел означен као **Скривен** на страници свог добављача искључен је из каталога и одбија се
са HTTP `404` / `model_not_found` када се изричито затражи. Провера користи разрешеног
добављача и модел, укључујући псеудониме добављача, префиксе чворова компатибилних добављача и
подразумеване вредности везе. Комбинација прескаче скривена одредишта и може да користи видљиво сродно одредиште; када
не преостане ниједно извршиво одредиште, враћа исти кôд грешке. Поништавање скривања ступа на снагу при следећем
захтеву. Замене видљивости само за слике не скривају модел за ћаскање са истим идентификатором.

Ово појединачно подешавање модела одвојено је од
[листа дозвољених/забрањених изложених модела](../routing/MODEL_EXPOSURE_LIST.md), које филтрирају
оглашавање каталога и кандидате за аутоматско усмеравање, док задржавају изричито прослеђивање. Дозволе модела
за API кључ настављају да се примењују независно. Подразумевани режим префикса каталога остаје `dual`.

### Варијанте модела без размишљања

За Claude моделе који подржавају размишљање, `/v1/models` такође оглашава варијанту **без размишљања** чији идентификатор има префикс `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Избор овог ID-а (нпр. у Claude Code конфигурацији која увек прилаже блок `thinking`) разрешава се назад на стварни `<provider>/<model>` са потиснутим резоновањем — `thinking:{type:"disabled"}` на путањи `/v1/messages`, односно уз изостављена поља `reasoning`/`reasoning_effort` на путањи `/v1/chat/completions`. Варијанта се приказује само за моделе из породице Claude који подржавају размишљање **и** поштују вредност `disabled` (тако су, нпр. искључени модели који подржавају искључиво адаптивни режим и одбацују `disabled`). Оператери могу принудно укључити или искључити варијанту за сваки модел путем `ModelSpec.noThinkingAlias`.

## ElevenLabs генерисање звука

Конфигуришите везу са провајдером `elevenlabs` у OmniRoute помоћу свог ElevenLabs API кључа.
Клијенти се аутентификују својим **OmniRoute** кључем (`Authorization: Bearer $OMNIROUTE_API_KEY`);
мрежни пролаз прослеђује сачувани кључ провајдера као `xi-api-key`. Никада не шаљите ElevenLabs кључ
као носећи токен мрежног пролаза.

| Метод | Путања                      | Одговор                                    | Категорија крајње тачке API кључа |
| ----- | --------------------------- | ------------------------------------------ | --------------------------------- |
| POST  | `/v1/sound-generation`      | Изворни аудио бајтови                      | `elevenlabs`                      |
| POST  | `/v1/music`                 | Изворни аудио бајтови                      | `music`                           |
| POST  | `/v1/music/stream`          | Стримовани аудио бајтови                   | `music`                           |
| POST  | `/v1/music/detailed`        | Изворни вишеделни аудио и план композиције | `music`                           |
| POST  | `/v1/music/detailed/stream` | Изворни SSE метаподаци и аудио сегменти    | `music`                           |
| POST  | `/v1/music/plan`            | JSON план композиције                      | `music`                           |

Ове крајње тачке допуњују постојеће руте `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` и `/v1/speech-to-text`. Изворна JSON поља
и параметри упита, као што су `output_format` и `enable_logging`, остају очувани.
Одговори са `/v1/music/detailed` задржавају своје вишеделне границе; рашчланите их као вишеделне.
`/v1/music/detailed/stream` враћа `text/event-stream` са метаподацима композиције и
base64 аудио сегментима у SSE догађајима. Свих шест рута подржава CORS претходне захтеве.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Кратак звучни ефекат. Трајање: од 0,5 до 30 секунди.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Трајање музике изражава се у милисекундама: од 3000 до 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Користите `/v1/music/stream` са истим JSON телом за постепену испоруку звука. Компоновање
прихвата тачно једно од `prompt` или `composition_plan`; `/v1/music/plan` захтева `prompt`
и опционо прихвата `source_composition_plan`. Изворне шеме задржавају додатна
поља провајдера како би верзије плана композиције и опције финог подешавања стигле до ElevenLabs.

Обједињена крајња тачка `/v1/music/generations` такође прихвата `elevenlabs/music_v1`,
`elevenlabs/music_v2` и `elevenlabs/music_v2_5`. Уз активну ElevenLabs везу,
ови модели су доступни у музичком каталогу. Ова крајња тачка враћа
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Њено поље `duration` изражено је у
секундама и мапира се на `music_length_ms`; експлицитно наведено `music_length_ms` има предност.
`instrumental` се мапира на `force_instrumental`, при чему изворно поље има предност.
Користите изворне стриминг крајње тачке за стримовање, а изворну крајњу тачку за компоновање
за захтеве засноване искључиво на плану композиције.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Ограничења крајње тачке, модела, буџета и везе примењују се пре позива узводног сервиса. Изворне
руте враћају непромењене статусне кодове и тела грешака узводног сервиса, укључујући `402` за
ограничење плана и `429` за ограничење квоте. Заглавља `character-cost`, `song-id`, `request-id` и `retry-after`
остају очувана када су присутна. Стање бесплатног кредита не гарантује приступ сваком
музичком моделу, излазном формату или API функцији: ElevenLabs одлучује о праву приступа за сваки захтев.
Обједињена крајња тачка задржава статусне кодове грешака у нормализованом OmniRoute омотачу грешке.

Уговори узводног сервиса: [звучни ефекти](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[компоновање музике](https://elevenlabs.io/docs/api-reference/music/compose) и
[детаљи стримовања музике](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

За клијенте који не могу да додају `Authorization: Bearer ...`, OmniRoute такође прихвата API кључеве у URL-у, било путем компатибилних параметара упита (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`), било путем наменских `/api/v1/vscode/{token}/...` крајњих тачака документованих у наставку.

```bash
# Поновно рангирање (добављач из регистра у облаку или чвор добављача компатибилан са OpenAI-јем као "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina класификација (акредитиви за Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina сегментатор
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina претрага (s.jina.ai; алијаси добављача: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Модерације
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — враћа тело у формату audio/mpeg (или у захтеваном формату)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS захтева језик и глас: `language` подразумевано има вредност "en"; ако глас
# недостаје или је наведен назив стандардног OpenAI гласа (alloy, nova, …), користи се "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Уређивање слике (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Генерисање видеа / музике (ID модела са префиксом добављача)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Чворови провајдера за поновно рангирање:** `POST /v1/rerank` такође усмерава захтеве ка чворовима провајдера компатибилним са OpenAI-јем
> (oMLX, vLLM, Infinity, TEI иза мрежног пролаза, …) адресираним као `<node-prefix>/<model>`. Чворови повратне петље
> (`localhost`, `127.0.0.1`, `172.16.0.0/12`) увек су прихватљиви, као и имена хостова која
> оператер наведе у `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (нпр. назив Docker/Compose сервиса као што
> је `http://reranker:8080/v1`; они се позивају директно, никада преко `HTTP(S)_PROXY` нити преко
> проксија фиксираног за везу). Чворови на било ком другом
> хосту — уређају на LAN мрежи или Tailscale равноправном чвору — прихватљиви су само када оператер омогући
> функционалну заставицу `RERANK_REMOTE_PROVIDER_NODES` **и** основни URL чвора задовољава смернице за
> одлазне URL-ове провајдера (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Корак поновног рангирања механизма меморије позива ову руту преко
> повратне петље, па исто правило важи за `rerankProviderModel` у подешавањима меморије.
>
> **Облици локалних сервера:** чвор се позива на `<base>/v1/rerank`, а у случају одговора 404 на `<base>/rerank`
> (Infinity, TEI). Тело захтева ка узводном серверу садржи и Cohere/OpenAI називе (`documents`,
> `return_documents`) и TEI називе (`texts`, `return_text`), а одговор узводног сервера
> нормализује се у Cohere омотач: TEI-јев необавијени `[{index, score, text}]`, `{results: [{index, score}]}`
> из једноставних мрежних пролаза и Voyage-ов `{data: [...]}` клијенту се враћају као
> `{results: [{index, relevance_score, document?}]}`, сортирани по оцени и ограничени вредношћу `top_n`.

> **Откривање чворова провајдера:** модели на чвору провајдера компатибилном са OpenAI-јем појављују се у `GET /v1/models`
> под префиксом чвора. Редови који не садрже метаподатке о крајњој тачки (што је типично за локалне `/v1/models` листе)
> наслеђују `apiType` чвора, тако да су модели чвора `embeddings` типа `type: "embedding"`, а модели
> чвора `rerank` типа `type: "rerank"` уместо да подразумевано буду типа за ћаскање; експлицитни
> `supportedEndpoints` у синхронизованом или ручно додатом реду и даље има предност.

### Exa и Tavily `provider_options`

Exa и Tavily читају поља специфична за добављача из простора имена:
`provider_options.exa` (или `provider_options["exa-search"]`) и `provider_options.tavily`
(или `provider_options["tavily-search"]`). Прослеђују се само кључеви наведени у наставку. Сваки од њих се
проверава према сопственој Zod шеми у `open-sse/handlers/search/providerOptionsPassthrough.ts`,
а кључ погрешног типа се одбацује. Сваки други кључ се игнорише, укључујући auth, основни URL,
`stream` и `outputSchema`. Равни кључеви које користе други добављачи (`cx`, `depth`, ...) раде
као и раније.

| Добављач | Поља највишег нивоа                                                                                                                                                                                                                                                                                                                                                       | Угнежђено                                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa      | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (равни примитивни типови), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                      | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` спојено преко подразумеваног `{ text: true, highlights: true }` |
| Tavily   | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                      |

Генеричка поља увек имају предност: `query`, `max_results`, `filters` (домени), `country` и
тема изведена из `search_type`. За Exa, `search_type: "news"` задржава `category: "news"`.
Tavily такође прихвата `search_type: "finance"` (`topic: "finance"`).

Генеричко поље `time_range` сада стиже до оба добављача: Exa добија `startPublishedDate` (ISO
временску ознаку), а Tavily добија `start_date` (`YYYY-MM-DD`). Експлицитни датум у `provider_options`
има предност над мапираним датумом.

Exa резултати задржавају `id`, `highlight_scores`, `summary`, `subpages`, `entities` и `extras` у
`provider_raw`. Tavily резултати задржавају `images` и `favicon`.

Обрачун трошкова и даље користи раван регистар `costPerQuery`. Tavily наплаћује
`search_depth: "advanced"` са више кредита по позиву, а та разлика није приказана у
`usage.search_cost_usd`.

## API за веб преузимање

Издваја садржај са URL адресе преко конфигурисаног добављача за веб преузимање (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, исти API кључ као за Parallel Search) враћа искључиво Markdown
— било који други `format` доводи до одговора `400` — и ограничава садржај на 100.000 знакова. Када
сама циљна страница не може да се издвоји, узводни сервис то пријављује унутар HTTP 200 одговора;
OmniRoute то приказује као `422` са фиксном поруком.

| Метод | Путања          | Опис                                                              |
| ----- | --------------- | ----------------------------------------------------------------- |
| POST  | `/v1/web/fetch` | Преузима/струже URL — тело се проверава помоћу `v1WebFetchSchema` |

**Аутентификација:** Bearer API кључ (`extractApiKey` + `isValidApiKey`). Политика се примењује преко `enforceApiKeyPolicy`.

**Резервни избор који узима у обзир квоту (#8297):** када није наведен експлицитни `provider`, скуп
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) се
обилази по фиксном
редоследу приоритета (прво попуњавање) — добављач који је конфигурисан, али му је ограничена брзина, прескаче се
уместо да одмах прекине захтев, а поновљива грешка узводног сервиса или грешка квоте
(HTTP 429 увек; 402/403 за бесплатне нивое Firecrawl/Tavily/TinyFish са ограничењима квоте —
не за Jina Reader и никада за обичан 400 лош захтев) током захтева прелази на
следећег неиспробаног добављача са подешеним акредитивима. Када су сви добављачи у
скупу исцрпљени, крајња тачка враћа један `429` (са заглављем `Retry-After`)
уместо претходног генеричког `400`. Када се затражи експлицитни `provider`,
**нема** неприметног резервног избора — експлицитни добављач са ограниченом брзином или грешком
приказује сопствену грешку (`429` ако је брзина ограничена, иначе статус
узводног сервиса).

## WebSocket стримовање

```bash
GET /v1/ws?handshake=1
```

Проверава WebSocket руковање за надоградњу везе и враћа примере порука жичаног протокола (`request`, `cancel`). Стварним WS оквирима управља укључени WS сервер изван табеле рута Next.js-а.

**Аутентификација:** Bearer API кључ током руковања.

### Responses API преко WebSocket-а (само codex)

```bash
# Исти хост и порт као HTTP API (подразумевано 20128); надоградите везу:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (или: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Први оквир МОРА бити response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Прокси за Responses API преко WebSocket-а повезан је **искључиво са `codex`** (ChatGPT
позадинским системом). Ослушкује на истом порту као API/контролна табла, на путањама `/v1/responses`,
`/responses` и `/api/v1/responses`. При првом `response.create` оквиру обавља
аутентификацију и припрему преко интерног `codex-responses-ws` моста, бира
codex OAuth везу и тунелује ка `wss://chatgpt.com/backend-api/codex/responses`
преко `wreq-js` транспорта. **Модели који нису codex се одбијају** (`codex_ws_provider_required`).
За усмеравање са дељењем квоте користите `model: "qtSd/<group>/codex/<model>"`. Имплементирано у
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Аутентификација:** Bearer API кључ током руковања. Укључени HTTP сервер (`server-ws.mjs`)
мора бити активна улазна тачка (што подразумевано јесте када постоји `app/server-ws.mjs`).

#### ID модела: користите основни ChatGPT ID (без префикса `codex/`)

OpenAI **Codex CLI** проверава назив модела на клијентској страни када је
`supports_websockets = true` и **одбија ID-ове са префиксом добављача**, као што је
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Пошаљите **основни** ID (нпр. `gpt-5.5`). OmniRoute мост је
намењен искључиво за codex, па поново разрешава основни ID као codex модел
(`resolveCodexWsModelInfo`) пре тунеловања ка узводном сервису — иако би се основни
`gpt-5.5` иначе преко HTTP-а усмерио ка другом добављачу.

#### Конфигурисање OpenAI Codex CLI-ја

Усмерите Codex CLI ка OmniRoute-у додавањем прилагођеног добављача са WebSocket
подршком у `~/.codex/config.toml` (користите засебан `CODEX_HOME` да не бисте мењали
постојећу конфигурацију):

```toml
model = "gpt-5.5"                 # основни ID — НЕ "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # без завршне косе црте; WS URL се изводи из ове вредности (у продукцији користите https/wss)
wire_api = "responses"                    # једина подржана вредност од фебруара 2026.
supports_websockets = true                # омогућава Responses-over-WS транспорт
env_key = "OMNIROUTE_API_KEY"             # садржи OmniRoute API кључ (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API кључ (било који кључ ако је REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI надограђује `base_url + /responses` у WebSocket везу, а OmniRoute је тунелује
ка изабраној codex OAuth вези. Потврђено од почетка до краја на локалном
серверу: ChatGPT враћа `codex.rate_limits` + `response.created` и стримује
довршавање.

## Самоуслужни преглед коришћења (`/api/usage/om-usage`)

Било који API кључ може да чита **сопствену** потрошњу и квоте — без управљачке аутентификације. Ово је крајња тачка коју
клијент (CLI, OmniCopilot панел) користи да би власнику кључа приказао његову потрошњу.

```bash
# Текстуални облик (историјски уговор — обичан текст за терминал)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Структурирани облик — оно што кориснички интерфејс користи
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Кључ мора да има омогућену опцију **`allowUsageCommand`** (подразумевано је искључена — менаџер API кључева на
контролној табли је укључује или искључује за сваки кључ). Без ње, крајња тачка одговара статусом `403`.

`?format=json` враћа дискриминисани облик, тако да позивалац никада не чита поље са подацима из
одговора којим је захтев одбијен. У случају успеха:

```jsonc
{
  "allowed": true,
  // присутно само када је за кључ укључено ограничење потрошње по кључу (дневно/недељно у USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // снимак квоте изабраног добављача или null ако још ништа није кеширано:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // снимак сваке везе, тако да кориснички интерфејс може да прикаже више добављача једног поред другог:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

При одбијању (`401` неисправан кључ / `403` није дозвољено), иста рута враћа
`{ "allowed": false, "error": { "message": "…" } }` — присутан, али празан `personal`/`provider`
(кључ је дозвољен, али још нема прикупљених података) представља стање различито од одбијања, а само JSON облик
прави разлику између њих.

**Аутентификација:** позиваочев сопствени Bearer API кључ, проверен помоћу `isValidApiKey` — ово _није_
управљачки интерфејс (`/api/keys/…`), који остаје заштићен помоћу `requireManagementAuth`.

### Необрађени проценти квоте наспрам процената прилагођених прагу прекида

При коришћењу `/api/usage/om-usage`, позиваоци треба да имају у виду разлику између
процената приказаних у **обично текстуалном излазу** и структурираном **JSON излазу**:

| Аспект              | Обично текстуални формат (`/api/usage/om-usage` / `@@om-usage`)                                      | JSON формат (`?format=json`)                                                                |
| :------------------ | :--------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------ |
| **Излазно поље**    | `NN% left` (нпр. `20% left`)                                                                         | `provider.quotas` / `providers[].quotas`                                                    |
| **Мерење**          | **Употребљива количина прилагођена прагу прекида**: преостали капацитет изнад прага прекида          | **Необрађена узводна квота**: неприлагођено мерење добављача                                |
| **Скалирање прага** | Скалирано помоћу `effectiveRemainingPercent()`, тако да се заштићена резерва приказује као `0% left` | Нема га (необрађене вредности снимка које је пријавио добављач)                             |
| **Подаци о прагу**  | Урачунати у приказани проценат                                                                       | Чувају се у `quotaWindowThresholds` за сваку везу (или као подразумеване вредности сервера) |
| **Главни корисник** | Интерактивни CLI алати, терминалски упити, људски оператери                                          | Програмске интеграције, контролне табле, аналитика, праћење наплате                         |

#### Формула за прилагођавање прагу прекида

OmniRoute подржава проактивне прагове прекида квоте ради спречавања исцрпљивања узводних ресурса (конфигурише се путем
`quotaWindowThresholds` везе, подразумеваних вредности добављача или глобалних подешавања отпорности). Када је праг прекида
(нпр. `cutoff = 25%`) активан за прозор квоте, текстуални приказ израчунава преосталу количину на следећи начин:

- Ако је `remaining <= cutoff`: враћа `0%`.
- Ако је `remaining > cutoff`: враћа `((remaining - cutoff) / (100 - cutoff)) * 100`.

Форматирани текстуални излаз заокружује ову вредност на најближи цео број (`Math.round(...)`).

#### Илустративни пример

Размотримо прозор добављача са **60% необрађене потрошње** (дакле, **40% необрађене преостале квоте**) и конфигурисаним
прагом прекида од **25% преостале квоте**:

| Приказ                               | Израчунавање                                       | Преостало |           Подразумевано искоришћено           |
| :----------------------------------- | :------------------------------------------------- | :-------: | :-------------------------------------------: |
| **Необрађени JSON (`?format=json`)** | Узводни снимак (`quotas[window]`)                  |  **40%**  |                    **60%**                    |
| **Текстуални формат (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**  | **80%** (ако се израчунава `100 - remaining`) |

- **Зашто текст приказује 20% преосталог капацитета:** Од 40% физичке квоте преостале на налогу, 25% је резервисано
  политиком прага прекида. Позиваоцу је преостало само 15% од 75% употребљивог расположивог капацитета пре него што рутер
  престане да усмерава захтеве ка овој вези. Скалирање осигурава да веза сигнализира исцрпљеност (`0% left`) тачно када
  усмеравање престане.
- **Зашто JSON задржава необрађене вредности:** JSON корисни садржај враћа тачан снимак добављача (`UsageSnapshot`),
  тако да спољни алати имају приступ стварном узводном искоришћењу и вредностима
  `quotaWindowThresholds` на нивоу везе, без губитака услед скалирања на страни сервера.

#### Смернице за миграцију корисника

Ако је спољна интеграција (као што је додатак за уређивач или проширење агента) раније издвајала податке са текстуалне
крајње тачке (`NN% left`) и израчунавала искоришћени проценат као `100 - NN`, прелазак на `?format=json` значи:

- Читање необрађених JSON вредности одражаваће **стварну потрошњу из изворног система** (60% искоришћено у горенаведеном примеру).
- Ако интеграција жели да задржи семантику расположиве квоте текстуалне крајње тачке, може на страни клијента
  израчунати формулу ефективно преостале квоте користећи `quotaWindowThresholds` за замене на нивоу везе.

## Semantički keš

```bash
# Preuzimanje statistike keša
GET /api/cache/stats

# Brisanje svih keševa
DELETE /api/cache/stats
```

Primer odgovora:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Uticaj na kašnjenje

Pogodak u semantičkom kešu isporučuje odgovor iz keša **bez poziva uzvodnog
servisa**, pa je prijavljena vrednost `X-OmniRoute-Response-Latency` približno nula
(bez obzira na prvobitno kašnjenje uzvodnog servisa). Klijenti osetljivi na kašnjenje
(benčmarking, p50/p99 nadzor) treba da provere zaglavlje odgovora
`X-OmniRoute-Cache-Latency`:

| Vrednost    | Značenje                                                                    |
| ----------- | --------------------------------------------------------------------------- |
| `synthetic` | Odgovor je isporučen iz keša; kašnjenje nije stvarno vreme uzvodnog servisa |
| _(odsutno)_ | Odgovor iz stvarnog poziva uzvodnog servisa                                 |

### Zaobilaženje keša po ključu

API ključevi mogu da isključe čitanje iz semantičkog keša pomoću `cacheDefaultMode`:

| Vrednost | Ponašanje                                                  |
| -------- | ---------------------------------------------------------- |
| `legacy` | Uobičajeno ponašanje keša (podrazumevano)                  |
| `bypass` | Potpuno preskoči pretragu keša; uvek poziva uzvodni servis |

Podesite pri kreiranju ključa (`POST /api/keys`) ili ažuriranju (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Zaobilaženje po zahtevu

Svaki zahtev može da zaobiđe keš bez obzira na podešavanja ključa:

```
X-OmniRoute-No-Cache: true
```

За синхронизоване/увезене моделе, `PUT /api/provider-models` прихвата `provider`, `modelId` и
`maxOutputTokenOverride`: позитиван цео број поставља ручно ограничење излазних токена, док га `null`
уклања ради враћања подразумеване вредности. `GET /api/provider-models?provider=<provider>` враћа ове
вредности у `modelOutputOverrides`, укључујући моделе без реда прилагођеног модела. Замена користи
могућност `max_output_tokens` током извршавања и опстаје након поновне синхронизације модела. Страница
провајдера компатибилног са OpenAI-јем нуди исте контроле за измену/уклањање и означава моделе са
изричитом подршком за вид.

Прилагођени Chat Completions чворови прилагођавају изричито искључивање закључивања узводном
позадинском систему. Успешан тест везе аутоматски бира контроле шаблона ћаскања за сваки тачан ID
модела чији унос `/models` доказује препознату вредност `owned_by`: `vllm`, `sglang` или `llamacpp`.
Транспарентни омотачи компатибилни са OpenAI-јем могу да сачувају оригинални унос модела унутар
угнежђеног објекта `openai`; откривање прати до три таква омотача. Модели са недостајућим, непознатим
или неусаглашеним власништвом задржавају уобичајено OpenAI понашање. Откривање поново користи постојећи
захтев каталогу, не генерише токене довршавања и поништава се када се приступна тачка везе промени.

Да бисте фиксирали понашање за позадински систем који не излаже те метаподатке, користите постојећи
API за делимично ажурирање провајдера:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Пошаљите то тело помоћу `PUT /api/providers/<connection-id>`. На тој вези, изричити напор
закључивања од `none` шаље се као `chat_template_kwargs.thinking=false` и
`chat_template_kwargs.enable_thinking=false`. Изричите изворне вредности шаблона остају меродавне,
осим ако правило закључивања на страни сервера не наметне ниво напора. Подешавање се примењује само
када прилагођена веза компатибилна са OpenAI-јем прослеђује тело Chat Completions захтева; Responses
захтеви и обични провајдери задржавају свој изворни облик захтева. Подесите `reasoningControl` на
`openai` да бисте наметнули уобичајено OpenAI прослеђивање параметра `reasoning_effort`, или га
изоставите/подесите на `null` да бисте користили аутоматско откривање.

Захтеви класификатора у аутоматском режиму Claude Code-а подразумевано постављају изворно
размишљање као онемогућено када не садрже изричите контроле закључивања. Откривање користи системску
ознаку класификатора у захтевима Claude формата, а не називе модела или ограничења довршавања.
Изричите контроле тела, подржана заглавља за напор/размишљање, правила усмеравања и разрешени напор
модела задржавају свој постојећи приоритет. Обе фазе класификатора задржавају своје упите, ограничења
довршавања, секвенце заустављања и стварне одлуке узводног система о дозволама; друга фаза и даље
може да произведе захтевано видљиво закључивање као обичан текст.

### Верзија и канал издања

```bash
GET /api/system/version
```

Управљачка рута доступна само преко loopback интерфејса (администраторска аутентификација). Враћа активну верзију, најновију
објављену верзију и статус аутоматског ажурирања. `releaseChannel` и `channels` су додатна
поља (грана 3.8.54); `channel` задржава своје значење — режим примене који програм за ажурирање контролне табле
користи (`npm`, `source` или `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm канал активне верзије: `nightly` за верзије `-nightly.*`,
  `next` за остала претходна издања (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` за стабилну верзију
  старије главне верзије од `channels.latest`, а у супротном `latest`. Иста правила као у
  `scripts/release/dist-tag.mjs`, који бира npm dist-tag у тренутку објављивања.
- `channels` — најновија објављена верзија сваког dist-tag-а, добијена помоћу `npm view omniroute dist-tags` (уз резервни
  приступ преко HTTP-а регистру), кеширана са истим TTL-ом од 10 минута као `latest`. `latest` је увек присутан
  (резервно користи поље `latest`, а затим `"unavailable"`); `next`, `nightly` и `lts` се појављују
  само када одговарајући dist-tag постоји. Захтев са `Cache-Control: no-cache` освежава обе претраге.

Модел канала (`latest` = v3 до општег издања верзије 4.0, `next` = rc, `nightly` = верзије са гране `develop`,
`lts` = исправке за v3 након општег издања верзије 4.0) описан је у `docs/ops/RELEASE_STRATEGY.md`.

## Алијаси са токеном за VS Code / без заглавља

Користите ове алијасе када интеграција не може да дода заглавље `Authorization` и захтева да API кључ буде уграђен у основни URL.

```bash
# Алијас каталога у OpenAI стилу
GET /api/v1/vscode/{token}/
GET /api/v1/vscode/{token}/models

# Алијаси за ћаскање у OpenAI стилу
POST /api/v1/vscode/{token}/chat/completions
POST /api/v1/vscode/{token}/responses

# Алијаси у Ollama стилу
POST /api/v1/vscode/{token}/api/chat
GET /api/v1/vscode/{token}/api/tags
```

Пример:

```bash
curl https://your-host.example/api/v1/vscode/YOUR_API_KEY/models
curl -X POST https://your-host.example/api/v1/vscode/YOUR_API_KEY/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"hello"}]}'
```

Напомене:

- Алијаси са токеном поново користе исте обрађиваче као `/v1/*` и `/api/tags`; структуре одговора остају идентичне.
- Кад год клијент подржава прилагођена заглавља, дајте предност заглављу `Authorization: Bearer ...`.
- Токени засновани на URL-у могу да се појаве у евиденцијама обрнутог проксија, историји прегледача и телеметрији изван OmniRoute-а. Третирајте их као опцију за компатибилност, а не као подразумевани начин аутентификације.

## Ограничења токена

Буџети **токена** по API кључу (разликују се од горенаведеног буџета заснованог на USD). Примењују се непосредно у путањи обраде захтева: када потрошња кључа у тренутном периоду достигне ограничење, захтеви се одбијају са `429 Too Many Requests`. Ограничења могу бити везана за одређени `model`, `provider` или примењена глобално на цео кључ помоћу опсега `global`; када се на захтев односи више ограничења, примењује се најрестриктивније.

```bash
# Прикажите ограничења токена за кључ (укључује тренутну потрошњу у периоду)
GET /api/usage/token-limits?apiKeyId=key-123

# Направите или ажурирајте ограничење токена
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Избришите ограничење токена према идентификатору
DELETE /api/usage/token-limits?id=tl-abc
```

> **Напомене о шеми** (`setTokenLimitSchema`): `apiKeyId` и `scopeType` (`model` | `provider` | `global`) су обавезни. `scopeValue` је обавезан осим ако је `scopeType` постављен на `global` (нпр. ID модела за опсег `model`, односно ID добављача за опсег `provider`). `tokenLimit` мора бити позитиван цео број (конвертује се из ниске). Опционо: `id` (изоставите га за креирање, наведите га за ажурирање), `resetInterval` (`daily` | `weekly` | `monthly`, подразумевано `monthly`), `resetTime` (`HH:MM`), `enabled` (подразумевано `true`). Одговори на `GET` обогаћују свако ограничење пољима `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` и `nextResetAt`. Ово је крајња тачка управљачке класе (аутентификација се примењује централно путем процеса ауторизације).

## Обрада захтева

1. Клијент шаље захтев на `/v1/*`
2. Обрађивач руте позива `handleChat`, `handleEmbedding`, `handleAudioTranscription` или `handleImageGeneration`
3. Модел се разрешава (директни добављач/модел или псеудоним/комбинација)
4. Акредитиви се бирају из локалне базе података уз филтрирање према доступности налога
5. За ћаскање: `handleChatCore` проверава семантички кеш/кеш потписа и разрешава подешавања компресије комбинације
6. Проактивна компресија се извршава пре превођења за добављача када је омогућена (`lite`, Caveman, RTK или наслагана)
7. Извршилац добављача шаље узводни захтев
8. Одговор се преводи назад у формат клијента (ћаскање) или се враћа непромењен (угнежђивања/слике/звук)
9. Бележе се потрошња, аналитика компресије и евиденције захтева
10. Резервна опција се примењује у случају грешака у складу са правилима комбинације

Потпуна референца архитектуре: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Отпорност (проширено)

OmniRoute пружа три независна механизма за привремене отказе; управљачке крајње тачке у наставку омогућавају оператерима да очитају и измене њихова стања:

| Опсег              | Складиште стања                        | Очитавање                                 | Ресетовање / брисање                                                      |
| ------------------ | -------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------- |
| Прекидач добављача | `domain_circuit_breakers` + у меморији | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                              |
| Период чекања везе | `rateLimitedUntil` на везама добављача | `/api/rate-limits`, `/api/providers/[id]` | (поново се омогућава по потреби; брише се путем PUT захтева за добављача) |
| Закључавање модела | Регистар доступности модела у меморији | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                  |

`PATCH /api/resilience` прихвата измене прекидача добављача у оквиру `providerBreaker.oauth` и `providerBreaker.apikey`. Сваки профил подржава `degradationThreshold`, `failureThreshold` и `resetTimeoutMs`; иста поља су доступна у Контролна табла → Подешавања → Отпорност.

```bash
# Обришите закључавање једног модела
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Обришите сва закључавања
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

За потпуну концептуалну референцу и подразумеване вредности прекидача погледајте [`CLAUDE.md`](../../CLAUDE.md) → „Стање извршавања отпорности“ и [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Ред за ограничење брзине и заштитни механизам аутоматског омогућавања

- **Подржана путања за упис**: `POST /api/rate-limits` са телом `{"connectionId": "<id>", "enabled": true|false}` представља подржану управљачку крајњу тачку за укључивање или искључивање заштите од ограничења брзине за везу. `PUT /api/providers/[id]` намерно не мења нити пребацује `rateLimitProtection` (#11278).
- **Семантика вредности `enabled: false`**: Постављање `enabled: false` уклања изричиту заштиту за везу, али **не** изузима активну везу са API кључем из глобалног заштитног механизма аутоматског омогућавања (`autoEnableApiKeyProviders = true`). У `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` и `undefined` су еквивалентни; активне везе са API кључем без изричите заштите остају заштићене глобалним механизмом аутоматског омогућавања.
- **Глобално онемогућавање**: Да бисте користили везе са API кључем без редова за ограничење брзине, глобално онемогућите заштитни механизам путем `RATE_LIMIT_AUTO_ENABLE=false` (променљива окружења) или `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Подешавања → Отпорност / `PATCH /api/resilience`).

## MCP сервер

OmniRoute испоручује уграђени Model Context Protocol сервер са 3 транспорта (stdio, SSE, streamable-http) и алатима ограниченог опсега. Крајње тачке контролне табле у наставку читају податке о статусу/ревизији и посреднички прослеђују HTTP транспорте.

| Метод | Путања | Опис |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Сигнал активности, транспорт, стање везе, последњи позив, најкоришћенији алати, стопа успеха током 24 h |
| GET | `/api/mcp/tools` | Листа MCP алата са `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Отвара SSE ток за SSE транспорт (враћа `503` ако је MCP онемогућен или се транспорт не подудара) |
| POST | `/api/mcp/sse` | Шаље JSON-RPC оквир преко SSE транспорта |
| GET | `/api/mcp/stream` | Отвара SSE страну Streamable HTTP транспорта (поруке које иницира сервер) |
| POST | `/api/mcp/stream` | Шаље JSON-RPC оквир преко Streamable HTTP транспорта |
| DELETE | `/api/mcp/stream` | Завршава Streamable HTTP сесију |
| GET | `/api/mcp/audit` | Претражује евиденцију ревизије — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Збирна статистика ревизије (укупни бројеви, стопа успеха, просечно трајање, најкоришћенији алати) |

**Аутентификација:** `sse`/`stream` транспорти поштују MCP-специфичан механизам аутентификације (Bearer API кључ са опсегом `mcp`); руте `status`/`tools`/`audit*` могу се читати са контролне табле (није потребна додатна аутентификација осим приступа хосту контролне табле).

> Оба HTTP транспорта су условљена подешавањима `settings.mcpEnabled` и `settings.mcpTransport` — неподударање транспорта враћа `400`, а онемогућено MCP стање враћа `503`.

## A2A сервер

OmniRoute пружа A2A (Agent-to-Agent) JSON-RPC 2.0 крајњу тачку, као и REST омотач за потребе прегледа и контролне табле.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # опционално, осим ако је OMNIROUTE_API_KEY подешен
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Усмери овај програмерски задатак"}]
  }
}
```

Подржани методи (сви зависе од `settings.a2aEnabled`):

| Метод            | Опис                                                             |
| ---------------- | ---------------------------------------------------------------- |
| `message/send`   | Синхроно извршавање вештине; враћа `{task, artifacts, metadata}` |
| `message/stream` | SSE стриминг извршавања истог скупа вештина                      |
| `tasks/get`      | Добавља задатак према `taskId`                                   |
| `tasks/cancel`   | Отказује задатак према `taskId`                                  |

Уграђене вештине: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Картица агента

```bash
GET /.well-known/agent.json
```

Враћа јавну A2A картицу агента (назив, опис, могућности, каталог вештина, шема аутентификације) — јавно се кешира 1 сат. Аутентификација није потребна.

### REST помоћне крајње тачке

| Метод | Путања                       | Опис                                                                                                                |
| ----- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/a2a/status`            | Статус омогућености A2A-а + статистика задатака + сажетак кеширане картице агента                                   |
| GET   | `/api/a2a/tasks`             | Листа задатака — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST  | `/api/a2a/tasks`             | (Није имплементирано као REST помоћна крајња тачка — креирајте преко JSON-RPC метода `message/send`)                |
| GET   | `/api/a2a/tasks/[id]`        | Преузима један задатак                                                                                              |
| POST  | `/api/a2a/tasks/[id]/cancel` | Отказује задатак                                                                                                    |

**Аутентификација:** REST помоћне крајње тачке раде без управљачке аутентификације (контролна табла може да их чита); JSON-RPC рута `/a2a` користи Bearer `OMNIROUTE_API_KEY` ако је конфигурисан.

## Аутентификација

Погледајте [Аутентификацију за управљање](../guides/MANAGEMENT-AUTH.md) за четири
породице акредитива (сесија контролне табле, локални CLI токен, `oma_live_…` приступни
токен, API кључ са опсегом за управљање) и објашњење по чему се разликују од кључева за инференцију.

- Руте контролне табле (`/dashboard/*`) користе `auth_token` колачић
- Пријављивање користи сачувани хеш лозинке; резервна вредност је `INITIAL_PASSWORD`
- `requireLogin` се може укључити или искључити путем `/api/settings/require-login`
- Руте `/v1/*` опционо захтевају Bearer API кључ када је `REQUIRE_API_KEY=true`
- „токен за управљање“ / „API кључ са опсегом за управљање“ у овој референци означава једну од породица из тог водича — а не неку недефинисану додатну врсту тајне

> **Неускладива промена (v3.8.0)** — `/api/v1/agents/tasks/*` и крајње тачке за управљање периодом мировања сада захтевају **аутентификацију за управљање** (`auth_token` колачић контролне табле или API кључ са опсегом за управљање). Клијенти који су претходно позивали ове руте без аутентификације добиће `401 Unauthorized`. Погледајте комит `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
