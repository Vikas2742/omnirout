## Ukamilishaji wa Gumzo

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

#### Kufunga akaunti kwa kila ombi

Mtoa huduma anapokuwa na miunganisho kadhaa (akaunti au funguo), kwa kawaida OmniRoute huchagua mmoja
kupitia mkakati wake wa kuchagua akaunti. Badala yake, ombi linaweza kufungwa kwa muunganisho mmoja mahususi
kwa kutumia kichwa cha `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Mahali pa kupata kitambulisho.** Fungua ukurasa wa mtoa huduma kwenye dashibodi
  (**Dashibodi → Watoa huduma → <mtoa huduma>**) na ubofye chipu ya kitambulisho cha `xxxxxxxx…` kwenye safu ya muunganisho
  — hatua hiyo hunakili kitambulisho kamili cha muunganisho.
- **Maombi yanayokiheshimu.** Maombi ya modeli moja (`provider/model`) kwenye
  `/v1/chat/completions`, `/v1/messages` na `/v1/responses`. Michanganyiko hupuuza kichwa hiki: funga
  akaunti kwa kila hatua ya mchanganyiko kupitia muunganisho wa hatua hiyo badala yake.
- **Ufungaji ni wa lazima, si mapendeleo.** Muunganisho uliofungwa hutumiwa peke yake. Hitilafu
  ndani ya ombi hurekodi kipindi cha kusubiri cha akaunti lakini **haihamii** kwenye akaunti nyingine
  ya mtoa huduma huyo.
- **Kipindi cha kusubiri na kiwango huondoa ufungaji.** Wakati muunganisho uliofungwa uko kwenye kipindi cha kusubiri,
  umeishiwa kiwango au umezuiwa na sera ya kiwango, maombi yanayofuata hutumia miunganisho mingine ya mtoa huduma,
  sawa kabisa na trafiki isiyofungwa.
- **Vitambulisho visivyojulikana au vilivyozimwa husababisha hitilafu.** Kitambulisho ambacho hakipo kwenye kundi amilifu la mtoa huduma (kilichofutwa,
  kilichozimwa, au kinachomilikiwa na mtoa huduma mwingine) hakiachi akaunti yoyote inayostahiki, kwa hivyo ombi
  hushindwa badala ya kuelekezwa kwingine bila taarifa.

Claude Code hutuma vichwa maalum kupitia `ANTHROPIC_CUSTOM_HEADERS`. Kiweke kwenye sehemu ya `env`
ya `~/.claude/settings.json`, au kwenye `.claude/settings.json` ya kiwango cha mradi ili kufunga akaunti tofauti
kwa kila mradi:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Chanzo: `src/sse/handlers/chat.ts` (usomaji wa kichwa), `src/sse/services/auth.ts` na
`src/sse/services/sessionAffinityPin.ts` (uondoaji wa ufungaji na ukaguzi wa kutokuwepo kwenye kundi).

> **Vichwa vya telemetria ya gharama:** majibu yaliyofaulu yasiyo ya utiririshaji pia hubeba mkusanyiko wa telemetria ya gharama wa `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, desimali 10 zisizobadilika; `0.0000000000` kwa huduma isiyolipishwa/isiyo na bei), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, na `X-OmniRoute-Fallback-Attempts` (wakati tu > 0), pamoja na `X-OmniRoute-Request-Id` na `X-OmniRoute-Version`. Hivi hutolewa na ukamilishaji wa gumzo, `/v1/responses`, `/v1/messages`, **na sehemu za mwisho za midia** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, na `/v1/moderations` (gharama daima ni `0`). Gharama ya midia huhesabiwa kwa kila aina ya modi (kwa kila picha, kwa kila sekunde, kwa kila herufi, kwa kila kipimo cha utafutaji) wakati bei inapatikana; vinginevyo ni `0` (huruhusu ombi kuendelea hata ukokotoaji ukishindwa).

> **Maana ya gharama ya kupatikana kwenye akiba:** kwenye HIT ya akiba ya kisemantiki (`X-OmniRoute-Cache-Hit: true`) hakuna ombi linalotumwa kwa huduma ya juu, kwa hivyo `X-OmniRoute-Response-Cost` ni `0.0000000000` (gharama **ya nyongeza** ya kutoa jibu lililopatikana kwenye akiba). Gharama ya awali/ambayo ingetokea huripotiwa kando katika `X-OmniRoute-Cost-Saved`. Watumiaji wa data ya utozaji wanapaswa kujumlisha `X-OmniRoute-Response-Cost` (majibu yaliyopatikana kwenye akiba hayana gharama); uchanganuzi wa akiba unaweza kujumlisha `X-OmniRoute-Cost-Saved`.

## Ukodishaji wa Kipekee wa Vipindi Vinavyodhibitiwa

Ukodishaji wa kipekee wa vipindi vinavyodhibitiwa ni mkataba wa hiari wa uelekezaji usiofungamana na mteja: mmiliki mmoja amilifu
anashikilia muunganisho mmoja unaostahiki wa OmniRoute. Haukodishi modeli, hauhitaji OAuth, hautambui
mteja mahususi, wala hauhitaji mtoa huduma mahususi.

Ufunguo wa API unaotumika kuthibitisha lazima uwe na upeo `lease:exclusive` na orodha dhahiri isiyo tupu ya
`allowedConnections`. Mpaka wa mabadiliko ya hifadhidata hulazimisha sehemu zote mbili kuwepo pamoja wakati wa
kuunda ufunguo na kufanya masasisho ya sehemu.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Majibu yaliyofaulu ya kupata, kusasisha na kuachilia huonyesha mihuri ya muda, `state`, na thamani chanya halisi ya
`generation`, lakini kamwe hayaonyeshi muunganisho uliochaguliwa au vitambulisho vya ufikiaji. Kusasisha na kuachilia huwasilisha
generation katika mwili wa JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Mmiliki wa ukodishaji amilifu anaweza kuomba wazi metadata salama kwa faragha ya kuonyesha kwa uunganishaji wake wa sasa:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Kitendo hiki cha hiari cha kuangalia hali hulindwa na mmiliki fiche, ufunguo wa API unaodhibitiwa na uliothibitishwa, pamoja na
generation halisi iliyo amilifu ndani ya muamala mmoja wa hifadhidata. `displayName` ni jina la muunganisho lililosanidiwa
ambalo nafasi zake za pembeni zimeondolewa pekee; huwa `null` ikiwa hakuna jina salama lililosanidiwa. OmniRoute kamwe haibadilishi hili kwa
barua pepe au utambulisho wa akaunti uliozalishwa. Thamani ya mtoa huduma ni lebo isiyo nyeti ya kuonyesha na kamwe si
kitambulisho kilichozalishwa cha mtoa huduma patanifu. Vitambulisho vya ufikiaji, tokeni, vidakuzi, vitambulisho ghafi vya muunganisho au
ufunguo wa API, hashi za mmiliki, siri za uzuiaji, na data ya ndani ya uelekezaji hazijumuishwi.

Utafutaji unaotumia ufunguo usio sahihi, mmiliki asiye sahihi, generation iliyopitwa na wakati, thamani inayokosekana, iliyokwisha muda, iliyoachiliwa, au iliyobatilishwa, wote
hurejesha hitilafu ileile ya `409 LEASE_FENCE_STALE` bila metadata ya muunganisho. Mteja aliyepokea jibu la kusubiri nafasi hana uunganishaji amilifu wa kukagua. Wakati uelekezaji unapohamisha ukodishaji amilifu,
generation ileile hubaki halali na hali hurejesha kwa utendajimoja uunganishaji mpya, kamwe si ule wa zamani.
Wateja waliopo hubaki bila kubadilishwa kwa sababu majibu ya kupata, kusasisha, kuachilia na kusubiri huhifadhi
miundo yao ya awali.

Mkataba huu wa seva haubadilishi `/status` ya kawaida ya OpenAI Codex. Kwa sasa, Codex ya kawaida huripoti
mtoa huduma wa modeli yake na hali iliyojengewa ndani ya uthibitishaji/akaunti lakini haionyeshi metadata holela ya
akaunti ya mtoa huduma maalum; ujumuishaji wa mteja wa baadaye lazima uite kitendo hiki na uamue jinsi ya
kuonyesha `connection.displayName`.

Kisha kila ombi la inferensi linalodhibitiwa huwasilisha vichwa vyote viwili vya udhibiti:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Mmiliki halisi, generation, muunganisho amilifu, na ufunguo wa API uliothibitishwa huzuiwa mara moja
kabla ya kila jaribio linalotumika la huduma ya juu. Kutumia tena mmiliki na generation kwa ufunguo mwingine hushindwa hata
ikiwa ufunguo huo unaruhusu muunganisho huohuo. Wamiliki ghafi hawahifadhiwi, hawaandikwi kwenye kumbukumbu, hawabakizwi katika
picha tuli ya ombi, wala hawatumwi kwa huduma ya juu.

Mgongano wa muda hurejesha HTTP `429` pamoja na `Retry-After` na:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Jibu hili linamaanisha tu kwamba seti ya kawaida inayostahiki haikuwa tupu na kila chaguo huru lilikuwa
linashikiliwa na ukodishaji amilifu wa mhusika mwingine. Modeli/watoa huduma wasiotumika, kutolingana kwa sera, kipindi cha kusubiri, kikomo,
afya, na hitilafu nyingine za kawaida za ustahiki huhifadhi majibu yao yaliyopo ya OmniRoute.

### `x-omniroute-compression`

Ubatilishaji wa mpango wa ubanaji kwa kila ombi. Una kipaumbele cha juu zaidi — unashinda ubatilishaji wa mchanganyiko wa uelekezaji,
wasifu amilifu, kichochezi otomatiki, na Chaguo-msingi la paneli. Thamani:

| Thamani       | Athari                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| `off`         | Hakuna ubanaji kwa ombi hili.                                                                                      |
| `default`     | Wasifu wa Chaguo-msingi unaotokana na paneli (hupuuza wasifu amilifu). Injini zinazopoteza data huachwa zimezimwa. |
| `safe`        | Uondoaji wa nakala rudufu na ukunjanaji wa nafasi tupu pekee.                                                      |
| `allow-lossy` | Hifadhi mpango wa mwendeshaji kwa ombi hili, ikijumuisha muhtasari na uandikaji upya wa mtindo.                    |
| `engine:<id>` | Injini moja ikiwa imewezeshwa, kwa mfano `engine:rtk`. Uwezeshaji wa hiari wa injini hiyo kwa kila ombi.           |
| `<combo>`     | Mchanganyiko wenye jina, unaolinganishwa kwanza kwa jina (bila kujali ukubwa wa herufi), kisha kwa id.             |

Vidokezo:

- Thamani zisizojulikana hupuuzwa (ombi kamwe halikataliwi); utatuzi huendelea hadi kwenye mpangilio wa kawaida wa vipaumbele vya mwendeshaji.
- Ikiwa michanganyiko mingi ina jina moja, wasilisha **id** ya mchanganyiko ili kupata ulinganishaji thabiti.
- Mchanganyiko ambao jina lake ni `off` au `default` hauwezi kuchaguliwa kwa jina (maneno hayo muhimu hufasiriwa kwanza); rejelea mchanganyiko huo kwa id yake.
- Swichi kuu ya ubanaji ni kizuizi kisichoweza kupitwa: ubanaji unapozimwa kwa ujumla, kichwa hiki hakiwezi kuuwezesha.

Mpango uliotumika hurudishwa katika kichwa cha jibu:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

ambapo `<source>` ni mojawapo ya `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, au `off`.

## Upachikaji

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Watoa huduma wanaopatikana: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Vitambulisho vya katalogi ni `provider/model` (mfano: `jina-ai/jina-embeddings-v5-omni-small`). Vitambulisho vya miundo ya Jina visivyo na kiambishi cha mtoa huduma vinavyoonekana kwenye sajili (kwa mfano `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) pia hutambuliwa. Uwekapachikaji/upangaji upya/uainishaji/ugawaji wa Jina hutumia kwanza vitambulisho vya `jina-ai` vilivyo kwenye dashibodi; `JINA_AI_API_KEY` hutumika kama mbadala ikiwa tu hakuna ufunguo kwenye dashibodi. Kadi ya `jina-reader` ni ya Reader / `r.jina.ai` pekee (`POST /v1/web/fetch`) na kamwe haitoi upachikaji wala upangaji upya.

Miundo ya sajili inayotangaza uwezo wa midia anuwai pia hukubali hadi vipengee 32 vilivyopangwa kwa muundo usiofungamana na mtoa huduma. Aina za vipengee vya midia ni `text`, `image`, `audio`, `video`, na `document`. `source` ya midia hiyo ni ama `{"type":"url","url":"https://..."}` au
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
na lakabu ya familia `jina-ai/jina-embeddings-v5-omni` → omni-small) pia hukubali hati asilia za EmbeddingsV5Request za Jina na **huzituma bila kuzibadilisha** kwenda `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Thamani asilia za `{ image | audio | video | pdf }` zinaweza kuwa URL ya umma ya HTTPS, URI ya `data:`, au base64 ghafi. OmniRoute haibadilishi vipengee hivyo kuwa mifuatano wala kuchota URL asilia za picha — Jina huchota midia ya umma yenyewe. Sehemu za ziada za Jina (`task`, `normalized`, `truncate`, `embedding_type`) hutumwa. SKU za Jina za maandishi pekee bado hukataa hati zisizo za maandishi.

Mipaka ya usalama na usafirishaji:

- URL za midia za mbali lazima ziwe za umma na zitumie HTTPS. Vipengee sanifu vya `{type,source:url}` huchotwa upande wa seva (uthibitishaji upya wa uelekezaji, muda wa kuisha, vikomo vya ukubwa, DNS ya umma, na kufungamanisha muunganisho) na kupachikwa ndani kabla ya ombi kwa mtoa huduma. Vipengee asilia vya Jina vya `{image:"https://..."}` hutumwa jinsi vilivyo baada ya ukaguzi huo huo wa HTTPS ya umma; Jina huchota URL.
- Midia ya base64 iliyopachikwa ina kikomo cha MiB 8 zilizofumbuliwa kwa kila kipengee na MiB 16 zilizofumbuliwa kwa ombi zima.

Ubadilishaji kwa kila mtoa huduma (vipengee sanifu kamwe havitumwi bila kubadilishwa):

- Miundo ya midia anuwai ya Jina: kila kipengee cha kiwango cha juu huwa kitu kimoja chenye ufunguo wa aina ya midia (`text` / `image` / `audio` / `video` / `pdf`), kikitumia URI za data kwa midia iliyopachikwa; vekta moja kwa kila kipengee cha kiwango cha juu.
- Familia ya Gemini Embedding 2: safu moja ya kiwango cha juu huwa ombi moja asilia la `models/{model}:embedContent` lenye `content.parts` (`text` au `inline_data`).
- llama.cpp (`llama-cpp/<model>`, muundo wowote uliopakiwa na seva ya ndani): vipengee sanifu vya `text` huwa mifuatano ya kawaida, na `image` / `audio` / `video` kila kimoja huwa kitu kimoja cha `{"content": [part]}`, kikitumia sehemu za maudhui ya gumzo za llama-server (`image_url`, `input_audio` yenye umbizo la `wav` / `mp3` / `flac`, `input_video`) pamoja na data iliyopachikwa; vekta moja kwa kila kipengee cha kiwango cha juu. Seva lazima iendeshwe kwa `--embedding --mmproj …`; bila projektor, yenyewe hukataa midia. `document` haitumiki.
- Miundo isiyojulikana/ibadilika isiyo na metadata ya wazi ya aina za midia hukataa ingizo lenye muundo kwa HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Mchanganyiko usiotumika wa muundo/aina ya midia hurejesha HTTP 400 badala ya kulazimisha ubadilishaji wa kipengee. Sehemu za viendelezi zisizo za ingizo katika maombi ya zamani ya mifuatano/tokeni zinaendelea kupitishwa bila kubadilishwa.

```bash
# Orodhesha miundo yote ya upachikaji
GET /v1/embeddings
```


### Mtiririko wa ukaguzi wa mara kwa mara wa Azure Document Intelligence

API ya `analyze` ya Azure Document Intelligence si sawia: ombi la awali hurejesha kichwa cha
`Operation-Location` badala ya mwili, na matokeo lazima yakaguliwe mara kwa mara. Kishughulikiaji
(`open-sse/handlers/ocr.ts`) hukagua URL hiyo kila sekunde kwa hadi majaribio 30, hushindwa mara moja (hakiendelei
kukagua) ikiwa jibu la ukaguzi si `ok` au hali ni `"failed"`, na hurejesha `504` ikiwa
operesheni bado inaendelea baada ya bajeti ya majaribio kuisha. Jibu la mwisho la Azure
husawazishwa kuwa muundo uleule wa `pages`/`markdown` unaotumiwa na Mistral kabla ya kurejeshwa kwa
mwombaji, kwa hivyo msimbo wa kiteja hauhitaji kushughulikia mtoa huduma kwa namna maalumu.

### Uthibitishaji na utatuzi wa ncha ya Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` hutumia tena uthibitishaji uleule wa Vertex AI ambao OmniRoute tayari inautumia kwa
trafiki ya gumzo/picha (`open-sse/executors/vertex.ts`): ufunguo wa API wa muunganisho huwa ama
kitambulisho cha JSON cha Akaunti ya Huduma (kinachobadilishwa kuwa tokeni ya ufikiaji ya OAuth ya muda mfupi kupitia mtiririko wa
JWT-bearer) au tokeni ya ufikiaji ya OAuth ambayo tayari imetolewa na hutumiwa jinsi ilivyo. URL ya ncha ya juu ni
ncha ya jumla ya mshirika ya Vertex ya `openapi/chat/completions`, iliyoundwa kutokana na mradi na
eneo la muunganisho — `providerSpecificData.project`/`providerSpecificData.region` iliyobainishwa wazi hupewa kipaumbele kila wakati;
vinginevyo mradi hutolewa kutoka kwa `project_id` ya JSON ya Akaunti ya Huduma na eneo
hutumia `us-central1` kwa chaguo-msingi. Utatuzi wote hufanyika katika `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), na hutumiwa na
`src/app/api/v1/ocr/route.ts` kabla ya kutumwa kwa `handleOcr`.

### Viambishi awali vya ID za modeli (`?prefix=`)

Modeli nyingi hutangazwa chini ya **kiambishi awali cha mtoa huduma**. Kiambishi awali unachopata hudhibitiwa na
alama ya kipengele ya `MODELS_CATALOG_PREFIX_MODE`, na kinaweza kubatilishwa **kwa kila ombi** kwa kutumia
kigezo cha hoja — jambo linalofaa kwa mteja anayetaka orodha safi bila kubadilisha mpangilio wa seva nzima
kwa watumiaji wengine wote:

```bash
GET /v1/models?prefix=alias        # ID moja kwa kila modeli — kiambishi awali kifupi cha lakabu
GET /v1/models?prefix=dual         # miundo yote miwili (chaguo-msingi la seva)
GET /v1/models?prefix=canonical    # kiambishi awali kamili cha ID ya mtoa huduma pekee
```

| Hali        | Hutoa                                                    | Vidokezo                                                                                                                                                                                                                 |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dual`      | `cc/claude-sonnet-4-6` **na** `claude/claude-sonnet-4-6` | **Chaguo-msingi.** ID zote mbili huelekezwa kwenye modeli ileile; zimehifadhiwa ili usanidi wa wateja ulioweka mojawapo ya miundo moja kwa moja uendelee kufanya kazi. Takribani huongeza ukubwa wa katalogi mara mbili. |
| `alias`     | `cc/claude-sonnet-4-6`                                   | Ingizo moja kwa kila modeli. Watoa huduma wasio na lakabu tofauti bado hutoa ingizo lao, kwa hivyo hakuna kinachopotea.                                                                                                  |
| `canonical` | `claude/claude-sonnet-4-6`                               | Ingizo moja kwa kila modeli chini ya kiambishi awali kamili cha ID ya mtoa huduma. Watoa huduma wasio na lakabu tofauti (k.m. `antigravity/…`, `agy/…`) pia hutoa ID yao moja hapa, kwa hivyo hakuna kinachopotea.       |

Kioo cha hali ya `dual` kinaweza pia kutambuliwa bila kigezo cha hoja: kina uga wa `parent`
unaoelekeza kwenye ID msingi.

Wateja wanaoonyesha kichagua modeli wanapaswa kuomba `?prefix=alias` — hivi ndivyo
[kiendelezi cha OmniCopilot cha VS Code](../guides/VSCODE-COPILOT.md) kinavyofanya.

### Vichujio vya ugunduzi (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` hukubali vichujio vya hiari vya ugunduzi. Bila chochote kati yavyo, jibu
halibadiliki. Hupunguza katalogi ambayo mwombaji tayari anaweza kuona (ruhusa za ufunguo wa API hutumika kwanza),
na hutekelezwa kabla ya ugawaji wa kurasa wa mtindo wa OpenAI wa `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # kila uwezo ulioorodheshwa lazima uwe kweli
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` ya katalogi; safu zisizo nayo ni `chat`
GET /v1/models?q=sonnet&limit=10                           # ulinganishaji usiojali ukubwa wa herufi kwenye ID au jina
```

| Kigezo        | Thamani                                                                                             |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | nambari kamili isiyo hasi, ikilinganishwa na `context_length`                                       |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | herufi 1–200                                                                                        |

Thamani isiyojulikana, au `min_context` ambayo si nambari kamili isiyo hasi (kwa mfano `1.5`),
hurejesha HTTP `400`, na ujumbe huorodhesha thamani halali. Utekelezaji:
`src/app/api/v1/models/catalogFilters.ts`.

### Orodha fupi ya modeli (`POST /v1/models/query`)

`POST /v1/models/query` hurejesha orodha fupi na thabiti kutoka kwenye katalogi hiyo hiyo, ikiwa na
uthibitishaji uleule na mwonekano uleule kwa kila ufunguo kama `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Kila uga ni wa hiari. `capabilities` na `exclude` hukubali safu au mfuatano uliotenganishwa kwa koma;
`max_output` hulinganishwa na `max_output_tokens`. Matokeo hupangwa kwa `owned_by`, kisha `id`.
Chaguo-msingi la `limit` ni `20`, na thamani zilizo juu ya `100` huwekewa kikomo cha `100`. JSON batili, uga
usiojulikana au thamani batili hurejesha HTTP `400`.

### Modeli za gumzo zilizofichwa kivyake

Modeli iliyowekwa alama ya **Imefichwa** kwenye ukurasa wa mtoa huduma wake huondolewa kwenye katalogi na kukataliwa
kwa HTTP `404` / `model_not_found` inapoombwa moja kwa moja. Ukaguzi hutumia mtoa huduma na modeli
zilizotambuliwa, ikijumuisha lakabu za watoa huduma, viambishi awali vya nodi za watoa huduma wanaooana, na
chaguo-msingi za muunganisho. Mchanganyiko huruka malengo yaliyofichwa na unaweza kutumia modeli nyingine inayoonekana; wakati hakuna
lengo linaloweza kutekelezwa linalosalia, hurejesha msimbo uleule wa hitilafu. Kuondoa ufichaji huanza kutumika kwenye ombi
linalofuata. Ubatilishaji wa mwonekano wa picha pekee haufichi modeli ya gumzo yenye ID ileile.

Mpangilio huu wa modeli binafsi ni tofauti na
[orodha za kuruhusu/kuzuia uonyeshaji wa modeli](../routing/MODEL_EXPOSURE_LIST.md), ambazo huchuja matangazo ya katalogi
na viteuliwa vya uelekezaji kiotomatiki huku zikidumisha utumaji wa moja kwa moja. Ruhusa za modeli za ufunguo wa API
huendelea kutumika kivyake. Hali chaguo-msingi ya kiambishi awali cha katalogi inasalia `dual`.

### Vibadala vya modeli visivyo na ufikiri

Kwa modeli za Claude zenye uwezo wa kufikiri, `/v1/models` pia hutangaza kibadala cha **bila kufikiri** ambacho ID yake huanza na `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Kuchagua kitambulisho hiki (k.m. katika usanidi wa Claude Code ambao daima huambatisha bloku ya `thinking`) hurejea tena `<provider>/<model>` halisi huku uhawilishaji ukizimwa — `thinking:{type:"disabled"}` kwenye njia ya `/v1/messages`, au sehemu za `reasoning`/`reasoning_effort` huondolewa kwenye njia ya `/v1/chat/completions`. Kibadala hiki huorodheshwa tu kwa modeli za familia ya Claude zinazotumia uhawilishaji **na** zinazokubali `disabled` (kwa hivyo, k.m. modeli zinazotumia hali ya kujirekebisha pekee na zinazokataa `disabled` hazijumuishwi). Waendeshaji wanaweza kulazimisha kibadala hiki kiwashwe au kizimwe kwa kila modeli kupitia `ModelSpec.noThinkingAlias`.

## Uzalishaji wa sauti wa ElevenLabs

Sanidi muunganisho wa mtoa huduma wa `elevenlabs` katika OmniRoute kwa kutumia ufunguo wako wa API wa ElevenLabs.
Wateja huthibitisha utambulisho kwa ufunguo wao wa **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`);
gateway hutoa ufunguo wa mtoa huduma uliohifadhiwa kama `xi-api-key`. Kamwe usitume ufunguo wa ElevenLabs
kama tokeni ya bearer ya gateway.

| Mbinu | Njia                        | Jibu                                          | Kategoria ya endpoint ya ufunguo wa API |
| ----- | --------------------------- | --------------------------------------------- | --------------------------------------- |
| POST  | `/v1/sound-generation`      | Baiti asilia za sauti                         | `elevenlabs`                            |
| POST  | `/v1/music`                 | Baiti asilia za sauti                         | `music`                                 |
| POST  | `/v1/music/stream`          | Baiti za sauti zinazotiririshwa               | `music`                                 |
| POST  | `/v1/music/detailed`        | Sauti asilia ya multipart na mpango wa utunzi | `music`                                 |
| POST  | `/v1/music/detailed/stream` | Metadata asilia ya SSE na vipande vya sauti   | `music`                                 |
| POST  | `/v1/music/plan`            | Mpango wa utunzi wa JSON                      | `music`                                 |

Endpoint hizi hukamilisha njia zilizopo za `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` na `/v1/speech-to-text`. Sehemu asilia za JSON
na vigezo vya hoja kama vile `output_format` na `enable_logging` huhifadhiwa.
Majibu ya `/v1/music/detailed` huhifadhi mipaka yake ya multipart; yachanganue kama multipart.
`/v1/music/detailed/stream` hurejesha `text/event-stream` yenye metadata ya utunzi na
vipande vya sauti vya base64 katika matukio ya SSE. Njia zote sita zinaweza kushughulikia ombi la awali la CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Athari fupi ya sauti. Muda: sekunde 0.5 hadi 30.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Muda wa muziki huonyeshwa kwa milisekunde: 3000 hadi 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Tumia `/v1/music/stream` pamoja na mwili uleule wa JSON kwa uwasilishaji wa sauti wa hatua kwa hatua. Utunzi
hukubali moja pekee kati ya `prompt` au `composition_plan`; `/v1/music/plan` huhitaji `prompt`
na kwa hiari hukubali `source_composition_plan`. Skima asilia huhifadhi sehemu za ziada za
mtoa huduma ili matoleo ya mpango wa utunzi na chaguo za uboreshaji maalumu zifikie ElevenLabs.

Endpoint iliyounganishwa ya `/v1/music/generations` pia hukubali `elevenlabs/music_v1`,
`elevenlabs/music_v2` na `elevenlabs/music_v2_5`. Muunganisho wa ElevenLabs ukiwa amilifu,
modeli hizi huonyeshwa na katalogi ya muziki. Endpoint hii hurejesha
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Sehemu yake ya `duration` hupimwa kwa
sekunde na hulinganishwa na `music_length_ms`; `music_length_ms` iliyobainishwa wazi hupewa kipaumbele.
`instrumental` hulinganishwa na `force_instrumental`, huku sehemu asilia ikipewa kipaumbele.
Tumia endpoint asilia za utiririshaji kwa utiririshaji na endpoint asilia ya utunzi
kwa maombi yanayoongozwa na mpango wa utunzi pekee.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Vizuizi vya endpoint, modeli, bajeti na muunganisho hutumika kabla ya wito wa upstream. Njia asilia
hurejesha misimbo ya hali na miili ya hitilafu ya upstream bila kubadilishwa, ikijumuisha `402` kwa kizuizi
cha mpango na `429` kwa kikomo cha mgao. Vichwa vya `character-cost`, `song-id`, `request-id` na `retry-after`
huhifadhiwa vinapokuwepo. Salio lisilolipishwa la mikopo halihakikishi ufikiaji wa kila
modeli ya muziki, umbizo la matokeo au kipengele cha API: ElevenLabs huamua haki ya ufikiaji kwa kila ombi.
Endpoint iliyounganishwa huhifadhi misimbo ya hali ya hitilafu katika bahasha ya hitilafu iliyosanifishwa ya OmniRoute.

Mikataba ya upstream: [athari za sauti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[utunzi wa muziki](https://elevenlabs.io/docs/api-reference/music/compose) na
[maelezo ya muziki unaotiririshwa](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (k.m. jina la huduma ya Docker/Compose kama
> `http://reranker:8080/v1`; hizi huitwa moja kwa moja, kamwe si kupitia `HTTP(S)_PROXY` au proksi
> iliyobandikwa ya muunganisho). Nodi kwenye host nyingine yoyote

> `RERANK_REMOTE_PROVIDER_NODES` **na** URL ya msingi ya nodi inapokidhi sera ya URL zinazotoka ya mtoa
> huduma (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Hatua ya kupanga upya ya injini ya kumbukumbu huita route hii kupitia
> loopback, kwa hivyo kanuni hiyo hiyo inatumika kwa `rerankProviderModel` katika mipangilio ya Kumbukumbu.
>
> **Miundo ya seva za ndani:** nodi huitwa katika `<base>/v1/rerank` na, ikipatikana 404, katika
> `<base>/rerank` (Infinity, TEI). Body ya upstream hubeba tahajia ya Cohere/OpenAI (`documents`,
> `return_documents`) pamoja na tahajia ya TEI (`texts`, `return_text`), na jibu la upstream

> alama na kupunguzwa hadi `top_n`.

> katika `GET /v1/models` chini ya kiambishi awali cha nodi. Safu ambazo hazina metadata ya endpoint
> (hali ya kawaida kwa orodha za ndani za `/v1/models`) hurithi `apiType` ya nodi, kwa hivyo modeli za

| Tavily      | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                           |

Nyuga za jumla hupewa kipaumbele kila wakati: `query`, `max_results`, `filters` (vikoa), `country` na
mada inayotokana na `search_type`. Kwenye Exa, `search_type: "news"` hudumisha `category: "news"`.
Tavily pia inakubali `search_type: "finance"` (`topic: "finance"`).

`time_range` ya jumla sasa huwafikia watoa huduma wote wawili: Exa hupokea `startPublishedDate` (muhuri wa muda wa ISO)
na Tavily hupokea `start_date` (`YYYY-MM-DD`). Tarehe iliyobainishwa waziwazi katika `provider_options`
hupewa kipaumbele kuliko ile iliyolinganishwa.

Matokeo ya Exa huhifadhi `id`, `highlight_scores`, `summary`, `subpages`, `entities` na `extras` katika
`provider_raw`. Matokeo ya Tavily huhifadhi `images` na `favicon`.

Uhasibu wa gharama bado unatumia sajili bapa ya `costPerQuery`. Tavily hutoza
`search_depth: "advanced"` kwa salio zaidi kwa kila ombi, na tofauti hiyo haionyeshwi katika
`usage.search_cost_usd`.

## API ya Uletaji wa Wavuti

Toa maudhui kutoka kwenye URL kupitia mtoa huduma aliyesanidiwa wa uletaji wa wavuti (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, ufunguo sawa wa API na Parallel Search) hurejesha Markdown
pekee — `format` nyingine yoyote husababisha `400` — na huweka kikomo cha maudhui kuwa herufi 100,000. Wakati
ukurasa lengwa wenyewe hauwezi kutolewa, mfumo wa juu huripoti hilo ndani ya HTTP 200;
OmniRoute huwasilisha hilo kama `422` yenye ujumbe maalum usiobadilika.

| Mbinu | Njia            | Maelezo                                                       |
| ----- | --------------- | ------------------------------------------------------------- |
| POST  | `/v1/web/fetch` | Leta/chambua URL — mwili unathibitishwa na `v1WebFetchSchema` |

**Uthibitishaji:** Ufunguo wa API wa Bearer (`extractApiKey` + `isValidApiKey`). Sera hutekelezwa kupitia `enforceApiKeyPolicy`.

**Mpito mbadala unaozingatia kiasi kinachoruhusiwa (#8297):** wakati hakuna `provider` mahususi aliyetolewa, kundi
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) hupitiwa kwa mpangilio maalum
wa kipaumbele (jaza-kwanza) — mtoa huduma aliyesanidiwa lakini aliyewekewa kikomo cha kasi hurukwa
badala ya kusitisha ombi mara moja, na hitilafu ya mfumo wa juu inayoweza kujaribiwa tena/ya kiasi kinachoruhusiwa
(HTTP 429 kila wakati; 402/403 kwa viwango vya bure vya Firecrawl/Tavily/TinyFish vya aina ya kiasi kinachoruhusiwa —
si kwa Jina Reader, na kamwe si kwa ombi batili la kawaida la 400) husababisha kuhamia kwa
mtoa huduma mwingine ambaye bado hajajaribiwa na aliye na kitambulisho wakati wa ombi. Wakati kila mtoa huduma katika
kundi amemalizika, ncha hurejesha `429` moja (ikiwa na kichwa cha `Retry-After`)
badala ya `400` ya jumla iliyotumika awali. Wakati `provider` mahususi
anaombwa, **hakuna** mpito mbadala wa kimya — mtoa huduma mahususi aliyewekewa
kikomo cha kasi au aliyeshindwa huwasilisha hitilafu yake mwenyewe (`429` ikiwa amewekewa kikomo cha kasi, vinginevyo hali ya
mfumo wa juu).

## Utiririshaji wa WebSocket

```bash
GET /v1/ws?handshake=1
```

Huthibitisha handshake ya uboreshaji wa WebSocket na kurejesha mifano ya ujumbe wa itifaki ya waya (`request`, `cancel`). Fremu halisi za WS hushughulikiwa na seva ya WS iliyojumuishwa nje ya jedwali la njia za Next.js.

**Uthibitishaji:** Ufunguo wa API wa Bearer wakati wa handshake.

### Responses API kupitia WebSocket (codex pekee)

```bash
# Mpangishaji:mlango sawa na API ya HTTP (chaguo-msingi 20128); boresha muunganisho:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (au: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Fremu ya kwanza LAZIMA iwe response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proksi ya Responses-API-over-WebSocket imeunganishwa **kipekee na `codex`** (sehemu ya nyuma ya ChatGPT). Husikiliza kwenye mlango sawa na API/dashibodi katika njia `/v1/responses`,
`/responses`, na `/api/v1/responses`. Kwenye fremu ya kwanza ya `response.create`,
huthibitisha + huandaa kupitia daraja la ndani la `codex-responses-ws`, huchagua
muunganisho wa codex OAuth, na kuunda handaki kwenda `wss://chatgpt.com/backend-api/codex/responses`
kupitia usafirishaji wa `wreq-js`. **Modeli zisizo za codex hukataliwa** (`codex_ws_provider_required`).
Kwa uelekezaji wa ugawanaji wa kiasi kinachoruhusiwa tumia `model: "qtSd/<group>/codex/<model>"`. Imetekelezwa katika
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Uthibitishaji:** Ufunguo wa API wa Bearer wakati wa handshake. Seva ya HTTP iliyojumuishwa (`server-ws.mjs`)
lazima iwe sehemu amilifu ya kuingilia (ndivyo ilivyo kwa chaguo-msingi, wakati `app/server-ws.mjs` ipo).

#### Kitambulisho cha modeli: tumia kitambulisho halisi cha ChatGPT (bila kiambishi awali cha `codex/`)

**Codex CLI** ya OpenAI huthibitisha jina la modeli upande wa kiteja wakati
`supports_websockets = true` na **hukataa vitambulisho vyenye kiambishi awali cha mtoa huduma** kama
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Tuma kitambulisho **halisi** (k.m. `gpt-5.5`). Daraja la OmniRoute ni
la codex pekee, kwa hivyo hutatua upya kitambulisho halisi kama modeli ya codex
(`resolveCodexWsModelInfo`) kabla ya kuunda handaki kwenda mfumo wa juu — ingawa kitambulisho halisi cha
`gpt-5.5` kingeelekezwa kwa mtoa huduma mwingine kupitia HTTP.

#### Kusanidi OpenAI Codex CLI

Elekeza Codex CLI kwa OmniRoute kwa kuongeza mtoa huduma maalum mwenye usaidizi wa WebSocket
kwenye `~/.codex/config.toml` (tumia `CODEX_HOME` tofauti ili kuepuka kubadilisha
usanidi uliopo):

```toml
model = "gpt-5.5"                 # kitambulisho halisi — SI "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bila mkwaju wa mwisho; URL ya WS hutolewa kutokana nayo (tumia https/wss katika uzalishaji)
wire_api = "responses"                    # thamani pekee inayotumika tangu Feb 2026
supports_websockets = true                # huwezesha usafirishaji wa Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # huhifadhi ufunguo wa API wa OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # ufunguo wa API wa OmniRoute (ufunguo wowote ikiwa REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI huboresha `base_url + /responses` kuwa WebSocket na OmniRoute huiundia handaki
kwenda kwenye muunganisho uliochaguliwa wa codex OAuth. Imethibitishwa mwanzo-hadi-mwisho dhidi ya seva ya ndani:
ChatGPT hurejesha `codex.rate_limits` + `response.created` na kutiririsha
ukamilishaji.

## Matumizi ya kujihudumia (`/api/usage/om-usage`)

Ufunguo wowote wa API unaweza kusoma matumizi na vikomo **vyake wenyewe** — uthibitishaji wa usimamizi hauhitajiki. Hiki ndicho kituo ambacho
kiteja (CLI, paneli ya OmniCopilot) hutumia kumwonyesha mmiliki wa ufunguo matumizi yake ya fedha.

```bash
# Muundo wa maandishi (mkataba wa awali — maandishi wazi kwa ajili ya terminali)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Muundo wenye mpangilio — unaotumiwa na UI
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Ufunguo lazima uwe na **`allowUsageCommand`** iliyowezeshwa (imezimwa kwa chaguo-msingi — kidhibiti cha funguo za API
cha dashibodi huiwasha au kuizima kwa kila ufunguo). Bila hiyo, kituo hujibu `403`.

`?format=json` hurejesha muundo bainifu ili mwitaji asisome kamwe sehemu ya data kutoka kwenye
jibu la kukataliwa. Inapofanikiwa:

```jsonc
{
  "allowed": true,
  // inapatikana tu wakati ufunguo umechagua kutumia vikomo vya matumizi vya kila ufunguo (USD kwa siku/wiki):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // muhtasari wa kikomo cha mtoa huduma aliyechaguliwa, au null wakati bado hakuna kilichohifadhiwa kwenye kache:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // muhtasari wa kila muunganisho, ili UI iweze kuonyesha watoa huduma kadhaa kando kwa kando:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Inapokataliwa (`401` ufunguo batili / `403` hairuhusiwi), njia hiyo hiyo hurejesha
`{ "allowed": false, "error": { "message": "…" } }` — `personal`/`provider` iliyopo lakini tupu
(ufunguo umeruhusiwa, bado hakuna kilichopatikana) ni hali tofauti na kukataliwa, na ni muundo wa JSON pekee
unaotofautisha hali hizo.

**Uthibitishaji:** Ufunguo wa API wa Bearer wa mwitaji mwenyewe, unaothibitishwa kwa `isValidApiKey` — hii _si_
sehemu ya usimamizi (`/api/keys/…`), ambayo inaendelea kulindwa na `requireManagementAuth`.

### Asilimia Ghafi dhidi ya Asilimia za Vikomo Zilizorekebishwa kwa Kizingiti cha Kukata

Wakati wa kutumia `/api/usage/om-usage`, waitaji wanapaswa kutambua tofauti kati ya
asilimia zinazowasilishwa na **tokeo la maandishi wazi** na **tokeo la JSON** lenye mpangilio:

| Kipengele                                | Muundo wa maandishi wazi (`/api/usage/om-usage` / `@@om-usage`)                                                       | Muundo wa JSON (`?format=json`)                                                             |
| :--------------------------------------- | :-------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------ |
| **Sehemu ya tokeo**                      | `NN% left` (k.m., `20% left`)                                                                                         | `provider.quotas` / `providers[].quotas`                                                    |
| **Kipimo**                               | **Kiasi kinachoweza kutumika kilichorekebishwa kwa kizingiti cha kukata**: uwezo uliobaki juu ya kizingiti cha kukata | **Kikomo ghafi cha upstream**: kipimo cha mtoa huduma ambacho hakijarekebishwa              |
| **Urekebishaji wa kizingiti cha kukata** | Hurekebishwa kupitia `effectiveRemainingPercent()` ili akiba iliyolindwa isomeke kama `0% left`                       | Hakuna (thamani ghafi za muhtasari kama zilivyoripotiwa na mtoa huduma)                     |
| **Data ya kizingiti**                    | Imejumuishwa katika asilimia inayoonyeshwa                                                                            | Imehifadhiwa katika `quotaWindowThresholds` kwa kila muunganisho (au chaguo-msingi za seva) |
| **Mtumiaji mkuu**                        | CLI shirikishi, vidokezo vya terminali, waendeshaji binadamu                                                          | Miunganisho ya kiprogramu, dashibodi, uchanganuzi, vifuatiliaji vya malipo                  |

#### Fomula ya Urekebishaji wa Kizingiti cha Kukata

OmniRoute inatumia vikomo vya kukata kwa njia ya mapema ili kuzuia kuisha kwa rasilimali za upstream (vinavyosanidiwa kupitia
`quotaWindowThresholds` za muunganisho, chaguo-msingi za mtoa huduma, au mipangilio ya jumla ya ustahimilivu). Wakati kizingiti cha kukata
(k.m., `cutoff = 25%`) kinatumika kwenye dirisha la kikomo, kiwasilishaji cha maandishi huhesabu kiasi kilichobaki kama ifuatavyo:

- Ikiwa `remaining <= cutoff`: hurejesha `0%`.
- Ikiwa `remaining > cutoff`: hurejesha `((remaining - cutoff) / (100 - cutoff)) * 100`.

Tokeo la maandishi lililoumbizwa huzungusha thamani hii hadi nambari kamili iliyo karibu zaidi (`Math.round(...)`).

#### Mfano wa Ufafanuzi

Fikiria dirisha la mtoa huduma lenye **matumizi ghafi ya 60%** (kwa hivyo **40% ya kikomo ghafi imebaki**) na
kizingiti kilichosanidiwa cha **kukata wakati 25% ya kikomo imebaki**:

| Uwakilishi                           | Hesabu                                             | Kilichobaki |               Matumizi Yanayodokezwa               |
| :----------------------------------- | :------------------------------------------------- | :---------: | :------------------------------------------------: |
| **JSON ghafi (`?format=json`)**      | Muhtasari wa upstream (`quotas[window]`)           |   **40%**   |                      **60%**                       |
| **Muundo wa maandishi (`NN% left`)** | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |   **20%**   | **80%** (ikiwa inahesabiwa kama `100 - remaining`) |

- **Kwa nini maandishi yanaonyesha 20% imebaki:** Kati ya 40% ya kikomo halisi kilichobaki kwenye akaunti, 25% imehifadhiwa na
  sera ya kukata. Mwitaji amebakiza nafasi inayoweza kutumika ya 15% tu kati ya 75% kabla ya kipanga-njia kuacha
  kuelekeza maombi kwenye muunganisho huu. Urekebishaji huhakikisha muunganisho unaashiria kuisha (`0% left`) wakati hasa
  uelekezaji utakaposimama.
- **Kwa nini JSON huhifadhi thamani ghafi:** Data ya JSON hurejesha muhtasari halisi wa mtoa huduma (`UsageSnapshot`)
  ili zana za nje ziweze kufikia matumizi halisi ya upstream na
  `quotaWindowThresholds` za kiwango cha muunganisho bila urekebishaji wa seva unaopoteza taarifa.

#### Mwongozo wa Uhamishaji kwa Watumiaji

Ikiwa muunganisho wa nje (kama vile programu-jalizi ya kihariri au kiendelezi cha wakala) hapo awali ulichota maandishi kutoka
sehemu ya mwisho ya maandishi (`NN% left`) na kukokotoa asilimia iliyotumika kama `100 - NN`, kuhamia kwenye `?format=json` kunamaanisha:

- Kusoma thamani ghafi za JSON kutaonyesha **matumizi halisi ya mfumo wa chanzo** (60% imetumika katika mfano ulio hapo juu).
- Ikiwa muunganisho unataka kuhifadhi semantiki za kiwango kinachoweza kutumika za sehemu ya mwisho ya maandishi, unaweza kutathmini
  fomula halisi ya kiasi kilichosalia upande wa mteja kwa kutumia `quotaWindowThresholds` kwa ubatilishaji wa kiwango cha muunganisho.

linathibitisha thamani inayotambulika ya `owned_by`: `vllm`, `sglang`, au `llamacpp`.
Vifungashio vinavyoonekana wazi vinavyooana na OpenAI vinaweza kuhifadhi ingizo asili la modeli ndani
ya kipengee cha `openai` kilichopachikwa; utambuzi hufuata hadi vifungashio vitatu vya aina hiyo.
Modeli ambazo umiliki wake haupo, hautambuliki, au unakinzana huhifadhi tabia ya kawaida ya OpenAI.
Utambuzi hutumia tena ombi lililopo la katalogi, hauzalishi tokeni zozote za ukamilishaji, na
hubatilishwa endpoint ya muunganisho inapobadilika.

Ili kuweka tabia hiyo kwa uthabiti kwa backend ambayo haifichui metadata hiyo, tumia API iliyopo ya
kusasisha sehemu ya mtoa huduma:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Tuma body hiyo kwa `PUT /api/providers/<connection-id>`. Kwenye muunganisho huo, kiwango bayana
cha juhudi ya urazini cha `none` hutumwa kama `chat_template_kwargs.thinking=false` na
`chat_template_kwargs.enable_thinking=false`. Thamani bayana asilia za kiolezo hubaki na mamlaka
isipokuwa kanuni ya urazini ya upande wa seva ilazimishe kiwango cha juhudi. Mpangilio huu hutumika
tu wakati muunganisho maalum unaooana na OpenAI unatuma body ya Chat Completions; maombi ya Responses
na watoa huduma wa kawaida huhifadhi muundo wao asilia wa ombi. Weka `reasoningControl` kuwa `openai`
ili kulazimisha upitishaji wa kawaida wa OpenAI wa `reasoning_effort`, au iache/seti kuwa `null` ili
kutumia utambuzi wa kiotomatiki.

Maombi ya kiainishaji cha hali ya kiotomatiki ya Claude Code huweka fikra asilia kuwa zimezimwa kwa
chaguo-msingi wakati hayana vidhibiti bayana vya urazini. Utambuzi hutumia kialamishi cha mfumo cha
kiainishaji katika maombi ya muundo wa Claude, wala si majina ya modeli au vikomo vya ukamilishaji.
Vidhibiti bayana vya body, headers zinazotumika za juhudi/fikra, kanuni za uelekezaji, na kiwango cha
juhudi ya modeli kilichobainishwa huhifadhi kipaumbele chake kilichopo. Hatua zote mbili za kiainishaji
huhifadhi prompts zake, vikomo vya ukamilishaji, mifuatano ya kusimamisha, na maamuzi halisi ya ruhusa
kutoka juu ya mkondo; hatua ya pili bado inaweza kutoa urazini unaoonekana ulioombwa kama maandishi ya
kawaida.

Hurejesha toleo linaloendeshwa, toleo jipya zaidi lililochapishwa na hali ya usasishaji wa kiotomatiki. `releaseChannel` na `channels` ni sehemu zilizoongezwa (toleo la 3.8.54); `channel` inadumisha maana yake — hali ya upelekaji ambayo kisasishaji cha dashibodi hutumia (`npm`, `source` au `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — kituo cha npm cha build inayoendeshwa: `nightly` kwa matoleo ya `-nightly.*`,
  `next` kwa matoleo mengine ya awali (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` kwa toleo thabiti la
  toleo kuu la zamani kuliko `channels.latest`, vinginevyo `latest`. Kanuni sawa na
  `scripts/release/dist-tag.mjs`, ambayo huchagua dist-tag ya npm wakati wa uchapishaji.
- `channels` — toleo la sasa lililochapishwa la kila dist-tag, kutoka `npm view omniroute dist-tags` (mbinu
  mbadala ya HTTP ya registry), lililohifadhiwa kwenye akiba kwa TTL ileile ya dakika 10 kama `latest`. `latest` inapatikana kila wakati
  (hutumia sehemu ya `latest` kama chaguo mbadala, kisha `"unavailable"`); `next`, `nightly` na `lts` huonekana
  tu wakati dist-tag hiyo ipo. Ombi la `Cache-Control: no-cache` huonyesha upya utafutaji wote wawili.

Muundo wa vituo (`latest` = v3 hadi upatikanaji wa jumla wa 4.0, `next` = rc, `nightly` = build za `develop`,
`lts` = viraka vya v3 baada ya upatikanaji wa jumla wa 4.0) umefafanuliwa katika `docs/ops/RELEASE_STRATEGY.md`.

## Vikomo vya Tokeni

Bajeti za **tokeni** kwa kila ufunguo wa API (tofauti na Bajeti inayotegemea USD hapo juu). Hutekelezwa moja kwa moja kwenye njia ya ombi: matumizi ya dirisha la sasa la ufunguo yanapofikia kikomo chake, maombi hukataliwa kwa `429 Too Many Requests`. Vikomo vinaweza kuwekwa kwa `model` mahususi, `provider`, au kutumika `global` kwa ufunguo mzima; vikomo kadhaa vinapolingana na ombi, kile chenye masharti makali zaidi ndicho hutumika.

```bash
# Orodhesha vikomo vya tokeni vya ufunguo (hujumuisha matumizi ya moja kwa moja ya dirisha)
GET /api/usage/token-limits?apiKeyId=key-123

# Unda au sasisha kikomo cha tokeni
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Futa kikomo cha tokeni kwa kutumia id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Maelezo ya schema** (`setTokenLimitSchema`): `apiKeyId` na `scopeType` (`model` | `provider` | `global`) zinahitajika. `scopeValue` inahitajika isipokuwa `scopeType` iwe `global` (k.m. id ya modeli kwa mawanda ya `model`, id ya mtoa huduma kwa mawanda ya `provider`). `tokenLimit` lazima iwe nambari kamili chanya (inabadilishwa kutoka kwenye mfuatano). Hiari: `id` (iache ili kuunda, itoe ili kusasisha), `resetInterval` (`daily` | `weekly` | `monthly`, chaguo-msingi `monthly`), `resetTime` (`HH:MM`), `enabled` (chaguo-msingi `true`). Majibu ya `GET` huboresha kila kikomo kwa `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, na `nextResetAt`. Hiki ni kituo cha aina ya usimamizi (uthibitishaji wa ruhusa unatekelezwa kwa pamoja na mchakato wa authz).

## Ustahimilivu (uliopanuliwa)

OmniRoute hutoa mbinu tatu huru za kushughulikia hitilafu za muda; endpoints za usimamizi zilizo hapa chini huwawezesha waendeshaji kusoma na kubatilisha mipangilio yake:

| Upeo                                 | Hifadhi ya hali                                       | Kusoma                                    | Kuweka upya / kufuta                                           |
| ------------------------------------ | ----------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------- |
| Kikatiza mzunguko cha mtoa huduma    | `domain_circuit_breakers` + kumbukumbu ya ndani       | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                   |
| Kipindi cha kusubiri cha muunganisho | `rateLimitedUntil` kwenye miunganisho ya watoa huduma | `/api/rate-limits`, `/api/providers/[id]` | (huwashwa tena inapohitajika; futa kupitia PUT ya mtoa huduma) |
| Kufungiwa kwa modeli                 | Sajili ya ndani ya upatikanaji wa modeli              | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                       |

`PATCH /api/resilience` hukubali ubatilishaji wa kikatiza mzunguko cha mtoa huduma chini ya `providerBreaker.oauth` na `providerBreaker.apikey`. Kila wasifu hutumia `degradationThreshold`, `failureThreshold`, na `resetTimeoutMs`; sehemu hizo hizo zinapatikana katika Dashibodi → Mipangilio → Ustahimilivu.

```bash
# Futa kufungiwa kwa modeli moja
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Futa kufungiwa kote
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Kwa marejeleo kamili ya dhana na chaguo-msingi za kikatiza mzunguko: angalia [`CLAUDE.md`](../../CLAUDE.md) → "Hali ya Uendeshaji ya Ustahimilivu" na [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Foleni ya Kikomo cha Kasi na Wavu wa Usalama wa Kuwasha Kiotomatiki

- **Njia ya uandishi inayotumika**: `POST /api/rate-limits` yenye mwili `{"connectionId": "<id>", "enabled": true|false}` ndiyo endpoint ya usimamizi inayotumika kuwasha au kuzima ulinzi wa kikomo cha kasi kwa muunganisho. `PUT /api/providers/[id]` kwa makusudi haibadilishi wala kugeuza `rateLimitProtection` (#11278).
- **Maana ya `enabled: false`**: Kuweka `enabled: false` huondoa ulinzi uliobainishwa wazi kwa muunganisho, lakini **hakuondoi** muunganisho amilifu wa ufunguo wa API kwenye wavu wa usalama wa kimataifa wa kuwasha kiotomatiki (`autoEnableApiKeyProviders = true`). Katika `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` na `undefined` ni sawa; miunganisho amilifu ya ufunguo wa API isiyo na ulinzi uliobainishwa wazi huendelea kulindwa chini ya wavu wa usalama wa kuwasha kiotomatiki.
- **Kuzima kimataifa**: Ili kuendesha miunganisho ya ufunguo wa API bila foleni za kikomo cha kasi, zima wavu wa usalama kimataifa kupitia `RATE_LIMIT_AUTO_ENABLE=false` (mazingira) au `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Mipangilio → Ustahimilivu / `PATCH /api/resilience`).

## Seva ya MCP

OmniRoute huja na seva iliyopachikwa ya Model Context Protocol yenye njia 3 za usafirishaji (stdio, SSE, streamable-http) na zana zenye upeo maalum. Endpointi za dashibodi zilizo hapa chini husoma data ya hali/ukaguzi na hupitisha kwa proksi njia za usafirishaji za HTTP.

| Mbinu | Njia | Maelezo |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Ishara ya uhai, njia ya usafirishaji, hali ya mtandaoni, simu ya mwisho, zana kuu, kiwango cha mafanikio cha saa 24 |
| GET | `/api/mcp/tools` | Orodha ya zana za MCP zenye `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Fungua mtiririko wa SSE kwa usafirishaji wa SSE (hurejesha `503` ikiwa MCP imezimwa au njia ya usafirishaji hailingani) |
| POST | `/api/mcp/sse` | Tuma fremu ya JSON-RPC kupitia usafirishaji wa SSE |
| GET | `/api/mcp/stream` | Fungua upande wa SSE wa usafirishaji wa Streamable HTTP (ujumbe unaoanzishwa na seva) |
| POST | `/api/mcp/stream` | Tuma fremu ya JSON-RPC kupitia usafirishaji wa Streamable HTTP |
| DELETE | `/api/mcp/stream` | Hitimisha kipindi cha Streamable HTTP |
| GET | `/api/mcp/audit` | Hoji kumbukumbu ya ukaguzi — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Takwimu zilizojumlishwa za ukaguzi (jumla, kiwango cha mafanikio, wastani wa muda, zana kuu) |

**Uthibitishaji:** njia za usafirishaji za `sse`/`stream` hutumia mfumo mahususi wa uthibitishaji wa MCP (ufunguo wa Bearer API wenye upeo wa `mcp`); njia za `status`/`tools`/`audit*` zinaweza kusomwa kutoka kwenye dashibodi (hakuna uthibitishaji wa ziada unaohitajika zaidi ya kufikia seva mwenyeji ya dashibodi).

> Njia zote mbili za usafirishaji za HTTP zinadhibitiwa na `settings.mcpEnabled` na `settings.mcpTransport` — kutolingana kwa njia ya usafirishaji hurejesha `400`, hali ambapo MCP imezimwa hurejesha `503`.

## Seva ya A2A

OmniRoute hutoa endpointi ya A2A (Wakala-kwa-Wakala) ya JSON-RPC 2.0 pamoja na kifungashio cha REST kwa ajili ya ukaguzi na matumizi ya dashibodi.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # si lazima isipokuwa OMNIROUTE_API_KEY imewekwa
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Mbinu zinazotumika (zote hudhibitiwa na `settings.a2aEnabled`):

| Mbinu            | Maelezo                                                             |
| ---------------- | ------------------------------------------------------------------- |
| `message/send`   | Utekelezaji sawia wa ujuzi; hurejesha `{task, artifacts, metadata}` |
| `message/stream` | Utekelezaji wa kutiririsha wa SSE wa seti hiyo hiyo ya ujuzi        |
| `tasks/get`      | Leta jukumu kwa kutumia `taskId`                                    |
| `tasks/cancel`   | Ghairi jukumu kwa kutumia `taskId`                                  |

Ujuzi uliojengewa ndani: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kadi ya Wakala

```bash
GET /.well-known/agent.json
```

Hurejesha kadi ya umma ya wakala wa A2A (jina, maelezo, uwezo, katalogi ya ujuzi, utaratibu wa uthibitishaji) — huhifadhiwa kwenye akiba kwa umma kwa 1h. Uthibitishaji hauhitajiki.

### Visaidizi vya REST

| Mbinu | Njia                         | Maelezo                                                                                                                 |
| ----- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/a2a/status`            | A2A imewezeshwa + takwimu za majukumu + muhtasari wa kadi ya wakala uliohifadhiwa kwenye akiba                          |
| GET   | `/api/a2a/tasks`             | Orodhesha majukumu — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST  | `/api/a2a/tasks`             | (Haijatekelezwa kama kisaidizi cha REST — unda kupitia JSON-RPC `message/send`)                                         |
| GET   | `/api/a2a/tasks/[id]`        | Pata jukumu moja                                                                                                        |
| POST  | `/api/a2a/tasks/[id]/cancel` | Ghairi jukumu                                                                                                           |

**Uthibitishaji:** visaidizi vya REST huendeshwa bila uthibitishaji wa usimamizi (vinaweza kusomwa na dashibodi); njia ya JSON-RPC `/a2a` hutumia Bearer `OMNIROUTE_API_KEY` ikiwa imesanidiwa.

## Uthibitishaji

Tazama [Uthibitishaji wa Usimamizi](../guides/MANAGEMENT-AUTH.md) kwa familia nne za
vitambulisho (kipindi cha dashibodi, tokeni ya CLI ya ndani, Tokeni ya Ufikiaji ya `oma_live_…`,
ufunguo wa API wenye wigo wa usimamizi) na jinsi zinavyotofautiana na funguo za inferensi.

- Njia za dashibodi (`/dashboard/*`) hutumia kidakuzi cha `auth_token`
- Kuingia hutumia hashi ya nenosiri iliyohifadhiwa; ikishindikana, hutumia `INITIAL_PASSWORD`
- `requireLogin` inaweza kuwashwa au kuzimwa kupitia `/api/settings/require-login`
- Njia za `/v1/*` zinaweza kuhitaji kwa hiari ufunguo wa API wa Bearer wakati `REQUIRE_API_KEY=true`
- "tokeni ya usimamizi" / "ufunguo wa API wenye wigo wa usimamizi" katika rejeleo hili humaanisha mojawapo ya familia zilizo katika mwongozo huo — si aina ya ziada ya siri ambayo haijafafanuliwa

> **Mabadiliko yanayovunja uoanifu (v3.8.0)** — `/api/v1/agents/tasks/*` na endpointi za usimamizi wa kipindi cha kusubiri sasa zinahitaji **uthibitishaji wa usimamizi** (kidakuzi cha dashibodi cha `auth_token` au ufunguo wa API wenye wigo wa usimamizi). Wateja ambao hapo awali waliita njia hizi bila uthibitishaji watapokea `401 Unauthorized`. Tazama commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
