## චැට් සම්පූර්ණ කිරීම්

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### අභිරුචි ශීර්ෂක

| ශීර්ෂකය                  | දිශාව     | විස්තරය                                                                                                                                                                                                         |
| ------------------------ | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | ඉල්ලීම    | හැඹිලිය මඟහැරීමට `true` ලෙස සකසන්න                                                                                                                                                                              |
| `x-omniroute-no-memory`  | ඉල්ලීම    | මෙම ඉල්ලීම සඳහා මතකය + කුසලතා ඇතුළත් කිරීම මඟහැරීමට `true` ලෙස සකසන්න (හැඹිලිය භාවිත නොකිරීමට සමානයි; එක් එක් ඇමතුම සඳහා වන ටෝකන/පිරිවැය අතිරේකය වළක්වයි)                                                       |
| `X-OmniRoute-Progress`   | ඉල්ලීම    | ප්රගති සිදුවීම් සඳහා `true` ලෙස සකසන්න                                                                                                                                                                          |
| `X-Session-Id`           | ඉල්ලීම    | බාහිර සැසි සම්බන්ධතාව සඳහා ස්ථාවර සැසි යතුර                                                                                                                                                                     |

#### එක් එක් request එක සඳහා account එකක් ස්ථිරව බැඳීම

Provider කෙනෙකුට connections (accounts හෝ keys) කිහිපයක් ඇති විට, OmniRoute සාමාන්යයෙන් එහි account-selection strategy එක හරහා එකක් තෝරාගනී. ඒ වෙනුවට, request එකකට `x-omniroute-connection` header එක භාවිතයෙන් නිශ්චිත connection එකක් ස්ථිරව බැඳිය හැක:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **id එක සොයාගත හැකි ස්ථානය.** Dashboard එකේ provider පිටුව
  (**Dashboard → Providers → <provider>**) විවෘත කර connection පේළියක ඇති `xxxxxxxx…` id chip එක ක්ලික් කරන්න
  — එවිට සම්පූර්ණ connection id එක පිටපත් වේ.
- **එය පිළිපදින requests.** `/v1/chat/completions`, `/v1/messages` සහ `/v1/responses` මත ඇති
  single-model requests (`provider/model`). Combos විසින් header එක නොසලකා හරිනු ලැබේ: ඒ වෙනුවට එක් එක් combo පියවර සඳහා
  එම පියවරේම connection එක හරහා account එකක් ස්ථිරව බඳින්න.
- **මෙම බැඳීම දැඩි නියමයක් මිස මනාපයක් නොවේ.** ස්ථිරව බැඳූ connection එක පමණක් භාවිත කෙරේ.
  Request එක තුළ ඇතිවන අසාර්ථකත්වයක් account එකේ cooldown එක සටහන් කරන නමුත්, එම providerගේ
  වෙනත් සමගාමී account එකකට **මාරු නොවේ**.
- **Cooldown සහ quota මඟින් බැඳීම නිදහස් කෙරේ.** ස්ථිරව බැඳූ connection එක cooldown තත්ත්වයේ පවතින විට,
  quota අවසන් වී ඇති විට හෝ quota policy එකක් මඟින් අවහිර කර ඇති විට, පසුකාලීන requests providerගේ
  අනෙකුත් connections වෙත මාරු වේ; එය ස්ථිරව නොබැඳූ traffic සඳහා සිදුවන ආකාරයටම වේ.
- **නොදන්නා හෝ අක්රීය කළ ids අසාර්ථක වේ.** Providerගේ active pool එකේ නොමැති id එකක් (මකා දැමූ,
  අක්රීය කළ, හෝ වෙනත් provider කෙනෙකුට අයත් එකක්) නිසා සුදුසු account එකක් ඉතිරි නොවන බැවින්, request එක
  නිහඬව වෙනත් ස්ථානයකට route කිරීම වෙනුවට අසාර්ථක වේ.

Claude Code විසින් `ANTHROPIC_CUSTOM_HEADERS` හරහා custom headers යවයි. එය
`~/.claude/settings.json` හි `env` block එක තුළ, හෝ එක් එක් project එක සඳහා වෙනස්
account එකක් ස්ථිරව බැඳීමට project-level `.claude/settings.json` එකක් තුළ තබන්න:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

මූලාශ්රය: `src/sse/handlers/chat.ts` (header එක කියවීම), `src/sse/services/auth.ts` සහ
`src/sse/services/sessionAffinityPin.ts` (බැඳීම නිදහස් කිරීම සහ pool එකේ නොමැතිදැයි කරන පරීක්ෂාව).

> **පිරිවැය telemetry headers:** streaming නොවන සාර්ථක responses තුළ `X-OmniRoute-*` පිරිවැය-telemetry කට්ටලයද ඇතුළත් වේ — `X-OmniRoute-Response-Cost` (USD, ස්ථාවර දශමස්ථාන 10ක්; නොමිලේ/මිල නියම කර නොමැති ඒවා සඳහා `0.0000000000`), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, සහ `X-OmniRoute-Fallback-Attempts` (> 0 විට පමණි), ඊට අමතරව `X-OmniRoute-Request-Id` සහ `X-OmniRoute-Version`. මේවා chat completions, `/v1/responses`, `/v1/messages`, **සහ media endpoints** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, සහ `/v1/moderations` (පිරිවැය සැමවිටම `0`) — මඟින් නිකුත් කෙරේ. මිලකරණය ලබාගත හැකි විට media පිරිවැය modality එක අනුව (එක් image එකකට, එක් second එකකට, එක් character එකකට, එක් search-unit එකකට) ගණනය කෙරෙන අතර, එසේ නොමැති නම් එය `0` වේ (fail-open).

> **Cache-hit පිරිවැය අර්ථකථනය:** semantic-cache HIT එකකදී (`X-OmniRoute-Cache-Hit: true`) upstream call එකක් සිදු නොවන බැවින්, `X-OmniRoute-Response-Cost` අගය `0.0000000000` වේ (hit එක සපයන විට ඇතිවන **අමතර** පිරිවැය). මුල්/වීමට තිබූ පිරිවැය `X-OmniRoute-Cost-Saved` තුළ වෙනම වාර්තා කෙරේ. Billing භාවිත කරන්නන් `X-OmniRoute-Response-Cost` අගයන් එකතු කළ යුතුය (hits සඳහා කිසිදු පිරිවැයක් නැත); cache analytics සඳහා `X-OmniRoute-Cost-Saved` අගයන් සමස්ත කළ හැක.

## අනන්ය කළමනාකෘත සැසි කල්බදු

අනන්ය කළමනාකෘත සැසි කල්බදු කිරීම යනු තෝරා භාවිත කළ හැකි, සේවාලාභියාට-ස්වාධීන මාර්ගගත කිරීමේ ගිවිසුමකි: එක් සක්රිය හිමිකරුවෙකු සුදුසුකම් ලත් එක් OmniRoute සම්බන්ධතාවක් රඳවා ගනී. එය ආකෘතියක් කල්බදු නොදෙයි, OAuth අවශ්ය නොකරයි, නිශ්චිත සේවාලාභියෙකු හඳුනා නොගනී, හෝ නිශ්චිත සැපයුම්කරුවෙකු අවශ්ය නොකරයි.

සත්යාපනය කරන API යතුරට `lease:exclusive` විෂය පථය සහ පැහැදිලිව දක්වා ඇති හිස් නොවන `allowedConnections` ලැයිස්තුවක් තිබිය යුතුය. දත්ත සමුදා විකෘති කිරීමේ සීමාව, යතුර සෑදීමේදී සහ අර්ධ යාවත්කාලීන කිරීම්වලදී මෙම ක්ෂේත්ර දෙකම එකට බලාත්මක කරයි.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

සාර්ථක අත්පත් කරගැනීමේ, අලුත් කිරීමේ සහ නිදහස් කිරීමේ ප්රතිචාර කාල මුද්රා, `state`, සහ නිශ්චිත ධන `generation` අගය නිරාවරණය කරයි, නමුත් තෝරාගත් සම්බන්ධතාව හෝ අක්තපත්ර කිසිවිටෙකත් නිරාවරණය නොකරයි. අලුත් කිරීම සහ නිදහස් කිරීම JSON අන්තර්ගතය තුළ generation අගය සපයයි:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

සක්රිය කල්බදු හිමිකරුවෙකුට තම වත්මන් බැඳීම සඳහා පෞද්ගලිකත්වයට ආරක්ෂිත දර්ශන පාරදත්ත පැහැදිලිව ඉල්ලා සිටිය හැකිය:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

මෙම තෝරා භාවිත කළ හැකි තත්ත්ව ක්රියාව, අපැහැදිලි හිමිකරු, සත්යාපිත කළමනාකෘත API යතුර, සහ නිශ්චිත සක්රිය generation අගය මඟින් එක් දත්ත සමුදා ගනුදෙනුවක් තුළ සීමා කර ඇත. `displayName` යනු හිස් ඉවත් කර සකස් කළ වින්යාසගත සම්බන්ධතා නාමය පමණි; ආරක්ෂිත වින්යාසගත නාමයක් නොමැති විට එය `null` වේ. OmniRoute කිසිවිටෙකත් ඒ වෙනුවට ඊමේල් ලිපිනයක් හෝ ජනනය කළ ගිණුම් අනන්යතාවක් භාවිත නොකරයි. සැපයුම්කරුගේ අගය සංවේදී නොවන දර්ශන ලේබලයක් වන අතර කිසිවිටෙකත් ජනනය කළ අනුකූල-සැපයුම්කරු හඳුනාගැනීමක් නොවේ. අක්තපත්ර, ටෝකන, කුකී, අමු සම්බන්ධතා හෝ API යතුරු හැඳුනුම්, හිමිකරු හැෂ්, සීමාකරණ රහස්, සහ අභ්යන්තර මාර්ගගත කිරීමේ දත්ත බැහැර කර ඇත.

වැරදි යතුර, වැරදි හිමිකරු, කල් ඉකුත් වූ generation අගය, නොපවතින, කල් ඉකුත් වූ, නිදහස් කළ, සහ අවලංගු කළ සෙවීම් සියල්ල සම්බන්ධතා පාරදත්ත නොමැතිව එකම `409 LEASE_FENCE_STALE` දෝෂය ලබා දෙයි. ධාරිතාව සඳහා රැඳී සිටීමේ ප්රතිචාරය ලැබූ සේවාලාභියෙකුට පරීක්ෂා කිරීමට සක්රිය බැඳීමක් නොමැත. මාර්ගගත කිරීම සක්රිය කල්බදුවක් සංක්රමණය කරන විට, එම generation අගයම වලංගුව පවතින අතර තත්ත්වය පරමාණුකව නව බැඳීම ලබා දෙයි, පැරණි එක කිසිවිටෙකත් ලබා නොදෙයි. අත්පත් කරගැනීමේ, අලුත් කිරීමේ, නිදහස් කිරීමේ, සහ රැඳී සිටීමේ ප්රතිචාර ඒවායේ පෙර ව්යුහයන්ම පවත්වා ගන්නා බැවින් පවතින සේවාලාභීන් වෙනස් නොවේ.

මෙම සේවාදායක ගිවිසුම සම්මත OpenAI Codex `/status` වෙනස් නොකරයි. සම්මත Codex දැනට එහි ආකෘති සැපයුම්කරු සහ ගොඩනඟා ඇති සත්යාපන/ගිණුම් තත්ත්වය වාර්තා කරන නමුත් අභිමත සැපයුම්කරු ගිණුම් පාරදත්ත නොපෙන්වයි; පසුකාලීන සේවාලාභී ඒකාබද්ධ කිරීමක් මෙම ක්රියාව කැඳවා `connection.displayName` පෙන්විය යුතු ආකාරය තීරණය කළ යුතුය.

ඉන්පසු සෑම කළමනාකෘත අනුමාන ඉල්ලීමක්ම පාලන ශීර්ෂ දෙකම සපයයි:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

සෑම සහය දක්වන උඩුගං උත්සාහයකටම වහා පෙර නිශ්චිත හිමිකරු, generation අගය, සක්රිය සම්බන්ධතාව, සහ සත්යාපිත API යතුර සීමා කරනු ලැබේ. වෙනත් යතුරක් සමඟ හිමිකරු සහ generation අගය නැවත භාවිත කිරීම, එම යතුර එකම සම්බන්ධතාවට අවසර දුන්නද අසාර්ථක වේ. අමු හිමිකරු අගයන් ස්ථිරව ගබඩා කිරීම, ලොග් කිරීම, ඉල්ලීම් සැණරුව තුළ රඳවා ගැනීම, හෝ උඩුගං වෙත යැවීම සිදු නොවේ.

තාවකාලික තරගකාරී තත්ත්වයකදී `Retry-After` සමඟ HTTP `429` සහ පහත ප්රතිචාරය ලැබේ:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

මෙම ප්රතිචාරයෙන් අදහස් වන්නේ සාමාන්ය සුදුසුකම් ලත් කට්ටලය හිස් නොවූ බවත්, සෑම නිදහස් අපේක්ෂකයෙකුම විදේශීය සක්රිය කල්බදුවක් විසින් රඳවාගෙන තිබූ බවත් පමණි. සහය නොදක්වන ආකෘති/සැපයුම්කරුවන්, ප්රතිපත්ති නොගැළපීම, සිසිලන කාලය, කෝටාව, සෞඛ්යය, සහ අනෙකුත් සාමාන්ය සුදුසුකම් අසාර්ථක වීම් ඒවායේ පවතින OmniRoute ප්රතිචාරම පවත්වා ගනී.

### `x-omniroute-compression`

සම්පීඩන සැලැස්ම සඳහා එක් එක් ඉල්ලීමට අදාළ අතික්රමණයකි. ඉහළම ප්රමුඛතාව — මාර්ගගත කිරීමේ කොම්බෝ අතික්රමණය, සක්රිය පැතිකඩ, ස්වයංක්රීය ප්රේරකය, සහ පැනලයේ පෙරනිමිය අභිබවා යයි. අගයන්:

| අගය           | බලපෑම                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `off`         | මෙම ඉල්ලීම සඳහා සම්පීඩනයක් නොමැත.                                                                   |
| `default`     | පැනලයෙන් ලබාගත් පෙරනිමි පැතිකඩයි (සක්රිය පැතිකඩ නොසලකා හරී). දත්ත හානි කරන එන්ජින් අක්රියව තබයි.    |
| `safe`        | අනුපිටපත් ඉවත් කිරීම සහ හිස් අවකාශ හකුළීම පමණි.                                                     |
| `allow-lossy` | සාරාංශ සහ ශෛලීය නැවත ලිවීම් ඇතුළුව, මෙම ඉල්ලීම සඳහා ක්රියාකරුගේ සැලැස්ම පවත්වා ගනී.                 |
| `engine:<id>` | සක්රිය කර ඇති විට එක් එන්ජිමක්, උදා. `engine:rtk`. එම එන්ජිම සඳහා එක් එක් ඉල්ලීමට අදාළ තෝරාගැනීමකි. |
| `<combo>`     | පළමුව නාමය අනුව (අකුරු ප්රමාණය නොසලකා), පසුව id අනුව ගළපන ලද නම් කළ කොම්බෝවකි.                      |

සටහන්:

- නොදන්නා අගයන් නොසලකා හරිනු ලැබේ (ඉල්ලීම කිසිවිටෙකත් ප්රතික්ෂේප නොවේ); නිරාකරණය සාමාන්ය ක්රියාකරු ප්රමුඛතා අනුපිළිවෙළ වෙත යොමු වේ.
- කොම්බෝ කිහිපයකට එකම නාමය තිබේ නම්, නියත ගැළපීමක් සඳහා කොම්බෝවේ **id** ලබා දෙන්න.
- නාමය `off` හෝ `default` වන කොම්බෝවක් නාමයෙන් තෝරාගත නොහැක (එම මූලපද පළමුව අර්ථකථනය කරනු ලැබේ); එවැනි කොම්බෝවක් එහි id මඟින් යොමු කරන්න.
- ප්රධාන සම්පීඩන ස්විචය දැඩි දොරටුවකි: සම්පීඩනය ගෝලීයව අක්රිය කර ඇති විට, මෙම ශීර්ෂයට එය සක්රිය කළ නොහැක.

යොදන ලද සැලැස්ම ප්රතිචාර ශීර්ෂය තුළ නැවත ලබා දෙයි:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

මෙහි `<source>` යනු `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, හෝ `off` යන අගයන්ගෙන් එකකි.

## Embeddings

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

ලබා ගත හැකි සපයන්නන්: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

නාමාවලි හැඳුනුම් `provider/model` ආකෘතියෙන් ඇත (උදාහරණය: `jina-ai/jina-embeddings-v5-omni-small`). රෙජිස්ට්රියේ දිස්වන සපයන්නාගේ නම රහිත Jina ආකෘති හැඳුනුම් (උදාහරණයක් ලෙස `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) ද නිවැරදිව විසඳේ. Jina embed/rerank/classify/segment සඳහා පළමුව dashboard `jina-ai` අක්තපත්ර භාවිත කරයි; dashboard යතුරක් නොමැති විට පමණක් `JINA_AI_API_KEY` පසුබැසි විකල්පයක් ලෙස භාවිත වේ. `jina-reader` කාඩ්පත Reader / `r.jina.ai` සඳහා පමණක් (`POST /v1/web/fetch`) වන අතර කිසිවිටෙක embeddings හෝ rerank සපයන්නේ නැත.

බහුමාධ්ය සහාය දක්වන බව සඳහන් කරන රෙජිස්ට්රි ආකෘති, සපයන්නාගෙන් ස්වාධීන ව්යුහගත
අයිතම 32ක් දක්වා ද පිළිගනී. මාධ්ය අයිතම වර්ග වන්නේ `text`, `image`, `audio`, `video`, සහ `document` ය. ඒවායේ මාධ්ය `source`
එක `{"type":"url","url":"https://..."}` හෝ
`{"type":"base64","data":"...","media_type":"..."}` වේ.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
සහ පවුල් අන්වර්ථ නාමය `jina-ai/jina-embeddings-v5-omni` → omni-small) Jina හි ස්වදේශීය
EmbeddingsV5Request ලේඛන ද පිළිගෙන ඒවා `https://api.jina.ai/v1/embeddings` වෙත **වෙනස් නොකර යොමු කරයි**:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

ස්වදේශීය `{ image | audio | video | pdf }` අගයන් පොදු HTTPS URL එකක්, `data:` URI එකක්, හෝ අමු
base64 දත්ත විය හැක. OmniRoute එම වස්තු තන්තු බවට පත් කරන්නේ හෝ ස්වදේශීය රූප URL ලබාගන්නේ නැත — Jina විසින්ම
පොදු මාධ්ය ලබාගනී. අමතර Jina ක්ෂේත්ර (`task`, `normalized`, `truncate`, `embedding_type`)
යොමු කරනු ලැබේ. පෙළ-පමණක් සහිත Jina SKU තවමත් පෙළ නොවන ලේඛන ප්රතික්ෂේප කරයි.

ආරක්ෂක සහ ප්රවාහන සීමා:

- දුරස්ථ මාධ්ය URL පොදු HTTPS විය යුතුය. සම්මත `{type,source:url}` අයිතම
  සේවාදායක පාර්ශ්වයෙන් ලබාගෙන (යළි-යොමු නැවත වලංගු කිරීම, කාල සීමාව, ප්රමාණ සීමා, පොදු DNS, සම්බන්ධතා ස්ථාපනය)
  සපයන්නා වෙත කරන ඇමතුමට පෙර පේළිගත කරනු ලැබේ. Jina-ස්වදේශීය `{image:"https://..."}` අයිතම එම
  පොදු-HTTPS පරීක්ෂාවෙන් පසු ඒ ආකාරයෙන්ම යොමු කරනු ලැබේ; Jina URL එක ලබාගනී.
- පේළිගත base64 මාධ්ය එක් අයිතමයකට විකේතනය කළ 8 MiB දක්වාත්, ඉල්ලීම පුරා විකේතනය කළ 16 MiB දක්වාත් සීමා වේ.

සපයන්නාට අදාළ පරිවර්තනය (සම්මත අයිතම කිසිවිටෙක වෙනස් නොකර යොමු නොකෙරේ):

- Jina බහුමාධ්ය ආකෘති: සෑම ඉහළ-මට්ටමේ අයිතමයක්ම, පේළිගත මාධ්ය සඳහා data URI භාවිත කරමින්,
  මාධ්ය වර්ග යතුරක් සහිත එක් වස්තුවක් (`text` / `image` / `audio` / `video` / `pdf`) බවට පත් වේ; එක්
  ඉහළ-මට්ටමේ අයිතමයකට එක් දෛශිකයකි.

### ආකෘති හැඳුනුම් උපසර්ග (`?prefix=`)

බොහෝ ආකෘති **සපයන්නාගේ උපසර්ගයක්** යටතේ ප්රකාශයට පත් කෙරේ. ඔබට ලැබෙන උපසර්ගය
`MODELS_CATALOG_PREFIX_MODE` විශේෂාංග සලකුණ මඟින් පාලනය වන අතර, query පරාමිතියක් මඟින්
**එක් එක් ඉල්ලීම සඳහා** එය අභිබවා යා හැක — අනෙක් සියලු දෙනා සඳහා සේවාදායකය පුරා ඇති
සැකසුම වෙනස් නොකර පිරිසිදු ලැයිස්තුවක් අවශ්ය client එකකට මෙය ප්රයෝජනවත් වේ:

```bash
GET /v1/models?prefix=alias        # එක් ආකෘතියකට එක් හැඳුනුමක් — කෙටි alias උපසර්ගය
GET /v1/models?prefix=dual         # ආකාර දෙකම (සේවාදායකයේ පෙරනිමිය)
GET /v1/models?prefix=canonical    # සම්පූර්ණ provider-id උපසර්ගය පමණි
```

| ----------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `canonical` | `claude/claude-sonnet-4-6`                               | සම්පූර්ණ provider-id උපසර්ගය යටතේ එක් ආකෘතියකට එක් ප්රවේශයක්. වෙනස් alias එකක් නොමැති සපයන්නන් (උදා. `antigravity/…`, `agy/…`) ද මෙහි තම තනි හැඳුනුම නිකුත් කරන බැවින් කිසිවක් නැති නොවේ. |

query පරාමිතිය නොමැතිව වුවද `dual`-ප්රකාරයේ mirror එකක් හඳුනාගත හැක: එය ප්රධාන
හැඳුනුම වෙත යොමු කරන `parent` ක්ෂේත්රයක් දරයි.

ආකෘති තේරීම්කාරකයක් පෙන්වන clients විසින් `?prefix=alias` ඉල්ලා සිටිය යුතුය —
[OmniCopilot VS Code extension](../guides/VSCODE-COPILOT.md) එක කරන්නේ මෙයයි.

### සොයාගැනීමේ පෙරහන් (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` මඟින් කැමැත්තෙන් සක්රිය කළ හැකි සොයාගැනීමේ පෙරහන් පිළිගනී. ඒ කිසිවක් නොමැතිව
ප්රතිචාරය වෙනස් නොවේ. ඒවා caller වෙත දැනටමත් පෙනෙන catalog එක පටු කරයි (පළමුව API-key අවසර
අදාළ වේ), තවද ඒවා OpenAI-ශෛලියේ `limit` / `after` paging කිරීමට පෙර ක්රියාත්මක වේ:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # ලැයිස්තුගත සෑම හැකියාවක්ම true විය යුතුය
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # catalog `type`; එකක් නොමැති පේළි `chat` වේ
GET /v1/models?q=sonnet&limit=10                           # හැඳුනුම හෝ නම මත අකුරු විශාලත්වය නොසලකා ගැළපීම
```

| පරාමිතිය      | අගයන්                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | ඍණ නොවන පූර්ණ සංඛ්යාවක්, `context_length` සමඟ සසඳනු ලැබේ                                            |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | අක්ෂර 1–200                                                                                         |

නොදන්නා අගයක් හෝ ඍණ නොවන පූර්ණ සංඛ්යාවක් නොවන `min_context` අගයක් (උදාහරණයක් ලෙස `1.5`)
HTTP `400` ආපසු ලබා දෙන අතර පණිවිඩයේ වලංගු අගයන් ලැයිස්තුගත වේ. ක්රියාත්මක කිරීම:
`src/app/api/v1/models/catalogFilters.ts`.

### ආකෘති කෙටි ලැයිස්තුව (`POST /v1/models/query`)

`POST /v1/models/query` මඟින් `GET /v1/models` හා සමාන සත්යාපනය සහ එක් key එකකට අදාළ දෘශ්යතාව
සහිතව, එම catalog එකෙන්ම කෙටි, නියත ලැයිස්තුවක් ආපසු ලබා දෙයි:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

සෑම ක්ෂේත්රයක්ම අත්යවශ්ය නොවේ. `capabilities` සහ `exclude` සඳහා array එකක් හෝ කොමාවලින් වෙන් කළ string එකක්
ලබා දිය හැක; `max_output` අගය `max_output_tokens` සමඟ සසඳයි. ප්රතිඵල පළමුව `owned_by` අනුවත්, ඉන්පසු `id`
අනුවත් අනුපිළිවෙළට සකසනු ලැබේ. `limit` හි පෙරනිමි අගය `20` වන අතර `100` ඉක්මවන අගයන් `100` දක්වා සීමා කෙරේ.
වලංගු නොවන JSON, නොදන්නා ක්ෂේත්රයක් හෝ වලංගු නොවන අගයක් HTTP `400` ආපසු ලබා දෙයි.

### තනි තනිව සඟවා ඇති කතාබස් ආකෘති

තම සපයන්නාගේ පිටුවේ **සඟවා ඇත** ලෙස සලකුණු කළ ආකෘතියක් catalog එකෙන් ඉවත් කරන අතර, පැහැදිලිව ඉල්ලා සිටින
විට HTTP `404` / `model_not_found` සමඟ ප්රතික්ෂේප කරයි. පරීක්ෂාව විසඳාගත් සපයන්නා සහ ආකෘතිය භාවිත කරන අතර,
එයට provider aliases, compatible-provider node උපසර්ග සහ connection පෙරනිමි ද ඇතුළත් වේ. combo එකක් සඟවා ඇති
ඉලක්ක මඟහැර දෘශ්ය sibling එකක් භාවිත කළ හැක; ක්රියාත්මක කළ හැකි කිසිදු ඉලක්කයක් ඉතිරි නොවන විට එය එම error
code එකම ආපසු ලබා දෙයි. සැඟවීම ඉවත් කිරීම ඊළඟ ඉල්ලීමේ සිට ක්රියාත්මක වේ. රූපවලට පමණක් අදාළ දෘශ්යතා overrides,
එම ID එක සහිත කතාබස් ආකෘතිය සඟවන්නේ නැත.

මෙම තනි ආකෘති සැකසුම, පැහැදිලි dispatch රඳවා තබා ගනිමින් catalog ප්රචාරණය සහ auto-routing අපේක්ෂකයන් පෙරහන් කරන
[ආකෘති නිරාවරණ allow/deny ලැයිස්තු](../routing/MODEL_EXPOSURE_LIST.md) වෙතින් වෙනස් වේ. API-key ආකෘති අවසර
ස්වාධීනව දිගටම අදාළ වේ. පෙරනිමි catalog උපසර්ග ප්රකාරය `dual` ලෙසම පවතී.

### සිතීම-රහිත ආකෘති ප්රභේද

සිතීමේ හැකියාව ඇති Claude ආකෘති සඳහා, `/v1/models` විසින් හැඳුනුමට `claude-3-omniroute-no-thinking/` උපසර්ගය යෙදූ
**සිතීම-රහිත** ප්රභේදයක් ද ප්රචාරණය කරයි:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

මෙම id එක තේරීමෙන් (උදාහරණයක් ලෙස, සෑම විටම `thinking` block එකක් අමුණන Claude Code config එකකදී) reasoning අක්රිය කර සැබෑ `<provider>/<model>` වෙත නැවත යොමු වේ — `/v1/messages` path එකේ `thinking:{type:"disabled"}` භාවිතයෙන් හෝ `/v1/chat/completions` path එකේ `reasoning`/`reasoning_effort` fields ඉවත් කිරීමෙන්. මෙම ප්රභේදය ලැයිස්තුගත කරන්නේ thinking සඳහා සහය දක්වන **සහ** `disabled` පිළිගන්නා Claude-family models සඳහා පමණි (එබැවින්, උදාහරණයක් ලෙස, `disabled` ප්රතික්ෂේප කරන adaptive-only models ඇතුළත් නොවේ). ක්රියාකරුවන්ට එක් එක් model එක සඳහා `ModelSpec.noThinkingAlias` හරහා මෙම ප්රභේදය බලහත්කාරයෙන් සක්රිය හෝ අක්රිය කළ හැක.

Exa සහ Tavily, නාමාවකාශගත එකතුවකින් සැපයුම්කරුට විශේෂිත ක්ෂේත්ර කියවයි:
`provider_options.exa` (හෝ `provider_options["exa-search"]`) සහ `provider_options.tavily`
(හෝ `provider_options["tavily-search"]`). පහත යතුරු පමණක් ඉදිරියට යවනු ලැබේ. සෑම යතුරක්ම
`open-sse/handlers/search/providerOptionsPassthrough.ts` තුළ ඇති එයටම අදාළ Zod යෝජනා ක්රමයට එරෙහිව
පරීක්ෂා කෙරෙන අතර, වැරදි වර්ගයක් සහිත යතුරක් ඉවත් කෙරේ. සත්යාපනය, මූලික URL,
`stream` සහ `outputSchema` ඇතුළුව වෙනත් ඕනෑම යතුරක් නොසලකා හරිනු ලැබේ. වෙනත් සැපයුම්කරුවන් භාවිත කරන
පැතලි යතුරු (`cx`, `depth`, ...) පෙර පරිදිම ක්රියා කරයි.

| සැපයුම්කරු | ඉහළ මට්ටමේ ක්ෂේත්ර                                                                                                                                                                                                                                                                                                                                                        | කැදලිගත                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa        | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (පැතලි ප්රාථමික අගයන්), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                         | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` පෙරනිමි `{ text: true, highlights: true }` මත ඒකාබද්ධ කෙරේ |

සාමාන්ය ක්ෂේත්ර සෑම විටම ප්රමුඛත්වය ගනී: `query`, `max_results`, `filters` (වසම්), `country` සහ
`search_type` වෙතින් ව්යුත්පන්න වන මාතෘකාව. Exa හිදී, `search_type: "news"` මඟින් `category: "news"` එලෙසම තබා ගනී.
Tavily ද `search_type: "finance"` (`topic: "finance"`) පිළිගනී.

සාමාන්ය `time_range` දැන් සැපයුම්කරුවන් දෙදෙනාටම ළඟා වේ: Exa වෙත `startPublishedDate` (ISO
කාලමුද්රාව) ලැබෙන අතර Tavily වෙත `start_date` (`YYYY-MM-DD`) ලැබේ. `provider_options`
තුළ පැහැදිලිව සඳහන් කළ දිනයක් සිතියම්ගත කළ දිනය අභිබවා යයි.

Exa ප්රතිඵල `provider_raw` තුළ `id`, `highlight_scores`, `summary`, `subpages`, `entities` සහ `extras`
රඳවා ගනී. Tavily ප්රතිඵල `images` සහ `favicon` රඳවා ගනී.

පිරිවැය ගිණුම්කරණය තවමත් පැතලි ලේඛකාධිකාරය වන `costPerQuery` භාවිත කරයි. Tavily හි
`search_depth: "advanced"` සඳහා එක් ඇමතුමකට වැඩි ණය ප්රමාණයක් අය කෙරෙන අතර, එම වෙනස
`usage.search_cost_usd` තුළ පිළිබිඹු නොවේ.

## Web Fetch API

වින්යාස කළ web-fetch සපයන්නෙකු (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract) හරහා URL එකකින් අන්තර්ගතය උපුටා ගන්න.

Parallel Extract (`parallel-search`, Parallel Search සඳහා භාවිත කරන API යතුරම) Markdown
පමණක් ආපසු ලබා දෙයි — වෙනත් ඕනෑම `format` එකක් `400` ප්රතිචාරයක් ලබා දෙයි — සහ අන්තර්ගතය අක්ෂර 100,000කට සීමා කරයි. ඉලක්ක පිටුවම
උපුටා ගත නොහැකි විට, upstream සේවාව HTTP 200 ප්රතිචාරයක් තුළ ඒ බව වාර්තා කරයි;
OmniRoute එය ස්ථාවර පණිවිඩයක් සහිත `422` ප්රතිචාරයක් ලෙස ඉදිරිපත් කරයි.

| ක්රමය | මාර්ගය          | විස්තරය                                                                       |
| ----- | --------------- | ----------------------------------------------------------------------------- |
| POST  | `/v1/web/fetch` | URL එකක් ලබා ගැනීම/scrape කිරීම — body එක `v1WebFetchSchema` මඟින් වලංගු කෙරේ |

**සත්යාපනය:** Bearer API යතුර (`extractApiKey` + `isValidApiKey`). ප්රතිපත්තිය `enforceApiKeyPolicy` හරහා බලාත්මක කෙරේ.

**Quota-aware fallback (#8297):** පැහැදිලි `provider` එකක් ලබා දී නොමැති විට, pool එක
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) ස්ථාවර
ප්රමුඛතා අනුපිළිවෙළකට (fill-first) අනුව
පරීක්ෂා කෙරේ — rate limit වී ඇති නමුත් වින්යාස කර ඇති සපයන්නෙකු request එක එතැනින්ම අවසන් කිරීම වෙනුවට මඟ හරිනු ලබන අතර, නැවත උත්සාහ කළ හැකි/quota සම්බන්ධ upstream අසාර්ථකත්වයක්
(HTTP 429 සැමවිටම; Firecrawl/Tavily/TinyFish හි quota ආකාරයේ free tiers සඳහා 402/403 —
Jina Reader සඳහා නොවේ, සහ සාමාන්ය 400 bad request එකක් සඳහා කිසිවිටෙකත් නොවේ) request එක ක්රියාත්මක වන අවස්ථාවේ මීළඟ, තවම උත්සාහ නොකළ සහ අක්තපත්ර සහිත සපයන්නා වෙත යොමු වේ. Pool එකේ සියලුම සපයන්නන්
අවසන් වූ විට, endpoint එක පෙර පැවති සාමාන්ය `400` වෙනුවට එක් `429` ප්රතිචාරයක් (`Retry-After`
header එකක් සමඟ) ලබා දෙයි. පැහැදිලි `provider` එකක්
ඉල්ලා ඇති විට, නිහඬ fallback එකක් **නොමැත** — rate limit වූ හෝ අසාර්ථක වූ පැහැදිලි
සපයන්නාගේම දෝෂය ඉදිරිපත් කෙරේ (rate limit වී ඇත්නම් `429`, එසේ නොමැති නම් upstream
status එක).

## WebSocket Streaming

```bash
GET /v1/ws?handshake=1
```

WebSocket upgrade handshake එකක් වලංගු කර wire protocol උදාහරණ පණිවිඩ (`request`, `cancel`) ආපසු ලබා දෙයි. සැබෑ WS frames හසුරුවනු ලබන්නේ Next.js route table එකෙන් පිටත ඇති bundle කළ WS server එක මඟිනි.

**සත්යාපනය:** Handshake අවස්ථාවේ Bearer API යතුර.

### WebSocket හරහා Responses API (codex සඳහා පමණි)

```bash
# HTTP API එකේ host:port එකම භාවිත කරන්න (පෙරනිමිය 20128); සම්බන්ධතාව upgrade කරන්න:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (හෝ: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# පළමු frame එක response.create විය යුතුමය:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Responses-API-over-WebSocket proxy එකක් **`codex` වෙත පමණක්** සම්බන්ධ කර ඇත (ChatGPT
backend). එය API/dashboard එක භාවිත කරන port එකේම `/v1/responses`,
`/responses`, සහ `/api/v1/responses` යන මාර්ගවලට සවන් දෙයි. පළමු `response.create` frame එක ලැබුණු විට, එය
අභ්යන්තර `codex-responses-ws` bridge එක හරහා සත්යාපනය කර සූදානම් කරයි, codex OAuth සම්බන්ධතාවක් තෝරා,
`wreq-js` transport එක හරහා `wss://chatgpt.com/backend-api/codex/responses`
වෙත tunnel කරයි. **codex නොවන models ප්රතික්ෂේප කෙරේ** (`codex_ws_provider_required`).
Quota-share routing සඳහා `model: "qtSd/<group>/codex/<model>"` භාවිත කරන්න. මෙය
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts` තුළ ක්රියාත්මක කර ඇත.

**සත්යාපනය:** Handshake අවස්ථාවේ Bearer API යතුර. Bundle කළ HTTP server එක (`server-ws.mjs`)
සක්රිය entrypoint එක විය යුතුය (`app/server-ws.mjs` පවතින විට පෙරනිමියෙන් එය එසේ වේ).

#### Model id: මූලික ChatGPT id එක භාවිත කරන්න (`codex/` prefix එක නොමැතිව)

OpenAI **Codex CLI** එක `supports_websockets = true` වන විට client-side හි model නාමය වලංගු කර,
`codex/gpt-5.5` වැනි **provider-prefixed ids ප්රතික්ෂේප කරයි**

## ස්වයං-සේවා භාවිතය (`/api/usage/om-usage`)

ඕනෑම API යතුරකට කළමනාකරණ සත්යාපනයකින් තොරව **තමන්ගේම** භාවිතය සහ කෝටා කියවිය හැක. යතුරු හිමිකරුවෙකුට ඔවුන්ගේ වියදම පෙන්වීමට සේවාලාභියෙකු (CLI, OmniCopilot පැනලය) භාවිත කරන අන්ත ලක්ෂ්යය මෙයයි.

```bash
# පෙළ ආකෘතිය (ඓතිහාසික ගිවිසුම — ටර්මිනලයක් සඳහා සරල පෙළ)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# ව්යුහගත ආකෘතිය — UI එකක් භාවිත කරන්නේ මෙයයි
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

යතුර සඳහා **`allowUsageCommand`** සක්රීය කර තිබිය යුතුය (පෙරනිමියෙන් අක්රීයයි — උපකරණ පුවරුවේ API-යතුරු කළමනාකරු එය එක් එක් යතුර සඳහා ටොගල් කරයි). එය නොමැති නම් අන්ත ලක්ෂ්යය `403` සමඟ පිළිතුරු දෙයි.

ඇමතුම්කරු ප්රතික්ෂේප කිරීමකදී දත්ත ක්ෂේත්රයක් නොකියවන බව සහතික කිරීම සඳහා `?format=json` විභේදිත ව්යුහයක් ආපසු ලබා දෙයි. සාර්ථක වූ විට:

```jsonc
{
  "allowed": true,
  // එක් එක් යතුරට අදාළ භාවිත සීමා (දෛනික/සතිපතා USD) සඳහා යතුර එකඟ වී ඇති විට පමණක් පවතී:
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // තෝරාගත් සැපයුම්කරුගේ කෝටා ස්නැප්ෂොට් එක, නැතහොත් තවම කිසිවක් හැඹිලිගත කර නොමැති විට null:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // UI එකකට සැපයුම්කරුවන් කිහිපදෙනෙකු එකිනෙකට යාබදව නිරූපණය කළ හැකි වන පරිදි සෑම සම්බන්ධතාවකම ස්නැප්ෂොට් එක:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

ප්රතික්ෂේප කිරීමකදී (`401` වැරදි යතුර / `403` අවසර නැත) එම මාර්ගයම
`{ "allowed": false, "error": { "message": "…" } }` ආපසු ලබා දෙයි — පවතින නමුත් හිස් `personal`/`provider`
(යතුරට අවසර ඇත, තවම කිසිවක් අනාවරණය වී නැත) යනු ප්රතික්ෂේප කිරීමකට වඩා වෙනස් තත්ත්වයක් වන අතර ඒවා වෙන්කර හඳුනාගන්නේ JSON ආකෘතිය පමණි.

**සත්යාපනය:** `isValidApiKey` සමඟ වලංගු කරන ලද ඇමතුම්කරුගේම Bearer API යතුර — මෙය
`requireManagementAuth` මඟින් ආරක්ෂා වන කළමනාකරණ පෘෂ්ඨය (`/api/keys/…`) _නොවේ_.

#### කඩඉම් ගැළපුම් සූත්රය

උඩුගං සම්පත් අවසන් වීම වැළැක්වීම සඳහා OmniRoute පූර්වක්රියාකාරී කෝටා කඩඉම් සඳහා සහාය දක්වයි (සම්බන්ධතාවේ
`quotaWindowThresholds`, සැපයුම්කරුගේ පෙරනිමි, හෝ ගෝලීය ප්රත්යස්ථතා සැකසුම් හරහා වින්යාස කර ඇත). කෝටා කවුළුවක් මත කඩඉම් සීමාවක්
(උදා., `cutoff = 25%`) සක්රීය වූ විට, පෙළ නිරූපකය ඉතිරි දීමනාව මෙසේ ගණනය කරයි:

- `remaining <= cutoff` නම්: `0%` ආපසු ලබා දෙයි.
- `remaining > cutoff` නම්: `((remaining - cutoff) / (100 - cutoff)) * 100` ආපසු ලබා දෙයි.

ආකෘතිගත පෙළ ප්රතිදානය මෙය ආසන්නතම පූර්ණ සංඛ්යාවට වට කරයි (`Math.round(...)`).

#### නිදර්ශනාත්මක උදාහරණය

**60% අමු භාවිතයක්** (එබැවින් **40% අමු ඉතිරි කෝටාවක්**) සහ වින්යාස කළ
**25% ඉතිරි-කෝටා කඩඉම්** සීමාවක් සහිත සැපයුම්කරු කවුළුවක් සලකා බලන්න:

| නිරූපණය                       | ගණනය                                               | ඉතිරිය  |                ඇඟවෙන භාවිතය                 |
| :---------------------------- | :------------------------------------------------- | :-----: | :-----------------------------------------: |
| **අමු JSON (`?format=json`)** | උඩුගං ස්නැප්ෂොට් එක (`quotas[window]`)             | **40%** |                   **60%**                   |
| **පෙළ ආකෘතිය (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (`100 - remaining` ගණනය කරන්නේ නම්) |

- **පෙළෙහි 20% ඉතිරි බව පෙන්වන්නේ ඇයි:** ගිණුමේ භෞතිකව ඉතිරිව ඇති 40% කෝටාවෙන් 25%ක් කඩඉම්
  ප්රතිපත්තිය මඟින් සංචිත කර ඇත. රවුටරය මෙම සම්බන්ධතාව වෙත රවුට් කිරීම නවත්වන තෙක් ඇමතුම්කරුට ඉතිරිව ඇත්තේ භාවිත කළ හැකි 75% අවකාශයෙන් 15%ක් පමණි.
  රවුට් කිරීම නවත්වන නිශ්චිත මොහොතේම සම්බන්ධතාව සම්පත් අවසන් වීම (`0% left`) සංඥා කරන බව පරිමාණනය සහතික කරයි.
- **JSON අමු අගයන් රැකගන්නේ ඇයි:** බාහිර මෙවලම්වලට සැබෑ උඩුගං භාවිතය සහ සම්බන්ධතා මට්ටමේ
  `quotaWindowThresholds` වෙත ප්රවේශය ලැබෙන පරිදි JSON පේලෝඩය නිශ්චිත සැපයුම්කරු ස්නැප්ෂොට් එක (`UsageSnapshot`)
  සේවාදායක පාර්ශ්වයේ දත්ත-අහිමි පරිමාණනයකින් තොරව ආපසු ලබා දෙයි.

#### පාරිභෝගික සංක්රමණ මාර්ගෝපදේශය

බාහිර අනුකලනයක් (සංස්කාරක ප්ලගිනයක් හෝ නියෝජිත දිගුවක් වැනි) මීට පෙර පෙළ
අන්ත ලක්ෂ්යයෙන් (`NN% left`) දත්ත උකහාගෙන, භාවිත කළ ප්රතිශතය `100 - NN` ලෙස ගණනය කළේ නම්, `?format=json` වෙත සංක්රමණය වීමෙන් අදහස් වන්නේ:

- අමු JSON අගයන් කියවීමෙන් **සැබෑ උඩුගං පරිභෝජනය** පිළිබිඹු වනු ඇත (ඉහත උදාහරණයේ 60%ක් භාවිත කර ඇත).
- අනුකලනයට පෙළ අන්ත ලක්ෂ්යයේ භාවිත කළ හැකි දීමනා අර්ථ විවරණය සුරැකීමට අවශ්ය නම්, සම්බන්ධතා මට්ටමේ අතික්රමණ සඳහා `quotaWindowThresholds` භාවිත කරමින්
  ඵලදායී ඉතිරි ප්රමාණය ගණනය කිරීමේ සූත්රය සේවාලාභී පාර්ශ්වයේදී ඇගයීමට එයට හැකිය.

## අර්ථානුකූල හැඹිලිය

```bash
# හැඹිලි සංඛ්යාලේඛන ලබා ගන්න
GET /api/cache/stats

# සියලු හැඹිලි හිස් කරන්න
DELETE /api/cache/stats
```

ප්රතිචාර උදාහරණය:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### ප්රමාදයට ඇති බලපෑම

අර්ථානුකූල හැඹිලි HIT එකකදී ප්රතිචාරය **උඩුගං ඇමතුමකින් තොරව**
හැඹිලියෙන් සපයන බැවින්, වාර්තා කරන `X-OmniRoute-Response-Latency` අගය
(මුල් උඩුගං ප්රමාදය කුමක් වුවත්) ශුන්යයට ආසන්න වේ. ප්රමාදයට සංවේදී
සේවාලාභීන් (මිණුම් සලකුණු කිරීම, p50/p99 අධීක්ෂණය) පහත
`X-OmniRoute-Cache-Latency` ප්රතිචාර ශීර්ෂය පරීක්ෂා කළ යුතුය:

| අගය         | අර්ථය                                                      |
| ----------- | ---------------------------------------------------------- |
| `synthetic` | ප්රතිචාරය හැඹිලියෙන් සපයා ඇත; ප්රමාදය සැබෑ උඩුගං කාලය නොවේ |
| _(නොමැති)_  | සැබෑ උඩුගං ඇමතුමකින් ලැබුණු ප්රතිචාරයකි                    |

### යතුරකට අදාළ හැඹිලි මඟහැරීම

API යතුරුවලට `cacheDefaultMode` හරහා අර්ථානුකූල හැඹිලි කියවීම්වලින් ඉවත් විය හැකිය:

| අගය      | හැසිරීම                                                    |
| -------- | ---------------------------------------------------------- |
| `legacy` | සාමාන්ය හැඹිලි හැසිරීම (පෙරනිමි)                           |
| `bypass` | හැඹිලි සෙවීම සම්පූර්ණයෙන් මඟහරින්න; සැමවිටම උඩුගං වෙත යන්න |

යතුර සෑදීමේදී (`POST /api/keys`) සකසන්න, නැතහොත් (`PATCH /api/keys/[id]`) යාවත්කාලීන කරන්න:

```json
{ "cacheDefaultMode": "bypass" }
```

### එක් එක් ඉල්ලීම සඳහා මඟහැරීම

යතුරු සැකසුම් නොසලකා ඕනෑම ඉල්ලීමකට හැඹිලිය මඟහැරිය හැකිය:

```
X-OmniRoute-No-Cache: true
```

අදියර දෙකම තම ප්රේරණ, සම්පූර්ණ කිරීමේ සීමා, නැවතුම් අනුක්රම, සහ සැබෑ උඩුගං අවසර
තීන්දු රඳවා ගනී; දෙවන අදියරට තවමත් එය ඉල්ලා ඇති දෘශ්ය තර්කනය සාමාන්ය පෙළ ලෙස නිපදවිය හැක.

### API යතුරු අවසර

`PATCH /api/keys/{id}` මඟින් පවතින යතුරක අවසර යාවත්කාලීන කරයි. සෑම `/api/keys*` මාර්ගයක් මෙන්ම, එයට අවශ්ය වන්නේ කළමනාකරණ බලය පැවරීමයි ([කළමනාකරණ සත්යාපනය](../guides/MANAGEMENT-AUTH.md) බලන්න), අනුමාන යතුරක් නොවේ. ඔබට වෙනස් කිරීමට අවශ්ය ක්ෂේත්ර පමණක් යවන්න; ඒවා කිසිවක් නොමැති ඉල්ලීමක් `No valid fields to update` සමඟ ප්රතික්ෂේප කරනු ලැබේ. පිළිගන්නා ක්ෂේත්ර `src/shared/validation/schemas/keys.ts` තුළ ඇති `updateKeyPermissionsSchema` මඟින් අර්ථ දක්වා ඇත.

- `releaseChannel` — ධාවනය වන ගොඩනැගීමේ npm නාලිකාව: `-nightly.*` අනුවාද සඳහා `nightly`,
  අනෙකුත් පූර්ව නිකුතු (`-rc.*`, `-beta.*`, `-alpha.*`) සඳහා `next`, `channels.latest` ට වඩා පැරණි ප්රධාන
  අනුවාදයක ස්ථාවර අනුවාදයක් සඳහා `lts`, එසේ නොමැති නම් `latest`. ප්රකාශන අවස්ථාවේ npm dist-tag තෝරන
  `scripts/release/dist-tag.mjs` හි නීතිවලට සමාන නීති අදාළ වේ.

  HTTP විකල්ප ක්රමය), `latest` මෙන්ම මිනිත්තු 10ක TTL සමඟ හැඹිලිගත කර ඇත. `latest` සෑම විටම පවතී
  (පළමුව `latest` ක්ෂේත්රය වෙතත්, ඉන්පසු `"unavailable"` වෙතත් විකල්පව යොමු වේ); `next`, `nightly` සහ `lts` දිස්වන්නේ
  අදාළ dist-tag එක පවතින විට පමණි. `Cache-Control: no-cache` ඉල්ලීමක් මඟින් සෙවීම් දෙකම නැවුම් කරයි.

## ටෝකන් සීමා

එක් එක් API යතුර සඳහා **ටෝකන්** අයවැය (ඉහත USD මත පදනම් වූ අයවැයෙන් වෙනස් වේ). ඉල්ලීම් මාර්ගයේදීම බලාත්මක කෙරේ: යතුරක වත්මන් කාල කවුළුවේ භාවිතය එහි සීමාවට ළඟා වූ විට, ඉල්ලීම් `429 Too Many Requests` සමඟ ප්රතික්ෂේප කෙරේ. සීමා නිශ්චිත `model` එකකට හෝ `provider` එකකට සීමා කළ හැකිය, නැතහොත් යතුර පුරා `global` ලෙස යෙදිය හැකිය; සීමා කිහිපයක් ඉල්ලීමකට ගැළපෙන විට, වඩාත්ම සීමාකාරී එක බලපැවැත්වේ.

```bash
DELETE /api/usage/token-limits?id=tl-abc
```

> **යෝජනා ක්රම සටහන්** (`setTokenLimitSchema`): `apiKeyId` සහ `scopeType` (`model` | `provider` | `global`) අවශ්ය වේ. `scopeType` එක `global` නොවන විට `scopeValue` අවශ්ය වේ (උදා., `model` පරාසය සඳහා model id එකක්, `provider` පරාසය සඳහා provider id එකක්). `tokenLimit` ධන පූර්ණ සංඛ්යාවක් විය යුතුය (string එකකින් පරිවර්තනය කෙරේ). විකල්ප: `id` (සෑදීමට නොයොදන්න, යාවත්කාලීන කිරීමට සපයන්න), `resetInterval` (`daily` | `weekly` | `monthly`, පෙරනිමිය `monthly`), `resetTime` (`HH:MM`), `enabled` (පෙරනිමිය `true`). `GET` ප්රතිචාර සෑම සීමාවකටම `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, සහ `nextResetAt` එක් කර වැඩිදියුණු කරයි. මෙය කළමනාකරණ-පන්තියේ අන්ත ලක්ෂ්යයකි (සත්යාපන අවසර නළ මාර්ගය මඟින් සත්යාපනය මධ්යගතව බලාත්මක කෙරේ).

### අනුපාත-සීමා පෝලිම සහ ස්වයංක්රීය-සක්රිය කිරීමේ ආරක්ෂණ ජාලය

- **සහාය දක්වන ලිවීමේ මාර්ගය**: `{"connectionId": "<id>", "enabled": true|false}` අන්තර්ගතය සහිත `POST /api/rate-limits`, සම්බන්ධතාවක් සඳහා අනුපාත-සීමා ආරක්ෂාව මාරු කිරීමට සහාය දක්වන කළමනාකරණ අන්ත ලක්ෂ්යය වේ. `PUT /api/providers/[id]` හිතාමතාම `rateLimitProtection` වෙනස් කිරීම හෝ මාරු කිරීම සිදු නොකරයි (#11278).
- **`enabled: false` හි අර්ථ නිරූපණය**: `enabled: false` ලෙස සැකසීම සම්බන්ධතාව සඳහා පැහැදිලි ආරක්ෂාව ඉවත් කරයි, නමුත් සක්රිය API-key සම්බන්ධතාවක් ගෝලීය ස්වයංක්රීය-සක්රිය කිරීමේ ආරක්ෂණ ජාලයෙන් (`autoEnableApiKeyProviders = true`) **ඉවත් නොකරයි**. `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) තුළ, `false` සහ `undefined` සමාන වේ; පැහැදිලි ආරක්ෂාවක් නොමැති සක්රිය API-key සම්බන්ධතා ස්වයංක්රීය-සක්රිය කිරීමේ ආරක්ෂණ ජාලය යටතේ තවදුරටත් ආරක්ෂා වේ.
- **ගෝලීය අක්රිය කිරීම**: අනුපාත-සීමා පෝලිම් නොමැතිව API-key සම්බන්ධතා ධාවනය කිරීමට, `RATE_LIMIT_AUTO_ENABLE=false` (පරිසර විචල්යය) හෝ `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`) හරහා ආරක්ෂණ ජාලය ගෝලීයව අක්රිය කරන්න.

## MCP සේවාදායකය

OmniRoute තුළ transports 3ක් (stdio, SSE, streamable-http) සහ විෂය පථයට සීමා කළ tools සහිත, අන්තර්ගත Model Context Protocol සේවාදායකයක් සපයයි. පහත dashboard endpoints තත්ත්ව/audit දත්ත කියවා HTTP transports සඳහා proxy ලෙස ක්රියා කරයි.

| ක්රමය | මාර්ගය | විස්තරය |

## A2A සේවාදායකය

OmniRoute මඟින් A2A (Agent-to-Agent) JSON-RPC 2.0 අන්ත ලක්ෂ්යයක් සහ පරීක්ෂා කිරීම/උපකරණ පුවරුව සඳහා REST ආවරණයක් සපයයි.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # OMNIROUTE_API_KEY සකසා නොමැති නම් විකල්පයකි
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

සහාය දක්වන ක්රම (සියල්ල `settings.a2aEnabled` මඟින් පාලනය වේ):

| ක්රමය            | විස්තරය                                                                        |
| ---------------- | ------------------------------------------------------------------------------ |
| `message/send`   | සමමුහුර්ත කුසලතා ක්රියාත්මක කිරීම; `{task, artifacts, metadata}` ආපසු ලබා දෙයි |
| `message/stream` | එම කුසලතා කට්ටලයම ප්රවාහ SSE ආකාරයෙන් ක්රියාත්මක කිරීම                         |
| `tasks/get`      | `taskId` අනුව කාර්යයක් ලබාගැනීම                                                |
| `tasks/cancel`   | `taskId` අනුව කාර්යයක් අවලංගු කිරීම                                            |

අන්තර්ගත කුසලතා: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### නියෝජිත කාඩ්පත

```bash
GET /.well-known/agent.json
```

පොදු A2A නියෝජිත කාඩ්පත (නම, විස්තරය, හැකියාවන්, කුසලතා නාමාවලිය, සත්යාපන යෝජනා ක්රමය) ආපසු ලබා දෙයි — පොදු භාවිතය සඳහා 1h කාලයක් හැඹිලිගත කෙරේ. සත්යාපනය අවශ්ය නොවේ.

### REST උපකාරක

| ක්රමය | මාර්ගය                       | විස්තරය                                                                                                                     |
| ----- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| GET   | `/api/a2a/status`            | A2A සක්රීය තත්ත්වය + කාර්ය සංඛ්යාලේඛන + හැඹිලිගත නියෝජිත කාඩ්පත් සාරාංශය                                                    |
| GET   | `/api/a2a/tasks`             | කාර්ය ලැයිස්තුගත කිරීම — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST  | `/api/a2a/tasks`             | (REST උපකාරකයක් ලෙස ක්රියාත්මක කර නොමැත — JSON-RPC `message/send` හරහා සාදන්න)                                              |
| GET   | `/api/a2a/tasks/[id]`        | එක් කාර්යයක් ලබාගැනීම                                                                                                       |
| POST  | `/api/a2a/tasks/[id]/cancel` | කාර්යයක් අවලංගු කිරීම                                                                                                       |

**සත්යාපනය:** REST උපකාරක කළමනාකරණ සත්යාපනයකින් තොරව ක්රියාත්මක වේ (උපකරණ පුවරුවෙන් කියවිය හැකිය); JSON-RPC `/a2a` මාර්ගය වින්යාස කර ඇත්නම් Bearer `OMNIROUTE_API_KEY` භාවිත කරයි.

## ACP (Agent Client Protocol) කළමනාකරණය

ළමා ක්රියාවලි ලෙස. මෙම අන්ත ලක්ෂ්ය ACP නියෝජිත හඳුනාගැනීම සහ අභිරුචි නියෝජිත ලියාපදිංචිය කළමනාකරණය කරයි.

| ක්රමය  | මාර්ගය            | විස්තරය                                                                                                                                                                                 |
| ------ | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/acp/agents` | ස්ථාපන තත්ත්වය, අනුවාදය සහ ද්විමය ගොනුව සමඟ දන්නා සියලුම CLI නියෝජිතයන් (අන්තර්නිර්මිත + අභිරුචි) ලැයිස්තුගත කරයි                                                                       |
| POST   | `/api/acp/agents` | අභිරුචි ACP නියෝජිතයෙකු ලියාපදිංචි කිරීම හෝ හැඹිලිය නැවුම් කිරීම — ඉල්ලීම් අන්තර්ගතය: `{id, name, binary, versionCommand, providerAlias, spawnArgs, protocol}` හෝ `{action: "refresh"}` |

## සත්යාපනය

අක්තපත්ර කාණ්ඩ හතර (උපකරණ පුවරු සැසිය, දේශීය CLI ටෝකනය, `oma_live_…` ප්රවේශ ටෝකනය, කළමනාකරණ විෂයපථය සහිත API යතුර) සහ ඒවා අනුමාන යතුරුවලින් වෙනස් වන ආකාරය සඳහා [කළමනාකරණ සත්යාපනය](../guides/MANAGEMENT-AUTH.md) බලන්න.

- උපකරණ පුවරු මාර්ග (`/dashboard/*`) `auth_token` කුකිය භාවිත කරයි
- පිවිසීම සුරකින ලද මුරපද හැෂ් අගය භාවිත කරයි; එය නොමැති විට `INITIAL_PASSWORD` භාවිත කරයි
- `requireLogin` `/api/settings/require-login` හරහා සක්රිය හෝ අක්රිය කළ හැක
- `REQUIRE_API_KEY=true` වන විට `/v1/*` මාර්ග සඳහා විකල්ප වශයෙන් Bearer API යතුරක් අවශ්ය වේ
- මෙම යොමුවෙහි "කළමනාකරණ ටෝකනය" / "කළමනාකරණ විෂයපථය සහිත API යතුර" යන්නෙන් අදහස් කරන්නේ එම මාර්ගෝපදේශයේ සඳහන් කාණ්ඩවලින් එකක් මිස නිර්වචනය නොකළ අමතර රහස් වර්ගයක් නොවේ

> **අනුකූලතාව බිඳ දමන වෙනස (v3.8.0)** — `/api/v1/agents/tasks/*` සහ cooldown කළමනාකරණ අන්ත ලක්ෂ්ය සඳහා දැන් **කළමනාකරණ සත්යාපනය** (උපකරණ පුවරුවේ `auth_token` කුකිය හෝ කළමනාකරණ විෂයපථය සහිත API යතුරක්) අවශ්ය වේ. මීට පෙර සත්යාපනයකින් තොරව මෙම මාර්ග ඇමතූ සේවාලාභීන්ට `401 Unauthorized` ලැබෙනු ඇත. `588a0333` commit එක (`fix(auth): require management auth for agent and cooldown APIs`) බලන්න.
