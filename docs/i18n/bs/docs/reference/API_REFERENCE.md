## Dovršavanja razgovora

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Prilagođena zaglavlja

| Zaglavlje                | Smjer   | Opis                                                                                                                                                                                                                                       |
| ------------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `X-OmniRoute-No-Cache`   | Zahtjev | Postavite na `true` da biste zaobišli predmemoriju                                                                                                                                                                                         |
| `x-omniroute-no-memory`  | Zahtjev | Postavite na `true` da biste preskočili ubacivanje memorije i vještina za ovaj zahtjev (ponaša se kao opcija bez predmemorije; izbjegava dodatnu potrošnju tokena/troškove po pozivu)                                                      |
| `X-OmniRoute-Progress`   | Zahtjev | Postavite na `true` za događaje napretka                                                                                                                                                                                                   |
| `X-Session-Id`           | Zahtjev | Ključ trajne sesije za afinitet vanjske sesije                                                                                                                                                                                             |
| `x_session_id`           | Zahtjev | Prihvaćena je i varijanta s donjom crtom (direktni HTTP)                                                                                                                                                                                   |
| `X-OmniRoute-Session-Id` | Zahtjev | Oznaka sesije/razgovora koju pruža pozivalac (također se prosljeđuje memoriji). Kada je prisutna, doslovno se pohranjuje u `call_logs.session_tag` radi pripisivanja troškova po sesiji (#8249) — nikada se ne generiše kada nije prisutna |
| `Idempotency-Key`        | Zahtjev | Ključ za uklanjanje duplikata (prozor od 5 s)                                                                                                                                                                                              |
| `X-Request-Id`           | Zahtjev | Alternativni ključ za uklanjanje duplikata                                                                                                                                                                                                 |
| `x-omniroute-connection` | Zahtjev | Vežite zahtjev za jedan model za jednu vezu pružaoca usluga (račun) pomoću njenog ID-a — pogledajte [Vezivanje računa po zahtjevu](#account-pinning-per-request)                                                                           |
| `X-OmniRoute-Cache`      | Odgovor | `HIT` ili `MISS` (bez prijenosa)                                                                                                                                                                                                           |
| `X-OmniRoute-Idempotent` | Odgovor | `true` ako su duplikati uklonjeni                                                                                                                                                                                                          |
| `X-OmniRoute-Progress`   | Odgovor | `enabled` ako je praćenje napretka uključeno                                                                                                                                                                                               |
| `X-OmniRoute-Session-Id` | Odgovor | Efektivni ID sesije koji koristi OmniRoute                                                                                                                                                                                                 |
| `X-OmniRoute-Request-Id` | Odgovor | ID za korelaciju zahtjeva (kada je poznat)                                                                                                                                                                                                 |
| `X-OmniRoute-Version`    | Odgovor | Verzija izdanja OmniRoutea (uvijek prisutna)                                                                                                                                                                                               |
| `X-OmniRoute-Cost-Saved` | Odgovor | Iznos u USD koji je predmemorija uštedjela pri rezultatu HIT (samo pogoci predmemorije)                                                                                                                                                    |
| `X-OmniRoute-Decision`   | Odgovor | Zapis usmjeravanja: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` je strategija kombinacije ili `single` za zahtjev koji nije kombinovan) — uvijek prisutan u odgovorima o završetku                                       |

#### Vezivanje računa po zahtjevu

Kada pružalac ima nekoliko veza (računa ili ključeva), OmniRoute obično bira jednu
putem svoje strategije odabira računa. Umjesto toga, zahtjev može vezati jednu određenu vezu
pomoću zaglavlja `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Gdje pronaći id.** Otvorite stranicu pružaoca na kontrolnoj ploči
  (**Kontrolna ploča → Pružaoci → <provider>**) i kliknite na oznaku id-a `xxxxxxxx…` u redu
  veze — time se kopira puni id veze.
- **Koji ga zahtjevi uvažavaju.** Zahtjevi s jednim modelom (`provider/model`) na
  `/v1/chat/completions`, `/v1/messages` i `/v1/responses`. Kombinacije zanemaruju zaglavlje:
  vežite račun za svaki korak kombinacije putem vlastite veze tog koraka.
- **Vezivanje je strogo, nije preferencija.** Vezana veza koristi se isključivo. Greška
  unutar zahtjeva evidentira period hlađenja računa, ali se **ne** prebacuje na drugi
  račun istog pružaoca.
- **Period hlađenja i kvota oslobađaju vezivanje.** Dok je vezana veza u periodu hlađenja,
  kada joj je kvota iscrpljena ili je blokirana pravilom kvote, kasniji zahtjevi prebacuju se
  na druge veze pružaoca, potpuno isto kao nevezani saobraćaj.
- **Nepoznati ili onemogućeni id-ovi uzrokuju grešku.** Id koji nije u aktivnom skupu pružaoca
  (izbrisan, deaktiviran ili pripada drugom pružaocu) ne ostavlja nijedan odgovarajući račun,
  pa zahtjev ne uspijeva umjesto da se neprimjetno usmjeri drugdje.

Claude Code šalje prilagođena zaglavlja putem `ANTHROPIC_CUSTOM_HEADERS`. Postavite ga u blok `env`
datoteke `~/.claude/settings.json` ili u `.claude/settings.json` na nivou projekta kako biste vezali
drugi račun za svaki projekt:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Izvor: `src/sse/handlers/chat.ts` (čitanje zaglavlja), `src/sse/services/auth.ts` i
`src/sse/services/sessionAffinityPin.ts` (oslobađanje vezivanja i provjera nedostaje li veza u skupu).

> **Zaglavlja telemetrije troškova:** uspješni odgovori bez streaminga također sadrže skup telemetrije troškova `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, fiksnih 10 decimalnih mjesta; `0.0000000000` za besplatne/neprocijenjene), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` i `X-OmniRoute-Fallback-Attempts` (samo kada je > 0), kao i `X-OmniRoute-Request-Id` i `X-OmniRoute-Version`. Njih emituju dovršavanja razgovora, `/v1/responses`, `/v1/messages`, **kao i krajnje tačke za medije** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` i `/v1/moderations` (trošak je uvijek `0`). Trošak medija izračunava se po modalitetu (po slici, po sekundi, po znaku, po jedinici pretrage) kada su cijene dostupne, a u suprotnom iznosi `0` (fail-open).

> **Semantika troška pogotka predmemorije:** pri POGOTKU semantičke predmemorije (`X-OmniRoute-Cache-Hit: true`) ne upućuje se poziv prema nadređenom servisu, pa je `X-OmniRoute-Response-Cost` jednak `0.0000000000` (**inkrementalni** trošak posluživanja pogotka). Izvorni trošak/trošak koji bi inače nastao zasebno se navodi u `X-OmniRoute-Cost-Saved`. Korisnici podataka za naplatu trebaju sabirati `X-OmniRoute-Response-Cost` (pogoci ne koštaju ništa); analitika predmemorije može agregirati `X-OmniRoute-Cost-Saved`.

## Ekskluzivni najmovi upravljanih sesija

Ekskluzivni najam upravljane sesije je opcionalan ugovor o usmjeravanju, nezavisan od klijenta: jedan aktivni vlasnik
drži jednu odgovarajuću OmniRoute vezu. Njime se ne iznajmljuje model, ne zahtijeva OAuth, ne identificira
određeni klijent niti se zahtijeva određeni pružalac usluge.

API ključ koji se koristi za autentifikaciju mora imati opseg `lease:exclusive` i eksplicitnu nepraznu
listu `allowedConnections`. Granica mutacije baze podataka zahtijeva oba polja zajedno prilikom kreiranja
ključa i djelimičnih ažuriranja.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Uspješni odgovori za preuzimanje, obnavljanje i oslobađanje prikazuju vremenske oznake, `state` i tačnu pozitivnu
vrijednost `generation`, ali nikada odabranu vezu ili pristupne podatke. Za obnavljanje i oslobađanje
generacija se navodi u JSON tijelu:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Vlasnik aktivnog najma može eksplicitno zatražiti metapodatke za prikaz koji čuvaju privatnost za svoju trenutnu dodjelu:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Ova opcionalna radnja za provjeru statusa zaštićena je neprozirnim vlasnikom, autentificiranim upravljanim API ključem i tačnom
aktivnom generacijom unutar jedne transakcije baze podataka. `displayName` je samo skraćeni konfigurirani
naziv veze; vrijednost je `null` kada ne postoji siguran konfigurirani naziv. OmniRoute nikada ne koristi
adresu e-pošte ili generirani identitet računa kao zamjenu. Vrijednost pružaoca usluge je neosjetljiva oznaka za prikaz i nikada
nije generirani identifikator kompatibilnog pružaoca usluge. Pristupni podaci, tokeni, kolačići, sirovi ID-jevi veze ili API
ključa, sažeci vlasnika, tajne za ograđivanje i interni podaci usmjeravanja su izostavljeni.

Pretrage s pogrešnim ključem, pogrešnim vlasnikom, zastarjelom generacijom te pretrage nedostajućih, isteklih, oslobođenih ili poništenih najmova
vraćaju istu grešku `409 LEASE_FENCE_STALE` bez metapodataka o vezi. Klijent koji je primio odgovor o čekanju na kapacitet nema aktivnu dodjelu koju može provjeriti. Kada usmjeravanje prebaci aktivni najam,
ista generacija ostaje važeća, a status atomski vraća novu dodjelu, nikada staru.
Postojeći klijenti ostaju nepromijenjeni jer odgovori za preuzimanje, obnavljanje, oslobađanje i čekanje zadržavaju
svoje prethodne oblike.

Ovaj ugovor servera ne mijenja standardni OpenAI Codex `/status`. Standardni Codex trenutno prijavljuje svog
pružaoca modela i ugrađeno stanje autentifikacije/računa, ali ne prikazuje proizvoljne prilagođene
metapodatke računa pružaoca usluge; buduća integracija klijenta mora pozvati ovu radnju i odlučiti kako
prikazati `connection.displayName`.

Svaki upravljani zahtjev za izvođenje zaključivanja zatim navodi oba kontrolna zaglavlja:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Tačni vlasnik, generacija, aktivna veza i autentificirani API ključ provjeravaju se
neposredno prije svakog podržanog pokušaja prema nadređenoj usluzi. Ponovno korištenje vlasnika i generacije s drugim ključem ne uspijeva čak
ni kada taj ključ dozvoljava istu vezu. Sirove vrijednosti vlasnika se ne pohranjuju, ne zapisuju u dnevnike, ne zadržavaju u
snimku zahtjeva niti prosljeđuju nadređenoj usluzi.

Privremeno zauzeće vraća HTTP `429` s `Retry-After` i:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Ovaj odgovor samo znači da uobičajeni skup odgovarajućih veza nije bio prazan i da je svaki slobodni kandidat
bio zauzet tuđim aktivnim najmom. Nepodržani modeli/pružaoci usluga, nepodudaranje pravila, period čekanja, kvota,
zdravstveno stanje i drugi uobičajeni neuspjesi pri provjeri podobnosti zadržavaju svoje postojeće OmniRoute odgovore.

### `x-omniroute-compression`

Nadjačavanje plana kompresije za pojedinačni zahtjev. Ima najviši prioritet — nadjačava nadjačavanje kombinacije usmjeravanja,
aktivni profil, automatski okidač i zadanu postavku panela. Vrijednosti:

| Vrijednost    | Efekat                                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------------------------- |
| `off`         | Nema kompresije za ovaj zahtjev.                                                                               |
| `default`     | Zadani profil izveden iz panela (zanemaruje aktivni profil). Mehanizmi s gubicima ostaju isključeni.           |
| `safe`        | Samo deduplikacija i sažimanje razmaka.                                                                        |
| `allow-lossy` | Zadržava plan operatera za ovaj zahtjev, uključujući sažetke i preoblikovanje stila.                           |
| `engine:<id>` | Jedan mehanizam kada je omogućen, npr. `engine:rtk`. Opcionalno uključivanje tog mehanizma po zahtjevu.        |
| `<combo>`     | Imenovana kombinacija, prvo uparena prema nazivu (bez razlikovanja velikih i malih slova), a zatim prema ID-u. |

Napomene:

- Nepoznate vrijednosti se zanemaruju (zahtjev se nikada ne odbija); razrješavanje se nastavlja prema uobičajenom prioritetu operatera.
- Ako više kombinacija dijeli isti naziv, proslijedite **id** kombinacije radi determinističkog podudaranja.
- Kombinacija čiji je naziv `off` ili `default` ne može se odabrati prema nazivu (te ključne riječi se prvo tumače); takvu kombinaciju navedite pomoću njenog ID-a.
- Glavni prekidač kompresije predstavlja čvrstu zabranu: kada je kompresija globalno onemogućena, ovo zaglavlje je ne može omogućiti.

Primijenjeni plan vraća se u zaglavlju odgovora:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

gdje je `<source>` jedna od vrijednosti `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` ili `off`.

## Ugradnje

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Dostupni pružatelji usluga: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID-jevi kataloga imaju oblik `provider/model` (primjer: `jina-ai/jina-embeddings-v5-omni-small`). Samostalni ID-jevi Jina modela koji se pojavljuju u registru (naprimjer `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) također se razrješavaju. Jina embed/rerank/classify/segment prvo koriste vjerodajnice `jina-ai` s kontrolne ploče; `JINA_AI_API_KEY` se koristi kao rezervna opcija samo kada ne postoji ključ s kontrolne ploče. Kartica `jina-reader` namijenjena je samo za Reader / `r.jina.ai` (`POST /v1/web/fetch`) i nikada ne pruža ugradnje niti ponovno rangiranje.

Modeli iz registra koji navode podršku za više modaliteta također prihvataju do 32 strukturirane
stavke nezavisne od pružatelja usluge. Tipovi medijskih stavki su `text`, `image`, `audio`, `video` i `document`. Njihov medijski `source`
je ili `{"type":"url","url":"https://..."}` ili
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
i alias porodice `jina-ai/jina-embeddings-v5-omni` → omni-small) također prihvata Jina izvorne
EmbeddingsV5Request dokumente i **prosljeđuje ih neizmijenjene** na `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Izvorne vrijednosti `{ image | audio | video | pdf }` mogu biti javni HTTPS URL, `data:` URI ili sirovi
base64. OmniRoute ne pretvara te objekte u niz znakova niti dohvaća izvorne URL-ove slika — Jina sama dohvaća
javni medijski sadržaj. Dodatna Jina polja (`task`, `normalized`, `truncate`, `embedding_type`) se
prosljeđuju. Jina SKU-ovi koji podržavaju samo tekst i dalje odbijaju netekstualne dokumente.

Sigurnosna i transportna ograničenja:

- URL-ovi udaljenih medijskih sadržaja moraju biti javni HTTPS. Kanonske `{type,source:url}` stavke dohvaćaju se
  na strani servera (ponovna validacija preusmjeravanja, vremensko ograničenje, ograničenja veličine, javni DNS, vezivanje konekcije) i
  umeću prije poziva pružatelju usluge. Jina izvorne `{image:"https://..."}` stavke prosljeđuju se neizmijenjene
  nakon iste provjere javnog HTTPS-a; Jina dohvaća URL.
- Umetnuti base64 medijski sadržaj ograničen je na 8 MiB dekodiranih podataka po stavci i 16 MiB dekodiranih podataka u cijelom zahtjevu.

Prevođenje za pružatelje usluga (kanonske stavke nikada se ne prosljeđuju neizmijenjene):

- Jina multimodalni modeli: svaka stavka najvišeg nivoa postaje jedan objekt s ključem modaliteta
  (`text` / `image` / `audio` / `video` / `pdf`) koji koristi URI-je podataka za umetnuti medijski sadržaj; jedan vektor po
  stavci najvišeg nivoa.
- Porodica Gemini Embedding 2: jedan niz najvišeg nivoa postaje jedan izvorni
  `models/{model}:embedContent` zahtjev s `content.parts` (`text` ili `inline_data`).
- llama.cpp (`llama-cpp/<model>`, bilo koji model koji je lokalni server učitao): kanonske `text` stavke
  postaju obični nizovi znakova, dok `image` / `audio` / `video` postaju po jedan
  `{"content": [part]}` objekt, koristeći dijelove sadržaja razgovora llama-servera (`image_url`,
  `input_audio` s formatom `wav` / `mp3` / `flac`, `input_video`) s umetnutim podacima; jedan vektor
  po stavci najvišeg nivoa. Server se mora pokretati s `--embedding --mmproj …`; bez projektora
  sam odbija medijski sadržaj. `document` nije podržan.
- Nepoznati/dinamički modeli bez eksplicitnih metapodataka o modalitetu odbijaju strukturirani unos uz HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Nepodržane kombinacije modela i modaliteta vraćaju HTTP 400 umjesto prisilnog pretvaranja stavke. Polja proširenja
koja nisu dio unosa u naslijeđenim zahtjevima s nizovima znakova/tokenima i dalje se prosljeđuju neizmijenjena.

```bash
# Prikaži sve modele za ugradnje
GET /v1/embeddings
```

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
```

Dostupni pružaoci uključuju OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokalno), ComfyUI (lokalno).

`n` vraća `n` slika u `data[]`. Za pružaoce čiji uzvodni API vraća jednu sliku po pozivu
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) izvršava se `n` zasebnih uzvodnih poziva, pri čemu se istovremeno izvršavaju najviše 4. Fiksna
vrijednost `seed` uvećava se za indeks poziva (`seed`, `seed + 1`, …), tako da se slike razlikuju, ali ostaju
ponovljive. `n` je ograničen na 10. Zahtjev u cjelini ne uspijeva ako bilo koji poziv ne uspije. Spisak

ZenMux ponovo koristi postojeću vezu s API ključem i prihvata prefikse `zenmux/` ili `zm/`:

- `zenmux/openai/gpt-image-2` koristi ZenMuxov OpenAI Images API. Opcije uključuju `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` i `response_format`.
- Drugi izdavači, kao što je `zm/meta/muse-image-1.0`, koriste ZenMuxovu Vertex AI krajnju tačku `:predict`.
  `n` se mapira na `sampleCount`, `aspect_ratio` na `aspectRatio`, a `image_size`
  (`1K`, `2K`, `4K`) na `sampleImageSize`. Vrijednost `size` izražena u pikselima određuje samo omjer stranica,
  bez garancije dimenzija u pikselima. Podržani omjeri, rezolucije i brojevi razlikuju se zavisno od modela.
- `zm/inclusionai/ming-image-0.1-design` sam bira svoje dimenzije. Izostavite `size`,
  `aspect_ratio` i `image_size`; eksplicitne vrijednosti vraćaju HTTP 400. PNG, JPEG i WebP
  mogu se zatražiti pomoću `output_format`.

Ova integracija podržava generisanje slike iz teksta, a ne uređivanje referentnih slika. Vertexov
izlaz normalizuje se u `data[].b64_json`; `response_format: "url"` vraća uzvodni
HTTPS URL ili URL s base64 podacima kada su dostupni samo bajtovi slike. Prazni/filtrirani izlazi
vraćaju grešku umjesto praznog uspješnog odgovora. Pristup modelu zavisi od ZenMux računa.
Pogledajte [ZenMuxov Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) i

`model` bira pružaoca OCR-a putem prefiksa `provider/model`; identifikator modela bez prefiksa (npr.

| ID pružaoca                   | ID modela            | Vrijednost `model`                                           | Napomene                                                                                                                             |
| ----------------------------- | -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (ili samo `mistral-ocr-latest`) | Sinhrono — odgovor se vraća direktno iz jednog uzvodnog poziva.                                                                      |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                  | Asinhroni uzvodni tok (`analyze` + provjera statusa) — pogledajte ispod.                                                             |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                      | Sinhrono, putem partnerske krajnje tačke Vertex AI-ja `openapi/chat/completions` — detalje o autentifikaciji/URL-u pogledajte ispod. |

Sva tri pružaoca odgovaraju istim tijelom u Mistral formatu:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Tok provjere statusa za Azure Document Intelligence

API `analyze` usluge Azure Document Intelligence je asinhron: početni zahtjev vraća
zaglavlje `Operation-Location` umjesto tijela, a rezultat se mora periodično provjeravati. Rukovalac
(`open-sse/handlers/ocr.ts`) provjerava taj URL svake sekunde, najviše 30 puta, odmah prekida s greškom (ne
nastavlja provjeravati) ako odgovor provjere nije `ok` ili ako je status `"failed"` te vraća `504` ako se
operacija i dalje izvršava nakon što se iscrpi dozvoljeni broj pokušaja. Konačni Azureov odgovor
normalizuje se u isti format `pages`/`markdown` koji koristi Mistral prije nego što se vrati
pozivaocu, tako da klijentski kôd ne mora posebno obrađivati svakog pružaoca.

### Autentifikacija i razrješavanje krajnje tačke za Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` ponovo koristi istu Vertex AI autentifikaciju koju OmniRoute već podržava za
saobraćaj razgovora/slika (`open-sse/executors/vertex.ts`): API ključ veze je ili
JSON vjerodajnica servisnog računa (koja se putem JWT-bearer toka razmjenjuje za kratkotrajni OAuth pristupni token)
ili već izdani OAuth pristupni token koji se koristi bez izmjena. URL uzvodne krajnje tačke je Vertexova
generička partnerska krajnja tačka `openapi/chat/completions`, izrađena na osnovu projekta i
regije veze — eksplicitni `providerSpecificData.project`/`providerSpecificData.region` uvijek imaju prednost;
u suprotnom, projekt se izvodi iz `project_id` u JSON-u servisnog računa, a zadana regija
je `us-central1`. Oba razrješavanja odvijaju se u `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), a koristi ih
`src/app/api/v1/ocr/route.ts` prije prosljeđivanja funkciji `handleOcr`.

## Prikaz modela

```bash
GET /v1/models
Authorization: Bearer your-api-key

→ Vraća sve modele za razgovor, ugrađivanje i slike + kombinacije u OpenAI formatu
```

### Prefiksi ID-a modela (`?prefix=`)

Većina modela oglašava se pod **prefiksom pružaoca usluge**. Prefiks koji dobijete određuje
zastavica funkcije `MODELS_CATALOG_PREFIX_MODE`, a može se nadjačati **za svaki zahtjev** pomoću
parametra upita — korisno za klijenta koji želi čist spisak bez mijenjanja postavke na nivou
servera za sve ostale:

```bash
GET /v1/models?prefix=alias        # jedan ID po modelu — kratki alias prefiks
GET /v1/models?prefix=dual         # oba oblika (zadana vrijednost servera)
GET /v1/models?prefix=canonical    # samo puni prefiks ID-a pružaoca usluge
```

| Način rada  | Emituje                                                 | Napomene                                                                                                                                                                                     |
| ----------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **i** `claude/claude-sonnet-4-6` | **Zadano.** Oba ID-a usmjeravaju na isti model; zadržana su kako bi klijentske konfiguracije u kojima je bilo koji oblik fiksno naveden nastavile raditi. Približno udvostručuje katalog.    |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Jedan unos po modelu. Pružaoci usluga bez zasebnog aliasa i dalje emituju svoj unos, tako da se ništa ne gubi.                                                                               |
| `canonical` | `claude/claude-sonnet-4-6`                              | Jedan unos po modelu pod punim prefiksom ID-a pružaoca usluge. Pružaoci usluga bez zasebnog aliasa (npr. `antigravity/…`, `agy/…`) i ovdje emituju svoj jedini ID, tako da se ništa ne gubi. |

Preslikani unos u načinu rada `dual` može se prepoznati i bez parametra upita: sadrži polje `parent`
koje pokazuje na primarni ID.

Klijenti koji prikazuju birač modela trebaju zatražiti `?prefix=alias` — to radi i
[OmniCopilot VS Code ekstenzija](../guides/VSCODE-COPILOT.md).

### Filteri za otkrivanje (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` prihvata opcionalne filtere za otkrivanje. Bez ijednog od njih odgovor ostaje
nepromijenjen. Oni sužavaju katalog koji pozivalac već vidi (dozvole API ključa primjenjuju se prvo),
a izvršavaju se prije straničenja u OpenAI stilu pomoću `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # svaka navedena mogućnost mora biti omogućena
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` kataloga; redovi bez njega su `chat`
GET /v1/models?q=sonnet&limit=10                           # podudaranje ID-a ili naziva bez razlikovanja velikih i malih slova
```

| Parametar     | Vrijednosti                                                                                         |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | cijeli broj koji nije negativan, poredi se sa `context_length`                                      |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 znakova                                                                                       |

Nepoznata vrijednost ili `min_context` koji nije cijeli broj bez negativnog predznaka (na primjer `1.5`)
vraća HTTP `400`, a poruka navodi važeće vrijednosti. Implementacija:
`src/app/api/v1/models/catalogFilters.ts`.

### Uži izbor modela (`POST /v1/models/query`)

`POST /v1/models/query` vraća kratak, deterministički spisak iz istog kataloga, uz istu
autentifikaciju i vidljivost po ključu kao `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Svako polje je opcionalno. `capabilities` i `exclude` prihvataju niz ili string odvojen zarezima;
`max_output` se poredi sa `max_output_tokens`. Rezultati se sortiraju prema `owned_by`, a zatim prema `id`.
Zadana vrijednost za `limit` je `20`, dok se vrijednosti iznad `100` ograničavaju na `100`. Nevažeći JSON,
nepoznato polje ili nevažeća vrijednost vraća HTTP `400`.

### Pojedinačno skriveni modeli za razgovor

Model označen kao **Skriven** na svojoj stranici pružaoca usluge izostavlja se iz kataloga i odbija
sa HTTP `404` / `model_not_found` kada se izričito zatraži. Provjera koristi razriješenog
pružaoca usluge i model, uključujući aliase pružalaca usluga, prefikse čvorova kompatibilnog pružaoca usluge i
zadane vrijednosti veze. Kombinacija preskače skrivene ciljeve i može koristiti vidljivi srodni model; kada
ne preostane nijedan izvršivi cilj, vraća isti kôd greške. Poništavanje skrivanja stupa na snagu pri sljedećem
zahtjevu. Nadjačavanja vidljivosti samo za slike ne skrivaju model za razgovor s istim ID-om.

Ova pojedinačna postavka modela odvojena je od
[spiskova dozvoljenih/zabranjenih izlaganja modela](../routing/MODEL_EXPOSURE_LIST.md), koji filtriraju oglašavanje
kataloga i kandidate za automatsko usmjeravanje, dok zadržavaju izričito prosljeđivanje. Dozvole modela
API ključa nastavljaju se primjenjivati nezavisno. Zadani način rada prefiksa kataloga ostaje `dual`.

### Varijante modela bez razmišljanja

Za Claude modele koji podržavaju razmišljanje, `/v1/models` također oglašava varijantu **bez razmišljanja** čiji ID ima prefiks `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Odabir ovog ID-a (npr. u Claude Code konfiguraciji koja uvijek prilaže blok `thinking`) razrješava se nazad na stvarni `<provider>/<model>` s potisnutim zaključivanjem — `thinking:{type:"disabled"}` na putanji `/v1/messages` ili izostavljanjem polja `reasoning`/`reasoning_effort` na putanji `/v1/chat/completions`. Varijanta se navodi samo za modele iz Claude porodice koji podržavaju razmišljanje **i** poštuju `disabled` (tako da su, npr., isključeni modeli koji podržavaju samo adaptivni način rada i odbijaju `disabled`). Operateri mogu prisilno uključiti ili isključiti varijantu za svaki model putem `ModelSpec.noThinkingAlias`.

## ElevenLabs generisanje zvuka

Konfigurišite vezu s pružaocem usluge `elevenlabs` u OmniRouteu pomoću svog ElevenLabs API ključa.
Klijenti se autentificiraju svojim **OmniRoute** ključem (`Authorization: Bearer $OMNIROUTE_API_KEY`);
mrežni prolaz prosljeđuje pohranjeni ključ pružaoca usluge kao `xi-api-key`. Nikada nemojte slati ElevenLabs ključ
kao bearer token mrežnog prolaza.

| Metoda | Putanja                     | Odgovor                                    | Kategorija krajnje tačke API ključa |
| ------ | --------------------------- | ------------------------------------------ | ----------------------------------- |
| POST   | `/v1/sound-generation`      | Izvorni audio bajtovi                      | `elevenlabs`                        |
| POST   | `/v1/music`                 | Izvorni audio bajtovi                      | `music`                             |
| POST   | `/v1/music/stream`          | Audio bajtovi u toku                       | `music`                             |
| POST   | `/v1/music/detailed`        | Izvorni multipart audio i plan kompozicije | `music`                             |
| POST   | `/v1/music/detailed/stream` | Izvorni SSE metapodaci i audio segmenti    | `music`                             |
| POST   | `/v1/music/plan`            | JSON plan kompozicije                      | `music`                             |

Ove krajnje tačke dopunjuju postojeće rute `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` i `/v1/speech-to-text`. Izvorna JSON polja
i parametri upita kao što su `output_format` i `enable_logging` ostaju nepromijenjeni.
Odgovori s `/v1/music/detailed` zadržavaju svoje multipart granice; raščlanite ih kao multipart.
`/v1/music/detailed/stream` vraća `text/event-stream` s metapodacima kompozicije i
base64 audio segmentima u SSE događajima. Svih šest ruta podržava CORS predzahtjeve.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Kratki zvučni efekt. Trajanje: od 0,5 do 30 sekundi.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Trajanje muzike izražava se u milisekundama: od 3000 do 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Koristite `/v1/music/stream` s istim JSON tijelom za postepenu isporuku zvuka. Kompozicija
prihvata tačno jedno od `prompt` ili `composition_plan`; `/v1/music/plan` zahtijeva `prompt`
i opcionalno prihvata `source_composition_plan`. Izvorne sheme zadržavaju dodatna
polja pružaoca usluge kako bi verzije plana kompozicije i opcije finog podešavanja stigle do ElevenLabsa.

Objedinjena krajnja tačka `/v1/music/generations` također prihvata `elevenlabs/music_v1`,
`elevenlabs/music_v2` i `elevenlabs/music_v2_5`. Uz aktivnu ElevenLabs vezu,
ovi modeli su dostupni u katalogu muzike. Ova krajnja tačka vraća
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Njeno polje `duration` izraženo je u
sekundama i mapira se na `music_length_ms`; eksplicitno navedeni `music_length_ms` ima prednost.
`instrumental` se mapira na `force_instrumental`, pri čemu izvorno polje ima prednost.
Koristite izvorne krajnje tačke za streaming i izvornu krajnju tačku za kompoziciju
za zahtjeve zasnovane isključivo na planu kompozicije.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Ograničenja krajnje tačke, modela, budžeta i veze primjenjuju se prije poziva uzvodne usluge. Izvorne
rute vraćaju statusne kodove i tijela grešaka uzvodne usluge bez izmjena, uključujući `402` za
ograničenje plana i `429` za ograničenje kvote. Zaglavlja `character-cost`, `song-id`, `request-id` i `retry-after`
ostaju sačuvana kada su prisutna. Besplatan saldo kredita ne garantuje pristup svakom
muzičkom modelu, izlaznom formatu ili API funkciji: ElevenLabs određuje prava pristupa za svaki zahtjev.
Objedinjena krajnja tačka zadržava statusne kodove grešaka u OmniRouteovoj normalizovanoj omotnici greške.

Ugovori uzvodne usluge: [zvučni efekti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[muzička kompozicija](https://elevenlabs.io/docs/api-reference/music/compose) i
[detalji streaminga muzike](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Sve POST rute prate isti oblik: `Bearer your-api-key` + Zod-validirano JSON tijelo (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` itd., pogledajte `src/shared/validation/schemas.ts`). U slučaju neuspjeha validacije sheme vraća se 4xx.

```bash
# Rerangiranje (pružalac iz registra u oblaku ili čvor pružaoca kompatibilnog s OpenAI-jem kao "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina klasifikacija (vjerodajnice za Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina segmenter
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina pretraga (s.jina.ai; aliasi pružaoca: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Moderiranje
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — vraća tijelo u formatu audio/mpeg (ili u traženom formatu)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS zahtijeva jezik i glas: `language` zadano ima vrijednost "en"; glas koji nedostaje
# ili naziv standardnog OpenAI glasa (alloy, nova, …) postaje "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Uređivanje slike (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Generisanje videa/muzike (ID modela s prefiksom pružaoca)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Čvorovi pružatelja za ponovno rangiranje:** `POST /v1/rerank` također se usmjerava na čvorove pružatelja kompatibilne s OpenAI-jem
> (oMLX, vLLM, Infinity, TEI iza gatewaya, …) adresirane kao `<node-prefix>/<model>`. Loopback
> čvorovi (`localhost`, `127.0.0.1`, `172.16.0.0/12`) uvijek ispunjavaju uslove, kao i nazivi hostova koje
> operater navede u `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (npr. naziv Docker/Compose servisa kao što je
> `http://reranker:8080/v1`; oni se pozivaju direktno, nikada putem `HTTP(S)_PROXY` ili
> proxyja prikvačenog za vezu). Čvorovi na bilo kojem drugom
> hostu — uređaju na LAN-u ili Tailscale ravnopravnom čvoru — ispunjavaju uslove samo kada operater omogući
> funkcijsku zastavicu `RERANK_REMOTE_PROVIDER_NODES` **i** osnovni URL čvora prođe politiku izlaznih
> URL-ova pružatelja (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Korak ponovnog rangiranja memorijskog mehanizma poziva ovu rutu putem
> loopbacka, pa isto pravilo određuje ponašanje postavke `rerankProviderModel` u postavkama memorije.
>
> **Oblici lokalnog servera:** čvor se poziva na `<base>/v1/rerank`, a u slučaju odgovora 404 na `<base>/rerank`
> (Infinity, TEI). Tijelo uzvodnog zahtjeva sadrži i Cohere/OpenAI način pisanja (`documents`,
> `return_documents`) i TEI način pisanja (`texts`, `return_text`), dok se uzvodni odgovor
> normalizira u Cohere omotnicu: TEI-jev čisti `[{index, score, text}]`, `{results: [{index, score}]}`
> iz jednostavnih gatewaya i Voyage stil `{data: [...]}` vraćaju se klijentu kao
> `{results: [{index, relevance_score, document?}]}`, sortirani prema rezultatu i ograničeni na `top_n`.

> **Otkrivanje čvorova pružatelja:** modeli na čvoru pružatelja kompatibilnom s OpenAI-jem pojavljuju se u `GET /v1/models`
> pod prefiksom čvora. Redovi koji ne sadrže metapodatke krajnje tačke (što je tipično za lokalne `/v1/models` popise)
> nasljeđuju `apiType` čvora, pa modeli čvora `embeddings` imaju `type: "embedding"`, a modeli
> čvora `rerank` imaju `type: "rerank"` umjesto da se podrazumijevano postave na chat; eksplicitni
> `supportedEndpoints` u sinhroniziranom ili ručno dodanom redu i dalje ima prednost.

### Exa i Tavily `provider_options`

Exa i Tavily čitaju polja specifična za pružatelja iz objekta s prostorom imena:
`provider_options.exa` (ili `provider_options["exa-search"]`) i `provider_options.tavily`
(ili `provider_options["tavily-search"]`). Prosljeđuju se samo ključevi navedeni ispod. Svaki se
provjerava prema vlastitoj Zod shemi u `open-sse/handlers/search/providerOptionsPassthrough.ts`,
a ključ pogrešnog tipa se odbacuje. Svi ostali ključevi se zanemaruju, uključujući autentifikaciju, osnovni URL,
`stream` i `outputSchema`. Ravni ključevi koje koriste drugi pružatelji (`cx`, `depth`, ...) rade
kao i ranije.

| Pružatelj | Polja najvišeg nivoa                                                                                                                                                                                                                                                                                                                                                      | Ugniježđena                                                                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa       | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (ravne primitivne vrijednosti), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                 | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` spojeno preko zadane vrijednosti `{ text: true, highlights: true }` |
| Tavily    | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                          |

Generička polja uvijek imaju prednost: `query`, `max_results`, `filters` (domene), `country` i
tema izvedena iz `search_type`. Kod Exa pružatelja, `search_type: "news"` zadržava `category: "news"`.
Tavily također prihvata `search_type: "finance"` (`topic: "finance"`).

Generički `time_range` sada se prosljeđuje obama pružateljima: Exa dobija `startPublishedDate` (ISO
vremensku oznaku), a Tavily dobija `start_date` (`YYYY-MM-DD`). Eksplicitni datum u `provider_options`
nadjačava mapirani datum.

Exa rezultati zadržavaju `id`, `highlight_scores`, `summary`, `subpages`, `entities` i `extras` u
`provider_raw`. Tavily rezultati zadržavaju `images` i `favicon`.

Obračun troškova i dalje koristi ravni registar `costPerQuery`. Tavily naplaćuje
`search_depth: "advanced"` uz više kredita po pozivu, a ta razlika nije prikazana u
`usage.search_cost_usd`.

Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, isti API ključ kao za Parallel Search) vraća isključivo Markdown
— bilo koji drugi `format` rezultira odgovorom `400` — i ograničava sadržaj na 100.000 znakova. Kada
se sama ciljna stranica ne može izdvojiti, nadređeni servis to prijavljuje unutar HTTP odgovora 200;
OmniRoute to prikazuje kao `422` s fiksnom porukom.

| Metoda | Putanja         | Opis                                                    |
| ------ | --------------- | ------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Dohvati/scrape URL — tijelo validira `v1WebFetchSchema` |

**Autentifikacija:** Bearer API ključ (`extractApiKey` + `isValidApiKey`). Pravila se primjenjuju putem `enforceApiKeyPolicy`.

**Rezervni odabir svjestan kvota (#8297):** kada nije naveden eksplicitni `provider`, skup
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) obilazi se fiksnim
redoslijedom prioriteta (prvo popunjavanje) — konfigurisan pružalac usluge s ograničenom stopom zahtjeva preskače se
umjesto da odmah prekine zahtjev, a ponovljiva greška ili greška kvote nadređenog servisa
(HTTP 429 uvijek; 402/403 za besplatne nivoe usluge Firecrawl/Tavily/TinyFish sa stilom kvota —
ne za Jina Reader i nikada za običan 400 neispravan zahtjev) u vrijeme zahtjeva prelazi na
sljedećeg neisprobanog pružaoca usluge s vjerodajnicama. Kada su svi pružaoci usluge u
skupu iscrpljeni, krajnja tačka vraća jedan `429` (sa zaglavljem `Retry-After`)
umjesto prethodnog generičkog `400`. Kada se zatraži eksplicitni `provider`, **nema**
neprimjetnog rezervnog odabira — eksplicitni pružalac usluge s ograničenom stopom ili greškom
prikazuje vlastitu grešku (`429` ako je stopa ograničena, inače status
nadređenog servisa).

## WebSocket streaming

```bash
GET /v1/ws?handshake=1
```

Validira rukovanje za WebSocket nadogradnju i vraća primjere poruka žičanog protokola (`request`, `cancel`). Stvarnim WS okvirima upravlja priloženi WS server izvan Next.js tabele ruta.

**Autentifikacija:** Bearer API ključ tokom rukovanja.

### Responses API preko WebSocketa (samo codex)

```bash
# Isti host:port kao HTTP API (zadano 20128); nadogradite vezu:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (ili: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Prvi okvir MORA biti response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy za Responses API preko WebSocketa povezan je **isključivo s `codex`** (ChatGPT
pozadinski sistem). Osluškuje na istom portu kao API/kontrolna ploča, na putanjama `/v1/responses`,
`/responses` i `/api/v1/responses`. Pri prvom okviru `response.create`
obavlja autentifikaciju i pripremu putem internog mosta `codex-responses-ws`, odabire
codex OAuth vezu i tunelira prema `wss://chatgpt.com/backend-api/codex/responses`
putem transporta `wreq-js`. **Modeli koji nisu codex odbijaju se** (`codex_ws_provider_required`).
Za usmjeravanje s dijeljenjem kvote koristite `model: "qtSd/<group>/codex/<model>"`. Implementirano u
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentifikacija:** Bearer API ključ tokom rukovanja. Priloženi HTTP server (`server-ws.mjs`)
mora biti aktivna ulazna tačka (što je zadano kada postoji `app/server-ws.mjs`).

#### ID modela: koristite osnovni ChatGPT ID (bez prefiksa `codex/`)

OpenAI **Codex CLI** validira naziv modela na strani klijenta kada je
`supports_websockets = true` i **odbija ID-ove s prefiksom pružaoca usluge** poput
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Pošaljite **osnovni** ID (npr. `gpt-5.5`). OmniRouteov most podržava
samo codex, pa osnovni ID ponovo razrješava kao codex model
(`resolveCodexWsModelInfo`) prije tuneliranja prema nadređenom servisu — iako bi se osnovni
`gpt-5.5` inače putem HTTP-a usmjerio drugom pružaocu usluge.

#### Konfigurisanje OpenAI Codex CLI-ja

Usmjerite Codex CLI prema OmniRouteu dodavanjem prilagođenog pružaoca usluge s podrškom za WebSocket
u `~/.codex/config.toml` (koristite zaseban `CODEX_HOME` kako ne biste mijenjali
postojeću konfiguraciju):

```toml
model = "gpt-5.5"                 # osnovni ID — NE "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bez završne kose crte; WS URL se izvodi automatski (koristite https/wss u produkciji)
wire_api = "responses"                    # jedina podržana vrijednost od februara 2026.
supports_websockets = true                # omogućava transport Responses-over-WS
env_key = "OMNIROUTE_API_KEY"             # sadrži OmniRoute API ključ (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API ključ (bilo koji ključ ako je REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI nadograđuje `base_url + /responses` na WebSocket, a OmniRoute ga tunelira
prema odabranoj codex OAuth vezi. Validirano od početka do kraja na lokalnom
serveru: ChatGPT vraća `codex.rate_limits` + `response.created` i emituje
dovršetak kao tok.

## Samostalni pristup podacima o korištenju (`/api/usage/om-usage`)

Svaki API ključ može očitati **vlastito** korištenje i kvote — bez upravljačke autorizacije. Ovo je krajnja tačka koju
klijent (CLI, OmniCopilot panel) koristi kako bi vlasniku ključa prikazao njegovu potrošnju.

```bash
# Tekstualni oblik (historijski ugovor — obični tekst za terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Strukturirani oblik — ono što korisnički interfejs koristi
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Ključ mora imati omogućenu opciju **`allowUsageCommand`** (podrazumijevano je isključena — upravitelj API ključeva
na kontrolnoj ploči uključuje je za svaki ključ zasebno). Bez nje krajnja tačka odgovara statusom `403`.

`?format=json` vraća oblik s diskriminatorom, tako da pozivalac nikada ne očitava podatkovno polje iz
odbijenog zahtjeva. U slučaju uspjeha:

```jsonc
{
  "allowed": true,
  // prisutno samo kada su za ključ uključena ograničenja korištenja po ključu (dnevna/sedmična u USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // snimak kvote odabranog pružaoca ili null kada još ništa nije keširano:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // snimak svake veze, tako da korisnički interfejs može prikazati više pružalaca jednog pored drugog:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

U slučaju odbijanja (`401` neispravan ključ / `403` nije dozvoljeno), ista ruta vraća
`{ "allowed": false, "error": { "message": "…" } }` — prisutno, ali prazno polje `personal`/`provider`
(ključ je dozvoljen, ali još ništa nije pribavljeno) predstavlja drugačije stanje od odbijanja, a samo ih JSON oblik
razlikuje.

**Autorizacija:** pozivaočev vlastiti Bearer API ključ, provjeren pomoću `isValidApiKey` — ovo _nije_
upravljačka površina (`/api/keys/…`), koja ostaje zaštićena pomoću `requireManagementAuth`.

### Neobrađeni naspram postotaka kvote prilagođenih graničnoj vrijednosti

Prilikom korištenja `/api/usage/om-usage`, pozivaoci trebaju obratiti pažnju na razliku između
postotaka prikazanih u **običnom tekstualnom izlazu** i strukturiranom **JSON izlazu**:

| Aspekt                | Format običnog teksta (`/api/usage/om-usage` / `@@om-usage`)                                         | JSON format (`?format=json`)                                                        |
| :-------------------- | :--------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------- |
| **Izlazno polje**     | `NN% left` (npr. `20% left`)                                                                         | `provider.quotas` / `providers[].quotas`                                            |
| **Mjerenje**          | **Iskoristivo ograničenje prilagođeno graničnoj vrijednosti**: preostali kapacitet iznad praga       | **Neobrađena uzvodna kvota**: neprilagođeno mjerenje pružaoca                       |
| **Skaliranje praga**  | Skalirano pomoću `effectiveRemainingPercent()`, tako da se zaštićena rezerva prikazuje kao `0% left` | Nema ga (neobrađene vrijednosti snimka kako ih je prijavio pružalac)                |
| **Podaci o pragu**    | Uključeni u prikazani postotak                                                                       | Pohranjeni u `quotaWindowThresholds` za svaku vezu (ili zadane vrijednosti servera) |
| **Primarni korisnik** | Interaktivni CLI alati, terminalski upiti, ljudski operateri                                         | Programske integracije, kontrolne ploče, analitika, alati za praćenje naplate       |

#### Formula prilagođavanja graničnoj vrijednosti

OmniRoute podržava proaktivne granične vrijednosti kvote radi sprečavanja iscrpljivanja uzvodnih resursa (konfigurisane putem
`quotaWindowThresholds` veze, zadanih vrijednosti pružaoca ili globalnih postavki otpornosti). Kada je granična vrijednost
(npr. `cutoff = 25%`) aktivna za period kvote, prikazivač teksta izračunava preostalo ograničenje na sljedeći način:

- Ako je `remaining <= cutoff`: vraća `0%`.
- Ako je `remaining > cutoff`: vraća `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formatirani tekstualni izlaz zaokružuje ovo na najbliži cijeli broj (`Math.round(...)`).

#### Ilustrativni primjer

Razmotrite period pružaoca sa **60% neobrađenog korištenja** (dakle, **40% neobrađene preostale kvote**) i konfigurisanim
pragom od **25% preostale kvote**:

| Prikaz                               | Izračun                                            | Preostalo |          Podrazumijevano iskorišteno          |
| :----------------------------------- | :------------------------------------------------- | :-------: | :-------------------------------------------: |
| **Neobrađeni JSON (`?format=json`)** | Uzvodni snimak (`quotas[window]`)                  |  **40%**  |                    **60%**                    |
| **Tekstualni format (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**  | **80%** (ako se izračunava `100 - remaining`) |

- **Zašto tekst prikazuje 20% preostalo:** Od 40% fizičke kvote preostale na računu, 25% je rezervisano pravilom
  granične vrijednosti. Pozivaocu je preostalo samo 15% od 75% iskoristivog prostora prije nego što usmjerivač prestane
  usmjeravati na ovu vezu. Skaliranje osigurava da veza signalizira iscrpljenost (`0% left`) tačno kada
  usmjeravanje prestane.
- **Zašto JSON zadržava neobrađene vrijednosti:** JSON sadržaj vraća tačan snimak pružaoca (`UsageSnapshot`)
  kako bi vanjski alati imali pristup stvarnom uzvodnom iskorištenju i vrijednostima
  `quotaWindowThresholds` na nivou veze, bez server-side skaliranja s gubitkom podataka.

#### Smjernice za migraciju korisnika

Ako je vanjska integracija (kao što je dodatak za uređivač ili proširenje agenta) prethodno izdvajala podatke iz tekstualne
krajnje tačke (`NN% left`) i izračunavala iskorišteni postotak kao `100 - NN`, prelazak na `?format=json` znači:

- Čitanje neobrađenih JSON vrijednosti odražavat će **stvarnu potrošnju na izvornom sistemu** (60% iskorišteno u prethodnom primjeru).
- Ako integracija želi zadržati semantiku upotrebljivog iznosa kvote tekstualne krajnje tačke, može izračunati
  efektivnu formulu preostalog iznosa na strani klijenta koristeći `quotaWindowThresholds` za nadjačavanja na nivou veze.

### Utjecaj na latenciju

POGODAK semantičkog keša poslužuje odgovor iz keša **bez uzvodnog

`X-OmniRoute-Cache-Latency`:

| Vrijednost  | Značenje                                                         |
| ----------- | ---------------------------------------------------------------- |
| `synthetic` | Odgovor poslužen iz keša; latencija nije stvarno uzvodno vrijeme |
| _(odsutno)_ | Odgovor iz stvarnog uzvodnog poziva                              |

### Zaobilaženje keša po ključu

| Vrijednost | Ponašanje                                                    |


Svaki zahtjev može zaobići keš bez obzira na postavke ključa:


koristi mogućnost `max_output_tokens` tokom izvršavanja i ostaje sačuvano nakon ponovne sinhronizacije modela. Stranica pružaoca
usluge kompatibilnog s OpenAI-jem nudi iste kontrole za uređivanje/brisanje i označava modele s eksplicitnom podrškom za vid.

Prilagođeni čvorovi Chat Completions prilagođavaju eksplicitna isključivanja rezonovanja uzvodnom sistemu. Uspješan
test veze automatski odabire kontrole predloška razgovora za svaki tačan ID modela
čiji unos `/models` dokazuje prepoznatu vrijednost `owned_by`: `vllm`, `sglang` ili `llamacpp`.
Transparentni omotači kompatibilni s OpenAI-jem mogu zadržati izvorni unos modela unutar ugniježđenog
objekta `openai`; otkrivanje prati do tri takva omotača. Modeli s nedostajućim, nepoznatim ili
konfliktnim vlasništvom zadržavaju uobičajeno ponašanje OpenAI-ja. Otkrivanje ponovo koristi postojeći zahtjev za katalog,
ne generira tokene dovršavanja i poništava se kada se promijeni krajnja tačka veze.

Da biste fiksirali ponašanje za pozadinski sistem koji ne izlaže te metapodatke, koristite postojeći API za djelimično
ažuriranje pružaoca usluge:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Pošaljite to tijelo putem `PUT /api/providers/<connection-id>`. Na toj vezi, eksplicitni
napor rezonovanja od `none` šalje se kao `chat_template_kwargs.thinking=false` i
`chat_template_kwargs.enable_thinking=false`. Eksplicitne izvorne vrijednosti predloška ostaju mjerodavne
osim ako pravilo rezonovanja na strani servera ne nametne nivo napora. Postavka se primjenjuje samo kada prilagođena
veza kompatibilna s OpenAI-jem šalje tijelo Chat Completions; zahtjevi Responses i uobičajeni
pružaoci usluga zadržavaju svoj izvorni oblik zahtjeva. Postavite `reasoningControl` na `openai` kako biste nametnuli uobičajeno OpenAI
prosljeđivanje `reasoning_effort` ili ga izostavite/postavite na `null` da biste koristili automatsko otkrivanje.

Zahtjevi klasifikatora automatskog načina rada Claude Codea podrazumijevano postavljaju izvorno razmišljanje kao onemogućeno kada ne sadrže
eksplicitne kontrole rezonovanja. Otkrivanje koristi sistemsku oznaku klasifikatora u zahtjevima Claude formata,
a ne nazive modela ili ograničenja dovršavanja. Eksplicitne kontrole tijela, podržana zaglavlja napora/razmišljanja,
pravila usmjeravanja i razriješeni nivo napora modela zadržavaju svoj postojeći prioritet. Obje faze klasifikatora
zadržavaju svoje upite, ograničenja dovršavanja, sekvence zaustavljanja i stvarne uzvodne odluke
o dozvolama; druga faza i dalje može proizvesti traženo vidljivo rezonovanje kao običan tekst.

### Verzija i kanal izdanja

```bash
GET /api/system/version
```

Upravljačka ruta dostupna samo preko loopback interfejsa (administratorska autentifikacija). Vraća trenutnu verziju, najnoviju
objavljenu verziju i status automatskog ažuriranja. `releaseChannel` i `channels` su dodatna
polja (grana 3.8.54); `channel` zadržava svoje značenje — način implementacije koji alat za ažuriranje kontrolne table
koristi (`npm`, `source` ili `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm kanal pokrenute verzije: `nightly` za verzije `-nightly.*`,
  `next` za druga predizdanja (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` za stabilnu verziju
  starije glavne verzije od `channels.latest`, a u suprotnom `latest`. Ista pravila kao u
  `scripts/release/dist-tag.mjs`, koji bira npm dist-tag prilikom objavljivanja.
- `channels` — najnovija objavljena verzija svake dist-tag oznake, iz `npm view omniroute dist-tags` (rezervni
  pristup putem HTTP-a registra), keširana s istim TTL-om od 10 minuta kao `latest`. `latest` je uvijek prisutan
  (rezervno koristi polje `latest`, a zatim `"unavailable"`); `next`, `nightly` i `lts` pojavljuju se
  samo kada ta dist-tag oznaka postoji. Zahtjev `Cache-Control: no-cache` osvježava obje provjere.

Model kanala (`latest` = v3 do opće dostupnosti verzije 4.0, `next` = rc, `nightly` = verzije s grane `develop`,
`lts` = zakrpe za v3 nakon opće dostupnosti verzije 4.0) opisan je u `docs/ops/RELEASE_STRATEGY.md`.

## Transkripcija zvuka

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data
```

Transkribirajte zvučne datoteke koristeći bilo kojeg konfiguriranog STT pružaoca. Prvi segment
putanje bira izvornog pružaoca (`openai/…`, `deepgram/…`). Pristupnici koji
ponovo izvoze model drugog dobavljača koriste kvalificirani ID
(`openrouter/deepgram/nova-3`).

**Zahtjev:**

```bash
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@recording.mp3" \
  -F "model=openai/whisper-1"
```

**Odgovor:**

```json
{
  "text": "Hello, this is the transcribed audio content.",
  "task": "transcribe",
  "language": "en",
  "duration": 12.5
}
```

## Ograničenja tokena

Budžeti **tokena** po API ključu (odvojeni od gore navedenog budžeta zasnovanog na USD-u). Primjenjuju se direktno na putanji zahtjeva: kada korištenje ključa u trenutnom vremenskom okviru dostigne ograničenje, zahtjevi se odbijaju odgovorom `429 Too Many Requests`. Ograničenja mogu biti vezana za određeni `model`, `provider` ili primijenjena `global`no na cijeli ključ; kada zahtjevu odgovara više ograničenja, primjenjuje se najrestriktivnije.

```bash
# Prikaži ograničenja tokena za ključ (uključuje trenutno korištenje u vremenskom okviru)
GET /api/usage/token-limits?apiKeyId=key-123

# Kreiraj ili ažuriraj ograničenje tokena
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Izbriši ograničenje tokena prema ID-u
DELETE /api/usage/token-limits?id=tl-abc
```

> **Napomene o shemi** (`setTokenLimitSchema`): `apiKeyId` i `scopeType` (`model` | `provider` | `global`) su obavezni. `scopeValue` je obavezan osim ako je `scopeType` postavljen na `global` (npr. ID modela za opseg `model`, ID pružaoca za opseg `provider`). `tokenLimit` mora biti pozitivan cijeli broj (konvertuje se iz niza znakova). Opcionalno: `id` (izostavite za kreiranje, navedite za ažuriranje), `resetInterval` (`daily` | `weekly` | `monthly`, zadana vrijednost `monthly`), `resetTime` (`HH:MM`), `enabled` (zadana vrijednost `true`). `GET` odgovori proširuju svako ograničenje poljima `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` i `nextResetAt`. Ovo je krajnja tačka upravljačke klase (autentifikacija se centralno provodi putem authz cjevovoda).

## Obrada zahtjeva

1. Klijent šalje zahtjev na `/v1/*`
2. Rukovalac rute poziva `handleChat`, `handleEmbedding`, `handleAudioTranscription` ili `handleImageGeneration`
3. Model se razrješava (direktni pružalac/model ili pseudonim/kombinacija)
4. Akreditivi se biraju iz lokalne baze podataka uz filtriranje prema dostupnosti računa
5. Za razgovor: `handleChatCore` provjerava semantički/potpisni keš i razrješava postavke kompresije kombinacije
6. Proaktivna kompresija izvršava se prije prevođenja za pružaoca kada je omogućena (`lite`, Caveman, RTK ili složena)
7. Izvršilac pružaoca šalje zahtjev uzvodno
8. Odgovor se prevodi nazad u format klijenta (razgovor) ili se vraća bez izmjena (ugradnje/slike/zvuk)
9. Bilježe se korištenje, analitika kompresije i dnevnici zahtjeva
10. Rezervna opcija primjenjuje se pri greškama u skladu s pravilima kombinacije

## Otpornost (prošireno)

OmniRoute pruža tri nezavisna mehanizma za privremene kvarove; upravljačke krajnje tačke u nastavku omogućavaju operaterima da ih pregledaju i promijene:

| Opseg               | Pohrana stanja                         | Pregled                                   | Resetovanje / brisanje                                          |
| ------------------- | -------------------------------------- | ----------------------------------------- | --------------------------------------------------------------- |
| Prekidač pružaoca   | `domain_circuit_breakers` + u memoriji | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                    |
| Period čekanja veze | `rateLimitedUntil` na vezama pružaoca  | `/api/rate-limits`, `/api/providers/[id]` | (ponovo se omogućava po potrebi; briše se putem PUT-a pružaoca) |
| Blokada modela      | Registar dostupnosti modela u memoriji | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                        |

`PATCH /api/resilience` prihvata nadjačavanja prekidača pružaoca pod `providerBreaker.oauth` i `providerBreaker.apikey`. Svaki profil podržava `degradationThreshold`, `failureThreshold` i `resetTimeoutMs`; ista polja dostupna su u Kontrolna tabla → Postavke → Otpornost.

```bash
# Ukloni blokadu jednog modela
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Izbriši sve blokade
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Za potpun konceptualni pregled i zadane vrijednosti prekidača pogledajte [`CLAUDE.md`](../../CLAUDE.md) → "Stanje otpornosti tokom izvršavanja" i [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Red ograničenja brzine i zaštitni mehanizam automatskog omogućavanja

- **Podržani put za zapisivanje**: `POST /api/rate-limits` s tijelom `{"connectionId": "<id>", "enabled": true|false}` predstavlja podržanu upravljačku krajnju tačku za uključivanje ili isključivanje zaštite od ograničenja brzine za vezu. `PUT /api/providers/[id]` namjerno ne mijenja niti prebacuje `rateLimitProtection` (#11278).
- **Semantika vrijednosti `enabled: false`**: Postavljanje `enabled: false` uklanja eksplicitnu zaštitu veze, ali **ne** izuzima aktivnu vezu s API ključem iz globalnog zaštitnog mehanizma automatskog omogućavanja (`autoEnableApiKeyProviders = true`). U `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` i `undefined` su ekvivalentni; aktivne veze s API ključem bez eksplicitne zaštite ostaju zaštićene globalnim zaštitnim mehanizmom automatskog omogućavanja.
- **Globalno onemogućavanje**: Da biste koristili veze s API ključem bez redova za ograničenje brzine, globalno onemogućite zaštitni mehanizam putem `RATE_LIMIT_AUTO_ENABLE=false` (varijabla okruženja) ili `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Postavke → Otpornost / `PATCH /api/resilience`).

```bash
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Podržane metode (sve zavise od postavke `settings.a2aEnabled`):

| Metoda           | Opis                                                               |
| ---------------- | ------------------------------------------------------------------ |
| `message/send`   | Sinhrono izvršavanje vještine; vraća `{task, artifacts, metadata}` |
| `message/stream` | Streaming SSE izvršavanje istog skupa vještina                     |
| `tasks/get`      | Dohvata zadatak prema `taskId`                                     |
| `tasks/cancel`   | Otkazuje zadatak prema `taskId`                                    |

Ugrađene vještine: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kartica agenta

```bash
GET /.well-known/agent.json
```

Vraća javnu karticu A2A agenta (naziv, opis, mogućnosti, katalog vještina, shema autentifikacije) — javno se kešira 1 sat. Autentifikacija nije potrebna.

### REST pomoćne krajnje tačke

| Metoda | Putanja                      | Opis                                                                                                                   |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Status omogućenosti A2A-a + statistika zadataka + sažetak keširane kartice agenta                                      |
| GET    | `/api/a2a/tasks`             | Prikazuje zadatke — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nije implementirano kao REST pomoćna krajnja tačka — kreirajte putem JSON-RPC metode `message/send`)                  |
| GET    | `/api/a2a/tasks/[id]`        | Dohvata jedan zadatak                                                                                                  |
| POST   | `/api/a2a/tasks/[id]/cancel` | Otkazuje zadatak                                                                                                       |

**Autentifikacija:** REST pomoćne krajnje tačke rade bez administratorske autentifikacije (nadzorna ploča ih može čitati); JSON-RPC ruta `/a2a` koristi Bearer `OMNIROUTE_API_KEY` ako je konfigurisan.

## Autentifikacija

Pogledajte [Autentifikacija za upravljanje](../guides/MANAGEMENT-AUTH.md) za četiri
grupe vjerodajnica (sesija kontrolne ploče, lokalni CLI token, `oma_live_…` pristupni
token, API ključ s opsegom za upravljanje) i način na koji se razlikuju od ključeva za inferenciju.

- Rute kontrolne ploče (`/dashboard/*`) koriste kolačić `auth_token`
- Prijava koristi sačuvani hash lozinke; rezervna opcija je `INITIAL_PASSWORD`
- `requireLogin` se može uključiti ili isključiti putem `/api/settings/require-login`
- Rute `/v1/*` opcionalno zahtijevaju Bearer API ključ kada je `REQUIRE_API_KEY=true`
- „token za upravljanje“ / „API ključ s opsegom za upravljanje“ u ovoj referenci označava jednu od grupa iz tog vodiča — a ne nedefiniranu dodatnu vrstu tajne

> **Prelomna promjena (v3.8.0)** — `/api/v1/agents/tasks/*` i krajnje tačke za upravljanje periodom čekanja sada zahtijevaju **autentifikaciju za upravljanje** (kolačić kontrolne ploče `auth_token` ili API ključ s opsegom za upravljanje). Klijenti koji su prethodno pozivali ove rute bez autentifikacije dobit će odgovor `401 Unauthorized`. Pogledajte commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
