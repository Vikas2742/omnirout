## Pelengkapan Sembang

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Pengepala Tersuai

| Pengepala                | Arah       | Penerangan                                                                                                                                                                                                                               |
| ------------------------ | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Permintaan | Tetapkan kepada `true` untuk memintas cache                                                                                                                                                                                              |
| `x-omniroute-no-memory`  | Permintaan | Tetapkan kepada `true` untuk melangkau penyuntikan memori + kemahiran bagi permintaan ini (mencerminkan no-cache; mengelakkan overhed token/kos bagi setiap panggilan)                                                                   |
| `X-OmniRoute-Progress`   | Permintaan | Tetapkan kepada `true` untuk peristiwa kemajuan                                                                                                                                                                                          |
| `X-Session-Id`           | Permintaan | Kunci sesi lekat untuk perkaitan sesi luaran                                                                                                                                                                                             |
| `x_session_id`           | Permintaan | Varian garis bawah turut diterima (HTTP langsung)                                                                                                                                                                                        |
| `X-OmniRoute-Session-Id` | Permintaan | Teg sesi/perbualan yang dibekalkan oleh pemanggil (turut disalurkan kepada memori). Apabila ada, dikekalkan kata demi kata dalam `call_logs.session_tag` untuk atribusi kos setiap sesi (#8249) — tidak sekali-kali dijana apabila tiada |
| `Idempotency-Key`        | Permintaan | Kunci penyahduaan (tetingkap 5s)                                                                                                                                                                                                         |
| `X-Request-Id`           | Permintaan | Kunci penyahduaan alternatif                                                                                                                                                                                                             |
| `x-omniroute-connection` | Permintaan | Sematkan permintaan model tunggal kepada satu sambungan penyedia (akaun) mengikut idnya — lihat [Penyematan akaun bagi setiap permintaan](#account-pinning-per-request)                                                                  |
| `X-OmniRoute-Cache`      | Respons    | `HIT` atau `MISS` (bukan penstriman)                                                                                                                                                                                                     |
| `X-OmniRoute-Idempotent` | Respons    | `true` jika dinyahduakan                                                                                                                                                                                                                 |
| `X-OmniRoute-Progress`   | Respons    | `enabled` jika penjejakan kemajuan diaktifkan                                                                                                                                                                                            |
| `X-OmniRoute-Session-Id` | Respons    | ID sesi berkuat kuasa yang digunakan oleh OmniRoute                                                                                                                                                                                      |
| `X-OmniRoute-Request-Id` | Respons    | Id korelasi permintaan (apabila diketahui)                                                                                                                                                                                               |
| `X-OmniRoute-Version`    | Respons    | Versi binaan OmniRoute (sentiasa ada)                                                                                                                                                                                                    |
| `X-OmniRoute-Cost-Saved` | Respons    | Nilai USD yang dijimatkan oleh cache pada `HIT` (hit cache sahaja)                                                                                                                                                                       |
| `X-OmniRoute-Decision`   | Respons    | Jejak penghalaan: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` ialah strategi kombo, atau `single` untuk permintaan bukan kombo) — sentiasa ada dalam respons pelengkapan                                               |

> Nota Nginx: jika anda bergantung pada pengepala yang mengandungi garis bawah (contohnya `x_session_id`), dayakan `underscores_in_headers on;`.

#### Mengepin akaun bagi setiap permintaan

Apabila penyedia mempunyai beberapa sambungan (akaun atau kunci), OmniRoute biasanya memilih satu
melalui strategi pemilihan akaunnya. Sebaliknya, permintaan boleh mengepin satu sambungan tertentu
dengan pengepala `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Tempat untuk mencari ID.** Buka halaman penyedia dalam papan pemuka
  (**Papan Pemuka → Penyedia → <provider>**) dan klik cip ID `xxxxxxxx…` pada baris sambungan
  — tindakan ini menyalin ID sambungan penuh.
- **Permintaan yang mematuhinya.** Permintaan model tunggal (`provider/model`) pada
  `/v1/chat/completions`, `/v1/messages` dan `/v1/responses`. Kombo mengabaikan pengepala tersebut: pin
  akaun bagi setiap langkah kombo melalui sambungan langkah itu sendiri.
- **Pin adalah ketat, bukan sekadar keutamaan.** Sambungan yang dipin digunakan secara eksklusif. Sebarang
  kegagalan dalam permintaan akan merekodkan tempoh bertenang akaun tetapi **tidak** beralih kepada
  akaun lain daripada penyedia yang sama.
- **Tempoh bertenang dan kuota melepaskan pin.** Semasa sambungan yang dipin sedang dalam tempoh bertenang,
  telah kehabisan kuota atau disekat oleh dasar kuota, permintaan berikutnya akan beralih kepada sambungan
  lain milik penyedia, sama seperti trafik yang tidak dipin.
- **ID yang tidak diketahui atau dinyahdayakan akan gagal.** ID yang tiada dalam kumpulan aktif penyedia (dipadamkan,
  dinyahaktifkan atau milik penyedia lain) menyebabkan tiada akaun yang layak, maka permintaan
  akan gagal dan bukannya dihalakan ke tempat lain secara senyap.

Claude Code menghantar pengepala tersuai melalui `ANTHROPIC_CUSTOM_HEADERS`. Letakkannya dalam blok `env`
bagi `~/.claude/settings.json`, atau dalam `.claude/settings.json` pada peringkat projek untuk mengepin akaun
yang berbeza bagi setiap projek:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Sumber: `src/sse/handlers/chat.ts` (pembacaan pengepala), `src/sse/services/auth.ts` dan
`src/sse/services/sessionAffinityPin.ts` (pelepasan pin dan semakan ketiadaan dalam kumpulan).

> **Pengepala telemetri kos:** respons berjaya bukan penstriman turut membawa set telemetri kos `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, tetap 10 tempat perpuluhan; `0.0000000000` untuk percuma/tanpa harga), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, dan `X-OmniRoute-Fallback-Attempts` (hanya apabila > 0), serta `X-OmniRoute-Request-Id` dan `X-OmniRoute-Version`. Pengepala ini dipancarkan oleh pelengkapan sembang, `/v1/responses`, `/v1/messages`, **dan titik akhir media** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, dan `/v1/moderations` (kos sentiasa `0`). Kos media dikira mengikut modaliti (bagi setiap imej, setiap saat, setiap aksara, setiap unit carian) apabila harga tersedia; jika tidak, nilainya ialah `0` (terus beroperasi ketika gagal).

> **Semantik kos padanan cache:** bagi HIT cache semantik (`X-OmniRoute-Cache-Hit: true`), tiada panggilan huluan dibuat, maka `X-OmniRoute-Response-Cost` ialah `0.0000000000` (kos **tambahan** untuk menyampaikan padanan tersebut). Kos asal/kos yang sepatutnya dikenakan dilaporkan secara berasingan dalam `X-OmniRoute-Cost-Saved`. Pengguna data pengebilan hendaklah menjumlahkan `X-OmniRoute-Response-Cost` (padanan tidak melibatkan kos); analitik cache boleh mengagregatkan `X-OmniRoute-Cost-Saved`.

## Pajakan Sesi Terurus Eksklusif

Pajakan sesi terurus eksklusif ialah kontrak penghalaan ikut serta yang neutral klien: satu pemilik aktif
memegang satu sambungan OmniRoute yang layak. Ia tidak memajak model, memerlukan OAuth, mengenal pasti
klien tertentu atau memerlukan penyedia tertentu.

Kunci API yang digunakan untuk pengesahan mesti mempunyai skop `lease:exclusive` dan senarai
`allowedConnections` eksplisit yang tidak kosong. Sempadan mutasi pangkalan data menguatkuasakan kedua-dua
medan secara serentak semasa penciptaan kunci dan kemas kini separa.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Respons pemerolehan, pembaharuan dan pelepasan yang berjaya mendedahkan cap masa, `state` dan nilai positif
`generation` yang tepat, tetapi tidak pernah mendedahkan sambungan atau bukti kelayakan yang dipilih. Pembaharuan dan pelepasan membekalkan
generasi dalam isi JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Pemilik pajakan aktif boleh meminta secara eksplisit metadata paparan yang selamat dari segi privasi untuk pengikatan semasanya:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Tindakan status ikut serta ini dipagari oleh pemilik legap, kunci API terurus yang disahkan dan
generasi aktif yang tepat dalam satu transaksi pangkalan data. `displayName` hanyalah nama sambungan
dikonfigurasi yang telah dibuang ruang kosong di sekelilingnya; nilainya ialah `null` apabila tiada nama dikonfigurasi yang selamat. OmniRoute tidak pernah menggantikannya dengan
e-mel atau identiti akaun yang dijana. Nilai penyedia ialah label paparan tidak sensitif dan tidak pernah
merupakan pengecam penyedia serasi yang dijana. Bukti kelayakan, token, kuki, ID sambungan atau kunci API
mentah, cincangan pemilik, rahsia pemagaran dan data penghalaan dalaman tidak disertakan.

Carian dengan kunci yang salah, pemilik yang salah, generasi lapuk, hilang, tamat tempoh, dilepaskan atau dibatalkan semuanya
mengembalikan ralat `409 LEASE_FENCE_STALE` yang sama tanpa metadata sambungan. Klien yang menerima respons menunggu kapasiti tidak mempunyai pengikatan aktif untuk diperiksa. Apabila penghalaan mengalihkan pajakan aktif,
generasi yang sama kekal sah dan status secara atom mengembalikan pengikatan baharu, bukan pengikatan lama.
Klien sedia ada kekal tidak berubah kerana respons pemerolehan, pembaharuan, pelepasan dan menunggu mengekalkan
bentuk sebelumnya.

Kontrak pelayan ini tidak mengubah `/status` OpenAI Codex standard. Codex standard pada masa ini melaporkan
penyedia modelnya dan keadaan pengesahan/akaun terbina dalam tetapi tidak memaparkan metadata akaun
penyedia tersuai yang sewenang-wenangnya; penyepaduan klien akan datang mesti memanggil tindakan ini dan menentukan cara
memaparkan `connection.displayName`.

Setiap permintaan inferens terurus kemudiannya membekalkan kedua-dua pengepala kawalan:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Pemilik yang tepat, generasi, sambungan aktif dan kunci API yang disahkan dipagari serta-merta
sebelum setiap percubaan huluan yang disokong. Memainkan semula pemilik dan generasi dengan kunci lain akan gagal walaupun
kunci tersebut membenarkan sambungan yang sama. Pemilik mentah tidak disimpan secara berterusan, dilog, dikekalkan dalam
petikan permintaan atau dimajukan ke huluan.

Perebutan sementara mengembalikan HTTP `429` dengan `Retry-After` dan:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Respons ini hanya bermaksud bahawa set layak biasa tidak kosong dan setiap calon bebas sedang
dipegang oleh pajakan aktif asing. Model/penyedia yang tidak disokong, ketidakpadanan dasar, tempoh bertenang, kuota,
kesihatan dan kegagalan kelayakan biasa yang lain mengekalkan respons OmniRoute sedia ada.

### `x-omniroute-compression`

Penggantian pelan pemampatan bagi setiap permintaan. Keutamaan tertinggi — mengatasi penggantian kombo penghalaan,
profil aktif, pencetus automatik dan Lalai panel. Nilai:

| Nilai         | Kesan                                                                                                            |
| ------------- | ---------------------------------------------------------------------------------------------------------------- |
| `off`         | Tiada pemampatan untuk permintaan ini.                                                                           |
| `default`     | Profil Lalai yang diperoleh daripada panel (mengabaikan profil aktif). Enjin lesap dibiarkan dimatikan.          |
| `safe`        | Penyahduplikasian dan pelipatan ruang putih sahaja.                                                              |
| `allow-lossy` | Kekalkan pelan pengendali untuk permintaan ini, termasuk ringkasan dan penulisan semula gaya.                    |
| `engine:<id>` | Satu enjin apabila didayakan, contohnya `engine:rtk`. Keikutsertaan bagi setiap permintaan untuk enjin tersebut. |
| `<combo>`     | Kombo bernama, dipadankan mengikut nama (tidak peka huruf besar/kecil) terlebih dahulu, kemudian mengikut ID.    |

Nota:

- Nilai yang tidak diketahui diabaikan (permintaan tidak pernah ditolak); penyelesaian diteruskan kepada keutamaan pengendali biasa.
- Jika berbilang kombo berkongsi nama, berikan **ID** kombo untuk padanan yang deterministik.
- Kombo yang namanya ialah `off` atau `default` tidak boleh dipilih mengikut nama (kata kunci tersebut ditafsirkan terlebih dahulu); rujuk kombo sedemikian menggunakan ID-nya.
- Suis pemampatan induk ialah gerbang mutlak: apabila pemampatan dinyahdayakan secara global, pengepala ini tidak boleh mendayakannya.

Pelan yang digunakan dikembalikan dalam pengepala respons:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

dengan `<source>` ialah salah satu daripada `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` atau `off`.

## Pembenaman

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Penyedia yang tersedia: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

ID katalog ialah `provider/model` (contoh: `jina-ai/jina-embeddings-v5-omni-small`). ID model Jina tanpa awalan yang muncul dalam pendaftaran (contohnya `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) juga boleh diselesaikan. Operasi embed/rerank/classify/segment Jina mengutamakan kelayakan `jina-ai` daripada papan pemuka; `JINA_AI_API_KEY` hanya digunakan sebagai sandaran apabila tiada kunci papan pemuka. Kad `jina-reader` hanya untuk Reader / `r.jina.ai` (`POST /v1/web/fetch`) dan tidak pernah menyediakan pembenaman atau penyusunan semula.

Model pendaftaran yang menyatakan sokongan multimodal turut menerima sehingga 32 item berstruktur
yang neutral penyedia. Jenis item media ialah `text`, `image`, `audio`, `video`, dan `document`. `source`
media tersebut sama ada `{"type":"url","url":"https://..."}` atau
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
dan alias keluarga `jina-ai/jina-embeddings-v5-omni` → omni-small) turut menerima dokumen
EmbeddingsV5Request asli Jina dan **memajukannya tanpa perubahan** kepada `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Nilai asli `{ image | audio | video | pdf }` boleh berupa URL HTTPS awam, URI `data:`, atau base64
mentah. OmniRoute tidak menukarkan objek tersebut kepada rentetan atau mengambil URL imej asli — Jina mendapatkan
media awam itu sendiri. Medan Jina tambahan (`task`, `normalized`, `truncate`, `embedding_type`)
akan dimajukan. SKU Jina teks sahaja masih menolak dokumen bukan teks.

Had keselamatan dan pengangkutan:

- URL media jauh mestilah HTTPS awam. Item kanonik `{type,source:url}` diambil
  pada bahagian pelayan (pengesahan semula ubah hala, tamat masa, had saiz, DNS awam, penyematan sambungan) dan
  dibenamkan sebelum panggilan penyedia. Item asli Jina `{image:"https://..."}` dimajukan tanpa perubahan
  selepas semakan HTTPS awam yang sama; Jina mengambil URL tersebut.
- Media base64 sebaris dihadkan kepada 8 MiB dinyahkod bagi setiap item dan 16 MiB dinyahkod bagi keseluruhan permintaan.

Terjemahan penyedia (item kanonik tidak pernah dimajukan tanpa perubahan):

- Model multimodal Jina: setiap item peringkat atas menjadi satu objek berkunci modaliti
  (`text` / `image` / `audio` / `video` / `pdf`) menggunakan URI data untuk media sebaris; satu vektor bagi
  setiap item peringkat atas.
- Keluarga Gemini Embedding 2: satu tatasusunan peringkat atas menjadi satu permintaan asli
  `models/{model}:embedContent` dengan `content.parts` (`text` atau `inline_data`).
- llama.cpp (`llama-cpp/<model>`, mana-mana model yang dimuatkan oleh pelayan setempat): item `text` kanonik
  menjadi rentetan biasa, manakala `image` / `audio` / `video` masing-masing menjadi satu objek
  `{"content": [part]}`, menggunakan bahagian kandungan sembang llama-server (`image_url`,
  `input_audio` dengan format `wav` / `mp3` / `flac`, `input_video`) bersama data sebaris; satu vektor
  bagi setiap item peringkat atas. Pelayan mesti dijalankan dengan `--embedding --mmproj …`; tanpa projektor, pelayan
  itu sendiri akan menolak media. `document` tidak disokong.
- Model tidak diketahui/dinamik tanpa metadata modaliti yang jelas menolak input berstruktur dengan HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Gabungan model/modaliti yang tidak disokong mengembalikan HTTP 400 dan bukannya menukar item secara paksa. Medan sambungan
bukan input pada permintaan rentetan/token legasi terus dihantar tanpa perubahan.

```bash
# Senaraikan semua model pembenaman
GET /v1/embeddings
```

## Penjanaan Imej

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Penyedia yang tersedia termasuk OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (setempat), ComfyUI (setempat).

`n` mengembalikan `n` imej dalam `data[]`. Penyedia yang API hulunya mengembalikan satu imej bagi setiap panggilan
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) menerima `n` panggilan hulu yang berasingan, dengan maksimum 4 panggilan serentak. Nilai
`seed` tetap diimbangi mengikut indeks panggilan (`seed`, `seed + 1`, …), supaya imej yang terhasil berbeza tetapi kekal
boleh dihasilkan semula. `n` dihadkan kepada 10. Permintaan secara keseluruhan akan gagal jika mana-mana panggilan gagal. Senarai
format pengembangan ialah `SINGLE_IMAGE_FANOUT_FORMATS` dalam
`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux menggunakan semula sambungan kunci API sedia ada dan menerima awalan `zenmux/` atau `zm/`:

- `zenmux/openai/gpt-image-2` menggunakan OpenAI Images API ZenMux. Pilihan termasuk `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background`, dan `response_format`.
- Penerbit lain, seperti `zm/meta/muse-image-1.0`, menggunakan titik akhir Vertex AI `:predict`
  ZenMux. `n` dipetakan kepada `sampleCount`, `aspect_ratio` kepada `aspectRatio`, dan `image_size`
  (`1K`, `2K`, `4K`) kepada `sampleImageSize`. `size` piksel hanya membekalkan nisbah aspek,
  bukan dimensi piksel yang dijamin. Nisbah, resolusi, dan bilangan yang disokong berbeza mengikut model.
- `zm/inclusionai/ming-image-0.1-design` memilih dimensinya sendiri. Abaikan `size`,
  `aspect_ratio`, dan `image_size`; nilai eksplisit mengembalikan HTTP 400. PNG, JPEG, dan WebP
  boleh diminta menggunakan `output_format`.

Penyepaduan ini menyokong penjanaan teks kepada imej, bukan penyuntingan imej rujukan. Output Vertex
dinormalkan kepada `data[].b64_json`; `response_format: "url"` mengembalikan URL HTTPS hulu
atau URL data base64 apabila hanya bait imej tersedia. Output kosong/ditapis
mengembalikan ralat dan bukannya kejayaan kosong. Akses model bergantung pada akaun ZenMux.
Lihat [API Vertex ZenMux](https://docs.zenmux.ai/api/vertexai/generate-images) dan
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

### Aliran tinjauan Azure Document Intelligence

API `analyze` Azure Document Intelligence adalah tak segerak: permintaan awal mengembalikan pengepala
`Operation-Location` dan bukannya isi, dan hasilnya perlu ditinjau. Pengendali
(`open-sse/handlers/ocr.ts`) meninjau URL tersebut setiap saat sehingga 30 percubaan, gagal serta-merta (tidak
meneruskan tinjauan) apabila respons tinjauan bukan `ok` atau berstatus `"failed"`, dan mengembalikan `504` jika
operasi masih berjalan selepas had percubaan habis. Respons akhir Azure
dinormalkan kepada bentuk `pages`/`markdown` yang sama seperti yang digunakan oleh Mistral sebelum dikembalikan kepada
pemanggil, supaya kod klien tidak perlu mengendalikan penyedia secara khusus.

### Pengesahan dan peleraian titik akhir OCR DeepSeek Vertex AI

`vertex-deepseek-ocr` menggunakan semula pengesahan Vertex AI yang sama yang telah disokong oleh OmniRoute untuk
trafik sembang/imej (`open-sse/executors/vertex.ts`): kunci API sambungan ialah sama ada
kelayakan JSON Service Account (ditukar dengan token akses OAuth jangka pendek melalui aliran JWT-bearer)
atau token akses OAuth yang telah dijana dan digunakan sebagaimana adanya. URL titik akhir hulu ialah titik akhir
rakan kongsi `openapi/chat/completions` generik Vertex, yang dibina daripada projek dan
rantau sambungan — `providerSpecificData.project`/`providerSpecificData.region` eksplisit sentiasa diutamakan;
jika tidak, projek diperoleh daripada `project_id` dalam JSON Service Account dan rantau
menggunakan `us-central1` secara lalai. Kedua-dua peleraian berlaku dalam `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), yang digunakan oleh
`src/app/api/v1/ocr/route.ts` sebelum dihantar kepada `handleOcr`.

### Awalan ID model (`?prefix=`)

Kebanyakan model diiklankan di bawah **awalan penyedia**. Awalan yang anda peroleh dikawal oleh
flag ciri `MODELS_CATALOG_PREFIX_MODE` dan boleh diatasi **bagi setiap permintaan** dengan
parameter pertanyaan — berguna untuk klien yang mahukan senarai yang kemas tanpa mengubah tetapan
seluruh pelayan untuk pengguna lain:

```bash
GET /v1/models?prefix=alias        # satu ID bagi setiap model — awalan alias pendek
GET /v1/models?prefix=dual         # kedua-dua bentuk (lalai pelayan)
GET /v1/models?prefix=canonical    # hanya awalan ID penyedia penuh
```

| Mod         | Menghasilkan                                              | Nota                                                                                                                                                                                                                 |
| ----------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **dan** `claude/claude-sonnet-4-6` | **Lalai.** Kedua-dua ID dihalakan kepada model yang sama; dikekalkan agar konfigurasi klien yang mengekod keras salah satu bentuk terus berfungsi. Kira-kira menggandakan saiz katalog.                              |
| `alias`     | `cc/claude-sonnet-4-6`                                    | Satu entri bagi setiap model. Penyedia tanpa alias yang berbeza masih menghasilkan entrinya, jadi tiada apa-apa yang hilang.                                                                                         |
| `canonical` | `claude/claude-sonnet-4-6`                                | Satu entri bagi setiap model di bawah awalan ID penyedia penuh. Penyedia tanpa alias yang berbeza (cth. `antigravity/…`, `agy/…`) turut menghasilkan satu-satunya ID mereka di sini, jadi tiada apa-apa yang hilang. |

Cerminan mod `dual` juga boleh dikenal pasti tanpa parameter pertanyaan: ia mempunyai medan `parent`
yang menunjuk kepada ID utama.

Klien yang memaparkan pemilih model hendaklah meminta `?prefix=alias` — inilah yang dilakukan oleh
[sambungan OmniCopilot VS Code](../guides/VSCODE-COPILOT.md).

### Penapis penemuan (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` menerima penapis penemuan ikut serta. Tanpa mana-mana penapis ini, respons
tidak berubah. Penapis ini mengecilkan katalog yang sudah boleh dilihat oleh pemanggil (keizinan kunci API digunakan terlebih dahulu),
dan dilaksanakan sebelum penomboran halaman `limit` / `after` gaya OpenAI:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # setiap keupayaan yang disenaraikan mestilah benar
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` katalog; baris tanpanya ialah `chat`
GET /v1/models?q=sonnet&limit=10                           # padanan tanpa mengira huruf besar atau kecil pada ID atau nama
```

| Parameter     | Nilai                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | integer bukan negatif, dibandingkan dengan `context_length`                                         |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 aksara                                                                                        |

Nilai yang tidak diketahui, atau `min_context` yang bukan integer bukan negatif (contohnya `1.5`),
mengembalikan HTTP `400` dan mesej tersebut menyenaraikan nilai yang sah. Pelaksanaan:
`src/app/api/v1/models/catalogFilters.ts`.

### Senarai pendek model (`POST /v1/models/query`)

`POST /v1/models/query` mengembalikan senarai pendek yang deterministik daripada katalog yang sama, dengan
pengesahan dan keterlihatan bagi setiap kunci yang sama seperti `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Setiap medan adalah pilihan. `capabilities` dan `exclude` menerima tatasusunan atau rentetan yang dipisahkan dengan koma;
`max_output` dibandingkan dengan `max_output_tokens`. Hasil diisih mengikut `owned_by`, kemudian `id`.
Nilai lalai `limit` ialah `20` dan nilai melebihi `100` dihadkan kepada `100`. JSON yang tidak sah, medan yang tidak diketahui
atau nilai yang tidak sah akan mengembalikan HTTP `400`.

### Model sembang yang disembunyikan secara individu

Model yang ditandakan sebagai **Tersembunyi** pada halaman penyedianya dikecualikan daripada katalog dan ditolak
dengan HTTP `404` / `model_not_found` apabila diminta secara eksplisit. Semakan menggunakan penyedia dan
model yang telah diselesaikan, termasuk alias penyedia, awalan nod penyedia serasi dan
lalai sambungan. Kombo melangkau sasaran tersembunyi dan boleh menggunakan model setara yang kelihatan; apabila tiada
sasaran boleh laksana yang tinggal, ia mengembalikan kod ralat yang sama. Tindakan menyahsembunyikan berkuat kuasa pada
permintaan seterusnya. Pengatasan keterlihatan imej sahaja tidak menyembunyikan model sembang dengan ID yang sama.

Tetapan model individu ini berasingan daripada
[senarai benarkan/tolak pendedahan model](../routing/MODEL_EXPOSURE_LIST.md), yang menapis pengiklanan katalog
dan calon penghalaan automatik sambil mengekalkan penghantaran eksplisit. Keizinan model kunci API
terus digunakan secara bebas. Mod awalan katalog lalai kekal sebagai `dual`.

### Varian model tanpa pemikiran

Bagi model Claude yang menyokong pemikiran, `/v1/models` turut mengiklankan varian **tanpa pemikiran** yang ID-nya diawali dengan `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Memilih id ini (cth. dalam konfigurasi Claude Code yang sentiasa melampirkan blok `thinking`) akan kembali kepada `<provider>/<model>` sebenar dengan penaakulan dimatikan — `thinking:{type:"disabled"}` pada laluan `/v1/messages`, atau medan `reasoning`/`reasoning_effort` digugurkan pada laluan `/v1/chat/completions`. Varian ini hanya disenaraikan untuk model keluarga Claude yang menyokong pemikiran **dan** mematuhi `disabled` (jadi, cth. model adaptif sahaja yang menolak `disabled` tidak disertakan). Operator boleh memaksa varian ini dihidupkan atau dimatikan bagi setiap model melalui `ModelSpec.noThinkingAlias`.

## Manifes Pemalam Penyedia


## Penjanaan audio ElevenLabs

Konfigurasikan sambungan penyedia `elevenlabs` dalam OmniRoute dengan kunci API ElevenLabs anda.
Klien membuat pengesahan dengan kunci **OmniRoute** mereka (`Authorization: Bearer $OMNIROUTE_API_KEY`);
get laluan membekalkan kunci penyedia yang disimpan sebagai `xi-api-key`. Jangan sekali-kali menghantar
kunci ElevenLabs sebagai token pembawa get laluan.

| Kaedah | Laluan                      | Respons                                          | Kategori titik akhir kunci API |
| ------ | --------------------------- | ------------------------------------------------ | ------------------------------ |
| POST   | `/v1/sound-generation`      | Bait audio natif                                 | `elevenlabs`                   |
| POST   | `/v1/music`                 | Bait audio natif                                 | `music`                        |
| POST   | `/v1/music/stream`          | Bait audio penstriman                            | `music`                        |
| POST   | `/v1/music/detailed`        | Audio berbilang bahagian dan pelan gubahan natif | `music`                        |
| POST   | `/v1/music/detailed/stream` | Metadata SSE dan cebisan audio natif             | `music`                        |
| POST   | `/v1/music/plan`            | Pelan gubahan JSON                               | `music`                        |

Titik akhir ini melengkapkan laluan `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` dan `/v1/speech-to-text` yang sedia ada. Medan JSON natif
dan parameter pertanyaan seperti `output_format` dan `enable_logging` dikekalkan.
Respons `/v1/music/detailed` mengekalkan sempadan berbilang bahagiannya; hurai respons tersebut sebagai berbilang bahagian.
`/v1/music/detailed/stream` mengembalikan `text/event-stream` dengan metadata gubahan dan
cebisan audio base64 dalam peristiwa SSE. Kesemua enam laluan menyokong prapenerbangan CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Kesan bunyi pendek. Tempoh: 0.5 hingga 30 saat.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Tempoh muzik dinyatakan dalam milisaat: 3000 hingga 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Gunakan `/v1/music/stream` dengan isi JSON yang sama untuk penghantaran audio secara berperingkat. Gubahan
menerima tepat satu daripada `prompt` atau `composition_plan`; `/v1/music/plan` memerlukan `prompt`
dan secara pilihan menerima `source_composition_plan`. Skema natif mengekalkan medan penyedia tambahan
supaya versi pelan gubahan dan pilihan penalaan halus sampai ke ElevenLabs.

Titik akhir bersepadu `/v1/music/generations` turut menerima `elevenlabs/music_v1`,
`elevenlabs/music_v2` dan `elevenlabs/music_v2_5`. Dengan sambungan ElevenLabs yang aktif,
model ini didedahkan oleh katalog muzik. Titik akhir ini mengembalikan
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Medan `duration` adalah dalam
saat dan dipetakan kepada `music_length_ms`; `music_length_ms` yang dinyatakan secara eksplisit diberi keutamaan.
`instrumental` dipetakan kepada `force_instrumental`, dengan medan natif diberi keutamaan.
Gunakan titik akhir penstriman natif untuk penstriman dan titik akhir gubahan natif
untuk permintaan yang hanya dipacu oleh pelan gubahan.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Sekatan titik akhir, model, belanjawan dan sambungan dikenakan sebelum panggilan huluan. Laluan
natif mengembalikan kod status dan isi ralat huluan tanpa perubahan, termasuk `402` untuk sekatan
pelan dan `429` untuk had kuota. Pengepala `character-cost`, `song-id`, `request-id` dan `retry-after`
dikekalkan apabila tersedia. Baki kredit percuma tidak menjamin akses kepada setiap
model muzik, format output atau ciri API: ElevenLabs menentukan kelayakan bagi setiap permintaan.
Titik akhir bersepadu mengekalkan kod status ralat dalam sampul ralat ternormal OmniRoute.

Kontrak huluan: [kesan bunyi](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[gubahan muzik](https://elevenlabs.io/docs/api-reference/music/compose) dan
[butiran muzik penstriman](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

### `provider_options` Exa dan Tavily

Exa dan Tavily membaca medan khusus penyedia daripada bekas bernama ruang:
`provider_options.exa` (atau `provider_options["exa-search"]`) dan `provider_options.tavily`
(atau `provider_options["tavily-search"]`). Hanya kunci di bawah dimajukan. Setiap satu
disemak berdasarkan skema Zod tersendiri dalam `open-sse/handlers/search/providerOptionsPassthrough.ts`,
dan kunci dengan jenis yang salah akan digugurkan. Sebarang kunci lain diabaikan, termasuk pengesahan, URL asas,
`stream` dan `outputSchema`. Kunci rata yang digunakan oleh penyedia lain (`cx`, `depth`, ...) berfungsi
seperti sebelumnya.

| Penyedia | Medan peringkat teratas                                                                                                                                                                                                                                                                                                                                                   | Tersarang                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa      | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (primitif rata), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                                                | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` digabungkan di atas lalai `{ text: true, highlights: true }` |
| Tavily   | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                   |

Medan generik sentiasa diutamakan: `query`, `max_results`, `filters` (domain), `country` dan
topik yang diterbitkan daripada `search_type`. Pada Exa, `search_type: "news"` mengekalkan `category: "news"`.
Tavily juga menerima `search_type: "finance"` (`topic: "finance"`).

`time_range` generik kini dihantar kepada kedua-dua penyedia: Exa menerima `startPublishedDate` (cap masa
ISO) dan Tavily menerima `start_date` (`YYYY-MM-DD`). Tarikh eksplisit dalam `provider_options`
mengatasi tarikh yang dipetakan.

Hasil Exa mengekalkan `id`, `highlight_scores`, `summary`, `subpages`, `entities` dan `extras` dalam
`provider_raw`. Hasil Tavily mengekalkan `images` dan `favicon`.

Perakaunan kos masih menggunakan daftar rata `costPerQuery`. Tavily mengenakan
lebih banyak kredit bagi setiap panggilan untuk `search_depth: "advanced"`, dan perbezaan tersebut tidak ditunjukkan dalam
`usage.search_cost_usd`.

## API Pengambilan Web

Ekstrak kandungan daripada URL melalui penyedia pengambilan web yang dikonfigurasikan (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, kunci API yang sama seperti Parallel Search) hanya mengembalikan Markdown
— sebarang `format` lain menghasilkan `400` — dan mengehadkan kandungan kepada 100,000 aksara. Apabila
halaman sasaran itu sendiri tidak dapat diekstrak, perkhidmatan huluan melaporkannya dalam HTTP 200;
OmniRoute memaparkannya sebagai `422` dengan mesej tetap.

| Kaedah | Laluan          | Perihalan                                                |
| ------ | --------------- | -------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Ambil/kikis URL — jasad disahkan oleh `v1WebFetchSchema` |

**Pengesahan:** Kunci API Bearer (`extractApiKey` + `isValidApiKey`). Dasar dikuatkuasakan melalui `enforceApiKeyPolicy`.

**Sandaran peka kuota (#8297):** apabila tiada `provider` yang dinyatakan secara eksplisit, kumpulan
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) dilalui mengikut
turutan keutamaan tetap
(isi dahulu) — penyedia yang dikonfigurasikan tetapi dikenakan had kadar dilangkau
dan bukannya terus menamatkan permintaan, manakala kegagalan huluan yang boleh dicuba semula/berkaitan kuota
(HTTP 429 sentiasa; 402/403 untuk peringkat percuma bercorak kuota Firecrawl/Tavily/TinyFish —
bukan untuk Jina Reader, dan tidak sekali-kali untuk permintaan rosak 400 biasa) akan beralih kepada
penyedia berkelayakan yang belum dicuba seterusnya ketika permintaan dibuat. Apabila setiap penyedia dalam
kumpulan telah kehabisan, titik akhir mengembalikan satu `429` (dengan pengepala `Retry-After`)
dan bukannya `400` generik terdahulu. Apabila `provider` eksplisit
diminta, **tiada** sandaran senyap — penyedia eksplisit yang dikenakan had kadar atau gagal
akan memaparkan ralatnya sendiri (`429` jika dikenakan had kadar, jika tidak, status
huluan).

### Responses API melalui WebSocket (codex sahaja)

```bash
# Hos:port yang sama seperti API HTTP (lalai 20128); naik taraf sambungan:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (atau: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Bingkai pertama MESTILAH response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proksi Responses-API-melalui-WebSocket disambungkan **secara eksklusif kepada `codex`** (bahagian belakang ChatGPT). Ia mendengar pada port yang sama seperti API/papan pemuka di laluan `/v1/responses`,
`/responses`, dan `/api/v1/responses`. Pada bingkai `response.create` pertama, ia
mengesahkan + menyediakan melalui jambatan dalaman `codex-responses-ws`, memilih
sambungan OAuth codex, dan menerowong ke `wss://chatgpt.com/backend-api/codex/responses`
melalui pengangkutan `wreq-js`. **Model bukan codex ditolak** (`codex_ws_provider_required`).
Untuk penghalaan perkongsian kuota, gunakan `model: "qtSd/<group>/codex/<model>"`. Dilaksanakan dalam
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Pengesahan:** Kunci API Bearer semasa jabat tangan. Pelayan HTTP terbina (`server-ws.mjs`)
mestilah menjadi titik masuk aktif (sememangnya begitu secara lalai apabila `app/server-ws.mjs` wujud).

#### ID model: gunakan ID ChatGPT tanpa awalan (tiada awalan `codex/`)

**Codex CLI** OpenAI mengesahkan nama model pada bahagian klien apabila
`supports_websockets = true` dan **menolak ID berawalan penyedia** seperti
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Hantar ID **tanpa awalan** (contohnya `gpt-5.5`). Jambatan OmniRoute
adalah untuk codex sahaja, maka ia menyelesaikan semula ID tanpa awalan sebagai model codex
(`resolveCodexWsModelInfo`) sebelum menerowong ke huluan — walaupun
`gpt-5.5` tanpa awalan sebaliknya akan dihalakan kepada penyedia lain melalui HTTP.

#### Mengkonfigurasikan OpenAI Codex CLI

Halakan Codex CLI ke OmniRoute dengan menambahkan penyedia tersuai dengan sokongan WebSocket
pada `~/.codex/config.toml` (gunakan `CODEX_HOME` yang berasingan untuk mengelakkan perubahan
pada konfigurasi sedia ada):

```toml
model = "gpt-5.5"                 # ID tanpa awalan — BUKAN "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # tiada garis miring penutup; URL WS diterbitkan daripadanya (gunakan https/wss dalam pengeluaran)
wire_api = "responses"                    # satu-satunya nilai yang disokong sejak Feb 2026
supports_websockets = true                # mendayakan pengangkutan Responses-melalui-WS
env_key = "OMNIROUTE_API_KEY"             # menyimpan kunci API OmniRoute (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # kunci API OmniRoute (sebarang kunci jika REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI menaik taraf `base_url + /responses` kepada WebSocket dan OmniRoute menerowongnya
ke sambungan OAuth codex yang dipilih. Disahkan dari hujung ke hujung terhadap pelayan
setempat: ChatGPT mengembalikan `codex.rate_limits` + `response.created` dan menstrim
pelengkapan.

## Penggunaan layan diri (`/api/usage/om-usage`)

Sebarang kunci API boleh membaca penggunaan dan kuota **miliknya sendiri** — tanpa pengesahan pengurusan. Ini ialah titik akhir yang
digunakan oleh klien (CLI, panel OmniCopilot) untuk menunjukkan perbelanjaan kepada pemegang kunci.

```bash
# Bentuk teks (kontrak terdahulu — teks biasa untuk terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Bentuk berstruktur — yang digunakan oleh UI
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Kunci tersebut mesti mengaktifkan **`allowUsageCommand`** (dimatikan secara lalai — pengurus kunci API
papan pemuka menetapkannya bagi setiap kunci). Tanpanya, titik akhir memberikan respons `403`.

`?format=json` mengembalikan struktur terbeza supaya pemanggil tidak sekali-kali membaca medan data daripada
respons penolakan. Jika berjaya:

```jsonc
{
  "allowed": true,
  // hanya tersedia apabila kunci memilih untuk menggunakan had penggunaan setiap kunci (USD harian/mingguan):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // petikan kuota penyedia yang dipilih, atau null apabila tiada apa-apa yang dicache lagi:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // petikan bagi setiap sambungan, supaya UI boleh memaparkan beberapa penyedia secara bersebelahan:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

Jika ditolak (`401` kunci tidak sah / `403` tidak dibenarkan), laluan yang sama mengembalikan
`{ "allowed": false, "error": { "message": "…" } }` — `personal`/`provider` yang wujud tetapi kosong
(kunci dibenarkan, tetapi belum memperoleh apa-apa maklumat) ialah keadaan yang berbeza daripada penolakan, dan hanya bentuk JSON
membezakannya.

**Pengesahan:** Kunci API Bearer milik pemanggil sendiri, disahkan dengan `isValidApiKey` — ini _bukan_
permukaan pengurusan (`/api/keys/…`), yang kekal dilindungi oleh `requireManagementAuth`.

### Peratusan Kuota Mentah lwn. Terlaras Mengikut Pemotongan

Apabila menggunakan `/api/usage/om-usage`, pemanggil harus mengambil perhatian tentang perbezaan antara
peratusan yang dipaparkan oleh **output teks biasa** dengan **output JSON** berstruktur:

| Aspek                     | Format teks biasa (`/api/usage/om-usage` / `@@om-usage`)                                              | Format JSON (`?format=json`)                                                            |
| :------------------------ | :---------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------- |
| **Medan output**          | `NN% left` (misalnya, `20% left`)                                                                     | `provider.quotas` / `providers[].quotas`                                                |
| **Pengukuran**            | **Peruntukan boleh guna terlaras mengikut pemotongan**: kapasiti berbaki melebihi ambang pemotongan   | **Kuota huluan mentah**: pengukuran penyedia yang tidak dilaraskan                      |
| **Penskalaan pemotongan** | Diskalakan melalui `effectiveRemainingPercent()` supaya rizab terlindung dipaparkan sebagai `0% left` | Tiada (nilai petikan mentah seperti yang dilaporkan oleh penyedia)                      |
| **Data ambang**           | Disertakan dalam peratusan yang dipaparkan                                                            | Disimpan dalam `quotaWindowThresholds` bagi setiap sambungan (atau nilai lalai pelayan) |
| **Pengguna utama**        | CLI interaktif, gesaan terminal, pengendali manusia                                                   | Integrasi berprogram, papan pemuka, analitis, penjejak pengebilan                       |

#### Formula Pelarasan Pemotongan

OmniRoute menyokong pemotongan kuota secara proaktif untuk mengelakkan kehabisan sumber huluan (dikonfigurasikan melalui
`quotaWindowThresholds` sambungan, nilai lalai penyedia, atau tetapan ketahanan global). Apabila ambang pemotongan
(misalnya, `cutoff = 25%`) aktif pada tetingkap kuota, pemapar teks mengira peruntukan berbaki seperti berikut:

- Jika `remaining <= cutoff`: mengembalikan `0%`.
- Jika `remaining > cutoff`: mengembalikan `((remaining - cutoff) / (100 - cutoff)) * 100`.

Output teks berformat membundarkan nilai ini kepada integer terdekat (`Math.round(...)`).

#### Contoh Ilustrasi

Pertimbangkan tetingkap penyedia dengan **60% penggunaan mentah** (oleh itu **40% kuota mentah berbaki**) dan ambang
**pemotongan kuota berbaki sebanyak 25%** yang dikonfigurasikan:

| Perwakilan                       | Pengiraan                                          | Berbaki |           Penggunaan Tersirat            |
| :------------------------------- | :------------------------------------------------- | :-----: | :--------------------------------------: |
| **JSON mentah (`?format=json`)** | Petikan huluan (`quotas[window]`)                  | **40%** |                 **60%**                  |
| **Format teks (`NN% left`)**     | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (jika mengira `100 - remaining`) |

- **Mengapa teks menunjukkan baki 20%:** Daripada 40% kuota fizikal yang berbaki dalam akaun, 25% dirizabkan oleh
  dasar pemotongan. Pemanggil hanya mempunyai ruang boleh guna sebanyak 15% daripada 75% yang berbaki sebelum penghala berhenti
  menghalakan trafik ke sambungan ini. Penskalaan memastikan sambungan menandakan kehabisan (`0% left`) tepat pada masa
  penghalaan akan dihentikan.
- **Mengapa JSON mengekalkan nilai mentah:** Muatan JSON mengembalikan petikan penyedia yang tepat (`UsageSnapshot`)
  supaya alat luaran mempunyai akses kepada penggunaan huluan sebenar dan
  `quotaWindowThresholds` peringkat sambungan tanpa penskalaan lossy pada bahagian pelayan.

#### Panduan Migrasi Pengguna

Jika integrasi luaran (seperti pemalam editor atau sambungan ejen) sebelum ini mengekstrak teks daripada
titik akhir (`NN% left`) dan mengira peratusan yang digunakan sebagai `100 - NN`, peralihan kepada `?format=json` bermaksud:

- Membaca nilai JSON mentah akan mencerminkan **penggunaan huluan sebenar** (60% digunakan dalam contoh di atas).
- Jika integrasi tersebut mahu mengekalkan semantik elaun boleh guna bagi titik akhir teks, ia boleh menilai
  formula baki berkesan pada sisi klien menggunakan `quotaWindowThresholds` untuk penggantian peringkat sambungan.

## Cache Semantik

```bash
# Dapatkan statistik cache
GET /api/cache/stats

# Kosongkan semua cache
DELETE /api/cache/stats
```

Contoh respons:

```json
{
  "semanticCache": {
    "memorySize": 42,
    "memoryMaxSize": 500,
    "dbSize": 128,
    "hitRate": 0.65
  },
  "idempotency": {
    "activeKeys": 3,
    "windowMs": 5000
  }
}
```

### Kesan latensi

HIT cache semantik menyediakan respons daripada cache **tanpa panggilan huluan
**, jadi `X-OmniRoute-Response-Latency` yang dilaporkan adalah hampir sifar
(tanpa mengira latensi huluan asal). Klien yang sensitif terhadap latensi
(penanda aras, pemantauan p50/p99) harus menyemak pengepala respons
`X-OmniRoute-Cache-Latency`:

| Nilai       | Maksud                                                               |
| ----------- | -------------------------------------------------------------------- |
| `synthetic` | Respons disediakan daripada cache; latensi bukan masa huluan sebenar |
| _(tiada)_   | Respons daripada panggilan huluan sebenar                            |

### Pintasan cache bagi setiap kunci

Kunci API boleh memilih untuk tidak menggunakan bacaan cache semantik melalui `cacheDefaultMode`:

| Nilai    | Tingkah laku                                             |
| -------- | -------------------------------------------------------- |
| `legacy` | Tingkah laku cache biasa (lalai)                         |
| `bypass` | Langkau carian cache sepenuhnya; sentiasa gunakan huluan |

Tetapkan semasa penciptaan kunci (`POST /api/keys`) atau kemas kini (`PATCH /api/keys/[id]`):

```json
{ "cacheDefaultMode": "bypass" }
```

### Pintasan bagi setiap permintaan

Sebarang permintaan boleh memintas cache tanpa mengira tetapan kunci:

```
X-OmniRoute-No-Cache: true
```

Bagi model yang disegerakkan/diimport, `PUT /api/provider-models` menerima `provider`, `modelId`, dan
`maxOutputTokenOverride`: integer positif menetapkan had token output manual, manakala `null`
mengosongkannya untuk memulihkan nilai lalai. `GET /api/provider-models?provider=<provider>` mengembalikan
nilai ini dalam `modelOutputOverrides`, termasuk model tanpa baris model tersuai. Penggantian tersebut
menggunakan keupayaan masa jalan `max_output_tokens` dan dikekalkan selepas penyegerakan semula model. Halaman
penyedia serasi OpenAI menawarkan kawalan edit/kosongkan yang sama dan menandakan model yang menyokong penglihatan secara eksplisit.

Nod Chat Completions tersuai menyesuaikan penolakan eksplisit terhadap penaakulan untuk bahagian belakang huluan. Ujian
sambungan yang berjaya memilih kawalan templat sembang secara automatik bagi setiap ID model tepat
yang entri `/models`-nya membuktikan nilai `owned_by` yang dikenali: `vllm`, `sglang`, atau `llamacpp`.
Pembalut serasi OpenAI yang telus mungkin mengekalkan entri model asal dalam objek `openai`
tersarang; pengesanan mengikuti sehingga tiga lapisan pembalut sedemikian. Model dengan pemilikan yang tiada, tidak diketahui, atau
bercanggah mengekalkan tingkah laku OpenAI biasa. Pengesanan menggunakan semula permintaan katalog sedia ada,
tidak menjana token pelengkapan, dan dibatalkan apabila titik akhir sambungan berubah.

Untuk menetapkan tingkah laku bagi bahagian belakang yang tidak mendedahkan metadata tersebut, gunakan API
kemas kini separa penyedia yang sedia ada:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Hantar isi tersebut dengan `PUT /api/providers/<connection-id>`. Pada sambungan itu, usaha
penaakulan eksplisit `none` dihantar sebagai `chat_template_kwargs.thinking=false` dan
`chat_template_kwargs.enable_thinking=false`. Nilai templat natif eksplisit kekal berkuasa
melainkan peraturan penaakulan sebelah pelayan memaksa sesuatu usaha. Tetapan tersebut hanya terpakai apabila sambungan
serasi OpenAI tersuai menghantar isi Chat Completions; permintaan Responses dan penyedia
biasa mengekalkan bentuk permintaan natif masing-masing. Tetapkan `reasoningControl` kepada `openai` untuk memaksa penerusan terus
`reasoning_effort` OpenAI biasa, atau abaikannya/tetapkannya kepada `null` untuk menggunakan pengesanan automatik.

Permintaan pengelas mod automatik Claude Code menetapkan pemikiran natif kepada dilumpuhkan secara lalai apabila permintaan tersebut
tidak mengandungi kawalan penaakulan eksplisit. Pengesanan menggunakan penanda sistem pengelas dalam permintaan
berformat Claude, bukan nama model atau had pelengkapan. Kawalan isi eksplisit, pengepala
usaha/pemikiran yang disokong, peraturan penghalaan, dan usaha model yang telah diselesaikan mengekalkan keutamaan sedia ada.
Kedua-dua peringkat pengelas mengekalkan gesaan, had pelengkapan, jujukan henti, dan keputusan
kebenaran huluan sebenar masing-masing; peringkat kedua masih boleh menghasilkan penaakulan ketara yang diminta sebagai teks biasa.

### Versi dan Saluran Keluaran

```bash
GET /api/system/version
```

Laluan pengurusan gelung balik sahaja (pengesahan pentadbir). Mengembalikan versi yang sedang berjalan, versi terkini yang diterbitkan dan status kemas kini automatik. `releaseChannel` dan `channels` ialah medan tambahan (landasan 3.8.54); `channel` mengekalkan maksudnya — mod penggunaan yang digunakan oleh pengemas kini papan pemuka (`npm`, `source` atau `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — saluran npm bagi binaan yang sedang berjalan: `nightly` untuk versi `-nightly.*`,
  `next` untuk prakeluaran lain (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` untuk versi stabil daripada
  versi utama yang lebih lama berbanding `channels.latest`, selainnya `latest`. Peraturan yang sama seperti
  `scripts/release/dist-tag.mjs`, yang memilih dist-tag npm semasa penerbitan.
- `channels` — keluaran terbaharu yang diterbitkan bagi setiap dist-tag, daripada `npm view omniroute dist-tags` (sandaran
  HTTP pendaftaran), dicache dengan TTL 10 minit yang sama seperti `latest`. `latest` sentiasa tersedia
  (kembali kepada medan `latest`, kemudian `"unavailable"`); `next`, `nightly` dan `lts` muncul
  hanya apabila dist-tag tersebut wujud. Permintaan `Cache-Control: no-cache` menyegarkan semula kedua-dua carian.

Model saluran (`latest` = v3 sehingga 4.0 GA, `next` = rc, `nightly` = binaan `develop`,
`lts` = tampalan v3 selepas 4.0 GA) diterangkan dalam `docs/ops/RELEASE_STRATEGY.md`.

## Had Token

Belanjawan **token** bagi setiap kunci API (berbeza daripada Belanjawan berasaskan USD di atas). Dikuatkuasakan secara langsung pada laluan permintaan: apabila penggunaan tetingkap semasa sesuatu kunci mencapai hadnya, permintaan akan ditolak dengan `429 Too Many Requests`. Had boleh dikhususkan kepada `model` tertentu, `provider`, atau digunakan secara `global` merentas kunci tersebut; apabila beberapa had sepadan dengan sesuatu permintaan, had yang paling ketat akan diguna pakai.

```bash
# Senaraikan had token sesuatu kunci (termasuk penggunaan tetingkap semasa)
GET /api/usage/token-limits?apiKeyId=key-123

# Cipta atau kemas kini had token
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Padam had token mengikut id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Catatan skema** (`setTokenLimitSchema`): `apiKeyId` dan `scopeType` (`model` | `provider` | `global`) diperlukan. `scopeValue` diperlukan melainkan `scopeType` ialah `global` (contohnya id model untuk skop `model`, id penyedia untuk skop `provider`). `tokenLimit` mestilah integer positif (ditukar daripada rentetan). Pilihan: `id` (abaikan untuk mencipta, berikan untuk mengemas kini), `resetInterval` (`daily` | `weekly` | `monthly`, lalai `monthly`), `resetTime` (`HH:MM`), `enabled` (lalai `true`). Respons `GET` memperkaya setiap had dengan `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, dan `nextResetAt`. Ini ialah titik akhir kelas pengurusan (pengesahan dikuatkuasakan secara berpusat oleh saluran authz).

## Pemprosesan Permintaan

1. Klien menghantar permintaan kepada `/v1/*`
2. Pengendali laluan memanggil `handleChat`, `handleEmbedding`, `handleAudioTranscription`, atau `handleImageGeneration`
3. Model ditentukan (penyedia/model langsung atau alias/kombo)
4. Bukti kelayakan dipilih daripada DB setempat dengan penapisan ketersediaan akaun
5. Untuk sembang: `handleChatCore` menyemak cache semantik/tandatangan dan menentukan tetapan pemampatan kombo
6. Pemampatan proaktif dijalankan sebelum penterjemahan penyedia apabila didayakan (`lite`, Caveman, RTK, atau bertindan)
7. Pelaksana penyedia menghantar permintaan huluan
8. Respons diterjemahkan kembali kepada format klien (sembang) atau dikembalikan tanpa perubahan (pembenaman/imej/audio)
9. Penggunaan, analitik pemampatan, dan log permintaan direkodkan
10. Sandaran digunakan apabila berlaku ralat mengikut peraturan kombo

Rujukan seni bina lengkap: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Ketahanan (lanjutan)

OmniRoute menyediakan tiga mekanisme kegagalan sementara yang bebas; titik akhir pengurusan di bawah membolehkan pengendali membaca dan mengatasinya:

| Skop                       | Storan keadaan                             | Baca                                      | Tetapkan semula / kosongkan                                          |
| -------------------------- | ------------------------------------------ | ----------------------------------------- | -------------------------------------------------------------------- |
| Pemutus penyedia           | `domain_circuit_breakers` + dalam memori   | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                         |
| Tempoh bertenang sambungan | `rateLimitedUntil` pada sambungan penyedia | `/api/rate-limits`, `/api/providers/[id]` | (didayakan semula secara tertangguh; kosongkan melalui PUT penyedia) |
| Penguncian model           | Daftar ketersediaan model dalam memori     | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                             |

`PATCH /api/resilience` menerima penggantian pemutus penyedia di bawah `providerBreaker.oauth` dan `providerBreaker.apikey`. Setiap profil menyokong `degradationThreshold`, `failureThreshold`, dan `resetTimeoutMs`; medan yang sama disediakan dalam Papan Pemuka → Tetapan → Ketahanan.

```bash
# Kosongkan satu penguncian model
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Kosongkan semua penguncian
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Untuk rujukan konsep penuh dan nilai lalai pemutus, lihat [`CLAUDE.md`](../../CLAUDE.md) → "Keadaan Masa Jalan Ketahanan" dan [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Baris Gilir Had Kadar & Jaringan Keselamatan Daya-Aktif Automatik

- **Laluan tulis yang disokong**: `POST /api/rate-limits` dengan isi `{"connectionId": "<id>", "enabled": true|false}` ialah titik akhir pengurusan yang disokong untuk menghidupkan atau mematikan perlindungan had kadar bagi sesuatu sambungan. `PUT /api/providers/[id]` sengaja tidak mengubah atau menukar `rateLimitProtection` (#11278).
- **Semantik `enabled: false`**: Menetapkan `enabled: false` mengalih keluar perlindungan eksplisit bagi sambungan tersebut, tetapi **tidak** mengecualikan sambungan kunci API yang aktif daripada jaringan keselamatan daya-aktif automatik global (`autoEnableApiKeyProviders = true`). Dalam `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` dan `undefined` adalah setara; sambungan kunci API aktif tanpa perlindungan eksplisit kekal dilindungi di bawah jaringan keselamatan daya-aktif automatik.
- **Nyahdaya global**: Untuk menjalankan sambungan kunci API tanpa baris gilir had kadar, nyahdayakan jaringan keselamatan secara global melalui `RATE_LIMIT_AUTO_ENABLE=false` (persekitaran) atau `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Tetapan → Ketahanan / `PATCH /api/resilience`).

## Pelayan MCP

OmniRoute disertakan dengan pelayan Model Context Protocol terbina dalam dengan 3 pengangkutan (stdio, SSE, streamable-http) dan alat dengan skop tertentu. Titik akhir papan pemuka di bawah membaca data status/audit dan memproksikan pengangkutan HTTP.

| Kaedah | Laluan | Penerangan |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------- |
| GET | `/api/mcp/status` | Denyutan jantung, pengangkutan, keadaan dalam talian, panggilan terakhir, alat paling kerap digunakan, kadar kejayaan 24 jam |
| GET | `/api/mcp/tools` | Senarai alat MCP dengan `name`, `description`, `scopes`, `phase`, `auditLevel`, `sourceEndpoints` |
| GET | `/api/mcp/sse` | Buka strim SSE untuk pengangkutan SSE (mengembalikan `503` jika MCP dinyahdayakan atau pengangkutan tidak sepadan) |
| POST | `/api/mcp/sse` | Hantar bingkai JSON-RPC melalui pengangkutan SSE |
| GET | `/api/mcp/stream` | Buka bahagian SSE bagi pengangkutan HTTP Boleh Distrim (mesej yang dimulakan oleh pelayan) |
| POST | `/api/mcp/stream` | Hantar bingkai JSON-RPC melalui pengangkutan HTTP Boleh Distrim |
| DELETE | `/api/mcp/stream` | Tamatkan sesi HTTP Boleh Distrim |
| GET | `/api/mcp/audit` | Tanya log audit — `?limit=`, `?offset=`, `?tool=`, `?success=true                                | false`, `?apiKeyId=` |
| GET | `/api/mcp/audit/stats` | Statistik audit agregat (jumlah, kadar kejayaan, purata tempoh, alat paling kerap digunakan) |

**Pengesahan:** pengangkutan `sse`/`stream` mematuhi permukaan pengesahan khusus MCP (kunci API Bearer dengan skop `mcp`); laluan `status`/`tools`/`audit*` boleh dibaca daripada papan pemuka (tiada pengesahan tambahan diperlukan selain dapat mencapai hos papan pemuka).

> Kedua-dua pengangkutan HTTP dikawal oleh `settings.mcpEnabled` dan `settings.mcpTransport` — ketidakpadanan pengangkutan mengembalikan `400`, manakala keadaan MCP yang dinyahdayakan mengembalikan `503`.

## Pelayan A2A

OmniRoute menyediakan titik akhir A2A (Ejen-ke-Ejen) JSON-RPC 2.0 serta pembalut REST untuk tujuan pemeriksaan/papan pemuka.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # pilihan melainkan OMNIROUTE_API_KEY ditetapkan
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Kaedah yang disokong (semuanya dikawal oleh `settings.a2aEnabled`):

| Kaedah           | Penerangan                                                                 |
| ---------------- | -------------------------------------------------------------------------- |
| `message/send`   | Pelaksanaan kemahiran segerak; mengembalikan `{task, artifacts, metadata}` |
| `message/stream` | Pelaksanaan penstriman SSE bagi set kemahiran yang sama                    |
| `tasks/get`      | Dapatkan tugas berdasarkan `taskId`                                        |
| `tasks/cancel`   | Batalkan tugas berdasarkan `taskId`                                        |

Kemahiran terbina dalam: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kad Ejen

```bash
GET /.well-known/agent.json
```

Mengembalikan kad ejen A2A awam (nama, penerangan, keupayaan, katalog kemahiran, skema pengesahan) — dicache secara awam selama 1 jam. Pengesahan tidak diperlukan.

### Pembantu REST

| Kaedah | Laluan                       | Penerangan                                                                                                            |
| ------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | A2A didayakan + statistik tugas + ringkasan kad ejen yang dicache                                                     |
| GET    | `/api/a2a/tasks`             | Senaraikan tugas — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Tidak dilaksanakan sebagai pembantu REST — cipta melalui JSON-RPC `message/send`)                                    |
| GET    | `/api/a2a/tasks/[id]`        | Dapatkan satu tugas                                                                                                   |
| POST   | `/api/a2a/tasks/[id]/cancel` | Batalkan tugas                                                                                                        |

**Pengesahan:** pembantu REST beroperasi tanpa pengesahan pengurusan (boleh dibaca oleh papan pemuka); laluan JSON-RPC `/a2a` menggunakan Bearer `OMNIROUTE_API_KEY` jika dikonfigurasikan.

devin-cli dan sebagainya). Lihat [Rujukan Penyedia](./PROVIDER_REFERENCE.md) untuk senarai penuh.

| Kaedah | Laluan                                  | Penerangan                                                                                                                                                      |
| ------ | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/cli-tools/all-statuses`           | Status semua alat CLI (dipasang, versi, kali terakhir dikesan)                                                                                                  |
| GET    | `/api/cli-tools/status`                 | Butiran status untuk satu alat CLI (pertanyaan `?tool=`)                                                                                                        |
| POST   | `/api/cli-tools/apply`                  | Tulis konfigurasi terjana alat (`dryRun` memaparkan pratonton; `422` + `containerEphemeralTarget` apabila dikontena; `migration` mencatatkan YAML Codex legasi) |
| GET    | `/api/cli-tools/backups`                | Senaraikan sandaran konfigurasi alat CLI                                                                                                                        |
| POST   | `/api/cli-tools/backups`                | Cipta sandaran bagi semua konfigurasi alat CLI                                                                                                                  |
| POST   | `/api/cli-tools/backups`                | Pulihkan: titik akhir yang sama dengan `{tool, backupId}` dalam badan akan memulihkan sandaran tersebut                                                         |
| GET    | `/api/cli-tools/antigravity-mitm`       | Status proksi MITM Antigravity (alat CLI "antigravity-mitm")                                                                                                    |
| POST   | `/api/cli-tools/antigravity-mitm/alias` | Konfigurasikan alias antigravity-mitm                                                                                                                           |

**Pengesahan:** Memerlukan sesi pengurusan.

## Kawalan Keselamatan

Periksa kawalan keselamatan masa jalan (pengesanan PII, pengesanan suntikan gesaan, perantaraan penglihatan). Kawalan keselamatan dijalankan pada setiap permintaan; pengecualian bagi setiap panggilan dilakukan melalui pengepala permintaan `x-omniroute-disabled-guardrails` — tiada permukaan daya/nyahdaya yang dikekalkan.

| Kaedah | Laluan                 | Penerangan                                                                                                             |
| ------ | ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/guardrails`      | Senaraikan kawalan keselamatan yang didaftarkan dan statusnya (nama / didayakan / keutamaan)                           |
| POST   | `/api/guardrails/test` | Jalankan percubaan kering bagi saluran paip prapanggilan pada input sampel — kandungan: `{input, disabledGuardrails?}` |

**Pengesahan:** Memerlukan sesi pengurusan.

Lihat [Keselamatan > Kawalan Keselamatan](../security/GUARDRAILS.md) untuk butiran lengkap.

## Pengesahan

Lihat [Pengesahan Pengurusan](../guides/MANAGEMENT-AUTH.md) untuk empat
keluarga kelayakan (sesi papan pemuka, token CLI setempat, Token Akses
`oma_live_…`, kunci API berskop pengurusan) dan perbezaannya daripada kunci inferens.

- Laluan papan pemuka (`/dashboard/*`) menggunakan kuki `auth_token`
- Log masuk menggunakan cincangan kata laluan yang disimpan; jika gagal, gunakan `INITIAL_PASSWORD`
- `requireLogin` boleh ditogol melalui `/api/settings/require-login`
- Laluan `/v1/*` boleh mewajibkan kunci API Bearer apabila `REQUIRE_API_KEY=true`
- "token pengurusan" / "kunci API berskop pengurusan" dalam rujukan ini bermaksud salah satu keluarga dalam panduan tersebut — bukan jenis rahsia tambahan yang tidak ditakrifkan

> **Perubahan yang memecahkan keserasian (v3.8.0)** — `/api/v1/agents/tasks/*` dan titik akhir pengurusan tempoh bertenang kini memerlukan **pengesahan pengurusan** (kuki `auth_token` papan pemuka atau kunci API berskop pengurusan). Klien yang sebelum ini memanggil laluan ini tanpa pengesahan akan menerima `401 Unauthorized`. Lihat komit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
