## Tlestijiet taċ-Chat

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

#### Iffissar ta’ kont għal kull talba

Meta fornitur ikollu diversi konnessjonijiet (kontijiet jew ċwievet), OmniRoute normalment jagħżel waħda
permezz tal-istrateġija tiegħu għall-għażla tal-kontijiet. Minflok, talba tista’ tiffissa konnessjoni
speċifika waħda bl-intestatura `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Fejn issib l-id.** Iftaħ il-paġna tal-fornitur fil-pannell
  (**Pannell → Fornituri → <fornitur>**) u kklikkja ċ-ċippa tal-id `xxxxxxxx…` fuq ringiela ta’ konnessjoni
  — din tikkopja l-id sħiħ tal-konnessjoni.
- **Liema talbiet jirrispettawh.** Talbiet b’mudell wieħed (`provider/model`) fuq
  `/v1/chat/completions`, `/v1/messages` u `/v1/responses`. Il-kombinazzjonijiet jinjoraw l-intestatura: iffissa
  kont għal kull pass tal-kombinazzjoni permezz tal-konnessjoni proprja tal-pass minflok.
- **L-iffissar huwa strett, mhux preferenza.** Il-konnessjoni ffissata tintuża esklussivament. Jekk
  iseħħ falliment fit-talba, jiġi rreġistrat il-perjodu ta’ sospensjoni tal-kont iżda **ma** ssirx rotazzjoni lejn
  kont ieħor tal-istess fornitur.
- **Il-perjodu ta’ sospensjoni u l-kwota jirrilaxxaw l-iffissar.** Waqt li l-konnessjoni ffissata tkun f’perjodu ta’ sospensjoni,
  tkun eżawriet il-kwota jew tkun imblukkata minn politika tal-kwoti, talbiet sussegwenti jaqgħu lura fuq
  il-konnessjonijiet l-oħra tal-fornitur, eżatt bħat-traffiku mhux iffissat.
- **Ids mhux magħrufa jew diżattivati jfallu.** Id li ma jkunx fil-ġabra attiva tal-fornitur (imħassar,
  diżattivat, jew li jappartjeni lil fornitur ieħor) ma jħalli l-ebda kont eliġibbli, għalhekk it-talba
  tfalli minflok ma tiġi diretta lejn post ieħor mingħajr avviż.

Claude Code jibgħat intestaturi personalizzati permezz ta’ `ANTHROPIC_CUSTOM_HEADERS`. Poġġih fil-blokka `env`
ta’ `~/.claude/settings.json`, jew f’`.claude/settings.json` fil-livell tal-proġett biex tiffissa kont
differenti għal kull proġett:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Sors: `src/sse/handlers/chat.ts` (qari tal-intestatura), `src/sse/services/auth.ts` u
`src/sse/services/sessionAffinityPin.ts` (rilaxx tal-iffissar u l-verifika ta’ assenza mill-ġabra).

> **Intestaturi tat-telemetrija tal-ispejjeż:** tweġibiet ta’ suċċess mingħajr streaming jinkludu wkoll is-sett tat-telemetrija tal-ispejjeż `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, b’10 ċifri deċimali fissi; `0.0000000000` għal servizzi bla ħlas/mingħajr prezz), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit`, u `X-OmniRoute-Fallback-Attempts` (meta > 0 biss), flimkien ma’ `X-OmniRoute-Request-Id` u `X-OmniRoute-Version`. Dawn jinħarġu mill-ikkompletar taċ-chat, `/v1/responses`, `/v1/messages`, **u mill-endpoints tal-midja** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations`, u `/v1/moderations` (dejjem bi spiża ta’ `0`). L-ispiża tal-midja tiġi kkalkolata għal kull modalità (għal kull immaġni, sekonda, karattru jew unità ta’ tiftix) meta l-ipprezzar ikun disponibbli; inkella tkun `0` (falliment permissiv).

> **Semantika tal-ispiża għal riżultat misjub fil-cache:** meta jkun hemm riżultat misjub fil-cache semantika (`X-OmniRoute-Cache-Hit: true`) ma ssir l-ebda sejħa upstream, għalhekk `X-OmniRoute-Response-Cost` ikun `0.0000000000` (l-ispiża **inkrementali** biex jiġi servut ir-riżultat). L-ispiża oriġinali/li kienet tkun applikabbli tiġi rrappurtata separatament f’`X-OmniRoute-Cost-Saved`. Il-konsumaturi tad-dejta tal-kontijiet għandhom jgħoddu s-somma ta’ `X-OmniRoute-Response-Cost` (ir-riżultati mill-cache ma jiswew xejn); l-analitika tal-cache tista’ taggrega `X-OmniRoute-Cost-Saved`.

Il-kiri esklussiv ta’ sessjonijiet immaniġġjati huwa kuntratt ta’ routing fakultattiv u newtrali għall-klijent: sid attiv wieħed
iżomm konnessjoni OmniRoute eliġibbli waħda. Dan ma jikrix mudell, ma jeħtieġx OAuth, ma jidentifikax
klijent partikolari, u lanqas ma jeħtieġ fornitur partikolari.

Iċ-ċavetta tal-API li tawtentika jrid ikollha l-ambitu `lease:exclusive` u lista espliċita mhux vojta
`allowedConnections`. Il-konfini tal-mutazzjoni tad-database jinforza ż-żewġ kampijiet flimkien waqt il-ħolqien
taċ-ċavetta u l-aġġornamenti parzjali.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Ir-risposti ta’ akkwist, tiġdid u rilaxx li jirnexxu juru timestamps, `state`, u l-valur pożittiv eżatt ta’
`generation`, iżda qatt il-konnessjoni magħżula jew il-kredenzjali. It-tiġdid u r-rilaxx jipprovdu l-
ġenerazzjoni fil-body JSON:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Sid ta’ kiri attiv jista’ jitlob b’mod espliċitu metadata għall-wiri sikura għall-privatezza għar-rabta attwali tiegħu:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Din l-azzjoni fakultattiva tal-istatus hija protetta mill-barriera tas-sid opak, miċ-ċavetta tal-API mmaniġġjata u awtentikata, u mill-
ġenerazzjoni attiva eżatta fi tranżazzjoni waħda tad-database. `displayName` huwa biss l-isem ikkonfigurat u mirqum
tal-konnessjoni; ikun `null` meta ma jkun jeżisti ebda isem ikkonfigurat sikur. OmniRoute qatt ma jissostitwixxi dan b’
email jew identità ġġenerata tal-kont. Il-valur tal-fornitur huwa tikketta mhux sensittiva għall-wiri u qatt
identifikatur iġġenerat ta’ fornitur kompatibbli. Kredenzjali, tokens, cookies, ids mhux ipproċessati tal-konnessjoni jew taċ-ċavetta tal-
API, hashes tas-sid, sigrieti tal-barriera, u data interna tar-routing huma esklużi.

Tfittxijiet b’ċavetta żbaljata, sid żbaljat, ġenerazzjoni skaduta, nieqsa, skaduta biż-żmien, rilaxxata, jew invalidata kollha
jirritornaw l-istess żball `409 LEASE_FENCE_STALE` mingħajr metadata tal-konnessjoni. Klijent li rċieva r-risposta ta’ stennija għall-kapaċità ma għandu l-ebda rabta attiva x’jispezzjona. Meta r-routing jittrasferixxi kiri attiv,
l-istess ġenerazzjoni tibqa’ valida u l-istatus jirritorna atomikament ir-rabta l-ġdida, qatt dik l-antika.
Il-klijenti eżistenti jibqgħu ma jinbidlux għax ir-risposti ta’ akkwist, tiġdid, rilaxx u stennija jżommu
l-forom preċedenti tagħhom.

Dan il-kuntratt tas-server ma jbiddilx `/status` standard ta’ OpenAI Codex. Il-verżjoni standard ta’ Codex bħalissa tirrapporta l-
fornitur tal-mudell tagħha u l-istat integrat tal-awtentikazzjoni/kont, iżda ma turix metadata arbitrarja tal-
kont ta’ fornitur personalizzat; integrazzjoni futura tal-klijent trid issejjaħ din l-azzjoni u tiddeċiedi kif
turi `connection.displayName`.

Kull talba ta’ inferenza mmaniġġjata mbagħad tipprovdi ż-żewġ headers ta’ kontroll:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Is-sid eżatt, il-ġenerazzjoni, il-konnessjoni attiva, u ċ-ċavetta tal-API awtentikata jiġu vverifikati mill-barriera immedjatament
qabel kull tentattiv upstream appoġġjat. Ir-ripetizzjoni tas-sid u tal-ġenerazzjoni b’ċavetta oħra tfalli anke
meta dik iċ-ċavetta tippermetti l-istess konnessjoni. Is-sidien mhux ipproċessati ma jiġux ippersistiti, irreġistrati fil-logs, miżmuma fl-
snapshot tat-talba, jew mgħoddija upstream.

Kontenzjoni temporanja tirritorna HTTP `429` b’`Retry-After` u:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Din ir-risposta tfisser biss li s-sett eliġibbli ordinarju ma kienx vojt u kull kandidat liberu kien
miżmum minn kiri attiv ta’ sid ieħor. Mudelli/fornituri mhux appoġġjati, nuqqas ta’ qbil mal-politika, cooldown, kwota,
saħħa, u fallimenti ordinarji oħra tal-eliġibbiltà jżommu r-risposti OmniRoute eżistenti tagħhom.

### `x-omniroute-compression`

Sovrascrittura għal kull talba tal-pjan tal-kompressjoni. L-ogħla preċedenza — tegħleb is-sovrascrittura tal-kombinazzjoni tar-routing,
il-profil attiv, l-attivazzjoni awtomatika, u l-Konfigurazzjoni Predefinita tal-pannell. Valuri:

| Valur         | Effett                                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------------------- |
| `off`         | Ebda kompressjoni għal din it-talba.                                                                             |
| `default`     | Il-profil Predefinit derivat mill-pannell (jinjora l-profil attiv). Il-magni lossy jibqgħu mitfija.              |
| `safe`        | Dedup u konsolidazzjoni tal-ispazji bojod biss.                                                                  |
| `allow-lossy` | Żomm il-pjan tal-operatur għal din it-talba, inklużi sommarji u kitbiet mill-ġdid tal-istil.                     |
| `engine:<id>` | Magna waħda meta tkun attivata, eż. `engine:rtk`. Attivazzjoni fakultattiva għal kull talba għal dik il-magna.   |
| `<combo>`     | Kombinazzjoni msemmija, imqabbla l-ewwel bl-isem (mingħajr distinzjoni bejn ittri kbar u żgħar), imbagħad bl-id. |

Noti:

- Valuri mhux magħrufa jiġu injorati (it-talba qatt ma tiġi rrifjutata); ir-riżoluzzjoni tkompli skont il-preċedenza normali tal-operatur.
- Jekk diversi kombinazzjonijiet ikollhom l-istess isem, għaddi l-**id** tal-kombinazzjoni għal tqabbil deterministiku.
- Kombinazzjoni li isimha huwa `off` jew `default` ma tistax tintgħażel bl-isem (dawk il-kliem ewlenin jiġu interpretati l-ewwel); irreferi għal tali kombinazzjoni bl-id tagħha.
- Is-swiċċ ewlieni tal-kompressjoni huwa restrizzjoni assoluta: meta l-kompressjoni tkun diżattivata globalment, dan il-header ma jistax jattivaha.

Il-pjan applikat jiġi ripetut fil-header tar-risposta:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

fejn `<source>` huwa wieħed minn `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, jew `off`.

## Inkorporazzjonijiet

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Fornituri disponibbli: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

L-identifikaturi tal-katalgu huma `provider/model` (eżempju: `jina-ai/jina-embeddings-v5-omni-small`). L-identifikaturi tal-mudelli Jina mingħajr prefiss li jidhru fir-reġistru (pereżempju `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) jiġu riżolti wkoll. L-operazzjonijiet ta’ Jina għall-inkorporazzjoni, ir-riklassifikazzjoni, il-klassifikazzjoni u s-segmentazzjoni jużaw l-ewwel il-kredenzjali `jina-ai` tad-dashboard; `JINA_AI_API_KEY` jintuża bħala alternattiva biss meta ma teżisti ebda ċavetta fid-dashboard. Il-kard `jina-reader` hija biss għal Reader / `r.jina.ai` (`POST /v1/web/fetch`) u qatt ma tipprovdi inkorporazzjonijiet jew riklassifikazzjoni.

Il-mudelli tar-reġistru li jiddikjaraw appoġġ multimodali jaċċettaw ukoll sa 32 element strutturat
indipendenti mill-fornitur. It-tipi tal-elementi tal-midja huma `text`, `image`, `audio`, `video`, u `document`. Is-`source`
tal-midja tagħhom tkun jew `{"type":"url","url":"https://..."}` jew
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`,
u l-alias tal-familja `jina-ai/jina-embeddings-v5-omni` → omni-small) jaċċetta wkoll id-dokumenti
nattivi EmbeddingsV5Request ta’ Jina u **jgħaddihom intatti** lil `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Il-valuri nattivi `{ image | audio | video | pdf }` jistgħu jkunu URL HTTPS pubbliku, URI `data:`, jew
base64 mhux ipproċessat. OmniRoute ma jikkonvertix dawk l-oġġetti f’strings u lanqas ma jġib URLs nattivi tal-immaġnijiet — Jina jġib
il-midja pubblika huwa stess. Oqsma addizzjonali ta’ Jina (`task`, `normalized`, `truncate`, `embedding_type`) jiġu
mgħoddija. L-SKUs ta’ Jina li jaċċettaw test biss xorta jirrifjutaw dokumenti li mhumiex test.

Limiti tas-sigurtà u tat-trasport:

- L-URLs remoti tal-midja jridu jkunu HTTPS pubbliċi. L-elementi kanoniċi `{type,source:url}` jinġiebu
  min-naħa tas-server (b’validazzjoni mill-ġdid tar-ridirezzjonijiet, timeout, limiti tad-daqs, DNS pubbliku u ffissar tal-konnessjoni) u
  jiġu inklużi direttament qabel is-sejħa lill-fornitur. L-elementi nattivi ta’ Jina `{image:"https://..."}` jiġu mgħoddija kif inhuma
  wara l-istess verifika tal-HTTPS pubbliku; Jina jġib il-URL.
- Il-midja base64 inkluża direttament hija limitata għal 8 MiB dekodifikati għal kull element u 16 MiB dekodifikati fit-talba kollha.

Traduzzjoni għall-fornitur (l-elementi kanoniċi qatt ma jiġu mgħoddija mingħajr tibdil):

- Mudelli multimodali ta’ Jina: kull element tal-ogħla livell isir oġġett wieħed b’ċavetta tal-modalità
  (`text` / `image` / `audio` / `video` / `pdf`) bl-użu ta’ URIs tad-data għall-midja inkluża direttament; vettur wieħed għal kull
  element tal-ogħla livell.
- Familja Gemini Embedding 2: array wieħed tal-ogħla livell isir talba nattiva waħda
  `models/{model}:embedContent` b’`content.parts` (`text` jew `inline_data`).
- llama.cpp (`llama-cpp/<model>`, kwalunkwe mudell li tella’ s-server lokali): l-elementi kanoniċi `text`
  jsiru strings sempliċi, u `image` / `audio` / `video` isiru oġġett wieħed
  `{"content": [part]}` kull wieħed, bl-użu tal-partijiet tal-kontenut taċ-chat ta’ llama-server (`image_url`,
  `input_audio` bil-format `wav` / `mp3` / `flac`, `input_video`) b’data inkluża direttament; vettur wieħed
  għal kull element tal-ogħla livell. Is-server irid jitħaddem b’`--embedding --mmproj …`; mingħajr proġettur huwa
  stess jirrifjuta l-midja. `document` mhuwiex appoġġjat.
- Mudelli mhux magħrufa/dinamiċi mingħajr metadata espliċita dwar il-modalità jirrifjutaw input strutturat b’HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Kombinazzjonijiet mhux appoġġjati ta’ mudell/modalità jirritornaw HTTP 400 minflok ma jikkonvertu l-element. L-oqsma ta’ estensjoni
li mhumiex tal-input f’talbiet preċedenti b’strings/tokens jibqgħu jiġu mgħoddija mingħajr tibdil.

```bash
# Elenka l-mudelli kollha tal-inkorporazzjonijiet
GET /v1/embeddings
```

### Prefissi tal-id tal-mudell (`?prefix=`)

Il-biċċa l-kbira tal-mudelli jiġu elenkati taħt **prefiss tal-fornitur**. Il-prefiss li tikseb jiġi kkontrollat mill-feature flag `MODELS_CATALOG_PREFIX_MODE`, u jista’ jiġi sostitwit **għal kull talba** permezz ta’ parametru tal-query — utli għal client li jkun irid lista nadifa mingħajr ma jibdel l-issettjar għas-server kollu għal kulħadd:

```bash
GET /v1/models?prefix=alias        # id wieħed għal kull mudell — il-prefiss qasir tal-alias
GET /v1/models?prefix=dual         # iż-żewġ forom (il-valur predefinit tas-server)
GET /v1/models?prefix=canonical    # il-prefiss sħiħ tal-id tal-fornitur biss
```

| Modalità    | Joħroġ                                                  | Noti                                                                                                                                                                                                                                   |
| ----------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **u** `claude/claude-sonnet-4-6` | **Predefinita.** Iż-żewġ ids jiġu direzzjonati lejn l-istess mudell; jinżammu sabiex il-konfigurazzjonijiet tal-clients li għandhom waħda mill-forom ikkodifikata direttament jibqgħu jaħdmu. Bejn wieħed u ieħor jirdoppja l-katalgu. |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Entrata waħda għal kull mudell. Il-fornituri mingħajr alias distint xorta joħorġu l-entrata tagħhom, għalhekk ma jintilef xejn.                                                                                                        |
| `canonical` | `claude/claude-sonnet-4-6`                              | Entrata waħda għal kull mudell taħt il-prefiss sħiħ tal-id tal-fornitur. Il-fornituri mingħajr alias distint (eż. `antigravity/…`, `agy/…`) joħorġu wkoll l-id waħdieni tagħhom hawnhekk, għalhekk ma jintilef xejn.                   |

Mirror fil-modalità `dual` jista’ jiġi rikonoxxut ukoll mingħajr il-parametru tal-query: ikollu field `parent` li jindika l-id primarju.

Il-clients li juru selettur tal-mudelli għandhom jitolbu `?prefix=alias` — hekk tagħmel l-[estensjoni OmniCopilot għal VS Code](../guides/VSCODE-COPILOT.md).

### Filtri tal-iskoperta (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` jaċċetta filtri tal-iskoperta li jridu jintgħażlu espliċitament. Mingħajr ebda wieħed minnhom, ir-rispons ma jinbidilx. Dawn jirrestrinġu l-katalgu li diġà jara min jagħmel it-talba (il-permessi tal-API key japplikaw l-ewwel), u jitħaddmu qabel il-paginazzjoni bi stil OpenAI ta’ `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # kull kapaċità elenkata trid tkun vera
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # it-`type` tal-katalgu; ir-ringieli mingħajru huma `chat`
GET /v1/models?q=sonnet&limit=10                           # tqabbil mhux sensittiv għall-ittri kbar jew żgħar fuq l-id jew l-isem
```

| Param         | Valuri                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | numru sħiħ mhux negattiv, imqabbel ma’ `context_length`                                             |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 karattru                                                                                      |

Valur mhux magħruf, jew `min_context` li mhuwiex numru sħiħ mhux negattiv (pereżempju `1.5`), jirritorna HTTP `400` u l-messaġġ jelenka l-valuri validi. Implimentazzjoni: `src/app/api/v1/models/catalogFilters.ts`.

### Lista qasira ta’ mudelli (`POST /v1/models/query`)

`POST /v1/models/query` jirritorna lista qasira u deterministika mill-istess katalgu, bl-istess awtentikazzjoni u viżibilità għal kull key bħal `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Kull field huwa fakultattiv. `capabilities` u `exclude` jaċċettaw array jew string separata b’virgoli; `max_output` jitqabbel ma’ `max_output_tokens`. Ir-riżultati jiġu magħżula skont `owned_by`, imbagħad skont `id`. Il-valur predefinit ta’ `limit` huwa `20` u l-valuri ogħla minn `100` jiġu limitati għal `100`. JSON invalidu, field mhux magħruf jew valur invalidu jirritorna HTTP `400`.

### Mudelli taċ-chat moħbija individwalment

Mudell immarkat bħala **Moħbi** fil-paġna tal-fornitur tiegħu jiġi eskluż mill-katalgu u miċħud b’HTTP `404` / `model_not_found` meta jintalab espliċitament. Il-verifika tuża l-fornitur u l-mudell riżolti, inklużi l-aliases tal-fornitur, il-prefissi tan-nodi tal-fornituri kompatibbli, u l-valuri predefiniti tal-konnessjoni. Kombinazzjoni taqbeż il-miri moħbija u tista’ tuża mudell relatat viżibbli; meta ma jibqa’ ebda mira eżegwibbli, tirritorna l-istess kodiċi ta’ żball. It-tneħħija tal-ħabi tidħol fis-seħħ mat-talba li jmiss. Is-sostituzzjonijiet tal-viżibilità għall-immaġnijiet biss ma jaħbux il-mudell taċ-chat bl-istess ID.

Dan l-issettjar individwali tal-mudell huwa separat mil-[listi ta’ permess/projbizzjoni għall-esponiment tal-mudelli](../routing/MODEL_EXPOSURE_LIST.md), li jiffiltraw ir-reklamar tal-katalgu u l-kandidati għad-direzzjonament awtomatiku filwaqt li jżommu d-dispaċċ espliċitu. Il-permessi tal-mudelli tal-API key jibqgħu japplikaw b’mod indipendenti. Il-modalità predefinita tal-prefiss tal-katalgu tibqa’ `dual`.

### Varjanti tal-mudelli mingħajr ħsieb

Għall-mudelli Claude li jappoġġjaw il-ħsieb, `/v1/models` jelenka wkoll varjant **mingħajr ħsieb** li l-id tiegħu għandu l-prefiss `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

L-għażla ta’ dan l-ID (eż. f’konfigurazzjoni ta’ Claude Code li dejjem tehmeż blokka `thinking`) terġa’ tirriżolvi għall-`<provider>/<model>` reali bir-raġunament diżattivat — `thinking:{type:"disabled"}` fil-mogħdija `/v1/messages`, jew jitneħħew il-kampijiet `reasoning`/`reasoning_effort` fil-mogħdija `/v1/chat/completions`. Il-varjant jiġi elenkat biss għal mudelli tal-familja Claude li jappoġġjaw il-ħsieb **u** jirrispettaw `disabled` (għalhekk, pereżempju, mudelli adaptive-only li jirrifjutaw `disabled` huma esklużi). L-operaturi jistgħu jġiegħlu l-varjant ikun mixgħul jew mitfi għal kull mudell permezz ta’ `ModelSpec.noThinkingAlias`.

## Ġenerazzjoni tal-awdjo b’ElevenLabs

Ikkonfigura konnessjoni tal-fornitur `elevenlabs` f’OmniRoute biċ-ċavetta API tiegħek ta’ ElevenLabs.
Il-klijenti jawtentikaw biċ-ċavetta **OmniRoute** tagħhom (`Authorization: Bearer $OMNIROUTE_API_KEY`);
il-gateway jipprovdi ċ-ċavetta tal-fornitur maħżuna bħala `xi-api-key`. Qatt tibgħat ċavetta ta’ ElevenLabs
bħala t-token bearer tal-gateway.

| Metodu | Mogħdija                    | Rispons                                         | Kategorija tal-endpoint taċ-ċavetta API |
| ------ | --------------------------- | ----------------------------------------------- | --------------------------------------- |
| POST   | `/v1/sound-generation`      | Bytes tal-awdjo nattivi                         | `elevenlabs`                            |
| POST   | `/v1/music`                 | Bytes tal-awdjo nattivi                         | `music`                                 |
| POST   | `/v1/music/stream`          | Bytes tal-awdjo fi streaming                    | `music`                                 |
| POST   | `/v1/music/detailed`        | Awdjo multipart nattiv u pjan ta’ kompożizzjoni | `music`                                 |
| POST   | `/v1/music/detailed/stream` | Metadata SSE nattiva u biċċiet tal-awdjo        | `music`                                 |
| POST   | `/v1/music/plan`            | Pjan ta’ kompożizzjoni JSON                     | `music`                                 |

Dawn l-endpoints jikkomplementaw ir-rotot eżistenti `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` u `/v1/speech-to-text`. Il-fields JSON nattivi
u l-parametri tal-query bħal `output_format` u `enable_logging` jinżammu.
Ir-risponsi ta’ `/v1/music/detailed` iżommu d-delimitaturi multipart tagħhom; analizzahom bħala multipart.
`/v1/music/detailed/stream` jirritorna `text/event-stream` b’metadata tal-kompożizzjoni u
biċċiet tal-awdjo base64 f’avvenimenti SSE. Is-sitt rotot kollha jappoġġjaw il-preflight ta’ CORS.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Effett tal-ħoss qasir. Tul: minn 0.5 sa 30 sekonda.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# It-tul tal-mużika huwa espress f'millisekondi: minn 3000 sa 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Uża `/v1/music/stream` bl-istess body JSON għat-trażmissjoni inkrementali tal-awdjo. Il-kompożizzjoni
taċċetta eżattament wieħed minn `prompt` jew `composition_plan`; `/v1/music/plan` jeħtieġ `prompt`
u b’mod fakultattiv jaċċetta `source_composition_plan`. L-iskemi nattivi jżommu fields addizzjonali
tal-fornitur sabiex il-verżjonijiet tal-pjanijiet ta’ kompożizzjoni u l-għażliet ta’ rfinar jaslu għand ElevenLabs.

L-endpoint unifikat `/v1/music/generations` jaċċetta wkoll `elevenlabs/music_v1`,
`elevenlabs/music_v2` u `elevenlabs/music_v2_5`. B’konnessjoni ElevenLabs attiva,
dawn il-mudelli jintwerew mill-katalgu tal-mużika. Dan l-endpoint jirritorna
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Il-field `duration` tiegħu jitkejjel
f’sekondi u jiġi mmappjat għal `music_length_ms`; `music_length_ms` espliċitu jieħu preċedenza.
`instrumental` jiġi mmappjat għal `force_instrumental`, bil-field nattiv jieħu preċedenza.
Uża l-endpoints nattivi tal-istreaming għall-istreaming u l-endpoint nattiv tal-kompożizzjoni
għal talbiet immexxija biss minn pjan ta’ kompożizzjoni.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Ir-restrizzjonijiet tal-endpoint, tal-mudell, tal-baġit u tal-konnessjoni japplikaw qabel sejħa upstream. Ir-rotot
nattivi jirritornaw il-kodiċijiet tal-istatus u l-bodies tal-iżbalji upstream mingħajr tibdil, inkluż `402` għal
restrizzjoni tal-pjan u `429` għal limitu tal-kwota. L-headers `character-cost`, `song-id`, `request-id` u `retry-after`
jinżammu meta jkunu preżenti. Bilanċ ta’ kreditu bla ħlas ma jiggarantixxix aċċess għal kull
mudell tal-mużika, format tal-output jew karatteristika tal-API: ElevenLabs jiddeċiedi l-intitolament għal kull talba.
L-endpoint unifikat iżomm il-kodiċijiet tal-istatus tal-iżbalji fl-envelop standardizzat tal-iżbalji ta’ OmniRoute.

Kuntratti upstream: [effetti tal-ħoss](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[kompożizzjoni tal-mużika](https://elevenlabs.io/docs/api-reference/music/compose) u
[dettalji tal-mużika fi streaming](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

> `http://reranker:8080/v1`; dawn jiġu msejħa direttament, qatt permezz ta’ `HTTP(S)_PROXY` jew
> proxy fiss ta’ konnessjoni). In-nodi fuq kwalunkwe

> tal-fornitur għall-URLs ħerġin (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Il-pass tal-klassifikazzjoni mill-ġdid tal-magna tal-memorja jsejjaħ din ir-rotta permezz tal-
> loopback, għalhekk l-istess regola tirregola `rerankProviderModel` fis-settings tal-Memorja.
>

> (Infinity, TEI). Il-korp mibgħut upstream jinkludi kemm it-terminoloġija ta’ Cohere/OpenAI (`documents`,
> `return_documents`) kif ukoll dik ta’ TEI (`texts`, `return_text`), u r-rispons upstream jiġi
> normalizzat għall-envelopp ta’ Cohere: il-format sempliċi ta’ TEI `[{index, score, text}]`, `{results: [{index, score}]}`
> minn gateways ħfief, u l-format ta’ Voyage `{data: [...]}` kollha jintbagħtu lura lill-klijent bħala
> `{results: [{index, relevance_score, document?}]}`, magħżula skont il-punteġġ u limitati għal `top_n`.

> **Sejbien tan-nodi tal-fornitur:** il-mudelli fuq nodu tal-fornitur kompatibbli ma’ OpenAI jidhru f’`GET /v1/models`
> taħt il-prefiss tan-nodu. Ir-ringieli li ma jkollhomx metadata dwar l-endpoint (kif tipikament jiġri fil-listi lokali ta’ `/v1/models`)
> jirtu l-`apiType` tan-nodu, għalhekk il-mudelli ta’ nodu `embeddings` ikunu `type: "embedding"` u dawk ta’
> nodu `rerank` ikunu `type: "rerank"` minflok ma jintuża chat bħala l-valur predefinit; `supportedEndpoints` espliċitu
> fuq ringiela sinkronizzata jew miżjuda manwalment xorta jieħu preċedenza.

## Użu self-service (`/api/usage/om-usage`)

Kwalunkwe ċavetta API tista' taqra l-użu u l-kwoti **tagħha stess** — mingħajr awtentikazzjoni ta' ġestjoni. Dan huwa l-endpoint li
klijent (CLI, il-pannell OmniCopilot) juża biex juri lid-detentur taċ-ċavetta l-infiq tiegħu.

```bash
# Forma testwali (il-kuntratt storiku — test sempliċi għal terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Forma strutturata — dik li tuża interfaċċa tal-utent
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Iċ-ċavetta għandu jkollha **`allowUsageCommand`** attivat (diżattivat b'mod predefinit — il-maniġer taċ-ċwievet API
tad-dashboard jaqilbu għal kull ċavetta). Mingħajru, l-endpoint iwieġeb `403`.

`?format=json` jirritorna struttura diskriminata sabiex min isejjaħ qatt ma jaqra kamp tad-data minn
rifjut. F'każ ta' suċċess:

```jsonc
{
  "allowed": true,
  // preżenti biss meta ċ-ċavetta tkun għażlet limiti tal-użu għal kull ċavetta (USD kuljum/kull ġimgħa):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // l-istampa attwali tal-kwota tal-fornitur magħżul, jew null meta għadu ma hemm xejn fil-cache:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // l-istampa attwali ta' kull konnessjoni, sabiex interfaċċa tal-utent tkun tista' tirrendi diversi fornituri ħdejn xulxin:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
```

### Perċentwali tal-Kwota Mhux Aġġustati meta mqabbla ma' Dawk Aġġustati għal-Limitu ta' Waqfien

Meta jużaw `/api/usage/om-usage`, dawk li jsejħu għandhom jinnotaw id-distinzjoni bejn il-
perċentwali ppreżentati mill-**output b'test sempliċi** u l-**output JSON** strutturat:

| Aspett                            | Format b'test sempliċi (`/api/usage/om-usage` / `@@om-usage`)                                           | Format JSON (`?format=json`)                                                                   |
| :-------------------------------- | :------------------------------------------------------------------------------------------------------ | :--------------------------------------------------------------------------------------------- |
| **Kamp tal-output**               | `NN% left` (eż., `20% left`)                                                                            | `provider.quotas` / `providers[].quotas`                                                       |
| **Kejl**                          | **Allokazzjoni użabbli aġġustata għal-limitu ta' waqfien**: kapaċità li fadal 'il fuq mil-livell limitu | **Kwota upstream mhux aġġustata**: kejl mhux aġġustat tal-fornitur                             |
| **Skalar tal-limitu ta' waqfien** | Skalata permezz ta' `effectiveRemainingPercent()` sabiex ir-riżerva protetta tidher bħala `0% left`     | Xejn (valuri mhux aġġustati tal-istampa attwali kif irrappurtati mill-fornitur)                |
| **Data tal-livell limitu**        | Inkorporata fil-perċentwal muri                                                                         | Maħżuna f'`quotaWindowThresholds` għal kull konnessjoni (jew il-valuri predefiniti tas-server) |
| **Konsumatur primarju**           | CLIs interattivi, prompts tat-terminal, operaturi umani                                                 | Integrazzjonijiet programmatiċi, dashboards, analitika, sistemi ta' traċċar tal-kontijiet      |

#### Il-Formula ta' Aġġustament għal-Limitu ta' Waqfien

OmniRoute jappoġġja limiti proattivi tal-kwota biex jipprevjeni l-eżawriment upstream (ikkonfigurati permezz tal-
`quotaWindowThresholds` tal-konnessjoni, il-valuri predefiniti tal-fornitur, jew is-settings globali tar-reżiljenza). Meta livell limitu ta' waqfien
(eż., `cutoff = 25%`) ikun attiv fuq tieqa tal-kwota, ir-renderer tat-test jikkalkula l-allokazzjoni li fadal hekk:

- Jekk `remaining <= cutoff`: jirritorna `0%`.
- Jekk `remaining > cutoff`: jirritorna `((remaining - cutoff) / (100 - cutoff)) * 100`.

L-output testwali fformattjat jarrotonda dan għall-eqreb numru sħiħ (`Math.round(...)`).

#### Eżempju Illustrattiv

Ikkunsidra tieqa ta' fornitur b'**60% użu mhux aġġustat** (għalhekk **40% tal-kwota mhux aġġustata għadha disponibbli**) u
livell limitu kkonfigurat ta' **25% tal-kwota li jifdal bħala limitu ta' waqfien**:

| Rappreżentazzjoni                       | Kalkolu                                            | Jifdal  |                  Użu Impliċitu                  |
| :-------------------------------------- | :------------------------------------------------- | :-----: | :---------------------------------------------: |
| **JSON mhux aġġustat (`?format=json`)** | Stampa attwali upstream (`quotas[window]`)         | **40%** |                     **60%**                     |
| **Format testwali (`NN% left`)**        | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` | **20%** | **80%** (jekk jiġi kkalkulat `100 - remaining`) |

- **Għaliex it-test juri 20% li fadal:** Mill-40% tal-kwota fiżika li għad fadal fil-kont, 25% hija riżervata mill-
  politika tal-limitu ta' waqfien. Min isejjaħ għandu biss 15% minn 75% ta' marġni użabbli li jifdal qabel ma r-router jieqaf
  jidderieġi lejn din il-konnessjoni. L-iskalar jiżgura li l-konnessjoni tindika l-eżawriment (`0% left`) eżattament meta
  jieqaf id-direzzjonament.
- **Għaliex JSON iżomm il-valuri mhux aġġustati:** Il-payload JSON jirritorna l-istampa attwali eżatta tal-fornitur (`UsageSnapshot`)
  sabiex għodod esterni jkollhom aċċess għall-użu upstream reali u għal
  `quotaWindowThresholds` fil-livell tal-konnessjoni mingħajr skalar b'telf min-naħa tas-server.

#### Gwida għall-Migrazzjoni tal-Konsumaturi

Jekk integrazzjoni esterna (bħal plugin ta’ editur jew estensjoni ta’ aġent) preċedentement kienet tiġbor it-test mill-
endpoint (`NN% left`) u tikkalkula l-perċentwal użat bħala `100 - NN`, il-migrazzjoni għal `?format=json` tfisser:

- Il-qari tal-valuri JSON mhux ipproċessati se jirrifletti l-**konsum upstream reali** (60% użat fl-eżempju ta’ hawn fuq).
- Jekk l-integrazzjoni tixtieq iżżomm is-semantika tal-allowance użabbli tal-endpoint tat-test, tista’ tevalwa
  l-formula effettiva tal-bqija min-naħa tal-klijent billi tuża `quotaWindowThresholds` għal overrides fil-livell tal-konnessjoni.

### Impatt fuq il-latenza

| `synthetic` | Rispons mogħti mill-cache; il-latenza mhijiex ħin upstream reali |

### Evitar tal-cache għal kull ċavetta

Iċ-ċwievet API jistgħu jagħżlu li ma jużawx qari mill-cache semantika permezz ta’ `cacheDefaultMode`:

| Valur    | Imġiba                                                        |


### Evitar għal kull talba

Kwalunkwe talba tista’ tevita l-cache irrispettivament mis-settings taċ-ċavetta:


Għall-mudelli sinkronizzati/importati, `PUT /api/provider-models` jaċċetta `provider`, `modelId`, u
`maxOutputTokenOverride`: numru sħiħ pożittiv jistabbilixxi l-limitu manwali tat-tokens tal-output, u `null`
ineħħih biex jerġa' jdaħħal il-valur predefinit. `GET /api/provider-models?provider=<provider>` jirritorna dawn
il-valuri f'`modelOutputOverrides`, inklużi mudelli mingħajr ringiela ta' mudell personalizzat. Is-sostituzzjoni
tuża l-kapaċità `max_output_tokens` waqt l-eżekuzzjoni u tibqa' fis-seħħ wara sinkronizzazzjoni mill-ġdid tal-mudell. Il-paġna tal-fornitur
kompatibbli ma' OpenAI toffri l-istess kontrolli għall-editjar/tneħħija u timmarka mudelli b'appoġġ espliċitu għall-viżjoni.

In-nodi personalizzati ta' Chat Completions jadattaw l-għażliet espliċiti ta' diżattivazzjoni tar-raġunament għall-backend upstream. Test
tal-konnessjoni li jirnexxi jagħżel awtomatikament il-kontrolli tal-mudell taċ-chat għal kull ID eżatt tal-mudell
li l-entrata tiegħu f'`/models` tagħti prova ta' valur rikonoxxut ta' `owned_by`: `vllm`, `sglang`, jew `llamacpp`.
Wrappers trasparenti kompatibbli ma' OpenAI jistgħu jżommu l-entrata oriġinali tal-mudell ġewwa oġġett
`openai` imbejjet; l-identifikazzjoni ssegwi sa tliet enveloppi bħal dawn. Mudelli bi sjieda nieqsa, mhux magħrufa, jew
kunfliġġenti jżommu l-imġiba ordinarja ta' OpenAI. L-identifikazzjoni terġa' tuża t-talba eżistenti tal-katalgu,
ma tiġġenera l-ebda token ta' tlestija, u tiġi invalidata meta jinbidel il-punt tat-tmiem tal-konnessjoni.

Biex tiffissa l-imġiba għal backend li ma jesponix dik il-metadata, uża l-API eżistenti
għall-aġġornament parzjali tal-fornitur:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Ibgħat dak il-body b'`PUT /api/providers/<connection-id>`. Fuq dik il-konnessjoni, livell espliċitu
ta' raġunament ta' `none` jintbagħat bħala `chat_template_kwargs.thinking=false` u
`chat_template_kwargs.enable_thinking=false`. Il-valuri espliċiti tal-mudell nattiv jibqgħu awtoritattivi
sakemm regola ta' raġunament fuq in-naħa tas-server ma timponix livell. Is-setting japplika biss meta konnessjoni
personalizzata kompatibbli ma' OpenAI tibgħat body ta' Chat Completions; it-talbiet ta' Responses u l-fornituri
ordinarji jżommu l-forma nattiva tat-talba tagħhom. Issettja `reasoningControl` għal `openai` biex timponi l-mogħdija
ordinarja ta' `reasoning_effort` ta' OpenAI, jew ħallih barra/issettjah għal `null` biex tuża l-identifikazzjoni awtomatika.

It-talbiet tal-klassifikatur tal-modalità awtomatika ta' Claude Code jistabbilixxu b'mod predefinit il-ħsieb nattiv bħala diżattivat meta ma jkun fihom
l-ebda kontroll espliċitu tar-raġunament. L-identifikazzjoni tuża l-markatur tas-sistema tal-klassifikatur fit-talbiet bil-format ta' Claude,
mhux l-ismijiet tal-mudelli jew il-limiti tat-tlestija. Il-kontrolli espliċiti tal-body, l-headers appoġġjati tal-livell/ħsieb,
ir-regoli tar-routing, u l-livell riżolt tal-mudell iżommu l-prijorità eżistenti tagħhom. Iż-żewġ stadji tal-klassifikatur
iżommu l-prompts, il-limiti tat-tlestija, is-sekwenzi ta' waqfien, u d-deċiżjonijiet reali tal-permessi upstream
tagħhom; it-tieni stadju xorta jista' jipproduċi r-raġunament viżibbli mitlub tiegħu bħala test ordinarju.

### Verżjoni u Kanal tar-Rilaxx

```bash
GET /api/system/version
```

Rotta ta’ ġestjoni aċċessibbli biss minn loopback (awtentikazzjoni tal-amministratur). Tirritorna l-verżjoni li qed taħdem, l-aħħar
verżjoni ppubblikata u l-istatus tal-aġġornament awtomatiku. `releaseChannel` u `channels` huma oqsma
addittivi (fergħa 3.8.54); `channel` iżomm it-tifsira tiegħu — il-modalità tad-deployment li juża
l-aġġornatur tad-dashboard (`npm`, `source` jew `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — il-kanal npm tal-build li qed jaħdem: `nightly` għall-verżjonijiet `-nightly.*`,
  `next` għal pre-rilaxxi oħra (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` għal verżjoni stabbli ta’
  verżjoni ewlenija eqdem minn `channels.latest`, inkella `latest`. L-istess regoli bħal
  `scripts/release/dist-tag.mjs`, li jagħżel l-npm dist-tag fil-ħin tal-pubblikazzjoni.
- `channels` — l-aħħar verżjoni ppubblikata ta’ kull dist-tag, minn `npm view omniroute dist-tags` (alternattiva ta’
  riżerva HTTP tar-reġistru), miżmuma fil-cache bl-istess TTL ta’ 10 minuti bħal `latest`. `latest` dejjem ikun preżenti
  (jekk meħtieġ, juża l-qasam `latest`, imbagħad `"unavailable"`); `next`, `nightly` u `lts` jidhru
  biss meta dak id-dist-tag ikun jeżisti. Talba `Cache-Control: no-cache` taġġorna ż-żewġ tfittxijiet.

Il-mudell tal-kanali (`latest` = v3 sal-4.0 GA, `next` = rc, `nightly` = builds ta’ `develop`,
`lts` = patches ta’ v3 wara l-4.0 GA) huwa deskritt f’`docs/ops/RELEASE_STRATEGY.md`.

## Limiti tat-Tokens

Baġits ta’ **tokens** għal kull ċavetta tal-API (distinti mill-Baġit ibbażat fuq USD imsemmi hawn fuq). Dawn jiġu infurzati direttament fil-fluss tat-talba: meta l-użu taċ-ċavetta fit-tieqa attwali jilħaq il-limitu tagħha, it-talbiet jiġu miċħuda b’`429 Too Many Requests`. Il-limiti jistgħu jiġu ristretti għal `model` speċifiku, għal `provider`, jew jiġu applikati `global` għaċ-ċavetta kollha; meta diversi limiti jaqblu ma’ talba, japplika l-aktar wieħed restrittiv.

```bash
# Elenka l-limiti tat-tokens ta’ ċavetta (jinkludi l-użu attwali tat-tieqa)
GET /api/usage/token-limits?apiKeyId=key-123

# Oħloq jew aġġorna limitu tat-tokens
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Ħassar limitu tat-tokens skont l-id
DELETE /api/usage/token-limits?id=tl-abc
```

> **Noti dwar l-iskema** (`setTokenLimitSchema`): `apiKeyId` u `scopeType` (`model` | `provider` | `global`) huma obbligatorji. `scopeValue` huwa obbligatorju sakemm `scopeType` ma jkunx `global` (eż. id ta’ mudell għall-ambitu `model`, jew id ta’ fornitur għall-ambitu `provider`). `tokenLimit` irid ikun numru sħiħ pożittiv (ikkonvertit minn sekwenza). Fakultattivi: `id` (ħallih barra biex toħloq, ipprovdih biex taġġorna), `resetInterval` (`daily` | `weekly` | `monthly`, valur predefinit `monthly`), `resetTime` (`HH:MM`), `enabled` (valur predefinit `true`). It-tweġibiet `GET` iżidu ma’ kull limitu l-valuri `tokensUsed`, `remaining`, `windowStart`, `periodStartAt`, u `nextResetAt`. Dan huwa endpoint tal-klassi ta’ ġestjoni (l-awtentikazzjoni tiġi infurzata ċentralment mill-pipeline tal-awtorizzazzjoni).

## Ipproċessar tat-Talbiet

1. Il-klijent jibgħat talba lil `/v1/*`
2. Il-handler tar-rotta jsejjaħ `handleChat`, `handleEmbedding`, `handleAudioTranscription`, jew `handleImageGeneration`
3. Jiġi ddeterminat il-mudell (fornitur/mudell dirett jew alias/combo)
4. Il-kredenzjali jintgħażlu mid-DB lokali b’filtrazzjoni skont id-disponibbiltà tal-kont
5. Għaċ-chat: `handleChatCore` jiċċekkja l-cache semantika/tal-firma u jiddetermina s-settings tal-kompressjoni tal-combo
6. Il-kompressjoni proattiva titħaddem qabel it-traduzzjoni tal-fornitur meta tkun attivata (`lite`, Caveman, RTK, jew f’saffi)
7. L-eżekutur tal-fornitur jibgħat it-talba lis-servizz upstream
8. It-tweġiba tiġi tradotta lura għall-format tal-klijent (chat) jew tintbagħat kif inhi (embeddings/stampi/awdjo)
9. L-użu, l-analitika tal-kompressjoni, u r-reġistri tat-talbiet jiġu rreġistrati
10. Il-fallback jiġi applikat meta jseħħu żbalji skont ir-regoli tal-combo

Referenza sħiħa tal-arkitettura: [`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md)

## Reżiljenza (estiża)

OmniRoute jesponi tliet mekkaniżmi indipendenti għal fallimenti temporanji; l-endpoints ta’ ġestjoni hawn taħt jippermettu lill-operaturi jaqrawhom u jissostitwixxu s-settings tagħhom:

| Ambitu                   | Ħażna tal-istat                                     | Qari                                      | Irrisettjar / tneħħija                                                    |
| ------------------------ | --------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------- |
| Interruttur tal-fornitur | `domain_circuit_breakers` + fil-memorja             | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                              |
| Stennija tal-konnessjoni | `rateLimitedUntil` fuq konnessjonijiet tal-fornitur | `/api/rate-limits`, `/api/providers/[id]` | (jerġa’ jiġi attivat b’mod differit; neħħih permezz ta’ PUT tal-fornitur) |
| Imblukkar tal-mudell     | Reġistru fil-memorja tad-disponibbiltà tal-mudelli  | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                                  |

`PATCH /api/resilience` jaċċetta sostituzzjonijiet tal-interruttur tal-fornitur taħt `providerBreaker.oauth` u `providerBreaker.apikey`. Kull profil jappoġġa `degradationThreshold`, `failureThreshold`, u `resetTimeoutMs`; l-istess oqsma huma disponibbli f’Dashboard → Settings → Resilience.

```bash
# Neħħi mblukkar ta’ mudell wieħed
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Neħħi l-imblukkar kollu
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Għar-referenza kunċettwali sħiħa u l-valuri predefiniti tal-interruttur: ara [`CLAUDE.md`](../../CLAUDE.md) → "L-Istat tar-Runtime tar-Reżiljenza" u [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Kju tal-Limitu tar-Rata u Xibka ta’ Sikurezza għall-Attivazzjoni Awtomatika

- **Mogħdija ta’ kitba appoġġata**: `POST /api/rate-limits` bil-body `{"connectionId": "<id>", "enabled": true|false}` huwa l-endpoint ta’ ġestjoni appoġġat biex tattiva jew tiddiżattiva l-protezzjoni tal-limitu tar-rata għal konnessjoni. `PUT /api/providers/[id]` intenzjonalment ma jimmodifikax jew jaqleb `rateLimitProtection` (#11278).
- **Semantika ta’ `enabled: false`**: L-issettjar ta’ `enabled: false` ineħħi l-protezzjoni espliċita għall-konnessjoni, iżda **ma** jeskludix konnessjoni attiva b’API key mix-xibka ta’ sikurezza globali għall-attivazzjoni awtomatika (`autoEnableApiKeyProviders = true`). F’`reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`), `false` u `undefined` huma ekwivalenti; konnessjonijiet attivi b’API key mingħajr protezzjoni espliċita jibqgħu protetti taħt ix-xibka ta’ sikurezza għall-attivazzjoni awtomatika.
- **Diżattivazzjoni globali**: Biex tħaddem konnessjonijiet b’API key mingħajr kjuwijiet tal-limitu tar-rata, iddiżattiva x-xibka ta’ sikurezza globalment permezz ta’ `RATE_LIMIT_AUTO_ENABLE=false` (varjabbli tal-ambjent) jew `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Settings → Resilience / `PATCH /api/resilience`).

## Server A2A

OmniRoute jesponi endpoint A2A (Agent-to-Agent) JSON-RPC 2.0 flimkien ma’ wrapper REST għall-ispezzjoni/użu mid-dashboard.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # fakultattiv sakemm OMNIROUTE_API_KEY ma jkunx issettjat
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Route this coding task"}]
  }
}
```

Metodi appoġġjati (kollha kkontrollati minn `settings.a2aEnabled`):

| Metodu           | Deskrizzjoni                                                              |
| ---------------- | ------------------------------------------------------------------------- |
| `message/send`   | Eżekuzzjoni sinkronika tal-ħila; tirritorna `{task, artifacts, metadata}` |
| `message/stream` | Eżekuzzjoni SSE bi streaming tal-istess sett ta’ ħiliet                   |
| `tasks/get`      | Iġib kompitu permezz ta’ `taskId`                                         |
| `tasks/cancel`   | Jikkanċella kompitu permezz ta’ `taskId`                                  |

Ħiliet integrati: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kard tal-Aġent

```bash
GET /.well-known/agent.json
```

Jirritorna l-kard pubblika tal-aġent A2A (isem, deskrizzjoni, kapaċitajiet, katalgu tal-ħiliet, skema ta’ awtentikazzjoni) — miżmuma pubblikament fil-cache għal 1h. Ma teħtieġx awtentikazzjoni.

### Helpers REST

| Metodu | Path                         | Deskrizzjoni                                                                                                           |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | A2A attivat + statistika tal-kompiti + sommarju tal-kard tal-aġent fil-cache                                           |
| GET    | `/api/a2a/tasks`             | Jelenka l-kompiti — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Mhux implimentat bħala helper REST — oħloq permezz ta’ JSON-RPC `message/send`)                                       |
| GET    | `/api/a2a/tasks/[id]`        | Jirkupra kompitu wieħed                                                                                                |
| POST   | `/api/a2a/tasks/[id]/cancel` | Jikkanċella kompitu                                                                                                    |

**Awtentikazzjoni:** il-helpers REST jaħdmu mingħajr awtentikazzjoni ta’ ġestjoni (jistgħu jinqraw mid-dashboard); ir-route JSON-RPC `/a2a` juża Bearer `OMNIROUTE_API_KEY` jekk ikun ikkonfigurat.

## Awtentikazzjoni

Ara [Awtentikazzjoni tal-Ġestjoni](../guides/MANAGEMENT-AUTH.md) għall-erba’
familji ta’ kredenzjali (sessjoni tad-dashboard, token lokali tas-CLI, Token
ta’ Aċċess `oma_live_…`, ċavetta API b’ambitu ta’ ġestjoni) u kif dawn huma differenti miċ-ċwievet tal-inferenza.

- Ir-rotot tad-dashboard (`/dashboard/*`) jużaw il-cookie `auth_token`
- Il-login juża l-hash tal-password issejvjata; bħala alternattiva juża `INITIAL_PASSWORD`
- `requireLogin` jista’ jiġi attivat jew diżattivat permezz ta’ `/api/settings/require-login`
- Ir-rotot `/v1/*` jistgħu jeħtieġu b’mod fakultattiv ċavetta API Bearer meta `REQUIRE_API_KEY=true`
- "token tal-ġestjoni" / "ċavetta API b’ambitu ta’ ġestjoni" f’din ir-referenza tfisser waħda mill-familji f’dik il-gwida — mhux tip ta’ sigriet addizzjonali mhux definit

> **Bidla inkompatibbli (v3.8.0)** — `/api/v1/agents/tasks/*` u l-endpoints tal-ġestjoni tal-perjodu ta’ stennija issa jeħtieġu **awtentikazzjoni tal-ġestjoni** (cookie `auth_token` tad-dashboard jew ċavetta API b’ambitu ta’ ġestjoni). Il-klijenti li qabel kienu jsejħu dawn ir-rotot mingħajr awtentikazzjoni se jirċievu `401 Unauthorized`. Ara l-commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
