## Dovršeci razgovora

```bash
POST /v1/chat/completions
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "cc/claude-opus-4-6",
  "messages": [
    {"role": "user", "content": "Write a function to..."}
  ],
  "stream": true
}
```

### Prilagođena zaglavlja

| Zaglavlje                | Smjer   | Opis                                                                                                                                                                                                                                  |
| ------------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `X-OmniRoute-No-Cache`   | Zahtjev | Postavite na `true` kako biste zaobišli predmemoriju                                                                                                                                                                                  |
| `x-omniroute-no-memory`  | Zahtjev | Postavite na `true` kako biste za ovaj zahtjev preskočili umetanje memorije i vještina (ponaša se kao opcija bez predmemorije; izbjegava trošak tokena i novčani trošak po pozivu)                                                    |
| `X-OmniRoute-Progress`   | Zahtjev | Postavite na `true` za događaje napretka                                                                                                                                                                                              |
| `X-Session-Id`           | Zahtjev | Ključ trajne sesije za afinitet vanjske sesije                                                                                                                                                                                        |
| `x_session_id`           | Zahtjev | Prihvaća se i inačica s podvlakom (izravni HTTP)                                                                                                                                                                                      |
| `X-OmniRoute-Session-Id` | Zahtjev | Oznaka sesije/razgovora koju zadaje pozivatelj (također se prosljeđuje memoriji). Kada je prisutna, doslovno se pohranjuje u `call_logs.session_tag` radi pripisivanja troškova po sesiji (#8249) — nikada se ne stvara ako nedostaje |
| `Idempotency-Key`        | Zahtjev | Ključ za uklanjanje duplikata (vremenski okvir od 5 s)                                                                                                                                                                                |
| `X-Request-Id`           | Zahtjev | Alternativni ključ za uklanjanje duplikata                                                                                                                                                                                            |
| `x-omniroute-connection` | Zahtjev | Prikvačite zahtjev za jedan model na jednu vezu pružatelja (račun) prema njezinu ID-u — pogledajte [Prikvačivanje računa po zahtjevu](#account-pinning-per-request)                                                                   |
| `X-OmniRoute-Cache`      | Odgovor | `HIT` ili `MISS` (bez strujanja)                                                                                                                                                                                                      |
| `X-OmniRoute-Idempotent` | Odgovor | `true` ako je duplikat uklonjen                                                                                                                                                                                                       |
| `X-OmniRoute-Progress`   | Odgovor | `enabled` ako je praćenje napretka uključeno                                                                                                                                                                                          |
| `X-OmniRoute-Session-Id` | Odgovor | Efektivni ID sesije koji upotrebljava OmniRoute                                                                                                                                                                                       |
| `X-OmniRoute-Request-Id` | Odgovor | Korelacijski ID zahtjeva (kada je poznat)                                                                                                                                                                                             |
| `X-OmniRoute-Version`    | Odgovor | Verzija međuverzije OmniRoutea (uvijek prisutna)                                                                                                                                                                                      |
| `X-OmniRoute-Cost-Saved` | Odgovor | Iznos u USD-u koji je predmemorija uštedjela pri rezultatu HIT (samo za pogotke u predmemoriji)                                                                                                                                       |
| `X-OmniRoute-Decision`   | Odgovor | Trag usmjeravanja: `strategy=<name>; provider=<alias>; latency_ms=<n>` (`<name>` je strategija kombinacije ili `single` za zahtjev bez kombinacije) — uvijek je prisutan u završnim odgovorima                                        |

#### Vezivanje računa po zahtjevu

Kada pružatelj ima nekoliko veza (računa ili ključeva), OmniRoute obično odabire jednu
putem svoje strategije odabira računa. Umjesto toga, zahtjev može vezati određenu vezu
pomoću zaglavlja `x-omniroute-connection`:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <your OmniRoute API key>" \
  -H "Content-Type: application/json" \
  -H "x-omniroute-connection: <connection id>" \
  -d '{"model": "codex/gpt-5.5", "messages": [{"role": "user", "content": "hi"}]}'
```

- **Gdje pronaći ID.** Otvorite stranicu pružatelja na nadzornoj ploči
  (**Nadzorna ploča → Pružatelji → <pružatelj>**) i kliknite oznaku ID-ja `xxxxxxxx…` u retku
  veze — time se kopira puni ID veze.
- **Koji ga zahtjevi poštuju.** Zahtjevi s jednim modelom (`provider/model`) na
  `/v1/chat/completions`, `/v1/messages` i `/v1/responses`. Kombinacije zanemaruju zaglavlje:
  umjesto toga vežite račun za svaki korak kombinacije putem vlastite veze tog koraka.
- **Vezivanje je strogo, nije samo preferencija.** Isključivo se koristi vezana veza. Neuspjeh
  unutar zahtjeva bilježi razdoblje mirovanja računa, ali se **ne** prebacuje na drugi
  račun istog pružatelja.
- **Razdoblje mirovanja i kvota oslobađaju vezivanje.** Dok je vezana veza u razdoblju mirovanja,
  dok joj je kvota iscrpljena ili je blokirana pravilom kvote, kasniji zahtjevi prebacuju se na
  druge veze pružatelja, baš kao i nevezani promet.
- **Nepoznati ili onemogućeni ID-jevi uzrokuju neuspjeh.** ID koji nije u aktivnom skupu pružatelja
  (izbrisan je, deaktiviran ili pripada drugom pružatelju) ne ostavlja nijedan prihvatljiv račun,
  pa zahtjev ne uspijeva umjesto da se neprimjetno usmjeri drugamo.

Claude Code šalje prilagođena zaglavlja putem `ANTHROPIC_CUSTOM_HEADERS`. Dodajte ga u blok `env`
datoteke `~/.claude/settings.json` ili u projektnu datoteku `.claude/settings.json` kako biste za
svaki projekt vezali drugi račun:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "ANTHROPIC_CUSTOM_HEADERS": "x-omniroute-connection: <connection id>",
  },
}
```

Izvor: `src/sse/handlers/chat.ts` (čitanje zaglavlja), `src/sse/services/auth.ts` i
`src/sse/services/sessionAffinityPin.ts` (oslobađanje vezivanja i provjera nedostaje li veza u skupu).

> **Zaglavlja telemetrije troškova:** uspješni odgovori bez strujanja također sadrže skup za telemetriju troškova `X-OmniRoute-*` — `X-OmniRoute-Response-Cost` (USD, fiksno 10 decimalnih mjesta; `0.0000000000` za besplatne stavke ili stavke bez utvrđene cijene), `X-OmniRoute-Tokens-In` / `X-OmniRoute-Tokens-Out`, `X-OmniRoute-Model`, `X-OmniRoute-Provider`, `X-OmniRoute-Latency-Ms`, `X-OmniRoute-Cache-Hit` i `X-OmniRoute-Fallback-Attempts` (samo kada je > 0), kao i `X-OmniRoute-Request-Id` i `X-OmniRoute-Version`. Njih emitiraju dovršavanja razgovora, `/v1/responses`, `/v1/messages`, **kao i krajnje točke za medije** — `/v1/embeddings`, `/v1/images/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/rerank`, `/v1/videos/generations`, `/v1/music/generations` i `/v1/moderations` (trošak je uvijek `0`). Trošak medija izračunava se po modalitetu (po slici, sekundi, znaku ili jedinici pretraživanja) kada su cijene dostupne, a inače iznosi `0` (nastavlja se rad u slučaju pogreške).

> **Semantika troška pogotka u predmemoriji:** pri POGOTKU semantičke predmemorije (`X-OmniRoute-Cache-Hit: true`) ne upućuje se poziv nadređenoj usluzi, stoga je `X-OmniRoute-Response-Cost` jednak `0.0000000000` (**inkrementalni** trošak posluživanja pogotka). Izvorni trošak, odnosno trošak koji bi inače nastao, zasebno se navodi u `X-OmniRoute-Cost-Saved`. Sustavi za obračun trebaju zbrajati `X-OmniRoute-Response-Cost` (pogoci ne koštaju ništa), dok analitika predmemorije može objedinjavati `X-OmniRoute-Cost-Saved`.

## Isključivi zakupi upravljanih sesija

Isključivi zakup upravljane sesije izborni je ugovor usmjeravanja neovisan o klijentu: jedan aktivni vlasnik
drži jednu prihvatljivu OmniRoute vezu. Ne zakupljuje model, ne zahtijeva OAuth, ne identificira
određenog klijenta niti zahtijeva određenog pružatelja usluga.

API ključ koji se upotrebljava za autentifikaciju mora imati opseg `lease:exclusive` i izričit popis
`allowedConnections` koji nije prazan. Granica mutacije baze podataka zahtijeva oba polja zajedno pri
izradi ključa i djelomičnim ažuriranjima.

```http
POST /api/v1/session-leases
Authorization: Bearer <managed-api-key>
Content-Type: application/json
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>

{"action":"acquire","model":"glm/glm-4.6"}
```

Uspješni odgovori za stjecanje, obnovu i oslobađanje izlažu vremenske oznake, `state` i točnu pozitivnu
vrijednost `generation`, ali nikada odabranu vezu ni vjerodajnice. Za obnovu i oslobađanje generacija
se navodi u JSON tijelu:

```json
{ "action": "renew", "generation": 1 }
```

```json
{ "action": "release", "generation": 1, "reason": "OWNER_EXIT" }
```

Aktivni vlasnik zakupa može izričito zatražiti metapodatke za prikaz koji štite privatnost za svoje trenutačno povezivanje:

```json
{ "action": "status", "generation": 1 }
```

```json
{
  "state": "ACTIVE",
  "generation": 1,
  "acquiredAt": "2026-08-28T12:00:00.000Z",
  "renewedAt": "2026-08-28T12:00:30.000Z",
  "expiresAt": "2026-08-28T12:02:30.000Z",
  "connection": {
    "displayName": "Primary Codex",
    "provider": "codex"
  }
}
```

Ova izborna radnja statusa zaštićena je neprozirnim vlasnikom, autentificiranim upravljanim API ključem i točnom
aktivnom generacijom unutar jedne transakcije baze podataka. `displayName` je samo obrezani konfigurirani
naziv veze; ima vrijednost `null` kada ne postoji siguran konfigurirani naziv. OmniRoute nikada ne zamjenjuje taj naziv
adresom e-pošte ili generiranim identitetom računa. Vrijednost pružatelja usluga neosjetljiva je oznaka za prikaz i nikada
nije generirani identifikator kompatibilnog pružatelja usluga. Vjerodajnice, tokeni, kolačići, neobrađeni identifikatori veze ili API
ključa, sažeci vlasnika, tajne za ograđivanje i interni podaci usmjeravanja isključeni su.

Pretraživanja s pogrešnim ključem, pogrešnim vlasnikom, zastarjelom generacijom te nedostajućim, isteklim, oslobođenim ili poništenim zakupom
vraćaju istu pogrešku `409 LEASE_FENCE_STALE` bez metapodataka o vezi. Klijent koji je primio odgovor o čekanju kapaciteta nema aktivno povezivanje koje bi mogao pregledati. Kada usmjeravanje prebaci aktivni zakup,
ista generacija ostaje valjana, a status atomski vraća novo povezivanje, nikada staro.
Postojeći klijenti ostaju nepromijenjeni jer odgovori za stjecanje, obnovu, oslobađanje i čekanje zadržavaju
svoje prethodne oblike.

Ovaj ugovor poslužitelja ne mijenja standardni OpenAI Codex `/status`. Standardni Codex trenutačno prijavljuje svojeg
pružatelja modela i ugrađeno stanje autentifikacije/računa, ali ne prikazuje proizvoljne prilagođene
metapodatke računa pružatelja usluga; buduća integracija klijenta mora pozvati ovu radnju i odlučiti kako
prikazati `connection.displayName`.

Svaki upravljani zahtjev za zaključivanje zatim navodi oba kontrolna zaglavlja:

```http
X-OmniRoute-Lease-Owner: vlo_<43-base64url-characters>
X-OmniRoute-Lease-Generation: 1
```

Točni vlasnik, generacija, aktivna veza i autentificirani API ključ ograđuju se neposredno
prije svakog podržanog pokušaja prema uzvodnom sustavu. Ponovna reprodukcija vlasnika i generacije s drugim ključem ne uspijeva čak ni
kada taj ključ dopušta istu vezu. Neobrađeni vlasnici ne pohranjuju se trajno, ne zapisuju se u zapisnike, ne zadržavaju se u
snimci zahtjeva niti se prosljeđuju uzvodnom sustavu.

Privremeno nadmetanje vraća HTTP `429` sa zaglavljem `Retry-After` i:

```json
{
  "state": "WAITING_FOR_CAPACITY",
  "error": { "type": "lease_error", "code": "LEASE_CAPACITY_UNAVAILABLE" },
  "reason": "NO_FREE_ELIGIBLE_CONNECTION",
  "retryAfter": 30
}
```

Ovaj odgovor znači samo da običan skup prihvatljivih veza nije bio prazan i da je svaki slobodan kandidat bio
zauzet stranim aktivnim zakupom. Nepodržani modeli/pružatelji usluga, nepodudaranje pravila, razdoblje čekanja, kvota,
stanje sustava i drugi uobičajeni neuspjesi prihvatljivosti zadržavaju svoje postojeće OmniRoute odgovore.

### `x-omniroute-compression`

Nadjačavanje plana kompresije za pojedinačni zahtjev. Ima najviši prioritet — nadjačava nadjačavanje kombinacije usmjeravanja,
aktivni profil, automatski okidač i zadanu postavku ploče. Vrijednosti:

| Vrijednost    | Učinak                                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `off`         | Bez kompresije za ovaj zahtjev.                                                                                                       |
| `default`     | Zadani profil izveden iz ploče (zanemaruje aktivni profil). Motori s gubicima ostaju isključeni.                                      |
| `safe`        | Samo deduplikacija i sažimanje razmaka.                                                                                               |
| `allow-lossy` | Zadržava plan operatera za ovaj zahtjev, uključujući sažetke i preoblikovanja stila.                                                  |
| `engine:<id>` | Jedan motor kada je omogućen, npr. `engine:rtk`. Izbor tog motora za pojedinačni zahtjev.                                             |
| `<combo>`     | Imenovana kombinacija, koja se najprije podudara prema nazivu (bez razlikovanja velikih i malih slova), a zatim prema identifikatoru. |

Napomene:

- Nepoznate se vrijednosti zanemaruju (zahtjev se nikada ne odbija); razrješavanje se nastavlja prema uobičajenom redoslijedu prioriteta operatera.
- Ako više kombinacija ima isti naziv, proslijedite **id** kombinacije radi determinističkog podudaranja.
- Kombinacija čiji je naziv `off` ili `default` ne može se odabrati prema nazivu (te se ključne riječi prve tumače); takvu kombinaciju referencirajte njezinim identifikatorom.
- Glavni prekidač kompresije čvrsto je ograničenje: kada je kompresija globalno onemogućena, ovo je zaglavlje ne može omogućiti.

Primijenjeni plan vraća se u zaglavlju odgovora:

```
X-OmniRoute-Compression: <mode>; source=<source>
```

gdje je `<source>` jedna od vrijednosti `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` ili `off`.

## Ugradnje

```bash
POST /v1/embeddings
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "nebius/Qwen/Qwen3-Embedding-8B",
  "input": "The food was delicious"
}
```

Dostupni pružatelji usluga: Nebius, OpenAI, Mistral, Together AI, Fireworks, NVIDIA, **OpenRouter**, Jina AI.

Identifikatori kataloga imaju oblik `provider/model` (primjer: `jina-ai/jina-embeddings-v5-omni-small`). Samostalni identifikatori Jina modela koji se pojavljuju u registru (primjerice `jina-embeddings-v5-text-small`, `jina-reranker-v3.5`) također se razrješavaju. Jina operacije ugrađivanja, ponovnog rangiranja, klasifikacije i segmentacije najprije upotrebljavaju vjerodajnice `jina-ai` s nadzorne ploče; `JINA_AI_API_KEY` služi kao pričuvna opcija samo kada ključ s nadzorne ploče ne postoji. Kartica `jina-reader` namijenjena je isključivo Readeru / `r.jina.ai` (`POST /v1/web/fetch`) i nikada ne pruža ugrađivanje ni ponovno rangiranje.

Modeli u registru koji navode podršku za više modaliteta prihvaćaju i do 32 strukturirane
stavke neovisne o pružatelju usluga. Vrste medijskih stavki su `text`, `image`, `audio`, `video` i `document`. Njihov medijski `source`
može biti `{"type":"url","url":"https://..."}` ili
`{"type":"base64","data":"...","media_type":"..."}`.

Jina v5 Omni (`jina-ai/jina-embeddings-v5-omni-small`, `jina-ai/jina-embeddings-v5-omni-nano`
i pseudonim obitelji `jina-ai/jina-embeddings-v5-omni` → omni-small) također prihvaća Jina izvorne
EmbeddingsV5Request dokumente i **prosljeđuje ih neizmijenjene** na `https://api.jina.ai/v1/embeddings`:

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "task": "retrieval.query",
  "normalized": true,
  "input": [
    { "text": "a red bicycle" },
    { "image": "https://example.com/bike.png" },
    { "content": [{ "text": "caption" }, { "image": "data:image/png;base64,..." }] }
  ]
}
```

Izvorne vrijednosti `{ image | audio | video | pdf }` mogu biti javni HTTPS URL, `data:` URI ili sirovi
base64. OmniRoute ne pretvara te objekte u nizove niti dohvaća izvorne URL-ove slika — Jina sama dohvaća
javno dostupne medije. Dodatna Jina polja (`task`, `normalized`, `truncate`, `embedding_type`) se
prosljeđuju. Jina SKU-ovi namijenjeni samo tekstu i dalje odbijaju dokumente koji nisu tekstualni.

Sigurnosna i prijenosna ograničenja:

- Udaljeni URL-ovi medija moraju biti javni HTTPS URL-ovi. Kanonske stavke `{type,source:url}` dohvaćaju se
  na strani poslužitelja (ponovna provjera preusmjeravanja, vremensko ograničenje, ograničenja veličine, javni DNS, vezivanje veze) i
  umeću prije poziva pružatelju usluga. Jina izvorne stavke `{image:"https://..."}` prosljeđuju se neizmijenjene
  nakon iste provjere javnog HTTPS-a; Jina dohvaća URL.
- Ugrađeni base64 mediji ograničeni su na 8 MiB dekodiranih podataka po stavci i 16 MiB dekodiranih podataka u cijelom zahtjevu.

Prevođenje za pružatelje usluga (kanonske stavke nikada se ne prosljeđuju neizmijenjene):

- Jina multimodalni modeli: svaka stavka najviše razine postaje jedan objekt s ključem modaliteta
  (`text` / `image` / `audio` / `video` / `pdf`) koji za ugrađene medije upotrebljava podatkovne URI-je; jedan vektor po
  stavci najviše razine.
- Obitelj Gemini Embedding 2: jedan niz najviše razine postaje jedan izvorni
  `models/{model}:embedContent` zahtjev s `content.parts` (`text` ili `inline_data`).
- llama.cpp (`llama-cpp/<model>`, bilo koji model učitan na lokalnom poslužitelju): kanonske `text` stavke
  postaju obični nizovi, a `image` / `audio` / `video` postaju po jedan
  `{"content": [part]}` objekt, uz uporabu dijelova sadržaja razgovora llama-servera (`image_url`,
  `input_audio` s formatom `wav` / `mp3` / `flac`, `input_video`) s ugrađenim podacima; jedan vektor
  po stavci najviše razine. Poslužitelj mora biti pokrenut s `--embedding --mmproj …`; bez projektora
  sam odbija medije. `document` nije podržan.
- Nepoznati/dinamički modeli bez izričitih metapodataka o modalitetima odbijaju strukturirani unos uz HTTP 400.

```json
{
  "model": "jina-ai/jina-embeddings-v5-omni-small",
  "input": [
    { "type": "text", "text": "A red bicycle" },
    {
      "type": "image",
      "source": { "type": "url", "url": "https://example.com/bicycle.png" }
    }
  ],
  "dimensions": 512,
  "encoding_format": "float"
}
```

Nepodržane kombinacije modela i modaliteta vraćaju HTTP 400 umjesto prisilne pretvorbe stavke. Polja proširenja koja nisu ulazna
u naslijeđenim zahtjevima s nizovima/tokenima i dalje se prosljeđuju neizmijenjena.

```bash
# Prikaži sve modele za ugrađivanje
GET /v1/embeddings
```

## Generiranje slika

```bash
POST /v1/images/generations
Authorization: Bearer your-api-key
Content-Type: application/json

{
  "model": "openai/gpt-image-2",
  "prompt": "A beautiful sunset over mountains",
  "size": "1024x1024"
}
```

Dostupni pružatelji uključuju OpenAI (GPT Image 2), xAI (Grok Image), Together AI (FLUX), Fireworks AI, Nebius (FLUX), Hyperbolic, NanoBanana, **OpenRouter**, **ZenMux**, SD WebUI (lokalno), ComfyUI (lokalno).

`n` vraća `n` slika u `data[]`. Za pružatelje čiji nadređeni API vraća jednu sliku po pozivu
(Black Forest Labs, Stability AI, Leonardo, Ideogram, Haiper, Hyperbolic, Magnific/Freepik,
NVIDIA NIM, Cloudflare Workers AI) izvršava se `n` zasebnih nadređenih poziva, uz najviše 4 istodobna poziva. Fiksni
`seed` uvećava se za indeks poziva (`seed`, `seed + 1`, …), pa se slike razlikuju, ali ostaju
ponovljive. `n` je ograničen na 10. Zahtjev u cijelosti ne uspijeva ako bilo koji poziv ne uspije. Popis

`open-sse/handlers/imageGeneration/fanOut.ts`.

ZenMux ponovno koristi postojeću vezu s API ključem i prihvaća prefikse `zenmux/` ili `zm/`:

- `zenmux/openai/gpt-image-2` koristi ZenMuxov OpenAI Images API. Opcije uključuju `size`,
  `quality`, `n`, `output_format`, `output_compression`, `background` i `response_format`.
- Drugi izdavači, kao što je `zm/meta/muse-image-1.0`, koriste ZenMuxovu Vertex AI krajnju točku `:predict`.
  `n` se preslikava na `sampleCount`, `aspect_ratio` na `aspectRatio`, a `image_size`
  (`1K`, `2K`, `4K`) na `sampleImageSize`. Vrijednost `size` u pikselima određuje samo omjer stranica,
  a ne zajamčene dimenzije u pikselima. Podržani omjeri, razlučivosti i brojevi razlikuju se ovisno o modelu.
- `zm/inclusionai/ming-image-0.1-design` sam odabire svoje dimenzije. Izostavite `size`,
  `aspect_ratio` i `image_size`; izričite vrijednosti vraćaju HTTP 400. PNG, JPEG i WebP
  mogu se zatražiti pomoću `output_format`.

Ova integracija podržava generiranje slika iz teksta, ali ne i uređivanje referentnih slika. Vertexov
izlaz normalizira se u `data[].b64_json`; `response_format: "url"` vraća nadređeni
HTTPS URL ili podatkovni URL u formatu base64 kada su dostupni samo bajtovi slike. Prazni/filtrirani izlazi
vraćaju pogrešku umjesto praznog uspješnog odgovora. Pristup modelima ovisi o ZenMux računu.
Pogledajte [ZenMuxov Vertex API](https://docs.zenmux.ai/api/vertexai/generate-images) i
[OpenAI Images API](https://docs.zenmux.ai/api/openai/generate-an-image).

`model` odabire pružatelja OCR-a putem prefiksa `provider/model`; samostalni ID modela (npr.

| ID pružatelja                 | ID modela            | Vrijednost `model`                                           | Napomene                                                                                                                                      |
| ----------------------------- | -------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `mistral`                     | `mistral-ocr-latest` | `mistral/mistral-ocr-latest` (ili samo `mistral-ocr-latest`) | Sinkrono — odgovor se vraća izravno iz jednog nadređenog poziva.                                                                              |
| `azure-document-intelligence` | `prebuilt-read`      | `azure-document-intelligence/prebuilt-read`                  | Asinkroni nadređeni sustav (`analyze` + provjera statusa) — pogledajte u nastavku.                                                            |
| `vertex-deepseek-ocr`         | `deepseek-ocr-maas`  | `vertex-deepseek-ocr/deepseek-ocr-maas`                      | Sinkrono, putem partnerske krajnje točke Vertex AI-ja `openapi/chat/completions` — u nastavku pogledajte pojedinosti o autentifikaciji/URL-u. |

Sva tri pružatelja odgovaraju tijelom istog oblika kao Mistral:

```json
{
  "pages": [{ "index": 0, "markdown": "# Extracted text..." }],
  "model": "mistral-ocr-latest",
  "usage_info": { "pages_processed": 1 }
}
```

### Tijek provjere statusa za Azure Document Intelligence

API `analyze` usluge Azure Document Intelligence asinkron je: početni zahtjev vraća
zaglavlje `Operation-Location` umjesto tijela, a rezultat se mora dohvatiti periodičnom provjerom statusa. Rukovatelj
(`open-sse/handlers/ocr.ts`) provjerava taj URL svake sekunde, najviše 30 puta, odmah prijavljuje neuspjeh (ne
nastavlja provjeravati) ako odgovor provjere nema status `ok` ili ima status `"failed"` te vraća `504` ako se
operacija i dalje izvodi nakon što se iscrpi dopušteni broj pokušaja. Konačni Azureov odgovor
normalizira se u isti oblik `pages`/`markdown` koji koristi Mistral prije vraćanja
pozivatelju, pa klijentski kod ne mora zasebno obrađivati pojedinog pružatelja.

### Autentifikacija i razrješavanje krajnje točke za Vertex AI DeepSeek OCR

`vertex-deepseek-ocr` ponovno koristi istu autentifikaciju za Vertex AI koju OmniRoute već podržava za
promet razgovora/slika (`open-sse/executors/vertex.ts`): API ključ veze može biti
vjerodajnica Service Accounta u JSON formatu (koja se razmjenjuje za kratkotrajni OAuth pristupni token putem
tijeka JWT bearer) ili već izdani OAuth pristupni token koji se koristi bez izmjena. URL nadređene krajnje točke
Vertexova je generička partnerska krajnja točka `openapi/chat/completions`, izrađena iz projekta i
regije veze — izričite vrijednosti `providerSpecificData.project`/`providerSpecificData.region` uvijek imaju prednost;
u suprotnom se projekt izvodi iz vrijednosti `project_id` u JSON-u Service Accounta, a zadana je regija
`us-central1`. Oba se razrješavanja odvijaju u `open-sse/handlers/ocr.ts`
(`resolveVertexOcrAccessToken`, `resolveVertexOcrBaseUrl`), a koristi ih
`src/app/api/v1/ocr/route.ts` prije prosljeđivanja u `handleOcr`.

### Prefiksi ID-a modela (`?prefix=`)

Većina modela navedena je pod **prefiksom pružatelja usluge**. Koji ćete prefiks dobiti određuje
zastavica značajke `MODELS_CATALOG_PREFIX_MODE`, a može se nadjačati **za svaki zahtjev** pomoću
parametra upita — korisno za klijenta koji želi čist popis bez promjene postavke na razini
poslužitelja za sve ostale:

```bash
GET /v1/models?prefix=alias        # jedan ID po modelu — kratki prefiks aliasa
GET /v1/models?prefix=dual         # oba oblika (zadana postavka poslužitelja)
GET /v1/models?prefix=canonical    # samo puni prefiks ID-a pružatelja usluge
```

| Način       | Emitira                                                 | Napomene                                                                                                                                                                                           |
| ----------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dual`      | `cc/claude-sonnet-4-6` **i** `claude/claude-sonnet-4-6` | **Zadano.** Oba ID-a usmjeravaju na isti model; zadržana su kako bi konfiguracije klijenata u kojima je jedan od oblika izravno zadan nastavile raditi. Približno udvostručuje katalog.            |
| `alias`     | `cc/claude-sonnet-4-6`                                  | Jedan unos po modelu. Pružatelji usluga bez zasebnog aliasa i dalje emitiraju svoj unos, tako da se ništa ne gubi.                                                                                 |
| `canonical` | `claude/claude-sonnet-4-6`                              | Jedan unos po modelu pod punim prefiksom ID-a pružatelja usluge. Pružatelji usluga bez zasebnog aliasa (npr. `antigravity/…`, `agy/…`) i ovdje emitiraju svoj jedini ID, tako da se ništa ne gubi. |

Zrcalni unos u načinu `dual` može se prepoznati i bez parametra upita: sadrži polje `parent`
koje upućuje na primarni ID.

Klijenti koji prikazuju birač modela trebali bi zatražiti `?prefix=alias` — to čini
[proširenje OmniCopilot za VS Code](../guides/VSCODE-COPILOT.md).

### Filtri za otkrivanje (`?capability=`, `?min_context=`, `?kind=`, `?q=`)

`GET /v1/models` prihvaća neobavezne filtre za otkrivanje. Bez njih odgovor ostaje
nepromijenjen. Oni sužavaju katalog koji pozivatelj već vidi (najprije se primjenjuju dopuštenja
API ključa), a izvršavaju se prije straničenja u stilu OpenAI-ja pomoću `limit` / `after`:

```bash
GET /v1/models?capability=vision&capability=tool_calling   # svaka navedena sposobnost mora biti omogućena
GET /v1/models?capability=vision,reasoning&min_context=200000
GET /v1/models?kind=embedding                              # `type` kataloga; redci bez njega imaju vrstu `chat`
GET /v1/models?q=sonnet&limit=10                           # podudaranje ID-a ili naziva bez razlikovanja velikih i malih slova
```

| Parametar     | Vrijednosti                                                                                         |
| ------------- | --------------------------------------------------------------------------------------------------- |
| `capability`  | `attachment`, `reasoning`, `structured_output`, `temperature`, `thinking`, `tool_calling`, `vision` |
| `min_context` | cijeli broj koji nije negativan, uspoređuje se s `context_length`                                   |
| `kind`        | `chat`, `audio`, `embedding`, `image`, `moderation`, `music`, `rerank`, `video`                     |
| `q`           | 1–200 znakova                                                                                       |

Nepoznata vrijednost ili `min_context` koji nije cijeli broj koji nije negativan (na primjer `1.5`)
vraća HTTP `400`, a poruka navodi valjane vrijednosti. Implementacija:
`src/app/api/v1/models/catalogFilters.ts`.

### Uži izbor modela (`POST /v1/models/query`)

`POST /v1/models/query` vraća kratak, deterministički popis iz istog kataloga, uz istu
autorizaciju i vidljivost po ključu kao `GET /v1/models`:

```bash
POST /v1/models/query
Authorization: Bearer your-api-key
Content-Type: application/json

{ "capabilities": ["vision", "tool_calling"], "min_context": 128000, "max_output": 16000,
  "kind": "chat", "q": "gpt", "owned_by": "openai", "exclude": ["openai/gpt-4o"], "limit": 5 }

→ { "object": "list", "data": [ ...models ] }
```

Svako je polje neobavezno. `capabilities` i `exclude` prihvaćaju polje ili niz odvojen zarezima;
`max_output` uspoređuje se s `max_output_tokens`. Rezultati se sortiraju prema `owned_by`, a zatim
prema `id`. Zadana vrijednost za `limit` jest `20`, a vrijednosti veće od `100` ograničavaju se
na `100`. Nevaljan JSON, nepoznato polje ili nevaljana vrijednost vraća HTTP `400`.

### Pojedinačno skriveni modeli za razgovor

Model označen kao **Skriven** na stranici svojeg pružatelja usluge izuzima se iz kataloga i odbija
uz HTTP `404` / `model_not_found` kada se izričito zatraži. Provjera koristi razriješenog
pružatelja usluge i model, uključujući aliase pružatelja usluga, prefikse čvorova kompatibilnih
pružatelja usluga i zadane postavke veze. Kombinacija preskače skrivene ciljeve i može upotrijebiti
vidljivi srodni model; kada ne preostane nijedan izvršiv cilj, vraća isti kôd pogreške. Otkrivanje
modela stupa na snagu pri sljedećem zahtjevu. Nadjačavanja vidljivosti samo za slike ne skrivaju
model za razgovor s istim ID-om.

Ova postavka pojedinačnog modela odvojena je od
[popisa dopuštenih/zabranjenih izlaganja modela](../routing/MODEL_EXPOSURE_LIST.md), koji filtriraju
oglašavanje u katalogu i kandidate za automatsko usmjeravanje, uz zadržavanje izričitog slanja.
Dopuštenja modela za API ključeve i dalje se primjenjuju neovisno. Zadani način prefiksa kataloga
ostaje `dual`.

### Varijante modela bez razmišljanja

Za Claude modele koji podržavaju razmišljanje `/v1/models` također navodi varijantu **bez razmišljanja** čiji ID ima prefiks `claude-3-omniroute-no-thinking/`:

```
claude-3-omniroute-no-thinking/<provider>/<model>
```

Odabirom ovog ID-a (npr. u konfiguraciji alata Claude Code koja uvijek prilaže blok `thinking`) ponovno se dobiva stvarni `<provider>/<model>` s potisnutim zaključivanjem — `thinking:{type:"disabled"}` na putanji `/v1/messages` ili izostavljanjem polja `reasoning`/`reasoning_effort` na putanji `/v1/chat/completions`. Varijanta se navodi samo za modele iz obitelji Claude koji podržavaju razmišljanje **i** prihvaćaju `disabled` (stoga su, primjerice, isključeni modeli koji podržavaju samo prilagodljivo razmišljanje i odbijaju `disabled`). Operateri mogu prisilno uključiti ili isključiti varijantu za pojedini model putem `ModelSpec.noThinkingAlias`.

## Generiranje zvuka putem ElevenLabsa

Konfigurirajte vezu s pružateljem `elevenlabs` u OmniRouteu pomoću svojeg ElevenLabs API ključa.
Klijenti se autentificiraju svojim ključem za **OmniRoute** (`Authorization: Bearer $OMNIROUTE_API_KEY`);
pristupnik prosljeđuje pohranjeni ključ pružatelja kao `xi-api-key`. Nikada nemojte slati ElevenLabs ključ
kao nositeljski token pristupnika.

| Metoda | Putanja                     | Odgovor                                     | Kategorija krajnje točke API ključa |
| ------ | --------------------------- | ------------------------------------------- | ----------------------------------- |
| POST   | `/v1/sound-generation`      | Izvorni zvučni bajtovi                      | `elevenlabs`                        |
| POST   | `/v1/music`                 | Izvorni zvučni bajtovi                      | `music`                             |
| POST   | `/v1/music/stream`          | Strujani zvučni bajtovi                     | `music`                             |
| POST   | `/v1/music/detailed`        | Izvorni višedijelni zvuk i plan kompozicije | `music`                             |
| POST   | `/v1/music/detailed/stream` | Izvorni SSE metapodaci i dijelovi zvuka     | `music`                             |
| POST   | `/v1/music/plan`            | JSON plan kompozicije                       | `music`                             |

Ove krajnje točke nadopunjuju postojeće rute `/v1/audio/speech`, `/v1/audio/transcriptions`,
`/v1/voices`, `/v1/text-to-speech/{voiceId}` i `/v1/speech-to-text`. Izvorna JSON polja
i parametri upita kao što su `output_format` i `enable_logging` ostaju nepromijenjeni.
Odgovori krajnje točke `/v1/music/detailed` zadržavaju svoje višedijelne granice; obradite ih kao višedijelne.
`/v1/music/detailed/stream` vraća `text/event-stream` s metapodacima kompozicije i
dijelovima zvuka kodiranima u base64 unutar SSE događaja. Svih šest ruta podržava CORS predprovjeru.

```bash
export OMNIROUTE_BASE_URL="http://localhost:20128"
export OMNIROUTE_API_KEY="your-omniroute-api-key"

# Kratki zvučni efekt. Trajanje: od 0,5 do 30 sekundi.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/sound-generation?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"A single soft bell chime","duration_seconds":1,"model_id":"eleven_text_to_sound_v2"}' \
  --output effect.mp3

# Trajanje glazbe izražava se u milisekundama: od 3000 do 600000.
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music?output_format=mp3_44100_128" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Gentle instrumental piano","music_length_ms":10000,"force_instrumental":true,"model_id":"music_v1"}' \
  --output music.mp3
```

Upotrijebite `/v1/music/stream` s istim JSON tijelom za postupnu isporuku zvuka. Kompozicija
prihvaća točno jedno od `prompt` ili `composition_plan`; `/v1/music/plan` zahtijeva `prompt`
i po želji prihvaća `source_composition_plan`. Izvorne sheme zadržavaju dodatna polja
pružatelja kako bi verzije planova kompozicije i opcije finog podešavanja stigle do ElevenLabsa.

Objedinjena krajnja točka `/v1/music/generations` također prihvaća `elevenlabs/music_v1`,
`elevenlabs/music_v2` i `elevenlabs/music_v2_5`. Uz aktivnu vezu s ElevenLabsom
ti su modeli dostupni u katalogu glazbe. Ova krajnja točka vraća
`{"created":...,"data":[{"b64_json":"...","format":"mp3"}]}`. Njezino polje `duration` izraženo je u
sekundama i preslikava se na `music_length_ms`; izričito navedeni `music_length_ms` ima prednost.
`instrumental` se preslikava na `force_instrumental`, pri čemu izvorno polje ima prednost.
Za strujanje upotrebljavajte izvorne krajnje točke za strujanje, a za zahtjeve vođene isključivo
planom kompozicije upotrebljavajte izvornu krajnju točku za kompoziciju.

```bash
curl --fail-with-body "$OMNIROUTE_BASE_URL/v1/music/generations" \
  -H "Authorization: Bearer $OMNIROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"elevenlabs/music_v1","prompt":"Gentle instrumental piano","duration":10,"instrumental":true}'
```

Ograničenja krajnje točke, modela, budžeta i veze primjenjuju se prije uzvodnog poziva. Izvorne
rute vraćaju uzvodne statusne kodove i tijela pogrešaka bez promjena, uključujući `402` za ograničenje
plana i `429` za ograničenje kvote. Zaglavlja `character-cost`, `song-id`, `request-id` i `retry-after`
zadržavaju se kada su prisutna. Besplatan saldo kredita ne jamči pristup svakom
glazbenom modelu, izlaznom formatu ili API značajci: ElevenLabs odlučuje o pravu pristupa za svaki zahtjev.
Objedinjena krajnja točka zadržava statusne kodove pogrešaka u normaliziranoj omotnici pogreške OmniRoutea.

Uzvodni ugovori: [zvučni efekti](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert),
[glazbena kompozicija](https://elevenlabs.io/docs/api-reference/music/compose) i
[pojedinosti o strujanju glazbe](https://elevenlabs.io/docs/api-reference/music/compose-detailed-stream).

Sve POST rute slijede isti oblik: `Bearer your-api-key` + JSON tijelo validirano pomoću Zoda (`v1RerankSchema`, `v1ModerationSchema`, `v1AudioSpeechSchema` itd.; pogledajte `src/shared/validation/schemas.ts`). U slučaju neuspješne validacije sheme vraća se 4xx.

Za klijente koji ne mogu priložiti `Authorization: Bearer ...`, OmniRoute također prihvaća API ključeve u URL-u putem kompatibilnih parametara niza upita (`?token=...`, `?apiKey=...`, `?api_key=...`, `?key=...`) ili namjenskih krajnjih točaka `/api/v1/vscode/{token}/...` dokumentiranih u nastavku.

```bash
# Ponovno rangiranje (pružatelj iz registra u oblaku ili čvor pružatelja kompatibilnog s OpenAI-jem kao "<prefix>/<model>")
POST /v1/rerank      { "model": "jina-ai/jina-reranker-v3.5", "query": "...", "documents": ["..."] }

# Jina klasifikacija (vjerodajnice za Foundation API)
POST /v1/classify    { "model": "jina-embeddings-v5-text-small", "input": ["..."], "labels": ["a", "b"] }

# Jina segmentator
POST /v1/segment     { "content": "...", "return_chunks": true }

# Jina pretraživanje (s.jina.ai; aliasi pružatelja: jina-search, jina-ai, jina)
POST /v1/search      { "query": "...", "provider": "jina-search" }

# Moderiranje
POST /v1/moderations { "model": "omni-moderation-latest", "input": "..." }

# TTS — vraća tijelo audio/mpeg (ili zatraženi format)
POST /v1/audio/speech { "model": "openai/tts-1", "input": "Hello", "voice": "alloy" }

# Soniox TTS zahtijeva jezik i glas: `language` zadano je "en"; glas koji nedostaje
# ili naziv standardnog OpenAI glasa (alloy, nova, …) postaje "Adrian"
POST /v1/audio/speech { "model": "soniox/tts-rt-v1", "input": "Xin chào", "voice": "Adrian", "language": "vi" }

# Uređivanje slike (multipart)
POST /v1/images/edits  -F image=@input.png -F prompt="..." -F mask=@mask.png

# Generiranje videozapisa / glazbe (ID modela s prefiksom pružatelja)
POST /v1/videos/generations { "model": "runway/gen-3", "prompt": "..." }
POST /v1/music/generations  { "model": "kie/suno-v4.0",   "prompt": "..." }
```

> **Čvorovi pružatelja za ponovno rangiranje:** `POST /v1/rerank` također usmjerava zahtjeve prema čvorovima pružatelja kompatibilnima s OpenAI-jem
> (oMLX, vLLM, Infinity, TEI iza pristupnika, …), adresiranima kao `<node-prefix>/<model>`. Čvorovi povratne petlje
> (`localhost`, `127.0.0.1`, `172.16.0.0/12`) uvijek su prihvatljivi, kao i nazivi hostova koje
> operator navede u `OMNIROUTE_LOCAL_PROVIDER_NODE_HOSTS` (npr. naziv Docker/Compose servisa kao što je
> `http://reranker:8080/v1`; oni se pozivaju izravno, nikada putem `HTTP(S)_PROXY` ili
> prikvačenog proxyja veze). Čvorovi na bilo kojem drugom
> hostu — računalu u LAN-u ili Tailscale čvoru — prihvatljivi su samo kada operator omogući
> zastavicu značajke `RERANK_REMOTE_PROVIDER_NODES` **i** osnovni URL čvora zadovoljava pravila za
> izlazne URL-ove pružatelja (`OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS` / `OMNIROUTE_ALLOW_PRIVATE_PROVIDER_URLS`).
> Korak ponovnog rangiranja mehanizma memorije poziva ovu rutu putem
> povratne petlje, pa isto pravilo uređuje `rerankProviderModel` u postavkama memorije.
>
> **Oblici lokalnog poslužitelja:** čvor se poziva na `<base>/v1/rerank`, a u slučaju odgovora 404 na `<base>/rerank`
> (Infinity, TEI). Tijelo zahtjeva prema nadređenom poslužitelju sadrži i Cohere/OpenAI nazive (`documents`,
> `return_documents`) i TEI nazive (`texts`, `return_text`), a odgovor nadređenog poslužitelja
> normalizira se u Cohereovu omotnicu: TEI-jev neomotani `[{index, score, text}]`, `{results: [{index, score}]}`
> iz jednostavnih pristupnika i Voyageov `{data: [...]}` vraćaju se klijentu kao
> `{results: [{index, relevance_score, document?}]}`, poredani prema rezultatu i ograničeni na `top_n`.

> **Otkrivanje čvorova pružatelja:** modeli na čvoru pružatelja kompatibilnom s OpenAI-jem pojavljuju se u `GET /v1/models`
> pod prefiksom čvora. Zapisi bez metapodataka krajnje točke (što je uobičajeno za lokalne popise `/v1/models`)
> nasljeđuju `apiType` čvora, pa su modeli čvora `embeddings` označeni kao `type: "embedding"`, a modeli
> čvora `rerank` kao `type: "rerank"` umjesto da se zadano tretiraju kao chat; izričito navedeni
> `supportedEndpoints` u sinkroniziranom ili ručno dodanom zapisu i dalje imaju prednost.

Apstrakcija pružatelja web-pretraživanja (Tavily, Brave, Exa, Serper itd.).

| Metoda | Putanja                | Opis                                                                                                                   |
| ------ | ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |

### Exa i Tavily `provider_options`

Exa i Tavily čitaju polja specifična za pružatelja iz objekta s imenskim prostorom:
`provider_options.exa` (ili `provider_options["exa-search"]`) i `provider_options.tavily`
(ili `provider_options["tavily-search"]`). Prosljeđuju se samo ključevi navedeni u nastavku. Svaki se
provjerava prema vlastitoj Zod shemi u `open-sse/handlers/search/providerOptionsPassthrough.ts`,
a ključ pogrešnog tipa se odbacuje. Svi ostali ključevi zanemaruju se, uključujući autentikaciju, osnovni URL,
`stream` i `outputSchema`. Ključevi na najvišoj razini koje upotrebljavaju drugi pružatelji (`cx`, `depth`, ...) rade
kao i prije.

| Pružatelj | Polja najviše razine                                                                                                                                                                                                                                                                                                                                                      | Ugniježđeno                                                                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exa       | `type`, `category`, `userLocation`, `moderation`, `additionalQueries`, `objective`, `systemPrompt`, `compliance` (jednostavne vrijednosti na najvišoj razini), `startPublishedDate`, `endPublishedDate`                                                                                                                                                                   | `contents.{text, highlights, summary, extras, subpages, subpageTarget, livecrawlTimeout, maxAgeHours}` spojeno preko zadane vrijednosti `{ text: true, highlights: true }` |
| Tavily    | `search_depth`, `chunks_per_source`, `time_range`, `start_date`, `end_date`, `include_published_date`, `filter_by_published_date`, `include_answer`, `include_raw_content`, `include_images`, `include_image_descriptions`, `include_favicon`, `include_domains_mode`, `language`, `filter_by_language`, `auto_parameters`, `exact_match`, `include_usage`, `safe_search` | —                                                                                                                                                                          |

Generička polja uvijek imaju prednost: `query`, `max_results`, `filters` (domene), `country` i
tema izvedena iz `search_type`. Za Exa, `search_type: "news"` zadržava `category: "news"`.
Tavily također prihvaća `search_type: "finance"` (`topic: "finance"`).

Generički `time_range` sada se prosljeđuje obama pružateljima: Exa dobiva `startPublishedDate` (ISO
vremenska oznaka), a Tavily dobiva `start_date` (`YYYY-MM-DD`). Izričito naveden datum u `provider_options`
nadjačava mapiranu vrijednost.

Rezultati pružatelja Exa zadržavaju `id`, `highlight_scores`, `summary`, `subpages`, `entities` i `extras` u
`provider_raw`. Rezultati pružatelja Tavily zadržavaju `images` i `favicon`.

Obračun troškova i dalje se temelji na registru najviše razine `costPerQuery`. Tavily naplaćuje
`search_depth: "advanced"` s više kredita po pozivu, a ta razlika nije prikazana u
`usage.search_cost_usd`.

## API za dohvaćanje web-sadržaja

Izdvojite sadržaj s URL-a putem konfiguriranog pružatelja za dohvaćanje web-sadržaja (Firecrawl, Jina
Reader, Tavily Extract, TinyFish Fetch, Nimble Extract, Parallel Extract).

Parallel Extract (`parallel-search`, isti API ključ kao za Parallel Search) vraća isključivo Markdown
— bilo koji drugi `format` rezultira odgovorom `400` — i ograničava sadržaj na 100.000 znakova. Kada
se sama ciljna stranica ne može izdvojiti, izvorni servis to prijavljuje unutar HTTP odgovora 200;
OmniRoute to izlaže kao `422` s fiksnom porukom.

| Metoda | Putanja         | Opis                                                            |
| ------ | --------------- | --------------------------------------------------------------- |
| POST   | `/v1/web/fetch` | Dohvaća/izdvaja URL — tijelo se provjerava s `v1WebFetchSchema` |

**Autentikacija:** Bearer API ključ (`extractApiKey` + `isValidApiKey`). Pravilo se provodi putem `enforceApiKeyPolicy`.

**Rezervni odabir svjestan kvota (#8297):** kada nije naveden izričit `provider`, skup
(`firecrawl` → `jina-reader` → `tavily-search` → `tinyfish` → `nimble-search` →
`parallel-search`) obilazi se fiksnim
redoslijedom prioriteta (prvo se popunjava najviši prioritet) — konfigurirani pružatelj s ograničenom stopom zahtjeva preskače se
umjesto da odmah prekine zahtjev, a privremeni neuspjeh ili prekoračenje kvote
izvornog servisa (HTTP 429 uvijek; 402/403 za besplatne razine s kvotama servisa Firecrawl/Tavily/TinyFish —
ne za Jina Reader i nikada za običan 400 zbog neispravnog zahtjeva) prebacuje se na
sljedećeg neisprobanog pružatelja s dostupnim vjerodajnicama tijekom obrade zahtjeva. Kada su svi pružatelji u
skupu iscrpljeni, krajnja točka vraća jedan `429` (sa zaglavljem `Retry-After`)
umjesto prethodnog generičkog odgovora `400`. Kada se zatraži izričit `provider`,
**nema** tihog rezervnog odabira — izričito odabrani pružatelj s ograničenom stopom zahtjeva ili neuspjehom
izlaže vlastitu pogrešku (`429` ako je stopa ograničena, a u suprotnom status
izvornog servisa).

## WebSocket strujanje

```bash
GET /v1/ws?handshake=1
```

Provjerava rukovanje nadogradnjom na WebSocket i vraća primjere poruka žičanog protokola (`request`, `cancel`). Stvarnim WS okvirima upravlja uključeni WS poslužitelj izvan tablice ruta sustava Next.js.

**Autentikacija:** Bearer API ključ tijekom rukovanja.

### Responses API putem WebSocketa (samo codex)

```bash
# Isti host:port kao HTTP API (zadano 20128); nadogradite vezu:
wscat -c "ws://localhost:20128/v1/responses?api_key=<OMNIROUTE_API_KEY>"
# (ili: -H "Authorization: Bearer <OMNIROUTE_API_KEY>")

# Prvi okvir MORA biti response.create:
{ "type": "response.create", "model": "gpt-5.5", "input": [ { "role": "user", "content": "hi" } ] }
```

Proxy za Responses API putem WebSocketa povezan je **isključivo s `codex`** (pozadinski
sustav ChatGPT). Osluškuje na istom portu kao API/nadzorna ploča, na putanjama `/v1/responses`,
`/responses` i `/api/v1/responses`. Pri prvom okviru `response.create`
obavlja autentikaciju i pripremu putem internog mosta `codex-responses-ws`, odabire
codex OAuth vezu i tunelira prema `wss://chatgpt.com/backend-api/codex/responses`
putem transporta `wreq-js`. **Modeli koji nisu codex odbijaju se** (`codex_ws_provider_required`).
Za usmjeravanje uz dijeljenje kvote upotrijebite `model: "qtSd/<group>/codex/<model>"`. Implementirano u
`app/server-ws.mjs` + `scripts/dev/responses-ws-proxy.mjs` + `src/app/api/internal/codex-responses-ws/route.ts`.

**Autentikacija:** Bearer API ključ tijekom rukovanja. Uključeni HTTP poslužitelj (`server-ws.mjs`)
mora biti aktivna ulazna točka (što je zadano kada postoji `app/server-ws.mjs`).

#### ID modela: upotrijebite osnovni ChatGPT ID (bez prefiksa `codex/`)

OpenAI **Codex CLI** provjerava naziv modela na strani klijenta kada je
`supports_websockets = true` i **odbija ID-ove s prefiksom pružatelja** kao što je
`codex/gpt-5.5` (`The 'codex/gpt-5.5' model is not supported when using Codex with
a ChatGPT account`). Pošaljite **osnovni** ID (npr. `gpt-5.5`). OmniRouteov most
namijenjen je samo za codex, pa osnovni ID ponovno razrješava kao codex model
(`resolveCodexWsModelInfo`) prije tuneliranja prema izvornom servisu — iako bi se osnovni
`gpt-5.5` putem HTTP-a inače usmjerio drugom pružatelju.

#### Konfiguriranje alata OpenAI Codex CLI

Usmjerite Codex CLI na OmniRoute dodavanjem prilagođenog pružatelja s podrškom za WebSocket
u `~/.codex/config.toml` (upotrijebite zaseban `CODEX_HOME` kako biste izbjegli izmjene
postojeće konfiguracije):

```toml
model = "gpt-5.5"                 # osnovni ID — NE "codex/gpt-5.5"
model_provider = "omniroute"

[model_providers.omniroute]
name = "OmniRoute (WS)"
base_url = "http://localhost:20128/v1"   # bez završne kose crte; WS URL izvodi se iz ove vrijednosti (u produkciji upotrijebite https/wss)
wire_api = "responses"                    # jedina podržana vrijednost od veljače 2026.
supports_websockets = true                # omogućuje transport Responses putem WS-a
env_key = "OMNIROUTE_API_KEY"             # sadrži OmniRoute API ključ (Bearer)
```

```bash
export OMNIROUTE_API_KEY=sk-...           # OmniRoute API ključ (bilo koji ključ ako je REQUIRE_API_KEY=false)
codex exec "Responda apenas: PONG"
```

CLI nadograđuje `base_url + /responses` na WebSocket, a OmniRoute ga tunelira
do odabrane codex OAuth veze. Provjereno od početka do kraja na lokalnom
poslužitelju: ChatGPT vraća `codex.rate_limits` + `response.created` i strujanjem šalje
dovršetak.

## Samostalni pregled potrošnje (`/api/usage/om-usage`)

Svaki API ključ može očitati **vlastitu** potrošnju i kvote — bez upravljačke autorizacije. Ovo je krajnja točka koju
klijent (CLI, ploča OmniCopilot) upotrebljava kako bi vlasniku ključa prikazao njegovu potrošnju.

```bash
# Tekstni oblik (povijesni ugovor — običan tekst za terminal)
curl -H "Authorization: Bearer <your-api-key>" \
  http://localhost:20128/api/usage/om-usage

# Strukturirani oblik — ono što korisničko sučelje koristi
curl -H "Authorization: Bearer <your-api-key>" \
  "http://localhost:20128/api/usage/om-usage?format=json"
```

Ključ mora imati omogućen **`allowUsageCommand`** (prema zadanim postavkama je isključen — upravitelj API ključeva
na nadzornoj ploči uključuje ga zasebno za svaki ključ). Bez njega krajnja točka odgovara statusom `403`.

`?format=json` vraća diskriminirani oblik kako pozivatelj nikada ne bi pročitao podatkovno polje iz
odbijenog zahtjeva. U slučaju uspjeha:

```jsonc
{
  "allowed": true,
  // prisutno samo kada je za ključ uključeno ograničenje potrošnje po ključu (dnevno/tjedno u USD):
  "personal": {
    "dailySpentUsd": 1.25,
    "dailyLimitUsd": 5,
    "dailyResetAtIso": "…",
    "weeklySpentUsd": 8,
    "weeklyLimitUsd": 20,
    "weeklyResetAtIso": "…" /* … */,
  },
  // snimka kvote odabranog pružatelja ili null kada još ništa nije predmemorirano:
  "provider": { "connectionId": "…", "provider": "claude", "plan": "…", "quotas": {/* … */} },
  // snimka svake veze kako bi korisničko sučelje moglo prikazati više pružatelja jednog uz drugoga:
  "providers": [
    { "connectionId": "…", "provider": "claude" /* … */ },
    { "provider": "codex" /* … */ },
  ],
}
```

U slučaju odbijanja (`401` neispravan ključ / `403` nije dopušteno) ista ruta vraća
`{ "allowed": false, "error": { "message": "…" } }` — prisutan, ali prazan `personal`/`provider`
(ključ je dopušten, ali još ništa nije dohvaćeno) predstavlja stanje različito od odbijanja, a samo ih JSON oblik
razlikuje.

**Autorizacija:** vlastiti Bearer API ključ pozivatelja, provjeren s pomoću `isValidApiKey` — ovo _nije_
upravljačko sučelje (`/api/keys/…`), koje ostaje zaštićeno funkcijom `requireManagementAuth`.

### Sirovi postoci kvote u odnosu na postotke prilagođene pragu prekida

Pri upotrebi `/api/usage/om-usage` pozivatelji trebaju imati na umu razliku između
postotaka prikazanih u **običnom tekstnom izlazu** i strukturiranom **JSON izlazu**:

| Aspekt                | Oblik običnog teksta (`/api/usage/om-usage` / `@@om-usage`)                                      | JSON oblik (`?format=json`)                                                           |
| :-------------------- | :----------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------ |
| **Izlazno polje**     | `NN% left` (npr. `20% left`)                                                                     | `provider.quotas` / `providers[].quotas`                                              |
| **Mjerenje**          | **Iskoristivo dopuštenje prilagođeno pragu prekida**: preostali kapacitet iznad praga prekida    | **Sirova kvota izvornog sustava**: neprilagođeno mjerenje pružatelja                  |
| **Skaliranje praga**  | Skalirano putem `effectiveRemainingPercent()` tako da se zaštićena rezerva očitava kao `0% left` | Nema ga (sirove vrijednosti snimke kako ih je prijavio pružatelj)                     |
| **Podaci o pragu**    | Uključeni u prikazani postotak                                                                   | Pohranjeni u `quotaWindowThresholds` za svaku vezu (ili zadane postavke poslužitelja) |
| **Primarni korisnik** | Interaktivni CLI-jevi, terminalni upiti, ljudski operateri                                       | Programske integracije, nadzorne ploče, analitika, alati za praćenje naplate          |

#### Formula prilagodbe pragu prekida

OmniRoute podržava proaktivne pragove prekida kvote radi sprječavanja iscrpljivanja izvornog sustava (konfigurirane putem
`quotaWindowThresholds` veze, zadanih postavki pružatelja ili globalnih postavki otpornosti). Kada je prag prekida
(npr. `cutoff = 25%`) aktivan u vremenskom okviru kvote, prikazivač teksta izračunava preostalo dopuštenje ovako:

- Ako je `remaining <= cutoff`: vraća `0%`.
- Ako je `remaining > cutoff`: vraća `((remaining - cutoff) / (100 - cutoff)) * 100`.

Formatirani tekstni izlaz zaokružuje to na najbliži cijeli broj (`Math.round(...)`).

#### Ilustrativni primjer

Razmotrite vremenski okvir pružatelja sa **60% sirove potrošnje** (dakle **40% sirove preostale kvote**) i konfiguriranim
pragom prekida na **25% preostale kvote**:

| Prikaz                           | Izračun                                            | Preostalo |           Implicitno potrošeno            |
| :------------------------------- | :------------------------------------------------- | :-------: | :---------------------------------------: |
| **Sirovi JSON (`?format=json`)** | Snimka izvornog sustava (`quotas[window]`)         |  **40%**  |                  **60%**                  |
| **Tekstni oblik (`NN% left`)**   | `((40 - 25) / (100 - 25)) * 100 = (15 / 75) * 100` |  **20%**  | **80%** (ako se računa `100 - remaining`) |

- **Zašto tekst prikazuje 20% preostalo:** Od 40% fizičke kvote koja je preostala na računu, pravilom
  praga prekida rezervirano je 25%. Pozivatelju je preostalo samo 15% od 75% iskoristivog prostora prije nego što usmjerivač
  prestane usmjeravati na ovu vezu. Skaliranje osigurava da veza signalizira iscrpljenost (`0% left`) točno kada
  usmjeravanje prestane.
- **Zašto JSON zadržava sirove vrijednosti:** JSON korisni podaci vraćaju točnu snimku pružatelja (`UsageSnapshot`)
  kako bi vanjski alati imali pristup stvarnom iskorištenju izvornog sustava i postavci
  `quotaWindowThresholds` na razini veze bez gubitaka nastalih skaliranjem na strani poslužitelja.

#### Smjernice za migraciju korisnika

Ako je vanjska integracija (poput dodatka za uređivač ili proširenja agenta) prethodno dohvaćala podatke s tekstualne krajnje točke (`NN% left`) i izračunavala iskorišteni postotak kao `100 - NN`, prelazak na `?format=json` znači:

- Čitanje neobrađenih JSON vrijednosti odražavat će **stvarnu potrošnju uzvodnog sustava** (60 % iskorišteno u prethodnom primjeru).
- Ako integracija želi zadržati semantiku raspoloživog dopuštenog iznosa tekstualne krajnje točke, može na strani klijenta izračunati formulu efektivnog preostalog iznosa koristeći `quotaWindowThresholds` za nadjačavanja na razini veze.

testiranje veze automatski odabire kontrole predloška razgovora za svaki točan ID modela
čiji unos u `/models` potvrđuje prepoznatu vrijednost `owned_by`: `vllm`, `sglang` ili `llamacpp`.
Transparentni omotači kompatibilni s OpenAI-jem mogu sačuvati izvorni unos modela unutar ugniježđenog
objekta `openai`; otkrivanje prati do tri takva omotača. Modeli s nedostajućim, nepoznatim ili
proturječnim vlasništvom zadržavaju uobičajeno ponašanje OpenAI-ja. Otkrivanje ponovno upotrebljava postojeći zahtjev za katalog,
ne generira tokene dovršetka i poništava se kada se promijeni krajnja točka veze.

za djelomično ažuriranje pružatelja:

```json
{
  "providerSpecificData": {
    "reasoningControl": "chat-template"
  }
}
```

Pošaljite to tijelo putem `PUT /api/providers/<connection-id>`. Na toj se vezi izričita
razina zaključivanja `none` šalje kao `chat_template_kwargs.thinking=false` i
`chat_template_kwargs.enable_thinking=false`. Izričite izvorne vrijednosti predloška ostaju mjerodavne,
osim ako poslužiteljsko pravilo zaključivanja ne nametne određenu razinu. Postavka se primjenjuje samo kada prilagođena
veza kompatibilna s OpenAI-jem šalje tijelo Chat Completions; zahtjevi Responses i uobičajeni
pružatelji zadržavaju svoj izvorni oblik zahtjeva. Postavite `reasoningControl` na `openai` kako biste prisilili uobičajeno OpenAI
prosljeđivanje vrijednosti `reasoning_effort` ili ga izostavite/postavite na `null` kako biste upotrijebili automatsko otkrivanje.

Zahtjevi klasifikatora u automatskom načinu rada Claude Codea prema zadanim postavkama onemogućuju izvorno razmišljanje kada
ne sadrže izričite kontrole zaključivanja. Otkrivanje upotrebljava sistemsku oznaku klasifikatora u zahtjevima
Claude formata, a ne nazive modela ili ograničenja dovršetka. Izričite kontrole tijela, podržana zaglavlja za razinu/razmišljanje,
pravila usmjeravanja i razriješena razina modela zadržavaju svoj postojeći prioritet. Obje faze klasifikatora
zadržavaju svoje upite, ograničenja dovršetka, zaustavne sekvence i stvarne odluke nadređenog sustava o dopuštenjima;
druga faza i dalje može proizvesti traženo vidljivo zaključivanje kao običan tekst.

### Verzija i kanal izdanja

```bash
GET /api/system/version
```

Upravljačka ruta dostupna samo putem povratne petlje (administratorska autentikacija). Vraća pokrenutu verziju, najnoviju
objavljenu verziju i status automatskog ažuriranja. `releaseChannel` i `channels` dodatna su
polja (grana 3.8.54); `channel` zadržava svoje značenje — način implementacije koji alat za ažuriranje
nadzorne ploče upotrebljava (`npm`, `source` ili `docker-compose`).

```json
{
  "current": "3.8.52",
  "latest": "3.8.52",
  "updateAvailable": false,
  "channel": "npm",
  "autoUpdateSupported": true,
  "autoUpdateError": null,
  "news": null,
  "releaseChannel": "latest",
  "channels": { "latest": "3.8.52", "next": "3.8.53-rc.1" }
}
```

- `releaseChannel` — npm kanal pokrenute međuverzije: `nightly` za verzije `-nightly.*`,
  `next` za ostala predizdanja (`-rc.*`, `-beta.*`, `-alpha.*`), `lts` za stabilnu verziju
  starije glavne verzije od `channels.latest`, a u suprotnom `latest`. Ista pravila kao u
  `scripts/release/dist-tag.mjs`, koji odabire npm dist-tag pri objavljivanju.
- `channels` — najnovija objavljena verzija svake dist-tag oznake, iz `npm view omniroute dist-tags` (uz
  rezervni pristup putem HTTP-a registra), predmemorirana uz isti TTL od 10 minuta kao `latest`. `latest` je uvijek prisutan
  (rezervno upotrebljava polje `latest`, a zatim `"unavailable"`); `next`, `nightly` i `lts` pojavljuju se
  samo kada ta dist-tag oznaka postoji. Zahtjev `Cache-Control: no-cache` osvježava oba dohvaćanja.

Model kanala (`latest` = v3 do opće dostupnosti verzije 4.0, `next` = rc, `nightly` = međuverzije grane `develop`,
`lts` = zakrpe za v3 nakon opće dostupnosti verzije 4.0) opisan je u `docs/ops/RELEASE_STRATEGY.md`.

## Ograničenja tokena

Proračuni **tokena** po API ključu (odvojeni od prethodno navedenog proračuna u USD-u). Primjenjuju se izravno tijekom obrade zahtjeva: kada potrošnja ključa u trenutačnom razdoblju dosegne ograničenje, zahtjevi se odbijaju odgovorom `429 Too Many Requests`. Ograničenja se mogu postaviti za određeni `model`, određenog pružatelja (`provider`) ili globalno (`global`) za cijeli ključ; kada zahtjevu odgovara više ograničenja, primjenjuje se najstrože.

```bash
# Prikaz ograničenja tokena za ključ (uključuje trenutačnu potrošnju u razdoblju)
GET /api/usage/token-limits?apiKeyId=key-123

# Stvaranje ili ažuriranje ograničenja tokena
POST /api/usage/token-limits
Content-Type: application/json

{
  "apiKeyId": "key-123",
  "scopeType": "model",
  "scopeValue": "openai/gpt-4o",
  "tokenLimit": 1000000,
  "resetInterval": "monthly",
  "enabled": true
}

# Brisanje ograničenja tokena prema ID-u
DELETE /api/usage/token-limits?id=tl-abc
```

> **Napomene o shemi** (`setTokenLimitSchema`): `apiKeyId` i `scopeType` (`model` | `provider` | `global`) obavezni su. `scopeValue` je obavezan osim ako je `scopeType` postavljen na `global` (npr. ID modela za opseg `model`, ID pružatelja za opseg `provider`). `tokenLimit` mora biti pozitivan cijeli broj (pretvara se iz niza znakova). Neobavezno: `id` (izostavite za stvaranje, navedite za ažuriranje), `resetInterval` (`daily` | `weekly` | `monthly`, zadano `monthly`), `resetTime` (`HH:MM`), `enabled` (zadano `true`). Odgovori na `GET` obogaćuju svako ograničenje poljima `tokensUsed`, `remaining`, `windowStart`, `periodStartAt` i `nextResetAt`. Ovo je krajnja točka za upravljanje (provjera autentičnosti provodi se centralno putem autorizacijskog procesnog slijeda).

## Obrada zahtjeva

1. Klijent šalje zahtjev na `/v1/*`
2. Rukovatelj rutom poziva `handleChat`, `handleEmbedding`, `handleAudioTranscription` ili `handleImageGeneration`
3. Model se razrješava (izravni pružatelj/model ili alias/kombinacija)
4. Vjerodajnice se odabiru iz lokalne baze podataka uz filtriranje prema dostupnosti računa
5. Za razgovor: `handleChatCore` provjerava semantičku/potpisnu predmemoriju i razrješava postavke kompresije kombinacije

8. Odgovor se prevodi natrag u klijentski format (razgovor) ili se vraća kakav jest (ugrađivanja/slike/zvuk)
9. Bilježe se potrošnja, analitika kompresije i zapisnici zahtjeva
10. U slučaju pogrešaka primjenjuje se pričuvna opcija u skladu s pravilima kombinacije

## Otpornost (prošireno)

OmniRoute nudi tri neovisna mehanizma za privremene kvarove; upravljačke krajnje točke u nastavku omogućuju operatorima njihovo očitavanje i nadjačavanje:

| Opseg                  | Pohrana stanja                          | Očitavanje                                | Ponovno postavljanje / brisanje                                       |
| ---------------------- | --------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------- |
| Osigurač pružatelja    | `domain_circuit_breakers` + u memoriji  | `/api/monitoring/health`                  | `POST /api/resilience/reset`                                          |
| Razdoblje čekanja veze | `rateLimitedUntil` na vezama pružatelja | `/api/rate-limits`, `/api/providers/[id]` | (ponovno se omogućuje lijeno; briše se putem PUT zahtjeva pružatelju) |
| Blokada modela         | Registar dostupnosti modela u memoriji  | `GET /api/resilience/model-cooldowns`     | `DELETE /api/resilience/model-cooldowns`                              |

`PATCH /api/resilience` prihvaća nadjačavanja osigurača pružatelja unutar `providerBreaker.oauth` i `providerBreaker.apikey`. Svaki profil podržava `degradationThreshold`, `failureThreshold` i `resetTimeoutMs`; ista su polja dostupna na Nadzorna ploča → Postavke → Otpornost.

```bash
# Ukloni blokadu jednog modela
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","model":"gpt-4o-mini"}'

# Ukloni sve blokade
curl -X DELETE http://localhost:20128/api/resilience/model-cooldowns \
  -H "Cookie: auth_token=..." \
  -d '{"all":true}'
```

Potpunu konceptualnu referencu i zadane vrijednosti osigurača potražite u [`CLAUDE.md`](../../CLAUDE.md) → "Stanje izvođenja otpornosti" i [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md).

### Red čekanja za ograničenje brzine i zaštitna mreža automatskog omogućavanja

- **Podržana putanja za zapisivanje**: `POST /api/rate-limits` s tijelom `{"connectionId": "<id>", "enabled": true|false}` podržana je upravljačka krajnja točka za uključivanje ili isključivanje zaštite od ograničenja brzine za vezu. `PUT /api/providers/[id]` namjerno ne mijenja niti prebacuje `rateLimitProtection` (#11278).
- **Semantika vrijednosti `enabled: false`**: Postavljanje vrijednosti `enabled: false` uklanja izričitu zaštitu veze, ali **ne** isključuje aktivnu vezu s API ključem iz globalne zaštitne mreže automatskog omogućavanja (`autoEnableApiKeyProviders = true`). U `reconcileEnabledConnections` (`open-sse/services/rateLimitManager.ts`) vrijednosti `false` i `undefined` istovjetne su; aktivne veze s API ključem bez izričite zaštite ostaju zaštićene globalnom zaštitnom mrežom automatskog omogućavanja.
- **Globalno onemogućavanje**: Za izvođenje veza s API ključem bez redova čekanja za ograničenje brzine globalno onemogućite zaštitnu mrežu putem `RATE_LIMIT_AUTO_ENABLE=false` (varijabla okruženja) ili `resilienceSettings.requestQueue.autoEnableApiKeyProviders = false` (Postavke → Otpornost / `PATCH /api/resilience`).

| GET | `/api/mcp/audit/stats` | Zbirna statistika revizije (ukupni brojevi, stopa uspješnosti, prosječno trajanje, najkorišteniji alati) |

**Autorizacija:** prijenosi `sse`/`stream` poštuju autentifikacijsku površinu specifičnu za MCP (Bearer API ključ s opsegom `mcp`); rute `status`/`tools`/`audit*` mogu se čitati s nadzorne ploče (nije potrebna dodatna autorizacija osim pristupa hostu nadzorne ploče).

> Oba HTTP prijenosa kontroliraju `settings.mcpEnabled` i `settings.mcpTransport` — nepodudaranje prijenosa vraća `400`, a onemogućeno stanje MCP-a vraća `503`.

## A2A poslužitelj

OmniRoute pruža A2A (Agent-to-Agent) JSON-RPC 2.0 krajnju točku i REST omotač za pregled i upotrebu na nadzornoj ploči.

### JSON-RPC

```bash
POST /a2a
Authorization: Bearer your-api-key   # neobavezno, osim ako je postavljen OMNIROUTE_API_KEY
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "message/send",
  "params": {
    "skill": "smart-routing",
    "messages": [{"role": "user", "content": "Usmjeri ovaj programski zadatak"}]
  }
}
```

Podržane metode (sve ovise o postavci `settings.a2aEnabled`):

| Metoda           | Opis                                                               |
| ---------------- | ------------------------------------------------------------------ |
| `message/send`   | Sinkrono izvršavanje vještine; vraća `{task, artifacts, metadata}` |
| `message/stream` | Izvršavanje istog skupa vještina uz SSE strujanje                  |
| `tasks/get`      | Dohvaća zadatak prema `taskId`                                     |
| `tasks/cancel`   | Otkazuje zadatak prema `taskId`                                    |

Ugrađene vještine: `smart-routing`, `quota-management`, `provider-discovery`, `cost-analysis`, `health-report`.

### Kartica agenta

```bash
GET /.well-known/agent.json
```

Vraća javnu karticu A2A agenta (naziv, opis, mogućnosti, katalog vještina, shemu autentifikacije) — javno se predmemorira 1 h. Autentifikacija nije potrebna.

### REST pomoćne krajnje točke

| Metoda | Putanja                      | Opis                                                                                                                |
| ------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/a2a/status`            | Status omogućenosti A2A-a + statistika zadataka + sažetak predmemorirane kartice agenta                             |
| GET    | `/api/a2a/tasks`             | Navodi zadatke — `?state=submitted\|working\|completed\|failed\|cancelled`, `?skill=`, `?limit=` (≤200), `?offset=` |
| POST   | `/api/a2a/tasks`             | (Nije implementirano kao REST pomoćna krajnja točka — izradite putem JSON-RPC metode `message/send`)                |
| GET    | `/api/a2a/tasks/[id]`        | Dohvaća jedan zadatak                                                                                               |
| POST   | `/api/a2a/tasks/[id]/cancel` | Otkazuje zadatak                                                                                                    |

**Autentifikacija:** REST pomoćne krajnje točke rade bez administratorske autentifikacije (čitljive su na nadzornoj ploči); JSON-RPC ruta `/a2a` upotrebljava Bearer `OMNIROUTE_API_KEY` ako je konfiguriran.

## Autentifikacija

Pogledajte [Autentifikacija za upravljanje](../guides/MANAGEMENT-AUTH.md) za četiri
skupine vjerodajnica (sesija nadzorne ploče, lokalni CLI token, `oma_live_…` pristupni
token, API ključ s opsegom za upravljanje) i njihove razlike u odnosu na ključeve za inferenciju.

- Rute nadzorne ploče (`/dashboard/*`) upotrebljavaju kolačić `auth_token`
- Prijava upotrebljava spremljeni sažetak lozinke; pričuvno se upotrebljava `INITIAL_PASSWORD`
- `requireLogin` se može uključiti ili isključiti putem `/api/settings/require-login`
- Rute `/v1/*` po potrebi zahtijevaju Bearer API ključ kada je `REQUIRE_API_KEY=true`
- „token za upravljanje” / „API ključ s opsegom za upravljanje” u ovoj referenci označava jednu od skupina iz tog vodiča — a ne dodatnu, nedefiniranu vrstu tajne

> **Promjena koja narušava kompatibilnost (v3.8.0)** — `/api/v1/agents/tasks/*` i krajnje točke za upravljanje razdobljem čekanja sada zahtijevaju **autentifikaciju za upravljanje** (kolačić `auth_token` nadzorne ploče ili API ključ s opsegom za upravljanje). Klijenti koji su prethodno pozivali te rute bez autentifikacije primit će `401 Unauthorized`. Pogledajte commit `588a0333` (`fix(auth): require management auth for agent and cooldown APIs`).
